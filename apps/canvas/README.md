# canvas

The 2D canvas's own app (spec 14.0): test sheets drawn through `canvas.h` in millimetres and nanometres, the units pcb gives it -- `shapes`, `areas`, `polygons`, `ramp`, `thin`, `long`, `glyphs`, `tags`, `overlap`, a `symbol` of an integrated circuit with turned pin names, and a two-layer `board` with a ground plane, a highlighted net, a picked pad and a trace removed. `--split` draws the board as two views, the second from below; `--ui` puts a UI panel over it; `--edit-thread` fills the board's edit on a thread of its own; `--budget` times the canvas draws. Drag pans and the wheel zooms the view under the cursor. Under `--canvas-probe` a sheet prints where its shapes landed, which the `canvas` gate group measures. `--idle` runs it in the engine's idle mode (spec 14.1), with a board filled on a thread mid-run, timed wakes, a texture loaded late, a UI fading in and a click handed to the debug GUI as the `idle` gate group's cases; G opens the debug GUI and F the FPS readout, which then counts the frames drawn. **Since 14.2 it tests the UI's text input and scrolling panes**, and none of it sketches pcb's interface. `--palette`: Cmd+K (Ctrl+K elsewhere) opens a modal palette over the app's own commands with their keys (= and - zoom, 0 resets the view, P prints it, keys that work in a view without it too), filtered and ordered by `fuzzy_match` with the matched letters lit, Up and Down and Enter or a click to run, Esc to close; `/` opens the jump over 5,000 generated names, one list of virtual rows over every match. The list is as tall as its rows up to twelve, then scrolls, by its `max_size` (14.3). `--history`: a column at the window's right, 200 messages as virtual rows of read-only fields, a speaker in a colour and now and then a part's name in a second face (PressStart2P, a pixel font, so it looks blocky on purpose), over a multi-line input line that submits on Enter; Enter in a view puts the caret there, Esc returns, and a sent message is answered by a reply streamed in a word at a time, appended to its row while the row is built (`ui_field_append`), so a selection in it holds. The UI's input is `ui_input_read` alone; the app keeps no pointer state of its own. `--ui-text TEXT` sets the `--ui` panel's text, for the glyph arms. The app's own keys stand down while `ui_wants_keyboard`. **Since 14.4 it tests the code editor**: `--font-sheet` draws JetBrains Mono at 11, 13 and 16 points from the editor's bitmaps beside the same face as the UI's distance field; `--editor FILE` opens a file in the editor over the whole window, standing in for pcb -- an S-expression highlighter on pcb's lexical rules, a parse on a thread whose errors land a few versions behind and are underlined where the typing since moved them, taken on the frame the thread's `engine_end_work` wakes as the board's is (`--editor-lag N` takes each result N frames after it began instead, so a headless run repeats), F6 landing an edit from another view and F7 reading the file again, in a mode of the app's own over the standard one -- and under `--canvas-probe` prints the text, the selections, the errors and whether every row is wrapped. **`--vim` (spec 14.5) puts that editor in the vim mode**, the app's mode a layer over it, with a line under the editor showing vim's state and a half-typed command and taking a search or a `:` line as the host's prompt -- lit as it is typed, "Pattern not found" or "Not an editor command" said there until the next key; `ui-vim-script` drives it from an input script. **Since 14.6 `--editor` may be given more than once, and the editors are PANES** -- a test bed for `ui_remove`, `ui_move` and `ui_editor_set_doc`, not pcb's panes, whose keys are pcb's: F8 splits the focused pane, a row put in its place with it moved into the row and a second editor on the same text beside it; F9 closes it from its own key, a row left holding one pane handing that pane up; F10 shows the next file in it, where that pane last was in that file, brought through the edits since. Under `--canvas-probe` it also prints every pane -- its file, the offset at its top, whether it has the focus and its selections -- every file's text, the panes' tree of rows and which pane the vim line is answering, which `canvas-panes` reads. The panes are the UI's tree itself: the app keeps no table of them, and finds a pane's file by the text it shows. **Since 14.7 it tests what pcb asked of cetra after its window's reviews**: `--read-only` makes every file's text read-only, each refusal counted and said on the vim line ("Cannot make changes, the text is read only"); `--refuse-close` refuses the first close the window is asked for and takes the next; `--work-delay MS` sets how long the board's thread pauses under `--idle --edit-thread`, which a headless frame now waits for. **Since 14.9 the rest of those reviews**: `--split-share F` gives F8's first side a share of its row, held through a resize; `--vim-lookup` answers `gd`, `gD`, Ctrl+] and `K`, saying on the vim line what it was asked and the name; `--vim-layout` answers `=`, `gq` and a new line's indent by the S-expression's open brackets; and `--idle-wake` asks times joined by `+` on one frame. **Since 14.10** `--ui-keys` makes the `--ui` panel focusable and gives it a key hook, as a pane pcb draws would have, its label saying the last two things it was handed, with a text field under it to move the pointer across while it holds the focus. **Its three fonts are built into the program** (`cetra_embed_files`, spec 14.6), so it reads no font from beside it; under `--font-sheet --canvas-probe` it holds each to the file it was built from. A debug harness for `stb_truetype.h`, which the glyph arms check against -- the coverage, the kerning of every pair and every glyph's field in the atlas -- and for cimgui, through which `--gui-click` reaches ImGui
