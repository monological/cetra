# Tier 4 · 4.16 — AgX tonemapping

## Context

Cetra offers two display transforms: ACES (filmic, but it hue-shifts and blows saturated
highlights) and Khronos PBR Neutral (faithful below ~0.76, flat as a "look"). AgX (Sobotka;
Blender 4+'s default view transform) is the modern third option: it desaturates toward white
as radiance climbs, so saturated HDR highlights (emissive screens, colored studio lights,
fog shafts, bloomed metal) roll off gracefully instead of skewing hue. §4.16 adds it as a
third `PostFXTonemapMode` — purely additive: existing modes stay byte-identical, the default
(NEUTRAL) does not change.

**Verified code facts (explored):**
- The scene is tonemapped in exactly ONE place: `tonemap_frag.glsl`'s `toneSelect(vec3)`
  (added in the 4.8 review; serves the scene path via `sceneToToned` and the GI/fog debug
  views). Current dispatch: `tonemapMode == 1 ? acesTonemap(c) : pbrNeutralTonemap(c)` —
  anything != 1 falls through to Neutral, so widening is mandatory, not optional.
- **Color-space contract:** `toneSelect` returns LDR-LINEAR [0,1]; `displayEncode` applies
  `pow(1/2.2)` later (finishing order: sharpen → grade → vignette → gamma → grain). Many AgX
  references output 2.2-encoded values from the sigmoid — ours must compose the inverse
  (outset + linearize) so it returns LINEAR. Do not double-encode.
- PASSTHROUGH (0) never reaches the shader (blit gate at postfx.c:934/949); the uniform
  upload passes any int through (postfx.c:1367); default `POSTFX_TONEMAP_NEUTRAL` at
  postfx.c:179. No other enum-value comparisons exist in C except the GUI.
- **GUI is a 2-way boolean checkbox** ("ACES Tonemap" ↔ Neutral, engine.c:1267-1269) — cannot
  express a third mode; becomes a combo.
- **No app can select a tonemap mode headless today** (no flag in render.c; gametest sets
  nothing). Same byte-gate trap as bloom had: the flag must land FIRST as the bridge that
  makes per-mode baselines capturable on an unchanged renderer.

## Design

**Shader (tonemap_frag.glsl):** add the standard minified AgX (Wrensch's fitted form, the
one Godot ships) between `pbrNeutralTonemap` and `displayEncode`:
- `agxDefaultContrastApprox(vec3 x)` — the 6th-order polynomial sigmoid.
- `agxTonemap(vec3 c)`:
  1. inset: `c = AGX_MAT * c` (the 3×3 inset matrix, exact published constants);
  2. `c = clamp(log2(max(c, vec3(1e-10))), MIN_EV, MAX_EV)` with MIN_EV = -12.47393,
     MAX_EV = 4.026069, then normalize to [0,1] — the `max()` guard is the house NaN law
     (log2(0) = -Inf);
  3. sigmoid via the polynomial (output is 2.2-encoded by construction);
  4. outset: `c = AGX_MAT_INV * c`, then `return pow(max(c, 0.0), vec3(2.2));` —
     linearize so the return honors the toneSelect LDR-linear contract.
  Base AgX only (Blender's default view transform); the "punchy" look is a follow-up knob,
  not v1. Comment style mirrors the ACES/Neutral headers (provenance + what the look does).
- `toneSelect`: `return tonemapMode == 3 ? agxTonemap(c)
                        : tonemapMode == 1 ? acesTonemap(c) : pbrNeutralTonemap(c);`
- Update the uniform comment (:30-32) to "1 = ACES, 2 = PBR Neutral, 3 = AgX".

**Enum (postfx.h:19-23):** `POSTFX_TONEMAP_AGX = 3,` with a one-line comment ("Desaturates
toward white with rising radiance; no hue skew on saturated highlights").

**GUI (engine.c:1267-1269):** replace the boolean checkbox with a combo:
```c
int tm = (int)fx->tonemap_mode - 1; // ACES=0, Neutral=1, AgX=2 (passthrough not offered)
if (igCombo_Str("Tonemap", &tm, "ACES\0PBR Neutral\0AgX\0", -1))
    fx->tonemap_mode = (PostFXTonemapMode)(tm + 1);
```
(Use whichever igCombo variant the cimgui in-tree headers expose — check the existing
igCombo usages if any; fall back to three igRadioButton_IntPtr on one line.)

**App flag (apps/render/src/render.c):** `--tonemap <aces|neutral|agx>` — args field
`int tonemap_mode` (0 = keep default sentinel), parse with strcmp on the value (error on
unknown), apply inside the shared `if (engine->postfx)` block (the 4.13 review's placement
law), usage line. gametest untouched.

## Risks / notes

1. **Constants fidelity:** the inset/outset matrices and polynomial coefficients must be the
   exact published values (they are inverses of each other through the sigmoid's encoding) —
   transcription errors show up as a global color cast. The visual gate's gray studio wall
   is the canary: it must stay neutral gray under AgX.
2. **fp16 inputs:** scene values arrive up to the 60000 clamp; log2 handles the range, and
   the sigmoid domain is normalized — no overflow path. The 1e-10 floor handles black.
3. **Debug views:** GI/fog debug views route through toneSelect and get AgX for free —
   correct and intended (they're HDR previews).
4. AgX is NOT made the default — evaluating that is the user's call after living with it.
