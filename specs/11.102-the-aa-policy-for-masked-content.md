# Spec 11.102 — The AA policy for masked content (roadmap row 64, G3)

## Context

Spec 11.101 measured where the live-path flicker on masked (alpha-tested) content actually comes
from: the render app's interactive session runs **TAA at MSAA 1**, and at one sample a binary
alpha test under a clamped TAA history cannot hold fractional coverage — the ladder fixture reads
0.16–0.22 of the stored coverage and churns, where **MSAA 4 + alpha-to-coverage keeps 0.89 at 8
flips a frame**. 11.101 shipped the jitter as a palliative for the one-sample path and booked the
policy question as G3: *should a masked material in the scene make the interactive default
MSAA 4 + TAA, what does that cost on forest, and does the one-sample path keep the palliative?*

Exploration settled more of it than the row expected, and corrected the row twice:

- **The row is wrong about `apps/tree`.** It says tree "runs MSAA 4 + TAA and never had the
  problem". Tree runs **MSAA 1 + TAA unconditionally** (`apps/tree/src/tree.c:1187`, commit
  6ff9082b, 2026-08-27, during 11.88) — chosen for cost AND because A2C on near-black leaves
  against a sunset produces a *correct* partial-coverage fringe that reads as an orange outline
  (2,616 rim px, none brighter than a straight blend). `docs/cli-reference.md:374-376` carries the
  same stale claim ("this app runs 4x MSAA *and* TAA").
- **Forest's cost is already measured.** Spec 11.34 (1600x900/60f, opaque GPU row, 0.23% floor):
  **121.6 ms at 1 sample, 353.2 at 2 (A2C on), 539.8 at 4 (A2C on)** — "A2C alone costs 202 ms;
  the fragment set explodes when foliage stops discarding." Promotion is unaffordable there; the
  phase-1 A/B re-confirms at head (forest is a different world since 11.63/11.98) rather than
  discovers.
- **11.31's "genuinely looks better" on the raiden groom does not transfer.** It was measured at
  the accidental 2-sample target AND under the 0.02 threshold 11.87 later called a bug ("the 0.02
  is in the wrong space") — strands came back partly because of the defect. Re-measure with crops.
- **The one-sample request is genuinely one sample since 11.34** (`engine.c:581-584`), so
  "A2C for free on the accidental second sample" is not an option.
- **The render app loads the scene before its AA policy runs** (`render.c:3158/3164` vs `:4191`),
  has no runtime scene reload, and the config snapshot applies AFTER the policy (`:4231`), so a
  restored `msaa_samples` still wins. A load-time content check is sufficient and safe.

So the answer to (b) is a number already in the tree, the answer to (c) follows from it (forest
and tree stay on the one-sample path, so the palliative keeps its consumers), and (a) is a
change to ONE app: the render app, whose scenes are single models and fixtures where four samples
are affordable and where the defect was surfaced.

## The design

**One engine fact, one app policy, headless made explicit.**

1. **`scene_has_masked_material(const Scene*)`** in `cetra/src/scene.c/h` — one loop over
   `scene->materials[i]->alpha_mode == ALPHA_MASK`. The material list is complete at that point
   (assimp import and `.cscn` material blocks set `alpha_mode` synchronously, `import.c:461-470`;
   only textures stream). Precedent for "a scene fact gates a default": OIT on `oit_mesh_count`,
   SSS inert without `subsurface > 0`.

2. **The render app's TAA policy chooses the sample count from content.** `render.c:4191`:
   ```c
   if (!args.headless || args.force_taa) {
       const bool masked = scene_has_masked_material(scene);
       set_engine_msaa_samples(engine, masked ? MASKED_MSAA_SAMPLES : 1);
       set_engine_taa_enabled(engine, true);
       // one log line naming the decision and the override
   }
   if (args.msaa > 0) set_engine_msaa_samples(engine, args.msaa);   // unchanged, still after
   ```
   `MASKED_MSAA_SAMPLES` is 4 unless phase 1 shows 2 clears the ladder's A2C bars (rule below).
   **The promotion rides the TAA policy, not `!headless` alone**, deliberately: a headless
   `--taa` run then reproduces the window's AA (the whole point of `--taa` as a diagnostic), and
   the decision is testable headless through `--config-dump`. The cost is that every gate arm
   that renders a masked fixture under `--taa` without `--msaa` currently gets the one-sample
   path by accident and must now **say `--msaa 1`** — which `mask-samples`' own comment already
   argues is the honest form. Headless without `--taa` (all 29 goldens) is untouched: MSAA 4,
   TAA off.
   `--msaa N` overrides either way; the GUI "MSAA 4x" checkbox and the snapshot's `msaa_samples`
   row remain the runtime levers (`set_engine_msaa_samples` rebuilds in place, `engine.c:794`).

3. **Forest and tree: no behaviour change.** Forest's comment at `forest.c:3222` says it
   "matches render's policy" — it no longer does; rewrite it to cite 11.34's number as the reason
   it stays at one sample. Tree's comment already states its two reasons.

4. **The palliative stays as shipped.** Its consumers are forest, tree, `--msaa 1`, and any
   unmasked-then-masked edge the policy cannot see; its gate (`alphaToCoverage == 0`) already
   turns it off on the promoted path. No shader change.

5. **A gate arm that asserts the policy** — `ladder-policy`, in the `ladder` group (the group
   about the live path for masked content): three cheap headless `--taa --config-dump` runs at
   400x300 / few frames, reading `engine.msaa_samples` from the JSON: the ladder fixture → the
   promoted count; `GPU_FIXTURE` (unmasked) → 1; the ladder fixture with `--msaa 1` → 1 (the
   override still wins). Docstring column added (gate-docs enforces both).

## Decision rules, pre-committed (phase 1 fills the numbers)

| question | instrument | rule |
|---|---|---|
| forest promotion | forest `--profiler`, 1600x900/60f, default vs `--msaa 4`, interleaved A/B/A/B/A/B, floor from adjacent A samples (`_timing_delta`'s shape) | refused if the opaque row more than doubles (11.34: 4.4x). Recorded, not decided by this spec's taste |
| 2 vs 4 samples for the render app | ladder `_ladder_pair` at `--taa --headless-jitter --msaa 2`: ratio (ladder-a2c's) and churn (ladder-still's) | ship the SMALLEST count clearing both `LADDER_A2C_MIN_RATIO 0.6` and `LADDER_A2C_CHURN_MAX 200`; expected 4 |
| render-app cost | raiden recipe + `ivy_arcade` (the user's scene) at 1600x1200 (the HiDPI window), `--taa --headless-jitter --profiler`, `--msaa 1/2/4`, interleaved, floor first | no bar — a viewer's frame; the numbers go in the row so the policy is priced |
| the fringe | 300% point-filtered crops, 1 vs 4 samples + TAA, ivy leaf edge and raiden strand against the brightest background | **hold point: the user's eye**, before phase 2. Tree's orange outline is the precedent |

   note pointing here. Full suite + 29 goldens.

## Risks

- **A masked material that is not foliage** (raiden's `Hair_1`, `translucent_shadow_fixture`'s
  one MASK material among BLEND) promotes the whole scene to four samples for one mesh. That is
  the rule working as stated; the cost row prices it on raiden, and `--msaa 1` is one flag away.
- **The fringe.** A2C's partial coverage against extreme contrast is correct AA that tree refused
  on look. The crops are the hold point; if the user refuses it on ivy, the escape is to keep the
  policy at 1 and record G3 as "documented, not promoted" — a legitimate closing of the row.
- **Gate enumeration misses one `--taa` masked arm** → it silently starts measuring MSAA 4. The
  full suite at the end catches a moved number; the enumeration is by grep, not memory.
- **Driver rounds `--msaa 2` up** (`engine.h:93-96` says above 1 the count is the driver's
  answer): the ladder measurement at 2 reads `msaa_samples_actual` from the log before trusting
  the row.

# As built — the promotion is REFUSED, and G3 closes documented

**No engine or app behaviour shipped.** Phase 2's measurements refused the design above, phases 3
and 4 were never built, and the deliverable is this ledger plus the corrections in phase 5. The
plan is left standing rather than rewritten, because what it got wrong is the transferable part.

## The price of the promotion

Interleaved A/B (never A-then-B), fastest run as the estimator, floor from the two fastest base
runs — `_timing_delta`'s shape, and the protocol `docs/verification.md` requires for forest.
Every pair below is SEPARATED (the variant's fastest run is slower than the base's slowest), so
no assignment of the noise accounts for the gap.

**`apps/forest`**, 1600x900 / 60 frames / `--taa`, `--msaa 4` against the shipped one sample:

| GPU row | one sample | MSAA 4 | delta | floor |
|---|---|---|---|---|
| opaque | 26.6 ms | 55.3 ms | +108% | 1.74% |
| TIMED | 54.6 ms | 83.6 ms | +53% | 1.32% |
| FRAME (wall) | 68.4 ms | 99.4 ms | +45% | 0.39% |
| shadow cascades | 19.2 ms | 19.2 ms | −0.2% | 1.87% |

The shadow row is the control and is the one pair that does NOT separate: the depth pass renders
into its own single-sampled array at every sample count, so a change there would have meant the
instrument was measuring the machine rather than the configuration.

**The render app**, 1600x1200 / 60 frames / `--taa --headless-jitter`, three counts interleaved:

| fixture | row | 1 | 2 | 4 | floor |
|---|---|---|---|---|---|
| raiden recipe | opaque | 2.53 ms | 4.24 ms | 4.88 ms | 0.87% |
| raiden recipe | FRAME (wall) | 10.2 ms | 13.9 ms | 17.1 ms | 0.51% |
| `assets/ivy_arcade` | opaque | 17.3 ms | 98.3 ms | 105.6 ms | 1.21% |
| `assets/ivy_arcade` | FRAME (wall) | 31.0 ms | 114.7 ms | 122.4 ms | 1.82% |

**Do NOT set 11.34's forest table (121.6 / 353.2 / 539.8 ms) beside the 26.6 above.** That build
predates 11.63 and 11.98 — a different island, a different quadtree, a different scatter, and an
occlusion pass — and `docs/verification.md` states no forest capture from before 11.63 compares at
all. The two tables are separate worlds; only the ratio WITHIN each pair is a measurement. No bake
changed between any two legs here, so both legs of every A/B served the same cooked artefacts.

## Why it costs what it costs, and the counter that cannot say so

**Two samples cost what four cost on ivy** (98.3 vs 105.6 ms, a 7% gap against a 1.21% floor).
That is the whole diagnosis: the expense is the alpha-to-coverage MODE, which `a2c_capable` arms
at any count above one, and not the sample count. It is why no intermediate rung exists to promote
onto.

The depth prepass, `--depth-prepass` on ivy at MSAA 4, takes the opaque row from 105.6 to 47.9 ms
against a 3.66% floor — and at one sample it moves 17.35 to 15.63, which does NOT separate. **That
is a sign reversal against what `docs/cli-reference.md` and roadmap row 31 record**, and both were
right: the prepass loses at one sample and wins under A2C, because A2C is what stops the alpha test
from discarding and leaves overdraw for a prepass to remove. It still does not reach the one-sample
row (47.9 vs 17.3), so it is a mitigation for a configuration this spec is refusing, not a reason to
accept it.

**A counter reading was misread mid-phase and is corrected here rather than quietly dropped.** The
shaded-samples figure went 5,429,176 to 21,691,383 between one sample and four, which was stated as
the fragment set exploding. It is not: `GL_SAMPLES_PASSED` counts SAMPLES, the frame's budget rises
by exactly 4, and the rise measured 3.995. Depth complexity — the ratio, which is the quantity that
means anything here — is FLAT at 2.83 against 2.82. The counter says A2C did not add overdraw at
all; the prepass row above says the overdraw was already there and A2C stopped hiding it. Roadmap
row 31 records this counter being halved by MSAA once and doubled by a bad budget once, which is
the reason to state what it counts before quoting a ratio of it.

## What it buys, and the quantity real content never reaches

The `ladder` fixture's own metrics, at the gate's framing, against the TAA-off truth:

| path | coverage kept | churn (px moving > 8 codes between adjacent frames) |
|---|---|---|
| 1 sample + TAA | 0.22 | 358 |
| 2 samples + A2C + TAA | 0.75 | 737 |
| 4 samples + A2C + TAA | 0.89 | 8 |

**Churn is not monotonic in the sample count**, which nothing predicted: two samples are worse than
one. Two would have failed the pre-committed stillness bar (200) while clearing the coverage bar
(0.6), so the rule would have selected four — and four is what the cost table refuses.

**The 0.89 is real and buys nothing visible on real content, and this is the paragraph that should
stop the next reader re-opening G3 on the coverage ratio alone.** 11.101 already found that
irregular content never dithers before its 1x1 tail — the ladder's foliage and speck rows scan to
−1 and only a regular lattice fires early. So the coverage the MSAA path preserves so much better is
coverage that foliage, groom and speck textures never had at a visible mip. The 300% crops confirm
it from the other end: at four samples the ivy leaf and the raiden strand edges are slightly softer,
neither scene shows the fringe `apps/tree` refused at 4x in 11.88, and **no raiden strands come
back**. `assets/ivy_arcade` is not pixel-comparable (8,674 px between two pinned runs), and these
frames carry TAA jitter besides, so the crops are a hand observation and no pixel count is claimed
from them.

**That kills the row's own supporting evidence.** Roadmap row 64 cited 11.31's "genuinely looks
better" on the raiden groom. 11.31 measured that at the accidental 2-sample target AND under the
fixed 0.02 threshold that 11.87 later called a bug in one sentence ("the 0.02 is in the wrong
space"). The strands it recovered were the defect, not A2C.

## What this spec got wrong about itself

**The refusal bar was attached to a decision that was already closed.** The only number in the
decision table was on the forest row — "refused if the opaque row more than doubles" — and the
design refused forest promotion three paragraphs earlier, in the Context, by citing 11.34. The row
that governed the change actually proposed, the render app's cost, reads "no bar". So the proposal
that would have shipped had no falsifier attached to it, and the rule that fired governed nothing.
The +108% on forest changed no decision; the +296% on ivy, which no rule covered, is what refused it.

**The hold point was mis-sequenced in its own text**: "hold point: the user's eye, before phase 2",
when the crops ARE phase 2. Written correctly it would have been phase 2a, with every profiled suite
contingent on it — and the crops alone refute the proposal, at no profiling cost. Of the four
measurement rows, two were worth their time (the crops, and the 2-sample ladder, which returned the
non-monotonic churn nothing implied), the forest A/B was unnecessary by the spec's own admission,
and the raiden and ivy sweeps at three counts were over-scoped where one pair was decisive.

**A cheaper instrument was in the spec's hand.** 11.34 did not only price forest, it DECOMPOSED the
price: "A2C alone costs 202 ms — the fragment set explodes when foliage stops discarding", with the
sample itself at ~93 ms. That decomposition is content-general, and ivy is dense masked cutouts. The
spec quoted 11.34's table and then failed to apply its mechanism to the app it was proposing to
change.

## Found on the way, and not fixed here

- **`alphaJitterFrame` was dead** — declared in `pbr_frag.glsl`, uploaded every frame, read
  nowhere, with a declaration comment claiming a rotation the shipped static anchor does not have.
  Removed on this branch as an 11.101 leftover, byte-identical.
- **The `ladder` group scaled its framebuffer request twice**, harmless at the calibrated 2x host
  scale and a doubling anywhere else, which would have shifted every card one mip. Fixed here.
- **Five apps take the engine's headless default** (4x MSAA, no temporal filter) because only
  render, forest and tree opt out — the state `apps/forest` fixed for itself and named as a bug.
  Spores and gametest are 3D scenes through the game framework and have the same case forest had;
  shapes, pcb and splash draw 2D primitives and SDF text, where four samples with no temporal
  filter may well be RIGHT and temporal jitter on static text is unexamined. Booked as a roadmap
  row rather than resolved blind, because a blanket "windowed means one sample plus TAA" default
  writes a 3D-scene assumption into the engine and would render a plausible frame in all three
  cases while being wrong.
- **`apps/render` and `apps/forest` set their sample count AFTER `init_engine`**, so both build
  every G-buffer attachment at four samples and immediately tear it down and rebuild at one.
  `apps/tree` states the rule in a comment and obeys it. Startup only; fixed here.
