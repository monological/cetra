# Spec 11.99 — The derived-data cook (roadmap F2, `.cca`)

## Context

Roadmap row 52 (F2), the last open item with a measurement behind it. Every app redoes its
derivation work on every launch: forest starts in **6.58 s debug / 1.36 s release** (11.65) —
procedural texture bakes, 20 cluster-DAG builds, erosion, and a Jolt BVH build that is **85% of
collider time in BOTH builds** (0.981 s debug / 0.040 s release, 11.64); the render app spends
**145.7 ms per 2048² sRGB texture** on the CPU mip chain (11.85). The gate suite launches forest
~55× per run. ~5.3 s of forest's debug startup is unattributed by any spec.

**Model (settled with the user): the UE DDC shape — a TRANSPARENT derived-data cache plus an
explicit `--cook` pre-warm verb.** Each derivation site wraps in a fetch-or-bake-and-store
bracket; the key IS the identity (input hash + recipe version + library version where a library
defines the byte format), so a stale artefact is never detected, it is **unfindable**; a miss
always falls through to the live bake; a corrupt file on a key hit is refused by name and treated
as a miss. This is the sanctioned crossing of "two builds are not two runs": the key never carries
the build type, artefacts are content, and gates own byte-reproducibility via `--no-cook` and a
controlled cache dir.

## The core module — `cetra/src/cook.c/h` (~565 LOC with the header charter)

**Process-global context** behind `cook_init(const char* dir, bool enabled)` / `cook_shutdown()`
— the `texture_set_compression_enabled` lever precedent, because the wrapped sites span five
modules (forest, texture.c, sky.c, sky_clouds.c, physics) that share no context type. An app that
never calls `cook_init` behaves exactly as today (every fetch misses, store no-ops). Dir
resolution: explicit arg > `CETRA_COOK_DIR` env > `cooked/` at the repo root (cwd-resolved;
first `getenv` in the engine, noted deliberately). `CETRA_NO_COOK` env disables for flagless apps.
`.gitignore` gains `cooked/` with an ivy-arcade-style comment.

API (by-value key on the caller's stack, no allocation in key building):

```c
CookKey cook_key(const char* recipe);            // "erosion/1" — name + VERSION, one string
void cook_key_u32/u64/i32/f32/str/bytes(...);    // f32 folds the IEEE bit pattern;
                                                 // bytes folds a u64 length prefix first
bool cook_fetch(const CookKey*, CookBlob* sections, int section_count);  // hit: each section
                                                 // its own malloc, caller owns/installs
bool cook_store(const CookKey*, const CookBlob* sections, int section_count);
void cook_probe(const char* label);              // the counter ledger
```

- Hash: **64-bit FNV-1a** (erosion.c's constants promoted; 32-bit `fnv1a_bytes` collides by
  ~9,300 artefacts). Never fold a struct by sizeof (padding); fold fields typed, in order.
  **Never fold `workers`** — worker-invariance is the bake modules' proven contract.
- `cook_fetch` takes the EXPECTED section count; a stored artefact disagreeing is refused by
  name (it means a recipe changed shape without a version bump — the tripwire).
- Store: write `<name>.cca.tmp.<pid>`, fflush+fclose, rename (atomic). Store failure warns once,
  disables stores, run continues — store is advisory. Refused files left in place (the re-bake's
  store overwrites atomically). Thread-safety v1: **main-thread only**, stated in the header.
- Private LE codecs (the terrain_stream.c:15-49 idiom, copied not shared — cts/heightmap outputs
  are gate-asserted and gain nothing from churn).

**The `.cca` format** — one file per artefact, flat dir, filename
`<recipe with / as ->-<16 hex of key>.cca`. 64-byte LE header: magic `CCA1`, container version,
key u64, section_count, flags, **payload_hash** (FNV-64 over all section bytes — the cache dir
lives under Dropbox sync, torn files have correct sizes), total_bytes, recipe string (24 B,
refusal-by-name needs the name in the file); then a `{u64 offset, u64 size}` section table whose
offsets the reader RECOMPUTES and compares (the terrain_stream layout cross-check), then packed
payload. Any failed check: `log_warn` naming file + check, count `refused`, return miss.
64-bit collision within a recipe namespace: accepted at ~1e-14, stated in the header comment.

## The Jolt escape hatch — `physics_cook.h` + `physics_cook.cpp` (~180 LOC)

Both at `cetra/src/` root (the glob compiles `src/*.cpp` but NOT `game/*.cpp`;
`cluster_build.cpp` is the precedent and the header comment cites it). C surface:

```c
unsigned char* physics_cook_shape_serialize(const JPC_Shape*, size_t* out_size);  // malloc'd
JPC_Shape* physics_cook_shape_restore(const unsigned char*, size_t);  // one ref to caller
uint64_t physics_cook_jolt_version(void);   // JPH_VERSION_ID (Core.h:71) — the key axis:
                                            // Jolt's cooked format is not stable across versions
```

Internals: `reinterpret_cast` between `JPC_Shape*`/`JPH::Shape*` (the OPAQUE_WRAPPER idiom,
JoltCImpl/JoltC.cpp:130, re-stated locally with a comment naming the source); two ~15-line
StreamOut/StreamIn subclasses over malloc buffers; `SaveWithChildren`/`sRestoreWithChildren`
(materials and compound shapes ride free the day they exist); restore mirrors
`HandleShapeResult`'s refcount contract (JoltC.cpp:1698) — one reference out, released via the
existing `JPC_Shape_Release` lifecycle.

## The cooked-texture entry point — texture.c/h (~280 LOC incl. the split)

Split `texture_upload_image` (texture.c:591-719) into pure `texture_derive_levels` (box-halve →
coverage rescale → block encode, no GL) and `texture_upload_levels` (the GL loop), both consumed
by the live path — so a hit and a miss provably upload identical bytes, one pipeline. **This
touches gate-covered arithmetic across all 29 goldens; expected byte-identical (same arithmetic,
same order); goldens verify in the same phase.** New sibling
`texture_pool_publish_cooked(pool, key, block_format, channels, desc, levels[], level_count)` —
uploads verbatim (`glCompressedTexImage2D` / `glTexImage2D`), refuses a chain not halving to 1×1
(`texture_mean_color` reads the 1×1 mip) or an S3TC format on a driver without the extension.
`texture_block_format_resolved(use, channels)` made public: the bracket folds the RESOLVED format
into the key, so a cooked-DXT artefact is structurally unfindable where S3TC is absent and the
compression switches address disjoint entries; the publish-time refusal is belt and braces.

## Wrapped sites and their keys

Every key = recipe version string + the folds below. Savings: [M] measured, [E] estimated
(Phase 0 attributes the 5.3 s lump before any number is quoted).

| recipe | site | key folds | artefact | saving |

| `texture-mips/1` | inside texture_pool_publish (ONE bracket covers all three producers) | level-0 pixel bytes as received (post-dilate), w/h/channels, all four TextureDesc fields, resolved block format | stored-format level stack + internal_format | [M] 145.7 ms per 2048² sRGB |

Erosion hit installs the four planes and **re-runs `terrain_field_build_pyramid`** — level 0
aliases the field's own array (terrain.h:83-92), so serializing levels would break the alias;
the shared `filter_plane` is what makes hit ≡ live. Cluster-DAG hits feed the same counters and
`cluster-probe` digests from restored bytes — **counters count outcomes, not work**; every
startup line and submission arm depends on that. The Jolt restore enters through a
`PhysicsShapeDesc` variant (or sibling entry) beside `physics_create_shape_from_desc`
(physics.c:508).

**Explicitly OUT, stated in cook.h's charter**: the scatter (0.206 s debug / 2.6% release — the
widest key surface of any candidate, and the region group's determinism story is about the LIVE
scatter); the material texture array (GPU resample, scene-dependent tenancy); sky/IBL/LTC LUTs
and captures (GPU, sun-keyed); quadtree patches (lazy, camera-dependent); shader programs (Apple
GL reports zero binary formats, 11.65); the async loader's worker-side decode (v1 is main-thread;
the bracket at publish still covers async textures' mip/encode).

## App wiring

- `GameConfig` gains `const char* cook_dir; bool no_cook;` under `profiler` (its exact precedent:
  must precede `init_engine`, which `create_game` owns). `create_game` calls `cook_init` right
  before `init_engine`; `free_game` calls `cook_shutdown` (prints the summary).
- forest + render parse `--cook` / `--no-cook` / `--cook-dir <p>`. `--cook` = headless one-frame
  run (render: plus the existing async drain) + report; `--cook --no-cook` is a usage error;
  `--cook` on a warm dir exits 0 with `cooked=0`. Other apps inherit through `create_game` /
  `cook_init` defaults; env is their lever.
- Report rows (always printed while enabled — the startup is already narrated; gates read them):
  `cook site=terrain-layer name=grass result=cooked|hit|refused bytes=... key=... ms=...` and a
  `cook-summary dir=... cooked=N hit=N refused=N bytes_written=... ms_bake=... ms_fetch=...`.
  A `refused` row is always followed by the re-cook's `cooked` row.
- `--terrain-erosion-probe` under a hit prints a named refusal ("cook hit; pass --no-cook to
  measure the bake") — a parser fails loudly instead of reading a sim that never ran.

## Gate group `cook` + suite policy

Arms (docstring lists them two-space line-initial, print order = run order; all arms use their
OWN cook dirs under workdir):

| arm | claim | falsifying mutation |
|---|---|---|
| cook-identity | warm run ≡ live run: forest region + erosion digests byte-equal `--no-cook`'s, render-mode-6 frame 0 px; render on the minifying texcomp fixture 0 px cooked-vs-live | swap bark/leaf store keys → canopy draws bark |
| cook-hit | second run of one command bakes nothing: `cooked=0`, hits = run 1's cooks, no bake banners | store filename derived differently from fetch → re-cooks every run |
| cook-key | a dir warmed at seed 1337 serves seed 4242 only the seed-blind sites (veg, DAGs); 4242's digests equal its own live run | drop the seed fold from terrain-layer → wrong-seed hit + frame moves |
| cook-miss | one artefact corrupted byte-wise → refused BY NAME, re-cooked, digests still equal live | delete the checksum verify → no refusal row |
| cook-lever | `--no-cook` against a warm dir: zero hit rows, bake banners present, digests unchanged | ignore the enabled flag in fetch |
| cook-determinism | two cold cooks into two dirs byte-identical per artefact, within one build | timestamp in the header |
| cook-speed | cold/warm/`--no-cook` wall clocks, min of 3, **REPORT-ONLY** — the asserted form of the speed claim is cook-hit's `cooked=0` (a count with no noise floor); startup wall clocks have no honest floor in-suite (11.65 measured them externally). Promotion to asserted non-overlap is one line once the ledger shows comfortable separation | deliberately unasserted, recorded in the ledger |

Suite policy: `gates.py` and `goldens.py` set `CETRA_COOK_DIR` into their workdir right after
mkdtemp — **mandatory**, else arms read the developer's persistent cache possibly cooked by
another build (the exact cross-build contamination verification.md warns about). No pre-warm
pass: transparent accumulation warms the shared dir (first launch of each config cooks, ~50 of
~55 forest launches hit). **The terrain group forces `--no-cook`** (archetype: `terrain-threads`
varies `--erode-workers`, which is deliberately NOT in the key — warm, its three digests are
copies of one artefact, vacuously green on a broken band split; other arms read live-sim probe
rows the hit-refusal would turn into false reds). Cluster group runs WARM deliberately (per-run
dirs mean a mutated builder cooks mutated artefacts) — its mutations re-proven red in the ledger,
falling back to `--no-cook` if any refuses.

## Phase 0 results — the attribution, measured

`startup-ms` k=v rows around every candidate site, `-x -f 1` at 320x200, three samples per
build, medians (spread under 1% on every row — the sites are pure CPU work on a quiet machine):

| site | debug ms | release ms | notes |
|---|---:|---:|---|
| veg-textures | 1796 | 326 | the largest slice, previously unattributed |
| terrain-layers (×4) | 360 | 55 | |
| terrain-splat | 578 | 104 | |
| prototypes (20 meshes) | 797 | 208 | of which cluster-lod 755 / 196 |
| regions (scatter+colliders+Jolt) | 1234 | 83 | matches 11.64's 1.23 s debug internals |
| sky (GPU LUTs + env) | 41 | 41 | not cookable, and not CPU |
| moon-surface (frame 0) | 335 | 63 | |
| on-init total | 4824 | 816 | the rest of 6.58 / 1.36 is GL context + shaders + process |

The cookable slice (veg + layers + splat + cluster-lod + Jolt/collider + moon) is **~4.8 s of
6.58 debug and ~0.75 s of 1.36 release**. The 11.65 attribution ("procedural 1K texture bakes,
20 cluster-DAG builds, the scatter, erosion") was right in kind and missed the ranking:
vegetation is first, and the scatter — the one site this spec declines to cook — is 4% of it.

**The cross-build sharing question is settled per artefact, not per policy.** The
`cluster-probe` row grew an `input=` digest over the builder's input bytes: of the 20
prototypes, the **12 tree meshes differ between debug and release** (tree_gen's float math
moves under -O2) and the **8 rock meshes are byte-identical**. A content-addressed key
therefore shares exactly where the producer's bytes agree and splits exactly where they do
not, with no build-type axis needed — the docs claim in §Docs is worded accordingly.

## As built — the numbers

Forest on the gate fixture (eroded 257×60): **cold 7.54 s debug → warm 2.81 s** (min of 3;
`--no-cook` 7.25 s, so the cache costs nothing when cold and the verb is worth 2.7×). The
shipping config's on-init: **4.9 s → 0.95 s debug** with 59 artefacts hitting — veg 1834→526 ms
(the residual was the publish-side mip encode until Phase 4 cached the chains too), splat
577→2.8, prototypes 823→53, regions 1247→218 (the 218 is the scatter, live by design). Release
on-init 816 → ~250 ms. The cache for the default forest run is ~124 MB on disk.

Nine arms, all green; the plan's `texture_pool_publish_cooked` sibling dissolved into the
derive/upload split (one pipeline, so hit ≡ miss by construction, verified by 29 goldens at
0 px across the refactor); the `--cook` verb needed nothing beyond a headless one-frame run.
CHANGELOG deliberately untouched — entries land at release time, as 11.96–11.98's did.
