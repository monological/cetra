# cetra 14.35: a host's edit joined to the last step

## Context

pcb 7.5's phase 20.3 keeps the person's theme file in order as it is saved from its pane: a save
whose text is out of order -- a row moved, a value given an opacity that moves its comment's column
-- is written back in pcb's order, the person's values and comments kept. pcb writes the ordered
text into the pane with `text_doc_set_text`, and the theme pane undoes with the text's own undo, a
person's own files being no part of the design's timeline.

A host's edit is always a step of its own. So after a save that reorders, the history holds the
person's edit and then pcb's rewrite: `u` takes back the rewrite alone, leaving the text out of
order, the next save writes the rewrite again, and the person's edit can never be undone. Vim meets
the same in a formatter run on save and answers it with `:undojoin`, which joins the next change to
the step before it.

Asked, the user chose this change in cetra over a pcb-only answer -- no rewrite on a save after an
undo, which needs two presses of `u` for every edit that was put in order, the first seeming to do
nothing (pcb 7.5, 2026-11-13).

Branch and spec: `14.35-a-host-edit-joined-to-the-last-step`, off cetra's master (`5c4531e9`).

## The design

In `text_doc.h`, beside `text_doc_set_text`:

```c
// The same, joined to the last step of undo where that step is the text's latest -- nothing has
// changed the text since its last action -- so one undo takes back both, as vim's :undojoin; a step
// of its own otherwise.
bool text_doc_set_text_joined(TextDoc* doc, const char* text, size_t len);
```

- **Joined as an action of the step is**: the change becomes the step's last part, through the
  path a group's actions take, so undo takes back the host's change and then the person's, and redo
  makes them again in order. The step's selections after are moved through the host's change, as
  the editors' carets were, so a redo leaves them where the edit left them.
- **Only the latest step joins**: one whose version is the text's. After an undo, a redo, an edit
  unkept with `keep_undo` off, or with no step at all, the edit is a step of its own, as
  `text_doc_set_text`'s is. A host keeping every state it saves in order meets no such case: undo
  lands on a text already in order, which it does not rewrite.
- **Typing after it starts a step**: the joined edit seals the typing, whose ends it may have moved,
  so a word typed after it is not merged into the step. A group held open stays open, its next
  action joining the step as before.
- **`text_doc_replace` gains no twin** until a host needs one; both join through one private
  function, so it costs a line when one does.

## As built

### Phase 1: the join (`28a323ca`)

- **One host's edit**: `_host_replace` checks the bytes, makes the change and keeps it, a step of
  its own or, joining, the last step's last part through `_keep`'s `KEEP_PART`, the path a group's
  actions take. It joins where the last step's version is the text's as the change begins, with
  `keep_undo` on; anything else is the step of its own `text_doc_replace` always made, which drops
  the redo as before. `_host_set_text` trims the shared ends and hands the one replacement on;
  `text_doc_replace`, `text_doc_set_text` and `text_doc_set_text_joined` each name themselves in
  what is refused.
- **Joined**: the step's selections after are copied and moved through the change as a view that
  is not its actor is, and kept as the step's after; the typing is sealed; a group's state is left
  as it was, so a group held open goes on joining its step.
- **Tests**: `ui-doc-undo` has seven lines more, 26: typing then a joined edit one step, the caret
  moved past the host's insertion; one undo back to the empty text with the caret at 0; a redo
  making both with the caret moved again; after an undo, a joined edit a step of its own with the
  redo dropped, undone alone; typing after a joined edit a step of its own, undone to the joined
  text. Falsified three ways, each caught by name: the join refused (`joined one`, `joined undone`,
  `typing own`), the typing left unsealed (`typing own`, `typing undone`: the typed byte was merged
  into the host's insertion), the selections after left unmoved (`joined redone`). The arms the
  host's edits and undo reach passed, 17 of the ui group's: the six other `ui-doc-` arms,
  `ui-editor-host-undo`, `-host-edit`, `-steps`, `-set-doc`, `-read-only` and `-ranges-late`,
  `ui-vim-undo`, `-host`, `-set-doc` and `-read-only`; and `gate-arm-docs`.
- **Docs**: `docs/ui.md`'s host's edits and Undo; 14.35 in `docs/eda-roadmap.md`. `docs/modules.md`'s
  row for `text_doc.c/h` needed nothing.

### Phase 2: the reviews (`ce6ff1fa`)

`/simplify`'s four and the thermo-nuclear over `5c4531e9..HEAD`, background agents at effort high,
applied once all were back.
- **Applied:**
  - **One home for the join rule** (reuse, altitude, thermo-nuclear): `_latest_step(doc, from)`,
    the last step when it was made from `from` with `keep_undo` on, which `_keep` and the host's
    edit both ask, where each had held its own copy of the test.
  - **One `_keep` for a host's edit** (thermo-nuclear): the step's selections after are copied and
    moved before the change, the branches differ only in their bookkeeping, and no pointer into
    the steps is held across `_run`, which lets them go when it runs out of memory.
  - **A group's selections let go when it joins** (thermo-nuclear, altitude): a group opened before
    a joined edit held its selections where the change had moved, and its first action began its
    step there, so an undo put the caret short by what the host inserted. Both branches drop them,
    and the first action starts its step where it finds the caret. `ui-doc-undo` holds it, 27
    lines; kept on a joined edit, `group before` failed.
  - **A step's version moves only once it holds the action** (thermo-nuclear): `_keep` moved it
    first, so a step that could not take an action out of memory claimed a change it did not hold.
  - `text_doc_seal_undo` where the typing was sealed by hand; the two guards on the copied
    selections, whose count is 0 when the copy is NULL; the header's contract in one sentence; the
    comment on `_host_set_text` that repeated its signature.
- **Skipped:**
  - Moving a step's selections after inside `_keep` for any part kept with none (altitude): it
    would change what a viewless edit inside a group leaves, behaviour outside this spec.
  - `_host_replace` without the name it is refused under (simplification): the design has each of
    the three name itself, as `_may_change` and `_history_reaches` do.
  - Copying the selections once, not twice (efficiency, which found nothing else): once a save, and
    `_keep`'s contract would take a special case.
- **Verified**: the 17 arms of phase 1 and `gate-arm-docs` passed again.
