# cetra 14.35: a host's edit joined to the last step

## Context

pcb 7.5's phase 20.3 keeps the person's theme file in order as it is saved from its pane: a save
whose text is out of order -- a row moved, a value given an opacity that moves its comment's column
-- is written back in pcb's order, the person's values and comments kept. pcb writes the ordered
text into the pane with `text_doc_set_text`, and the theme pane undoes with the text's own undo, a
person's own files being no part of the design's timeline.

A host's edit is always a step of its own. So after a save that reorders, the history holds the
person's edit and then pcb's rewrite: `u` takes back the rewrite alone, leaving the text out of
order, the next save writes the rewrite again, and the person's edit can never be undone. Vim meets
the same in a formatter run on save and answers it with `:undojoin`, which joins the next change to
the step before it.

Asked, the user chose this change in cetra over a pcb-only answer -- no rewrite on a save after an
undo, which needs two presses of `u` for every edit that was put in order, the first seeming to do
nothing (pcb 7.5, 2026-11-13).

Branch and spec: `14.35-a-host-edit-joined-to-the-last-step`, off cetra's master (`5c4531e9`).

## The design

In `text_doc.h`, beside `text_doc_set_text`:

```c
// The same, joined to the last step of undo where that step is the text's latest -- nothing has
// changed the text since its last action -- so one undo takes back both, as vim's :undojoin; a step
// of its own otherwise.
bool text_doc_set_text_joined(TextDoc* doc, const char* text, size_t len);
```

- **Joined as an action of the step is**: the change becomes the step's last part, through the
  path a group's actions take, so undo takes back the host's change and then the person's, and redo
  makes them again in order. The step's selections after are moved through the host's change, as
  the editors' carets were, so a redo leaves them where the edit left them.
- **Only the latest step joins**: one whose version is the text's. After an undo, a redo, an edit
  unkept with `keep_undo` off, or with no step at all, the edit is a step of its own, as
  `text_doc_set_text`'s is. A host keeping every state it saves in order meets no such case: undo
  lands on a text already in order, which it does not rewrite.
- **Typing after it starts a step**: the joined edit seals the typing, whose ends it may have moved,
  so a word typed after it is not merged into the step. A group held open stays open, its next
  action joining the step as before.
- **`text_doc_replace` gains no twin** until a host needs one; both join through one private
  function, so it costs a line when one does.
