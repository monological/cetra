# 11.64 — paying down what 11.63's review found and 11.63 did not fix

## Context

Spec 11.63 shipped and merged. Its nine-agent review produced ~110 deduped findings; **34 were
applied** — every correctness bug, every gate-soundness defect, the worst of the false comments.
The rest were skipped under "outside the reviewed diff", which was doing more work than it should
have been. This spec is the paydown, on the user's standing instruction: **refactor for structure
even where there is no measured performance win.**

Two verification results shape it, and both cut against the review:

- **The review is reliable on correctness and unreliable on sizing.** All 9 correctness findings
  were real. But `_grid_tiles`' "easy win" is rejected by its own docstring; `_region_run`'s
  "wasteful default" has one caller; `sample_ground`'s "5 evals → 2.4" was never timed. Every
  number here is re-measured or marked unmeasured — none is carried forward.
- **Four items are unfinished work from the review pass, not backlog.** They are listed first and
  are not optional.

## The axis that organises this

Not category — **whether an item can move a rendered pixel or a gate number**, because that
decides how it is verified.

| | moves a pixel or gate number? | verified by |
|---|---|---|
| **A** — deletions, shared helpers, dead params, comment fixes | **No, by construction** | `goldens.py` 0 px + touched gate groups' numbers **identical**, not merely green |
| **B** — gate-suite runtime | **No** — `gates.py` only | identical suite result, lower wall clock |
| **C** — RNG order, float rounding, flag meaning | **Yes, deliberately** | measured before/after, re-baselined arms, A/B crops |

A non-zero golden diff on a Group A change means the change was not what it claimed. That is the
point of the split.

## Phase 1 — Group A, cannot move a pixel

Ordered by value per unit risk. Each is one commit.

**Tier 1**
1. **`_upload_float_stream` / `_upload_int_stream`** (`cetra/src/mesh.c:285` + `:296-400`). The
   existing `_upload_morph_stream` is one parameter short of absorbing five float blocks
   (normals/tangents/uv0/uv1/colors, six lines each at counts 3/4/2/2/4) and two int blocks. This
   is the copy-paste substrate that produced the uninitialised-field bug 11.63 shipped.
   *Size: the review said −75, I counted −30 for the float half alone. Report the real number.*
2. **Hoist `sample_ground`'s margin box** (`forest.c:546-548`) — `margin` and four
   `terrain_world_*` calls recomputed on ~118k attempts for terrain constants. **Hoist to once
   per `scatter_trees`/`scatter_rocks` CALL, never to an init-time static**: the bounds derive
   from `g_terrain.center`, which an origin shift moves, and `regions_rebuild` re-scatters after
   exactly that — a static would place every post-shift prop against a stale margin. Per-call is
   bit-identical.
3. **Swap the flow test above the normal test** (`forest.c:552` vs `:558`) — **the free half of
   the reorder.** Both are pure and neither consumes `rnd()`, so the accepted set and the stream
   are untouched. Honest sizing: with no `--erode` field, `terrain_mask_at` returns 0 in two
   instructions and never rejects, so the win exists only under an erosion bake — this is a
   cheapest-first structure fix, not a default-path speedup. *The waterline half is Group C.*
4. **Hoist `kept`** (`terrain.c:587`) — `analytic_octaves(terrain_level_cell(...))` is a pure
   function of `(p, level)` recomputed per height *sample*. Shape: an internal
   `height_at_level_kept(p, x, z, kept)`; the public function computes `kept` once and delegates;
   `build_grid` and `terrain_normal_at_level` hoist it. Honest sizing: ~octaves float-mults per
   sample against perlin evals that dwarf them — structure, small win.

**Rejected from Tier 1, recorded so it is not re-filed:**
- **`fill_morph_targets` reading the cached parent's vertex heights** (the review's "bit-identical,
  −405 fbm evals per patch") — **rejected twice over.** It is not bit-identical: an odd-indexed
  child's even nodes reach the parent's coordinates through a different float expression tree, so
  the stored heights differ by ulps from what the function currently evaluates. And it is worse
  than not-bit-identical: `fill_morph_targets` lives in `terrain.c`, which cannot see the quadtree
  cache, so the parent mesh would have to be threaded in from `terrain_quadtree.c` — making the
  morph target depend on whether the parent HAPPENED to be cached when the child was built. A
  surface that depends on selection history is exactly what CPU-built patches exist to prevent.

**Tier 2 — clean deletions** *(the two structural ones verified: `RegionNode.group` has exactly
two uses, both dead once `free_node` unlinks; `mesh_cluster_stats` has exactly one caller)*
`mesh_lod_eligible` shared between `cluster_build.cpp:131-148` and `lod.c:51-66` (−20) ·
`RegionNode` collapses to a bare `SceneNode*` now that `free_node` unlinks, killing dead
`remove_child_node` calls (−15) · cluster stats off `Mesh` into the builder's out-param (−15,
12 bytes off every mesh) · one `gates.py` forest runner replacing eight hand-written command

the parsers stay where they are) · `grow_array` in `util.h` for four hand-rolled doubling loops
that silently drop OOM (−20) · **delete the pyramid's three unread mask planes**

**Rejected from Tier 2:** de-exporting the `terrain_*_level*` functions. `terrain_height_at_level`

## The measurement that retired Group C, and most of the perf backlog with it

Everything below this line was written before forest's startup was profiled. It has been, and
the premise did not survive.

**Where forest's startup actually goes, at the shipping configuration, `-f 1`:**

| | debug (`out/bin`) | release (`out/release/bin`) | ratio |
|---|---:|---:|---|
| total startup (user) | 6.57 s | **1.40 s** | 4.7x |
| Jolt BVH build (per-region collider) | 0.981 s | **0.040 s** | 24x |
| collider mesh build | 0.042 s | 0.007 s | 6x |
| `sample_ground` (the whole scatter) | 0.206 s | **0.036 s** | 5.7x |
| node emit (~7,000 nodes) + Morton sort | 0.004 s | 0.001 s | — |

**Three things follow, and the third is the one to carry.**

*The perf backlog was measured on `-O0`.* In release the scatter and the colliders together are
0.083 s of a 1.40 s startup — 6%, not the 26% a debug build reports. Every perf-motivated item in
this spec was aimed at a slice that size or smaller, so they are dropped rather than deferred:
`PF-3`'s hoisted `kept`, `PF-14`'s scratch buffer, `PF-8`'s index window, and `C1`'s full
rejection reorder. C1 was separately measured at **0.8% over four interleaved samples**, because
residency only loads regions near the camera and the camera spawns on land, so the waterline test
almost never fires on the resident set.

*The largest region-load cost is Jolt's BVH builder*, at 85% of collider time in BOTH builds — and
no reviewer found it, because it is inside a vendored library and none of the code they were
reading is where the time goes. Out of scope here; the levers are collider resolution per region
or moving the build off the load path, and anyone trying to make mid-walk region loading smooth
should start there rather than with anything in this spec.

*AGENTS.md already carried this warning, for the erosion bake, and it did not prevent the
mistake.* The rule is not "remember that debug is slow" — it is that **a timing from `out/bin` is
not a measurement**, and the failure mode is that it makes cheap things look expensive in exactly
the proportion that motivates work on them. This is the second recorded instance.

**What survives:** the structural work and the false comments, justified on structure alone. The
mesh upload helpers still delete the duplication class that shipped 11.63's uninitialised-field
bug; that argument never depended on a clock.

## Phase 2 — Group B, gate runtime

- **Memoize `_forest_run` on `(extra, cam)`.** `cluster_dag`/`lod_on` and `cluster_nolod`/`lod_off`
  are byte-identical commands differing only in output filename — two 20-frame 800×450 runs.
- **`_grid_tiles`' 1,024-tile build needs a decision, not a fix.** It burns ~12.3 M fbm
  evaluations to read one integer, but its docstring deliberately rejects the obvious fix:
  *"It still has to be a real run rather than arithmetic on the extent, or an app that quietly
  stopped growing its grid would be read as the quadtree's win."* Printing the count earlier does
  not help — `on_init` builds regardless. Making it cheap needs an early-exit flag, i.e. a small
  feature. **Default: leave it and record why**, so the next reader does not re-file it.
- **`_region_run`'s 400 frames: leave.** One caller uses the default, and it is the walk that
  `region-return`, `region-leak` and `region-collider` all read.

## Verification

```bash
./build.sh
python3 scripts/goldens.py                        # 25/25 at 0 px, every Phase 0/1/2 commit
python3 scripts/gates.py --only <touched groups>  # numbers IDENTICAL, not merely green
python3 scripts/gates.py                          # once, at the end
```

Each commit builds in isolation — checked, since that is how 11.63's broken intermediate was
found. Group C items get a measured before/after in the commit message; C3b gets A/B crops before
landing. Standing rule: forest is not pixel-deterministic with the sky on, so pixel reads use
`--render-mode 6` or `--no-sky` and the floor is measured at the exact framing first.
