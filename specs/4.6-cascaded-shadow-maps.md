# Tier 2 · 4.6 — Cascaded Shadow Maps

## Context

The shadow system spreads one fixed 2048² ortho map across each caster's entire fitted
volume — a world-origin-centered box of ±2·scene_radius, camera-independent, with no texel
snapping (it never needed any). On a single centered asset that's fine; on large scenes
(japanese-house, big grounds) resolution starves, and the fog spec documents the coverage
gap. §4.6 splits the camera frustum into N depth slices, each cascade an ortho map fitted
tightly to its slice: near shadows get high effective resolution, texel snapping kills the
shimmer camera-fitted maps otherwise produce, and PCSS keeps working via per-cascade
geometry parameters. Design validated by two exploration passes + an architecture review.

**Verified consumer inventory (every seam anchored):** pbr_frag calculateShadow (PCF +
16+16-tap PCSS, all geometry inputs GLOBAL scalars today), catcher_frag (5×5 PCF × casters,
matrices uploaded render.c:711-722), fog_frag (per-caster affine march hoist — one line
cannot span cascades), shadow_publish_to_postfx + POSTFX_FOG_MAX_LIGHTS assert,
uniform_cache_shadows literal 3 (program.c:410), the max-light budget constant
(USED_UNIFORM_COMPONENTS=77, util.c:26-38), and probe capture (works ONLY because fitting
is camera-independent; one depth bake serves all 6 faces).

## Design (validator-amended)

**Layering — uniform cascading, count-strided:** every caster gets `cascade_count` cascades
(runtime 1..SHADOW_CASCADES=3 on ShadowSystem); **layer = slot * cascade_count + cascade**
(stride by the RUNTIME count — at count==1 layers are 0,1,2 exactly as master, which is the
byte-identity linchpin; striding by the compile-time constant is the likeliest silent
gate-breaker). Array allocated to `MAX_SHADOW_LIGHTS * cascade_count` layers, reallocated
on count change (no 3× VRAM at the default; 9 layers ≈ 151MB only when requested). Depth
pass renders active_count × cascade_count traversals. One code path in all four consumers.
Known cost cliff: the depth pass re-uploads skinning uniforms per mesh per traversal — 9×
bone uploads on animated scenes is the CPU cost to MEASURE in M1 (per-cascade culling is
the later escape, not M-scope).

**count==1 byte-identity discipline:**
- Fitting branches at the top: count==1 uses the existing
  `compute_directional_light_space_matrix` with ss->ortho_size/near/far verbatim (never the
  snap path). Nothing else reads those three fields (grep-verified) — they survive as the
  legacy-fit inputs + scene-extent clamp source.
- Selection loop degenerates structurally (`for i < cascadeCount-1` never runs at 1).
- Scalar→array reads (cascadeParams[layer]) carry identical uploaded values through
  identical expressions; the `2.0f * ortho_size` computation stays CPU-side.
- No blend band anywhere in v1 (also keeps the gate clean).
- Fog's count==1 path reduces to exactly today's single bounds-check + tap.

**Fitting (count>1): sphere-of-slice + texel snap.** Split [cam_near, shadow_distance] by
the λ=0.75 log/uniform mix; per-cascade ortho box sized from the slice's bounding sphere in
light space (rotation-invariant diameter → stable under orbit; the ~1.5-2× texel waste is
the standard price and still nets a large win over today's 4r-wide box); center snapped in
light view space by diameter/map_size increments (diameter constant per slice); **box near
plane EXTENDED toward the light to scene extent** (a tight slice near-plane clips
out-of-slice casters — tall geometry shadowing the near slice); shadow_distance is app
policy (scene-scaled ~8r). The cascade fitting variant takes a small camera-slice struct
(not Engine*) to keep shadow.c decoupled; camera data is available at the engine.c call
site.

**Per-cascade parameters:** `mat4 lightSpaceMatrix[9]` + `vec4 cascadeParams[9]` =
**(frustumWidth, near, far, biasScale)** — texelSize stays a GLOBAL (map size is uniform
across layers; the .w slot belongs to the per-cascade texel-proportional bias, not texel)
— + `vec4 cascadeSplits` + `int cascadeCount`. PCSS's linearize/penumbra math reads
cascadeParams[layer]. Budget: +~130 components → USED_UNIFORM_COMPONENTS 77 → ~210 (audit
exact at implementation); floor-spec max lights 45 → ~38, harmless. uniform_cache_shadows
+ the program.c literal 3 grow to 9.

**Cascade selection (pbr + catcher):** per-fragment by view-space depth vs cascadeSplits,
HARD boundaries (the seam artifact is filter-width discontinuity, not occlusion
disagreement; at 2048/cascade with PCSS softness it's usually below notice; dither/blend is
the follow-up ONLY if the A/B shows it). catcher_frag already has the view uniform; its
large grazing ground plane is the designated seam A/B surface, with a per-cascade kernel
scale as the ready fix.

**Fog march:** hoist lsBase/lsDelta per (caster, cascade); per-step fall-through — try
cascade 0's affine projection, on out-of-bounds fall to next, lit after last. Validated:
any in-bounds cascade holds correct depth (each renders the whole scene), index order picks
the TIGHTEST covering cascade (at-worst-equal to view-depth selection, occasionally
better), per-step flips perturb only resolution and are absorbed by the march jitter +
temporal accumulation. Fog keeps the single published fog_shadow_bias scalar (per-cascade
bias there is scope creep); fog layer indexing uses the same stride-by-count rule.

**Publish block:** fog_light_space → flattened [POSTFX_FOG_MAX_LIGHTS ×
POSTFX_FOG_CASCADES]; new `_Static_assert(POSTFX_FOG_CASCADES == SHADOW_CASCADES)` beside
the existing caster assert; publish gains a cascade inner loop + published cascade count;
postfx upload loop grows.

**Probe capture:** save/force cascade_count=1/restore in the EXISTING capture isolation
block — the restore must sit in the end-of-capture restore side so the force spans the six
face renders (bind_shadow_maps_to_program reads ss state per face), not just the depth
bake. Lands in M1 with the first count>1 code, not later.

**Defaults & GUI:** library default stays cascade_count=1 (create_shadow_system);
the VIEWER app flips to 3 in M4 at the policy site (the PCSS-opt-in precedent). GUI:
cascade count control + cascade-tint debug toggle in the Shadows group.

## Milestones (branch `csm`, `git commit -S -v`)

**M0 — bridge.** `ShadowSystem.cascade_count` (default 1) + SHADOW_CASCADES constant +
`--shadow-cascades <n>` flag, count==1 semantics only. *Gate:* c64 + raiden byte-identical
to master.

**M1 — cascaded depth + PCF selection + debug + probe isolation.** Count-strided layer
layout + realloc-on-change; camera-frustum split/sphere-fit/snap (count>1 path); depth-pass
cascade loop; per-cascade matrices/params upload; pbr_frag selection + per-cascade PCF;
`--csm-debug` cascade-tint view; probe force-to-1; **cascade-0 compatibility shims for
catcher + publish** (they upload each slot's cascade-0 matrix until M2/M3 give them real
selection). *Gates:* count==1 byte-identical everywhere; count==3 japanese-house A/B shows
visibly sharper near shadows; tint view shows sane splits; determinism ×2; snap stability
(orbit strip: no edge crawl; CPU check: repeated identical frames → identical matrices);
depth-pass cost measured on raiden (the 9× skinning-upload cliff).

**M2 — PCSS per-cascade + catcher selection.** cascadeParams drive blocker/penumbra math;
catcher per-fragment selection. *Gates:* count==1 byte gates hold incl. --shadow-softness
suite; count==3 penumbra continuity at a boundary on the catcher plane (the designated seam
surface); japanese-house ground shadows correct.

**M3 — fog + publish growth.** Per-cascade hoists + fall-through; publish/postfx/asserts.
*Gates:* fog suite byte-identical at count==1; fog+CSM on c64 consistent with count==1
(RMSE + eyeball); far-coverage improvement visible on a large scene.

**M4 — viewer default flip + policy + GUI + roadmap.** App default 3 + shadow_distance
policy; GUI; roadmap §4.6 ✅ + table + sequence; memory notes. *Gates:*
`--shadow-cascades 1` remains the byte bridge; probe+CSM capture deterministic and
artifact-free; full-suite visual pass.

**M5 — review fanout** (/thermo-nuclear + /simplify, ALL run_in_background); user merges.

## Risks

1. **count==1 byte-identity** — the central discipline; the stride-by-count rule is the
   known trap; gates at every milestone.
2. **Shimmer** — sphere-fit + snap mandatory in M1; verified by orbit strips + the
   identical-matrices CPU check.
3. **PCSS/PCF filter-width seams** — hard select first; catcher plane is the sentinel;
   blend band and per-cascade kernel scale are the ready follow-ups.
4. **Depth-pass CPU cost on animated scenes** (9× skinning uploads) — measured in M1;
   per-cascade culling is the later escape.
5. **Near-plane clipping of out-of-slice casters** — the extend-toward-light amendment is
   load-bearing; the japanese-house interior (tall walls) is the test.
