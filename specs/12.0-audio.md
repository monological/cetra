# Spec 12.0 — Audio

## Context

The rendering roadmap is closed. `docs/game-engine-status.md` lists what the engine lacks as a
game platform, smallest-effort-first, and with gamepad input landed (11.109) the next item is
**audio**: "No game ships silent." Today there is no audio anywhere — `COMPONENT_AUDIO_SOURCE`
is a bare enum stub (`cetra/src/game/component.h:13`), and no sound/miniaudio/OpenAL code exists
in the tree. This spec adds a real audio subsystem: an output device, 2D fire-and-forget SFX and
music, 3D positional sound with the camera as listener, the dormant `AUDIO_SOURCE` component
implemented, and a headless gate group that verifies the spatialization math with no device and
no committed audio files.

**This is 12.0 — the first spec of the game-platform era.** 11.109 stays the last renderer-era
spec; a one-line pivot note goes in `game-engine-status.md`. Numbering restarts a major here
because the *kind* of work changed (renderer → game platform), which is what every prior major
bump marked.

## Design

### The library and the seam
miniaudio, single-header C, vendored under `cetra/src/ext/miniaudio.h` — no new build dependency,
carries its own OS backends (CoreAudio / ALSA / WASAPI). We wrap its high-level `ma_engine`
(3D spatialization, sound groups, streaming, fades — all built in); we do not rebuild any of it.

The seam mirrors gamepad's reader seam exactly:
- **Windowed** → `ma_engine` on the default device (real-time audio thread).
- **Headless** → `ma_engine` in **`noDevice` mode**: opens no device, renders offline via
  `ma_engine_read_pcm_frames`, so the graph is a pure deterministic function of frames pulled.

That headless mode is both the CI-safety story (no device enumeration on a gate box) and the
verification story (the offline PCM is what the `audio` gate asserts on). The real device path —
actual playback quality, other OSes — is owed a human's ears, stated in the ledger like 11.109's.

### Ownership — a Game subsystem, like physics
`AudioSystem` owns the one `ma_engine` device. Built by the app with `create_audio_system`,
installed on the `Game` with `game_set_audio_system` (takes ownership, frees on replace), and
freed in `free_game` **after the entity manager, before the engine** — because
`COMPONENT_AUDIO_SOURCE` components hold `ma_sound` handles that live in the engine, so the
entity manager (which frees those components) must tear down while the `ma_engine` is still alive.
This is the exact physics ordering (`game.c:41-73`, entity manager then physics world).

Files live under `cetra/src/game/` — auto-public as `cetra/game/audio.h` (the `game/` tree is
allowlisted; no `CETRA_PUBLIC_HEADERS` edit). `cetra/src/game/audio.c` is also the single TU that
does `#define MINIAUDIO_IMPLEMENTATION` then `#include "../ext/miniaudio.h"` — the stb-in-import.c
pattern (`import.c:18`). Structs use 11.108's three banners; names follow 11.106 (subject-first,
`create_X`/`free_X`, `x_get_y` logs / `x_find_y` silent, mutators void+log / bool on a refusable
request).

### The API (`cetra/src/game/audio.h`)
```c
typedef struct AudioSystem AudioSystem;   // owns ma_engine
typedef struct Sound Sound;               // a playable voice; wraps ma_sound

typedef enum { AUDIO_BUS_MASTER, AUDIO_BUS_MUSIC, AUDIO_BUS_SFX, AUDIO_BUS_UI } AudioBus;

AudioSystem* create_audio_system(struct Engine* engine); // noDevice iff engine->headless
void free_audio_system(AudioSystem*);
void audio_set_bus_volume(AudioSystem*, AudioBus, float); // master + three ma sound groups

// 2D fire-and-forget (UI, music). A one-shot self-reaps; music returns a handle for stop/loop.
void   audio_play_oneshot(AudioSystem*, const char* path, AudioBus, float volume);
Sound* audio_play_music(AudioSystem*, const char* path, bool loop);

// A held voice: from a file (WAV/MP3/FLAC decode) or a procedural waveform (no asset).
Sound* audio_sound_from_file(AudioSystem*, const char* path, AudioBus);
Sound* audio_sound_from_tone(AudioSystem*, float hz, AudioBus); // ma_waveform data source
void   audio_sound_play(Sound*);  void audio_sound_stop(Sound*);
void   audio_sound_set_looping(Sound*, bool);
void   audio_sound_set_volume(Sound*, float);
void   audio_sound_set_position(Sound*, vec3 world_pos); // enables 3D spatialization
void   free_sound(AudioSystem*, Sound*);

// Once per frame: listener from the camera, reap finished one-shots, push component positions.
void audio_system_update(AudioSystem*, vec3 listener_pos, vec3 forward, vec3 up);

// Headless only: render offline. Returns 0 in device mode. The gate's readout.
size_t audio_system_read_pcm(AudioSystem*, float* out, size_t frames);
```

### The component and per-frame drive
`COMPONENT_AUDIO_SOURCE` implemented off the RIGID_BODY template (`physics.c:653-663`): an
`AudioSource { struct Entity* entity; Sound* sound; ... }`, `entity_add_audio_source` (calls
`entity_add_component` + `entity_set_component_free`), `entity_get_audio_source`. Each frame the
subsystem walks `entity_manager_foreach_with(COMPONENT_BIT(COMPONENT_AUDIO_SOURCE), ...)` and sets
each sound's position from `entity->position` (current — physics/character have written it).

`audio_system_update` is called **once per rendered frame** from the game framework, after the
fixed-step loop settles positions, reading `engine->camera` for the listener
(`forward = normalize(look_at - position)`, `up = up_vector` — `camera.h:28/29/37`; no accessor,
read the borrowed pointer). One-frame listener latency is accepted, exactly as particles accept it.
Non-framework apps (`apps/render`) get no audio in v1 — the engine second-home hook (the
`if (!frame_clock)` site at `engine.c:2527`) is a deferred non-goal, noted not built.

### The demo (gametest) — procedural tones, no committed assets
- Jump and spawn fire `audio_play_oneshot` with a short `ma_waveform` tone (distinct pitches).
- One looping positional tone attached to a node/entity (the hinge door or a beacon), so circling
  it demonstrates pan and distance falloff by ear.
- Master/bus volume reachable; `--mute` for a silent run.
- The file-loading API is built and exercised, so dropping real SFX into `assets/audio/` later
  needs no engine change. No binary audio ships in this spec.

### The `audio` gate group (`scripts/gates.py`)
gametest gains `--audio-probe <case>`: headless (noDevice), it plays a fixed procedural geometry,
renders a fixed duration via `audio_system_read_pcm`, and prints `audio window <n> rms <l> <r>`
lines a regex reads (the `_GAMETEST_TRACE` shape). Arms, each defeating a plausible wrong impl:
- `audio-onset` — a tone starts at a known frame: PCM silent before, energetic after (an always-on
  or never-on bug fails).
- `audio-pan` — source hard-left vs hard-right: L/R energy imbalance in the correct direction (a
  mono/centered bug fails; it is a ratio, not "louder").
- `audio-distance` — source near vs far on one axis: near RMS / far RMS above a floor (no
  attenuation fails).
- `audio-master` — master bus 0 → silence, 1 → energy (a volume that does not route fails).
- `audio-decode` — synthesize a tiny sine WAV into the run's tmp dir, load it via
  `audio_sound_from_file`, render, assert energy (covers the real decode path with no committed
  binary).
Registered in `GATE_GROUPS` after `gamepad`, arm list in the docstring (`gate-arm-docs` holds it).

## Verification, and what can be checked on this Mac
- **The `audio` gate group** is the proof for everything above the device seam: onset, pan,
  distance falloff, bus routing, and the file decode path — all deterministic, headless, here.
- **By hand, windowed:** jump/spawn are audible; the looping positional source pans left/right and
  quietens with distance as you walk around it. Needs your ears.
- **Not verifiable here:** the real device path on Linux/Windows (this Mac builds only the Apple
  backend; `-ldl`/WASAPI link is owed a `docs/build-vms.md` run), and subjective playback quality.
  The ledger says which was run.
- **Goldens** are unaffected by design and run to prove it.

## Risks
- **Headless CI must open no device.** `noDevice` mode opens nothing and enumerates nothing —
  the mitigation is structural, gated on `engine->headless` the way the hidden window is.
- **Cross-platform link untested here.** macOS only on this machine; Linux `-ldl`/ALSA and Windows
  WASAPI are owed the build VMs, stated in the ledger (the 11.109 device-path precedent).
- **Device-mode audio is not deterministic** (real-time thread) — which is why the gate uses
  `noDevice` and windowed audio is verified by ear, not asserted.
- **miniaudio is a ~90k-line header** compiled into one TU — a one-time build-time cost, like
  assimp; it rebuilds one object on an audio edit, not the tree.
- **Thread safety:** `ma_engine` playback controls are documented thread-safe; the game thread
  calls them once per frame. `noDevice` has no audio thread at all.

## Non-goals
DSP effects beyond miniaudio's built-ins (reverb, filters); `.cscn` audio authoring (the format
extends cleanly by the `parse_wind`/`parse_dust` template — deferred, noted); the engine
second-home so non-framework apps play sound (deferred); HRTF / Steam Audio (a later backend);
committed real SFX or music (a content task — the file API is built for it).
