# Spec 11.80 — the night-sky floor

## Context

Roadmap row 47 / **B12**, the item B11 explicitly depends on. 11.79's night is stars over
a void: Hillaire models scattered SUNLIGHT only, so once `sky_apply_sun_to_light` fades the
key light out (3°→0°, `sky.c:677`) the env cube goes black with the sky and the world below
the star field is unlit. The real night sky between the stars is not black — airglow,
zodiacal light and integrated starlight hold it at ~2e-4 cd/m² — and that floor is what a
moonless world is lit BY. Every night screenshot of tree shows the gap.

User decisions locked in: implement B12 now, alone (moon = B13, Purkinje = B14, cycle =
B11, all booked as rows). Library OFF by default, tree ON — the stars precedent, for the
same golden-protection reasons.

## The insertion point — one term in the sky-view LUT bake

The floor must reach the GROUND, which is what separates it from the stars: it has to be in
the env cube and the IBL, and it may be — the firefly rule that bans the sun disc and the
stars from `sky_env_frag` bars POINT sources aliasing the prefilter importance sampler,
not a near-constant field.

The judo: **everything that needs the floor already samples the sky-view LUT.**
`sky_background_frag` (via `skyRadiance`), `sky_env_frag` (above-horizon texels →
env cube → `ibl_bake_from_cubemap` → irradiance + prefilter → every lit surface including
the water's split-sum), and `cloud_march_frag` (its ambient tap). So the floor is ONE
addition at the end of `sky_view_frag.glsl`'s march:

```glsl
// after the loop, where `through` holds transmittance to the top of atmosphere:
vec3 sky = min(L * SUN_ILLUMINANCE, vec3(100.0));
if (!ground)
    sky += nightFloor * through;   // uniform vec3, premultiplied on the CPU
FragColor = vec4(sky, 1.0);
```

Four properties fall out:
- **The ground cut is free** — `ground` is already computed (`sky_view_frag.glsl:61`), and
  a ground-hitting ray must not glow.
- **Horizon extinction is free** — `through` is the ray's own accumulated transmittance,
  so the floor dims and warms toward the horizon exactly as the airglow shell's light
  would, with no new lookup.
- **The re-bake cadence is already correct** — the LUT re-bakes on sun moves
  (`sky_bake_view_lut`), and the ramp is a pure function of sun elevation, so the floor
  can never be stale.
- **Off is bit-exact** — `nightFloor = vec3(0)` adds `0.0` to non-negative floats, so the
  default-off path is byte-identical, which is what keeps all 27 goldens at 0 px.

The stars layer cleanly on top: `skyRadiance` adds them AFTER sampling the LUT, so
background = floor + stars with no double count.

**The one twin: `sky_zenith_radiance` (`sky.c:189`)** — the CPU march that feeds the fog
ambient (`publish_fog_ambient`, `sky.c:404-408`), cached on sun move by
`sky_update_sun_dir`. It early-outs to zero below the horizon; the floor term is added
BEFORE that early-out (an isotropic skyglow field contributes its radiance as ambient
directly), so night fog stops being pitch black. The file already carries hand-mirrored
GLSL constants under a SOURCE-OF-TRUTH sync comment (`sky.c:97-115`) — the floor's base
color and radiance constants follow that precedent: defined in the shader, C copies beside
the `SKY_*` block with the same comment.

## State, ramp, and the exposure honesty

**`sky.h`**, beside the stars group: `bool night_floor_enabled; float
night_floor_brightness;` (1.0 = the shipping look; the base radiance and the restrained
blue-grey color are shader constants, not knobs — nothing varies them, and a color nobody
sets is a reviewer finding). Library default off; tree on.

**The ramp is shared with the stars, and extracting it is part of the spec**: a static
`sky_night_factor(const SkyAtmosphere*)` in `sky.c` returning
`1 - glm_smoothstep(-8, 3, elevation)`, used by (a) the star-intensity upload in
`sky_render_background`, (b) the `nightFloor` uniform in `sky_bake_view_lut`, (c) the
zenith twin. One definition of "night" instead of three.

**The exposure honesty applies a second time, and the comment says so**: auto-exposure
only ever darkens (`exposure_auto_gain` caps at 1), so no adaptation lifts a dim world —
the authored radiance IS the night brightness, a look-calibrated constant like the star
ramp, not physics. Starting guess: base radiance ~0.01 in working units, color leaning
blue-grey; **calibrated against tree renders during implementation, A/B crops to the user
before freeze** (the 11.79 lesson: look constants are wrong until the user has seen them).

## Changes

**`cetra/shaders/sky_view_frag.glsl`** — the uniform + the one addition above.

**`cetra/src/sky.c`** — `sky_night_factor` extracted; `sky_bake_view_lut` uploads
`nightFloor = enabled ? color * base * brightness * ramp : 0`; the zenith twin gains the
same term before its early-out; defaults in `create_sky_atmosphere`.

**`cetra/src/gui.c`** — a "Night Floor" checkbox + brightness slider in the Sky group.
Unlike the star widgets these MUST ride the `sun_moved` / `sun_released` pattern
(`gui.c:518-533`): the floor lives in baked data, so an edit re-bakes via
`sky_update_sun` and re-derives probes/GI via `scene_environment_changed` on release —
exactly the sun slider's cost profile, which is the established price of touching baked
sky state.

**`cetra/src/config_snapshot.c`** — two rows under `sky` (`night_floor`,
`night_floor_brightness`) as `CFG_ROW_FN` with a small apply combining
`_apply_sun_angle`'s FLAGS with `_apply_cloud_field`'s CHANGE DETECTION: on change, store
and set **both `ctx->sun_moved` and `ctx->env_changed`**. The flags matter and the obvious
borrow is wrong: `_apply_cloud_field` sets `env_changed` alone, and
`scene_environment_changed` re-bakes the env ONLY when cloud noise is baked
(`scene.c:581`) — which tree and plain render never have, so an env_changed-only floor row
would restore into a stale LUT. `sun_moved` is what reaches the unconditional
`sky_update_sun` (LUT + env + IBL + the zenith re-march) at `:1556`, and it runs before
the `env_changed` chain. Change-detected because the comment at `:303-314` prices a
spurious re-bake at 0.11 s per restore. `config-coverage` requires the GUI widgets map to
rows; `config-perturb` exercises the round trip and the re-bake chain unasked.

**`cetra/src/cscene.c/h` + `apps/render/src/cscene_apply.c`** — a nested
`environment.night_floor` block (`enabled`, `brightness`), per-field presence flags, its
own closed `warn_unknown_keys` — the stars block's shape verbatim, including the parent
`known[]` append.

**`apps/render/src/render.c` / `render_args.h`** — `--night-floor` (implies `--sky`),
`--night-floor-brightness <f>` (implies both), `--no-night-floor` as the way off a
`.cscn`; sentinels and apply-site ordering matching the stars flags exactly.

**`apps/tree/src/tree.c`** — ON by default beside `stars_enabled` at the sky-creation
splice; `--no-night-floor` via the four-site idiom. No brightness flag (the GUI slider and
`-c/--config` cover tuning; flags are for arms and bisects).

**`scripts/gates.py`** — a `night-floor` group on `aerial_fixture`, exposure pinned,
every read an on-vs-off delta (the stars doctrine), each arm with its named falsifying
mutation:

| arm | asserts | falsified by |
|---|---|---|
| `nightfloor-sky` | at −12°, the sky band lifts vs `--no-night-floor` | the feature doing nothing |
| `nightfloor-ground` | at −12°, the TERRAIN band lifts too — the arm that proves the env→IBL path, which is B12's entire reason to exist and which no stars arm touches | implementing the floor as a background-shader term instead of in the LUT: sky lifts, ground never does — the wrong-layer implementation this arm exists to refuse |
| `nightfloor-fog` | at −12° the on-vs-off delta WITH `--fog` (60 frames) exceeds the on-vs-off delta WITHOUT fog by a real ratio — only the fog ambient (the zenith twin's output) can supply the excess. A plain with-fog on-vs-off read would be VACUOUS against this arm's own mutation: the LUT and IBL halves lift either way, so a dead C twin would still pass it | dropping the floor term from the C march — the with-fog delta collapses onto the no-fog delta |
| `nightfloor-daylight` | at +35°, on vs off is 0 px — the ramp zeroes and the LUT is bit-identical | deleting or mis-ranging the shared ramp |
| `nightfloor-cscn` | the authored block reads 0 px from its flag twin, and `--no-night-floor` beats the file at 0 px (the stars-cscn idiom) | deleting the parse |

Plus `gate-docs` registration. Bars calibrated from the first run, recorded in the
constants block with honest margins (the 11.79 review's "order of magnitude" lesson).

**`specs/11.80-night-sky-floor.md`** — this plan, committed alone on branch
`11.80-night-sky-floor` off master before code. Roadmap row 47/B12 gets its DONE marker at
closeout, in phases like 11.79 (commit per coherent phase, not one pile at the end).

## Predictions, written before implementing

1. **All 27 goldens 0 px, no rebake** — default off adds a literal `0.0` to non-negative
   floats in a re-baked LUT, which is bit-exact, not merely close. The sky-bearing eight
   recompile `sky_view_frag`; PAE 1/255 codegen movement is the one acceptable deviation.
2. **The stars group holds** — its arms never pass `--night-floor`, so the field is off in
   every leg. "Byte-identical" is not promised: the group renders through a recompiled
   `sky_view_frag`, so codegen may move the LUT within an ulp and shift readings by a code
   — the bars absorb that; a verdict flip is a finding.
3. `nightfloor-daylight` reads 0 px; if not, the shared ramp is wrong, not the physics.
4. Perf: zero per-frame cost — the term lives in a bake that already runs, on its existing
   cadence.

## Verification

- Noise floor first: `aerial_fixture` at −12° with the floor on, twice, 0 px.
- `./build.sh`; `python3 scripts/goldens.py` — 27/27, no rebake; a mover is a finding.
- `python3 scripts/gates.py --only night-floor,stars,config,gate-docs` during
  development — the blast radius is the sky LUT bake, the config table, and the stars'
  shared ramp. Full suite once at the end on a quiet machine.
- Falsify all five arms by hand with the named mutations; record the readings in the spec.
- **A/B crops of tree at −6° and −12° for the user before the look freezes** — floor
  brightness and color are look constants, and 11.79 established they are wrong until seen.
  Watch the sea specifically: the day-bright teal at night should dim once the env cube
  carries a night sky, but if it stays wrong the cause is water's own shading and gets
  noted for a separate fix, not silently absorbed into this spec.

## Deliberately out of scope

- **`skyVirtualGround` floor bounce** — the env cube's lower hemisphere stays sun-lit
  only; a night bounce off the virtual ground is a refinement nothing currently measures.
- **The aerial-perspective volume at night** — it marches sunlight and contributes ~0 at
  night; correct enough, noted not fixed.
- **The moon (B13), Purkinje (B14), the cycle (B11)** — booked rows, in that order after
  this.
