# Spec 11.95 — Sampler declarations, and whether Wall 1 is still there

## Context

Tier 5 (specs 11.89–11.94) is closed. It left four things behind, and the largest is roadmap
**row 62**: spec 11.93 built lit-surface shader variants and put *sampler declarations* first in its
evidence order, then shipped everything except that. All five of its feature gates are runtime
`bool`s inside `main()`; not one gates a declaration. So a `pbr-0` variant — the one `apps/forest`
resolves to, and the one every content scene in the tree lands on — still declares samplers it has
no code left to read.

Two things ride on fixing it:

- **Wall 1.** `pbr_frag` declares 16 samplers against a GL 4.1 guarantee of 16. `AGENTS.md`
  documents six escapes from that ledger and a roll call of features booked against it; every one
  routes *around* the wall. Returning units would be the first mechanism that dissolves it. It also
  makes exclusivity a **link-time fact** rather than a prose claim — today's escapes rest on
  sentences like "provably mutually exclusive" and "made true by authoring policy".
- **Occupancy.** 11.93 measured the mechanism: a dynamically-uniform branch an unusing scene already
  skips is worth 0.05 ms to guard at runtime and 24 ms to remove at compile time, because live
  values and declared samplers are paid by every fragment regardless. Whether declarations behave
  like live values is the open question, not an established one.

Roadmap **row 63** (skinned variants, S) pairs with it: `pbr_skinned` compiles the *same*
`pbr_frag` source with **no defines at all**, so every rig in every scene is on the uber-shader and
gets none of 11.93's −17%. It needs the same builder this spec touches.

**Note on D0.** The roadmap already has a "free two `pbr_frag` sampler units" item, **refused on
investigation (11.85)** — it asked which two textures could be *folded together*, and the fold was
unsound. This spec asks a different question: which declarations are *unreachable*. That question
has answers the first one did not.

## What exploration established (three corrections to row 62)

**1. Three samplers are fully gated, not four.** Every read traced:

| Sampler | Unit | Declared | Gate |
|---|---|---|---|
| `ltcTex` | 7 | `include/ltc.glsl:21` | **`PBR_FEAT_AREA`** — all reads inside `if (areaLightsActive)` (`pbr_frag.glsl:1769`, `:1772`, and `ltc.glsl:44`/`:107` reached only from `:1830`, behind the `if (!areaLightsActive) continue;` at `:1828`) |
| `sheenTex` | 8 | `pbr_frag.glsl:139` | **`PBR_FEAT_SHEEN`** — one read at `:565` in `sheenColorAt()`, sole caller `:1663` inside `if (sheenActive)` |
| `charliePrefilteredMap` | 9 | `pbr_frag.glsl:305` | **`PBR_FEAT_SHEEN`** — one read at `:2300`, inside `if (sheenActive)` at `:2299` |

`heightTex` **misses by exactly one read** — `layers.glsl:407`, the virtual-texture page tap through
the `vtPageSurfaceTex` alias. The other 12 have ungated reads.

**2. The row's implied one-line `#if` is not the work.** `pbr_frag.glsl` contains **no `#if` at
all** today — the only conditional in the file is `#ifndef CETRA_PBR_FEATURES` at `:12-14`. All five
gates are runtime `bool`s over a compile-time-constant macro. Gating a declaration therefore also
requires lifting its readers' gates to preprocessor form, which is where the care goes: any local
the removed block writes must still be defined on the other path.

**3. The `heightTex` trap is loud, not silent.** `AGENTS.md` and the row imply a plausible-picture
failure. It is not: `vtPageSurfaceTex` is a `#define` over `heightTex` (`pbr_frag.glsl:260`), so
removing the declaration makes `layers.glsl:407` reference an undeclared name — **a compile error on
the first forest run.** forest's terrain is layered (`forest.c:916`).

**Existing precedent to follow:** `cloud_shadow.glsl:12-14` already self-suppresses a sampler
declaration under `#ifndef cloudShadowTex`. Conditionally-declared samplers are not new here.

## Phase 0 — the instrument, and the falsification it performs

**The premise may already be false, and it is one hour to find out.** `AGENTS.md:639` asserts *"the
driver counts sampler DECLARATIONS, not uses"*. That was true when written: 11.93 records that
`pbr_frag`'s unconditional terminal `FragColor` write defeats dead-code elimination for the whole
body, so nothing was dropped and every sampler stayed live. **11.93 changed exactly that.** On a
lean variant the reading code is now folded away, and GL counts *active* samplers against the limit
— so the units may already be back.

There is **no `GL_ACTIVE_UNIFORMS` introspection anywhere in first-party code**. Build it, because it
is the gate arm either way.

- In `program.c`, beside the existing `ubo_wire_blocks()` call in `setup_program_uniforms()`
  (`:405-426`), count sampler-typed active uniforms via `glGetProgramiv(GL_ACTIVE_UNIFORMS)` +
  `glGetActiveUniform`. Cache it as a fourth derived field on `ShaderProgram`, beside `instanced` /
  `depth_prepass_safe` / `pbr_features`. **`ubo_wire_program_block` (`ubo.c:62-113`) is the exact
  precedent** — ask the linked program a question at build time, store the answer.
- Extend the one diagnostic line at `program.c:466-469` to carry it:
  `pbr variant %s: features %u of %u samplers %d`. That line is already `gates.py`'s only window
  into this feature (`_PBR_VARIANT`, `gates.py:19260`); widening it costs no new flag.

**Run it and read the two numbers.** One `render -x -f 3 -m assets/sheen_fixture.gltf` builds both
`pbr` (mask 31) and `pbr-0`.

| Outcome | Meaning | What happens next |
|---|---|---|
| `pbr-0` reports **16** | The driver keeps unused declarations. Row 62 is real work with a certain payoff. | Phases 1–3 as written. |
| `pbr-0` reports **13** | The driver already drops them. The units are already free and `AGENTS.md:639` is stale post-11.93. | **Close the spec here.** Deliverable is the instrument, the arm, and the doc correction. Phase 2 still runs on its own merits. |
| Anything between | Partial elimination — read which names survived. | Decide from the names. |

This is the discipline that deleted four of Tier 5's six booked premises. Row 62's premise is
inherited from a sentence written *before* the change that would invalidate it shipped.

### Phase 0 result: the premise survives, 16 = 16 = 16

`render -x -f 3 -m assets/sheen_fixture.gltf`, which builds three variants in one process:

```
pbr variant pbr:   features 31 of 31 samplers 16
pbr variant pbr-4: features  4 of 31 samplers 16
pbr variant pbr-0: features  0 of 31 samplers 16
```

**The driver keeps every declaration.** A sampler whose every read sits behind a branch on a
compile-time-false constant is still active on the linked program, so it is still spending a texture
image unit. `AGENTS.md:639` is correct and 11.93 did not invalidate it: the reads were folded, the
*declarations* were not, and the ledger is what declarations bind.

`pbr-4` is the useful control. It carries sheen and nothing else, so `ltcTex` is unreachable in it
and it still reports 16 — the elimination is not merely incomplete, it is absent.

Outcome (a). Phases 1 and 3 stand as written, and the four escapes `AGENTS.md` documents are still
load-bearing until Phase 1 returns a unit.

## Phase 1 — gate the three declarations

Only if Phase 0 says the driver keeps them.

**The guard form.** `CETRA_HAS` moves from `pbr_frag.glsl:15` into `pbr_features.glsl`, so a chunk
can use it. Every gated declaration then takes the generalised `cloud_shadow.glsl` shape:

```glsl
#if !defined(CETRA_PBR_FEATURES) || CETRA_HAS(PBR_FEAT_AREA)
uniform sampler2DArray ltcTex;
#endif
```

`ltc.glsl` has exactly one includer today (`pbr_frag.glsl:206`), so the `!defined` clause is
defensive rather than required — but without it a future second includer gets an undefined
*function-like* macro in `#if`, which is a parse error rather than a 0. One clause removes a
landmine. Note `pbr_features.glsl` is `#include`d into C at `program.h:111`; `CETRA_HAS` is valid in
both languages, and that file's "numbers only" rule needs its header comment updated to admit an
integer macro.

**Per sampler**, wrap the declaration *and* lift its readers' gates:

- **`charliePrefilteredMap`** — cleanest. One read at `:2300` inside `if (sheenActive)` at `:2299`.
- **`sheenTex`** — declaration `:139`, `sheenColorAt()` `:562-566`, call site `:1663`.
- **`ltcTex`** — largest. Declaration `ltc.glsl:21`; `ltcMatrix()` `:44`, `_ltcIntegrate()` `:107`,
  `ltcPanel()` `:151-152`; call sites `pbr_frag.glsl:1758-1775` and `:1828-1830`. `ltcMinv` /
  `ltcAmp` are named in `AGENTS.md`'s own live-value calibration (11 floats), so this is also where
  any occupancy win concentrates.

**Ordering is already favourable** and needs no change: `shader_source_with_defines` splices after
line 1, `#line 2` restores numbering, and every include lands at line 169+ — so `CETRA_PBR_FEATURES`
and `CETRA_HAS` are both defined far above every declaration site, inlined ones included
(`gen_shader_header.py:49-52` textually expands includes before the C string exists).

**Polarity stays subtractive.** No defines → `PBR_FEAT_ALL` → byte-identical to today. That is what
keeps `pbr_skinned` (which passes no defines at all) correct while Phase 2 is unbuilt.

### Phase 1 result: three units back, and the occupancy win is real but small

```
pbr variant pbr:   features 31 of 31 samplers 16   (unchanged)
pbr variant pbr-4: features  4 of 31 samplers 15   (lost ltcTex)
pbr variant pbr-0: features  0 of 31 samplers 13   (lost all three)
```

**Sixteen to thirteen on the lean variant.** All 29 goldens 0 px — including the three area-light
ones (`roughness_sweep`, `backface_dark`, `guard_thin_panel`) and `sheen_fixture` — and 22 arms
green across `pbr-variant`, `emissive`, `skin-area`, `grazing` and `gate-docs`.

`apps/forest`, release, 1600x900 Retina, 120 headless frames, two runs a side:

| | opaque GPU | FRAME wall |
|---|---|---|
| before | 123.304 / 123.511 | 177.566 / 177.927 |
| after | 121.121 / 120.442 | 174.604 / 174.767 |

**−2.63 ms of opaque (−2.13%), −3.06 ms of frame (−1.72%).** Worst spread on either side is 0.56%,
so it clears the floor — but read the size honestly. 11.93 removed whole feature *bodies* and got
−17.2%; this removes three declarations, the entire LTC library and eleven floats of live range
across the light loop, and gets −2.1%. **The occupancy model is confirmed and its remaining headroom
is small.** What is left on this shader is not declarations.

So the deliverable is the *units*, and the frame time is a bonus that does not change any decision.

## Phase 2 — skinned variants (row 63)

Independent of Phase 0's answer; worth doing whatever it says.

- Generalise `_create_pbr_variant(name, features)` (`program.c:428`) to carry its own vertex source,
  and add a family to `ShaderProgram` so `engine_pbr_variant` can build in either. Names become
  `pbr` / `pbr-<mask>` and `pbr_skinned` / `pbr_skinned-<mask>`. `pbr_variant_name()` stays the one
  place the key is spelled — it is the program-cache key, and a second speller would miss the lookup
  forever and compile a fresh 2,500-line program every frame while rendering correctly.
- `create_pbr_skinned_program()` (`program.c:577`) becomes the full-mask member of its family and
  sets `pbr_features`, which is what admits it to the resolver (membership is `pbr_features >= 0`,
  `render.c:765`). No resolver logic changes.
- Derived flags carry themselves: `depth_prepass_safe = true` for both families;
  `instanced` is resolved from the linked program by `ubo_wire_blocks`, so a skinned variant comes
  out `false` because `pbr_skinned_vert.glsl` includes no `instancing.glsl`.

**This has zero golden coverage.** None of the 29 goldens is skinned — the corpus is entirely
static, and `apps/render` is the only app that builds `pbr_skinned` at all. So it needs an arm, and
`assets/skinned_instance_fixture.gltf` is the fixture built for exactly this question
(`docs/verification.md`: *"skinned but has no animation at all … because that fixture is about which
PROGRAM a mesh takes"*). 11.28's `skinned-nobatch` / `skinned-identity` arms must stay green.

### Phase 2 result: the family lands, and raiden moves 2 pixels

```
pbr variant pbr:            features 31 of 31 samplers 16
pbr variant pbr_skinned:    features 31 of 31 samplers 16
pbr variant pbr_skinned-0:  features  0 of 31 samplers 13
```

All 29 goldens 0 px. `skinned-nobatch` (2 draws for 2 instances), `skinned-identity` (0 px against
`--no-instancing`) and `lod-skinned` all green, so the skinned variant still links without an
`InstanceBlock` and 11.28's rule holds without this spec asserting it.

**The check the corpus cannot do.** Nothing in `assets/` is skinned, so the only instrument for
"does a rig render the same on its lean variant" is the raiden recipe. Uber-shader against
`pbr_skinned-0`, `-f 120 --no-springs --no-auto-exposure -E 1.0`, **against a 0 px floor measured on
the same build**:

```
(1369,759)   before=(24,31,37)  after=(24,31,36)
(2645,1341)  before=(10,15,19)  after=(10,15,18)
2 of 8,294,400 pixels
```

**Two pixels, one 8-bit code down in blue only, both in dark regions.** Not byte-identical, and it
is worth saying so rather than rounding it to zero — the floor is 0, so this is real. It is the
last-bit signature `docs/verification.md` describes and the cause 11.93 already recorded for this
feature: removing code re-schedules the arithmetic around it, and a pixel sitting on a rounding
boundary lands the other way. The 29 rigid goldens moved 0 px under the same transformation, which
is consistent — a different vertex stage gets a different register allocation.

## Phase 3 — the fourth unit, conditional

`heightTex` needs a sixth bit, `PBR_FEAT_LAYERS`, set from `mat->layer_count > 0`. The exclusivity
already exists C-side — `render.c:304`'s `refuse_maps_34` forces `heightTexExists` and
`clearcoatNormalExists` to 0 for a layered material — it is simply never told to the shader.

**Go/no-go, decided by measurement rather than taste:** build it only if Phase 0 shows declarations
are counted *and* Phase 1's wall-clock shows the frame actually moved. If declarations are free, a
sixth bit buys a unit nobody needed; if they are counted but occupancy does not move, it buys one
unit for a new bit, a new resolver field, a new arm and a change to the most intricate path in
`layers.glsl`. Record the finding either way.

`clearcoatNormalTex` (unit 3) is **out of scope regardless** — clearcoat has no feature bit and is
gated by a uniform, so it would need a seventh.

### Phase 3 result: GO, and the bit is worth more than the unit it was booked for

Both criteria met — declarations are counted, and the frame moved — so the bit was built. But the
reason to build it turned out not to be the unit.

**`sampleLayeredSurface` and `sampleCachedSurface` are called on every fragment of every material.**
The branch above them selects between the two on a *uniform* (`layersVtActive`), and the
`layerCount <= 0` early-out lives INSIDE both callees — so an unlayered material links the whole
four-layer triplanar blend and carries a `LayerSurface` across the light loop to reach an
`if (layered)` it never takes. That is the same shape as 11.93's live values, on the largest body
left in the file.

forest splits cleanly, which is what makes it the right fixture: `pbr-32` for the layered terrain,
`pbr-0` for the trees and props that are most of the pixels.

| | opaque GPU | FRAME wall |
|---|---|---|
| after phase 1+2 | 121.121 / 120.442 | 174.604 / 174.767 |
| with the layers bit | 114.272 / 115.593 | 170.357 / 170.098 |

**−5.85 ms of opaque (−4.84%), −4.46 ms of frame (−2.55%)**, against a 1.15% worst spread. **Larger
than phase 1**, which removed three declarations and the whole LTC library for −2.13%.

Cumulative over the spec: opaque **123.408 → 114.93 (−6.87%)**, frame **177.747 → 170.23 (−4.23%)**.

All 29 goldens 0 px, `layer_fixture` and `layer_vt_fixture` included. `pbr-variant-full` picked the
sixth bit up with no arm edit — it reads the union out of `pbr_features.glsl` and now reports 63
over 6 bits, which is the shared-file contract doing the job it was built for.

**What this reframes.** The row booked a sixth bit as the price of a fourth unit. It is the other way
round: the bit is a bigger occupancy win than everything in phase 1 put together, and the unit is
the part still outstanding.

`CLAUDE.md` is a committed symlink to `AGENTS.md`; one edit covers both.

- **`AGENTS.md:639`, the Wall 1 paragraph.** Correct *"the driver counts sampler DECLARATIONS, not
  uses"* to whatever Phase 0 measured, and — if units come back — record the seventh escape as the
  one that returns units rather than routing around them, with the caveat that it returns them
  **per variant**, not globally.
- **`AGENTS.md:365`** says *"Two include files are compiled by BOTH languages"*. It is three:
  `pbr_features.glsl` joined them in 11.93 and the paragraph was never updated. Add it, and state
  that it relaxes the numbers-only rule to admit an integer macro and why.
- **The variant system is entirely undocumented.** 11.93 shipped `shader_source_with_defines`, the
  shared mask, `engine_pbr_variant` and a per-frame resolver, and none of it appears in `AGENTS.md`.
  Add it to the Shaders section: the subtractive polarity and why (a resolver that fails to run must
  yield the slow program, never a fast one missing a feature), and that the mask is a shared
  **number** because the first shape — C emitting macro *names* — was untypeable-wrong-and-silent.
- **`docs/aaa-rendering-roadmap.md`** rows 62 and 63, closed with numbers in the house style —
  including the three corrections above, since a row that describes the work incorrectly is the
  failure mode that document keeps recording about itself.

## Verification

- **Noise floor first**, every time. One configuration rendered twice, diffed, before any number is
  quoted.
- **New arms**, in the `pbr-variant` group: a declaration-count arm asserting a lean variant
  declares strictly fewer samplers than the full one, and (Phase 2) a skinned-variant arm asserting
  a skinned material resolves into its own family. Both must fail under a one-line mutation that
  deletes the feature — name that mutation before writing the bar.
- **Docstring format is exact** (`gate-arm-docs`): a prose line at indent 4 to anchor
  `cleandoc`'s common-indent strip, arm names at indent 6, continuations deeper, and the verdict
  printed as `print(f"  <name> ... {'PASS' if ok else 'FAIL'} ...` in one double-quoted literal.
  11.93 shipped this broken.
- **Run `--only pbr-variant,gate-docs`** while iterating — `--only` matches by substring and
  `gate-docs` is last, so no targeted run reaches it otherwise. **Never edit `gates.py` while a run
  is in progress**; `gate-arm-docs` reads its source from disk.
- **Goldens must be 0 px across all 29.** This changes what a variant compiles, never what it
  computes — any movement is a bug, not a rebake. Phase 2 is the exception to trust here: the corpus
  cannot see skinned programs at all, which is why that phase carries an arm instead.
- **Occupancy is measured on wall clock**, not the GPU profiler, which prices it badly. `apps/forest`
  (resolves to `pbr-0`), release build, two runs a side, opaque pass and frame total, same protocol
  as 11.93.
- **Whole suite once at the end**; `--bin-dir out/release/bin` for gates, default `out/bin` for
  goldens.

## What this will NOT do

- **Fold two textures together.** That is D0, refused on investigation in 11.85.
- **Gate `clearcoatNormalTex`, `materialArray`, or the shadow arrays.** Each has ungated reads; a
  seventh bit for clearcoat is not obviously worth a unit and is not argued here.
- **Assume the occupancy win.** 11.93's mechanism predicts one. Four of Tier 5's six phases had a
  premise of exactly that confidence deleted by measurement.
