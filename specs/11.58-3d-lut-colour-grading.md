# 11.58 — 3D LUT colour grading (roadmap E2, row 28)

## Context

Roadmap row 28 (E2), the last unblocked-and-small item on the table after 11.53 (E8), 11.56 (C5) and
11.57 (C3) took the other three.

Cetra's grade is three knobs per channel — lift, gamma, gain (`tonemap_frag.glsl:415-418`). That is a
per-channel curve, so by construction it cannot rotate a hue, cannot mix channels, cannot split-tone.
A `.cube` LUT is not a formula but a table of answers, so it can do all of it. The workflow this buys:
grade in Resolve, export a `.cube`, drop it in — instead of hand-transcribing sliders.

It changes no default frame. With no LUT loaded the output must be byte-identical to today, which is
the `postfx.h:472-473` invariant ("with every toggle off the frame is unchanged") that ~30 existing
gate arms rest on.

## What exploration settled before any code

**The row's own number is wrong for the format it names.** It says "a 32³ `.cube`". 32³ is not a
standard `.cube` size — `LUT_3D_SIZE` runs 2–256 and what actually ships is **33³** (Resolve's
default, and most vendor LUTs), 17³ for small looks, 65³ for precision ones. Hardcoding 32 rejects
the files the feature exists to accept. **Size is read from the file**, bounded 2–64, texture
allocated N³.

**Wall 1 is not in play, and it is checkable.** `tonemap_frag` declares **10 of 16** samplers. Its
unit space is its own, separate from `pbr_frag`'s ledger, assigned once at `postfx.c:853-864`;
**unit 11 is the next free one** (unit 7 is the retired adapted-luminance slot, deliberately bound to
0 at `postfx.c:3485-3486`).

**Display-referred, applied after `displayEncode`.** This is the contract to state, not a detail.
`view.glsl` — the authority — names three spaces: scene radiance, working space (pre-exposed, 1.0 is
diffuse white), display. Inside `tonemap_frag` the frame passes through *two* display-referred states:
LDR-linear (`toneSelect`'s stated contract, where lift/gamma/gain runs) and gamma-2.2-encoded (after
`displayEncode:147-150`; there is no `GL_FRAMEBUFFER_SRGB` anywhere, so that manual `pow` is the whole
encode). A colourist's `.cube` is authored against the second. Applying one to LDR-linear values
produces a plausible image that is not the look the artist made.

**Log / pre-tonemap was considered and declined, and the reason is not the one I first gave.** It is
*not* structurally hard here — `agxTonemap:134-143` already log-encodes with an EV window, transforms,
and linearizes back to honour `toneSelect`'s contract, so a log LUT would be a fourth branch of
`toneSelect` in exactly that shape. It is declined because **an off-the-shelf `.cube` cannot be used in
it**: a log LUT must be authored against the specific log window we pin, which no vendor LUT is. It
would also replace the tonemap outright (discarding AgX), and contaminate the GI debug view, which
calls `toneSelect` at `:332` where the display path's early `return` at `:309-362` cannot reach.
Display-referred *composes* with whichever curve the scene picked; log *replaces* it.

**The residual risk, stated plainly:** a `.cube` does not declare its input space, and a log/show LUT
loads without complaint and renders washed out. `DOMAIN_MIN/MAX` is a hint, not a guarantee. Mitigated
by a heuristic warning (below), not by a check that can be trusted.

**Tetrahedral, with trilinear retained as the falsifier.** Tetrahedral is what Resolve/Nuke/Baselight
use and it keeps the neutral axis exact (r==g==b in, r==g==b out); trilinear's 8-corner blend pulls in
off-diagonal corners and can faintly tint greys. But **tetrahedral alone is unfalsifiable** — a broken
implementation that degenerates toward trilinear passes any arm written against it, since nothing in
the frame is a reference. Keeping trilinear behind a flag is one `texture()` call and is what makes
the two arms that matter possible.

**Ordering.** `tonemap_frag.glsl:48-50` is the authority and states dither must stay last. New order:
`sharpen -> grade -> vignette -> gamma -> LUT -> grain -> dither`. The LUT is the creative look; grain
is sensor noise over the finished look; dither is quantization.

**Debug and passthrough frames are already exempt.** Debug views `return` at `:309-362` before any
finishing stage, and `postfx.c:2941` replaces the whole pass with a blit for
`POSTFX_TONEMAP_PASSTHROUGH`. Correct — they are data, not pictures. Same reasoning 11.24 recorded.

**`--film` must not sweep it in** (`render_args.h:214`, "the whole finishing stack at sane defaults").
There is no sane default for a LUT; it needs a file.

## Phase 0 — build the instrument and take the number, before either shader path exists

A fixture is a claim and must be measured (11.21). Before any shader:

1. Generate the chart fixture and render it with no LUT. **Verify the quads land spread across the
   display range** (a chart whose patches all land in the midtones exercises one corner of the table)
   and that two runs of one build are **0 px**.
2. In Python, take the rendered no-LUT pixel values and push them through each test LUT under *both*
   interpolants. **Report the max |delta| in 8-bit codes.** This is the number that justifies
   tetrahedral, taken before there is anything to be attached to.

If the delta is under 1 LSB on every LUT including the steep one, that is a finding to record —
tetrahedral is then a correctness choice rather than a visible one, which is still fine, but the spec
says so honestly rather than implying an improvement nobody can see.

### Phase 0 — results

**The chart.** 24 patches at 400x300 (800x600 framebuffer), 30 frames, `--no-auto-exposure -E 1.0
--no-dither --no-vignette`. Two runs of one build: **0 px**. Display range **32..244** over all
channels, so the table is exercised across its domain with nothing clipped at either end. Grey ramp
lands at **32 / 81 / 133 / 179 / 223 / 244**, and all six read **exactly r == g == b**, which is what
gives the neutral-axis arm a signal at all.

**The interpolation number, and it is the honest one.** Sampled off-lattice across the cube:

| table | N | max tri-vs-tet delta | grey tint, trilinear | grey tint, tetrahedral |
|---|---|---|---|---|
| `lut_identity` | 17 | 0.000 | 0.000 | 0.000 |
| `lut_swap` | 17 | 0.000 | 0.000 | 0.000 |
| `lut_steep` | 33 | **0.076** | 0.000 | 0.000 |
| `lut_neutral` | 9 | **7.841** | **7.471** | **0.000** |

**At 33³ — the size real files ship at — the two interpolants differ by 0.076 of one 8-bit code.**
That is a fifth of a quantization step: invisible, and it will stay invisible on any well-formed look
LUT. So tetrahedral is **not** being shipped because it looks better. It is being shipped because it
is exact on the **neutral axis**, where trilinear puts 7.471 codes of tint through a table that
touches greys not at all — and a grey that has gone faintly warm is the one error a colourist is
guaranteed to notice. That is the claim, and the 0.076 is what keeps it from being overstated.

Both linear tables read **exactly 0.000** under both interpolants, which is the property that lets
`lut_swap` isolate "is the table right" from "is the interpolation right".

**Two construction traps, both found by measuring rather than by reasoning.** The first
`lut_neutral` was a steep curve applied identically to all three channels, and it measured **zero
tint under both interpolants** — a *separable* table preserves greys under trilinear because the
off-axis weights sum to one and factor out. The second was symmetric in its channels, and measured
**zero as well** — at a grey sample the trilinear weights are themselves symmetric under permuting
the axes, so the corner pairs carry equal weight and opposite channel differences and cancel exactly.
The table has to be **neither separable nor channel-symmetric**, which is why the shipped one lifts
red alone. Both traps are asserted in the generator so a later edit cannot walk back into them.

## Design

### The loader — `cetra/src/lut.c` / `lut.h` (new)

`ies.c`'s idiom throughout, since it is the tree's worked example of a hand-written ASCII parser:

- `read_entire_file` (`util.c:177-203`) — returns NULL on short reads, caller frees.
- Token-stream lexer over the data block (`ies.c:161-187` shape): `strtod` + end-pointer, skipping
  whitespace and commas. **Not line-by-line** — `.cube` data rows are conventionally one triple per
  line but nothing in the format requires it.
- Line-anchored, case-folded header scan (`ies.c:238-262` shape) for `LUT_3D_SIZE`, `LUT_1D_SIZE`,
  `DOMAIN_MIN`, `DOMAIN_MAX`, `TITLE`.
- **Refuse by name, never truncate** — every failure is a `log_warn` naming the path plus
  `return false`, exactly as `ies.c` refuses `TILT=INCLUDE` rather than ignoring it. The refusals:
  a `LUT_1D_SIZE` file (say "1D LUT" explicitly), size outside 2–64, a non-default `DOMAIN`, a short
  or non-numeric data block, a non-finite value.
- **Data order is red-fastest**, then green, then blue. Reading it in the other order is a silent bug
  that still produces a plausible image — it is what `lut-swap` below exists to catch.
- Success is one `log_info` line naming the file, its size and its title.

**Optional, ~10 lines — the space heuristic.** After load, evaluate the table at (0.5, 0.5, 0.5). A
display-referred LUT lands near mid-grey; a log LUT lands far off (LogC's 0.5 is roughly 2.5 stops
over). If the distance exceeds a threshold, `log_warn` naming the file and pointing at the flag's
documentation. It still renders. This converts the one silent failure mode into a named warning
without adding a mode or a space. *Strike this if you would rather it stay silent.*

### GPU upload

`create_texture_3d_float(N, N, N, GL_RGB16F, GL_RGB, data)` — `texture.c:129-143` already exists and
already does exactly what a LUT needs: `CLAMP_TO_EDGE` on all three axes, `LINEAR` min/mag, no mips,
`glTexImage3D` (not `glTexStorage3D`, which is 4.2). Its sibling `create_texture_3d_rgba8_tiling` is
the `GL_REPEAT`+mipped one and is the wrong helper. Row alignment is safe at RGB: floats are 4 bytes
and the default `GL_UNPACK_ALIGNMENT` is 4.

### Ownership — PostFX, not Scene

The existing grade lives there (`postfx.h:476-479`), and a LUT is a look, not a scene citizen. It is
**resolution-independent**, so it follows `noise_texture` (`postfx.c:781` / `:1994`): created outside
`postfx_alloc_targets`, freed only in `free_postfx`, and **not** touched by `postfx_free_targets` or
`postfx_invalidate_targets` — a resize must not drop it.

But `create_postfx` runs in `init_engine` (`engine.c:953`) *before* the app applies its args
(`render.c:2294`), so the path is not available there. New setter:

```c
bool postfx_load_lut(PostFX* fx, const char* path);   // parse + upload; false and unchanged on refusal
void postfx_clear_lut(PostFX* fx);
```

New `PostFX` fields, in the finishing region beside the grade: `lut_texture`, `lut_size`,
`lut_enabled`, `lut_strength`, `lut_interp`, and the loaded file's basename for the GUI readout.

### The shader — `tonemap_frag.glsl`

New uniforms beside the finishing block: `sampler3D lutTex`, `int lutEnabled`, `float lutStrength`,
`float lutSize`, `int lutInterp`. Sampler int set once at `postfx.c:853-864` as unit **11**; the rest
uploaded per frame in the finishing block at `postfx.c:3540-3560` (no registration needed —
`uniform_binding` caches lazily, and `uniform_write_wanted` elides unchanged writes).

Applied **after `displayEncode` (`:430`), before grain (`:432`)**, and the order comment at `:50`
updated with it.

**The half-texel inset is the classic silent bug** — without it an identity LUT stops being an
identity:

```glsl
vec3 uvw = (c * (lutSize - 1.0) + 0.5) / lutSize;   // [0,1] -> texel CENTRES
```

Trilinear is `texture(lutTex, uvw).rgb`. Tetrahedral is the 6-simplex decomposition: order the three
fractional coordinates to pick one of six tetrahedra, then `texelFetch` its 4 corners with barycentric
weights.

Strength is `color = mix(color, graded, lutStrength)`. **`mix(a, b, 0.0)` is exactly `a` in IEEE**, so
strength 0 is a genuine bit-exact identity and gate-able at 0 px.

### CLI — `apps/render/src/render_args.h` + `render.c`

Four flags, each following an existing verbatim pattern:

| flag | shape | model |
|---|---|---|
| `--lut <path>` | `const char*`, borrowed from `argv` | `-e/--env`, `render.c:431-436` |
| `--lut-strength <f>` | float, `-1` sentinel | `--sharpen`, `render.c:1283-1288` |
| `--lut-interp <trilinear\|tetrahedral>` | string vocabulary → enum | `--tonemap`, `render.c:1186-1200` |
| `--no-lut` | int | `--no-water` — the only way off a `.cscn`-authored LUT |

Applied in the `if (engine->postfx)` block at `render.c:2294-2363`, after `--film` so it overrides.

### Scene file — `post.lut`

Nested block under `post`, following `post.metering`'s template verbatim (`cscene.c:387-422`):
`{"path": "look.cube", "strength": 1.0, "interp": "tetrahedral"}`.

Three things that are easy to miss and each break something:
- **Add `"lut"` to the closed `known[]` at `cscene.c:466-470`** or every load warns.
- **Add a `resolve_in_place` line at `cscene.c:824-830`**, beside `env_hdr` and `ies_path` — a `.cube`
  is not a pooled texture, so it has no second resolver that would win. `char lut_path[CSCENE_MAX_PATH]`
  inline, never a pointer, because `cscene_free` is a bare `free(desc)`.
- Per-field `has_*` flags and CLI-wins guards in `cscene_apply.c`, the two-hop route
  (`.cscn` → `RenderArgs` → `PostFX`) that `render.c:2294-2363` is the single writer for.

### GUI

A "Color LUT" group in the Finishing header (`gui.c:939-988`) via `_begin_effect_group` /
`_end_effect_group`: enable checkbox, strength slider, interp combo, and the loaded file's basename as
a read-only label. **No file picker** — loading is CLI/`.cscn` only. That keeps every GUI control on
the existing per-frame-upload path and avoids being the first control here that needs a file reload.

## The fixture

`assets/gen_lut_fixture.py` → a colour chart: a grey ramp row plus patches spread across the RGB cube,
so the LUT is exercised across its domain rather than in one corner. `gen_mask_fixture.py` is the
model — patches placed **frame-symmetrically so the vignette cancels between compared pairs**, values
chosen off the tonemap's ends (mid-tones, not white, which clips and compares equal however wrong the
table is), inline base64 buffer, `json.dump(indent=1)` + trailing newline so `fixture-gen` can compare
bytes. Generator carries `assert`s on patch spread and separation, so an edit that stops the fixture
testing anything fails loudly at regeneration.

Four generated `.cube` files, each answering a question no other does:

| file | closed form | what only it catches |
|---|---|---|
| `lut_identity.cube` | out = in | the half-texel inset, and axis order |
| `lut_swap.cube` | (r,g,b) → (b,g,r) | red-fastest data order. Linear, so both interpolants agree exactly — it isolates *correctness* from *interpolation* |
| `lut_steep.cube` | a hard S-curve + hue shift | the interpolants must disagree here |
| `lut_neutral.cube` | one steep curve applied identically to all three channels | greys must stay grey — the arm that justifies tetrahedral |

## Gate arms — `lut` group

Every arm rendered with `--no-dither` (eight existing precedents; these read patches, and a ±1 LSB is
large against a channel ratio).

| arm | asserts | rejects |
|---|---|---|
| `lut-closed-form` | read the **no-LUT** pixel, push it through the LUT's closed form in Python, compare to the with-LUT pixel | needs no knowledge of the scene's absolute values, so it cannot be fooled by exposure or tonemap changes. The arm that decides the item |
| `lut-swap` | R and B exchanged across every patch | red-fastest data order read backwards |
| `lut-identity` | identity `.cube` is **0 px** vs `--no-lut` | the inset bug. **Cannot stand alone** — a dead feature also reads 0 px (11.22), so it is meaningful only beside `lut-closed-form` |
| `lut-strength` | strength 0 is bit-exact 0 px; 0.5 lands measurably between off and 1.0 | a C-side short-circuit making on and off take one path (11.21 shipped exactly that arm) |
| `lut-off` | `--no-lut` on a `.cscn` that authors one is 0 px against a no-LUT build | the escape hatch, and that the feature is free when unused |
| `lut-interp` | trilinear and tetrahedral agree within N codes on `lut_swap`, and **disagree** on `lut_steep` | a tetrahedral path that silently degenerates |
| `lut-neutral` | under `lut_neutral.cube`, tetrahedral holds grey channel spread at ~0 while trilinear does not | the whole justification for tetrahedral. If this reads 0 for both, say so and record it |

The group gets an arm-listing docstring, which opts it into `gate-arm-docs` — **arm order in the
docstring must match run order**, and the two existing post groups (`dither`, `flare`) are exempt only
because they have no list.

## Verification

```bash
./build.sh
python3 scripts/goldens.py                              # all 24 at 0 px -- the invariant
python3 scripts/gates.py --only lut,fixture-gen,gate-docs,dither
python3 scripts/gates.py                                # once, at the end
```

- **All 24 goldens 0 px through P2 and after.** 23 of the 24 run the full finishing block; only
  `contact_debug` returns early. A moved golden means the no-LUT path is not a no-op.
- **Measure the noise floor before quoting any pixel diff** — one config rendered twice, first.
- **Every `lut` arm falsified by hand** against a named one-line mutation (drop the inset; read the
  data block blue-fastest; make `lutStrength` ignore its uniform; degenerate tetrahedral to trilinear).
- No existing arm should need `--no-dither` added or a threshold widened. If one moves, the
  "every toggle off is unchanged" invariant is broken, not the arm.
