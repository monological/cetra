# cetra 14.27: eight range layers

## Context

pcb 7.4.1's look: the caret on a violation in pcb's checks pane takes the code to the rule that
applied, and the user could not tell which line it had taken them to. They asked for the rule's line
tinted. A whole line's tint is a range of a `UIEditorStyle` with `whole_lines` (spec 14.15), and a
host's ranges sit in a `TextDoc`'s layers, of which there are `TEXT_DOC_LAYERS`, 4. pcb uses all
four on a design's file: what the evaluation found, the code that makes what is chosen, the code
that mentions it, and the lines added since a version compared. A fifth thing to mark has no layer.

Branch and spec: `14.27-eight-range-layers`, off cetra's master (`0051de78`).

## The design

- **`TEXT_DOC_LAYERS` is 8**, in `cetra/src/text_doc.h`. Nothing else names a count: `text_doc.c`
  and `ui_editor.c` loop to the constant and size their arrays by it, and a layer past the last is
  refused and logged as now.
- **Its comment says what a layer is for** -- the host's to fill -- not the four pcb happens to use.
- **The cost**: `_draw` in `ui_editor.c` keeps four arrays of `RANGES_DRAWN * TEXT_DOC_LAYERS`
  ranges and two of pointers on the stack, about 57KB more at 8; a `TextDoc` four more slots of a
  pointer and two counts. No layer is walked that holds nothing, past its count of 0.

## Tests

**`ui-editor-whole-lines`**, 14.15's arm: `probe_editor_whole_lines` in
`apps/gametest/src/ui_editor_probe.c` puts its green range, the one `plain` reads, on the last layer,
`TEXT_DOC_LAYERS - 1`, in place of layer 1, so `plain` says the last layer is drawn. The arm's flags
keep their names and count.

**Then**, as the user asked in choosing this way: cetra's master fast-forwards and is pushed, the
branch deleted; pcb's `extern/cetra` moves to it, and pcb tints the rule's line.
