# cetra 14.29: the gate suite in files

## Context

`scripts/gates.py` is one file of 37,078 lines: 110 group functions (25,229 lines), 386 helpers
(5,732 lines) and about 1,050 module-level constants and statements. Measured from its AST:
- About 1,200 helpers and constants are reached by exactly one group.
- About 170 are shared by two or three sibling groups: `water`/`water-night`, `terrain`/`terrain-stream`,
  `rainfall`/`fog-miss` and `penumbra`/`shadow-tiles` share about 10 names each, and the skin
  groups share several.
- About 25 are used across the suite: `_run` (91 groups), `asset` (90), `_read_ppm`, `compare`,
  `render`, the `.cscn` builders.

The user wants it split first, and then, in this spec's phase 4, `--arms` built on the split.
`--arms` runs the arms a change reaches instead of a whole group: `ui` alone is 116 arms. AGENTS.md
then says how to run tests. 14.28 is paused and rebases onto master after this.

Agreed with the user:
- `scripts/gates.py` stays the command, invoked as today.
- Shared code goes in `scripts/gatelib/`. Not `scripts/gates/`: next to `gates.py`, Python's `import gates`
  would take the folder, and `goldens.py` already imports `from gates`.
- One file per group, and sibling groups that share helpers share a file.
- A script does the move. It changes no code, only where the code lives.

Branch and spec: `14.29-the-gate-suite-in-files`, off master (`89b10d88`). The 14.28 branch is
clean and stays as it is.

## The layout

```
  goldens.py              imports asset and compare from gatelib
  vim_layout.vim          unchanged
  gatelib/
    __init__.py

    probes.py             the gametest and canvas probe runners several groups use
    <subject>.py          more only if the sharing report shows a cluster that belongs to no
                          group file (shadow helpers shared by penumbra and shadow-tiles, say)

```

**Where a name goes:** a name reached by one file lives in that file. A name reached by several
files goes to a gatelib module by subject. Function names, selectors, banners and run order all
stay as they are.

## The move script

A one-off Python script in the session scratchpad, not committed. It writes the files and checks
its own output.

1. **It slices source text, not the AST.** Each top-level statement's span runs from the first
   comment or blank line directly above it (or its decorators) to its last line. Comments sit
   between definitions and the AST drops them.
2. **It finds what each group reaches**, transitively, starting from each `GATE_GROUPS` function
   and following top-level functions, classes and constants.
3. **It assigns names by two hand-written tables**, both reviewed against a sharing report the
   script prints first:
   - **FILES:** which groups share which file.
   - **SHARED:** which gatelib module each shared name goes to.

   A name that falls in no table stops the script; it never guesses.
4. **It writes each module.** Each gets its spans in original order, plus the stdlib, numpy and
   gatelib imports it uses, worked out from the names it reads.
5. **It checks its output, and fails on any miss:**
   - **Line accounting:** every line of the old file lands in exactly one new file, in its original
     order there. The only exceptions are the import lines and the edits listed below.
   - **Identity:** every function, class and constant is the same as before, compared as an
     `ast.dump`, except the edits listed below.
   - **No global crosses a file:** for every `global X` statement (`_FB_SCALE`, `_LAYER_GEN`,
     `_DECAL_GEN`…), X and every function reading it are in one module.
   - **No import cycle**, and every module imports cleanly.
   - **No undefined names**, through `python3 -m pyflakes` if it's installed, else the script's own
     AST check.

## Edits the move needs (with the Edit tool, after the script)

- **`__file__` paths:**
  - `ROOT` in `harness.py` becomes `SCRIPTS = dirname(dirname(abspath(__file__)))` and
    `ROOT = dirname(SCRIPTS)`.
  - `_UI_HEADER` and `_VIM_LAYOUT` join from `SCRIPTS`. Moved one level deeper, the old
    expressions would silently point at the wrong place.
- **`--bin-dir`:** today `main` rebinds `BIN_DIR`, `RENDER`, `FOREST`, `SPORES` and `GAMETEST` with
  `global`. Across files, that rebinding never reaches the modules that imported the old values. So
  `gates.py` parses its arguments first, sets `CETRA_BIN_DIR` from `--bin-dir`, and only then imports
  gatelib. `harness.py` already reads `CETRA_BIN_DIR` at import, and the `global` block goes.
- **gate-docs:**
  - `run_gate_docs_gate` imports `GATE_GROUPS` inside the function, since the table imports its
    module.
  - `gate-names` (no top-level name defined twice) walks every file under `gatelib/` and
    `gates.py`, not just `__file__`. A name both imported and defined in one file counts as defined
    twice.
  - Its docstring says so.
- **`goldens.py`:** `from gates import asset, compare` becomes imports from `gatelib`.
- **`gates.py`:** keeps its module docstring, `main`, `_detect_fb_scale`'s call and the summary. It
  imports the table from `gatelib.groups`.
