# Closing the working-space contract

## Context

Spec 10.1 declared a working-space contract, moved the pipeline into it, and
finished with every gate green: nine goldens at 0 px, scale invariance at 0 px,
auto-exposure converging to six decimal places.

Six independent reviews of that finished branch found three shading paths that
never made the move, one asset path that regressed, and three of the four
surviving `WS_*` ceilings still violating the contract's own stated admission
rule. Two of the findings were then reproduced by direct measurement.

**Every one of them was invisible to every gate 10.1 ran.** That is the part
worth understanding before the fixes, because the fixes are mostly small and the
blind spot is not.

## Why nothing caught any of it

Three independent reasons, and they compound:

1. **Every golden pins exposure.** All nine run `--no-auto-exposure -E 1.0`, so
   `preExposure == 1.0` and multiplying by it is the identity. Every
   space-mixing bug in this document is *algebraically* invisible to all of
   them. They are not weak tests; they are structurally blind to this class.

2. **The scale-invariance test used one light type.** `cornell_point` has a
   single punctual light and no area panel, no SSS material, no reflective
   catcher surface, and fog off. It proved the punctual path scale-invariant and
   said nothing about the other three.

3. **The convergence test reused that same scene.** SSR contributed nothing (no
   catcher-marked surface), SSGI and fog were off. So the auto-exposure loop was
   demonstrated stable on the one configuration where none of the three
   remaining white-relative clamps were live.

The verification set tested **one light type, through one post configuration, at
one exposure**, and reported the contract as holding. Phase 3 exists to fix the
test set, and it should land before or alongside the code fixes, not after.

## Status

- **Phase 3 — DONE** (`gates: fixtures that can actually fail`). `scripts/gates.py`
  runs the matrix; the x1000 half is generated mechanically so the two halves
  cannot drift except in the scale. New fixtures for the area, subsurface and fog
  paths plus a glTF point light with an authored range.
- **Gate criterion changed** (`gates: pass on peak error`). Phase 1 reassociated
  float arithmetic and moved every pixel count, which is exactly how a per-gate
  budget gets raised until it hides something. Gates pass on peak error instead:
  1/255 is one 8-bit step, so at or below it nothing is visible, and above it
  something genuinely changed however few pixels carry it.
- **Phase 1 — DONE** (`pbr: convert to working space once`). area 195020 px -> 1,
  subsurface 72180 px -> 1, both at peak 1/255. Goldens exactly 0 px.
- **Phase 2 — DONE** (`import: read glTF light range from where assimp puts it`).
  Authored 25.0 now imports as 25.0.
- **Phases 4, 5, 6 — NOT STARTED.** Follow-ups; the branch is mergeable without
  them.

## Corrections to 10.1

Recorded because they are false statements currently in the tree, several
load-bearing:

- **`postfx.c` — the `glReadPixels` stall claim is wrong, and measured wrong.**
  The comment says reading the ping-pong slot not written this frame means the
  GPU "finished it long ago, so glReadPixels finds it resident and does not
  stall." Benchmarked on M1 Max, 600 frames, GPU frames ~5.4 ms: reading the
  previous slot blocks **5.253 ms**; reading the just-written slot blocks
  **4.748 ms**. The slot choice buys nothing — a non-PBO `glReadPixels` drains
  the command stream whatever it targets. It does not show in frame time only
  because the loop is GPU-bound with an idle CPU, which is not true of
  `gametest` or `spores`, and the block scales with GPU frame time.
- **`pbr_frag.glsl` — the pre-exposure placement comment names `WS_LIGHT_MAX`,
  a symbol this same branch deleted.** The constraint it describes no longer
  exists, which is exactly what makes Phase 1 possible.
- **`pbr_frag.glsl` — `DiffuseOut`'s "Working space already" comment is false**
  for one of the two taps that fill it.
- **`postfx.c` — two comments describe the tonemap dividing by the adapted
  mean.** The same commit deleted that code.
- **`exposure.c` — `EXPOSURE_MIN_GAIN`'s rationale is backwards.** `gain = key /
  adapted_luminance`, so a dark frame produces a *large* gain, caught by the
  `1.0` ceiling. The floor can only bite when metered luminance exceeds `64 x
  key = 11.52` nits — it limits darkening, not brightening.
- **`lum_measure_frag.glsl` — "the ceiling is the one pbr_frag already wrote
  under, so it clips nothing a shading pass let through."** SSR, SSGI, fog and
  SSS all add into the buffer after pbr_frag's clamp. The conclusion happens to
  hold; the stated reason does not.

## Phase 1 — One conversion site per shader

Three separate bugs, one fault. `Lo` is accumulated from four sites and each
needs its own `preExposure`; three got it wrong.

| site | what it adds | converted? |
|---|---|---|
| punctual loop | `brdf * radiance * NdotL * shadow` | yes |
| area-light branch | `ltc * colorIntensity * aShadow` | **no** |
| SSS back-transmission | `subsurfaceTransmission(..., lightCI * attenuation)` | **no** |
| `sssDiffuse` IBL tap | `kD * diffuse * aoMap * envScale` | **no** |

The area branch `continue`s before the line that pre-exposes; the SSS
transmission is passed the un-multiplied value from one line away; the
`sssDiffuse` accumulator is filled by one converted tap and one absolute one and
written unconverted to `DiffuseOut`.

**Severity.** Area lights are an unconditional `1/preExposure` term in the
metered buffer, so under the default `automatic = true` the gain has no positive
equilibrium for any panel brighter than 0.18 nits — it collapses to the floor
and the room renders black under a blown-out panel. `DiffuseOut` feeds
`hdr + blur(D) - D`; at 10.1's own measured gain of 0.0368 the IBL half is 27x
too large, so the subtract drives skin negative.

**Measured:** area-light scale invariance **399967 px (83.3%)** against 0 px for
the punctual case.

**Fix — do not patch the three sites.** Delete the per-light multiply and
convert once, at the composite:

```glsl
vec3 color = min((Lo + ambient + transmitted + emissiveMap) * preExposure,
                 vec3(WS_SCENE_MAX));
```

plus the matching multiply on `DiffuseOut`. Patching each site individually
leaves the same structure and a fourth path will land wrong.

This is only available *because* 10.1's phase 5a made the firefly clamp
dimensionless. Nothing between `radiance` and the composite is scale-sensitive
any more, so the multiply distributes out of the whole sum. The comment that
justified the early placement names the constant that used to sit in the way and
no longer exists.

*Gate: area-light scale test 0 px, SSS scale test 0 px, nine goldens 0 px (all
pin exposure, so this must be exactly identity for them).*

## Phase 2 — glTF punctual range

`import.c` recovers `Light.range` as `sqrt(1/quadratic)`. That is correct for
assimp's Blender loader, which fits `q = 1/dist^2`. It is wrong for the glTF2
loader, which sets `quadratic = 1.0` unconditionally as a **sentinel meaning
"inverse-square, no range"** and puts the authored range on node metadata as
`PBR_LightRange`. Nothing reads that metadata.

So every imported glTF point and spot light gets `range = sqrt(1/1) = 1.0`.
`light_cull_radius` returns that, so the light is culled past one metre.

**Measured:** a glTF authoring `"range": 25.0` imports as `range=1.000000`.

Combined with 10.0's (correct) removal of the `/683` divide, glTF lights now
arrive at the right magnitude with a one-metre reach — a worse failure than the
one that change fixed. The FBX path is wrong differently (`q = 2/decay^2`, and a
`1.0` default that lands on 1 m again).

**Fix:** read `PBR_LightRange` from the node metadata. When absent, leave
`range` at 0 — unbounded, which is KHR's default and what the field comment
already says it wants. Delete the inversion; it is a heuristic standing in for a
value the importer actually carries.

*Gate: a point-light glTF fixture round-trips its authored range; absent range
imports as 0, not 1.*

## Phase 3 — Fixtures that can actually fail

**This phase is the point of the document.** Land it first if anything slips.

The gaps, each mapped to what it would have caught:

- **`assets/area_scale_fixture.cscn`** — a Cornell box lit only by an area
  panel, for the scale test. Catches phase 1's area bug.
- **`assets/sss_scale_fixture.cscn`** — an SSS material with a punctual key, for
  the scale test. Catches phase 1's transmission and `DiffuseOut` bugs.
- **A reflective surface in the convergence fixture** so SSR is live, plus
  convergence runs with `--ssgi` and `--fog`. Catches phase 4's clamps.
- **`assets/point_import_fixture.gltf`** — a glTF authoring a point light with
  an explicit `range`. Catches phase 2. The existing `light_import_fixture`
  authors a directional, which is the one type that code path skips.

**The standing rule this encodes:** a gate that pins exposure cannot see a
space-mixing bug. Every scene-buffer term needs a scale-invariance run at a
non-unity exposure, and the scale test needs to cover every light type and every
post pass that writes into the HDR buffer — not one representative scene.

Consider a single `scripts/gates.sh` that runs the whole matrix, so "all gates
green" stops meaning "the subset I remembered".

## Phase 4 — The three remaining contract violations

`view.glsl` states the admission rule: a ceiling belongs there only if what it
bounds is genuinely measured in multiples of white, and anything scaling with
`1/preExposure` does not, "because auto-exposure meters through it and will
chase it". Three of its four constants break that rule, and all three are
upstream of the metering pass:

| constant | binds at | reaches meter via |
|---|---|---|
| `WS_REFLECT_MAX` = 2.0 | **+1 stop** | SSR composite |
| `WS_BOUNCE_MAX` = 4.0 | +2 stops | SSGI composite |
| `WS_MEDIA_MAX` = 500.0 | +9 stops | fog composite |

`WS_REFLECT_MAX` is the one to act on: 5x tighter than the `WS_LIGHT_MAX` that
demonstrably caused sustained drift, and SSR is on by default. These are
self-limiting rather than runaway (the clamp releases as the gain closes), which
is milder than phase 1 — but that was equally true of `WS_LIGHT_MAX`.

**Fix, per 10.1's own recipe: clamp the dimensionless factor.** For SSR that is
the reflected radiance *relative to the reflecting pixel's own* — a ratio. For
the GTAO gather, `rad / max(centre_radiance, eps)`. `WS_MEDIA_MAX` is different
in kind: it guards fp16 overflow of the volume, so it should move *upstream* of
the `* preExposure` and become an absolute storage bound.

Afterwards `view.glsl` holds the contract, `ViewParams`, and `WS_SCENE_MAX` —
which legitimately stays, since it guards a store that literally holds working
space. Single-consumer thresholds belong at their use site with a one-line
annotation, not compiled into twelve shaders that cannot use them.

*Gate: convergence with SSR, SSGI and fog all live (phase 3's fixture).*

## Phase 5 — Exposure semantics under absolute metering

10.1 made `preExposure` depend on constants that were tuned when `1.0` was
white. They are now load-bearing and in absolute nits:

- **`EXPOSURE_MIN_GAIN` (1/64).** Limits darkening to 6 stops. Metered
  luminance spans ~25 stops (starlight 1e-3, interior 50-500, overcast 2000, sun
  1e5+). Any scene averaging over 11.5 nits pins at the floor and blows out —
  i.e. most daylit photometric scenes, which is what the photometric work was
  for. Replace with a bound on the derived EV100, or drop it and rate-limit the
  slew, which is what "a cut to black should not spike" actually needs.
- **`lum_measure`'s `clamp(lum, autoKey, 10000.0)`.** The ceiling used to be an
  unreachable +13-stop guard; in nits it is ordinary daylight (overcast ~8000,
  sunlit white ~1e4), so on exteriors it binds across the frame and the mean
  pins to it. The floor at `autoKey = 0.18` means any scene averaging below that
  meters *as* the key, so the gain is exactly 1 and a candle- or moonlit scene
  renders near-black with auto-exposure structurally unable to help. The "only
  ever darkens" invariant was written for a normalised buffer and does not
  survive absolute input — decide deliberately whether to keep it.
- **`Exposure.bias` carries two meanings** split on `physical`, and the header
  claims the split is on `physical || automatic`. It is not, and `spores` is the
  live counter-example (`automatic` on, `physical` off, `bias = 0.15` used as a
  linear multiplier). The GUI slider is hardcoded to the linear range 0.05–8.0,
  so under an authored `post.camera` it is stops, cannot reach 0, and cannot
  stop down — while the CLI seeds `bias = 0.0`, below the slider minimum.
  Either split the field, or drive the GUI from `physical`.

Also unresolved and worth stating: **"scene radiance" is not yet one space.**
The sky path runs on an arbitrary scale (`KEY_LIGHT_TOTAL_INTENSITY = 10.0` as
lux, `SKY_SUN_ILLUMINANCE 3.0`, an analytic disc at 20.0, a bare 30000 clamp)
while the punctual path is genuinely photometric. Since the meter now compares
absolute radiance against an absolute key, a scene lit by an imported lamp and
one lit by the sky land ~4 decades apart, and a scene lit by both cannot be
exposed correctly for either. Either migrate the atmosphere to lux/nits or say
plainly in `view.glsl` that it is exempt.

## Phase 6 — Structural cleanup (no behaviour change)

- **Delete the GPU adaptation pass.** Nothing on the GPU reads `lum_adapt` any
  more — the tonemap's sampler is gone and unit 7 is bound to 0. It survives as
  a 1x1 ping-pong FBO pair, a shader, a fullscreen draw, two FBO binds, a
  viewport change and a uniform upload per frame, to compute `mix(prev,
  measured, 0.04)` with a deadband: three lines of C now that the value lives on
  the CPU. Read `lum_texture`'s top mip instead and do the EMA in `exposure.c`,
  beside the rest of the adaptation policy. Deletes the ping-pong, the program,
  `lum_adapt_frag.glsl`, the `MEASURE_TOP_MIP` C-to-GLSL coupling, the `reset`
  uniform, the `valid` flag, and the `lum_write ^ 1` indexing.
- **PBO + fence for the readback.** Measured 0.033 ms against 5.253 ms, a 160x
  reduction, still landing a fresh sample every ~3rd frame — far inside the
  25-frame time constant. A plain PBO is *not* enough (a blocking map two frames
  later still costs 4.672 ms, because the CPU runs more than two frames ahead);
  the fence poll is the part that matters. Fix the comment regardless of whether
  the code changes: as written it invites a second "free" readback.
- **`Exposure` by value on `Engine`.** Deletes `create_exposure`,
  `free_exposure`, the free-ordering comment, `postfx_set_exposure`, its
  unenforceable "call before first postfx_run" contract, and six `if (!ex)`
  guards. The worst of those guards skips the ViewParams upload entirely, leaving
  the UBO at its calloc'd zero — `preExposure = 0`, a black frame — as a silent
  fallback for an invariant that is unconditional.
- **`cscene.c` duplicates `light_canonical_units`** against a parallel enum, in
  a file that already includes `light.h`. Lift the `CSceneLightType -> LightType`
  mapping (a third copy of which sits in `cscene_apply.c`'s switch) and call the
  real thing. Better: a `light_units_valid_for_type()` predicate beside it, so
  the next asset path does not re-implement the check.
- **Comment corrections** from the list above.
- **Smaller:** `DiffuseOut` is the only attachment written without an fp16
  ceiling (relies on implementation-defined saturation; verified clean at 20M cd
  on this GPU, but by luck). `vec3(0.03)` survives in the
  `RENDER_MODE_SIMPLE_LIGHTING` path. `min(brdf, BRDF_MAX)` is per-channel, so a
  coloured spike desaturates toward white — the grey-cube failure one level in;
  a luminance-preserving form keeps the ratio. `BRDF_MAX`'s stated derivation
  does not match the path it guards, and it is numerically inert on the area
  branch. `taa_resolve`/`ssgi_accum` are near-verbatim duplicates of a YCoCg
  clamp plus inverse-luma blend that belongs in `color.glsl`.

## Sequencing

Phase 3 first — the fixtures are what make the rest verifiable, and landing them
before the fixes means watching each gate go red then green. Then phase 1 (one
edit, three bugs), then phase 2. Those three make the branch mergeable.

Phases 4–6 are follow-ups and can ship separately. Phase 5 in particular is
design work with look consequences, not cleanup, and deserves its own decision
rather than being folded into a fix pass.

## Verification

Every gate below runs at a **non-unity exposure** unless it is a golden. That is
the whole lesson.

1. Area-light scale invariance: 0 px (currently 399967).
2. SSS scale invariance: 0 px.
3. Punctual scale invariance: stays 0 px.
4. Fog scale invariance: stays at its 3 px floor.
5. Nine goldens: 0 px throughout — they pin exposure, so every phase-1 change
   must be exact identity for them. Movement means a writer was missed.
6. Auto-exposure convergence with SSR, SSGI and fog **live**, not just the bare
   room.
7. glTF authored range round-trips.
8. fp16 headroom: no Inf/NaN at 50,000 cd (passes today at 20,000,000).
