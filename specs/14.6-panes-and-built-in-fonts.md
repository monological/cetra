# 14.6: panes and built-in fonts

## Context

pcb's window (pcb spec 6.1, ARCH section 8) is a tree of panes. `|`, `\` and Space Enter split the
focused pane, `:q` closes it, Space m puts the messages under every pane and takes them away, and
Cmd+P shows another file in a code pane. Its fonts are built into the `pcb` binary, so the program
is one file. pcb's ARCH lists this as section 9's item 9, "what the panes and the fonts need of
cetra's UI"; this spec is that item.

cetra cannot do any of it today:
- **An element cannot be taken out or moved.** Elements are made under a parent and appended
  (`_new_element`, `ui.c:353`), and freed only with their whole screen or as a pane's virtual row
  (`_rows_drop`, `ui.c:1190`). A closed pane cannot go, and a split cannot put the pane it splits
  under a new row.
- **An editor shows one text for its life.** `ui_editor(parent, doc)` joins the text at creation
  (`ui_editor_make`, `ui_editor.c:652`); nothing points it at another.
- **Fonts load from a file path only.** `load_font` (`text.c:464`) and `create_glyph_cache`
  (`glyph_cache.c:73`) each read the file into a buffer they own.

Decided with the user (2026-10-31): this is a cetra spec of its own, the next number, before pcb
6.1; and pcb's fonts are built into its binary.

## Found while planning

- **`_rows_drop` already lets go of everything held inside an element it frees**: the pressed
  element, the bar being dragged, the focus last seen, and each screen's focus. Removing any element
  needs exactly that, so the two share it.
- **The vim mode remembers the last editor it saw by pointer** (`UIEditorVim.el`, compared in
  `_switch`, `ui_editor_vim.c:4904`) and never reads through it. An element freed and another made
  at the same address, or an editor shown another text, would inherit a half-typed command, an
  insert's open undo group or a visual area measured on the other text.
- **A text forgets a view that leaves it only partly**: `text_doc_remove_view` clears its undo
  records' view but not an undo group held to it (`group_view`, `text_doc.c:683`), which stays open
  on the text with no editor to close it.
- **Where an editor is scrolled is not public.** `ui_editor_scroll_place` is in the private
  `ui_editor_internal.h`, and nothing reads the scroll back. A pane going back to a file wants its
  carets and its view where they were.
- **The canvas app reads its fonts by path** (`canvas_app.c:1516`, `:1845`, `:2649`, `:2715`), the
  `--editor` mode among them, so it is the place to prove the built-in path end to end.
- `cetra_embed_shaders` (`cetra/CMakeLists.txt:148`) already builds an app's GLSL into a header;
  files of bytes have no such helper.

## The design

### 1. Elements taken out and moved (`ui.c`)

- **`void ui_remove(UISystem* ui, UIElement* el)`** takes `el` out of its parent and frees it with
  everything under it. Whatever the system or a screen held inside it is let go first -- the
  pressed element, the bar being dragged, the focus last seen, and a screen's focus, which is left
  on nothing. One function does that letting go for this and for `_rows_drop`.
  Refused by name: a screen's root, a pane's virtual row (the pane builds and frees its own), and an
  element of no screen of `ui`'s.
- **`void ui_move(UIElement* el, UIElement* parent, size_t index)`** takes `el` out of its parent
  and puts it under `parent` at `index`, the end when `index` is past the last child. It keeps
  everything it holds: an editor's carets and scroll, a field's text, the focus.
  Refused by name: a screen's root, a move into `el` itself or under it, a pane's virtual row or a
  move into a pane with virtual rows, and a move to another screen, whose focus would be left
  pointing out of it.
- A split in a host is then a new row at the pane's index, the pane moved into it, and a new pane
  beside it; the messages under every pane are a new column at the root's place with the old
  content moved into it. Neither needs anything more.

### 2. An editor shown another text (`ui_editor.c`, `text_doc.c`, `ui_editor_vim.c`)

- **`void ui_editor_set_doc(UIElement* el, TextDoc* doc)`**: the editor leaves its text and shows
  `doc` from its start -- one caret at 0, scrolled to the top, its rows and its budget started
  afresh. Its mode, its find query and its look stay. NULL shows nothing, as a text freed first
  does; the same text again changes nothing.
- **A text forgets a view that leaves it**, its undo group too: `text_doc_remove_view` closes a
  group held to that view, the step as far as it got. That covers an editor freed as well as one
  shown another text.
- **An editor has a serial**, new when it is made and each time it is shown another text (private,
  `ui_editor_serial` in `ui_editor_internal.h`). The vim mode compares serials, not pointers, so a
  freed editor's successor at its address, or an editor shown another text, lets go of what was
  unfinished as reaching another editor does.
- **Where the view is:** `size_t ui_editor_top(const UIElement* el)` is the offset starting the
  row at the view's top, and `ui_editor_scroll_place` moves from the private header to
  `ui_editor.h`. A host going back to a file sets its carets with `ui_editor_set_selections` and its
  view with `ui_editor_scroll_place(el, top, 0)`.

### 3. Fonts from bytes (`text.c`, `glyph_cache.c`)

- **`Font* load_font_memory(FontPool* pool, const char* name, const void* bytes, size_t size, float
  base_size, bool use_sdf)`**: a font from a TrueType file's bytes, copied, since stb_truetype reads
  them for as long as the font lives. The pool keeps it under `name`, so a second load of that name
  shares it as a second `load_font` of a path does. `load_font` reads its file and calls it, so
  there is one way a font is made.
- **`GlyphCache* create_glyph_cache_memory(const void* bytes, size_t size, float pixel_size)`**,
  the same for the editor's face; `create_glyph_cache` reads its file and calls it.
- The same bytes give the same font, to the byte: its glyphs, its kerning table and its atlas.

### 4. Files built into an app (`cetra/CMakeLists.txt`)

- **`cetra_embed_files(<target> <name> <file>...)`**, beside `cetra_embed_shaders`: each file as a
  `const unsigned char <stem>_bytes[]` and its `size_t <stem>_size` in `<target>_<name>.h`, for the
  target alone to include; a stem's characters past letters, digits and `_` become `_`. A small
  generator, `cetra/gen_embed_header.py`, writes it.
- **The canvas app takes its fonts from its binary** this way: Roboto, PressStart2P and JetBrains
  Mono.

### 5. The canvas app's editor, as panes

`--editor FILE` may be given more than once. While the editor shows:
- **F8** splits the focused editor, the same text beside it with carets of its own;
- **F9** closes the focused editor, the focus going to the one left;
- **F10** shows the next file in the focused editor, back where it was in that file.

These are a test bed for sections 1 and 2, not pcb's panes, whose keys are pcb's.

# As built

## Phase 1: elements removed and moved, as built

- **`ui_remove(ui, el)` and `ui_move(el, parent, index)`** (`ui.c`, `ui.h`). The letting-go that
  `_rows_drop` did inline is `_forget`, shared by the two; `_detach` takes an element out of its
  parent's children, and `_root_of` finds its screen's root.
- **An element removed during a pass is freed when the pass ends.** This was not in the plan.
  F9, or pcb's `:q`, closes an editor from its own key, inside `_route_keys`, which then calls the
  editor's `keys_end`. A button whose action removes it returns into the input pass, which then
  writes `hovered->state`. So `ui_layout`, the input pass and the build each count as a pass
  (`UISystem.passes`). An element removed during one is taken out and let go of at once, and freed
  as the last pass ends. It is let go of again just before it is freed, since the pass may have
  taken hold of it since: a press captured before the callback that removed it.
- **`ui_move`'s index counts the children once the element is out**, so a move within one parent
  reads as the order wanted. `ui_move` takes no system, so "another screen" is two different
  roots.
- **The text forgetting a view's group came forward from phase 2.** `ui-remove`'s mid-insert check
  needs it. `text_doc_remove_view` also forgets the text's typing record when it is that view's
  (`doc->typing.view`): an editor made later at the same address would otherwise join typing that
  was not its own.
- **Private:** `ui_system_held` (`ui_internal.h`) reads the pressed element, the held bar and the
  focus last seen, for the arm.
- **Arms** (`ui` group): `ui-remove` (11 flags), `ui-move` (9).
- **Falsified** on the committed work:
  - Without `_forget` in `ui_remove`, the focus, seen, pressed and bar flags read 0.
  - Without the group closed in `text_doc_remove_view`, the insert flag reads 0.
  - `own_action` stays 1 either way, since the pass's end lets go again.
  - The case also passes with `MallocScribble` set.
- **Gates:** `ui` and `gate-docs` pass.

## Phase 2: an editor shown another text, as built

- **`ui_editor_set_doc`** (`ui_editor.c`). `ui_editor_make` and it share one helper, `_show`,
  which sets up what belongs to a text: one caret at 0, the view at the top, every line's rows a
  guess at the columns last laid out, and the budget started afresh. The text left is told first
  (`text_doc_remove_view`, which closes a group held to the editor: phase 1). The mode, find's
  query, the face and the geometry stay.
- **The serial** (`ui_editor_serial`, private) comes from a counter at every `_show`, so a new
  editor and a new text each get one. The vim mode keeps the serial (`UIEditorVim.editor`) where
  it kept the element's address. `_switch` compares it, and `_pointer` calls `_switch` for any
  editor showing a text.
- **`ui_editor_top(el)` is public** and returns the offset. The private hook of the same name,
  which returns the line, the row and the columns and which the probes read, is renamed
  `ui_editor_view_top`. `ui_editor_scroll_place` moved to `ui_editor.h`.
- **Found:** going back to a file means bringing what was kept through the edits made since. The
  arm does it with `text_doc_map`, as a host will: an edit made in the text while the editor showed
  another put the kept top two bytes behind.
- **Arms** (`ui` group): `ui-editor-set-doc` (7 flags), `ui-vim-set-doc` (4).
- **Falsified** on the committed work:
  - The serial kept across texts fails all four vim flags; the view not put back to the top fails
    `start`.
  - The vim mode comparing element addresses, as before 14.6, fails all four, the freed case among
    them. The probe says the new editor took the freed one's address, and the freed case presses
    Esc first, so it stands apart from the cases before it.
- **Gates:** `ui`, `canvas`, `idle` and `gate-docs` pass.

## Phase 3: fonts from bytes and files built in, as built

- **`load_font_memory` and `create_glyph_cache_memory`.** Each loader pair has one maker behind
  it: `_make_font` in `text.c` and `_make_face` in `glyph_cache.c`. The maker takes a buffer and
  keeps it. A path loader hands it the buffer it read, and a byte loader hands it a copy. The plan
  had a path loader call the byte loader instead, which would have copied every file twice and lost
  the file's name from the errors. A font made from bytes keeps no `filepath` (NULL).
- **`cetra_embed_files` changed shape, at the user's direction: a font is named only where it is
  defined.**
  - **The new call** gives each file after a name saying what it is for:
    `cetra_embed_files(canvas fonts LABEL <file> PIXEL <file> EDITOR <file>)`.
  - **The generated header** holds a table, `CetraEmbeddedFile canvas_fonts[]`, indexed by
    `CANVAS_FONTS_LABEL` and the rest. Each entry is the file's own name, its path from the source
    root, its bytes and their count.
  - **Why:** the first shape gave each file a `<stem>_bytes` array and a `<stem>_size`. The app
    then named every font three more times: a name to keep it under in the pool, a path for the
    probe, and the arrays. Its error message named one a fourth time.
  - **Now** the file is named only in the CMake list, and the app says only what each font is for.
- **An entry's size is the count of the bytes written into its array**, not the file's size read
  again. The falsification found this (below).
- **The canvas app's three fonts are built in**, and the pool keeps each under its file's name.
- **Arm** (`canvas` group): `canvas-font-memory`, under `--font-sheet --canvas-probe`. The plan
  called it `font-memory`; it takes the group's prefix.
- **Falsified** on the committed work:
  - With the generator dropping each file's last byte, the bytes still read as equal at first: the
    size came from the file on disk, so the comparison ran one byte past the array. With the size
    fixed, the bytes read 0 of 3.
  - A font from bytes made a pixel larger than asked reads fonts 0 of 3. A face from bytes made a
    pixel larger reads faces 0 of 3. A font's last byte is read by nothing, so the face check
    needed its own mutation.
- **Look:** the font sheet, headless, draws as before: the labels from the built-in Roboto, and the
  editor's face as bitmaps and as a distance field.
- **Gates:** `ui`, `canvas`, `idle` and `gate-docs` pass.

## Phase 4: the canvas app's editor as panes, as built

- **`--editor` may be given up to eight times.** Each file is an `EditorFile`: its text, its
  parse and the version that parse read. Each pane is an `EditorPane`: its editor, the file it
  shows, and where it last was in each file. The panes sit in a row, `area`, with no padding of
  its own, so one pane stands where the editor alone stood.
- **F8 splits**, as pcb's `|` will: a row is put at the pane's index, the pane is moved into it
  (`ui_move`), and a second editor on the same text goes beside it with the focus.
- **F9 closes** (`ui_remove`), from the pane's own key, so the editor is freed as the pass ends.
  A row left holding one pane hands it to the row's parent, and the row goes. The focus goes to the
  pane now standing in the closed one's place. The last pane stays.
- **F10 shows the next file** (`ui_editor_set_doc`). The pane keeps its selections, with the
  primary last, and the offset at its view's top, at the text's version. On return they are brought
  through the edits since with `text_doc_map`, then put back with `ui_editor_set_selections` and
  `ui_editor_scroll_place`.
- **F6 and F7** act on the focused pane's file. The vim line answers the editor that asked for it
  (`EditorSheet.asking`).
- **The probe's `canvas editor` lines** describe the focused pane, so the 14.4 and 14.5 arms read
  as before. Each pane (`canvas pane`) and each file's text (`canvas file`) is printed besides.
- **Arm** (`canvas` group): `canvas-panes`. It makes three runs on two files: one opened, one
  split and switched with a click across, and the same closed.
- **Falsified** on the committed work:
  - The kept carets put back without being brought through the edits: the second pane returns
    with its caret at 1, not 15.
  - **A removal inside a pass freed at once (phase 1's rule) crashes the app** when F9 closes a
    pane from its own key under `MallocScribble` (exit 139). It is the use after free the deferral
    exists for, seen in the real app.
- **Look:** headless, two panes side by side, the focused one's border lit and its caret back
  after the X. The user's own look in a window is the command in the hand-off.
- **Gates:** `ui`, `canvas`, `idle` and `gate-docs` pass.

## Phase 6: reviews, as built

Five reviews ran in background agents over `71dd6557..91890e1f`: `/simplify`'s four angles (reuse,
simplification, efficiency, altitude) and a correctness pass. Every one was back before anything
was applied.

**Applied** (`6271f43b`, `79dc52de`, `b7f38a05`):

- **An editor's first row top was never set.** `_show` grew `tops` with `grow_array`, which does
  not zero, where `ui_editor_make` had used `calloc`. Nothing writes `tops[0]`, and every row's
  place is summed from it, so a new editor could start from garbage. With freed memory scribbled
  over and `tops[0]` left unset, 14.4's `editor-carets` reads `bar_then_drag 0`. `_show` zeroes it
  now, and `ui-editor-carets` runs scribbled so it keeps seeing this.
- **A key's character goes where its key went.** A key that makes a character, used by a command
  that moves the focus, typed its character into the newly focused editor. pcb's `|` split would
  have typed a `|` into the pane it made. `_route_keys` now hands that character to the element
  that took the key, whose swallow takes it. Nothing is dropped, so the text field, which uses
  every key, still types (14.5 refused a drop there for that reason). The test, a printable key
  with neither Ctrl nor Cmd, is `ui_typing_makes_char`, shared by the editor and `ui.c`.
  `ui-move` gained `key_char`.
- **One leaving path.** A pane's dropped rows were still freed at once inside the layout pass.
  `_leave` now frees or defers for both rows and removed elements. A second refusal goes into
  `ui_move`: a move into one of a pane's built rows, which the pane would free.
- **The late-free arms run with freed memory scribbled over** (`_SCRIBBLED`: `MallocScribble`,
  `MALLOC_PERTURB_`). This covers `ui-remove` and `canvas-panes`' close; before, a free not
  deferred passed on unscribbled memory. Falsified: `_leave` freeing at once crashes the scribbled
  `remove` case (exit 139), and taking out the character handoff reads `key_char 0`.
- **The canvas vim line hands on when its pane closes.** F9 on the pane that asked for the line
  left `asking` pointing at a freed editor. It now moves to the pane given the focus.
- **Embedded files get a source of their own.**
  - Before, the header held the bytes as `static` arrays: 3.3 MB, re-read with every compile of
    `canvas_app.c` (about a second each time). A second file including it got a second copy.
  - Now `<target>_<name>.c` defines the table, its bytes written in decimal (1.5 MB), and
    compiles only when a file changes. The header declares it `extern`.
  - `CetraEmbeddedFile` lives in a public `embedded_file.h`, defined once. An entry's size is
    `sizeof` its array.
  - The generator refuses by name a table name C cannot use, index names equal but for case, two
    files of one name (one pool key) and an empty file.
- **Smaller:**
  - `ui_editor_top` and `ui_editor_row_at` share `_row_down_from_top`.
  - `_show` leaves its old text itself and resets a press under way.
  - `ui_remove` names a second removal as such.
  - `free_ui_system`'s dead loop is gone.
  - `Font.filepath`, which nothing read, is gone; `_pooled` is `get_font` and `font_retain`.
  - The canvas app has `pane_row`, a packed pane list with `pane_free`, `built_in_font` taking a
    pool (which the probe uses), and `probe_atlas` reading through `atlas_of`.
  - The probe's `move` uses the public `ui_editor_scroll_place` and `ui_editor_top`, and

**Tried and backed out:** folding the editor's `_of` and `_seen` into one helper. The two exist
for cppcheck: `_of` takes a non-const element so the mutators stay non-const. Folded, cppcheck

**Not applied, for the user:**

- **Going back to where a pane was in a file is the host's to write.** The canvas app writes it,

  4,096 changes.
  - The deeper form, from the altitude review: the editor keeps its place in each text it leaves,
    as a parked view that the text moves at every change, and `ui_editor_set_doc` restores it.
  - Smaller forms: `ui_editor_set_selections` taking the primary as an index, or a helper mapping
    a selection list by version.
  - Each is new API.
- **`ui_index(el)`**, or `ui_move` taking a sibling, so a host does not walk its parent's children
  for an index (the canvas app's `index_in`). New API.
- **An editor shown a text again re-wraps it whole**, at 192 KB a frame: about 52 frames for a

- **The editor's state for the text it shows** could sit in a struct of its own that `_show`
  resets in one assignment, rather than a list `_show` has to keep complete. The list is

## Phase 7: the thermo-nuclear review, as built

Not in the plan. A thermo-nuclear quality review of `master..5fd34a43` ran in background agents, at
their default effort, and every one was back before anything was applied. Five of its findings were
new API and went to the user; each was taken.

**The user's decisions** (`01a78778`):

1. **An editor keeps its place in every text it has shown**, as a vim window keeps a buffer's.
   This was phase 6's first item for the user, in its deeper form.
   - Everything an editor holds about the text it shows is one struct, `UIEditorPlace`: the
     selections and their wanted columns, every line's rows and tops, the view's top, the guesses
     and the highlighter's walk. That was phase 6's last item for the user.
   - Leaving a text, the editor PARKS its place on it as a view, so every edit made there moves
     it as it moves an editor showing the text, the changed lines' rows made guesses again.
     Shown that text again, the editor takes the place back, rows and all, so the whole re-wrap
     phase 6 listed is gone. Rows wrapped at other columns are guesses on return.
   - A text freed lets its parked places go; freeing the editor frees the rest.
   - The canvas app's F10 is `ui_editor_set_doc` and nothing else, and the probe keeps no place
     of its own. Nothing keeps a version or calls `text_doc_map` to come back.
   - **A place asked for before the editor is laid out on its text is held for that layout**
     (`ui_editor_scroll_place`, `ui_editor_reveal`): before it, the editor has no row height and
     wraps at no columns. A split's new pane is placed so.
2. **A used key's character is dropped in ONE place**, `_route_keys`: the character event straight
   after a key something used that makes one, whatever holds the focus at its turn.
   - Phase 6 had handed the character to the element that took the key, whose own swallow flag
     took it. That was two owners of one rule, and a third the day a widget other than the editor
     wanted it.
   - 14.5 refused a drop in `_route_keys` because the text field said it used every key, so a
     drop there stopped every field typing. The field now says it used a key only when it acted
     on it: its shortcuts (Cmd+A, C, X, V and Z, and Ctrl+Y off macOS) and the keys it moves,
     deletes and submits by. A letter is typed from its character, and its key is not used.
   - The editor's swallow flag, its `keys_end` and `ui_typing_makes_char` are gone; the test is
     `ui.c`'s own `_makes_char`.
3. **`ui_remove(el)`**, no longer `ui_remove(ui, el)`. An element knows its screen through its
   root (`UIElement.screen`, set on a screen's root alone), and the screen its system.
4. **`ui_move(el, parent, before)`**, no longer an index: `before` is the child of `parent` to go in
   front of, NULL the end, as the DOM's `insertBefore`. The index had to say whether it counted the
   children with the element among them, which phase 1 documented rather than settled, and the
   canvas app walked its parent's children to find one (`index_in`, gone). `before == el` stays
   where it is; a `before` not a child of `parent` is refused by name.
5. **`ui_editor(parent, NULL)`** makes an editor showing nothing, and **`ui_editor_doc`** is public,
   so a host finds a pane's file from the pane.

**Plain fixes** (`01a78778`):
- **The removed elements are a list through themselves** (`UIElement.removed_next`), so a removal
  cannot fail for memory. `_pass_end` frees them without forgetting them a second time. The second
  `_forget` was for a pass taking hold of an element after the callback that removed it, and none
  does: the pointer's element is hit after the layout drops its rows, and the press and the focus
  are taken before the callbacks they are handed to, so a removal inside one lets go of them.
- **`ui_set_focus` refuses an element not on its screen**: another screen's, which had been taken as
  a focus nothing could reach, or one taken out, which had been kept as a focus on what the pass's
  end then freed.
- **`ui_system_held`**, which only the probe reads, moved to a private `ui_hooks.h`, out of
  `ui_internal.h`.
- **The vim mode**: one `_enter` makes the editor the one being driven for the keys, the pointer,
  a search and a `:` line, which four places had each spelt out. Its open undo group is a flag
  rather than the text it was opened in: keys reaching another editor, or this one shown another
  text, let go of the group first, so the text is always the one the keys reach.
- **`text_doc_remove_view` ends a view's typing through `text_doc_seal_undo`**, the one statement
  of what that is, rather than writing its count itself.
- **Embedded files**: `CetraEmbeddedFile` lost its `name`, and a font is pooled under the file's
  path from the source root. Two files of one name in two directories are no longer refused; they
  are two fonts.
  - The generator writes the path as an escaped C string, so a quote or a byte past ASCII in a
    path cannot break the source.
  - `cetra_embed_files` refuses an odd or empty list by name at configure.
  - `CETRA_SHADER_PYTHON` is `CETRA_PYTHON`, since it runs both generators.
- **The canvas app's panes are the UI's tree itself.** The pane table, its spots, its cap and
  `index_in` are gone: a pane's file is found by `ui_editor_doc`, the panes by walking the tree,
  and the focused pane is the focused editor. A split is `ui_move(row, parent, el)` then
  `ui_move(el, row, NULL)`; a close is `ui_remove`, and a row left with one pane is collapsed by
  moving that pane in front of it and removing it. `build_editor` names its own failures.
- **The probes**:
  - `paired-char` gained `moved dropped` (a used key that moved the focus) and `field typed` (a
    field types its letters).
  - `remove` gained `focus refused`; `move` gained `before order` and `before refused`, and lost
    `key_char`, which `paired-char` now holds.
  - `set-doc` checks the place coming back on its own (`back where`), held for the first layout
    (`fresh placed`), and let go with its text (`parked freed`).
  - `vim-set-doc` prints whether the allocator gave the new editor the freed one's address, and
    the arm says so when it did not, since then the case proves less.
  - The canvas probe prints the panes' tree and the pane the vim line answers; `canvas-panes`
    reads both, through a nested split and close and a close under `--vim`.

**Not moved:** Roboto and PressStart2P stay in `apps/splash/assets/`, where other apps read them.

**Falsified**, each broken in the committed code, the probe run with freed memory scribbled over,
