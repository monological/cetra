# Spec 12.2 — The game UI layer

## Context

`docs/game-engine-roadmap.md` Part 3 item 4: **Game UI / menus — Absent (ImGui is dev-only; SDF
text exists)**, ~2–3 weeks, the next thing after 12.1. It is the last remaining gap that blocks
"a game" rather than "a shipped game": there is no main menu, no pause screen, no settings screen
and no HUD, and nothing in the tree to build one with.

Confirmed absent by sweep: zero occurrences of widget / button-as-UI / HUD-as-system / menu /
layout / anchor / nine-slice / sprite quad / screen rect / hit test anywhere in `cetra/src` or
`apps/` outside `src/ext/`. The only GUI is `gui.c` (1271 lines of cimgui), a renderer-tuning
panel.

**ImGui is not the answer, and the reasons are structural rather than aesthetic.** The ImGui
frame only exists when a debug flag is on — `engine->gui_frame_active = show_gui || show_fps ||
show_camera_hud` (`engine.c:2498`) gates `NewFrame`, so in a shipped run with all three false
there is no frame and `igBegin` is a call outside one. `igRender()` is unconditional inside
`gui_render_frame` (`gui.c:1269`), so a game menu would share a draw list with the debug panels
and be drawn over by them. Its font is a baked bitmap atlas, not the engine's SDF path. Its
gamepad navigation is its own, separate from the action table 11.109 built. ImGui stays what it
is: the dev panel.

**Nor is this a re-implementation of ImGui.** Its in-tree core is 55,774 lines, and what those
lines are FOR is floating/resizable/dockable/z-ordered/scrollable windows with `.ini`
persistence, an ID stack, ~60 widgets, tables, and its own anti-aliased vector rasteriser plus
font-atlas baker. A retained tree of full-screen screens has no floating windows, no docking, no
z-order and no ID stack — identity is the node pointer, which is the problem immediate mode
invents for itself and then solves. The engine already has a renderer and an SDF glyph atlas, so
there is no rasteriser and no baker. What remains is a layout pass, a focus model, hit-testing,
six element kinds and a theme.

**The scope discipline this spec rests on: the element list is CLOSED.** Panel, label, button,
toggle, slider, selector. Anything else goes through the escape hatches — a custom draw
callback, a custom shader program, or the raw draw-list and hit-test primitives. A layer that
grows a seventh element by request is the failure mode, and the `ui-elements-closed` arm asserts
the list against the header.

**Non-goals** (stated, not built): rich-text markup and reflow around shapes; vector/morph
animation; video; virtualised scrolling lists; text ENTRY (no char input reaches game code —
`glfwSetCharCallback` goes straight to ImGui at `engine.c:856` — so a name field is a later
spec); ImGui replacement for the debug panel; localisation and RTL; `.cscn` or file-based menu
authoring (menus are C); save games (this spec carries SETTINGS only).

## Design

### 1. The overlay hook (`cetra/src/engine.h/.c`)

**There is no post-tone-map draw hook today.** `engine_present_frame` is internal
(`engine_internal.h:45`) with exactly one caller (`engine.c:2772`), and the only thing that draws
after PostFX is `gui_render_frame` (`engine.c:1863`). An app's `render` hook draws into the MSAA
HDR scene FBO at RENDER resolution (`engine.c:2664-2669`), so anything drawn there is
tone-mapped, bloomed, graded, grained and TAA'd, and rescaled by `--render-scale`.

Add one general hook rather than a UI-shaped one:

```c
typedef void (*EngineOverlayFunc)(Engine*, void* user);
void engine_set_overlay(Engine*, EngineOverlayFunc, void* user);   // BY FUNCTION (installs)
```

Called in `engine_present_frame` after the post chain and the debug blits
(`engine.c:1849-1858`) and **before** `gui_render_frame` — the debug panel is a developer's
overlay and belongs on top of the game's. The engine does not learn what a `UISystem` is; the UI
installs itself with `ui_attach(ui, engine)`. A letterbox, a fade-to-black or an app's own HUD
are the same hook's other consumers.

Two consequences worth stating: with nothing installed the hook is a NULL compare, so all 31
goldens must be 0 px after phase 2 — that is the phase's gate. And because screenshot capture is
at `engine.c:2780-2793`, AFTER `engine_present_frame`, **a menu appears in a headless
screenshot** — which is what makes a menu golden and the pixel arms possible.

### 2. Coordinate space and the draw list (`cetra/src/ui_draw.c`, new)

**Window points, top-left origin, +Y down.** This matches the text renderer's ortho
(`glm_ortho(0, w, h, 0, ...)`, `text.c:735`, deliberately in points not framebuffer pixels —
`engine.c:1103-1109` records why) and `input_mouse_pos` (GLFW window coords, `input.h:98-99`).
So text metrics, hit-testing and ImGui all agree and nothing converts. The engine's own
`InputState` is framebuffer pixels with +Y up (`input.h:9-12`) and is NOT used by the UI.
DPI scaling is free: points mean the UI is the same physical size on Retina and is captured at
framebuffer resolution.

The UI owns its own program pair, `cetra/shaders/ui_vert.glsl` + `ui_frag.glsl`, and a dynamic
vertex buffer:

```c
typedef struct UIVertex { float x, y; float u, v; float r, g, b, a; float mode; } UIVertex;
// mode: 0 flat, 1 textured, 2 SDF glyph
```

One draw per (program, texture, clip rect). A menu of flat panels plus one font is two draws.

**Rejected: reusing `TextMesh` / `render_text_2d`.** It is one `glDrawElements` per mesh
(`text.c:798`) and one mesh per glyph when letter tracking is wanted (`splash.c:78-117`); it
clobbers rather than restores GL state (`text.c:801-803` unconditionally re-enables depth test
and disables blend); `sdfEdge`/`sdfSmoothing` are hardcoded (`text.c:770-771`); and it sets no
viewport. What IS reused, and is the good part of that file, is `Font` — stb_truetype SDF
baking, the auto-growing 1024² atlas, the ref-counted glyph cache and `font_get_glyph`
(`text.c:74-317`). The UI builds its own vertices from those glyphs.

**Rejected: `mesh_generate_rect` for panels.** It emits no UVs at all (`_flat_plane_attributes`,
`geometry.c:119-137`), so it cannot carry a texture, a gradient or a 9-slice; a rounded rect is
129 vertices at `RECT_RESOLUTION 32`; and `position` means the CENTRE in the sharp branch
(`geometry.c:324`) but a shifted corner in the rounded branch (`geometry.c:251-260`). Emitting
quads into the draw list directly avoids all three and leaves `geometry.c` untouched — rounded
corners and borders become a signed-distance evaluation in `ui_frag.glsl`, which is exact at any
radius and costs no vertices.

Draw-list API, public on its own (escape hatch 3):

```c
void ui_draw_quad(UIDrawList*, UIRect, vec4 color);
void ui_draw_textured_quad(UIDrawList*, UIRect, const Texture*, vec4 tint);
void ui_draw_9slice(UIDrawList*, UIRect, const Texture*, const float insets[4], vec4 tint);
void ui_draw_rounded(UIDrawList*, UIRect, float radius, vec4 fill, vec4 border, float border_w);
void ui_draw_text(UIDrawList*, UIRect, const char*, const UIStyle*, UIAlign);
void ui_push_clip(UIDrawList*, UIRect);  void ui_pop_clip(UIDrawList*);
bool ui_rect_hit(UIRect, float x, float y);
```

### 3. Elements, layout and theme (`cetra/src/ui.c/.h`, new; `CETRA_PUBLIC_HEADERS`)

**Retained tree.** A `UIScreen` owns a tree of `UIElement`. Identity is the pointer, so hover /
focus / active / easing state lives on the element and there is no ID stack.

Six kinds, closed: `UI_PANEL`, `UI_LABEL`, `UI_BUTTON`, `UI_TOGGLE`, `UI_SLIDER`, `UI_SELECTOR`.

```c
UISystem*  create_ui_system(Engine*);          void free_ui_system(UISystem*);
void       ui_attach(UISystem*, Engine*);      // installs the overlay hook
void       ui_set_font(UISystem*, Font*);      void ui_set_theme(UISystem*, const UITheme*);

UIScreen*  ui_screen(UISystem*, const char* name);
void       ui_screen_layout(UIScreen*, UIDir, UIAlign main, UIAlign cross);
void       ui_screen_set_modal(UIScreen*, bool);          // modal captures input
void       ui_push(UISystem*, UIScreen*);  void ui_pop(UISystem*);  void ui_pop_all(UISystem*);

UIElement* ui_panel   (UIElement* parent);
UIElement* ui_label   (UIElement* parent, const char* text);
UIElement* ui_button  (UIElement* parent, const char* text, UIActionFn, void* user);
UIElement* ui_toggle  (UIElement* parent, const char* text, bool* bound, UIActionFn, void* user);
UIElement* ui_slider  (UIElement* parent, const char* text, float lo, float hi, float* bound,
                       UIActionFn, void* user);
UIElement* ui_selector(UIElement* parent, const char* text, const char* const* opts, int n,
                       int* bound, UIActionFn, void* user);

void ui_update(UISystem*, GameInputState*, float dt);   // layout -> hit -> nav -> callbacks
```

A control binds a `bool*` / `float*` / `int*` directly and writes through it. That works because
since 11.108 the engine's settings ARE plain fields — `engine->postfx->bloom_enabled = x` is the
supported way to set it — so a settings screen needs no adapter. The callback is for the side
effect (`audio_set_bus_volume`), not for the store.

**Layout is a pure function** `ui_layout(screen, width, height)` filling every `element->rect`.
No GL, no time, no input. Box model: per-axis `UI_FIXED` (pixels) / `UI_FIT` (content) /
`UI_GROW` (share the remainder), plus padding, spacing, direction and main/cross alignment, plus
`ui_anchor(el, UI_FILL)` for a full-screen backdrop. Two passes — measure bottom-up for FIT,
arrange top-down for GROW and alignment. That purity is the whole verification story: the `ui`
gate group asserts laid-out rects with no GPU at all.

**Text wrapping and alignment live HERE, in the UI's own text layout** — a label with a
constrained width breaks on word boundaries using `font_get_glyph` advances. It is deliberately
not a revival of `TextMesh`'s `alignment` and `max_width`, which are stored by public setters and
read by nothing (`text.c:339/402/405`, `text.c:340/409-413`, and `text_measure_height` is
literally `(void)max_width; // TODO` at `text.c:621`). A setter that stores and does nothing is
worse than an absent one — the 11.107/11.108 line. **Those three dead entry points are deleted**
(after a grep proves no caller; `apps/splash` hand-rolls its centring with `text_measure_bounds`
and does not use them).

**Theme: a struct of plain fields, zero = the engine default**, the `CameraDesc` / `LightDesc`
convention from 11.106 — fill the fields you mean.

```c
typedef struct UIStyle {
    vec4 bg, fg, border;  float border_width, corner_radius;  float padding[4]; // t r b l
    float font_size;  Font* font;                 // 0 / NULL = inherit
    Texture* bg_tex;  float bg_slice[4];          // NULL = flat; 0 insets = stretch
} UIStyle;

typedef struct UITheme {
    Font* font; float font_size, spacing;
    UIStyle panel, label;
    UIStyle button[UI_STATE_COUNT];   // normal / hover / focus / active / disabled
    UIStyle toggle[UI_STATE_COUNT], slider[UI_STATE_COUNT], selector[UI_STATE_COUNT];
} UITheme;
```

Per-element override with `ui_set_style(el, const UIStyle*)`. The layer eases `el->t_hover` and
`el->t_focus` toward their targets each frame, so a focused control can grow, tint or drive a
shader with nothing animated by hand; `ui_screen_transition(screen, UI_FADE|UI_SLIDE, seconds)`
for screen changes. **`ui-theme-identity` asserts that a zeroed style renders byte-identically to
one with the theme's values copied in explicitly** — proving "zero = default" is a resolution,
not a second code path.

### 4. The escape hatches — why this is not a closed box

1. **Custom draw**, keeping layout, focus and input:
   `void ui_set_draw(UIElement*, UIDrawFn fn, void* user);` with
   `typedef void (*UIDrawFn)(UIElement*, UIDrawList*, void* user);`
2. **Custom program.** `void ui_set_program(UIElement*, ShaderProgram*);` breaks the batch and
   draws that element with its own fragment stage, with a stated uniform contract:
   `uRect` (x, y, w, h in points), `uResolution`, `uTime`, `uFocus` (the eased 0..1 weight),
   `uTex`. This is the shader-driven animated background. An app carrying its own GLSL is
   precedented by `apps/network` (its own two shaders on a material, `time` set per frame).
3. **The primitives alone.** §2's draw-list calls plus `ui_rect_hit` and the action table, for
   anything the element vocabulary refuses — a radial wheel, a diegetic panel, a map.

**A callback is an ordinary C function, so a button may do anything, including replace the
scene** — the UI has no opinion about the world. Two properties fall out of placement and cost
nothing: callbacks fire inside `ui_update` in `on_pre_render` (`game.c:269` ← `engine.c:2628`),
which is BEFORE `scene_propagate_transforms` (`engine.c:2633`) and the camera derive
(`engine.c:2640`), so a scene swapped by a button is walked, culled and shadowed THAT frame with
no one-frame flash. And because pausing stops only the fixed step (`game.c:207`) while the whole
render path keeps running, "a menu over a live 3D background" needs no support at all — load the
scene, leave the sim paused, push the screen. The layer is additive and never takes the frame
over.

### 5. Input routing (`cetra/src/game/input.c/.h`, `cetra/src/game/game.c`)

Three defects have to be settled or a menu fights the game:

- **`input_update` polls GLFW directly and never consults ImGui's capture flags**
  (`input.c:153-157`); only scroll is filtered, upstream at `engine.c:1227`. So today, typing in
  a debug slider also walks the character.
- **A menu must consume input**, and guarding every call site by hand is the error-prone shape.
- **Escape is hard-wired to quit** at `game.c:196-199`, with an early return that skips the whole
  sim for that frame. A pause menu needs Escape as "back".

Settled at one depth each:

```c
// input.h — InputAction gains one field
typedef struct InputAction { const char* name; bool ui; InputSource sources[6]; } InputAction;
void input_set_suppressed(GameInputState*, bool);   // game actions read 0; ui actions still read
```

`input_action_value/_down/_pressed/_released` return zero for any action with `ui == false` while
suppressed. One branch in one place, no strings, and the action table is already where a game
declares intent. The UI re-derives it every frame from whether a modal screen is up, so a screen
closed by any route gives input back.

**The debug GUI's claim is NOT folded into that gate**, and the first attempt at this proved why.
Suppression answers "who owns the game's input"; `engine_gui_wants_keyboard()` answers "where did
this keystroke go". Asking the second one above the action — where the source kind is not yet
known — took the GAMEPAD down with the keyboard, so typing a number into an ImGui slider stopped
a pad player moving. It belongs in `_source_value`, per source: a KEY source reads zero while the
GUI wants the keyboard, a MOUSE source while it wants the mouse, and a pad source never. Same
one-place fix to the defect `engine.h` documents and no app ever honoured, applied at the
granularity the fact actually has.

**Escape is a plain key and the game framework holds no quit policy.** The hardwired
Escape-quits-the-window block is gone from `game_frame_update` and from the four apps that had
their own copy, because a game's Escape opens its menu and quitting is an item inside it.
gametest binds `menu` (Escape, and BACK on the pad since `pause` already holds START), and the
app owns only "open when nothing is up" -- closing is the layer's, through `UIInput.back`, so
`ui_pop` has one caller rather than two racing for the same stack.

Navigation actions the UI reads: `ui_up`, `ui_down`, `ui_left`, `ui_right`, `ui_accept`,
`ui_back`, all `ui = true`, all rebindable like any other. **Focus movement is geometric** — the
nearest focusable element whose centre lies in the direction's cone, wrapping at the ends — not
tree order, because a two-column settings screen has to work. It is a pure function of the
laid-out rects, so `ui-nav` asserts it without drawing.

### 6. Settings persistence (`cetra/src/game/settings.c/.h`, new)

The settings screen needs somewhere to put settings, and **`config_snapshot.c` structurally
cannot reach any of them**: its owner enum (`config_snapshot.c:31-60`) is Engine / PostFX /
Exposure / Scene / Camera / Shadow / Sky / Cloud / IBL / GI / LightCluster / Water only — there
is no Game, no AudioSystem, no GameInputState owner and no `CFG_STRUCT_*` entry to paste — and it
has no string type. It is a renderer-tuning snapshot, by design.

So a second table in the same proven shape — one descriptor array walked in both directions, the
property `config_snapshot.h:15-19` exists to state — over what the GAME layer owns: the four bus
volumes, window mode / vsync, and the action table's bindings. cJSON, versioned, unknown keys
warned and skipped.

Two things it needs that do not exist anywhere in the tree:

- **`audio_get_bus_volume`** — there is no getter (`audio.h:45` has only the setter), so a slider
  has nothing to initialise from.
- **A user data directory.** Every `fopen(..., "wb")` in the engine writes relative to cwd
  (screenshot `engine.c:1756`, config `config_snapshot.c:1260`, cook `cook.c:383`, heightmaps),
  and the only `getenv` calls outside `ext/` are the two cook variables. `settings_default_path()`
  resolves `%APPDATA%` / `~/Library/Application Support` / `$XDG_CONFIG_HOME`, creating the
  directory, with `CETRA_SETTINGS_DIR` as the override the gates use to stay hermetic.

**This is the cheap half of roadmap item 5 folded in, and it is the one part of this spec that
can be cut** to shrink it — the screens would then drive live state only and reset on relaunch.
Save games remain item 5's own spec.

### 7. gametest

The host, because it is the only app that already owns an `AudioSystem`, a bound action table and
a gamepad path — the two things a settings screen needs and the config snapshot does not carry.

- **Main menu** over the puppet scene with the sim paused, a `ui_set_program` backdrop, and
  New Game / Settings / Quit. New Game pops the stack and unpauses.
- **Pause** on the existing `pause` action, drawn over live gameplay; Resume / Settings / Quit.
- **Settings**: master + music + sfx volume (bound to the buses), a bloom toggle, a window-mode
  selector, and Back — writing through `settings.c`.
- **HUD**: a non-modal screen showing speed and the animator's blend param, which is what proves
  a non-capturing screen coexists with gameplay.
- Flags: `--ui-screen <name>` (open a screen at startup, for goldens), `--no-ui`,
  `--ui-probe <case>` — the early-exit headless probe, the shape `--audio-probe`
  (`gametest.c:1529-1539`) and `--anim-probe` (`:1543-1553`) already established.

### 8. The `ui` gate group (`scripts/gates.py`) and two goldens

Group tuple appended to `GATE_GROUPS` (after `("anim", ...)` at `:22319`), one
`run_ui_gate(workdir)` returning failed arm names, docstring with a column-0 prose line then arms
at exactly two spaces in run order (`run_gate_docs_gate`, `:17096-17162`). Probe lines
`ui <case> <label> <key> <numbers…>` at `%.6f`, parsed like `_ANIM_PROBE` (`:14891`).

| arm | asserts |
|---|---|
| `ui-layout` | a column at 1280×720: every rect equals its closed-form value exactly; FIT hugs content, GROW splits the remainder, padding and spacing land |
| `ui-layout-resize` | the same tree at 640×360 and 2560×1440 — centred stays centred, GROW ratios exact, no drift |
| `ui-wrap` | a label at 400 px breaks at the right words, every line's measured width ≤ 400, line count exact |
| `ui-nav` | down/up/wrap through a column; left/right across two columns picks the geometric neighbour; disabled skipped |
| `ui-hit` | point-in-rect per element including overlap and clip; a point in a padding gap hits the parent, not the child |
| `ui-capture` | modal up ⇒ `input_action_down("move_x")` is 0 and `ui_accept` still fires; popped ⇒ the reverse; a non-modal HUD never captures |
| `ui-stack` | push/pop/pop_all depth and draw order; the screen beneath draws but does not take input |
| `ui-theme-identity` | a zeroed style and an explicitly-copied theme style produce byte-identical draw-list vertices |
| `ui-elements-closed` | the element constructors exported by `ui.h` are exactly the six — the scope ratchet, asserted rather than promised |
| `ui-settings-roundtrip` | write, mutate live state, read back: every field equals what was written (the `config-roundtrip` precedent) |

**Goldens** (`scripts/goldens.py` `RECIPES`, dicts like `puppet` at `:325-327`): `menu` and
`menu_focus` — gametest `--ui-screen main`, the second with the second button focused. The pair
is what proves the focus VISUAL, and their diff must be confined to that button's rect.

**Must not move**, run before and after each core phase: all 31 goldens, and the `anim`, `audio`,
`gamepad` and `config` groups.

## Verification

- **Automated, here.** The `ui` group's ten arms prove layout, wrapping, geometric navigation,
  hit-testing, capture, the stack, theme resolution, the settings round-trip and the closed
  element list — all analytic, no GPU, so they run in the suite's CPU budget. The two goldens see
  the actual pixels, including the focus visual. The must-not-move set (31 goldens + `anim`,
  `audio`, `gamepad`, `config`) proves the overlay hook and the input changes are additive.
- **By hand, windowed.** gametest: navigate every screen with the keyboard and with a pad; the
  pause menu over live gameplay with the sim frozen and the scene still drawing; a volume slider
  audibly moving the bus; New Game replacing the scene with no flash; the settings file surviving
  a relaunch; a window resize re-laying-out mid-menu.
- **Not verifiable here, recorded as owed.** A menu on a 4K/HiDPI display other than this one;
  the settings path on Linux and Windows; a real controller through the menu (the same pad debt
  11.109 already carries).

## Risks

- **The overlay hook must be inert.** If any of the 31 goldens move in phase 2, the hook is
  changing the frame when nothing is installed. Proven before a single element exists.
- **Golden determinism.** SDF glyph rasterisation must be reproducible run to run; `--rebake`
  already renders twice and refuses on any difference (`goldens.py:435-467`), which is the check.
- **Scope.** The element list is closed and `ui-elements-closed` enforces it. A seventh element
  is a later spec, not a patch to this one.
- **Input suppression is a new global.** A screen that fails to lower it leaves the game deaf;
  `ui-capture` asserts both directions, and `ui_pop_all` restores unconditionally.
- **Removing the hardwired Escape quit changes five apps.** `render`, `tree`, `shapes` and
  `spores` lose a keyboard quit for a menu they do not have, and `forest` -- which captured the
  cursor and relied on the framework's -- keeps TAB to release it and the window close after
  that. Accepted deliberately: the engine holding a key policy is what produced three different
  spellings of Escape across five apps in the first place.
- **The settings file is the cut line.** If the spec runs long, §6 and `ui-settings-roundtrip`
  come out and the screens drive live state only.
