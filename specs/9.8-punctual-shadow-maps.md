# 9.8 — Punctual shadow maps: shadows for all four light types

## Context

Cetra has four light types and shadows for one and a half of them. Directional lights get cascaded
shadow maps (up to 3 casters × 3 cascades, `GL_TEXTURE_2D_ARRAY` on unit 10). Spot lights get
*one* map — `scene_first_spot_light` (`shadow.c:484-493`) literally picks the first spot in scene
order, a limit the code calls "v1: the flashlight". Point and area lights get nothing:
`shadow.c:525-535` counts only `LIGHT_DIRECTIONAL` and resets `shadow_map_index = -1` for
everything else.

This is a real gap, not a cosmetic one. `specs/6.2-cscn-light-types.md:147-148` records that a
`.cscn` may already set `cast_shadows` on a point or area light and it is **silently ignored** —
"harmless, not honored". So the authoring surface exists and lies. And `specs/9.2` lists "no area
shadows" as an explicit v1 limit of LTC area lights, which means every Cornell-style interior in
this repo is lit by a panel that cannot cast.

Two things make now the right moment. First, spec 9.7 just moved every per-light-type shadow gate
inside `bind_shadow_maps_to_program`, whose comment (`shadow.c:346-354`) now reads *"Point and area
shadows will add their own clauses HERE and no caller will change"* — the extension point is built
and empty. Second, that same work exposed two bugs whose shared root cause was one condition trying
to model four light types, so the modelling problem is already understood.

**The roadmap has no entry for this.** A grep across `docs/`, `specs/` and `plans/` for point/cube/
omni shadows returns exactly one hit — the A2 line deferring area shadows. A6 (moment shadow maps)
is a parked Tier-3 sketch about *filtering quality*, not about which lights can cast, and is
explicitly "do not schedule until the rest of Track A lands". So this work is unbooked and needs a
roadmap entry as well as a spec.

### The constraint that determines the design

**`pbr_frag` has zero free texture units.** All 16 are actively sampled — I verified each call site.
(The `common.h:50` comment calling unit 8 "reserved… unsampled today" is stale; `sheenTex` is
sampled at `pbr_frag.glsl:379`.) Unit 15, the last legal one, currently holds a single `sampler2D`
spot map.

That rules out the obvious implementation. `samplerCubeArray` would serve point lights, but it is
GLSL 400 while all 66 shaders are `#version 330 core`, it has never been used here, and it would
need a *second* sampler for spot/area — and there is no unit for it.

**So the design is forced, which is a good sign:** unit 15 becomes one `sampler2DArray` holding
every perspective shadow map — spot (1 layer), point (6 layers, cube faces as array layers selected
by dominant axis), area (1 layer down the panel normal). One sampler, no new unit, no version bump.
Unit 10 and the whole directional path are untouched, which is what protects the three
shadow-coupled goldens.

### The limiting factor is per-frame traversals, not VRAM

`render_shadow_depth_pass` re-renders every layer every frame (`shadow.c:685-697`), so **layers =
scene-graph traversals per frame**. Today that is 9 + 1 = 10. One shadow-casting point light adds
6. At 1024² a layer is 4 MiB, which is noise on this target; the traversals are not.

Pool sizing is quantized by 6 — a point light needs all six faces or it has holes — so any pool
below 6 means point lights cannot cast at all. **`MAX_PUNCTUAL_SHADOW_LAYERS = 8`**: one point light
plus two spot/area, or eight spot/area. Allocation is demand-driven (mirroring the directional
array, which sizes to runtime `cascade_count` rather than the ceiling), so a spot-only scene
allocates and renders one layer. The constant is therefore a *worst-case frame-cost cap*, and
raising it is a one-line change.

Erring small is deliberate: exhausting the pool is a visible failure a log line can name, while an
over-large pool degrades frame time with no signal at all.

## Design

### One punctual array beside the cascade array

```
unit 10  shadowMaps          sampler2DArray  DEPTH24  2048²  directional cascades   (unchanged)
unit 15  punctualShadowMaps  sampler2DArray  DEPTH24  1024²  spot / point / area    (new)
```

Both follow the established array idiom — `glTexImage3D` (never `glTexStorage3D`, which is GL 4.2;
the reason is written down at `mask_array.c:134-135`), one FBO reused via
`glFramebufferTextureLayer`, per-layer completeness check. `init_shadow_map_array` and
`begin_shadow_pass` (`shadow.c:132-215`) are the templates to copy.

Depth cube *faces* are not needed: a point light's six 90° frusta become six ordinary 2D layers, and
the shader picks one by the dominant axis of `P - lightPos`. This is why the 2D array serves all
three types.

### Per-light plumbing reuses a field that already exists and is dead

`Light` (`light.h:53-55`) carries `cast_shadows` and `shadow_map_index`. Add **one** field,
`int shadow_layer` — the base layer in the punctual array, `-1` for none. Keeping it separate from
`shadow_map_index` (which stays the directional CSM slot) avoids one int meaning two things by type.

On the GPU side nothing grows: `spotShadowSize.y` in `PackedLight` **already carries
`shadow_map_index`, is written at `light_cluster.c:231`, and is read by no shader** — the UBO
comment calls it "spare — the spot map is global today". It becomes the punctual layer base. There
are 3–7 further spare words per clustered light if more is ever needed.

### Shader interface follows `csm.glsl`

New `cetra/shaders/include/punctual_shadow.glsl`, modelled on `include/csm.glsl` — whose header
states the pattern explicitly: the uniform names are "a contract with ONE C function", the binder is
location-guarded, and `uniform.c:171-182` runs a drift check if the shader arrays come out smaller
than C believes. Declares `sampler2DArray punctualShadowMaps`, `mat4 punctualShadowMatrix[N]`, and
the per-layer count, plus one lookup taking a layer base and a light kind.

`calculateSpotShadow` (`pbr_frag.glsl:597-619`) generalises into it. Consumers of `csm.glsl`
(`catcher_frag`, `particle_frag`) are directional-only and do not need the new include; fog keeps
its private mirror, which `csm.glsl:16-19` already argues should stay separate.

### Fog: measure before deciding

`froxel_inject_frag.glsl:202` skips shadowing clustered point lights outright, while fog already
shadows the spot fully. Giving point lights maps makes that line a decision. Per the scope call,
**N3 measures what unshadowed in-scatter actually looks like in a point-lit foggy scene and records
the finding**; wiring it is a follow-up with its own gate, because it moves `froxel_fog_golden`.

### Filtering quality is explicitly out of scope

Point and area inherit the spot's current 3×3 PCF. The silhouette staircase (root-caused in 9.7 as
spot shadow-map quantization, not GI) is recorded as a measured residual. Once all four types share
one path, filtering becomes a single change that fixes all of them — which is the argument for
doing it after, not during.

## Verification

Complete `./build.sh` every time — never piped through `head`. Pin exposure with
`--no-auto-exposure -E 1.0`. Measure the same-build noise floor before trusting any comparison.

1. **The three shadow-coupled goldens stay 0 px throughout** — `froxel_fog`, `contact_debug`,
   `aerial_fixture`. The directional path is untouched by design, so any movement means the shared
   array or publish path was disturbed. This is the gate that makes the refactor safe.
2. **The four area-lit goldens stay 0 px until N4** — `roughness_sweep`, `backface_dark`,
   `guard_thin_panel`, `cornell_box` — then move once, deliberately, inspected at 1:1.
3. **`cornell_leak` occlusion holds from N1 on.** Dark half ≈ 17.58 with the partition shadowing;
   this is the only asset exercising the spot map and it has no committed golden, so the measurement
   is the test. *As-built: superseded by something stronger — every milestone compared `cornell_leak`
   byte-for-byte against a build of the pre-branch commit (0 px, noise floor 0), and it now has a
   committed golden of its own.*
4. **Point shadow correctness:** a point light inside a box casts in all six directions with no seam
   at a face boundary — the failure mode dominant-axis selection produces. Check the ±X/±Y/±Z
   junctions specifically, at 1:1.
5. **Area shadow correctness:** the Cornell partition casts from the ceiling panel.
6. **Cost is checkable, not asserted.** Instrument the per-frame layer count the way 9.7's
   `captures_total` made converge-then-idle falsifiable, and report actual traversal counts for a
   spot-only, a point-lit and a mixed scene. The limiting factor deserves a number.
7. **Pool exhaustion is loud.** Two shadow-casting point lights against an 8-layer pool: the second
   must log which light got no slot.
8. **Headless determinism 0 px** — two identical runs.
9. **Spot regression** — `spores` (a shadow-casting spot flashlight) and `tree` smoke.

## As-built

All four light types cast. Shipped as planned except where measurement said otherwise, below.

| type | layers | projection | notes |
|---|---|---|---|
| directional | 1–9 | ortho cascades, unit 10 | untouched by this work |
| spot | 1 | perspective, fov from the cone | was the "flashlight"; now one per light |
| point | 6 | six 90° faces, `+X -X +Y -Y +Z -Z` | face picked by dominant axis |
| area | 1 | perspective, 120° down the panel normal | multiplied into the LTC term |

`MAX_PUNCTUAL_SHADOW_LAYERS = 8`, allocated on demand. Measured traversal counts, from the
allocator's own log line rather than assertion: spot-only 1, two spots 2, one point light 6,
spot + point 7. Every layer is a full scene-graph walk every frame, which is what the ceiling caps.
Nine casting spots against eight layers logs the name of the first light that got no slot, once,
latched — a per-frame version of that line is why such warnings get deleted.

### Decided by measurement, against the plan

- **Map size stayed 2048, not the 1024 the plan sketched.** The existing size comment records why it
  was raised: a spot's fov comes from its cone, so a wide cone spreads the same texel count over a
  far larger footprint. Shrinking it would regress the artifact 9.7 root-caused.
- **No fov overlap between cube faces.** Faces were widened by two texels on the theory that a PCF
  tap at a 45° boundary clamps to the white border and draws a hairline. Measured from straight
  above, where all four floor junctions cross cast shadow: 1737 of 2.56M pixels differ, all of it
  silhouette quantization from the resolution change, and at 1:1 the junctions are
  indistinguishable. The mechanism is real and below the noise floor at 2048², so the overlap was
  removed rather than kept as unmeasured insurance.
- **Bias is slope-scaled by `tan(incidence)`, not `(1 - NdotL)`.** Forced by N4: a panel sits above a
  room, which puts every wall near edge-on, where `(1 - NdotL)` saturates at 1 and the tangent
  follows the geometry. The first area render had visible moiré. `cornell_leak` stays
  byte-identical across the change, because where receivers face their light both formulas hit the
  same clamped floor.

### Honest residuals

- **A bright hairline traces the contact line where an object rests on a receiver.** Visible in
  `cornell_point` along each box's base. Diagnosed, not fixed. Established by measurement:
  it vanishes with shadows off; it vanishes entirely under `glCullFace(GL_BACK)`; it is unaffected
  by the depth bias at any magnitude including zero and negative; and embedding the caster through
  the floor does not move it. The cause is the depth pass front-face culling: the map stores the
  occluder's FAR surface, and the ray to a contact point exits that surface *at* the contact, so the
  comparison ties there and one texel of map resolution is one texel of ambiguity. Back-face culling
  is not the trade — it covers the spot fixture in acne. This is the same phenomenon
  `gen_cornell_rooms.py` already documents on the leak partition, where it states that no filter
  width or map resolution removes it. The untried candidate is receiver-plane depth bias (Isidoro).
- **Area shadows are hard, from a soft source.** The LTC integral is over the rectangle and a single
  binary lookup scales the whole of it, so a panel is either visible from a fragment or it is not.
  No partial occlusion of one edge.
- **An area light's reach is a chosen 120°**, because one perspective map cannot cover the
  hemisphere a panel emits into. Outside the cone the white border reads as lit — a missing shadow
  rather than an invented one.
- **Fog still ignores point-light occlusion.** `froxel_inject_frag` skips shadowing clustered point
  lights. Measured on `cornell_point`: fog RAISES a shadowed region 49.45 → 52.57 (+3.12, +6.3%
  relative) while DIMMING lit floor 135.11 → 133.92, since extinction wins where the surface is
  already bright. That asymmetry is the signature of unshadowed in-scatter. Wiring it moves
  `froxel_fog_golden`, so it is a follow-up with its own gate.
- **Filtering quality unchanged.** Point and area inherit the spot's 3×3 PCF, as scoped.

### Goldens

Three new, one moved:

```
./out/bin/render -m assets/cornell_point.gltf -x -f 30 --no-auto-exposure -E 1.0 \
    -W 800 -H 600 -S /tmp/p.ppm      # -> assets/cornell_point_golden.png   (point, 6 faces)
./out/bin/render -m assets/cornell_leak.gltf  -x -f 30 --no-auto-exposure -E 1.0 \
    -W 800 -H 600 -S /tmp/l.ppm      # -> assets/cornell_leak_golden.png    (spot)
./out/bin/render -m assets/cornell_box.gltf --gi-volume -x -f 30 --no-auto-exposure -E 1.0 \
    -W 800 -H 600 -S /tmp/c.ppm      # -> assets/cornell_box_golden.png     (area, REGENERATED)
```

`cornell_leak` had no golden before; it is the only spot-shadow asset, so the measurement was the
only test. It has one now, which also pins the 17.5364 dark-half number (crop `640x1200+840+0` of
the 1600×1200 supersampled frame — the plan's 17.58 was a slightly different crop of the same
image).

`cornell_box_golden` moved 589,226 px (30%), once, inspected at 1:1 first. It now exercises the
probe volume AND area shadows where 9.7 built it for GI alone. The alternative was a fourth Cornell
room differing only by a flag; this is the repo's area-lit room and the panel not casting was the
thing being fixed.
