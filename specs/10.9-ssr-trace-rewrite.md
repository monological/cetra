# 10.9 — SSR trace rewrite: interval acceptance, honest occlusion

## Context

The user's clean isolation (sheen fixture + aquarium HDR, free camera
parked, everything off except sheen + SSR with temporal AND denoise off +
normals G-buffer, TAA off) shows the RAW deterministic trace producing
vertical comb striping across the catcher floor and a ghost blob below the
spheres. With TAA on, that estimator variance is the flicker. 10.7.2/10.8.1
improved the laundering; this rewrites the estimator. Design was
pressure-tested by an independent design review (verdict folded in below).

**The acceptance render — the user's command, verbatim:**

```
./out/bin/render -m assets/sheen_fixture.gltf \
  -e my_models/ushaka_sea_world_aquarium_8k.hdr \
  -W 800 -H 600 --fov 50.0 --cam-eye -1.874,0.806,1.369 \
  --cam-target -1.664,0.270,0.119 --cam-up 0.000,1.000,0.000
```

with everything off except sheen + SSR (temporal off, denoise off) +
normals G-buffer, TAA off. Headless-harness equivalent of the same
isolation: append `-x -f 30 --no-ssr-denoise --no-ssao --no-bloom
--no-auto-exposure -E 1.0 -S out.ppm` (headless already forces TAA off →
SSR temporal off). Acceptance = clean sphere reflection on the floor at
this camera: no per-column combs, no ghost blob (those rays miss → probe).

## Root causes, anchored in the code

1. **Phase-dependent point-sample acceptance → the combs.** At the finest
   hi-z level: an 8-tap rescan over the cell bracket demanding a sign flip,
   then 3 bisections (`ssr_frag.glsl:239-274`). Whether the true crossing
   lands inside the bracket depends on hi-z cell-grid phase, which shifts
   per screen column — adjacent columns alternate hit/miss. Compounding
   absurdity: at full-res, hi-z level 0 is a 1:1 depth copy
   (`postfx.c:1602-1603`), so the bracket spans ONE depth texel and the 8
   taps read the same value at 8 phases.
2. **Fat fixed thickness → the ghost blob.** Accept is
   `sceneZ - rayZ < thickness`, a constant view-space uniform (default 0.3,
   `max(0.3, scene_radius*0.002)` in the app). Rays passing just behind the
   sphere silhouette have a gap under that and ACCEPT, smearing the
   sphere's edge color onto the floor. The gap off a silhouette grows
   quadratically, so shrinking the constant only narrows the rim (~2.4x at
   0.05) — the fix must recognize the silhouette itself.
3. **No occlusion semantics in the hi-z branch → budget death.** After a
   failed thickness test the loop crawls at level 0, one texel per
   iteration, across the whole occluder until the 256-cap dies →
   camera-dependent miss patchwork.
4. The separate toward-camera fixed-step branch has its own artifact
   signature (64 jittered point samples) and a bisection that updates
   `hitUV` without re-checking thickness — resolved below by deleting the
   branch entirely.

## Design (review verdict: pure fixed hi-z — "option B")

Keep: the NDC-endpoint parameterization (exact — projective maps preserve
lines), the min-depth hi-z pyramid + build pass byte-unchanged (the
full-res `copySrc` 1:1 identity becomes load-bearing: level 0 IS the depth
buffer, so the finest-cell test is exact — add a comment saying so), the
probe fallback and its premultiplied contract, the stochastic-jitter block
and both inline-IGN waivers, the reflective-marker gate, near-plane clamp
and distance-scaled start bias, backface rejection at hit, the fade stack,
WS_REFLECT_MAX. The trace stops sampling `depthTex` mid-march entirely —
one texture, `texelFetch` only.

Replace the whole march (`ssr_frag.glsl:184-334`) with ONE unified hi-z
loop (the toward-camera split is deleted; boundary-plane stepping never
depended on z direction — symmetric `max(zIn, zOut)` endpoints handle both
signs; the near-plane clamp keeps toward-camera segments short):

1. **Exact per-cell interval test.** Each iteration computes the cell's
   entry/exit params analytically from its boundary planes (entry
   recomputed, not the eps-nudged cursor — the quarter-texel z-coverage gap
   would reintroduce faint striping) and the ray's z-span across the cell.
   Descend while the span reaches behind `cellMin`; at level 0 the cell is
   one depth texel and `cellMin` is the exact scene depth.
2. **Acceptance, two cases at the finest level:**
   - Ray CROSSES the surface inside the column (`zNear >= sceneZ` while
     entering in front): ALWAYS a hit, no thickness term — the geometry is
     exact there. Comb dead. Hit param solved analytically
     (`(cellMin - seg0.z)/dseg.z`, clamped to the cell); `hitUV` at the
     texel center (no filter bleed). Bisection deleted.
   - Ray ENTERS the column already behind (a depth STEP, not a crossing):
     accept only if within the slab `thickV` AND the receiver is
     continuous — the neighbor column the ray entered through has depth
     within `thickV` of this one. A silhouette (floor→sphere) fails even
     at tiny gaps. Ghost dead.
3. **Slope-aware slab.** `thickV = thicknessMin + THICK_SCALE * (ray's own
   view-z travel across the column)` — incidence-invariant: thick where
   grazing needs it, thin where the blob lived. One knob family serves the
   slab, the continuity tolerance, and the occlusion scale.
4. **Behind-for-good → probe.** Rejected-behind columns crawl at level 0
   (deliberately NO ascend while behind: a min pyramid descends right back
   — 2 wasted iterations) but are hard-bounded: gap > K_OCCLUDE*thickV OR
   M_BEHIND consecutive behind-columns → occluded → probe. Thin foreground
   (< ~12 px) still gets crossed; wide occluders cost <= 12 fine
   iterations. Re-ascension stays on the clear-cell path (unchanged).
5. **Origin-texel skip:** start just past the fragment's own column so the
   ray never tests itself.

Constants (shader consts; promoted to uniforms only if Phase-B tuning
demands): `MAX_ITERS 128` (down from 256 — worst path drops ~an order of
magnitude), `THICK_SCALE 1.5`, `K_OCCLUDE 8.0`, `M_BEHIND 12`. Uniform
`thickness` becomes `thicknessMin` (default 0.05, was 0.3); `steps` and
`fx->ssr_steps` retired (no fixed-step branch remains); render.c's
scene-scale raise KEPT, retargeted at the new floor. Cap-out and occlusion
both return the probe — the cap frontier sits in the distFade tail, so
degradation swaps one probe-dominated value for another (verified by an
iteration-count debug render, Phase B).

Top tuning risks carried into Phase B with cheap probes (full list in the
spec): steep continuous receivers vs the continuity test (sweep
THICK_SCALE on a ramp), re-emergence loss behind wide occluders (moot at
the acceptance camera — behind the spheres is probe anyway), half-res
mode's 2x2-min silhouette inflation (toggle ssr_full_res; a 2-fetch
refinement is the recorded remedy if edges crawl), and grazing
self-re-hit: the unconditional crossing-accept near-parallel to the
receiver leans on the kept distance-scaled start bias
(`ssr_frag.glsl:161`) exactly as the old accept did — the acceptance
camera IS this configuration, so Phase B tunes the bias deliberately if
streaks appear rather than discovering it.

## As-built (10.9)

Implemented in one commit on `sheen-spec-conformance` after the spec
commit. Everything in the Design section landed as planned; the deltas and
measured numbers follow.

### What changed vs the plan

- Nothing structural. Constants shipped at the planned defaults
  (`MAX_ITERS 128`, `THICK_SCALE 1.5`, `K_OCCLUDE 8.0`, `M_BEHIND 12`,
  `thicknessMin 0.05`) — no tuning was needed at the acceptance camera.
- The plan's "both inline-IGN waivers kept" became one: deleting the
  toward-camera branch deleted its hash copy along with its use. The
  stochastic block's copy and waiver are untouched.

### Phase A/B — raw deterministic trace at the acceptance camera

Comb proxy metric: AE (2% fuzz) of the floor crop (840x420+260+780 at the
1600x1200 retina capture) against its own 1-px horizontal shift.

| capture | before | after |
|---|---|---|
| raw march buffer (--ssr-debug) | 44,239 px (12.5%) | 4,433 px (1.3%) |
| final image | 15,096 px | 6,157 px |
| final image, SSR off (legit-edge floor) | 2,033 px | — |

The after-number on the march buffer is essentially the reflection disc's
own perimeter (~2x pi r for the visible discs ~ 4,400 px): the interior
contributes nothing. The behind-silhouette ghost blob is gone — that
region now falls to the miss path. Visual A/B: the striped double-image
below the red sphere became a single smooth mirror image.

Budget heatmap (temporary shader instrumentation, reverted in the same
session, proven reverted by a 0-px render comparison): typical floor
pixels use 25-45 of 128 iterations; the only near-cap pixels are thin
arcs tangent to the reflected silhouettes, which terminate in the
miss->probe path. No broad cap-out regions.

Half-res mode (`--no-ssr-full-res`): smooth interior, no combs, no ghost;
the hit/miss frontier teeth are ~2x chunkier from the 2x2-min level 0, as
predicted (risk R4). The recorded 2-fetch refinement was not needed.

Residual artifact, recorded honestly: a sawtooth serration (~2-5 px at
native res) along the hit->miss frontier where rays graze the reflected
silhouette tangent. This is the quantization floor of a deterministic
trace against a discrete depth buffer; the stochastic jitter + denoiser +
TAA dress exactly this frontier.

### Review outcome (5 background agents: structural audit + 4 cleanup angles)

Verdict across all five: the rewrite is structurally sound; C-side rename
surface grep-verified clean by three agents independently; the as-built
numbers verified accurate against the shipped shader.

Applied (proven bit-exact: acceptance render compares 0 px pre/post):
- `cellSpan()` helper extracts the ray-vs-cell boundary-plane math that was
  spelled two ways at the origin-skip and loop-body sites (flagged by 3 of
  5 agents); `enteredOnX` became `enteredAxis` with axis-indexed stepping.
- `texelFetch(hizTex, fromCell, level)` instead of a hardcoded mip 0 that
  was only correct via a guard 30 lines away.
- Dead `min(tOut, 1.0)` removed (tOut is provably <= 1 there); `sizeFine`
  reused instead of rebuilding `ivec2(hizWidth, hizHeight)` per iteration.
- Comment fixes: occlusion-exit policy narrated once (at the loop site, not
  the const block), stale "max steps" vocabulary, the hitUV texel-center
  claim qualified for half-res, the hiz copySrc comment no longer names its
  caller, and the thicknessMin default records the app-scales-it contract.

Skipped, recorded: reciprocal-multiply forms of the per-iteration divides
(last-bit perturbing -- would re-open the pixel-verified baseline for an
unmeasured win); skipping entry-plane math at coarse levels for away rays
(bit-exact but adds a mode conditional the structural angles would count
against legibility; available if profiling ever demands); sinking the probe
call past the loop (triples call sites for a speculative register win);
renaming K_OCCLUDE/M_BEHIND (they trace 1:1 to this spec); deduplicating
the pre-existing fresnel stack shared by probeSample and the hit fades
(pre-existing, out of this diff's blast radius -- a recorded follow-up).
