# Shader Include Seam + Normal-Matrix Hoist + Handedness Varying

Three follow-ups from the 8.3 reviews, one branch, independent commits. Commit
1 is a pure build-time refactor (bar: 0 differing pixels). Commit 2 moves a
uniform-only matrix inverse off the per-vertex path and deletes a redundant
second normal transform (bar: ~0 pixels, honest perf measurement either way).
Commit 3 passes tangent.w as a flat varying and deletes the fragment shader's
two dot-and-flip sign recoveries (bar: ~0 pixels; the recovery it replaces is
lossy, the varying is exact).

## Context

Five review agents converged on two structural findings against the shipped
8.3 work:

**1. `windOffset()` is triplicated.** 31 byte-identical executable lines plus a
~12-line uniform block in each of `pbr_vert.glsl`, `pbr_skinned_vert.glsl`,
`shadow_depth_vert.glsl`. The copies must stay identical — the shadow depth
pass and the shading pass must displace a vertex to the same place or a swaying
branch casts its shadow from where it isn't — and they are kept identical by
hand. They have already drifted in comments. The TBN construction is a second,
smaller triplication (`pbr_vert`, `pbr_skinned_vert`, `shape_vert`) that 8.3
had to edit three times in lockstep. This is the third time the tax was paid
(8.2 triplicated windOffset; 8.3 triplicated TBN and hand-added `uWindMode` to
a fourth shader).

**2. `transpose(inverse(model))` per vertex.** `model` is a uniform — constant
across the draw call — but three shaders compute a full mat4 cofactor inverse
per vertex (`pbr_vert.glsl:147`, `pbr_skinned_vert.glsl:184`,
`shape_vert.glsl:59`). The grass mesh alone is ~480k-864k vertices redrawn
every frame. Drivers MAY hoist uniform-only expressions; Apple's GLSL path is
not trusted to. Additionally `pbr_vert` transforms the normal a SECOND time
(`:156`, `mat3(model) * aNormal`) for `TBN[2]` — redundant, and the less
correct of the two under non-uniform scale (the fragment shader's Gram-Schmidt
at `pbr_frag.glsl:796` orthogonalizes against the `Normal` varying, not
`TBN[2]`).

### Answers to the design questions (user asked)

- **No runtime GLSL reading.** The include mechanism lives entirely in
  `gen_shader_header.py`, which already converts every `.glsl` into a C string
  literal in `shader_strings.h` at build time. `#include` is expanded during
  that conversion; the app still ships and compiles from string literals
  exactly as today. Nothing about the runtime load path changes.
- **Per-topic chunk files, not one `util.glsl`.** Each shader pulls only what
  it uses (`#include "wind.glsl"` brings the wind uniforms + `windOffset`;
  `#include "tbn.glsl"` brings `buildTBN`). One catch-all util file would force
  every including shader to declare every shared uniform whether used or not —
  legal, but it pollutes the uniform namespace and makes the include line say
  nothing. A chunk per concept is self-documenting.

## Phase A — build-time `#include` (commit 1, zero-pixel refactor)

### `cetra/gen_shader_header.py`

Add include expansion as a text-level pass BEFORE the string-literal
conversion (`shader_to_string` currently reads lines and escapes them; insert
`expand_includes(path)` between read and escape):

- A line matching `#include "name.glsl"` is replaced by the contents of
  `cetra/shaders/include/name.glsl`, recursively.
- **Include-once semantics** (like `#pragma once`): track a `seen` set per
  top-level shader; a chunk included twice expands once. GLSL has no include
  guards, and double-expansion would be a duplicate-definition compile error.
- Cycle guard: same `seen` set.
- **`#line` directives** so GLSL compile errors map back to real files: emit
  `#line 1 <chunk_index>` at chunk start and `#line <resume_line> 0` after,
  where chunk_index is a stable per-chunk number (write the index→filename
  mapping as a comment at the top of the expanded shader). `#line` is core
  GLSL since 1.10. If the Apple driver misbehaves with it, drop the directives
  — they are a nicety, not load-bearing.
- `os.listdir(input_dir)` does not recurse, so chunk files in `include/` do
  NOT get their own `*_shader_str` variables. No change needed there.

### `cetra/CMakeLists.txt`

Line 18's `file(GLOB SHADER_FILES ${SHADER_DIR}/*.glsl)` does not see a
subdirectory — without a fix, editing a chunk would NOT retrigger generation
(silently stale shaders). Add:

```cmake
file(GLOB SHADER_INCLUDE_FILES ${SHADER_DIR}/include/*.glsl)
```

and append `${SHADER_INCLUDE_FILES}` to the custom command's `DEPENDS`
(line 24).

### Chunk files (new)

- `cetra/shaders/include/wind.glsl` — the 11 wind uniforms (`uDeltaTime`,
  `uWindDir/Strength/Speed/GustFreq/GustAmount/Turbulence/Response/MaskMinY/
  MaskMaxY`, `uWindMode`) + the `windOffset()` body. Seed it from the
  `pbr_vert.glsl` copy (the one that kept its comments).
- `cetra/shaders/include/tbn.glsl` — one function packaging the current TBN
  lines verbatim (no math change in this phase):

```glsl
// N is the world-space normal the TBN should carry; tangentLocal/w come from
// the vec4 tangent attribute. B is derived, handedness in w (see mesh.h).
mat3 buildTBN(mat3 modelRot, vec3 N, vec3 tangentLocal, float w) {
    vec3 T = normalize(modelRot * tangentLocal);
    vec3 B = cross(N, T) * w;
    return mat3(T, B, N);
}
```

### Shader edits (replace copies with includes)

- `pbr_vert.glsl` — delete the wind uniform block + `windOffset` body →
  `#include "wind.glsl"`; TBN lines → `TBN = buildTBN(mat3(model), N, aTangent.xyz, aTangent.w)`
  with `N = normalize(mat3(model) * aNormal)` staying put this phase.
- `pbr_skinned_vert.glsl` — same two replacements (`buildTBN(mat3(model),
  N, localTangent, aTangent.w)`).
- `shadow_depth_vert.glsl` — wind include only (it uses no tangent data).
- `shape_vert.glsl` — tbn include only (it has no wind).

Note `uDeltaTime` moves into wind.glsl; `pbr_frag.glsl`'s own `uWindMode`
declaration is a separate stage and stays as-is.

- 0 differing pixels on both deterministic baselines (commands in the

## Phase B — hoist the normal matrix, delete the second transform (commit 2)

### C side

- `cetra/src/uniform.{c,h}` — add `uniform_set_mat3` (there is only
  `uniform_set_mat4` today, `uniform.c:220`); same location-guarded shape,
  `glUniformMatrix3fv`.
- `cetra/src/render.c:467` (`_render_node`, next to the existing `model` /
  `uPrevModel` uploads) — compute and upload per node:

```c
mat4 inv;
glm_mat4_inv(node->global_transform, inv);
mat3 nm;
glm_mat4_pick3t(inv, nm);   // transpose of inverse's 3x3 == normal matrix
uniform_set_mat3(u, "uNormalMatrix", (const float*)nm);
```

  `glm_mat4_pick3t` exists (cglm mat4.h:264). One CPU inverse per node
  (~hundreds) replaces one GPU inverse per vertex (~hundreds of thousands).
  Location-guarded, so programs without the uniform (shadow depth, particles)
  are no-ops. `render.c:527` (the second `model` upload site, the
  non-PBR/debug path) gets the same upload.
- `shadow.c` needs nothing: `shadow_depth_vert.glsl` uses no normals
  (verified by grep).

### Shader side

- `pbr_vert.glsl:147` → `Normal = normalize(uNormalMatrix * aNormal);`
  (declare `uniform mat3 uNormalMatrix;`). Delete line 156's second normal
  transform; pass `Normal` into `buildTBN` as N. `TBN[2]` becomes the
  inverse-transpose normal — the one the fragment stage already orthogonalizes
  against, so this is the more consistent choice, not just the cheaper one.
- `pbr_skinned_vert.glsl:184` → same substitution applied to `localNormal`.
  The per-vertex bone inverse at `:149` STAYS — bone matrices are per-vertex
  blends and genuinely cannot be hoisted.
- `shape_vert.glsl:59` → same substitution.

### Phase B verification

- Both baselines again. Expectation: ~0 but possibly not exactly 0 —
  CPU-cglm and GPU float inverses differ in operation order (last-bit normal
  differences), and under non-uniform node scale the `TBN[2]` change is a
  deliberate correctness improvement. Nonzero result requires the diff map to
  be sparse LSB speckle / confined to non-uniformly-scaled nodes, not
  structured lighting change.
- **Honest perf measurement** (the ~180 ops/vertex figure is an agent
  estimate, never measured; the driver may already hoist it): time
  `./out/bin/tree -x -f 600` three runs before and after phase B, compare wall
  clock. Report whatever it shows, including "no measurable win" — the
  redundant-transform deletion and the consistency fix stand on their own.

## Phase C — handedness as a flat varying (commit 3)

The 8.3 change made `TBN[1] = cross(N,T) * w` in the vertex stage, but the
fragment stage still recovers `w` by re-deriving `B = cross(Ng, T)` and
flipping it to match the interpolated `TBN[1]`'s sign — a round-trip that
encodes one bit into a vec3 varying and reads it back with a dot product.
Both agents that traced it also flagged the recovery as lossy: `TBN[2]`'s
normal and the `Normal` varying diverge under non-uniform scale, and a
near-degenerate interpolated `TBN[1]` (slivers, UV-seam vertices where
mirrored islands meet) can flip the recovered sign for the wrong reason. The
vertex stage holds `w` exactly; pass it.

- Vertex shaders (`pbr_vert`, `pbr_skinned_vert`, `shape_vert`): add
  `flat out float TangentW; ... TangentW = aTangent.w;` — natural home is
  next to the `buildTBN` call site, or as an out-param convention documented
  in `tbn.glsl`. `flat` because handedness is per-island constant;
  interpolating it across a seam triangle would blend +1 toward -1.
- `pbr_frag.glsl` — declare `flat in float TangentW;` and collapse both
  recovery sites:
  - `:797-801` → `vec3 B = cross(Ng, T) * TangentW;`
  - `:650-654` (clearcoat) → `vec3 Bc = cross(Ngeo, Tc) * TangentW;`
  Delete the two now-false comments ("preserve the mesh's authored bitangent
  handedness" — no authored bitangent exists).
- `shape_frag` (whatever consumes `shape_vert`'s TBN_vs): check whether it
  has an equivalent recovery site; if it never uses TBN[1]'s sign, add
  nothing — an unconsumed varying is legal.
- Varying budget note: this adds 1 component; the earlier audit put pbr's
  varying set at 14 of 15 guaranteed vec4 slots, and one flat float packs
  into an existing partially-filled slot under component packing — verify the
  program still links on the GL 4.1 driver (link error = immediate, loud).

### Phase C verification

Both baselines. Expectation: exactly 0 on the static scene (every `w` is
uniform per island and the recovery currently succeeds there); raiden may show
sparse LSB speckle where interpolated near-degenerate TBN[1] previously
recovered the sign differently — the diff map must be sparse specks, and any
visible cluster on a mirrored-UV island means the varying is wired wrong.
