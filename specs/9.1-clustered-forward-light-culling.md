# A1 Subplan — Clustered Forward Light Culling

## Context

First feature of the AAA rendering roadmap (`specs/9.0-aaa-rendering-roadmap.md`, Tier 1 item 1).
Today every node shades against a per-node k-nearest selection of ≤64 lights uploaded as a
`uniform Light lights[64]` struct array — 13 `glUniform*` calls per light, re-fired on every
program switch during scene traversal. That caps light counts, causes per-object light popping,
and is the single biggest CPU cost in the render loop. Clustered forward replaces it with three
std140 UBOs (lights / cluster grid / index list) built once per frame on the CPU, letting the
engine shade hundreds of correct local lights with zero per-node upload work.

This is also the roadmap's foundation-owner for **UBO machinery** (first UBO in the codebase) and
the **CPU light-culling module** — both reused later by froxel volumetric fog (B1).

Branch: `clustered-forward` (already created off master, which carries the 9.0 spec).
Spec file: `specs/9.1-clustered-forward-light-culling.md` (committed first, per project workflow).

## Verified codebase facts (exploration, current tree)

- `lights[]` is declared ONLY in `pbr_frag.glsl` (:57); two loops consume it: Loop B = main PBR
  (:998-1156), Loop A = renderMode 7 SIMPLE_LIGHTING debug (:889-904).
- Shadow bridge: `shadowLightIndex[i]` maps loop index → CSM slot (:1079); slot assigned by
  `render_shadow_depth_pass` walking scene->lights order (shadow.c:653). Spot shadow is a single
  global map found by `type==2 && spotShadowActive` (:1086) — no per-light index.
- Upload path to delete: `_update_program_light_uniforms` (render.c:91-153), called per program
  switch (:415-417); selection `get_closest_lights` (scene.c:386-447) called per node (:611).
- `setup_program_uniforms` (program.c:397-412) runs post-link for every program — the single
  hook for `glGetUniformBlockIndex`/`glUniformBlockBinding` (guard `GL_INVALID_INDEX`).
  pbr_frag is compiled by exactly two programs: "pbr" (engine.c:1018) and "pbr_skinned"
  (created app-side, apps/render/src/render.c:1408). `reload_program_from_paths` exists but
  has zero callers — patch anyway.
- Uniform setters no-op at loc<0 (uniform.c guards) — legacy upload code degrades silently
  while both paths coexist.
- Per-frame hook: `render_current_scene` builds `view_proj` + extracts the `Frustum` at
  render.c:684-686, before the opaque pass (:722). Hooking the cluster build there makes probe
  capture (probe.c re-enters render_current_scene per cube face with per-face cameras) rebuild
  clusters per face automatically — no probe changes needed.
- `intersect.c` has only an AABB frustum test — a sphere test must be added.
- Light struct has NO radius/range — cull radius must be derived from
  constant/linear/quadratic + intensity (defaults 1.0/0.09/0.032).
- std140 blocks are legal in GLSL 330; `layout(binding=N)` is not (4.2) — bind from C.
  GLEW exposes the UBO API unconditionally; `glBindBufferBase` already used (transform feedback).
- fog/catcher/particle shaders consume shadow-system/postfx-published data, not `lights[]` —
  unaffected by deleting the per-node path.
- UBOs don't count against `GL_MAX_FRAGMENT_UNIFORM_COMPONENTS` (default-block only), so legacy
  array + new blocks can coexist during bring-up.

## Design (from master spec — locked)

- Three std140 UBOs, each <16KB: `LightsBlock` (≤4 directionals outside clustering + ≤128 packed
  clustered lights), `ClusterBlock` (16×8×24 grid, packed offset|count), `ClusterIndexBlock`
  (≤4096 indices). Exponential view-Z slicing (Doom 2016), constants shared via
  `include/lights_ubo.glsl` (froxel fog reuses them later).
- New files: `cetra/src/ubo.c/h` (generic UBO machinery), `cetra/src/light_cluster.c/h`
  (cull + pack + grid build), `cetra/shaders/include/lights_ubo.glsl`.
- Bring-up behind `--clustered` toggle; final commit flips default + deletes legacy
  (lights[] array, per-node upload, get_closest_lights render-path use, uniform_cache_lights).
- One spare vec4 per packed light reserved for LTC's `Light.up` (A2).
- CLI `--point-light-grid N[,radius,intensity]`; ImGui cluster-occupancy heatmap
  (csmDebug-style in-shader tint via `clusterDebug` uniform).
- Verification: 0-diff gate on the raiden directional-only baseline
  (`-x -f 120 --no-springs --no-auto-exposure -E 1.0`); legacy-vs-clustered A/B on a point-grid
  scene; LSB-only PAE 1/255 acceptable as compiler noise per CLAUDE.md.

## Resolved design points

1. **Coexistence**: runtime `uniform int clusteredEnabled` branch in pbr_frag, single program (no
   variant system exists; uniform control flow is legal around texture fetches). UBO blocks don't
   count against the default-block uniform component limit (bounded instead by
   `GL_MAX_UNIFORM_BLOCK_SIZE` ≥ 16384, `GL_MAX_FRAGMENT_UNIFORM_BLOCKS` ≥ 12 — we use 3), so
   legacy array + blocks coexist. Legacy branch kept byte-verbatim through bring-up. Loop A
   (renderMode 7 debug) stays legacy-only until the final commit.
2. **Dropped fields**: `lights[i].specular`/`.ambient` are never read in pbr_frag (verified grep) —
   not carried in the packed layout. `color * intensity` premultiplied on CPU (left-associated at
   all three use sites → bit-identical).
3. **Cull radius**: solve `I_eff/(c + l·d + q·d²) = ε`, `I_eff = intensity·max(color.rgb)`,
   `ε = 1/256`. Quadratic formula when q>0; linear when q=0,l>0; both zero → uncullable (all
   clusters). Area lights add `0.5·length(size)`. New `float range` on `Light` (0 = derive) +
   `set_light_range()` as authored override. Derivation = `light_cull_radius()` in light_cluster.c.
4. **Assignment**: per-light tile/slice range computation (O(lights)), no per-cluster AABB
   refinement in v1 (heatmap makes overfill observable; refinement is the designated follow-up).
   Z: `slice = floor(log2(z)·sliceScale + sliceBias)`, `sliceScale = 24/log2(far/near)`,
   `sliceBias = −24·log2(near)/log2(far/near)` (inverse documented in the include for froxel-fog
   reuse). XY: project the 4 extreme view-space points at `zproj = max(zc−r, near)` (conservative),
   clamp NDC, map to tiles; sphere crossing near plane → full-screen rect. Two-pass fill (count →
   prefix-sum → write), clamped at 4096 with one-shot warning; deterministic order. Frustum sphere
   cull first via new `frustum_test_sphere` in intersect.c.
5. **Shadow bridge**: each DirLight carries its own slot in `dirShadow.w` — replaces the
   `shadowLightIndex[i]` indirection (and fixes its ordering fragility). Bring-up: legacy
   shadowLightIndex upload untouched. Final commit deletes only the pbr_frag decl + the
   shadow.c:386-388 upload loop — `numShadowLights`/cascades/spot uniforms stay (catcher_frag:48,
   particle_frag:81 consume them). Spot shadow unchanged: type-keyed global map.
6. **Loop restructure**: single fused loop, `k < numDir + clusterCount`; fetch phase computes
   L/attenuation/radiance + `dirShadowSlot`/`isSpot` selectors; the EXACT legacy body follows
   (shadow site consumes the selectors; needs NdotL so not hoistable). One body, no triplication.
7. **Upload**: `glBindBufferBase` bases 0-2 once at init (different indexed target than the
   transform-feedback use — no conflict); per `render_current_scene` invocation (incl. each probe
   face — required for correctness, ~32KB) rebuild + 3 orphaning `glBufferData` uploads.
8. **Test harness**: `--point-light-grid N[,radius,intensity]` (defaults 10, 5): N×N XZ grid,
   HSV-hued, each light's `q` derived so it dies at its cull radius; N²>128 clamps + warns.
   Heatmap: `clusterDebug` uniform, csmDebug-style tint before FragColor: count/16 → 5-stop
   blue→cyan→green→yellow→red ramp, mix 0.6, count 0 untinted.

## std140 layouts (binding points in ubo.h: 0/1/2)

```
LightsBlock (binding 0) — 12,512 B
  0     ivec4 lightCounts;            // x=numDir (≤4), y=numClustered (≤128)
  16    vec4  clusterParams;          // x=sliceScale, y=sliceBias, z=16/fbW, w=8/fbH
  32    DirLight dirLights[4];        // stride 48:
        //   vec4 dirShadow      (xyz dir, w = float(shadow_map_index), −1 none)
        //   vec4 colorIntensity (xyz premultiplied)
        //   vec4 sizeMisc       (xy = size for CSM penumbra)
  224   PackedLight clusterLights[128];  // stride 96:
        //   vec4 posRange       (xyz pos, w cull radius)
        //   vec4 dirType        (xyz dir, w = 1 point / 2 spot / 3 area)
        //   vec4 colorIntensity
        //   vec4 attenCutoff    (constant, linear, quadratic, cos inner)
        //   vec4 spotShadowSize (cos outer, shadow slot [spare], size.xy)
        //   vec4 upReserved     — RESERVED for LTC `up` (A2); do not repurpose

ClusterBlock (binding 1) — 12,288 B:  uvec4 clusters[768]      // 3072 words: (offset<<12)|count
ClusterIndexBlock (binding 2) — 8,192 B:  uvec4 lightIndices[512]  // 4096 × 16-bit, 2 per uint
```

std140 trap: scalar arrays get 16-byte stride — the uvec4 packing is mandatory, not stylistic.
C mirrors use only `float[4]`/`int32_t[4]` rows + `_Static_assert(sizeof == …)`; runtime
`GL_UNIFORM_BLOCK_DATA_SIZE` check per program. GLSL 330 has uint shifts/masks and dynamic vector
component indexing; access isolated in two tiny helpers (`clusterWord`, `lightIndexAt`) as the
single point of repair if Apple's GLSL compiler misbehaves.

## Risks

1. **std140 offset mismatch** (silent garbage) → vec4-row-only C mirrors, static asserts, runtime
   block-size check, uvec4 packing rule.
2. **LSB drift on the 0-diff gate** → legacy branch byte-verbatim through C6; PAE 1/255 allowance;
   bisect include placement if exceeded.
3. **macOS GLSL compiler quirks** (large UBO struct arrays, dynamic component indexing) → access
   isolated in 2 helpers; under 16KB guaranteed minimum; path lit up early at C4, not at the end.
4. **Probe-capture parameter skew** → every build parameter sourced from the same locals the
   frustum extraction uses; C6 probe A/B check.
5. **Index-pool overflow (4096)** → deterministic truncation + one-shot warning + heatmap
   visibility; per-cluster AABB refinement is the follow-up if red.

## As-built notes (verification results)

- **Every off-gate ran exactly 0 px** vs the pre-branch golden (C1-C6) — even C2's block
  declarations compiled into pbr_frag without perturbing Metal GLSL codegen. The final C7 build
  (clustered as the only path) also reproduces the pre-branch golden at **exactly 0 px**.
- **Clustered == legacy byte-identical** on the directional-only raiden scene (the CPU
  premultiplied color*intensity is bit-exact; directionals bypass clustering).
- **The point-light A/B exposed a real legacy bug**: with >3 lights sorting ahead of the
  shadow-casting directionals in the per-node k-nearest heap, legacy's `i < MAX_SHADOW_LIGHTS`
  guard silently dropped key-light shadows (the exact ordering fragility documented at the old
  pbr_frag:1069). ~80% of A/B pixel differences were legacy being wrong; clustered shadows
  correctly via the DirLight-carried slot. The residue (0.34% px, PAE ≤ 27/255) is the ε-tail
  cutoff at cull radii, gamma-amplified in dark regions (linear 1/256 ≈ 20-27 sRGB LSB in
  blacks). Follow-up candidate: windowed range falloff `(1-(d/r)^4)^2` à la Frostbite/UE, now
  trivial with a single code path.
- **The v1 box-fill assignment overflowed the 4096-index pool on the first real test** (a
  near-camera light's tile-rect × slice-range box massively over-covers the actual sphere), so
  the designated follow-up moved into C6: per-cluster sphere-vs-AABB refinement + pool grown to
  6144 (12KB block). Post-refinement the same scene sits at ~4.2k/6144 with no truncation.
- **Probe capture with clustering: 7 px @ PAE exactly 1/255** — the documented compiler-noise
  floor; per-face cluster rebuilds are correct by construction (the build hooks inside
  render_current_scene and reads the invocation's own viewport/camera).
- **Spot/flashlight**: not headless-testable in the render app (no spot CLI); the clustered spot
  branch is type-keyed identical to legacy and the global spot-map mechanism is untouched.
  Covered interactively via gametest now that clustered is the only path.
- C7 removed 555 lines against 96 added; `uniform_array_location`, `uniform_cache_lights`,
  `get_closest_lights` + the per-node heap, `get_gl_max_lights`, and the
  `USED_UNIFORM_COMPONENTS`/`PBR_MAX_LIGHTS` budget accounting are gone.
