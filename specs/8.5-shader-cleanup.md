# 8.5 Shader Cleanup: dead code, dedup via chunks, and what to leave alone

Runs AFTER 8.4 completes (phase C, the handedness varying, is still pending
there and touches `pbr_frag`'s sign-recovery sites -- land it first so this
plan edits settled code).

Sources: three independent audits -- a duplication catalog (10 cross-file
blocks), a hygiene inventory (dead code, mismatches, conventions), and a
C-coupling map (what C uploads where, what is rename-safe). Findings below are
CONFIRMED by trace unless marked otherwise; file:line references are from the
audit date and may drift a few lines.

## Context

8.4 built a build-time `#include` mechanism (`cetra/shaders/include/`,
expanded by `gen_shader_header.py`) and used it for exactly two chunks (wind,
tbn). The corpus is ~5,700 lines across 58 built shaders; roughly 300 lines
are duplicated blocks the seam should absorb, and a further ~150 are dead.
Five comments in the sky shaders literally say "GLSL has no includes; keep in
sync" -- a premise now false -- and the sky intersection helper has ALREADY
drifted into two behaviours under three names. One duplication
(`MAX_LIGHTS` 70 vs 64 on the same-named uniform array in one linked program)
is a latent link error.

## Hard constraints (from the C-coupling map)

- **`particle_sim_vert.glsl` TF varyings `oCenter/oParams/oColor/oVelAge/oLife`
  are order-locked** to `ParticleGpuState` (program.c hardcodes the list).
  Never rename; corruption is silent.
- **snprintf'd uniform families fail silently on rename**: `lights[i].*` (13
  field names), `shadowLightIndex[]`, `shadowLightWeight[]`,
  `lightSpaceMatrix[]`, `cascadeParams[]`, `boneMatrices[]`, `uPrevBoneRows[]`,
  `lightColor[]`, `lightDir[]`.
- **`post_vert.glsl` is frozen** -- its `out vec2 TexCoords` feeds 34 programs.
- **`pbr_frag` links against two vertex shaders** (`pbr`, `pbr_skinned`); any
  varying change is a three-file lockstep edit.
- **`ibl_cubemap_vert` also feeds `sky_env`; `skybox_vert` also feeds
  `sky_background`** -- easy-to-miss cross-links.
- A shared "varyings" chunk across shader FAMILIES is not viable: `TexCoords`
  is vec2 in the post family and vec3 in the skybox family.
- Sky atmosphere constants are pure GLSL `const`, uploaded by nobody -- fully
  unconstrained. BUT `sky.c:62-75` keeps an independent C mirror (`SKY_RG`,
  `ray[]`, `mie_ext`, `ozone[]`) for CPU-side sun transmittance; the chunk
  must carry a comment naming that mirror or a value change silently desyncs
  sun color.
- `ibl_prefilter_frag`'s `roughness`/`resolution` are uploaded per mip from
  `ibl.c` -- they stay uniforms with those names. `SAMPLE_COUNT` is local and
  free to move.
- `fog_frag` declares the CSM block under PRIVATE names
  (`MAX_FOG_LIGHTS`/`FOG_CASCADES`) and is fed by a separate upload path in
  `postfx.c:1224-1254`, not `bind_shadow_maps_to_program`.

## Phase 1 -- deletions (one commit, bar: 0 differing pixels)

Everything here is dead by trace; deletion also resolves both `MAX_LIGHTS`
mismatches and both `gl_Position`-read-before-write sites.

1. **Delete `cetra/shaders/pbr_frag.glsl.old`** (unbuilt backup, carries
   MAX_LIGHTS 75 as a red herring).
2. **Gut `shape_vert.glsl` (~55 of 71 lines).** The pipeline is
   `shape_vert -> shape_geo -> shape_frag`; `shape_geo` consumes ONLY
   `WorldPos_vs`, `shape_frag` consumes nothing. Dead: 7 of 8 outputs, the
   `Light` struct + `lights[]`/`numLights` (`MAX_LIGHTS 70` copy #2), `camPos`,
   `time`, `uNormalMatrix`, `aNormal`/`aTangent` attributes, the
   `#include "tbn.glsl"`, and all writes to the dead outputs. Also
   `shape_geo.glsl:10 uniform float time;` (unused).
3. **Delete the `FragPos`/`ClipDepth`/`FragDepth` varying chain** in
   `pbr_vert`, `pbr_skinned_vert`, `pbr_frag` (declared, written, never read
   -- the only "reference" is a prose comment at pbr_frag:895). Removes 3
   interpolator slots and both undefined-behaviour `gl_Position` reads
   (`pbr_vert:85`, `shape_vert:60` -- reading a vertex OUTPUT before writing
   it is undefined per spec, harmless today only because the consumers are
   dead).
4. **Delete `pbr_vert.glsl:22-41` + `camPos`** (the dead `Light`
   struct/`lights[70]`/`numLights` copy -- resolves the latent
   two-sizes-one-program link hazard) and `pbr_skinned_vert.glsl`'s dead
   `camPos`.
5. **Delete 8 dead `pbr_frag` uniforms** -- `model`, `nearClip`, `farClip`,
   `time`, `reflectanceTex`, `reflectanceTexExists`, `numShadowLights`
   (dead in pbr_frag only; LIVE in catcher/particle -- delete the
   declaration, not the shadow.c upload) -- **and their per-draw C uploads**:
   `render.c:218` (reflectanceTex), `:275` (reflectanceTexExists),
   `:288-289` (nearClip/farClip), plus the `uniform_cache_standard` warm
   lines for reflectanceTex/reflectanceTexExists/nearClip/farClip in
   `uniform.c`. Measurable per-draw CPU saving (hash lookups + no-op sets).
6. **Delete `xyz_frag.glsl`'s three dead matrix uniforms** (`model`, `view`,
   `projection` -- the shader is a flat color write).
7. **Small sweep:** `ibl.c:12` dead `#include "shader_strings.h"`;
   `sky_transmittance_frag.glsl:15` unused `PI`; dead `in vec2 TexCoords` in
   `lum_adapt_frag` and `motion_blur_tilemax_frag`; orphaned clearcoat
   comment block `pbr_frag:815-819`; `A2C_MIN_ALPHA`/`alphaBelowCutoff()`
   wedged mid-uniform-block (`pbr_frag:93-98`, move below the uniforms);
   trailing blank lines (`pbr_vert`, `shape_vert`, `shape_geo`, `shape_frag`)
   and the whitespace-only `shape_vert:51`.

## Phase 2 -- sky atmosphere chunks (one commit, bar: 0 pixels on a --sky render)

The strongest dedup case: ~120 redundant lines across 5 files, three "keep in
sync" comments now factually wrong, and the ray/sphere helper already drifted
(`distanceToSphere` clamps the discriminant; `distanceToTop` in sky_view
returns -1 on miss -- same math, incompatible contracts, callers not
swappable).

- `include/atmosphere.glsl`: `Rg`, `Rt`, `PI`, `VIEW_ALTITUDE`,
  `GROUND_ALBEDO`, `SUN_ILLUMINANCE`, Rayleigh/Mie/Ozone coefficients, ONE
  intersection helper exposing both contracts explicitly (e.g.
  `distanceToSphereClamped` + `distanceToSphereOrMiss`), the shared density/
  extinction sampling, `hitsGround()`. Carry a comment naming the
  `sky.c:62-75` C mirror.
- `include/sky_lut.glsl`: the `skyViewUv()` encode/decode pair (28
  byte-identical lines in sky_env + sky_background), `transmittanceUv()`/
  `transmittanceTo()`.
- Per-shader tuning constants STAY local: `TRANSMITTANCE_STEPS`,
  `SPHERE_DIRS`/`MARCH_STEPS`, `SKY_STEPS`, `MIE_G`.
- `sky_debug_frag` includes nothing (it uses none of this).
- Fix the stale "no includes" comments as part of this phase.

Consumers: `sky_transmittance/multiscatter/view/env/background_frag` -- 5
programs, zero C changes.

## Phase 3 -- IBL importance-sampling chunk (one commit, bar: 0 pixels with -e HDR)

`include/sampling.glsl`: `RadicalInverse_VdC` (14 lines), `Hammersley` (4),
`ImportanceSampleGGX` (19) -- byte-identical or trivially so across
`ibl_prefilter_frag` + `ibl_brdf_frag`. Drift here silently breaks split-sum
energy conservation (prefilter and LUT must sample the SAME distribution), and
the error is smooth enough to pass eyeballing. The two `DistributionGGX`/
`GeometrySmith` variants differ DELIBERATELY (direct-lighting k vs IBL k) and
stay put. Smallest blast radius of all chunks: 2 programs.

## Phase 4 -- skinning chunk (one commit, bar: 0 pixels on raiden)

`shadow_depth_vert.glsl:15` says "mirrors pbr_skinned_vert" -- the same
comment-enforced lockstep the wind chunk killed, in the same file pair, and
already drifted stylistically (inverted guard conditions).

`include/skin.glsl`: `MAX_BONES`, `skinned`, `boneMatrices[]`, and the blend
loop as a function. The depth pass deliberately omits `uPrevBoneRows` and the
previous-pose blend (~384 vec4s of vertex uniform budget it must not pay), so
gate that half behind `#define SKIN_PREV_POSE` set by `pbr_skinned_vert`
before the include -- expansion is textual and the real preprocessor runs
after, so this works today. Uniform names are hard-locked by
`render_update_skinning_uniforms` (used by BOTH the scene and shadow passes).

## Phase 5 -- CSM shadow chunk for the pbr/catcher/particle trio (one commit)

The uniform block + PCF sampling duplicated with variations across
`pbr_frag:161-189`, `catcher_frag:22-37`, `particle_frag:44-53`, all fed by
`bind_shadow_maps_to_program` (a C-side rename silently no-ops per shader
missed -- the location-guarded binder is why this block MUST be one text).

- `include/csm.glsl`: `MAX_SHADOW_LIGHTS`/`SHADOW_CASCADES` + the core
  uniforms all three declare (`shadowMaps`, `lightSpaceMatrix[]`,
  `cascadeParams[]`, `cascadeCount`, `numShadowLights`, `shadowBias`,
  `shadowTexelSize`) + `float outermostCascadeOcclusion(vec3 worldPos, int
  slot, int halfKernel)` for the catcher/particle `occlusion_from` twins
  (identical except PCF kernel extent -- parameterize).
- Per-shader extras stay local: pbr's PCSS/spot/csmDebug/`cascadeSplits`/
  `shadowLightIndex[]`, catcher's `shadowLightWeight[]`/`sceneOrthoWidth`.
- **`fog_frag` is deliberately EXCLUDED**: private macro names, partial block
  (no `cascadeParams`), and its own upload path in postfx.c. Folding it in is
  the highest-risk move in the whole plan for the least payoff. Instead: one
  comment on `MAX_FOG_LIGHTS`/`FOG_CASCADES` stating they must track
  `shadow.h`'s constants (the latent drift: bump `SHADOW_CASCADES` to 4 and
  fog silently corrupts its layer indexing).

Blast radius: `pbr`, `pbr_skinned`, `shadow_catcher`, `particle` -- verify
raiden (pbr shadows) plus a `--ground` render (catcher) plus tree `-f 2`
smoke (particles).

## Phase 6 -- small chunks, take-or-leave per item (one commit if taken)

Each is real duplication but small; skip any that fights the diff.

- `include/depth.glsl`: `viewZFromNdcZ` (4 identical lines in ssr_frag,
  dof_coc_frag, dof_composite_frag; particle_frag has a fourth drifted-in-form
  copy) + `viewPosFromLinZ` (gtao_frag, fog_frag). All encode the cglm
  projection convention -- a convention change must hit all of them.
- DoF CoC: the 7-line CoC computation duplicated in dof_coc + dof_composite;
  the composite exists to reproduce pass 1's CoC, so drift is a real bug.
- `include/color.glsl`: `rgbToYCoCg`/`yCoCgToRgb` (taa_resolve, ssgi_accum).
  The surrounding neighborhood-clamp code differs DELIBERATELY; move only the
  transform pair.
- `include/atrous.glsl`: the ssgi/ssr atrous twins share ~28 executable lines;
  `ssr_atrous_frag:17-20`'s stated reasons for cloning ("no GLSL #include",
  "byte-identity gate") are both void now.
- Interleaved-gradient-noise constants (4 files): borderline -- one line per
  site saved; SKIP unless already editing those files.

## Explicitly out of scope, with reasons

- **pbr_frag full decomposition.** The audit mapped it: ~450-500 lines are
  cleanly liftable (brdf/pom/sheen/thinfilm/sss as pure-function chunks), but
  main() is 691 lines reading ~18 shared locals, and the light loop / IBL
  block need a Surface struct refactor to move -- behaviour-affecting, not
  mechanical. After phases 1+5 the file lands ~1,100 lines. Decide separately
  whether the readability is worth chunks that no second shader consumes.
- **Naming/brace/varying-convention normalization.** Five varying conventions,
  a 1%-consistent `u` prefix, 14-vs-44 brace split. Zero functional gain,
  large diff, and every uniform rename risks a silent location-guarded no-op.
  If ever done: single mechanical pass, after all deletions, never mixed with
  functional commits.
- **fog_frag CSM unification** (above) and **particle_sim TF varyings**
  (hard-locked).

## Verification

Per phase, the deterministic recipe (both flags load-bearing -- see AGENTS.md
"Deterministic Renders"):

```bash
./out/bin/render -m my_models/raiden/source/raiden_textured_rigged.glb \
    -t my_models/raiden/textures -e my_models/studio_small_03_8k.hdr \
    -a my_models/animations/strut_walk.fbx -s my_models/animations/T-Pose.fbx \
    -x -f 120 --no-springs --no-auto-exposure -E 1.0 -S <scratch>/85_<phase>.ppm
magick compare -metric AE before.ppm after.ppm null:   # bar: 0 (tolerate <=10 px at PAE 1/255)
```

Phase 2 adds a `--sky --sun-elevation 30 --sun-azimuth 120` variant of the
same command (exercises all 5 sky programs + the IBL bake from sky). Phase 5
adds a `--ground` variant (catcher) and `./out/bin/tree -x -f 2` +
`./out/bin/spores -x -f 2` as compile/link smoke tests only.

Additionally, for every pure-move phase: regenerate `shader_strings.h` before
and after, unescape, strip comments, and diff -- the header is sorted and
reproducible, so this proves "no executable GLSL changed" without a renderer.
Phases 2/4/5 will NOT diff clean (functions get renamed/parameterized); for
those the pixel bar is the evidence.

Build gotchas that already cost time once: never pipe `./build.sh` through
`head` (SIGPIPE kills the link mid-way); `-m foo.glb` auto-loads a sibling
`foo.cscn` (use `--no-scene-file`).

## Ordering rationale

Deletions first so nothing later reformats or extracts lines about to die.
Sky before IBL/skinning because it retires an ACTIVE drift, not a potential
one. CSM last of the big chunks because it has the widest blast radius and
depends on 8.4 phase C having settled pbr_frag. Convention work never blocks
anything and is deliberately parked.

## Shipped outcome

All six phases landed (`2d61d5b`, `f6b63fc`, `89b26e3`, `54ae5bc`, `51299b8`,
`c207d3e`, `1534466`), every one verified at **0 differing pixels**.

Corpus: 5,771 -> 5,133 lines of top-level shader, plus 541 lines of shared
chunk. The eleven comments admitting hand-maintained duplication are down to
two, and both of those now describe genuine parallel-but-different code
(fog's spot cone alignment, pbr's light-loop shape) rather than copied text.
That count was taken with too narrow a pattern: `ssr_atrous_frag.glsl` still
carried a third, asserting "no GLSL #include here" -- a premise this branch
itself falsified -- and it survived phase 6 examining that very file. Rewritten
to state the reason the clone actually persists (vec4 vs vec3 filtering).

Chunks now in `cetra/shaders/include/`: wind, tbn (from 8.4), atmosphere,
sky_lut, sampling, skin, csm, depth, color.

### What the plan got wrong or under-specified

**The gating pattern turned out to be the load-bearing idea**, and the plan
only anticipated it once (for skinning). Three chunks needed it, for the same
reason each time: GLSL compiles the whole translation unit, so a helper that
references uniforms its includer does not declare is a compile error even if
nothing calls it.
- `SKIN_PREV_POSE` -- keeps `uPrevBoneRows` (384 vec4s) out of the depth pass.
- `CSM_OUTERMOST_PCF` + `CSM_PCF_HALF_KERNEL` -- pbr takes the uniform block
  only; the kernel radius is a define rather than a parameter so the PCF loops
  keep constant bounds and unroll as the hand-written copies did. A runtime
  parameter would have changed codegen and broken the 0-pixel bar.
- `DOF_COC` -- `cocAtNdcZ` reads focus uniforms that ssr/gtao/fog do not have.

**Phase 2's premise was understated.** The plan said the sky intersection
helper "has already drifted"; it had drifted into two incompatible CONTRACTS
under three names (clamp-to-zero vs return -1 on a miss), so the fix could not
be one function. Both are now spelled out as `...Clamped` / `...OrMiss` and
each caller picks deliberately. Likewise the density profile had three
signatures, not one -- `atmosphereSample` takes the superset and the other two
derive from it with identical arithmetic in identical order.

**Phase 1 was under-scoped in the plan and over-delivered in practice.** It
also turned up `glLineWidth(3.0)` in the bone overlay, which core profile
rejects (GL_ALIASED_LINE_WIDTH_RANGE is 1..1 here) -- so the debug bones had
always drawn 1px, and the rejected call raised an error every frame that
surfaced at the NEXT check_gl_error, in an unrelated postfx pass. Fixed
separately in `348eb4e` by drawing camera-facing quads.

### Still open

- `pbr_frag` decomposition: still parked, and the earlier figures here were
  wrong. Measured: 1,362 -> 1,345 lines, so phases 1 and 5 removed **17**
  lines, not ~200, and the file is 1,345, not ~1,150. It is 26% of the
  top-level corpus and essentially untouched. Parking is still the right call
  (`main()` is ~690 lines over ~18 shared locals; moving the light loop needs a
  Surface struct, which is behaviour-affecting rather than mechanical) -- but
  the wrong numbers mattered, because they are exactly what someone would use
  to judge whether the parked work is still worth doing.
- Convention normalization: still parked, same reasoning.
- The a-trous pair and the interleaved-gradient-noise constants: examined in
  phase 6 and skipped -- the shared a-trous body is entangled with
  per-shader vec3-vs-vec4 sampling, and the noise constants save one line per
  site.
- `fog_frag` remains outside the CSM chunk by design, with a comment recording
  that its private `MAX_FOG_LIGHTS`/`FOG_CASCADES` must still track
  `shadow.h`.

### Post-hoc measurements (added after the phases landed)

Facts gathered while reviewing, recorded because the phase notes above assert
some of them without having checked:

**No dead uniform declarations were reintroduced.** Phase 1 deleted dead
uniforms as a virtue, and three chunks (wind, skin, csm) declare uniforms, so
this was worth verifying rather than assuming. Measured on the EXPANDED source
in the generated header, not the .glsl sources: pbr_frag 96 uniforms / 0 dead,
catcher_frag 13 / 0, particle_frag 17 / 0, shadow_depth_vert 16 / 0. The
`#ifdef CSM_OUTERMOST_PCF` gate correctly keeps `numShadowLights` and
`sceneOrthoWidth` out of pbr_frag, and `#ifdef SKIN_PREV_POSE` keeps
`uPrevBoneRows` out of the depth pass. (A first pass at this measurement
reported a false positive because it grepped text without evaluating `#ifdef` —
the gate is invisible to naive greps, which is itself worth knowing.)

**All four atmosphere intersection variants are genuinely called**, so exposing
both contracts did not leave dead code: `distanceToTopClamped` (transmittance
bake + transmittanceUv), `distanceToTopOrMiss` (sky_view),
`distanceToGroundClamped` (multiscatter), `distanceToGroundOrMiss` (sky_view).

**atmosphere.glsl is coarse, by measurement.** Of its 22 exported symbols,
sky_background uses 2, sky_env 5, sky_transmittance 4, sky_view 9,
multiscatter 9. These are `const`s and functions, which GLSL strips — no
uniform locations consumed, no runtime cost — so this is a granularity
observation, not a regression. Whether it should split (e.g. the density model
apart from the geometry) is open.

**The branch left 8 thin forwarding wrappers**, kept so call sites stayed
untouched and the 0-pixel bar held: `occlusion_from` (catcher, particle — one
call site each), `transmittanceTo` (sky_view, sky_env, sky_background,
multiscatter — one to three call sites each), `extinctionAt` (transmittance
bake — one call site), `scatteringAt` (multiscatter — one call site). "It kept
the diff small" is an honest reason for the shape of the change but not an
argument that the shape is right; several are single-call-site identity
wrappers that could be inlined.
