# B7 — Lens flare and chromatic aberration (roadmap row 17)

## Context

Row 17 is one of two unstarted items left on the roadmap; every row through 16
is DONE and 19 (B8) closed today. Row 18 (A6 moment shadows) is the other, and
it should wait: it costs 4x shadow memory, gives up PCSS contact-hardening, and
lands in the same shadow code the 232-commit `area-light-shadows-and-ltc-horizon`
branch is rewriting. B7 collides with nothing — it is pure post, touches no
material model, no mask array, no scene graph.

**The roadmap's B7 sketch is stale and this plan corrects it.** It lists
"frame_index-hashed deterministic grain, vignette, edge chromatic aberration" as
work to do. Grain, vignette, sharpen and grade all shipped — `tonemap_frag.glsl`
has them at `:46-57` and `postfx_apply_film_look` (`postfx.c:1802`) presets four
of them. What is genuinely unbuilt is the **flare chain** and **chromatic
aberration**. Scope is those two; the spec records the correction so row 17 is
not re-read as more work than it is.

**Everything defaults OFF, so the entire golden battery is the correctness
test** — the same falsification shape that made 11.19 Phase 1 verifiable.

## What already exists and gets reused

- **`postfx_run_bloom`** (`postfx.c:1573`) — Jimenez dual-filter pyramid on one
  mipped texture via FBO re-attach + BASE/MAX_LEVEL pinning.
- **The tonemap composite** (`postfx.c:3040-3070`) already blends bloom
  additively and owns `bloomStrength` / `bloomEnabled`. The flare joins it
  rather than adding a composite pass.
- **Free sampler units.** `tonemap_frag.glsl` declares 9 of 16 samplers, and
  units 7 and 8 both bind 0 (`postfx.c:3058-3061`, unit 8 the retired fog debug
  buffer). No ledger pressure — that constraint is `pbr_frag`'s, not this one's.
- **`--sharpen` / `--film`** are the precedent for a default-off finishing knob
  with a CLI flag and a `.cscn` post key.
- **`post.render_scale`** (added this branch) is the precedent for a new
  `.cscn` post field with CLI-beats-scene-beats-default precedence.

## The one real design decision

**The flare reads the finished bloom pyramid, not a private bright pass.**

`postfx_run_bloom`'s upsample writes back down onto level 0, so after it runs
level 0 is the *summed blur*, not the bright-pass output — there is no
persistent thresholded buffer to read. Three options:

1. A second bright pass into a private target — duplicates the threshold/knee/
   firefly-clamp logic, and a second copy of that arithmetic will drift.
2. Run the flare between the bright pass and the downsample chain — couples the
   flare's lifetime to the inside of a function that owns an FBO re-attach loop.
3. **Read a mid mip of the finished pyramid.** Thresholded and pre-blurred
   already, which is exactly what ghosts want, and it costs nothing.

Take 3. Ghosts are defocused by construction, so sampling a blurred source is
correct rather than a compromise. It also means **the flare is gated on bloom
being on** — state that in the flag's help text rather than silently producing
nothing.

## Phase 1 — the flare pass

**`cetra/shaders/lens_flare_frag.glsl`** (new). Chapman-style, all in one pass
at quarter post-res:

- **Ghosts**: N samples of the source at `uv` mirrored about the centre and
  scaled by a per-ghost factor (`vec2 g = (0.5 - uv) * scale + 0.5`), weighted
  by distance from centre so off-axis ghosts fade.
- **Chromatic offset**: R/G/B sampled at slightly different radial scales, which
  is what makes a ghost read as a lens artifact rather than a blurred copy.
- **Lens-colour gradient**: radial 1D ramp, as a small `const` array in GLSL
  rather than a texture — the same call spec 11.13 made for the skin fit, and it
  keeps the sampler count where it is.
- **Halo**: one sample along the vector toward the centre at a fixed radius.

**`PostFX`** gains a lazily-allocated `flare_texture` + `flare_fbo` at quarter
post-res, `flare_program`, and `flare_enabled` / `flare_strength` /
`flare_ghosts` / `flare_halo_width` / `flare_chroma`. Lazy allocation follows
the fog pass, which `CLAUDE.md` names as the canonical gated/lazy/half-res
template.

**`postfx_run_flare(PostFX*, ...)`** runs immediately after
`postfx_run_bloom` in `postfx_run` — inside the same `if (fx->bloom_enabled)`
neighbourhood, gated additionally on `flare_enabled`.

**Composite**: `tonemap_frag` gains `flareTex` (unit 8) + `flareStrength` +
`flareEnabled`, added alongside bloom in the existing composite. Guarded so
`flareEnabled == 0` compiles to the expression that is there today.

## Phase 2 — chromatic aberration

~10 lines in `tonemap_frag.glsl`, in the existing finishing block
(`:318-354`, order `sharpen -> grade -> vignette -> gamma -> grain`). Sample the
composited colour three times at radially scaled UVs, one per channel, scaled by
`caStrength * r^2` so the centre is untouched and the corners carry it.

**Placement matters and should be stated in the spec:** it goes *before* grain,
because grain is display-space noise that must not be resampled, and *after*
grade, because a grade applied per-channel to already-separated samples would
shift the fringe colour.

`ca_enabled` / `ca_strength` on `PostFX`, default off.

## Phase 3 — controls

- **CLI** (`apps/render/src/render.c`): `--flare` (+ `--flare-strength`),
  `--chromatic-aberration` (+ strength). Help text for `--flare` says it needs
  bloom.
- **`.cscn`** post keys via the `has_*` + presence-flag pattern
  (`cscene.h` / `cscene.c` / `cscene_apply.c`), same shape as `render_scale`.
- **GUI**: the Post section in `gui.c` — `_begin_effect_group` / `_end_effect_group`
  is the established paired idiom for a checkbox with dependent sliders.
- **`--film` is NOT touched.** Its output stays byte-identical, so anything
  captured with it still compares.

## Phase 4 — fixture, gate and golden

**Fixture**: `assets/gen_flare_fixture.py` — a dark scene with one small
very bright emissive quad off-centre, which is the configuration a ghost chain
is visible in at all. Reuses the generator idiom in `assets/gen_*.py`.

**Gate**, `run_flare_gate` in `scripts/gates.py`, self-verifying and no stored
image:

1. **Off is off.** `--flare` absent vs present-at-strength-0 must be **0 px**.
   The gate that matters: it proves the default path is untouched.
2. **Ghosts land opposite the source.** The emitter is off-centre, so the
   flare's energy must appear on the *other* side of frame centre. Compare the
   mean of the half opposite the emitter, flare on vs off — it must rise, and
   the emitter's own half must not. That is the claim "these are ghosts of the
   bright source" rather than "the image got brighter".
3. **CA separates channels radially.** At a high-contrast corner edge, the R and
   B channel edge positions must differ with CA on and coincide with it off.
   Asserts the mechanism, not a magnitude.

**Golden**: one flare-on image, following the DoF/SSS precedent of a first
golden for a new pass. Captured with `--no-auto-exposure -E 1.0` per the
determinism rules.

## Verification

1. `./build.sh` clean.
2. **All 18 goldens 0 px and 35 gates unchanged.** Nothing is on by default, so
   any movement is a defect — a stray uniform upload or a composite that is not
   actually guarded. This is the strongest check available and it is free.
3. `run_flare_gate` passes, and its arm 1 (off-vs-zero-strength) is shown to
   fail against a deliberately broken guard before being trusted.
4. Determinism x2 on the flare fixture: the pass must be frame-index-pure, like
   grain (`grain_seed` is already documented as deterministic across equal
   `--frames` runs).
5. Visual pass on the fixture and one real scene, presented as an A/B crop.
