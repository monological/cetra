# Cetra Particle System — Implementation Plan (v2, post-review)

## Context

Cetra is a C11 / OpenGL 4.1 rendering engine with a strong renderer and Jolt physics, but
**no particle system** (and no instanced-draw path anywhere). The goal is a **general,
reusable, Niagara-style particle system** as the deliverable, validated by a **cordyceps
spore-room demo** as its first test — TLOU-style infected-air spores: dense, pale with a
faint green tint, floating/drifting with curl-noise turbulence, HDR-bright so bloom catches
them, in a dark interior lit by one directional light.

Decisions locked with the user:
- **Full Niagara-style architecture**: `System → Emitter → composable Modules (spawn/init/
  update phases) → pluggable Renderers`, particles stored **SoA** in bounded pools.
- **Sim backend**: CPU implementation now behind a backend interface, with a clean seam for
  a future **GL 4.3 compute** backend. **No second graphics API** (Metal/Vulkan/DX interop
  rejected: high cost, partial win, macOS hole). No transform feedback in v1.
- **Host**: the cetra **game loop** (`create_game`/`run_game`) **without physics**; sim runs
  in `on_update(game, dt)` at fixed timestep.

This plan is the reviewed v2: it fixes sim-loop ownership, spawn accounting, kill ordering,
renderer/engine coupling, the backend↔renderer instance contract, GL-state restore, and
demo emitter math (details inline, marked **[fix]**).

## Architecture overview

```
ParticleSystem ──owns──▶ ParticleEmitter[] ──owns──▶ ParticlePool (SoA) + Module lists + ParticleRenderer
      │
ParticleSimBackend (owns SIM STEPPING; CPU now, GL4.3-compute seam)
```

- **[fix] One owner for the sim loop**: `ParticleSimBackend.simulate()` is THE entry point
  that steps an emitter. The emitter is **data** (pool + phase-ordered module lists +
  config) — it has no public tick of its own. (v1 had both `emitter_tick` and
  `backend->simulate`; that ambiguity is removed.)
- **The seam, stated honestly**: what survives a CPU→GPU backend swap is (a) the emitter's
  *module configuration* (descriptor list + params — a GPU backend interprets it, bringing
  GLSL counterparts per module type, the way Niagara compiles module stacks into sim
  shaders), and (b) the **render contract**: renderers consume only a
  `ParticleInstanceView`, never the pool. CPU backend hands back a packed CPU buffer; a GPU
  backend would hand back a pre-filled VBO; the draw path is identical. CPU module
  fn-pointers themselves do not port — the `[begin,end)` slice signature keeps kernels
  shaped like GPU invocations (and is also the future CPU-threading seam).

## Naming **[fix]**

Consistent `Particle*` / `particle_*` prefix throughout: `ParticleEmitter` (bare `Emitter`
collides with existing light-emitter terminology, e.g. PCSS emitter size `shadow.h:45`),
`ParticleSimBackend`, `ParticleModule`, `ParticlePool`, `ParticleRenderer`,
`ParticleSystem`. Factories follow cetra's `create_*`/`free_*` convention. Structs are open
(house style — `Light`, `Camera`, `ShadowSystem` are all open), with internal fields
commented as such.

## Core interfaces (load-bearing)

```c
// particle_pool.h — SoA, live particles compact in [0,count)
typedef struct ParticlePool {
    size_t capacity, count;
    vec3 *position, *velocity;  vec4 *color;         // color = linear HDR rgba (base color)
    float *size, *rotation, *age, *lifetime, *seed;
} ParticlePool;
size_t particle_pool_spawn(ParticlePool*, size_t n);  // appends zeroed, clamped; returns first new index
void   particle_pool_kill_swap(ParticlePool*, size_t i);

// particle_module.h
typedef enum { PARTICLE_PHASE_SPAWN, PARTICLE_PHASE_INIT, PARTICLE_PHASE_UPDATE } ParticleModulePhase;
typedef void (*ParticleModuleFn)(ParticleModule* m, ParticleEmitter* e,
                                 size_t begin, size_t end, float dt, float t);
struct ParticleModule { const char* name; ParticleModulePhase phase; ParticleModuleFn run;
                        void (*free_fn)(ParticleModule*); void* params; };
```

**Phase contract** (enforced by the CPU backend's tick, in this order):
1. **SPAWN** modules: slice unused; each accumulates into `e->spawn_request` (float).
   **[fix] Fractional accumulation is mandatory**: `params->acc += rate*dt; whole = floorf(acc);
   acc -= whole; e->spawn_request += whole;` — naive per-tick flooring makes any rate < 1/dt
   (e.g. 30/s at 60fps) spawn **zero particles forever**.
2. Backend spawns `n = min(spawn_request, capacity - count)` via `particle_pool_spawn`,
   then stamps infrastructure defaults on the new slice: `age=0`, `lifetime=1` (guard
   against div-by-zero lifeFrac), `seed=` per-emitter xorshift32. Seeding is backend
   bookkeeping, not a module — modules express *behavior*.
3. **INIT** modules run over the new slice `[old_count, count)`.
4. **UPDATE** modules run over all live `[0, count)`. **[fix] Update modules never kill.**
5. Backend **compact** pass kills expired (`age >= lifetime`) iterating **backwards**
   (`i = count-1 … 0`) so swap-remove never swaps an unprocessed particle into a skipped
   slot. Kill logic lives in exactly one place.

Module design = fn-pointer descriptors + module-owned opaque params (not an enum switch —
that would centralize all behavior; not a typed union — that couples core to every module
and bloats to the largest member). Matches cetra's `create_*`/`free_*` + callback style
(`game.h:17-20`). **Factories return the `ParticleModule*` so apps can hold handles for
runtime tuning**; v1 ships setters only where the demo needs them
(`particle_module_spawn_rate_set`, `particle_module_curl_set_strength`).

```c
// particle_sim.h — the seam + the layout contract
typedef struct ParticleInstanceData {   // [fix] THE canonical v1 instance layout, shared by
    vec3 center; float _pad0;           // backend (packer) and billboard renderer (consumer).
    vec4 params;                        // x=size, y=rotation, z=lifeFrac, w=seed
    vec4 color;                         // linear HDR premultipliable rgba (base)
    vec3 velocity; float _pad1;         // for velocity stretch
} ParticleInstanceData;                 // 64B, explicit padding, std430-friendly for the
                                        // future GPU backend. Future renderers (mesh/ribbon)
                                        // add a layout enum the backend switches on.
typedef struct ParticleInstanceView {
    size_t count;  const ParticleInstanceData* cpu_instances;  // CPU path (GPU path: NULL)
    GLuint gpu_instance_vbo;                                   // GPU path (CPU path: 0)
} ParticleInstanceView;

typedef struct ParticleSimBackend { const char* name;
    void (*simulate)(ParticleSimBackend*, ParticleEmitter*, float dt, float t); // THE sim entry
    void (*acquire_instances)(ParticleSimBackend*, ParticleEmitter*, ParticleInstanceView* out);
    void (*free_fn)(ParticleSimBackend*); } ParticleSimBackend;
ParticleSimBackend* create_cpu_particle_sim_backend(void);

// particle_renderer.h — [fix] decoupled from Engine: exactly what renderers consume.
typedef struct ParticleRenderContext {
    mat4 view, proj;  vec3 camera_pos;  float time;
    struct Scene* scene;          // lights[] + shadow_system (bind_shadow_maps_to_program)
    GLuint scene_depth_texture;   // single-sample depth for soft particles; 0 = feature off
} ParticleRenderContext;
typedef struct ParticleRenderer { const char* name;
    void (*prepare)(ParticleRenderer*, ParticleEmitter*, const ParticleRenderContext*); // upload
    void (*draw)(ParticleRenderer*, ParticleEmitter*, const ParticleRenderContext*);
    void (*free_fn)(ParticleRenderer*); void* impl; } ParticleRenderer;
ParticleRenderer* create_billboard_particle_renderer(ShaderProgram*);
```

Renderers depend on **GL + Scene only** — never `Engine`. The app (which has the engine)
fills the context; the M4 depth-resolve helper lives engine-side and its output texture is
passed in. This keeps renderers testable and reusable (e.g. a future shadow-pass draw with
different matrices).

## Instanced billboard renderer

- **VAO**: static unit-quad VBO on **slot 0** (corner, vec2) + **slot 2** (uv) — per
  `common.h:6-14` (slots 0–8 taken, **9+ free**, verified). Per-instance VBO =
  `ParticleInstanceData` stream, `glVertexAttribDivisor(slot,1)` on slots **9** center,
  **10** params, **11** color, **12** velocity.
- **Setup** mirrors the bone-line VAO (`engine.c:648-658`); **per-frame upload** mirrors the
  bone re-upload (`render.c:920-935`): one `glBufferData(count*sizeof(ParticleInstanceData),
  view.cpu_instances, GL_DYNAMIC_DRAW)`. **Draw**: `glDrawArraysInstanced(GL_TRIANGLES, 0, 6, count)`.
- **`particle_vert.glsl`**: camera-facing basis from view-matrix columns; rotate+scale
  corner; optional velocity stretch (lerp basis toward screen-projected velocity by speed);
  emit `WorldPos`, `uv`, color, `lifeFrac`, view-space z.
- **`particle_frag.glsl`**:
  - Procedural radial soft alpha (`smoothstep`), no texture → no sampler-0 conflict.
  - **[fix] Alpha life envelope in-shader from `lifeFrac`** (already in instance params):
    fade-in first ~10%, fade-out last ~30%. Non-destructive (base color stays in the pool);
    kills the need for a color-over-life update module in v1.
  - Directional light from auto-cached `lights[]` (applied like `pbr_frag.glsl:963-965`)
    with **half-Lambert** wrap (spores are near-isotropic scatterers) + small ambient floor.
  - **CSM shadow**: copy `occlusion_from` from `catcher_frag.glsl:47-76` (verified) —
    deliberately samples the **outermost scene-fit cascade** (no per-fragment cascade
    selection, no seams; soft 5×5 PCF) — the right simplification for volumetric motes too.
    Requires `sceneOrthoWidth`, which `bind_shadow_maps_to_program → 
    shadow_upload_cascade_uniforms` already uploads (`shadow.c:329`, verified). We do NOT
    use the catcher's `shadowLightWeight[]` (not set by the bind helper; catcher-specific).
  - **HDR gain** (×4–8) so pale-green spores exceed 1.0 and bloom picks them up.
  - **Premultiplied-alpha** output `vec4(rgb*a, a)`; blend `GL_ONE, GL_ONE_MINUS_SRC_ALPHA`.
  - Soft-particle fade (M4): sample `scene_depth_texture` (unit **7**, free per
    `common.h:23`), reconstruct view-Z from `proj`, `a *= saturate((sceneZ - particleZ)/softDist)`.

## Draw hook + GL state

Dedicated pass **right after `render_current_scene()` returns** in the app's `on_render`
(precedent: `render_skeleton_bones`, `apps/render/src/render.c:1098`). State there:
`engine->framebuffer` (MSAA RGBA16F HDR) bound, color-only attachment 0, depth test
ON/`GL_LESS` vs opaque+skybox depth.

```c
glDepthMask(GL_FALSE);
glBlendFunc(GL_ONE, GL_ONE_MINUS_SRC_ALPHA);            // premultiplied
particle_system_render(g_sys, &ctx);
glDepthMask(GL_TRUE);
glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA);      // [fix] restore engine BASELINE func;
// blending STAYS ENABLED — engine.c:330-331 enables it once at init and every later pass
// assumes it. (v1 plan disabled GL_BLEND here — that would break subsequent passes.)
```

Then `engine_present_frame → postfx_run` applies bloom/tonemap/DOF automatically. Deferred
(M5): engine-side hook inside `render_current_scene` before the depth-write restore at
`render.c:737`, enabling velocity-to-aux for TAA.

## Risks / gotchas

- **CMake reconfigure for new shaders**: `*.glsl` GLOB captured at configure time
  (`cetra/CMakeLists.txt:18-24`) — re-run cmake or `particle_*_shader_str` won't exist.
- **TAA ghosting**: particle pass writes no velocity → smearing under TAA. v1: keep TAA off
  (MSAA 4x default `engine.c:116`; headless runs TAA-off). Fix lands with M5 engine hook.
- **Blend/sort**: premultiplied-over is order-tolerant for mostly-emissive low-alpha spores,
  not order-*independent*; if dense clusters artifact, add coarse CPU back-to-front sort
  (data already CPU-side).
- **Fog-over-particles approximation**: volumetric fog composites using *opaque* depth, so
  spores in front of far walls get slightly over-fogged. Acceptable v1; haze is optional.
- **Sampler units**: `shadowMaps` fixed unit 10 (`shadow.h:18`); soft-depth unit 7 (free,
  `common.h:23`); 15 also free. Procedural spores bind no material textures.
- **Depth feedback loop**: never sample the bound depth attachment — blit to a separate
  single-sample texture first (the reason `engine_resolve_opaque_color` exists).
- **Sim-space**: v1 simulates `PARTICLE_SPACE_WORLD` only; `LOCAL` enum + `local_to_world`
  present but stubbed. Single-threaded CPU sim (20k × ~8 modules is sub-ms); the
  `[begin,end)` slices are the future threading seam.
