# A2 Subplan — LTC Area Lights

## Context

Second feature of the AAA rendering roadmap (`specs/9.0-aaa-rendering-roadmap.md`, Tier 1 item 2),
building directly on A1 (clustered forward lighting, `specs/9.1`, merged). Today `LIGHT_AREA`
lights shade as point lights — `light.size` only feeds PCSS emitter softness. LTC (Linearly
Transformed Cosines, Heitz/Dupuy/Hill/Neubelt SIGGRAPH 2016) gives physically correct rectangular
area-light diffuse + specular — including stretched glossy reflections — from two small LUT
fetches per light. This is the roadmap's first feature with directly visible payoff, and it must
land before A4 (DDGI) so probe captures see area-lit environments.

A1 changed the integration surface from the original mini-spec: lights now flow through the
std140 `PackedLight` UBO (which already reserves `upReserved` for this feature), and the shading
loop is the fused dir+cluster loop in pbr_frag.

**User decisions locked:**
- `.cscn` scene files gain `"type": "area"` support (+ size/direction) in this branch.
- **No GUI in v1** — CLI + cscn only (three GUI placement bugs shipped in A1 because ImGui layout
  can't be verified headless; any A2 GUI comes later as its own interactively-verified change).
- LTC tables **vendored**: the published MIT-licensed table data from Heitz's `ltc_code` repo is
  copied into `tools/`, converted once by a new `tools/gen_ltc_lut.py` into a checked-in C header.
  Builds never regenerate and never touch the network.

## Verified integration facts (exploration, current master)

- **Insertion point**: pbr_frag's fused loop — packed-light fetch ends at :1021; the area branch
  goes right after it (`if area → Lo += LTC; continue;`), skipping the whole Cook-Torrance body.
  Other light types keep the exact existing expression stream.
- **`upReserved` is ready**: reserved in `PackedLight` (lights_ubo.glsl:33), zeroed by
  `_gather_lights`' memset, read nowhere — packing `up` changes no layout, no sizes.
- **`Light` has no up**: add `original_up`/`up` mirroring the `original_direction`/`direction`
  pair; scene.c:743-749 is the rotation site to mirror (glm_mat4_mulv3 w=0 + normalize).
- **Texture units**: 7 is free (no define exists); 9 is `TEXUNIT_REFLECTANCE`, reserved and never
  bound anywhere. Bind model: per program switch beside `bind_ibl_textures` (render.c:377-388).
- **LUT fetches must be `textureLod(..., 0.0)`**: the cluster loop is non-uniform control flow;
  plain `texture()` derivatives are undefined there. (Existing in-loop taps get away with
  `texture()` only because shadow/height maps are mip-less.)
- **No float-texture-from-memory helper exists** (`load_texture_from_memory` is 8-bit only) —
  A2 owns building `create_texture_2d_float()` per the roadmap's foundations table.
- **LUT ownership**: engine-lifetime (unlike the scene-owned, environment-baked brdf_lut) —
  Engine fields created in `init_engine`, freed in teardown, following bone_line_vao/catcher_vao.
- **Import hazard (must fix in this branch)**: `process_ai_lights` (import.c:1175-1193) maps
  assimp's `default:` — including AMBIENT/UNDEFINED *and* real AREA lights — to `LIGHT_AREA`,
  and never reads `aiLight::mSize`, leaving the default 50×50 size. Harmless while AREA shades
  as a point light; after LTC every junk imported light becomes a giant glowing panel. Fix: an
  explicit `aiLightSource_AREA` case that reads `mSize`, and `default → LIGHT_UNKNOWN` (already
  skipped by the light gather). Regression check required (abandoned_window's lights are
  explicitly typed — verify unchanged).
- **cscene**: `CSceneLight` (cscene.h:37-42) has no type/size/direction fields; the parser
  (cscene.c:96-127) explicitly rejects non-"point" types; `add_cscene_lights`
  (cscene_apply.c:134-155) hardcodes `LIGHT_POINT`. All three grow area support.
- **renderMode 7 debug loop** also reads `dirType.w` — decide its area handling (default: leave
  point-ish; it's a debug view).
- New `include/ltc.glsl` works via the existing build-time include expansion; shaders are
  `#version 330 core` (textureLod is core; nothing else needed).

## Resolved design

1. **LTC math** (follows selfshadow/ltc_code WebGL reference verbatim; three.js carries the same
   code). Per-fragment (hoisted OUT of the light loop, guarded by new dynamically-uniform
   `lightCounts.z > 0` — the area-light count packed into the free `light_counts[2]`):
   `uv = vec2(roughness, sqrt(1-NdotV)) * 63/64 + 0.5/64` (half-texel constants); `t1 =
   textureLod(ltcMatTex, uv, 0)` → `Minv = mat3(vec3(t1.x,0,t1.y), vec3(0,1,0), vec3(t1.z,0,t1.w))`
   (columns; fit normalized m[1][1]=1); `ltcAmp = textureLod(ltcAmpTex, uv, 0)`. Raw
   `roughnessMap`, NOT the Karis-widened `areaLightRoughness` (that stays for the other lights;
   new symbols use `ltc`/`panel` prefixes to avoid the name collision).
   Per light (clipless): corners `lightPos ± right*halfW ± up*halfH`, `right = cross(up, dir)`,
   winding making the polygon normal ∥ +direction — **a panel illuminates the half-space its
   direction points into** (spot semantics), enforced first by the exact plane test
   `if (dot(WorldPos - lightPos, direction) <= 0) continue;` (single-sided v1). Then tangent frame
   `T1 = normalize(V - N*NdotV)`, `T2 = cross(N, T1)`; corners through
   `Minv * transpose(mat3(T1,T2,N))`; Hill's rational-fit `ltcIntegrateEdgeVec` over 4 edges →
   `vsum`; horizon-clipped-sphere lookup at its OWN uv:
   `form = len * textureLod(ltcAmpTex, vec2(z*0.5+0.5, len)*SCALE+BIAS, 0).w` — the `.w` table
   owns the 1/2π normalization and horizon clip (do NOT "fix" a missing 2π).
   Combine in pbr_frag (material coupling stays out of the include):
   `areaSpec = (F0*ltcAmp.x + (1-F0)*ltcAmp.y) * ltcEvaluate(Minv, …)`;
   `areaDiff = (1-metallic)*(1-transmissionEff)*albedo * ltcEvaluate(identity, …)` (no 1/π —
   already in the form factor; no Fresnel kD, per reference);
   `Lo += min((areaDiff + areaSpec) * lightCI, vec3(10.0)); continue;` — the `continue`
   implements the v1 skips (no shadows/clearcoat/sheen/SSS/POM on panels) by construction.
   Branch sits right after the packed-light fetch closes (pbr_frag:1021). renderMode 7 debug
   loop: untouched (attenuated-point look still proves cluster membership; zero off-gate risk).
2. **Intensity semantics + cull radius**: area `intensity` = emitted radiance of the panel;
   constant/linear/quadratic are dead for area lights (the form factor carries 1/d²).
   `light_cull_radius` for AREA (authored `range` still wins): head-on far-field bound
   `r = sqrt(256 * I_eff * A / π) + 0.5*diagonal`, `A = size.x*size.y` — same 1/256 visibility
   floor as the point path, conservative.
3. **LUT format RGBA32F** (matrix entries exceed [0,1] and fp16 comfort at grazing/low-roughness
   corners; published fit is float32; 128 KB total).
4. **Unit 9: rename `TEXUNIT_REFLECTANCE` → `TEXUNIT_LTC_AMP`** (reserved-never-bound; the 9.0
   ledger already assigned it); add `TEXUNIT_LTC_MAT 7`; `TEXUNIT_MATERIAL_MAX` follows; extend
   the render.c:31-49 assert chain (SCENE_COLOR < LTC_MAT < SHEEN < LTC_AMP).
5. **Tools**: `tools/ltc_data.js` (verbatim vendored ltc_code LUT data, upstream hash +
   `tools/LTC_LICENSE` MIT text), `tools/gen_ltc_lut.py` (stdlib-only, extracts the two
   16384-float arrays in file order, validates, emits `cetra/src/ltc_lut.h` with a
   GENERATED/DO-NOT-EDIT banner + regen command). NOT wired to CMake — run-once, checked in.
6. **`up` API**: `Light.original_up`/`up` mirroring the direction pair; `set_light_up` writes
   both; default `{0,0,1}` (with default direction {0,-1,0} → right = +X); scene.c:743-749 gains
   the identical rotate-by-global-transform for up. Pack time (AREA only): Gram-Schmidt up
   against direction, fallback to smallest-world-axis cross when parallel; result →
   `up_reserved[0..2]`. Every path (CLI/cscn/import) may leave up unset — orthonormalization
   makes any value safe, no sentinel needed.
7. **LUT plumbing**: new `create_texture_2d_float(w, h, internal_format, format, pixels)` in
   texture.c (LINEAR/CLAMP_TO_EDGE/no-mips baked in, ibl.c:508-511 state); engine-lifetime
   `GLuint ltc_mat_tex, ltc_amp_tex` on Engine (bone_line_vao pattern: init_engine creates,
   teardown deletes); bound unconditionally per program switch beside the IBL binds
   (render.c:377-388) — location-miss no-ops on non-PBR programs. Samplers declared inside
   `ltc.glsl` (csm.glsl precedent).
8. **Energy sanity (headless, quantitative)**: invariance golden pairs on raiden with
   `--no-key-light --ibl-intensity 0` (panel = only light) — the tonemap nonlinearity cancels
   when linear radiance matches:
   E1 inverse-square: (dist d, radiance I) vs (2d, 4I) with a small panel → PAE ≤ 2/255.
   E2 radiance×area: (0.2×0.2, I=40) vs (0.4×0.4, I=10) at fixed distance → same threshold.

## ltc.glsl inventory (~90 lines)

`ltcMatTex`/`ltcAmpTex` samplers · `LTC_LUT_SCALE/BIAS` consts · `ltcCoords(roughness, NdotV)` ·
`ltcMatrix(coords)` (fetch + Minv reconstruction) · `ltcIntegrateEdgeVec(v1, v2)` ·
`ltcEvaluate(N, V, P, Minv, p0..p3)` (tangent frame, transform, 4-edge sum, sphere-clip lookup) ·
`ltcPanelCorners(center, dir, up, halfSize, out p0..p3)`. Composition/combine lives in pbr_frag.

## Risks

1. **Minv packing/transpose bug** → rotated/smeared highlights. Constructor copied verbatim;
   identity-matrix diffuse is packing-independent, so "diffuse right, specular wrong" isolates it.
2. **Winding/handedness sign flip** → wrong half-space or black panel. Plane early-out pins the
   emit side independently; C5 gate (b) tests it; both sign knobs live in single functions.
3. **Half-texel/orientation errors** → banding at extremes. Constants + data order vendored
   together from one reference; C5 gate (c).
4. **Metal codegen perturbation breaking the off-gate** → hoisted fetches behind the
   dynamically-uniform guard leave area-free fragments one integer compare heavier; textureLod
   everywhere; 9.1 precedent held 0 px through bigger shader edits; LSB escape hatch.
5. **Import-mapping regression** → C1 first, 0-px checks on both checked-in scenes, loud warn on
   every default-mapped light.
6. **Energy mistakes** (double 1/π, missing amp combine, spurious 2π "fix") → normalization
   contract documented (the `.w` table owns 1/2π); E1/E2 catch scale errors quantitatively.

## As-built notes

**Corrections to this plan, found during implementation:**

- **License is BSD 3-clause, not MIT.** The plan said MIT; the actual upstream terms are
  BSD 3-clause, © 2017 Eric Heitz, Jonathan Dupuy, Stephen Hill, David Neubelt. `tools/LTC_LICENSE`
  is a verbatim copy of the upstream `LICENSE`. Vendored file is `fit/results/ltc.js` from
  selfshadow/ltc_code @ `31e5e96b54f98f33098f8503003119ba2231a1c6` (the plan guessed a
  `webgl/lib/` path that does not exist).
- **Generator float formatting.** `%.9g` renders 1.0 as bare `1`, which is not a valid C float
  literal once suffixed (`1f`). `gen_ltc_lut.py` forces a decimal point.
- **Test subject.** The plan's E1/E2 recipe used raiden, which is fully metallic — with IBL off it
  has no diffuse response whatsoever, so it validates only the specular half and looks
  near-black either way. Replaced with a purpose-built fixture,
  `assets/area_light_fixture.gltf` (generator: `assets/gen_area_light_fixture.py`): six
  dielectric spheres sweeping roughness 0.05 → 0.95 over a diffuse ground quad. Follows the
  existing `gen_*_fixture.py` convention.
- **Suppressing all other light.** `--no-key-light` alone is not enough: with no IBL *and* no
  authored lights the app installs a three-point rig. An HDR must still be passed
  (`-e <hdr> --no-key-light --ibl-intensity 0`) to take the IBL branch and get zero analytic
  lights. `--no-ground` and explicit `--cam-eye/--cam-target` are also needed for a readable
  frame. All recorded in `goldens/9.2/README.md`.

**Measured results:**

| Gate | Result |
|---|---|
| Off-gate (raiden), every commit C1–C6 | **0 px** |
| Import fixtures before/after C1 | **0 px** (`light_import_fixture`); `abandoned_window` is wind-driven and non-deterministic, RMSE within its own same-build noise floor |
| Sign check (panel normal negated) | **all spheres pure black** |
| Roughness sweep 0.05 → 0.95 | sharp rectangular highlight → soft wash, no banding at LUT extremes |
| E1 inverse-square (2× distance, 4× radiance) | **PAE 2/255**, RMSE 0.18% |
| E2 radiance × area (same power, fixed distance) | **PAE 1/255**, RMSE 0.014% |
| C6 `.cscn` vs equivalent `--area-light` | **0 px** |

E1/E2 are centre-crop comparisons: the sphere row's horizontal spread means off-axis distances
do not scale with the centre, so the residual is geometric, not an energy error.

**No sign flip or transpose fix was needed** — the vendored reconstruction and winding were
correct first try, which the three independent checks (plane test, backface golden, roughness
sweep) corroborate.

**Not done in v1** (unchanged from the plan): area-light shadows; clearcoat/sheen/SSS/POM
contribution from panels (the `continue` skips them by construction); two-sided panels; any GUI.
`renderMode == 7` still shades panels as attenuated points — it is a cluster-assignment debug
view, and touching it would risk the off-gate for no benefit.
