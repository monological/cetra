# 8.1 Foliage Quality

## Context

The tree from 8.0 has correct foliage plumbing -- alpha-masked cards, shadow
casting, transmission, wind flutter -- but the leaves read as flat green disks.
Two independent causes:

1. **The silhouette is literally an ellipse.** `generate_leaf_albedo` builds its
   alpha mask from an ellipse SDF with a slight point at the tip, and each quad
   carries exactly one leaf. The outline you see is that ellipse. At the current
   size (6.5 units against an 80-unit trunk) each one is large enough to read
   individually, so the canopy is a pile of ovals.

2. **Every card shades as an independent flat plane.** Each leaf's shading normal
   is its own card normal, so a thousand cards catch the light a thousand
   different ways and the canopy reads as confetti rather than as a volume.

Neither is fixable by tuning. This spec applies the five things a production
vegetation pipeline (SpeedTree/Unreal) does differently.

Not needed: back-face lighting is already correct -- `pbr_frag.glsl` flips the
normal on `!gl_FrontFacing`, so back-lit leaves already shade properly.

## Design

### 1. Cluster cards

No production tree puts one leaf on one quad. A foliage card holds a whole
*sprig* -- several overlapping leaves with varied size, rotation, and tone baked
into one alpha texture -- so one quad buys an irregular, concave silhouette at
the same vertex cost, and the canopy densifies without more geometry.

`generate_leaf_albedo` / `generate_leaf_normal` are replaced by a single
`generate_leaf_cluster_maps()` that rasterizes ~9 leaves per cluster and emits
albedo (RGBA), normal (RGB), and roughness (R) together, so all three agree
per texel.

Leaves are rasterized one at a time into their own bounding box and composited
(later leaves over earlier), rather than evaluated per-pixel against every leaf
in the cluster -- same result, a fraction of the work.

### 2. Canopy-volume normals

The single biggest lighting difference in vegetation rendering. Each leaf vertex
normal is blended away from the card normal and toward the canopy volume normal
-- the direction from the canopy center out through that vertex:

```
vol  = normalize(vertex_pos - canopy_center)
N    = normalize(mix(card_normal, vol, 0.65))
```

The crown then shades as one soft body, lit on the sunward side and falling off
into shadow, instead of thousands of independently-flipping planes. Nearly free:
`tree_mesh_leaves` already computes `canopy_center` for the baked occlusion. The
tangent is re-orthogonalized against the new normal so normal mapping still
works; it now perturbs around the volume normal, which is what SpeedTree does.

### 3. Real leaf shape

The rasterized leaf outline, in leaf-local coords (`u` across the width in
[-1,1], `v` stem to tip in [0,1]):

- half-width `w(v) = A * sin(pi * v^0.65)` -- widest around 40-45% of the
  length, tapering to a point at the tip
- serration: `w *= 1 + 0.05 * sin(v * 18pi)`, a toothed edge
- asymmetry: a small per-leaf skew so the two halves differ
- petiole: below `v < 0.1` the width collapses to a thin stalk, so the leaf
  visibly attaches to something instead of floating
- midrib plus ~5 angled secondary veins, slightly darker, and a matching ridge
  in the normal map

### 4. Cluster variants

Four distinct clusters in a **horizontal 4x1 atlas**; each card picks one by UV
offset. Identical repeated sprites are a strong tell.

The atlas must tile along U only. The wind shader uses `UV0.y` as the flutter
weight so the card pivots about its stem (`v = 0`); splitting V across atlas
rows would break that pivot and scale flutter differently per row.

Card UVs become `u = (variant + uu + 0.5) / 4`, `v` unchanged in [0,1].

### 5. Waxy specular

Leaves have a cuticle: a tighter, brighter highlight than the current flat
roughness 0.5. Material roughness drops to 0.35, and the cluster pass writes a
roughness map with a per-leaf value in [0.25, 0.5], so leaves within a cluster
glint unevenly rather than as one sheet. The roughness layer samples UV0, so the
atlas UVs are fine -- and unlike an AO map it does not collide with UV1's wind
data (see 8.0).

### Sizing

A card now carries ~9 leaves, so it represents a sprig rather than a leaf:
`leaf_size` 6.5 -> 15, `leaf_density` 5.5 -> 2.5. Roughly the same vertex count
(~35k) for roughly nine times the apparent leaves.

## Files

- `apps/tree/src/tree.c` -- replace the two leaf texture generators with
  `generate_leaf_cluster_maps()`; bake the new roughness map; leaf material
  roughness + roughness texture; new leaf size/density defaults.
- `apps/tree/src/tree_gen.c` -- `emit_leaf_card()` takes a variant index and the
  canopy center; atlas UVs and volume-normal blending.
- `apps/tree/src/tree_gen.h` -- `TG_LEAF_VARIANTS`.

## Verification

```bash
./build.sh
# canopy should read as a lit volume with an irregular silhouette
./out/bin/tree -x -f 240 -S <scratch>/leaf_hero.ppm
# no-fog, high sun: check silhouette detail and per-leaf specular variation
./out/bin/tree -x -f 240 --no-fog --sun-elevation 40 -S <scratch>/leaf_clear.ppm
# back-lit: transmission through cluster cards
./out/bin/tree -x -f 240 --no-fog --sun-elevation 8 --sun-azimuth 30 -S <scratch>/leaf_backlit.ppm
```

Check: no visible repetition across the four variants; the canopy has a clear
lit side and shaded side; leaf edges are serrated, not elliptical; the ground
dapple still resolves as leaf-shaped.
