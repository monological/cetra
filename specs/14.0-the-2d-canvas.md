# 14.0: the 2D canvas

## Context

**What 14.0 builds.** cetra gains a 2D canvas: a module that draws exact 2D shapes after tone mapping, at display resolution, retained on the GPU and edited in place. It is item 1 of `docs/eda-roadmap.md`, the first spec of the 14.x series, and what pcb's schematic and layout views will stand on (pcb's ARCH sections 6, 8 and 9).

**It draws:**
- segments with a width, round or flat ended;
- arcs;
- circles and rounded rectangles, rotated, filled or outlined;
- filled polygons with holes;
- text.

**Its properties:**
- every edge exact at any zoom, with no multisampling;
- 64-bit integer coordinates in the app's unit, exact at any offset;
- layers with their own opacity, a translucent layer's overlaps showing once;
- instant highlighting through a table of tag states;
- edits built off the main thread, uploading only the tiles they touch;
- several views on one window, each with its own pan, zoom and shown layers.

**Why now.** pcb's step 6, the window with its schematic, cannot start without it, and the layout (step 7) uses it too. Nothing in cetra draws 2D this way today: the UI's draw list is rebuilt every frame in window points, and `geometry.c`'s shapes are tessellated scene meshes.

**Who uses it.** pcb, from its own repository. cetra names no pcb type: the canvas is a general engine module that pcb is the first user of.

## Found while planning

- **The overlay hook is one slot** (`engine.h:488-489`, `engine.c:2471-2476`), and the game UI takes it (`ui_attach`, `ui.c:1176-1180`). The canvas and the UI must share it.
- **`free_ui_system` never clears that slot** (`ui.c:1160-1174`). An engine that outlives its UI keeps a dangling pointer.
- **UI text is drawn about 2.3 atlas pixels bolder than its outline.** stb puts a glyph's true edge at 180/255 (`text.c:91`), and `ui_frag.glsl:50` and `text_frag.glsl:46` cut at 0.5.
- **The UI's quads are not padded**, so only the inner half of each edge's antialiasing ramp is drawn (`ui_frag.glsl:66-67`).
- **Text claims lazy glyph baking that does not exist** (`text.h:49`, `ui.h:208-209`). The atlas is printable ASCII only (`text.c:20-22`).
- **No polygon triangulation exists in `cetra/src`.** silent's `ear_clip` is app code, has no holes, and is O(n³).
- **`CanvasController`'s functions already use the `canvas_` prefix** (`app.h:84-130`), which collides with the new module. `canvas_world_under_cursor` also breaks the subject-first naming rule. Its users are `apps/shapes`, and pcb's `window.c` demo.
- **Draw calls cost about 2.1 µs each on Apple GL** (`specs/11.28`). One draw per tile per layer would be thousands of draws zoomed out.
- **Apple's GL runs tiled on Metal**, so every framebuffer switch stores and reloads whole attachments. A scratch target per layer would move gigabytes a frame at 4K.
- **The window is 4x multisampled** (`engine.c:546`), and the picture FBO is colour-only. Stencil fills would have no stencil buffer to use.

## Design

### The overlay list (`engine.c/h`, `ui.c/h`)

- **The API:**
  - `bool engine_add_overlay(engine, fn, user, order)` and `engine_remove_overlay(engine, fn, user)`.
  - The list is a bounded array of 8, drawn in ascending order, equal orders in insertion order.
  - `engine_add_overlay` refuses with false when the list is full, or when the same function and user are already on it.
  - The present loop iterates a copy, so an entry may remove itself.
- **What it replaces:** `engine_set_overlay` is deleted. The UI's own callers never named it.
- **The UI:**
  - `ui_attach` adds the UI at `UI_OVERLAY_ORDER` (100), keeping its engine.
  - `free_ui_system` removes the UI from the list.
- **Where it runs:** the same place in `engine_present_frame` the slot ran, so nothing draws differently.

### The model and the API (`canvas.h`, public)

**Every shape description starts with `CanvasPaint {layer, style, net, object}`.**
- Tags of 0 mean none.
- Tags are dense indices, and the table grows to fit them.
- The object tag is also what `canvas_edit_remove_object` removes by.

**The shapes:**

| Shape | Fields | Notes |
|---|---|---|
| Segment | `a`, `b`, `width`, `flat_ends` | |
| Arc | two endpoints, a radius, `clockwise`, `major`, `width` | As pcb and SVG state them. The endpoints stay exact for joints. |
| Circle | `centre`, `radius`, `stroke` | stroke 0 = filled |
| Box | `centre`, `size_x`, `size_y`, `corner`, `stroke`, `angle` | radians |
| Polyline | points, `closed`, `width` | |
| Polygon | an outer contour, holes, `stroke` | 0 = filled |
| Text | `Font*`, string, anchor point, `size` (the em, as SVG's font-size), `angle`, horizontal and vertical anchor | |

**Field roles**, following cetra's three:
- **Layer SETTINGS:** `opacity` and `order`.
- **Canvas SETTINGS:** `text_min_px` and `shape_min_px`.
- **Canvas ENGINE-OWNED:**
  - the counters `uploads` and `bytes_uploaded`;
  - `generation`, bumped by every apply, style write and tag write, for idle mode later.

### Coordinates and precision

- **Tiles are 2^22 units square by default.** A shape belongs to the tile of its anchor.
- **Its GPU record holds int32 offsets from that tile's origin.**
- **Each frame**, the CPU writes each tile's int32 offset from the view's integer centre into a tile table (an `isamplerBuffer`).
- **The vertex stage:**
  1. adds the two in int32, which is exact;
  2. converts to float relative to the view, exact within 2^24 units of it;
  3. subtracts the view's fraction;
  4. scales to pixels.
- **Long shapes are split.** A segment or arc reaching more than a tile from its anchor, and every fill triangle, is split or clipped at tile boundaries with hard, unantialiased cuts, so the pieces meet with no seam.
- **Large circles, boxes and strings stay whole.** They are placed from their centre or anchor, exact within 2^24 units of the view.

### The GPU form

**Each layer has two buffers:**
- **Shape instances**, 48 bytes each:
  - `ivec4` the int32 points;
  - `vec4` the shape's measures;
  - `uvec4` kind, flags and style; net; object; tile and glyph.
- **Fill triangles**, 24-byte vertices, unindexed.

**A tile is a range of its layer's buffers, uploaded alone with `glBufferSubData`.**
- Each range has slack, and a tile that outgrows it moves to the buffer's end.
- Dead slots are kind NONE.
- This replaces ARCH's "one buffer per tile", which cost one draw per tile per layer. The deviation is recorded in the roadmap.

**A layer is drawn by a few draws whatever its tile count.**
- Instances of tiles out of view are culled in the vertex stage from a visibility bit in the tile table.
- GL 4.1 has no base instance, so a range cannot be drawn alone.

**A shape is a unit quad from `gl_VertexID`.**
- It is padded by one framebuffer pixel plus its stroke.
- The fragment stage evaluates the shape's exact signed distance `d` in pixels, from the known scale rather than `fwidth`.
- Coverage is `clamp(0.5 - d)`, so measured areas match closed forms.

**The tables are buffer textures**, the first in cetra (checked on all three platforms in phase 2):
- styles;
- tag states;
- tiles;
- each font's glyphs.

### Fills (`triangulate.c/h`, new)

- **The triangulator:** a CPU, earcut-style triangulator of an outer contour with holes. It is a port of Mapbox's earcut (ISC), keeping its notice, and is safe off the main thread.
- **Who calls it:** `canvas_edit_polygon`, which then clips the triangles to tiles.
- **Edge bits:** each triangle carries three bits saying which of its edges lie on a contour.
- **Antialiasing:**
  - The fragment stage antialiases the inside half of contour edges, by distance from them.
  - Edge instances draw the outside half.
  - So every pixel has one contributor, matching `clamp(0.5 - d)`.
  - Edges inside the polygon are never antialiased, so there are no seams.

### Layers and translucency

**Each `canvas_draw` renders the view into one RGBA8 single-sample target the canvas owns**, sized to the largest view and reused view after view: one framebuffer switch per view.

**In that pass:**
- The background is drawn opaque.
- Each layer, in order with the active one last, is resolved using the target's alpha as scratch:
  1. Alpha is zeroed in the rect.
  2. The layer's coverage is drawn into alpha alone, with union blending.
  3. Alpha is multiplied by the layer's opacity.
  4. The layer's colour is drawn with RGB blended by destination alpha and alpha set to zero. The first shape reaching a pixel spends the whole union coverage; overlaps add nothing.

**The colour pass's order** decides which colour wins where shapes overlap:
1. raised tags;
2. coverage of ½ or more;
3. the rest.

**Then one quad composites the rect into the overlay's target** (FBO 0 or the picture) as `vec4(rgb, 1)` with blending off. `glBlitFramebuffer` cannot write a multisampled FBO 0.

**GL state.** `canvas_draw` saves and restores what it changes, through `gl_pass_begin`/`gl_pass_end` (`util.h:38-50`) plus:
- the colour mask;
- the blend equation;
- `GL_MULTISAMPLE`, disabled while drawing.

### Tags and styles

- **A style** is a colour. Changing it recolours every shape that uses it.
- **A tag state** is:
  - `colour`, overriding the style's;
  - `outline`, a ring band round distance-field shapes, for ARCH's pick candidate, with no new geometry;
  - `dim`, a colour scale;
  - `hidden`;
  - `raised`.
- **How a shape's two tags merge**, field by field:
  - **Colour and outline:** the object's if set, else the net's.
  - **Dim:** the larger of the two.
  - **Hidden and raised:** either.
- **Why two tags, where ARCH has one net ID:** diff colours and selection belong to objects, highlighting to nets. Recorded in the roadmap.
- **`CanvasTags` is an object of its own**, borrowed by canvases. One write highlights a net in the schematic and the layout at once.
- **The object index:** `canvas_apply` keeps a CPU index from object to its (layer, tile, slot) entries, so a remove costs time in proportion to the object.

### Text

- **Changes to `text.c/h`:**
  - `Font` exposes its SDF edge (180/255) and its distance scale.
  - The false lazy-baking comments are corrected.
- **The canvas owns layout.**
  - A string becomes glyph records: an anchor plus pen offsets, with kerning from `font_kern_advance`. Rotation and mirroring are about the anchor.
  - Size is the em.
  - Records hold a glyph index into the font's glyph table, so a re-bake touches no geometry.
  - Glyphs are cut at the font's true edge.
  - `canvas_text_width` measures with the same metrics, for pcb's layout and picking.
- **Fonts per canvas:** up to 4, on fixed texture units, chosen by branch. GL 4.1 cannot index a sampler array per instance.
- **The UI's cut** (`ui_frag.glsl`, `text_frag.glsl`) moves to the font's true edge too, so canvas and UI text agree. You see before and after pictures of silent's HUD and menus and of gametest's menus before it is committed.

### Detail by zoom

All of this happens in the vertex stage, so zooming rebuilds nothing:
- Widths are clamped to at least one framebuffer pixel.
- A string is dropped when its em is under `text_min_px`.
- A shape is dropped when it spans less than `shape_min_px`; 0, never, is the default.

### Edits off the main thread

- **A `CanvasEdit` holds no GL**, so pcb's worker threads can fill one. Splitting, clipping, triangulating and laying out text all happen inside it.
- **`canvas_apply`** merges an edit on the main thread in time proportional to the edit, marking the tiles it touched. Those tiles upload at the next draw.
- **Transient drawing** (a route being drawn, the ratsnest, a rubber band) is an ordinary layer cleared and refilled each frame. An arm holds that this is cheap.

### The rename (`app.c/h`)

- `CanvasController` becomes `PlaneDrag`, with functions `plane_drag_*`, mirroring `CameraDrag`.
- `canvas_world_under_cursor` becomes `plane_drag_point_under`.
- Callers updated: `apps/shapes/src/shapes.c` and the docstring at `scripts/gates.py:28514-28517`. pcb's `window.c` follows when pcb bumps its submodule.

## Tests (`apps/canvas`, the `canvas` gate group)

**`apps/canvas`** is new, windowed or headless:
- `-x`, `-f`, `-S`, `-W` and `-H`;
- `--sheet NAME`, a test sheet;
- `--canvas-probe CASE`, which prints lines as gametest's `--ui-probe` does;

**Arms with no pixels** (a hidden context only):
- tile bookkeeping;
- uploads after an edit: only the touched tiles;
- a tag or style write uploads no geometry;
- triangulated area against the shoelace formula, holes included;
- text metrics against stb's;
- the view round trip, unit to point to unit;
- a transient layer refilled each frame costs time in proportion to its contents.

**Pixel arms**, read from the headless PPM, with sizes in framebuffer pixels. The noise floor is measured first, by rendering one sheet twice.

| Arm | What it checks |
|---|---|
| Areas | Coverage summed against closed forms: circle πr², ring, rounded rect, capsule, arc band, polygon with holes |
| Ramp | The edge ramp's shape |
| One-pixel minimum | A column sum of 1.0 for a line thinner than a pixel |
| Translation twin | The sheet at the origin and at 2^40 units, the view on a tile corner: 0 px |
| Long segment | A long segment seen deep in its middle against a short copy: 0 px |
| Mirror twin | The sheet against its mirror image |
| Target twin | FBO 0 against the picture FBO, forced by an after-tonemap pass: 0 px |
| Overlap once | Two overlapping capsules in a 50% layer: the overlap equals the rest |
| Glyph edge | A glyph's area against `stbtt_MakeCodepointBitmap`'s coverage |
| Under the UI | The UI drawn over the canvas |
| Budget | Frame time on the dense board. A timing arm, so it does not travel between machines |

### Phase 2: first drawing (`d64c49d8`)

**Built:**
- **The module.** `canvas.h` (public), `canvas.c` (layers, tiles, tables, apply, upload, draw),
  `canvas_edit.c` (no GL), `canvas_record.h` (internal: the record and an edit's steps).
- **The shaders.** `canvas_vert.glsl`, `canvas_frag.glsl` and `canvas_composite_frag.glsl`, over
  `include/canvas_constants.glsl`, the kinds and flags, which C includes too
  (shore_constants.glsl's technique).
- **Shapes:** segments with round or flat ends, arcs, circles, boxes, and polylines as round-ended
  segments, each an instanced quad and an exact distance in pixels with coverage
  `clamp(0.5 - d)`.
- **Tables:** tags (three RGBA8 texels each, the written range re-uploaded), styles and tiles, as
  buffer textures.
- **Layers** drawn in order, the active one last, each in one instanced draw over its whole buffer.
- **The view's target** (RGBA8, grown only) composited into the overlay's framebuffer, opaque.
- **The view helpers**, and `apps/canvas` with the `shapes` sheet, `--view`, `--offset`,
  `--mirror`, `--tile-shift`, panning by drag and zooming by the wheel.

**Different from the plan, and why:**
- **`create_canvas(engine, desc)`**, not `create_canvas(desc)`: a canvas needs its engine for the
  framebuffer's scale and its programs, and every other `create_` taking an engine takes it first.
- **`CanvasView.points_per_unit`**, not pixels per unit. The view helpers work in window points and
  must not need an engine to answer, so the zoom is in the same space and `canvas_draw` converts
  it with the framebuffer's scale.
- **The tile table is indexed by tile COORDINATE**, shared by every layer, not by a layer's tile.
  The offset depends only on where a tile is, and a table a coordinate stays short across forty
  layers; a record's tile field is therefore 32 bits, and a glyph will carry its index in the
  measures instead.

### Phase 3: the geometry arms (`fe5f74cf`)

**Built:**
- **The `canvas` gate group** (`run_canvas_gate`), seven arms.
- **`apps/canvas` gains probe sheets**, each white on black so a pixel's red code is its coverage:
  `areas`, `ramp`, `thin`, `long` and `long-short`.
- **`--canvas-probe`** prints where each shape landed and its measures in framebuffer pixels, and
  which framebuffer the overlay drew into, so the arms restate no layout.
- **`--picture`** adds an after-tonemap pass that changes nothing, so the frame is drawn into the
  picture as under a CRT or a grade.

**Found and fixed: a flat end drew full coverage for the half pixel short of it.** Between the
ends the shader measured only the sides, so the inner half of a flat end's ramp was missing: a
flat-ended bar came out 4.4 px^2 over an exact simulation, single pixels by up to 0.44. Inside
the shape a flat end's distance now joins the sides' through `max`, which is the box's exact
interior distance, for segments and arcs alike; the bar then matches the simulation to 0.0034 a
pixel.

**The arms, as measured at 400x300 points (800x600 pixels), noise floor 0 px:**

| Arm | Bound | Measured |
|---|---|---|
| `canvas-areas` | within 0.03 px per pixel of edge | worst 0.0200, the box at 45 degrees |
| `canvas-ramp` | the crossed pixel 1 - f to a code, 0 before, 1 after | 0.898 for 0.9, and so on |
| `canvas-thin` | each column and row sums to 1 within 2/255 | 1.0000 |
| `canvas-translation` | 0 px | 0 px |
| `canvas-long-segment` | within 5 codes, the line drawn | 4 codes over 1,600 px |
| `canvas-mirror` | within 1 code | 5 px a code apart |
| `canvas-target` | 0 px, and drawn into the picture | 0 px |

**Different from the plan, and why:**
- **The 45-degree box's area error is the method's, not the shader's.** An exact distance sampled
  at pixel centres, computed in numpy, gives the same sum to 0.0013 a pixel: every row of a
  45-degree edge falls at the same phase of the pixel grid, so the ramp's sampling error does not
  average out along it. Since an area error grows with an edge's length, the arm bounds the error
  per pixel of perimeter, which holds at a 1x framebuffer as at a 2x one.
- **The long segment is within 5 codes, not 0 px.** A piece ends up to 2^23 units from the view,
  which is exact as a float, but scaling it to pixels rounds it by about 0.02 px at the arm's
  zoom, 80 px a micrometre. The error grows with the zoom times the tile's size, so a smaller
  tile would shrink it; at any zoom pcb will use it is far under a code.
- **The mirror is within a code, not 0 px.** The geometry is exactly mirrored, and the rasterizer
  interpolates a mirrored triangle's varyings in the other order, which rounds a few pixels a code
  apart: 5 at 400x300, none at 960x600.

**Falsified:** with the one-pixel floor on a segment's width removed, `canvas-thin` fails: a line
a tenth of a pixel wide sums to 0.42 a column rather than 1.

**Looked at:** the areas sheet beside its copy 2^40 units away, and the long line beside its
short copy.
