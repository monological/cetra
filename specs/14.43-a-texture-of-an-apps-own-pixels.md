# cetra 14.43: a texture of an app's own pixels

## Context

pcb's step 10 shows a datasheet's pages in a pane (its spec 10.2): PDFium draws a page into RGBA
pixels on a worker thread, in tiles at the pane's zoom, and the window has to show them. cetra's
roadmap had that as "images and datasheet pages" on the 2D canvas, a record kind kept free
(`docs/eda-roadmap.md`, item 1).

Read through with the user (2026-11-22), the canvas is not where a page belongs:

- **A page is a pane of its own.** Nothing in pcb's roadmaps puts a picture among a canvas's
  shapes -- under copper, between layers, on a sheet. A logo is shapes already (`pcb logo` reads an
  SVG into rings).
- **The UI already draws a picture**, or a part of one, clipped to a pane, from a draw hook:
  `ui_draw_textured_quad_uv` (`ui.h`). pcb paints its board pane and its panes' overlays that way.
- **An image on the canvas is a spec of days** -- a record kind, its textures, a pass of its own
  beside a layer's coverage, tags, mirror, the read off the screen -- and with no case its rules
  would be guesses. It stays left for later, costing then what it costs now; nothing here is
  thrown away by it.

What is missing is the texture. The one way to make a `Texture` from pixels is
`texture_load_memory`, a model's path (`texture_pool_publish`, `texture.c`): every pixel hashed for
the cook, a mip chain built on the CPU and kept on disk where the cook is on, repeat wrap with
trilinear and anisotropic filtering, a pool keyed by a string where a second use of a key answers
with the first picture, and pixels never written again. The engine goes round it for itself:
`glyph_cache.c` makes the code editor's atlas by hand -- clamped, linear, one level, a rectangle
written a glyph -- and hands the UI a `Texture` it filled in. An app has no such way.

And pictures will now meet edge to edge. Spec 14.23 left an image drawn to its rect, saying
"nothing draws images meeting edge to edge today". Page tiles do. On pixel bounds they should meet
with nothing between them and be drawn texel for pixel; this spec holds that with an arm and writes
the rule down.

Branch and spec: `14.43-a-texture-of-an-apps-own-pixels`, off cetra's master (`fbdd3941`).

## The design

Two functions in `texture.h`, and nothing new in the UI:

```c
// A texture of pixels an app made, for the UI's quads: width * height pixels of red, green, blue
// and alpha, a byte each, rows from the top, stored as given -- so drawn as given by the UI, which
// blends display-encoded values, the alpha a pixel's opacity. Clamped at its edges, filtered
// linearly, one level, in no pool and never cooked. `rgba` NULL makes every byte 0. The caller's
// to free (free_texture; texture_release once shared). NULL, logged, for a side under 1 or past
// GL's largest. Main thread.
Texture* create_texture_rgba8(int width, int height, const unsigned char* rgba);

// Writes `rgba`, width * height pixels, over the rectangle whose top left pixel is (x, y). Logged,
// and nothing written, for a texture create_texture_rgba8 did not make or a rectangle not inside
// it. Main thread.
void texture_write_rgba8(Texture* texture, int x, int y, int width, int height,
                         const unsigned char* rgba);
```

- **Stored `GL_RGBA8`, not sRGB**: the UI multiplies a texel into a display-encoded colour
  (`ui_frag.glsl`), so the bytes given are the bytes shown. Rows from the top, as a `Picture`'s
  are: the UI's `v0` is a rect's top, so no row is turned over.
- **Made through `create_texture`**, which mallocs and sets each field, so the new field is set
  there too.
- **`Texture.app_pixels`**, a field: what `texture_write_rgba8` asks before it writes, a pooled
  texture's pixels being hashed, mipped and averaged once. `texture_gpu_bytes` counts one level for
  it and not a chain; a write forgets the remembered mean (`mean_valid`).
- **GL's pixel-store state is put back** after an upload, as `glyph_cache.c` does.
- **Its own four lines of sampler state.** `create_texture_2d_float` and `glyph_cache.c` set the
  same four; they are left alone, since sharing them reaches every lit scene's tables for no
  change in what is drawn.
- **Not taken**:
  - a one-channel form for `glyph_cache.c` to stand on -- its atlas is swizzled to white and
    written from a wider buffer by row length, two more parameters for one user inside the engine;
  - mips or a nearest filter -- a picture is drawn at its own size or, mid-zoom, stretched for a
    frame or two;
  - an upload off the main thread through a pixel buffer -- measured first (phase 1), added when a
    frame shows it.
- **An image's edge part way into a pixel stays as 14.23 left it**, counted by the samples and the
  ramp. The rule for an app is the one fills have: put a join on a pixel.

**What pcb does with it** (its 10.2, not this spec): a tile is a texture, or a rectangle of one
written in place; each tile's rect is rounded to whole framebuffer pixels (`fb_width` over
`win_width`), stretched ones too, so neighbours share an edge; tiles are made and freed in the
update hook, never between a draw hook and its frame; a tile landing on the worker asks for a
frame (`engine_request_frame`, any thread).

## Tests

A case in `apps/canvas` beside `--ui-seams` and `--ui-lines`, and an arm in the `canvas` group
(`scripts/gatelib/groups/canvas.py`), its docstring in the group's list, which `gate-docs` holds to
the arms. The case is staged as theirs are: `push_pixel_sheet`, a draw hook working in framebuffer
pixels, a line printed for each picture with its rect (`canvas pictures NAME ...`), and the arm
reads the screenshot against them. No existing check looks at an image's pixels: `ui-textured-uv`
compares vertices, on a `Texture` with no GL behind it.

- **`--ui-pictures`** -> `canvas-ui-pictures`, on an opaque backdrop no picture holds:
  - `exact`: a picture of a fixed pattern, a pixel-wide checker among it, drawn texel for pixel on
    whole pixels: every pixel is its texel. Fails for rows turned over, an sRGB decode, a mip, or
    half a pixel's shift.
  - `stack`: four textures two by two, meeting on pixel bounds: every pixel across the joins is its
    own picture's texel, the backdrop nowhere.
  - `clamp`: a picture red down its left column and blue down its right, drawn eight times its
    size: its outermost pixels are red and blue, neither mixed with the far edge.
  - `write`: a picture made clear with a rectangle written, and one made whole with a rectangle
    written over: inside the rectangle the new pixels, outside it the old.
  - `part`: a rectangle of a larger texture drawn by its UVs, texel for pixel: its own texels, no
    neighbour's at its edges.
  - `alpha`: a picture half opaque: half way to the backdrop.
  - Printed, not drawn: `texture_gpu_bytes` is width * height * 4; the scene's pool holds no more
    textures after than before; a size of 0, a size past GL's largest, a write outside the texture
    and a write into a pooled texture are each refused.
- **The tolerance** is `canvas-ui-seams`'s, 2 codes, unless a run shows the pixels come back to the
  byte, in which case it is 0 and the spec says so.
- **The ratio is the display's.** A headless run has no flag for it and takes the display's, two
  pixels a point on this Mac, and the case stages itself in framebuffer pixels, so the arm holds a
  64-pixel picture in a 32-point rect here and in a 64-point one on a 1x display. Nothing here
  runs at 1x.

## As built

### Phase 1: the texture, the case and the arm (`9e209aab`)

- **`create_texture_rgba8` and `texture_write_rgba8`**, as designed, with `Texture.app_pixels`
  set false in `create_texture`. `texture_gpu_bytes` stops at one level for such a texture.
- **No pixel-store state is touched**, a departure from the design's "put back": four bytes a
  pixel is a whole word a row, which is GL's default at rest, and `glyph_cache.c` leaves it there.
- **`--ui-pictures`**, the design's six pictures and, under them, a card for looking at: four
  textures two by two, a pixel-wide checker, upright and level lines a pixel wide and a checker
  of two pixels. A picture's pixels come from one function of a seed and a place, which the arm
  makes again in numpy (`_picture_pixels`).
- **`canvas-ui-pictures` holds every opaque pixel to the byte**, not within the 2 codes
  `canvas-ui-seams` allows: the first run showed the texels come back exactly, at this Mac's two
  pixels a point. The half-opaque picture is within 1 code, its blend 0.42 off by rounding. It
  holds the backdrop untouched 2 pixels round the picture drawn texel for pixel as well.
- **Falsified**, each put back:
  - repeat wrap: `clamp` alone, 512 pixels, every outer half texel;
  - `GL_SRGB8_ALPHA8`: `exact` 2304 pixels, and every picture with a tone between black and
    full; `clamp` passes, 0 and 255 decoding to themselves;
  - a write a row down: the two written pictures alone, 408 and 484 pixels.
- **Measured**, headless, a debug build, three runs, `glFinish` after each call: a texture 2048
  pixels a side made in 4.3 to 5.9 ms; a rectangle of 512 by 512 written in 0.17 to 0.19 ms, the
  least of 20. Apple's GL may put the copy to the GPU off until the texture is drawn, so these
  are the calls' cost and a floor on the whole.
- **Verified**: built, no warning in cetra's sources; `--arms
  canvas-ui-pictures,canvas-ui-seams,canvas-ui-lines` and `--only gate-docs,texcomp,clearcoat`
  pass, sixteen arms.
- **The look**: the headless picture's corner at three times its size in Preview, and the case in
  a window, 400 by 300 points at two pixels a point.

### Phase 3: the reviews (`6fcf50f1`)

`/simplify`'s four, the thermo-nuclear and a correctness review over `fbdd3941..5dad2c37`,
background agents at effort high, applied once all were back. Correctness found nothing in the
two functions that gives a wrong picture, a crash or a leak.

- **Applied, the engine:**
  - **NULL when GL cannot store it** (correctness): a failed upload returned a texture with a
    size and no storage. The error is read after the upload, the name deleted and NULL returned.
    Read, not run: nothing here makes GL refuse an upload.
  - **Comments made true** (simplification, altitude, thermo-nuclear, correctness): "pixels are
    never rewritten in place" in three places, the byte count's "including its mip chain", and
    "every upload path".
  - `get_gl_max_texture_size` for the query written out (reuse, altitude, thermo-nuclear); the
    level-count parameter dropped, which changes nothing under a linear filter (thermo-nuclear).
  - **The contract** says what is stored and not how the UI blends, that a material's textures
    are the pool's, and that a rectangle of no size is refused (simplification, altitude,
    correctness).
  - `ui.h` says a texture outlives its frame once, over the three calls that draw an image
    (altitude, thermo-nuclear).
- **Applied, the case and the arm:**
  - **One table** (thermo-nuclear, simplification): the seeded pictures are rows of `PICTURES[]`,
    drawn and said from it as `--ui-seams`' and `--ui-lines`' are, each line "x y w h seed u v".
    The arm paints them in turn on the backdrop and compares the whole region once, so the
    backdrop between the pictures is held, where only the ring round one was.
  - **A rectangle written into a texture already drawn** (correctness): `over`'s is written in
    the update hook after the first frame. Every write had come before any draw, which is not how
    pcb will use it.
  - **The write outside is observed** (correctness): GL's error is read straight after it. With
    the bounds check deleted the arm had passed: GL refuses such a write itself, and a later
    call drained its error.
  - **The backdrop is whole codes** (correctness): 0.10 put its red on a rounding tie, and it is
    held to the byte.
  - **The timing is gone** (efficiency, simplification, thermo-nuclear): nothing read it and
    every run of the arm made a 16 MB picture for it. Phase 1's numbers stand as what they are,
    the client's copy: no draw sat between a write and its `glFinish`.
  - Offsets, a multiplier and a generator nobody varied; the app's own expectation of its bytes,
    now the arm's (simplification); `rgba_bytes` (reuse).
- **Applied, the docs:** an off-grid join between two images shows up to a half of what is under
  it, not a quarter (altitude; 14.23 measured 0.497 for a quad drawn to its rect); the lifetime
  rule a bullet of the draw list; `cli-reference.md` points at the README; the roadmap's bullet
  and date line point and do not restate.
- **Skipped:**
  - **A level count in place of the flag** (thermo-nuclear; altitude and simplification would
    keep the flag): `Texture.levels` from the upload would also right the ledger for a chain cut
    short by memory, but it reaches the pool's upload, and the write's guard would rest on
    `GL_RGBA8` being nobody else's format. For when a second maker of one level comes.
  - **One helper for clamped, linear sampler state** (thermo-nuclear; reuse against): four
    policies that agree today.
  - **The app composing the picture the arm compares** (thermo-nuclear's larger move): the arm's
    twin of one function is smaller than a blit and a path argument.
  - **`pictures_` shared with `pictures.c`'s names** (reuse): nothing collides, and a collision
    would not compile.
  - **A material given such a texture** (altitude): it is copied into the material array at
    build and a later write is not seen there. The contract says a material's are the pool's;
    nothing refuses it.
  - **An image's off-grid edge mended in the UI** (altitude): a spec of its own.
- **Falsified again**, the arm being new, each put back:
  - repeat wrap with an sRGB store: 512 pixels of `clamp`, every seeded rect, 8448 pixels, and
    the half-opaque one;
  - a write a row down with the bounds check out: 892 pixels in the four written rects, and
    "outside" 0;
  - the late write skipped: the 480 pixels of `over`'s rectangle.
- **Verified**: built, no warning in cetra's sources; `--arms
  canvas-ui-pictures,canvas-ui-seams,canvas-ui-lines` and `--only gate-docs` pass.
  `texture_gpu_bytes` is as phase 1's run of `texcomp` and `clearcoat` had it.
