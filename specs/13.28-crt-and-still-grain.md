# Spec 13.28 -- grain that holds still, and a CRT

## Context
The film grain crawls in diagonal lines. The cause is one line in `tonemap_frag.glsl:730`,
`hash21(gl_FragCoord.xy + grainSeed, ...)`. The frame number is added to BOTH x and y, so each
frame is the previous frame's noise shifted one pixel diagonally, and the whole field slides
across the screen. Real engines make every frame's grain independent. Unreal, for example,
jumps a grain texture to a random offset each frame. The Purkinje rod noise
(`include/purkinje.glsl:200`) is seeded the same way and has the same crawl.

The user also wants a CRT effect for silent: a consumer TV with a slot mask, soft scanlines, a
little composite colour bleed and a slight curve with rounded dark corners, all "noticeable
but subtle". The game's own UI (the door prompt, the menus) goes through the CRT; the Cetra
debug GUI and the FPS counter do not.

silent gets grain off and CRT on. Both remain engine features, off by default.

## Phase 1 -- grain fix
1. **Read the source first.** Jarzynski and Olano, "Hash Functions for GPU Rendering" (JCGT
   2020), through pdf2md into `docs/papers`. Implement `pcg3d` from its text.
2. **An integer hash of (pixel x, pixel y, frame)** in `include/noise.glsl`, as
   `frameNoise(uvec2 pixel, uint frame)`. Every frame becomes independent noise, with nothing
   sliding. GLSL 330 has uint arithmetic.
3. **The grain calls it** with `uvec2(gl_FragCoord.xy)` and a new int uniform, the frame
   index. The luma weighting and the clamp stay as they are.
4. **Purkinje's rod noise calls it too**, on `uvec2(uv * 1024)`, so its basis stays independent
   of resolution. This moves `purkinje_night`, the one golden that evaluates it; the change is
   shown and re-baked. The float `grainSeed` uniform then has no reader and goes.
5. **The E10 rule.** AGENTS.md records "replacing the sin-fract form with an integer hash is
   REJECTED (roadmap E10)" and names grain, because "no consumer has a correct pattern to
   regress against". This crawl is that demonstrated artifact, which the row's own revive
   clause asks for. The change is scoped to grain and Purkinje. `hash21` and `hash13` and their
   other consumers (wind, foam, curl noise, tile offsets) are untouched. AGENTS.md's E10
   paragraph, its stale "zero of the 27 goldens", and the roadmap row get updated to say so.
6. **The dither is left alone.** It is static by design (spec 11.24), not crawling.
7. **Look:** silent with grain forced on, frames N and N+1 side by side plus a short
   `--screenshot-every` strip, for the user to confirm nothing crawls.

## Phase 2 -- the CRT, engine side
**Method.** Timothy Lottes' CRTS (2018, Unlicense; libretro `crt-lottes-fast.slang` and
Shadertoy MtSfRK). Before writing code, fetch its source into `docs/papers` and implement from
it.
- Rounded corners follow crt-geom's `corner()`, from its description only (crt-geom is GPL).
- The composite chroma bleed is YIQ with chroma band-limited wider than luma. That follows the
  NTSC bandwidth ratios: luma 4.2 MHz, I 1.3 MHz, Q 0.6 MHz.

**Placement:**
- When `crt_enabled`, `engine_present_frame` (`engine.c:2334`) passes an fb-sized RGBA16F
  intermediate as `postfx_run`'s `target_fbo` instead of 0.
- The debug tiles and the overlay hook (where the game UI draws) bind no framebuffer, so they
  land in it.
- The CRT then draws to framebuffer 0 between the overlay (2360) and ImGui (2364). So the game
  UI is CRT'd, while the debug GUI and the FPS counter stay sharp.
- The headless screenshot reads framebuffer 0, so it shows the CRT.
- With CRT off nothing changes: the target stays 0 and every golden stays 0 px.
- The intermediate must be exactly fb-sized, because `ui_draw.c:767` scales its scissor by
  `fb_width` and `fb_height`.

**Dither stays last (spec 11.24).**
- `ditherPattern` moves from `tonemap_frag.glsl` into `include/dither.glsl`.
- The tonemap skips it when CRT is on, and the CRT pass ends with it.
- It stays static, with no frame term.

**Passes** (`crt.c/h`, made on first use and latched off on failure, copying
`create_glare` / `glare_run` at `glare.c:264` and `postfx.c:3934`):
1. **`crt_resample_frag`.** The finished frame becomes a virtual-resolution signal:
   `crt_lines` tall (default 480), width from the aspect ratio.
   - Area-filtered from the full-resolution intermediate.
   - Decoded to linear with the tonemap's own `pow(2.2)` encode, not sRGB.
   - Stored RGBA16F.
   - Cheap, because it runs at about 854x480.
2. **`crt_frag`**, per output pixel:
   1. Lottes' `Warp` on the screen position, scaled by `crt_curvature`; black past the tube,
      with rounded corners.
   2. Two scanlines times a 4-tap horizontal filter: CRTS's windowed-cosine scanline, and its
      `exp2(blur*d^2)` horizontal filter.
   3. Luma and chroma taken through YIQ, with chroma blurred wider by `crt_bleed`.
   4. A darken-only slot mask in output-pixel units, its period scaled with output height.
   5. CRTS's exposure lift, so the picture keeps its mid-grey.
   6. Re-encode, then dither.

**Settings** (plain fields under PostFX's SETTINGS banner, all off by default):
- `crt_enabled`
- `crt_lines` (480)
- `crt_scanlines`, `crt_mask`, `crt_curvature`, `crt_bleed` (each 0..1)

The defaults are "subtle" values, set during the look. Scanlines and mask fade out when fewer
than about 2 output pixels fall on each virtual line, so a small window gets no moire.

`create_post_program` gets the two new programs (`program.c`), and `free_postfx` frees the
object.

**Look.** In the render app on a fixture, at the three window sizes, and in silent through a
temporary flag. Iterate on the picture with the user until it is signed off.

## Phase 4 -- plumbing, gates, docs
- **Config rows** (`config_snapshot.c`, `postfx.crt.*`) and **GUI controls** (`gui.c`,
  Finishing, a "CRT" effect group). The member names are `crt_*`, so `config-coverage` matches
  them.
- **Render app flags** (`render_args.h`, `render.c`): `--crt`, `--crt-lines`,
  `--crt-scanlines`, `--crt-mask`, `--crt-curvature`, `--crt-bleed`, parsed in `--dither`'s
  validated `strtod` form, with `--help` text.
- **Gate group `grain`** (no group covers grain today):
  - `grain-still`: the crawl metric about 0, against about 1 for the old seeding. This is the
    falsifier.
  - `grain-amount`: the noise field's spread at mid-grey matches `grain_strength`.
- **Gate group `crt`:**
  - `crt-off`: fields set but disabled renders 0 px from defaults.
  - `crt-lines`: a flat field's vertical luminance has its period at output height over
    `crt_lines`, and none with scanlines at 0.
  - `crt-mean`: the mean luminance stays within a few per cent of CRT off.
  - `crt-curve`: the corners are black and the centre does not move.
  - `crt-dither-last`: the output's quantization error is TPDF, not banding.
  - Each arm is falsified by hand.
- **Docs:**
  - AGENTS.md: the PostFX chain line (CRT after the overlay), the Defaults line, the shader
    inventory, the finishing-order rule (with CRT on, the dither lives in the CRT pass), the
    E10 paragraph, and silent's row.
  - `docs/shader-subsystems.md`: CRT and grain sections.
  - `docs/cli-reference.md`: the render app's CRT flags and silent's `--no-crt`.
