# A shore that dissolves, a beach that remembers, and sand that dries

## Context

11.44 shipped a surf. It arrives, it breaks, it runs up — and it still reads wrong in two
specific ways the eye catches immediately:

- **The swash is a solid line.** `water_frag.glsl:223` is the whole shore band:
  `WATER_SHORE_FOAM = 0.92`, resting at `WATER_SHORE_FOAM_REST = 0.3`. A scalar strength
  becomes a colour. Real whitewater is a *lacework* that fragments into clumps as it thins.
- **The beach forgets.** Foam accumulates per **cascade texel**, so it tiles the world and
  has one decay rate. Nothing is left on the sand behind a retreating wave.

And the sand itself never changes: `ground_beach_color` (`apps/tree/src/ground.c:147`) paints
a fixed wet band below `GROUND_WET_SAND_M` 0.18 m, baked once into vertex colour at mesh build
(`:281`, `GL_STATIC_DRAW`). `ground.h:143` already says what is missing, in its own words:
*"what is wet ABOVE it at any moment is the swash's business, not a band's."*

**What prompted this plan.** First the wet-sand ask; then `github.com/tompng/gpuocean` as a
reference, whose shore looks right. It was cloned and read in full (2,377 lines). The gap is
not the wave model — it is a solver, a foam *pattern*, and two decay rates.

**Outcome:** a surf line that erodes into clumps instead of fading as a bar; foam the beach
keeps until the next wave eats it; crest foam on the Gerstner path for the first time; sand
that darkens where the swash reached and dries behind it; and, last, a real swash film.

---

## What the reference does that we do not

| | gpuocean | cetra today |
|---|---|---|
| Swash | 256 columns x 64 Lagrangian nodes, shallow-water pressure form, 4 substeps/frame (`chain.js`) | `shoreRunup()` closed form, stateless |
| Foam shape | noise pattern eroded by a **rising threshold** — thin parts vanish first | foam value -> foam colour |
| Foam onset | one-pole rise, `FOAM_RISE = 0.08 s` | instantaneous |
| Foam decay | `foamLife` 4 s, **and 0.5 s where a wave floods over it** | one rate |
| Foam frame | world-space for waves, **(band, column) material space** for the film; only the MASKS blend | one frame, per cascade texel |
| Breaking | Jacobian **and** `H/h` depth-limited | Jacobian only -> FFT-only crest foam |
| Wet sand | none — the wet look is *real water* still on the beach | a painted band |
| Shoreline | authored analytic curve + `colT()` arclength | none; `WaterHeightFn` is opaque |

Two quotes worth carrying into the code, because both are traps:

> *"A linear spring law is NOT usable here… the pressure form pins the equilibrium to
> 'surface flat' uniquely."* — `chain.js:6`

> *"each erodes its own pattern lookup in its own frame and only the resulting MASKS blend.
> Eroding a single pattern at blended coordinates smears it into streaks."* — `ocean.wgsl:373`

## P1 — foam is an eroded pattern, not a strength

The single highest look-per-cost item, and it needs no solver.

Three mechanisms, all in `water_frag.glsl` where the foam is composited:

```glsl
mask = smoothstep(0.0, EDGE, pattern - (1.05 - 1.15 * acc));   // erode from the thin parts
acc  = mix(gen, prevAcc, foamRise);                             // ~0.1 s onset
pat  = mix(patFine, patCoarse, 1.0 - smoothstep(a, b, stretch)); // stop streaks shrinking
```

**The sampler problem, and its answer.** `water_frag` is at **16/16 declared samplers** — the
project's Wall 1 — so a foam pattern texture has nowhere to bind. `include/noise.glsl` is only
interleaved-gradient (a screen-space dither, wrong for this) and the cloud noise is a CPU-baked
texture. So the pattern is **procedural ALU**: a new `include/foam_pattern.glsl` with a hash and
a 2-octave value noise, sampled in the shore band's own coordinates. Costs arithmetic instead
of a unit, which is the trade this program has to make.

The rise term needs the previous accumulation, which `water_foam_frag.glsl` already keeps
(`foamHistoryAvailable`, `foamDecay`) — this is a second use of an existing history, not a new
target.

**Bar:** both water goldens are Gerstner with no bed and no crest foam, so they should move
**0 px**. `beach_fixture` and `water_fixture`'s shore band move and should. New arm
`beach-foam-clumps`: the foam mask's connected-component count rises as the band decays,
where a solid bar's would stay at 1.

## P2 — the breaking criterion that is not the Jacobian

```glsl
genSurf = smoothstep(0.55, 0.9, waveHeight / depth) * smoothstep(0.0, 0.5, depth);
gen     = max(genJacobian, genSurf);
```

Depth-limited breaking (`H/h`) does not care which wave model made the height, so **this gives
the Gerstner path crest foam for the first time**. CLAUDE.md currently records crest foam as
FFT-only *by construction* because the Gerstner steepness is clamped so its mapping cannot
compress — that sentence changes with this phase, and the docs go with it.

**Bar:** FFT frames barely move (the Jacobian already fires there). Gerstner frames gain foam
where the bed is shallow — which is the point. `water-crest-foam` may need its FFT-only
precondition relaxed; if an arm asserts Gerstner has no crest foam, that arm was asserting the
limitation, not the behaviour.

## P3 — foam the beach keeps

Two decay rates, selected by whether water is over the foam *right now*:

```glsl
swallowed = smoothstep(...,  edge - h);          // shoreRunup() already gives edge
decay     = mix(foamDecay, foamDecaySwallow, swallowed);
```

Slow on drying sand (seconds), fast where the next wave floods it (sub-second). The test is
nearly free because `shoreRunup().edge` is exactly "where the water is", and `shore.glsl`
already publishes it with no sampler.

`--no-water-foam-history` stays the bisect lever. **Bar:** a new arm `beach-foam-persist`
reading foam above the waterline at two frames a half-period apart — it must survive the
retreat and be erased by the next arrival.

## P4 — wet sand with a memory (the original ask)

March back ~3 primary periods in taps of `T/3`, **accumulating** rather than taking a max:

```
h = WorldPos.y - waterLevel
for k in 0..N-1:
    e     = shoreRunup(WorldPos.xz, time - k*dt).edge
    cover = 1 - smoothstep(-s, +s, h - e)
    wet   = 1 - (1 - wet)  * (1 - cover * decaySlow(k))
    film  = 1 - (1 - film) * (1 - cover * decayFast(k))
wet = max(wet, waterTable(h))
```

Accumulation is what makes history legible: the lower beach, hit by every wave, saturates dark;
the upper beach, hit by one in twenty, stays barely damp. A max gives a step. The water-table
floor stops the lower beach flickering dry between waves.

**Shading, from Lagarde rather than from guesses:**

- **Porosity darkening** `Kd *= (1 - alpha * Gp)`, alpha ~0.35–0.45 (inside Lagarde's stated
  25–50% band for natural materials).
- **`F0 -> 0.02` and flatten the normal toward `Ng`.** A water layer's air/water interface is
  *less* reflective than sand's 0.04 — the surface reads shinier because it goes **smooth**.
- **The hue shift.** Compute the Beer-Lambert number FIRST: water's `(0.0035, 0.0004, 0)` per cm
  over a 0.1–1 mm film is `exp(-0.0007) ~ 0.9993`, i.e. nothing. This session already shipped and
  reverted exactly that mistake once (the Cox-Munk capillary term, measured to zero). Use the
  mechanism that actually causes it — Lekner-Dorf internal reflection, `a_wet ~ a_dry^p`, p > 1 —
  which saturates correctly and composes with the porosity term.
- **Two-phase drying**: fast film drain (seconds), slow pore evaporation (tens of seconds).
  The shape is right per the TVBRDF work; the constants start eyeballed and are flagged as such.

**Zero new samplers.** `shoreRunup` is a pure function of (p, t) over scalar uniforms — that is
the whole reason `shore.glsl` exists (P0, landed as `3fae9ad`). `pbr_frag` needs one line,
`uniform float time;` — `render.c:348` already publishes it per program switch; the fragment
stage simply never declared it.

**Cost control.** Analytic ceiling `edge <= 1.35 * r2 * upm` is a uniform-computable scalar, so
dry sand runs no taps. Taps share train evaluations: `swPrev(t_k) = sw(t_k - T)`, which at
`dt = T/3` is `sw(t_{k+3})` — N taps cost N+3 evaluations, not 2N.

**Gating.** `Material.shore_wetness` defaulting to 0, in the shape of `wind_response`
(`material.h:119`), uploaded at `render.c:145-270`. Shore floats published by a new
`water_bind_shore()` from the program-switch block (`render.c:407-422`). `--no-water-wetness`
is the exact pre-change frame. **Nothing in the corpus opts in, so all 24 goldens stay 0 px.**

**tree wires it up** (`tree.c:1254-1263`, `:1273-1282`): island material, seabed material *and*
the shore boulders — the first two share `ground_beach_color` and would seam at the rim
otherwise. `ground_beach_color` drops `GROUND_SAND_WET` / `GROUND_WET_SAND_M` from the
above-water side and keeps the submerged pale ramp; note it has **four call sites**
(`ground.c:232, :281, :367`), not one. Re-measure whether the 128 rings (`tree.c:276`) can come
back down now the band is per-pixel. Fix two stale comments found in passing: `tree.c:270`
(0.35 m of a 2.16 m rise against defines of 0.18/1.70) and `tree.c:239` (slope 0.145 against
`GROUND_BEACH_SLOPE` 0.09).

**The fixture must be able to see it.** `beach_fixture.gltf` authors the dome emissive over a
**black** base colour (`gen_beach_fixture.py:132-142`), so an albedo change is invisible today.
Regenerate with a lit sand `baseColorFactor` alongside the emissive; author `shoreWetness`
through the `.cscn` materials block (one row in `cscene_apply.c`'s table). Arms: `beach-wet`
(swash band darker, **dry crown 0 px** — the half that matters), `beach-wet-history`
(brightness rises monotonically up three boxes; a band gives two levels, a memory gives a ramp),
`beach-wet-moves` (px between frames 30 and 44 above a floor).

## P5 — the shoreline, extracted from the bed

The enabler for P6 and P7, and the object that has been missing all along.

`_water_bake_bed` (`water.c:488`) already sweeps 256² on the CPU with the height callback. Add a
pass that **marches the zero level set** and emits a shoreline polyline: per column a world
position, a landward normal, and a cumulative **arc length**. That is exactly what `chain.js`
gets from its authored `shoreX(z)` curve and `colT()` — except derived from whatever
`WaterHeightFn` the app supplied, so it works for tree's wobbly island, forest's terrain and the
dome fixture without any of them declaring a shape.

Invalidated with the bed (level / extent / units, `water.c:496-498`) plus anything that moves
the bed itself.

**This is also the honest answer to the A1 question that stalled Part A.** The alongshore phase
refraction needs is an arc length along the shore; the shader had no line for it; this is the
line. Whether to spend it on wave phase is a later call — see Deferred.

## P6 — foam in the film's own frame

With P5's polyline, foam gets a `(band, column)` material coordinate and rides the swash instead
of sitting in world space. Per the reference's hard-won note, wave foam and film foam **erode
their own pattern in their own frame and only the resulting masks blend** — blending the
coordinates smears the pattern into streaks across the handover.

This also removes the per-cascade-texel tiling that forced every beach gate arm onto Gerstner.

## P7 — the swash film

A Lagrangian chain per shoreline column, ported to C against P5's polyline:

- Per segment, conserved rest volume; depth is `vol / length`.
- `eta = terrain + vol/length + shock viscosity`, `a = -g * d(eta)/dx`.
- **Pressure form, never a linear spring** — a preloaded linear chain has degenerate equilibria
  and settles into piled-up states. This is recorded because it is the failure mode.
- Friction ramping landward; CFL caps on acceleration and velocity; alongshore smoothing.
- Seaward node driven by the wave's orbital displacement at a junction isobath; the film's rest
  state cancels the terrain rise so a resting film is the flat sea surface.

`shoreRunup().edge` becomes the **fallback** rather than the only answer: no bed, no polyline, or
the film off, and the closed form still runs. That keeps every existing frame reachable and makes
this phase revertible by a flag rather than by a revert.

Everything built on `edge` — P3's swallow test and P4's wet sand — inherits the simulated tip for
free, because both read the same value.

## Deferred, with reasons

- **A1, refraction's phase.** Snell conserves `k*sin(theta)`, and the code already computes that
  magnitude (`OCEAN_SURF_OBLIQUE` is `sin(theta)`). Only the *direction* is wrong, and fixing it
  needs an alongshore arc length. Worse, a per-point `kv` breaks the analytic derivative:
  `oceanSurfTrains` takes the phase gradient as `om*dTau - kv`, which assumes `kv` is constant in
  p, and the derivative feeds the normal. And `perp(shoreward)` degenerates — on a round island
  `p` is radial, so `dot(p, perp(s)) == 0` and the whole shoreline pulses in unison. Fundamentally
  a curved shore has no single-valued alongshore phase at constant wavenumber
  (`curl(t_hat) = div(n_hat) =` the shoreline's curvature), and where rays cross the phase is
  genuinely multivalued. **Revisit only after P5**, which supplies the arc length.
- **A2, refractive focusing.** Needs the bed's *second* derivative. `ocean.glsl` already records
  what happened when a per-point quantity was taken off tree's wobbly bed gradient: it *"printed
  every crest as a comb of humps at the wobble's period."* Curvature is noisier still, and the
  dome fixture is a surface of revolution where focusing is azimuthally uniform and therefore
  invisible. If it is built, bake it (the bed texture's `.a` is free) rather than sampling it.
- **A3, the Iribarren breaker type.** Clean and cheap, but it is calibrated to reproduce the
  present look at the present sea state, so it moves nothing until the sea state does. Worth
  doing; not worth doing before any of the above.
