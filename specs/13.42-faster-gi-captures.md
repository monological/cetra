# Spec 13.42: faster GI captures

## Context

Silent's home GI volume takes 792 probe captures before it is converged. With classification on,
an opening-sweep probe costs 12 face renders (6 shaded, 6 back-face depth) and 3 projections. The
mansion adds 847 more probes, and each launch pays for all of it again. The user asked for all
four speed-ups:

1. converged lighting cached on disk;
2. small objects cut from GI captures;
3. all six faces of a probe drawn in one pass;
4. fewer probes.

Options 1 and 2 are kept. Options 3 and 4 are trials: each has a pass test written down before it
is built, and is backed out if it fails.

What the exploration found, which shapes the plan:

- **Most per-face work is overhead, not drawing.**
  - `SubmitState` is reset inside `engine_render_scene` (`render.c:1727`), so every face re-runs
    each program's ~35-uniform bind block and each material's ~60-uniform block. Each uniform set
    is also a uthash string lookup (`uniform.c:65-77`).
  - The whole draw list is walked, and every item's bounds recomputed, on every face
    (`draw_list.c:446-515`).
  - Every probe creates and deletes two FBOs (`render.c:2253, 2317`) and calls `glFinish`
    whenever the budget is set (`render.c:2057-2070`).
- **The fragment side does not depend on the face in a GI capture.**
  - The light list is shared at 16 px (`light_cluster.c:897-935`).
  - Probe specular is dead under `captureDiffuseOnly`, the cascade count is 1, and `camPos` is
    the probe for all six faces.
  - Only the view and projection change per face. That is what makes a single layered pass
    possible.
- **A capture is not a pure function today, which blocks a disk cache.**
  - LOD comes from the main camera (`render.c:2093-2100`).
  - Lights animate between bursts: candles (`fire.c:774-804`), the failing tube
    (`lights.c:302-304`), the TV (`tv.c:230-231`), the basement bulb (`basement.c:704-709`) and
    the flashlight.
  - The clock's pendulum and hands move every frame.
  - The cook's charter forbids caching captures for exactly this reason (`cook.h:37-41`).
- **Classification lives in the irradiance alpha.** Kept texels are portable between atlas
  slots, and an upload path already exists (`residency.c:61-68`, `gi_volume.c:458-466`). A disk
  cache is a new source for `kept`, not a new path.

Intended outcome: a measured sweep time per probe and per volume before and after each option; a
second launch of silent that restores both volumes and the reflection probes from disk; and the
picture unchanged except where the user has looked at a change and accepted it.

## Phase 0: the instrument and the baseline

- Add `Engine.capture_timing`, a plain SETTINGS field. At each volume's convergence it prints:
  ```
  gi-timing volume=<i> probes= frames= ms= setup-ms= shaded-ms= classify-ms= project-ms= draws= tris=
  ```
  - The setup time is `scene_capture_begin`, including its shadow pass.
  - The profiler is suspended inside captures, so this is the only breakdown available.
  - The engine has a timing mode that brackets each part with `glFinish`, giving wall time per
    part. Comparing it with a run without the `glFinish` calls shows how much is CPU
    submission.
  - The render app takes `--capture-timing`. Silent's `--startup-ms` turns it on.
- Add a per-probe histogram of what was drawn, by projected size on a 16 px face. Option 2's gain
  depends on it: silent's kit batches geometry per material per cell, so it may have few small
  items.
- Silent's `--startup-ms` also prints each volume's atlas digest (`gi_world_probe_print`). Later
  phases use it as the determinism check.
- **Baseline:** silent `-x -f 300 --mute --startup-ms`, at budget 0 and at
  `--capture-budget-ms 100`, two runs each. Also profile CPU hot spots with `sample` on a headless
  run (the scratchpad's `sample_load.sh`). Record everything in the spec.

## Phase 1: option 3a, one pass of bookkeeping per probe (trial)

This is the CPU half of "one pass", and it has no geometry shader.

- **One cull walk per probe.**
  - Each item's bounds are computed once per burst and cached, since nothing moves inside a burst.
  - Items are kept if they meet the probe's cube (the union of the six frusta).
  - Each face then tests only those survivors against its own frustum.
- **Bind state across faces.** `SubmitState` lives with the capture burst, not inside
  `engine_render_scene`.
  - Program and material blocks run once per burst.
  - Only `view`, `projection`, `uCurrViewProjNoJitter` and `camPos` are re-uploaded per face or
    per probe.
  - The skybox, sky background and catcher bind their own programs and units, so they must
    invalidate exactly what they touch.
- **One FBO per burst**, owned by the burst rather than created and deleted for each call.
- **Pass test:**
  - the home volume's headless sweep time drops at least 15% below baseline, beyond the noise
    floor;
  - `--only lighting-stream`, `--only probe-set` and `--only emissive` pass;
  - the `cornell_box` golden stays at 0 px.
  - The arithmetic is unchanged, so anything other than 0 px is a bug.
- If it fails, revert it.

## Phase 2: option 3b, six faces in one layered draw (trial)

- **Geometry stage.** A new `pbr_capture_geo.glsl`, built with a GLSL 330 loop (no version mixing):
  - For each face k, it skips the triangle if it lies wholly outside one of face k's clip planes.
  - Otherwise it emits the triangle with `gl_Layer = k`, and `ViewPos` and `gl_Position` derived
    from `WorldPos` through `uFaceView[k]`. Every other varying passes through unchanged, with
    matching `centroid` and `flat` qualifiers.
  - `max_vertices` is 18, at about 44 components each.
- **Programs.** A layered build of each lit-surface variant:
  - `_create_pbr_variant` gains a layered argument and passes the geometry source to
    `create_program_from_source`, which already accepts one (`program.c:150-185`).
  - The name takes a suffix (`pbr-<mask>[-h<id>]-l`), so it cannot collide.
  - A hooked material gets a layered build of its own variant.
- **Target.** The cube colour and depth are attached layered (`glFramebufferTexture`); one clear
  covers all six faces.
- **Draw order.**
  1. The opaque pass, layered.
  2. Per face, with face i re-attached: the skybox or sky background, then the catcher.
  3. The blend and transmissive lanes, layered.
- **Fallbacks.** Lines, points and non-PBR programs are drawn per face. Reflection probes are
  unchanged: they render one face per call.
- **Trial order.**
  1. First, the classification depth pass alone: depth-only, the cheapest program. Its pass test:
     the classify part drops at least 30% against phase 1.
  2. Only then, the shaded pass.
- **Pass test, overall:**
  - the sweep time drops a further 20% against phase 1;
  - the atlas matches phase 1 to within 2^-10 relative per texel;
  - silent's views are within the noise floor;
  - `lighting-stream` passes.
  - If `cornell_box` moves, show the diff. Rounding in the vertex stage is a re-bake (memory:
    *glsl-branch-not-byte-identical*).
- **Abandon** if either test fails; the six-pass path stays.
- **Risk.** Apple's GL runs over Metal, which has no geometry shaders, so the emulation may be
  slow. That is why the depth-only trial comes first.

## Phase 3: option 2, captures draw what a 16-pixel face can see (kept)

- **LOD from the probe.**
  - A capture picks each survivor's LOD from the probe's position, with `select_lod`'s rule
    (`draw_list.c:228-263`), scaled by the face's pixel size against the main view's.
  - Run joining uses that capture LOD.
  - This also removes the camera from the capture's inputs, which phase 5 needs.
- **Small-object cut.**
  - A survivor whose projected diameter on the face is under `GIWorld.cull_pixels` pixels is
    skipped.
  - Never skipped: emissive materials, and nodes with a new inherited `SceneNode.capture_always`
    (the same pattern as `capture_hidden`, `draw_list.c:338, 376-377`).
  - The engine default is 0, which leaves every existing GI scene unchanged.
  - The shaded pass and the classification pass use the same survivors, so the wall test cannot
    see something the shaded pass skipped.
  - Applies to GI captures only. Reflection probes are 1024 px mirrors.
- **The user looks.** Silent's views at `cull_pixels` 0, 0.5, 1 and 2, and with LOD from the probe
  against LOD from the camera, opened in Preview with the time saved for each. Silent sets the
  value the user picks.
- **Gates:** `--only lighting-stream`, plus the `draw-distance`, `lod` and `cull` groups.

## Phase 3b: option 5, a capture draws the chunks of a big mesh it can see (added)

Added after phase 0 measured where the time goes, at the user's request. Silent's `world` kit
draws one mesh per material across the whole street, 28,000 to 136,000 triangles each, and
every probe stands inside their bounds, so every face of every probe draws all of each: about
600,000 triangles a face, and the sweep is GPU-bound. A probe reaches 26 m.

- **Chunks.** A large mesh -- 4,096 triangles or more, at least 16 m across -- carries its
  level-0 triangles a second time, sorted into chunks: by the 4 m cell each triangle's centroid
  falls in, each chunk a contiguous range of the index buffer with its own object-space box (the
  union of its triangles', so a long triangle widens its chunk rather than escaping it). The copy
  is appended to the mesh's own element buffer, so its VAO draws it; the camera, the shadows and
  everything else keep drawing the original indices in the original order, and their pixels
  cannot move. Built once, in `scene_capture_begin`, for the meshes a capture is about to draw:
  an app with no captures pays nothing, at load or ever.
- **Only where the box is the truth.** A mesh whose vertices something moves -- a pose, wind, the
  CDLOD morph, an offset hook, a coat's shells -- is drawn whole, as now: its chunk boxes would
  not hold what it draws. Nor one whose level is not 0, nor one drawn instanced (a chunked mesh
  draws one object a run in a capture).
- **The draw.** In a capture face, an item with chunks tests each chunk's box against the face's
  frustum, far plane included, and draws the ones that pass with one `glMultiDrawElements`,
  neighbouring chunks merged into one range. The wall test draws the same chunks, since it culls
  through the same view.
- **What can move.** A capture face draws the chunked copy's order, not the original's, so two
  surfaces at exactly equal depth may resolve the other way in a capture: the home's digest
  moves, and silent's six views of the house are compared as phase 3's were.
- **Measured** with `--capture-timing` and `--startup-ms`, headless, twice: triangles a face, the
  sweep's GPU wall, and `lit`, against phase 3. And windowed-like, `--capture-budget-ms 100
  --loading-screen`.
- **Gates:** `--only lighting-stream`, `probe-set`, `emissive`, `cull`, `lod`; `cornell_box`'s
  golden.

## Phase 4: captures see the scene at rest (prerequisite for option 1)

- **The hook.** `scene_set_capture_rest(scene, fn, user)`.
  - `scene_capture_begin` calls `fn(user, true)` before it derives panels, resolves variants or
    draws shadows.
  - `scene_capture_end` calls `fn(user, false)`.
  - The render clock is already frozen at 0 in a capture (`render.c:2072-2127`); this extends the
    same rule to what the CPU animates.
- **Fires.** The engine holds its own fires at rest for a burst: the flame's `mean_intensity`, its
  colour, and its centroid at the loop's mean height (`fire.h:144-146, 251`).
- **Silent's rest function:**
  - the failing tube at its nits;
  - the bulb at full;
  - the TV's glass and glow at the picture's long-run mean;
  - the flashlight off;
  - on `false`, it drives everything again from the current time.
- **Silent's moving parts:** the clock's pendulum and hands become `capture_hidden`, since they
  move every frame.
- **Test:** silent's atlas digests at budget 0 and at `--capture-budget-ms 100` must match, and so
  must two runs of each. Captures land on different frames in those runs, so matching digests
  mean nothing that moves is captured.
- **The user looks** at the GI near the tube, the TV and the candles, before and after. A probe
  captured mid-flicker no longer bakes a dark patch in.

## Phase 5: option 1, converged lighting cached on disk (kept)

- **Charter.** Amend `cook.h`. A GI volume's opening sweep and a reflection probe's column may be
  cooked, because phases 3 and 4 make a capture a pure function of inputs that can be folded into
  a key.
- **Content identities that stay stable across runs:**
  - a mesh content hash, computed lazily and cached against `upload_count`;
  - a texture's content key, kept from the `texture-mips` cook key it already computes
    (`texture.c:976-1058`). A texture without one makes the scene unkeyable, and the sweep runs
    live (the `fold_terrain_content` precedent, `forest.c:1044-1063`).
- **The key**, `gi-volume/1`, folds:
  - an engine build digest, generated at build time over `cetra/src` and `cetra/shaders`, so any
    engine change misses;
  - the GL vendor, renderer and version strings;
  - the volume's grid and the capture constants;
  - the settings of the engine, scene, shadow, sky, IBL, rain and wind, by walking
    `config_snapshot`'s one descriptor table a third way (`config_snapshot_fold`);
  - every light, at rest;
  - every draw item within reach that is not capture-hidden: its world transform, mesh hash, LOD
    chain, lane and flags, material rows, texture keys, and its hook's source and parameters;
  - decals and roads;
  - the keys of the neighbour volumes that are loaded.
- **Flow.**
  - When a volume becomes due for its opening sweep: build the key, then fetch.
  - On a hit: seed `kept`, take the existing UPLOAD path, and set `dirty_count = 0`
    (`gi_volume.c:46-67` arms it at creation).
  - On a miss: sweep. At the end, build the key again. If it is equal, read the rectangle back
    (`lighting_atlas_keep`) and `cook_store` it. If it is not, log `result=unstable` naming the
    first class that differed.
- **Reflection probes**, `probe-column/1`: the same scene fold, plus the probe's parameters, plus
  the keys of the GI volumes its box touches. Stored at `publish()` (`probe_set.c:172-186`),
  seeded through the upload path already at `probe_set.c:214-220`. That is about 4.3 MB a probe,
  47 MB for silent, and `cooked/` syncs through Dropbox.
- **Opt-in:** `GIWorld.cook` and `ProbeSet.cook` are SETTINGS, default false. Silent turns them on;
  the render app takes `--gi-cook`. The gate suite shares one cook directory (`gates.py:31162`), so
  being on by default would break `stream-paced`, `stream-once` and `gpu-gated`.
- **Gate group `gi-cook`** on `stream_rooms.cscn`, each arm with its own cook directory:
  - `gi-cook-hit`: the second run captures 0 probes and its frame is 0 px against the first run's.
  - `gi-cook-pure`: two cold runs, and a budgeted against an unbudgeted run, give the same key and
    the same digest.
  - `gi-cook-miss`: each class of perturbation misses — a node moved, a material parameter, a
    light, a sky setting, a texture's bytes.
  - `gi-cook-unstable`: a node moving during the sweep is not stored.
  - `probe-cook-hit`.
  Also run `--only cook`; `cook-recipe` checks recipe lengths.
- **Silent:** time to `lit` on a second launch, recorded beside the first.

## As built

### Phase 0: the instrument and the baseline

- `Engine.capture_timing` (SETTINGS) and `Engine.capture_submit` (ENGINE-OWNED, the count a timed
  capture's draw sites add to; `_submit_stats` in `render.c` is the one place a draw site asks
  where to count). Each GI volume keeps a `GISweepTiming` and prints three rows as it converges:
  `gi-timing` (each part as `cpu/wall` ms, with the faces' draws and triangles), `gi-sizes` (what
  each probe had in reach, by its diameter on a 16-pixel face, as `items/triangles`) and
  `gi-heavy` (the eight heaviest items in reach of the volume's centre, as
  `name:triangles@level/levels:pixels`). `draw_item_projected` (draw_list.c) is the measure,
  radius over distance, the one LOD reads.
- The render app takes `--capture-timing`; silent takes `--capture-timing` too, and its
  `--startup-ms` now prints the GI volumes' digests after the `lit` row. Headless, `lit` and `up`
  land on the same frame and the `lit` row was never printed; both are now.
- Baseline, silent headless, debug build, GPU otherwise idle:

  | Run | `lit` | Home digest |
  |---|---|---|
  | untimed, budget 0 | 13,272 ms | `6f33430b` |
  | untimed, budget 0 | 13,336 ms | `6f33430b` |
  | budget 100 ms (as a window loads) | 29,535 ms, 161 frames | `a0ef52e4` |
  | budget 100 ms | 30,944 ms, 167 frames | `fc66a7be` |
  | timed, budget 0 | 21,511 ms | `6f33430b` |

  The timed sweep: setup 31 ms; shaded faces 3,929 ms CPU / 10,574 ms wall; classification
  faces 3,709 / 6,025; projections 67 / 681. 589,181 draws and 5.76 billion triangles over 792
  probes, about 600,000 a face.
- **What the numbers say.**
  - The sweep is GPU-bound: the shaded faces' wall is 2.7 times their CPU.
  - The triangles are not small things. Items under 2 px on a face are 10 million of the 5.76
    billion; items 8 px and over are 574 million of the 677 million in reach.
  - The heaviest items in reach are silent's `world` kit meshes, one per material spanning the
    street, 28,000 to 136,000 triangles each, with no LOD chain, and every probe sits inside their
    bounds -- so every face of every probe shades every one of their vertices.
  - The budgeted runs' digests differ from each other and from the unbudgeted one: what a capture
    sees depends on the frame it lands in. That is phase 4's premise, measured.
- **The order changes.** Option 3b (the layered draw) is the lever this measurement points at: it
  shades a street-spanning mesh's vertices once a probe instead of six times. 3a's savings are CPU,
  which the GPU hides while it is the bottleneck, and the layered pass brings them anyway (one
  walk, one bind block a probe). So phase 2's trial runs first. 3a runs only if 3b is abandoned.
  Option 2's small-object cut has little to cut in silent; LOD from the probe touches nothing
  here (the heavy meshes have no chain) but phase 5 still needs it for the key.

### Phase 1: option 3b, the layered draw -- abandoned

- **Built:** `pbr_capture_geo.glsl` between pbr_vert and pbr_frag in a layered build of each
  lit-surface variant (pbr_vert's outputs renamed under `CETRA_LAYERED`, a `-l` name suffix, a
  `layered` pointer on the variant), the cube colour and depth attached layered, and the
  classification's back-face depth drawn once a probe against the cube the six faces reach.
- **Correct:** the home volume's digest was `6f33430b` both ways, every run.
- **Slower, in both forms the geometry stage can take** (timed, classification faces, CPU / wall):

  | | CPU | wall |
  |---|---|---|
  | a face at a time (phase 0) | 3,709 ms | 6,025 ms |
  | layered, one invocation looping six faces | 18,723 ms | 20,469 ms |
  | layered, six invocations (`invocations = 6`) | 13,115 ms | 14,353 ms |

  The draws fell by two thirds and the CPU time rose five times.
- **Why, from a `sample` of the layered sweep:** every draw through a geometry stage goes down
  Apple's emulation, `GLDContextRec::startTransformFeedbackComputeCommandEncoderIfNeeded`, which
  opens a compute "preprocessing" command buffer for it; most of the main thread's time is
  `-[_MTLCommandBuffer initWithQueue:]` waiting on a semaphore for one. Metal has no geometry stage
  and this driver pays for one per draw. Nothing in the shader can change that.
- **Abandoned**, as the test written beforehand said: the diff is not kept. The approach is sound
  where a geometry stage (or a vertex-stage layer) is native, which is not this platform.

### Phase 1, again: option 3a, one pass of bookkeeping per probe -- not built

A `sample` of the face-at-a-time sweep says where its CPU goes, and that bounds what 3a can save
without building it. Of the shaded faces' 3,282 samples:

- **1,187 are the driver's draw calls** (`glDrawElements`), one per item per face. 3a keeps them.
- **888 are the material block** (`_update_program_material_uniforms`). silent's kit draws one
  mesh per material, so the material changes at every draw: keeping the tracking state across a
  probe's faces saves the first upload a face and no more.
- **426 are the cull** (`draw_item_visible` and the run it forms).
- **About 150 are framebuffer state** (`gleUpdateDrawFramebufferState` under each face's clear),
  from attaching a new cube face.
- The per-program block is about 100.

The plan's 3a -- state kept across faces, one framebuffer for the burst -- reaches the last two,
under 5% of the capture's CPU. Drawing the six faces into one strip with a viewport each, item by
item, would run each material block once a probe and attach once, about a quarter of the CPU.
But headless the sweep is GPU-bound (an untimed sweep takes 11.3 s against 7.7 s of CPU), so that
saves nothing there, and paced as a window paces it, CPU and GPU in series, it is about a tenth:
under the 15% the test asked for, either way. What the numbers point at instead is the GPU's
triangles, which neither form of option 3 reduces.

### Phase 3: option 2, what a 16-pixel face can see

- **LOD from the probe.** `scene_capture_faces` builds the list from the camera first (so a node's
  draw distance stays the camera's), then `draw_list_select_lod` picks every item's level from the
  capture point, at a bias of `face_size / (2 * 935)` -- a face read as a 1080-line, 60-degree view
  -- and puts the camera's levels back as it restores the camera (`_camera_lod`). Silent's home:
  5.765 billion triangles to 5.709, draws 589,181 to 576,981, and **0 px** in six views of the house
  (kitchen, living room, the hall twice, bathroom, basement). The volume's digest moves
  (`6f33430b` to `af70173e`), below an 8-bit pixel.
- **The cut.** `GIWorld.cull_pixels` (0, the default, takes everything): a GI capture leaves out an
  item whose bound spans fewer pixels than that across a face, through `CullView.min_projected`,
  set in `_scene_pass_prepare` for an IRRADIANCE capture only, so the shaded faces and the wall
  test leave out the same. Never cut: an emitter, or anything under a node set `capture_always`
