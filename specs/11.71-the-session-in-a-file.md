# 11.71 — the session in a file: a JSON config snapshot you can hand to someone else

## Context

There is one "tell me what I'm looking at" affordance in the whole engine: the **Print Camera**
button (`gui.c:1049-1061`), which emits a 13-number CLI fragment. Everything else a session
accumulates — ~185 GUI controls across PostFX, Engine, Scene subsystems and the camera — is
unreachable from outside the process. So a visual defect found by dragging sliders cannot be
handed to anyone: the state that produced it exists only on screen.

The goal is a **button that writes the entire live configuration to JSON**, and a `--config <path>`
that reads one back and reproduces the frame exactly — so a session can be handed to an agent (or
to a future self) and rendered headlessly into the same pixels.

The relationship to `.cscn` is the design's whole shape, so it is stated first.

## How this relates to `.cscn` — the boundary

They are different kinds of file and neither contains the other.

| | `.cscn` | config snapshot |
|---|---|---|
| answers | **what exists** in the world | **how it is tuned** right now |
| owns | model, lights' existence/type/position/units/IES, material texture bindings, `layers[]`, `roads[]`, `splatDomain`, fog-volume placement, probe placement, dust, wind, SSS profile slots | every slider, checkbox, combo and camera pose the GUI can move |
| has no key for | all shadows, SSAO/SSR/SSGI/contact shadows, the 12 material-feature toggles, GI volume, DoF, motion blur, film/vignette/grain/dither/sharpen/grade, clouds, layers-VT, draw-path levers (~150 `RenderArgs` fields) | anything with no runtime setter — see the load-time column above |
| written by | hand, or `tools/cetra_export.py` (6 of 12 blocks) | this feature |

**Precedence: `defaults → .cscn → CLI → snapshot`.** The snapshot is applied **after** model load
and **after** the scene-radius `fmaxf` clamps at `render.c:3297-3338` — apply it earlier and those
clamps silently raise `ssao_radius`, `ssr_max_distance`, `ssr_thickness_min` back up.

**The snapshot owns the look; the CLI owns the run.** `--headless`, `-f/--frames`,
`-S/--screenshot`, `--screenshot-every`, `--profiler` and the `*-at` diagnostic schedules are never
written by the dump and never applied by the restore, so handing an agent a snapshot to capture
headlessly cannot fight itself.

**A snapshot stands alone on the command line but does not replace a `.cscn`.** It carries a
`source` block naming the model or `.cscn` it was taken against, so `render --config snap.json`
with no `-m` works. It cannot *substitute* for a `.cscn` because everything in that file's
load-time column has no runtime setter at all — restoring those is a re-load, not an apply.

## The shape of the file

```json
{
  "version": 1,
  "source": { "model": "assets/cornell_rooms.cscn", "hdr": null, "lut": null,
              "width": 1600, "height": 900, "ss_scale": 1, "sky": true },
  "camera": { "eye": [...], "target": [...], "up": [...], "fov": 45.0,
              "near": 0.1, "far": 500.0, "mode": "free" },
  "engine":  { "specular_aa_strength": 0.5, "clearcoat": true, "lod_bias": 0.0,
               "render_scale": 1.0, "msaa": 4, "render_mode": "pbr", ... },
  "postfx":  { "bloom": {...}, "ssr": {...}, "fog": {...}, "dof": {...}, ... },
  "exposure":{ "automatic": true, "bias_stops": 0.0, "meter_mode": "centre",
               "adapted_luminance": 1.37, "adapted_valid": true },
  "shadow":  { "enabled": true, "cascades": 3, "pcss": true, ... },
  "sky":     { "sun_elevation": 8.0, "clouds": {...} },
  "water":   { "level": 0.0, "sea": { "wind_sea": {...}, "swell": {...} }, ... },
  "gi":      { "enabled": false, "rate": 4 },
  "probes":  [ { "index": 0, "enabled": true, "intensity": 1.0, "box_fade": 0.2 } ],
  "lights":  [ { "name": "key", "intensity": 3.2, "range": 0.0 } ],
  "materials": { "floor": { "roughness": 0.08, "metallic": 1.0 } }
}
```

`source` is the pre-engine half — the app merges it into `RenderArgs` sentinels exactly as a CLI
flag would, before `cscene_setup`. Everything else is the post-load half, applied as a live GUI
edit would be.

Sections whose owner is absent (`scene->water == NULL`, no probes, no sky) are **omitted on dump
and skipped with a warning on apply** — 18 sections are presence-gated.

## Mechanism

### One table, walked twice — the central decision

Dump and restore drifting apart is the failure this design exists to prevent; `render.c:1889-1891`
records the same hazard on `frame_schedule` ("stood at two for three specs while the body ran
five"). So there is **one static descriptor table** and both directions walk it. Adding a control
is one row, and a row cannot be dumped-but-not-restored.

```c
// cetra/src/config_snapshot.c
typedef struct ConfigField {
    ConfigOwner  owner;    // ENGINE POSTFX EXPOSURE SCENE CAMERA SHADOW SKY WATER IBL GI CLUSTER
    const char*  section;  // "postfx.ssr"
    const char*  key;      // "max_distance"
    ConfigType   type;     // BOOL INT FLOAT VEC3 VEC4 ENUM
    size_t       offset;   // within the resolved owner
    const char* const* labels;   // ENUM only, so the JSON reads "centre" not 1
    void (*apply)(struct Engine*, struct Scene*, const ConfigField*, const void* v);
} ConfigField;
```

`apply` is NULL for the ~90% that are a direct write. It is non-NULL for the handful that must go
through a setter or carry a side effect, each of which is a known trap:

| field | why it needs a setter |
|---|---|
| `render_scale`, `msaa`, `ss_scale`, `taa` | `set_engine_*` — rebuild render targets at the next frame top (`engine.h:444-462`) |
| `ssr_full_res` | `postfx_set_ssr_full_res` (`postfx.h:811`) — reallocates targets |
| `fog_ambient` | must also clear `scene->sky->publish_fog_ambient`, or the sky stamps over it (`render.c:3333-3343`) |
| sun elevation/azimuth | `sky_update_sun` — triggers the live LUT + env + IBL re-bake |
| light intensity | `set_light_intensity_units` — stored units differ from displayed |
| camera pose | `apply_explicit_pose` (`render.c:1608-1625`) — **without it the orbit controller rewrites `camera->position` on frame 1**; it also kills auto-orbit and forces `CAMERA_MODE_FREE`. `up_vector` is set by the caller, which `apply_explicit_pose` does not touch |
| exposure adaptation | restore `adapted_luminance` + `adapted_valid` together so frame 1 blends from the right place instead of re-approaching |

### What the table deliberately does not list

Exclusion is by construction, not by a blocklist. The three structs declare ~520 fields; ~350 are
GPU handles, `*_ready`/`*_built_*` lazy-alloc guards, the seven per-frame **published** blocks
(reflection probe, fog volumes, cloud shadow, water medium, fog casters, fog spot, aerial), the
nine temporal ping-pongs, the matrices, and the timings. Restoring any of them corrupts the frame
rather than reproducing it — write a stale `froxel_prev_frame` and reprojection reads a volume from
a camera that no longer exists.

### Files

**New**
- `cetra/src/config_snapshot.h/.c` — the table, `config_snapshot_save/write` (`cJSON_CreateObject`
  + `cJSON_Print`, already vendored and linked at `cetra/src/ext/cJSON.c`; today only
  `cscene.c` uses it and only for reading), `config_snapshot_apply/load`, and
  `config_snapshot_read_source` which parses the `source` block **without touching the engine** —
  the app needs it before `create_engine` exists.

**Changed**
- `gui.c` — a **"Dump Config"** button beside Print Camera (`gui.c:1049`), writing
  `cetra_config.json` in the cwd and printing the resolved path. Same one-printf idiom.
- `apps/render/src/render_args.h/.c` — `--config <path>` (restore) and `--config-dump <path>`
  (write at exit, the headless half of the button). Usage text.
- `apps/render/src/render.c` — two call sites, and the order is the whole contract:
  `config_snapshot_read_source` merged into `args` **before** `cscene_setup` (`render.c:2317`),
  and `config_snapshot_apply` **after** the scene-radius block (`render.c:3338`), immediately
  before the loop. `--config-dump` fires alongside the final screenshot.
- `AGENTS.md` — the flags, and a row in the determinism table saying a snapshot pins the look but
  not the frame index.

### The one gap the current arg surface has

`post.fog.enabled` is set **one-way** by a `.cscn` (`cscene_apply.c:173-175`) and there is no
`--no-fog` anywhere. A snapshot recording "fog off" over a fog-authoring `.cscn` cannot express it.
Fixed by applying `fog_enabled` directly on PostFX in the post-load half, where it is a plain bool
— the snapshot does not go through `RenderArgs` for it. Worth knowing rather than worth a flag.

## Phases

1. Spec into `specs/`, branch named for it, committed alone.
2. **Table + writer.** The descriptor table for the five scalar owners (engine, postfx, exposure,
   scene, camera) and the JSON writer. The GUI button. Nothing reads a snapshot yet.
3. **Subsystem sections + arrays.** shadow / sky / water / ibl / gi / cluster owners, then the
   three arrays (lights by name, probes by index, materials by name). Presence gating.
4. **Reader + apply.** `config_snapshot_read_source`, the post-load apply, the seven setter rows,
   `--config` / `--config-dump`. **CHECKPOINT: dump a hand-tuned session, restart from it, and
   show the two frames side by side before going further.**
5. **Gates.** New `config` group (below), docstring.
6. **Falsification.** Every mutation run and recorded.
7. **Docs.** AGENTS.md, `--help`, spec AS-BUILT + Measured.

## Gates — new group `config`

| arm | asserts | anti-vacuity | mutation |
|---|---|---|---|
| `config-roundtrip` | dump → restart with `--config` → dump again → the two JSONs are **byte-identical** | both dumps carry > 300 keys | drop one row from the table: the second dump differs |
| `config-coverage` | **every `ig{Checkbox,SliderFloat,SliderInt,Combo,ColorEdit3}` target in `gui.c` appears in the dump** — parsed out of the source, not transcribed | the parse finds > 150 controls | add a GUI control without a table row: arm fails |
| `config-pixels` | run A with ~10 non-default flags dumps at exit; run B passes `--config` **only**; frames compare 0 px (exposure pinned, floor measured x2 first) | run B without `--config` differs by > 1% | skip the post-load apply: pixels diverge |
| `config-standalone` | run B passes **no `-m`** — the `source` block carries the model — and reads the same bytes | the run does not error out | blank the `source` block: the run refuses by name |
| `config-override` | a snapshot with SSR off applied over a `.cscn` + CLI that both have it on: the SSR-sensitive read moves to the no-SSR value | the control run reads apart | apply before the `fmaxf` block: clamped values reappear |
| `config-schema` | unknown key warns and is skipped; a `water` section on a waterless scene warns and is skipped; a malformed value is refused **by name** | the applied-field count is printed and non-zero | remove the presence gate: a NULL owner crashes |

Must-stay-green, real selectors only: **gate-docs**, and `scripts/goldens.py` — the dump adds no
render work and every golden must stay 0 px.

## Verification

```bash
./build.sh
python3 scripts/gates.py --only config
python3 scripts/gates.py --only gate-docs
python3 scripts/goldens.py                      # 27 goldens, 0 px
```

By hand, which is the actual use case:

```bash
./out/bin/render -m assets/cornell_rooms.cscn         # drag sliders, hit Dump Config
./out/bin/render --config cetra_config.json           # same frame, no other flag
./out/bin/render --config cetra_config.json -x -f 2 -S /tmp/agent.ppm
```

Then the full suite once at the end.
