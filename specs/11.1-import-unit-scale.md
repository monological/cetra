# 11.1 — Import unit scale (FBX centimetres → engine metres)

## Context

**The problem.** `./out/bin/render -m assets/c64.fbx` renders black. The FBX has two
point lights (authored 800 unitless, clamped to 100 cd at import), but the asset is
centimetre-scale: the lights sit 1,200–1,860 world units from the model. Since specs
9.9/10.0 made lighting photometric, 1 world unit = 1 metre is load-bearing — the
inverse-square falloff (`lights_ubo.glsl:117`) and the cluster cull radius
(`light_cluster.c:81`, reach = 16·√intensity ≈ 160 units at 100 cd) read those
positions as kilometres. Both lights cull to nothing; the shader receives an empty
light list; since e7aa468 removed the fake 3% ambient floor, unlit is honestly black.

**Is importer-side unit scaling the proper fix? Yes.** Normalizing to a canonical
engine unit at the asset boundary is what every engine with physical lighting does
(Unreal converts everything to cm at import; Unity applies File Scale; glTF mandates
metres by spec). A photometric renderer cannot function without a defined metre, and
the import boundary is the only place the file's declared unit is still known.
Assimp already does the work: its FBX importer always reads `UnitScaleFactor` and
computes the cm→m factor (`FBXImporter.cpp:172-180`); passing `aiProcess_GlobalScale`
activates the bake (vertices, node translations, bone offsets, animation position
keys). For glTF/GLB the file scale stays 1.0 and the pass provably no-ops — which is
exactly the property the goldens need, since every committed golden is baked from a
glTF fixture.

**Why was it never done?** Three reasons, all verifiable in the history:
1. **Units were physically meaningless until three weeks ago.** Before 9.9, falloff
   was authored attenuation coefficients plus a 3%-of-white ambient floor, and the
   orbit camera auto-frames from the scene AABB — a cm-scale asset rendered
   identically to a metre-scale one. There was nothing to normalize *for*.
2. **When length units first mattered (the 9.6 atmosphere), the fix was a manual
   knob, scoped to the sky.** Commit 86884aa added `world_units_per_km` on
   SkyAtmosphere ("deliberately not scene-scaled: how large a scene is in the world
   is an authoring fact") with `--world-scale` as the override. It was framed as
   sky-only; nothing else adopted it.
3. **Specs 9.9/10.0 then made every punctual light a second consumer of the same
   fact without noticing.** Spec 10.0 is entirely about *photometric* units
   (candela/lux); geometric units are never mentioned — a genuine blind spot, not a
   deliberate deferral. Spec 10.2 even flagged the FBX light path as "wrong
   differently" and left it; and no golden or gate exercises FBX light import at
   all, so nothing ever tripped.

**The intent.** Add `aiProcess_GlobalScale` at the single assimp call site so FBX
assets land in metres; scale the two light fields node transforms don't carry
(`Light.size`, `Light.range`); verify the glTF no-op empirically against every
golden; and make `assets/c64.fbx` render lit as the acceptance demo.

## Settled design

- **Mechanism: baked scale via `aiProcess_GlobalScale`, OR'd into the flags inside
  `import_ai_scene()` (import.c:112-121)** — the single assimp chokepoint, so model
  imports, animation-only imports (`load_animations_from_file`), and the `-s` source
  skeleton all inherit it. Baked (not a root-node transform) because spring bones
  simulate in skeleton model space upstream of the node matrix with absolute metre
  constants — baking puts the sim in metres; a root scale would leave it in cm.
- **Animation imports scaled too** (automatic from the chokepoint): the native
  FBX-model + FBX-clip path stays self-consistent; retargeted matched bones are
  immune (animation.c:901-907 substitutes target bind translations); unmatched
  channels become metre-correct against glTF targets.
- **`process_ai_lights` scales what node transforms don't carry**: `light->size`
  (authored branch only, import.c:1223-1224 — the 1×1 default is already metres) and
  the glTF `khr_range` (:1268-1272). The factor comes from
  `aiScene->mMetaData["UnitScaleFactor"]` (raw × 0.01 × multiplier), read with the
  exact metadata-iteration pattern already at import.c:1154-1159. FBX range is never
  imported (always 0), so size is the real customer.
- **Two knobs following the existing `set_import_flip_uvs` idiom** (import.c:74-76):
  `set_import_unit_scale(bool)` + `set_import_scale_multiplier(float)`; the
  multiplier feeds `AI_CONFIG_GLOBAL_SCALE_FACTOR_KEY` via `aiSetImportPropertyFloat`.
- **CLI**: `--import-scale <f>` (extra multiplier) and `--no-unit-scale` (drops the
  flag entirely — exact pre-change behaviour; warn if both given).
- **Logging**: one `log_info` at the chokepoint when applied scale ≠ 1.0 (path +
  factor), and when a non-1 factor is suppressed by `--no-unit-scale`.
- **Camera cliff fix**: render.c:2136-2137 `if (camera_distance < 1.0f) → 100.0f`
  becomes `if (scene_radius <= 0.0f)` — a real 40 cm asset (radius 0.2 → distance
  0.5) must not teleport to 100 m; the comment already says "fallback for empty
  scenes". The `fmaxf(metre_default, r*k)` floors and the 0.1 shadow nears stay:
  they were the metre-scale policy all along and cm→m scales scenes *down*.
- **`IMPORTED_LIGHT_INTENSITY_MAX` 100 → 10,000 cd** (import.c:103, same warning) as
  its own commit — spec 10.0:55-57 ordered this and it was never done; without it
  c64's authored 800 cd clamps to 100 (~0.7 lux at the now-12 m distance).
- **Fold in a latent header bug**: import.c doesn't `#include "import.h"`, hiding a
  prototype mismatch (`uint32_t*` vs `size_t*` on the lights/cameras counts).
  Include the header, fix import.h:23,26 to `size_t*` (matches definitions; no
  external callers).
- glTF/GLB are provably untouched: only the FBX importer sets a file scale;
  ScaleProcess early-returns at 1.0. Every committed golden is baked from a glTF
  fixture. `.cscn`+FBX interplay is latent (no `.cscn` names an FBX today) —
  documented in the spec, no code. `--world-scale` stays as the atmosphere escape
  hatch but stops being load-bearing for FBX.

## Phases

Branch off master. Spec `specs/11.1-import-unit-scale.md` committed first, per the
planning workflow.

**Phase 0 — baselines (nothing committed).** Build master. Raiden determinism recipe
(CLAUDE.md) rendered ×2, must self-compare 0 px, kept as `baseline_raiden.ppm`. c64
"before" capture (black) kept as `baseline_c64.ppm`. Fresh-render every committed
golden per its recorded recipe and record deltas (protects against misattributing
pre-existing drift). gates.py green.

**Phase 1 — core unit scale (commit includes spec).** The chokepoint flag + metadata
helper + size/range scaling + setters + header fix. Verify: all goldens 0 px vs
Phase-0 renders; raiden recipe 0 px vs baseline (if nonzero: diff map, only
unmatched/root position channels may legitimately move — matched-bone diffs mean
stop); determinism ×2; c64 log shows the 0.01× line and the model is no longer black
(lights at ~12 m, inside the 160-unit cull radius; still dim until phase 3);
monkey.fbx/room.fbx frame sanely; gates green.

**Phase 2 — CLI escape hatches.** `--import-scale`, `--no-unit-scale` in the render
app arg parser, applied before any scene load. Verify: `--no-unit-scale` c64 render
compares 0 px vs `baseline_c64.ppm` (exact pre-change behaviour); `--import-scale 2`
on monkey.fbx with a pinned camera visibly differs (auto-fit would hide it
otherwise); one golden re-checked 0 px; gates green.

**Phase 3 — guards + photometric ceiling (two commits).** (a) Camera-cliff fix;
verify all goldens 0 px (this IS the check that no committed fixture sat below the
old cliff). (b) Intensity ceiling 100 → 10,000 cd; verify goldens 0 px (none
exercises FBX light import — say so in the commit), then the acceptance demo:
`./out/bin/render -m assets/c64.fbx -t assets/c64.fbm` shows a visibly lit model
(800 cd at ~12 m ≈ 5.6 lux); determinism ×2 headless; gates green. (c64 renders
untextured regardless — its .fbm textures point at a dead path; the demo is about
lighting.)

Reviews (/thermo-nuclear + /simplify) as background agents at the end, wait for ALL
before applying fixes; as-built with measured numbers; no merge to master without
explicit permission.
