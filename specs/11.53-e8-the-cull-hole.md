# 11.53 — E8: the cull hole, and collecting the payoff it was booked for

## Context

Roadmap item 34 (E8). `draw_list.c:110` marks a mesh `DRAW_UNBOUNDED` and `draw_item_visible`
(`draw_list.c:230`) then accepts it unconditionally — camera frustum *and* every shadow cascade:

```c
// Neither is bounded by mesh->aabb: calculate_aabb runs once at import, so
// a skinned mesh carries bind-pose bounds, and wind displacement is computed
// in the shader after the fact.
if (mesh->is_skinned || mat->wind_response > 0.0f)
    *flags |= DRAW_UNBOUNDED;
```

The comment is exactly right about *why*. This spec supplies the bounds it says do not exist, so the
exemption can be deleted rather than documented.

**The roadmap describes half of it.** Row 34 and the E8 section both say the flag is set by
`wind_response > 0` and prescribe "expand those meshes' AABB by maximum wind displacement". The
condition is `is_skinned || wind_response > 0`, so **every skinned mesh in every scene is also exempt
from every frustum test** — and an AABB expansion does not address that case at all: a bind-pose bound
is not a loose bound on an animated pose, it is a bound on a different shape. The flag's own comment
knows this; the roadmap row and section, which are what nominate the work, name wind alone. This is
the habit 11.52 recorded: read the code the row describes before believing the row.

**The payoff is real and the cull fix alone does not collect it.** `forest.c:14-15` states that the
app carries no wind on 2,000 scattered trees *specifically* because a wind material is
`DRAW_UNBOUNDED`; `11.51:215` records the same constraint from the other side ("These chunks are
uncullable. At 24-96 that is acceptable; at 60k it would not be"). But wind is applied in object space
with per-mesh uniforms, so every instance of a shared prototype sways in lockstep — making the trees
cullable is necessary and not sufficient. Both halves ship here, and forest gets its wind.

## What is actually broken — five findings

1. **Skinned meshes are exempt from all culling**, recorded only in the flag's comment; the roadmap
   names wind alone (`draw_list.c:110`).
2. **`_count_late_meshes` disagrees with the lane that draws.** `render.c:980-986` frustum-tests the
   transmissive lane against the raw `mesh->aabb` with **no** `DRAW_UNBOUNDED` check, while the pass
   that draws those meshes exempts them. A skinned or wind transmissive mesh whose bind-pose bound is
   off-screen is **drawn without the refraction resolve that feeds it** — the count gates a full-frame
   resolve (`render.c:961-963`). Latent, unreported, and closed by the same change.
3. **`DRAW_UNBOUNDED`'s doc comment describes the pre-E5 camera walker, not the code.**
   `draw_list.h:46-55` says "The camera pass has always culled both anyway ... Not worth inheriting"
   into shadows — the decision was to keep the camera's wrong cull off the shadow path, and it was
   implemented by exempting in the ONE predicate both paths reach, so the camera stopped culling them
   too. The comment records a decision; the code does something stronger.
4. **The wind bound was always computable.** Every term in `windOffset` is sin/cos-bounded and nothing
   scales with `|p|` — vertex position enters only inside sine *arguments*, as phase decorrelation.
5. **`Material.wind_response` is documented 0..1 and `tree.c:1383` sets 1.7.** The GUI range
   (`material.c:93`) is advisory. Any bound reads the field, never the documented range.

## Design

### The decision moves to cull time, carried by the type the frustum already travels in

`DRAW_UNBOUNDED` is a build-time flag and cannot stay one, for two reasons the plan's first draft got
wrong. `classify` runs once per FRAME — the stamp folds `total_frames` (`draw_list.h:96-101`) — at
the first pass's `engine_build_draw_list`, which is the shadow pass (`shadow.c:1203`), *before* the
app's render callback steps the animation. And it takes only `Mesh*`/`Material*`: it can see neither
`scene->wind` (GUI-mutable, `tree.c:561`) nor the pose. So the bound is evaluated **at cull time**,
from whatever the pass is about to draw with.

Every cull site already threads a `const Frustum*` from the pass that owns it — `render.c:1034` for
the camera, `shadow.c:825-835` for cascades and punctual faces, `shadow.c:1108` for TSM. That
parameter becomes:

```c
// What a pass culls against: its frustum, plus the two things that move
// geometry off its import bounds. NULL accepts everything, as a NULL frustum
// did. Built by the pass, at the pass, so the pose it tests is the pose it
// draws -- the shadow pass runs before the app's animation step and the
// camera pass after, and both upload from the same global at draw time.
typedef struct CullView {
    const Frustum* frustum;
    const struct Wind* wind;            // scene->wind; NULL = no wind field
    const struct AnimationState* pose;  // get_render_animation_state(); NULL = bind pose
} CullView;

bool draw_item_visible(const DrawItem* item, const CullView* view);
bool draw_run_can_join(const DrawItem* head, const DrawItem* next, const CullView* view);
```

The type change is what makes it safe: every site that passes a frustum today (`_visible_run`,
`_visible_caster_run`, `_submit_lanes`, `_submit_depth_prepass`, `_draw_shadow_items`,
`_count_late_meshes`) fails to compile until it passes the view, so nothing can keep culling on the
bind bound by omission. `shadow.c` already depends on `render.h` for `render_update_skinning_uniforms`
(`shadow.c:702`), so it can call the pose getter with no new dependency; `draw_list.c` only sees the
struct. Per-list state was considered and rejected: `draw_list_sort_lane` copies items into
`engine->sorted_opaque` and a header field it forgot to copy would cull with no margin — silently.

Inside `draw_item_visible`, one internal `_item_bounds(item, view, out_min, out_max)` returns the
object-space box the geometry actually occupies — or false, which the predicate reads as visible — and
the existing `frustum_test_aabb_transformed` does the rest. `_count_late_meshes` calls
`draw_item_visible`, closing finding 2. `DRAW_UNBOUNDED` and its enum comment are deleted.

`item_world_bounds` (LOD selection, depth-sort distance) stays on `mesh->aabb`, deliberately: LOD
refuses skinned meshes outright (`lod.c:54`), and a few centimetres of wind margin is nothing to a
distance bucket. Documented at the function.

### The wind half — a closed-form margin

`windOffset` (`shaders/include/wind.glsl:31-73`) is applied in **object space** and then multiplied by
the model matrix (`object_position.glsl:45,69`), so the margin is object-space and the existing
transformed-AABB test carries the node scale for free. With `S = wind->strength`,
`R = mat->wind_response`, `T = wind->turbulence`, `G = wind->gust_amount`, and
`A = S·R·max(1, |1-G|)`:

| mode | bound on `|offset|` |
|---|---|
| 0 cloth | `A · (1 + 0.42426·T)` |
| 1 vegetation branch | `A · (0.6 + B·(0.5 + 0.35355·T))` |
| 2 vegetation leaf | `A · (0.6 + B·(0.5 + 0.35355·T) + C·1.23288·T)` |

`0.42426 = 0.3√2`, `0.35355 = 0.25√2`, `1.23288 = √(1+0.4²+0.6²)` — magnitudes of the fixed vectors
the turbulence terms are built from. `gust ≤ 1` for the documented `G ∈ [0,1]` and `max(1,|1-G|)`
covers anything outside it; `dir` is normalized in the shader; every `sin`/`cos`, `sway`, `mask` and
`h²` lies in `[0,1]` or `[-1,1]`. **The margin is 0 exactly when the shader early-outs** —
`S <= 0 || R <= 0` — mirrored on the CPU, because a negative `R` would otherwise *shrink* the box.

**The coefficients are shared, not duplicated.** `0.6 / 0.5 / 0.25 / 0.3` and the `(1, 0.4, 0.6)`
flutter vector move into `shaders/include/wind_bounds.glsl`, a file of nothing but `#define`s that is
valid C and valid GLSL: `wind.glsl` splices it through the build-time expander
(`gen_shader_header.py:12`, any name under `include/`) and `wind.c` includes it by relative path. The
alternative is the house's "must match, checked by eye" pattern (`stochastic.glsl:22`), and here the
failure it invites is a silent pop, so it is not good enough.

`B` and `C` are the only per-vertex terms. `flex = uv1.y` and mode 2's `uv0.y` are **raw unclamped
multipliers** (`11.51:33-34`), so they are measured, not assumed:

- `B = max_v |uv1.y|`
- `C = max_v |uv1.y · uv0.y|` — the *joint* max, tighter than `B·max|uv0.y|` and still conservative

**Measured at upload, not in `calculate_aabb`.** `upload_mesh_buffers_to_gpu` (`mesh.c:188`) is the one
point every drawable mesh passes after all its CPU data is final — the list refuses `vao == 0`
(`draw_list.c:189`) — and it is where `tex_coords2` and the bone arrays are handed to the GPU. A
measurement taken there is a measurement of what the shader will see. `calculate_aabb` runs at
`import.c:1604` and `mesh_builder.c:121`, and a mesh that had UV1 attached after it (or never called it
— nothing forces a procedural mesh to) would carry `B = 0` against a shader reading real flex, which is
the under-bound this spec must not ship. The CPU arrays outlive the upload (`mesh.c:128-144`, freed
only in `free_mesh`), so this is one `O(verts)` loop per upload. No UV1 gives `B = C = 0`, matching
the shader — a disabled attribute reads `(0,0,0,1)`.

Sanity against real content: `abandoned_window` curtains 6.6 cm; `ivy_arcade` fringe 6.9 cm against a
4 m arcade. `apps/tree`'s grass is the pathological case at 8.04 units (`S=2.5`, `R=1.7`) — but its
grass, bark and leaves are one mesh each, always in view, so tree culls nothing either way.

### The skinned half — per-bone bind-space boxes, unioned through the pose

The shader computes `world = global_transform · (Σᵢ wᵢ·B[idᵢ]) · aPos` (`skin.glsl:29-40`). The
weights are **convex**, so the blended point lies in the convex hull of `{B[idᵢ]·aPos}`. That is the
whole theorem: bound what each bone individually could produce and union — no blending is evaluated.

At upload, in the same loop as `B`/`C`: for each vertex, accumulate its bind position into a per-bone
AABB for every influence with `w > 0`; a vertex whose weights sum below 0.001 goes into a separate
`rest` box instead, because `skinMatrix` returns identity for it (`skin.glsl:39`) and it draws at bind
position. `2·vec3` per bone plus one — 3 KB at 128 bones. Per cull, union
`aabb_transform(bone_aabb[j], pose->bone_matrices[j])` over the bones the mesh binds, plus the rest
box untransformed. Bounding the whole `mesh->aabb` by every bone instead needs no upload work but asks
a hand bone to bound the whole body — 2–4× inflation, not tight enough to cull with.

**What the shader draws, case by case, is what the bound follows** (`render.c:80-102`):

| state | shader | bound |
|---|---|---|
| `pose == NULL` or `active_bone_count == 0` | `skinned = 0`, bind pose | `mesh->aabb`, exact |
| `mesh->skeleton == pose->skeleton` | posed | per-bone union ∪ rest box |
| skeleton mismatch | posed with a foreign rig's matrices | **cannot bound → visible** |

The first row is the common one — an unanimated rig — and it is exact, not a fallback. The third is
the guard that stops a two-rig scene bounding rig B with rig A's pose (`g_current_animation_state`
is one global for the process, `render.c:64-73`); both fields exist (`mesh.h:80`, `animation.h:135`).

**The one-frame lag is not a trap here, and the first draft said it was.** The shadow pass culls
(`shadow.c:650`) and draws with the pose in the global at that moment — frame N−1's — and the camera
pass culls and draws with frame N's, because `render_update_skinning_uniforms` reads the same global
at draw time. Evaluated at cull time from the `CullView`, each pass's bound is the bound of what it
draws. The hazard is only ever **caching** a bound across the app's animation step, which the design
above cannot do. No union with the previous pose is needed; the draft's version was looser for
nothing.

A mesh that is both skinned and wind-driven composes: `windOffset` is added post-skinning and its
mask reads rest-space `p.y`, so the margin still holds and widens the posed union.

### Per-object wind phase — a scene field, not an instance-block one, and not gated on batching

The roadmap's sketch is "one instance-block field". Neither half of that survives contact:

- The InstanceBlock (`instancing.glsl:22-29`) is three `mat4[64]`; a fourth field costs ~1 KB of
  std140 padding, and it is not needed — the per-object phase can be **hashed from the object's
  world origin**, the translation column of the model matrix, which every vertex program already
  holds. Zero UBO cost, and it de-phases by position, which is what "these two trees should not
  sway together" means.
- The draft gated it on `uInstanced`, and that is wrong in a way that would pop. Whether a tree is in
  a batched run is a **batching decision** — LOD splits runs, `draw_run_can_join` cuts them at every
  culled neighbour, `--no-instancing` removes them — and a phase tied to it would flip as runs re-form
  frame to frame, and would break the instanced-against-non-instanced identity (`inst-identity`,
  `forest-batch-off`) for every wind material.

So: `Wind` gains `phase_variation` (turns; **default 0**, which is today's lockstep), uploaded as
`uWindPhaseVariation`, authorable as `wind.phaseVariation` in a `.cscn` (`parse_wind`,
`cscene.c:445`). `windOffset` gains an `origin` argument and adds `phase_variation · hash(origin) · 2π`
to **every** phase argument in all three modes — including the trunk lean `sin(t·speed·0.35)`, which
has no per-branch phase today and is the most visible unison. `cetra_local_position` forwards it; the
four vertex programs pass `cetra_instance_model(model)[3].xyz` (`pbr_skinned_vert` has no instancing
and passes `model[3].xyz`), and the two direct previous-position calls (`pbr_vert.glsl:88`,
`pbr_skinned_vert.glsl:89`) pass the same origin — the phase is a property of the object, not of the
frame. Both draw paths compute the hash from the same floats, so the identity holds.

Default 0 means `phase + 0·hash = phase` exactly, so every existing wind frame is bit-identical modulo
codegen — the `wind-uv` group's proportionality read (three quads at three origins) depends on this
and would break under any position-derived phase that was not opt-in. Forest sets it in C. `ivy_arcade`
could author it to decorrelate its 24 chunks; left off, since that is a look change to shipped content.

### Forest gets wind

Forest's prototypes come from `tree_gen` (`forest.c:447-462`), the same generator `apps/tree` uses,
and `tree_gen.c:444,742` already author UV1 flex. So this is `wind_response` on the two shared
materials (`g_mat_bark`, `g_mat_leaf`), a `create_wind` on the scene with `phase_variation` set, and a
strength tuned for a 125-unit trunk — not new geometry. `forest.c:14-15`'s comment goes with it. **Show
an A/B crop before committing the strength**; a look is the user's call.

### `--no-frustum-cull`

An engine bool, default on, that passes a NULL `CullView` — the bisect lever in the `--no-instancing`
/ `--no-sort-opaque` idiom, and 0 px by construction on every scene (the cascade cull is exact,
`shadow.c:639-649`). It is what the pixel arm below compares against; there is no such lever today.

## The verification problem, stated before the phases

**No golden contains wind or skinned geometry.** All 24 recipes in `goldens.py` were checked: zero
hits for raiden, tree, ivy, `abandoned_window` or wind. `raiden` is a *gate* subject
(`gates.py:5969`, `prepass-masked`) and is skipped entirely when `my_models/` is absent.
`skinned_instance_fixture.gltf`, the corpus's only in-repo skinned asset, has **no animation** — its
joints sit at the origin so the pose cannot drift (`gen_skinned_instance_fixture.py:26-29`), so it can
never leave its bind bound.

So "24 goldens 0 px" is a necessary regression check that **structurally cannot go red for this
change**. Claiming it as evidence would be exactly the pattern 11.40 filed against 11.39 — green
results that could not have gone red. This spec brings its own fixtures, and every arm below is
written so that "nothing was culled" and "everything was correctly kept" cannot both read green.

**Existing arms that will move, to be re-derived rather than re-baked:**

| arm | why |
|---|---|
| `shadowcull-live` | `abandoned_window_shadowed.cscn` authors `windResponse: 1.0` on two curtains; the cascade cull share (≥ 0.15) can only rise |
| `forest-cull` | asserts **exactly** all-culled and `draws == 0` at `FOREST_CAM_AWAY`; wind on the scatter puts a widened bound against that exactness (the other forest arms are ratios and inequalities) |

| `wind-uv` (whole group) | must be **unchanged** — that is the `phase_variation` default arm |

## Phases

**P0 — the instrument and the fail-first baseline.** Confirm the exempt population before changing
anything: `render -m assets/ivy_arcade/ivy_arcade.gltf --profiler` at a framing inside the tunnel
looking one way must report `meshes culled` **0** on the opaque row for its 24 wind chunks. Record
it. Free — `SubmitStats` already carries the counters with the invariant
`meshes_seen == instances + meshes_culled` (`profiler.h:51-65`).

**P1 — the wind half.** `wind_bounds.glsl` shared defines; `B`/`C` measured at upload; the margin in
`wind.c`; `CullView` threaded through every site; `_item_bounds`; `DRAW_UNBOUNDED` deleted;
`_count_late_meshes` onto the predicate; `--no-frustum-cull`. Goldens 0 px as regression;
`shadowcull-live` and `wind-uv` re-run.

**P2 — the skinned half.** Per-bone and rest boxes at upload, the three-row table above, the skeleton
guard. Goldens 0 px; `prepass-masked` and the two `skinned-*` arms re-run.

**P3 — `phase_variation`.** The field, the uniform, the `.cscn` key, the `origin` argument through
`windOffset` / `cetra_local_position` / four programs. Default 0 must leave every existing frame
bit-identical: `wind-uv` unchanged, goldens 0 px. If codegen moves a golden by PAE 1/255 specks (as
11.28's `instancing.glsl` include did), the diff map is what says so.

**P4 — forest gets wind, and the payoff is measured.** Then the number this item was booked for:
`meshes_culled`, draws, instances and triangles with and without. Forest is **not

## The review, and what it changed

Seven agents (four `/simplify` angles, three quality-review scopes). Convergent findings only —
each of these was raised independently by two or more, or verified against the source here.

**Defects, all of them in things this spec wrote:**

- **`wind_bounds.glsl` had unsuffixed literals**, so `wind_max_offset` evaluated in *double* against
  a shader that evaluates in float. Worse, the file was written as if the technique were novel:
  **`shore_constants.glsl` is the established precedent** — included from C at `shore_runup.h` —
  and its header states the `f` suffix is load-bearing for exactly this reason. The new file now
  carries the suffixes, the cross-reference, and that file's "numbers only" constraint.
- **`create_mesh` left `bone_rest_aabb` as malloc garbage**, guarded only by the `has_bone_rest`
  flag — which was itself the FLT_MAX sentinel the per-bone boxes already use, written a second way.
  Deleting the flag without seeding the box would have made the garbage live, so both moved together.
- **The cull toggle was read in three places in two idioms**, and `draw_shadow_layer` took a
  `CullView` **by value** and conditionally overwrote its frustum — correct only because its caller
  happened to pass NULL. One `render_cull_view` constructor now owns it; `frustum_cull_enabled` has
  exactly one reader.
- **`apps/forest` bypassed `set_scene_wind`** (which owns the free-on-replace) and dereferenced
  `create_wind`'s result unguarded, while the water block twenty lines below guards. Its comment also
  said "five prototypes" against `TREE_PROTOTYPES` 6.

**False documentation, which this corpus treats as worse than none:**

- **`item_world_bounds` still claimed "how big is this mesh" has ONE definition** — which this spec
  broke and P6 promised to document at the function and did not. Now documented, including the part
  the original justification missed: `item_distance` feeds the opaque depth sort and skinned meshes
  *are* in that lane, so a posed mesh sorts from its bind centre. That costs early-Z, not
  correctness, and saying so is the point.
- **`CullView`'s stated justification did not hold.** It claimed both members vary per pass; the wind
  field never does, and the pose is a process-global both passes read the same pointer to. The real
  reasons are decoupling and the compile-forcing type change, and those are what it says now.
- **The `cull` group's docstring opted out of `gate-arm-docs` citing two precedents, and neither was
  one** — `run_submission_gate` has no docstring at all, and `run_forest_gate` never calls
  `_submit_sum_ok`. Fixed at the root instead: `_submit_sum_ok` was the file's *only* helper that
  printed a verdict, so it now returns `(ok, detail)` and callers print. The group is arm-listed and
  machine-checked, and `gate-arm-docs` covers **10 groups instead of 9**.

**The coverage gap, which is the finding worth carrying:** the fixture authored `turbulence: 0` and
no `windMode`, so `wind_max_offset` collapsed to `strength × response` and **none of the six
`WIND_*` coefficients, neither per-mesh maximum, nor any of the vegetation arithmetic affected the
value under test** — the branch `apps/forest` ships on. A vegetation quad now sits on the same
frustum edge with turbulence on and UV1 authored flat (a ramp would meet `uv0.y = 0` at every vertex
where flex was non-zero and zero the leaf term out). Falsified by hand: zeroing the vegetation branch
takes `cull-wind` from 3 culled to 4 and loses **4,846 px**, so both arms now go red on it.

**Skipped, with reasons.** The efficiency pass measured all five suspected hot-path costs and found
the total new per-frame CPU is **0.017 ms on raiden and 0.125 ms on forest**, under the noise floor —
so no caching, no memo, no early-out. A `--wind-bound-probe` (checking the bound against a swept
CPU port of `windOffset`, in the `--water-fft-probe` idiom) and promoting a shared `hash13` into
`noise.glsl` are both worth doing and are follow-ups, not cleanup. Extracting `AABB` operations
(`aabb_empty`/`union`/`expand`) would touch `scene.c` and beyond this diff.
