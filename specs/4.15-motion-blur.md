# 4.15 — Motion Blur (McGuire velocity reconstruction)

## Context

The engine already produces a full-res, un-jittered **velocity buffer** for TAA (camera + per-object
+ per-bone motion, `aux_texture.xy` in UV units) but never uses it for blur — fast motion and
turntables read crisp and lifeless. 4.15 adds a **post-process motion blur** that reconstructs
plausible blur from that velocity buffer using McGuire's tile-max / neighbor-max dilation + a
depth-aware reconstruction filter. Tier-4 finishing effect; the velocity input is essentially free,
so the whole feature is a self-contained postfx pass.

Two decisions settled up front:
- **Default OFF / opt-in** (mirrors DoF): sharp by default, enabled by `--motion-blur` / GUI. The
  pass is skipped when off, so byte-gates stay trivially clean.
- **Full McGuire, staged** M1→M3 (per-pixel gather → tile-max/neighbor-max dilation → depth-aware
  reconstruction), so a fast object's blur bleeds past its silhouette instead of cutting off hard.

## Recon (verified against source)

The velocity input already exists — no shader/matrix work needed:
- `pbr_frag.glsl` writes `VelocityOut = vec4(screenVelocity(), ViewPos.z, roughnessMap)` into color
  attachment 2. `screenVelocity()` = `currUV − prevUV` (UV units, **un-jittered**, prev→current).
  `.z` = linear view-space Z, `.w` = perceptual roughness.
- Encoded from un-jittered matrices (`uCurrViewProjNoJitter` / `uPrevViewProj·uPrevModel`); skinned
  adds dual-pose LBS via `uPrevBoneRows[3·128]`. CPU prev-state all present: `engine->prev_view_proj`,
  `node->prev_global_transform`, `animation`'s `prev_bone_rows` (snapshot once/frame).
- Attachment 2 is `GL_RGBA32F`, full render-res, resolved to `fx->aux_texture` (`GL_NEAREST`).
- Producer gate `postfx_wants_aux_gbuffer(fx)` = `taa || ssao || ssgi || fog`. SSAO is on by default,
  so velocity is already produced headless; a `|| fx->motion_blur_enabled` term guarantees it under
  `--no-ssao`.
- Debug view `renderMode == 9` already visualizes the velocity field.

Postfx conventions: effect toggles live on `PostFX` (not `engine`). `postfx_run_dof` is the pass
template (reads `hdr_texture`, writes own texture); `postfx_run_fog` is the scaffolding template
(`return 0` gate + lazy `ensure_*_targets`). Chain order puts motion blur in the linear-HDR region
right after fog and before DoF. GL 4.1 has no texture barrier, so a pass cannot read+write the same
texture — write a scratch, then blit back into `hdr_fbo`. Tile-max mirrors the Hi-Z reduction idiom
but needs only one level (res→res/K), so a single fullscreen pass suffices.

## Design

1. **Velocity-driven, full-res, one new HDR buffer.** Read `fx->hdr_texture` + `fx->aux_texture`
   (`.xy` velocity, `.z` view-Z), reconstruct into `fx->motion_blur_texture` (`GL_RGBA16F`, full-res),
   **blit back into `hdr_fbo`** so DoF/bloom/tonemap all see the blurred scene. Velocity in UV units ×
   render resolution = pixel displacement; scaled by `motion_blur_scale` (shutter, default 1.0),
   clamped to the tile size so blur can't exceed the neighbor-max search radius.
2. **`PostFX` state:** `bool motion_blur_enabled` (default false), `float motion_blur_scale`
   (default 1.0). Shader constants `TILE_SIZE = 20` px, `SAMPLES = 16`. Add `|| motion_blur_enabled`
   to `postfx_wants_aux_gbuffer`.
3. **Three GPU passes (McGuire):** `tilemax` (res→res/20, max-magnitude velocity per 20×20 tile) →
   `neighbormax` (res/20, max over the 3×3 tile neighborhood) → `reconstruction` (per-pixel: gather
   `SAMPLES` taps along the neighbor-max tile velocity, weighted by depth classification + velocity
   cones, dithered by interleaved-gradient noise). Tile buffers `GL_RG16F` at `width/20 × height/20`.

## Byte-identity invariants

- **OFF path:** the hook is `if (motion_blur_enabled && aux_written) {…}` — skipped when off,
  `hdr_fbo` untouched → `cmp`-exact vs master. The aux-predicate term is `false` when off (no change
  to `aux_this_frame`). All new code is in NEW shaders + a gated C hook; **no shipped shader is
  edited**, so the float-reassociation cmp gotcha does not apply to the OFF gate.
- **Zero-motion invariant:** reconstruction early-outs to the exact center texel when the neighbor-max
  velocity is below ~0.5 px. So a **static** scene (static camera, no `-a`) renders `cmp`-exact
  whether the flag is on or off — a strong ON-path gate headless can verify.

## Milestones (branch `motion-blur` off `master`; each byte-identical off)

- **M0 — Spec (this file), committed first.**
- **M1 — Plumbing + reconstruction (per-pixel gather).** PostFX fields + program + targets +
  aux-predicate term + orchestrator hook/blit-back + toggle/CLI/GUI. `motion_blur_frag.glsl` gathers
  along the per-pixel velocity, early-out < 0.5 px. Gate: c64+raiden static OFF `cmp`-exact; static ON
  `cmp`-exact; animated ON shows limb blur; `--render-mode 9` sane.
- **M2 — Tile-max + neighbor-max dilation.** Two passes + `RG16F` tile buffers (res/20).
  Reconstruction uses the neighbor-max tile velocity so blur bleeds past silhouettes. Gate: OFF
  `cmp`-exact vs M1-off; ON fast object blurs past its edge.
- **M3 — Depth-aware McGuire reconstruction.** Foreground/background classification via `aux.z`,
  velocity-cone weights, interleaved-gradient-noise tap jitter, half-velocity center sample. Gate:
  OFF `cmp`-exact; ON clean boundaries, no banding, no NaN.
- **R — Review + ship (user-gated).** thermo + simplify (background), re-gate, roadmap + memory,
  user-gated merge.

## Risks

1. **Velocity availability:** gated on `taa||ssao||ssgi||fog`; the `|| motion_blur_enabled` term
   removes the SSAO dependency. Sky/uncovered texels clear to zero velocity → no bleed from the bg.
2. **Read-write hazard (GL 4.1):** never read+write `hdr_texture`; write `motion_blur_texture`, blit
   back. Same idiom as SSR/fog.
3. **Byte-identity off:** gated skip + false aux-term + no edits to shipped shaders. Zero-motion
   early-out makes the ON path byte-exact on static scenes.
4. **Blur radius clamp:** velocity clamped to `TILE_SIZE`=20 px; very fast motion saturates rather
   than searching unboundedly (documented; tune `TILE_SIZE`/`scale`).
5. **First-frame identity glitch:** `prev_view_proj` inits to identity → frame 0 has huge velocity;
   irrelevant to `--frames 30` (static converges before) but note for short runs.

## Shipped — outcome & review fixes

All milestones landed as the full McGuire pipeline. OFF byte gates `cmp`-exact vs master (c64 + raiden
static); the zero-motion early-out holds so `--motion-blur` on a static scene is `cmp`-exact too; the
gather path is deterministic run-to-run (frame-0 identity-velocity glitch, byte-identical ×2).

R-phase review (4 /simplify angles + thermo-nuclear + correctness) surfaced one real defect and two
cleanups, all applied:
- **Correctness (medium):** the depth-aware reconstruction read `depthX = -aux.z`, but sky/uncovered
  texels are cleared to `aux.z = 0` -> treated as the NEAREST surface, inverting the compare so a fast
  object was hard-clipped at its silhouette against the sky/backdrop (M3 regressed the background case
  M2 handled with no depth term). Fixed with `viewDist(z) = z < 0 ? -z : 1e6` (uncovered -> far), so
  foreground blurs over background again. Byte-safe: the fix runs after the zero-motion early-out and
  the OFF path skips the pass.
- **Coupling (3 agents converged):** the reconstruction's `MAX_PIXELS = 20` was a hand-copied literal
  of `MOTION_BLUR_TILE`; promoted to a `maxBlurPx` uniform sourced from the C `#define` (single source
  of truth). Value unchanged -> ON output identical.
- **Simplification:** dropped a redundant `clamp()` in tile-max (`auxTex` is CLAMP_TO_EDGE, so the
  partial-edge sample already resolves to the edge texel).

Reviews confirmed the structure is sound (3-pass + blit-back mirrors DoF/fog; tile-max is NOT a third
`create_mip_chain` instance; the tile-max 400-tap loop is optimal, separable would regress it).

## After 4.15

Per-object shutter/segment tuning; motion-blur-aware TAA (skip history where blur is strong); a
scale-relative `SOFT_Z` for the reconstruction's soft depth compare (the constant degenerates to a hard
step on very large-scale scenes -- graceful, cosmetic). Note the tile-max is a SINGLE-pass reduction
(res -> res/K), structurally unrelated to the bloom/hi-z multi-level mip-chains, so it is NOT a third
`create_mip_chain` instance -- that helper stays a two-candidate (bloom + hi-z) case.
