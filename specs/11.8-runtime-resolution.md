# 11.8 — Runtime resolution: a live render-scale slider, and window resize

## Context

11.7 shipped TAAU as a launch-only CLI flag because no resize path exists:
every PostFX target is sized once in `create_postfx`, and
`set_engine_render_scale` refuses any post-init change. The GUI shows the
launch value as read-only text.

Two consequences, and this spec removes both. You cannot try 0.67 against
1.0 without relaunching — exactly how you'd want to judge a
quality-for-speed trade. And **resizing the window today is worse than
"does nothing"**: no GL target is reallocated, but `fb_width/fb_height` are
silently refreshed inside the cursor and mouse-button callbacks
(engine.c:878, :909). After a resize plus any mouse input the engine is
incoherent — `engine_render_size()` returns the new size, the scene viewport
and the three self-healing targets follow it, the MSAA scene buffer and
every PostFX target do not. Since GL 3.0 dropped
`FRAMEBUFFER_INCOMPLETE_DIMENSIONS` that does not error; it silently renders
into the intersection. A live bug today, independent of TAAU.

Both want the same missing primitive: rebuild every resolution-dependent GL
target, in place, at a new size, without disturbing anything else.

## Settled design

**D1 — `postfx_resize` rebuilds the GL side in place; settings are never
touched.** `free_postfx` + `create_postfx` + restore is rejected on
inventory: ~90 fields on `PostFX` are settings, per-frame published blocks,
or borrowed handles — the AO/SSR/fog/DoF/grade parameters, the shadow +
probe + aerial publishes (four borrowed GL handles), the `sss_profiles`
table whose slot indices live in `material->subsurface_profile`, the
borrowed `exposure` pointer. A ~90-field restore list breaks the first time
someone adds a setting. Rebuilding only handles is immune to that drift, and
`create_ssr_buffers`/`destroy_ssr_buffers` (postfx.c:113/:155, driven at
runtime by `postfx_set_ssr_full_res`) is the working precedent.

Extract one allocation list and one teardown list from the existing bodies:

- `postfx_alloc_targets(fx)` — the eager block (hdr, bloom pyramid, depth,
  normal, ssao[2], `ao_history`, `create_ssr_buffers`, aux + its NEAREST
  filter, albedo, `taa_history`, and `post_fbo` when the scale splits).
  **The cut is not mechanical:** postfx.c:461-464 sets `ssr_full_res`,
  `ssr_temporal`, `ssr_denoise`, `ssr_jitter` inline in the middle of that
  region. Those are SETTINGS. Swept into the extraction they would silently
  revert the "SSR Full Res" checkbox and three sliders on every window drag.
  They stay in `create_postfx`; `ssr_full_res` becomes an *input* to the
  allocation.
- `postfx_free_targets(fx)` — the size-dependent deletes, **excluding** the
  three fixed-size resources (64x64 lum, 4x4 noise, 160x90x64 froxel
  volumes), **zeroing every handle**. Zeroing is load-bearing twice over:
  `postfx_taau_active` keys on `post_fbo != 0`, and `create_pingpong`
  (postfx.c:93) returns on its first failure leaving slot 1 untouched, so a
  partial alloc followed by a later free would double-delete a name GL may
  have recycled. `free_pingpong` and `destroy_ssr_buffers` must zero too.
- `postfx_resize(fx, width, height, ss_scale, render_scale)` — free, recompute
  the five size pairs, alloc, then D2. It is a THIRD door onto the
  `[0.5, 1]` clamp (postfx.c:251 documents that the doors must not disagree)
  and needs the same rule. It ends with `glUseProgram(0)` +
  `glBindFramebuffer(GL_FRAMEBUFFER, 0)`, matching `create_postfx`'s tail.

Two `del_fbo`/`del_tex` delete-and-zero helpers collapse ~60 paired lines.

**D2 — What a rebuild must fix up beyond allocation, and what it must NOT
touch.** Each was found by inventory; each is silent if missed.

1. **`noiseScale` on the GTAO program** — the ONE size-dependent uniform
   seeded once at create (postfx.c:671, from `half_*`). Re-seed it (needs
   its own `glUseProgram`).
2. **`ssgi_gi_texture` is an attachment on `ssao_fbo[0]`** (postfx.c:783).
   Recreating the SSAO FBOs orphans it, so `ssgi_ready` must be cleared.
3. **Eight lazy guards** — `dof_ready`, `ssgi_ready`, `fog_layer_ready`,
   `cs_ready`, `motion_blur_ready`, `sss_ready`, `oit_ready`, `spec_ready`
   — plus `fog_layer_failed`, a one-shot latch that would otherwise let a
   transient failure at the old size disable temporal fog permanently.
   NOT `froxel_ready`.
4. **Clear `ssao_texture[1]` at allocation.** `ao_result_tex` defaults to it
   (postfx.c:2263) and binds to tonemap unit 2 unconditionally even when the
   GTAO chain never ran, so `--no-ssao` with spec-occ on samples undefined
   content. A pre-existing frame-0 shape — but a rebuild recreates the
   frame-0 window on every resize, turning a startup flash into a per-resize
   one.

**Do NOT reset `froxel_prev_frame`.** My first draft did, on the theory that
the volume reprojects against the aux buffer. It does not: the fog volume
reprojects volume-to-volume through its own stored `froxel_prev_view` /
`froxel_prev_proj` (postfx.c:1708-1718 says so explicitly), which are
camera-space and resolution-free, and the volumes themselves survive. Forcing
`temporal = 0` for a frame costs exactly what the comment at postfx.c:1710
warns about — raw stair-stepped cascade taps in the fog — as a visible flash
on every resize, bought for nothing. Reset `fog_layer_frame` (that history IS
render-res) and every `PingPong.valid`; leave the volume's stamp alone.

The TAAU program is compiled only when `render_scale < 1` (postfx.c:545), so
raising the scale from 1.0 leaves it NULL — compile and seed it on demand.
Going back to 1.0, destroying `post_fbo` is what switches the seam off, so
the program may stay compiled.

**D3 — Engine lockstep, with a failure contract.**
`engine_rebuild_render_targets` mirrors `set_engine_msaa_samples`
(engine.c:560) then calls `postfx_resize`. The MSAA target must be rebuilt
explicitly — alone among engine targets it stores no size and has no
self-heal guard. The other three (`_ensure_opaque_color_target`:2133,
`_ensure_scene_depth_target`:2200, `_ensure_oit_targets`:2261) compare
stored w/h and reallocate on next use. MSAA goes first because
`_destroy_msaa_attachments` is what invalidates the OIT FBO and its borrowed
depth renderbuffer together.

**The invariant the pair must never be seen violating:** every
`resolve_color_attachment` and depth blit in `postfx_run` is a *multisample*
blit at `fx->width/height`. Multisample blits require identical src/dst
rects — a size mismatch is `INVALID_OPERATION` that resolves nothing.

Failure is not hypothetical and the precedent is wrong to copy:
`set_engine_msaa_samples` **ignores** `_create_msaa_attachments`'s return
(engine.c:582). Check it, and bail before touching postfx. If `postfx_resize`
fails partway, `hdr_fbo` can end up 0, and `postfx_run` would then blit into
the default framebuffer as a draw target. So: on any failure, log once and
set `engine->render_suspended`, which skips the scene pass, present, and
screenshot until a subsequent size succeeds — the same latch the degenerate
case uses, rather than a second recovery path.

**D4 — One apply point, and make it a self-heal rather than an event
latch.** At frame top (engine.c:2373, before the ImGui frame and any GL
work): if `engine_render_size()` / `engine_post_size()` disagree with
`fx->width/height` / `fx->post_*`, rebuild. This is precisely the idiom the
codebase already trusts twice — `_ensure_opaque_color_target` (engine.c:2132)
and `ensure_march_targets` (sky_clouds.c:185).

Chosen over an event-driven pending block because it subsumes three separate
bugs instead of dodging them: a stray `fb_width` write becomes a correct
rebuild instead of a missed one, `set_engine_ss_scale` (engine.c:1315, today
has neither a pre-init door nor a rebuild, so a post-init call silently
desyncs everything) becomes correct for free, and any future trigger —
dynamic resolution, a `.cscn` key — works with no new call site. Every
entry point then just writes `engine->render_scale` or the size fields and
lets the next frame top notice. A failure latch prevents retry-spam.

Frame top, not mid-frame, for two reasons that are not GL safety (a
slider-driven rebuild inside the panel would actually be safe — the panel
builds after `postfx_run` at engine.c:2062 and before ImGui snapshots GL
state): `_save_framebuffer_ppm` runs after present and reads `fb_width`
against the back buffer, and `postfx_taau_active` is consulted during the
*scene pass* for the 8-vs-16 Halton choice (render.c:704). Applying at frame
top keeps the switched frame comparable with a straight run — see D8.

**D5 — Window resize.** A GLFW framebuffer-size callback updates the pending
size; the self-heal does the rest. Also in the same handler: refresh
`win_width/win_height` (they change without `fb_*` when a window moves
between displays, and the FPS overlay and cursor mapping read them), call
`update_engine_camera_perspective` (engine.c:1006, already recomputes
aspect), and call `text_renderer_update_screen_size` (text.c:747 — it exists
and is called by nobody today, so text is stale at any size but the launch
one).

**Remove the `fb_width/fb_height` writes at engine.c:879 and :909-910.**
Not hygiene: they fire mid-frame, so `engine_render_size()` can change
between the frame-top check and the scene pass, which is exactly the
multisample-blit mismatch in D3. Init and the resize handler become the only
writers; the callbacks do their coordinate math against the stored values.

**Degenerate sizes.** A minimized macOS window reports 0x0.
`postfx_scaled_dim` is asymmetric there (0 at scale 1, floored to 2 below
it), `update_engine_camera_perspective` computes `0.0f/0.0f` = NaN which
propagates into every derived matrix, and `light_cluster_build_and_upload`
uploads `+inf` from the live zero viewport. Guard in one place — the
frame-top self-heal refuses any dimension `< 1` and latches
`render_suspended` (the documented GLFW iconify pattern). Two 2-line
hardenings land anyway because they kill whole classes: guard
`update_engine_camera_perspective` on `fb_height <= 0`, and early-out
`light_cluster_build_and_upload` on a zero viewport. A 1x1 window survives
today (`half_*`/`bloom_*` have `> 0 ? : 1` floors), so `< 1` is the right
threshold. `engine_resolve_opaque_color` (engine.c:2177) is also missing the
`rw <= 0` check its sibling `engine_resolve_scene_depth` has.

**D6 — GUI: five lines.** `igSliderFloat("Render Scale", 0.5, 1.0, "%.2f",
ImGuiSliderFlags_AlwaysClamp)` applied on `igIsItemDeactivatedAfterEdit()`,
writing `engine->render_scale`. Both details have precedent and both are
load-bearing: the release idiom is how the sun/cloud sliders defer their
re-bake (engine.c:1665-1702), and `AlwaysClamp` is used exactly once
already, on the cascade slider, because Ctrl+click text entry must not
escape a range that sizes allocations (engine.c:1724). A no-op guard after
clamping, or a click without a drag rebuilds. Shown at 1.0 too — otherwise
TAAU can never be switched on. Annotated/disabled when TAA is off, because
at `render_scale < 1` with TAA off `postfx_run` falls back to a bilinear
magnify: the slider would make the frame blurry rather than fast. Precedent:
"SSR Temporal (needs TAA)" (engine.c:1845).

`set_engine_render_scale` drops its refusal, and must re-apply the
headless-jitter rule that today runs only at init (engine.c:797) — otherwise
a runtime call in headless gives TAAU one repeated sample position forever,
which looks like a working gate and is a permanently soft frame.

**D7 — A diagnostic flag makes the rebuild reachable headless.**
`--render-scale-at <frame>:<scale>[,...]`, in the spirit of
`--check-stretch`. It must be **engine-side** (a scheduled write to
`engine->render_scale`, consumed by the self-heal): the render app passes
NULL for the update callback, so its only hook is `render_scene_callback`,
which runs *inside* the scene pass — a rebuild there would destroy the MSAA
color attachment mid-draw.

**D8 — Verification.**
- **Master gate, non-negotiable:** the default path never resizes, so the
  15-golden sweep stays exact 0, `gates.py` green, raiden byte-identical to
  the 11.7 baseline, determinism x2.
- **Size assertion — the highest-value check, ranked above PSNR.** Behind
  the diagnostic flag, after each rebuild walk the live targets with
  `glGetTexLevelParameteriv(GL_TEXTURE_WIDTH/HEIGHT)` and compare against the
  derived size. ~20 lines, deterministic, and it names the offender. GL
  errors alone will not: a stale `ssgi_ready` does error (incomplete MRT),
  but stale `dof_ready`/`cs_ready`/`sss_ready`/`motion_blur_ready` just draw
  a wrong-size viewport into a wrong-size texture, silently.
- **Leak probe:** after N rebuilds, `glGenTextures` once and print the name.
  Linear growth with N means leaked handles — three lines, and far more
  direct than watching RSS.
- **Convergence equivalence:** switch 1.0 -> 0.67 at frame 60, run to 180,
  versus a straight 0.67 run to 180. Sound because the Halton index is
  `total_frames % phases + 1` — a pure function of the frame counter, so from
  frame 60 both runs draw identical positions, but ONLY if the switch lands
  at frame top. Requires `--no-auto-exposure -E 1.0` (AGENTS.md measures
  99.77% of pixels differing on a provable no-op otherwise) and a pinned
  camera (TAA never converges under motion). Expect the floor to be set by
  the 0.97 accumulators, not TAA: `0.97^120` leaves ~2.6% of the AO and SSR
  history, against TAA's `0.9^120` = 3.5e-6. Measure the bar rather than
  asserting one; report the reverse switch too.
- **Run all of the above with the features ON** — DoF, SSGI, fog, contact
  shadows, motion blur, SSS, OIT. With defaults the gate exercises exactly
  one of the nine lazy latches, i.e. it proves nothing about the thing most
  likely to be wrong.
- **Window resize by hand:** drag-resize, confirm re-render rather than
  stretch, correct aspect, one rebuild per settle (log-counted), and that
  minimizing does not spam errors.

**D9 — Already safe, checked.** No app, the screenshot path, or the GUI
stores a PostFX GL handle. The light cluster re-derives from the live
viewport each frame (render.c:654). The view UBO is republished per
invocation. Shadow/IBL/GI/probe are fixed-size and save/restore the viewport.
`prev_view_proj` and `prev_global_transform` are matrices, resolution-free —
so the first frame after a rebuild has slightly wrong edge velocities, but
the history that would consume them was just reset. `sky_clouds` self-heals
AND resets its own parity stamp in the same place (sky_clouds.c:221), the
best precedent in the repo for this change. `apps/splash` drives its own
loop and never calls `engine_run`, so it gets no rebuild — harmless (text
only), worth a note. No app installs a framebuffer-size callback today and
ImGui's GLFW backend is initialized with `install_callbacks = false`, so the
chaining hook can stay minimal.

## Phases

**Continue on the existing `taau` branch** — no new branch. 11.7 is complete
and unmerged there (8 commits, HEAD `3c0ced8`), and this work builds directly
on its seam, so the two ship together as one merge to master. Spec committed
first (`specs/11.8-runtime-resolution.md`, alongside 11.7's rather than
replacing it). Every phase: build, 15-golden sweep 0 px, gates green, raiden
byte-identical, commit.

The raiden baseline the master gate compares against is the one captured at
11.7 Phase 0 (`tmp/taau_p0_raiden.ppm`) and stays valid — same branch, same
build lineage, and the default path still never resizes.

**P1 — extract, no behaviour change.** `postfx_alloc_targets` (taking
`ssr_full_res` as input, leaving postfx.c:461-464 behind) /
`postfx_free_targets` / the delete-and-zero helpers, with `free_pingpong`
and `destroy_ssr_buffers` zeroing. Pure refactor; the master gate is the
whole test.

**P2 — the mechanism.** `postfx_resize` + `engine_rebuild_render_targets` +
the frame-top self-heal + the degenerate/failure latch + the diagnostic
flag. Gated by the size assertion, the leak probe, and convergence
equivalence with features on. Nothing in the UI yet, so headless is the
proving ground.

**P3 — window resize.** Callback, `win_*` refresh, camera aspect, text
renderer, removal of the mouse-callback size writes, the two 2-line
hardenings. The risky phase, landing on a mechanism already proven in P2.

**P4 — the GUI slider.** Five lines onto a working self-heal.

**PR — reviews + as-built.** Five background audits, wait for ALL, apply as
one commit, re-gate. Retire the "no resize path exists" claim in the
roadmap B4 row, the 11.7 follow-up list, `postfx.h:97`, and the AGENTS.md
TAA paragraph. Merge only on explicit permission, and note that the merge
now carries 11.7 and 11.8 together.

## Risks

A wide teardown of live GL state fails as a stale handle, not a crash —
mitigated by zeroing on delete and by the size assertion, which is the only
check that names a missed latch. Histories reset on every rebuild, so expect
a visible re-converge after each change; correct, and worth stating in the
GUI rather than hiding. On macOS a live border-drag blocks inside
`glfwPollEvents` (engine.c:2565, loop bottom), so frames stop during the
drag and one rebuild lands at the end — the self-heal handles that
naturally, which is another reason not to build a debounce timer. One
latent hole this makes reachable: `ensure_march_targets`' failure path
(sky_clouds.c:242) returns with a cloud FBO still bound, unbinding the scene
FBO mid-pass; today only reachable on frame 1, after this on any resize.

**Effort: M** (4 phases + reviews; P1 mechanical, P2 carries the risk).
