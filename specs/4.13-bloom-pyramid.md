# Tier 3 · 4.13 — Bloom pyramid (Jimenez dual-filter down/upsample)

## Context

Cetra's bloom is a bright-pass + 2-iteration separable Gaussian ping-pong at fixed half res
(postfx.c:1201-1229). A shallow single-resolution Gaussian cannot be both wide and smooth: glow
stays tight around bright sources (softbox highlights, emissive screens, fog shafts), and wider
kernels at one resolution band and shimmer. §4.13 replaces the blur with the industry standard
(Jimenez, CoD:AW 2014): a progressive **downsample mip pyramid** (13-tap filter per level,
halving to ~8-16 px) followed by a progressive **tent upsample that accumulates** back up the
chain — wide, smooth, temporally stable glow at equal-or-lower cost. The bright pass (Karis
soft-knee + firefly clamp, bloom_bright_frag.glsl:19-26) and the tonemap composite (bloomTex
unit 1, `bloomStrength`/`bloomEnabled`) are preserved unchanged.

**Verified code facts (explored):**
- Current chain: bright pass writes `bloom_fbo[0]` at bloom_width/height = internal/2
  (1920×1080 at the standard 2× SSAA command), format `GL_R11F_G11F_B10F` (deliberate: bloom
  never reads alpha, packed float halves bandwidth); H/V Gaussian ping-pong `blur_iterations`
  (=2) times; result always lands in `bloom_texture[0]`; tonemap binds it to unit 1.
- Bloom runs AFTER fog/DoF/auto-exposure, reading `scene_tex` (hdr or dof output). Unchanged.
- `blur_iterations` has NO GUI slider and NO app flag — removing it touches only postfx.{h,c}.
- `blur_program` has no other consumer (DoF and SSAO have their own blurs). `bloom_texture[1]`
  is scratch only. No debug view reads bloom. Teardown hard-codes the 2-arrays
  (postfx.c:582-583).
- **`bloom_width/height` are the codebase's shared half-res size** (DoF targets and
  `ssao_width` alias them) — the pyramid must NOT repurpose them; level 0 just uses them.
- **The shared `upsample_tent_program` cannot be reused**: its `texelSize` is set once at init
  (postfx.c:431-435) and the SSR/fog composites draw assuming it; bloom needs per-level
  texelSize, so it gets its own upsample program (kernel copied from upsample_tent_frag.glsl).
- **The two GL-4.1 idioms to mirror exactly** (no compute, no texture barrier):
  hiz mip-chain allocation — manual `glTexImage2D` per level + `GL_TEXTURE_MAX_LEVEL`
  (postfx.c:270-294; "an incomplete chain samples as black" — the shipped lesson), and the
  hiz build loop — one FBO re-attached per mip, sample the adjacent level of the SAME texture
  with BASE/MAX_LEVEL pinning, restore full range after (postfx.c:1042-1065).
- No bloom app flags exist at all — meaning there is currently NO headless way to disable
  bloom, which the byte-gate needs (see M0a).
- When `bloom_enabled` is false the whole block is skipped and `bloomEnabled=0` gates the
  shader sample; the texture stays bound. Unchanged by this plan.

## Design

**Storage (postfx.h/c):** replace `GLuint bloom_fbo[2]; GLuint bloom_texture[2];` with a
single `GLuint bloom_fbo;` (re-attached per level, hiz style) + `GLuint bloom_texture;`
(mipmapped `GL_R11F_G11F_B10F`, level 0 = bloom_width/height) + `int bloom_mips`. Level count
from the hiz cap idiom, stopping when min(w,h) < 8, cap 8 — 1920×1080 → 8 levels (1080→~8).
Filters: MIN `GL_LINEAR_MIPMAP_NEAREST` (bilinear within the pinned level), MAG `GL_LINEAR`,
`GL_CLAMP_TO_EDGE`, `GL_TEXTURE_MAX_LEVEL = bloom_mips - 1`. Delete `blur_iterations`.
Tonemap needs NO change: it magnifies the half-res texture, and magnification always samples
level 0.

**Shaders:**
- `bloom_bright_frag.glsl` — UNCHANGED; still the prefilter + first downsample into level 0.
- `bloom_downsample_frag.glsl` (new) — Jimenez 13-tap (5 overlapping bilinear 2×2 boxes,
  center-weighted 0.5/0.125) sampling `srcTex` with `texelSize` = 1/source-level dims.
  Comment: the 13-tap's overlapping boxes kill the pulsing/firefly aliasing a plain 2×2 box
  chain produces under motion (the reason this beats iterating the old Gaussian).
- `bloom_upsample_frag.glsl` (new) — 3×3 tent (KERNEL {0.25,0.5,0.25}, copied from
  upsample_tent_frag.glsl) sampling `srcTex` at `texelSize` = 1/source-level dims. Additive
  accumulation happens via call-site blend, not in-shader.
- DELETE `bloom_blur_frag.glsl`.

**postfx_run bloom block (replaces :1201-1229, same `if (fx->bloom_enabled)` gate):**
1. Bright pass → attach `bloom_texture` level 0, viewport bloom_width/height, unchanged
   uniforms (threshold/knee/maxBrightness), reads `scene_tex`. (Must
   `glFramebufferTexture2D` level 0 explicitly since the FBO is re-attached below.)
2. Downsample loop, mip 1..bloom_mips-1: attach level `mip`, pin BASE/MAX_LEVEL to `mip-1`,
   viewport = level dims, `texelSize` = 1/level(mip-1) dims, draw.
3. Upsample loop, mip bloom_mips-2..0: attach level `mip`, pin sampling to `mip+1`,
   `glEnable(GL_BLEND); glBlendFunc(GL_ONE, GL_ONE)` (accumulate onto the level's
   downsampled content — the progressive widening), `texelSize` = 1/level(mip+1) dims, draw.
   After the loop: `glDisable(GL_BLEND); glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`
   (house restore idiom) and restore BASE/MAX_LEVEL to (0, bloom_mips-1).
4. Tonemap bind site: `bloom_texture` (was `bloom_texture[0]`).

**Energy/default retune:** level 0 now holds its own content PLUS ~7 accumulated coarser
levels — several times the old chain's energy. Keep the composite contract untouched and
retune `bloom_strength` default (0.08 → ~0.02-0.04, judged in the M1 visual pass against the
old look: same overall intensity, wider softer falloff). Threshold/knee/max_brightness
defaults unchanged.

**Programs (program.c/h, `create_post_program` one-liners):** delete
`create_bloom_blur_program`/`blur_program` field; add `create_bloom_down_program` /
`create_bloom_up_program` + `bloom_down_program`/`bloom_up_program` fields
(create/null-check/free; sampler init `srcTex = 0` for both; `texelSize` per draw — these are
bloom-private so no init-once conflict).

**App flag:** `--no-bloom` (args field + parse + apply `engine->postfx->bloom_enabled = false`
+ usage line), copying `--no-energy-comp`. Needed for the byte gate; useful regardless.

## Risks / notes

1. **R11F_G11F_B10F banding:** kept (current format, deliberate bandwidth choice; values ≥0,
   no alpha needed). The pyramid's accumulation could expose the 5-6-bit mantissa as ring
   banding on very wide gradients — checked in the M0b A/B; upgrade path is RGBA16F for the
   pyramid texture only (one enum change).
2. **Sampling-while-attached:** same-texture adjacent-level read/write is exactly the shipped
   hiz idiom (BASE/MAX_LEVEL pinning excludes the attached level from the sampled set); the
   upsample adds blending on top, which touches only the attachment, not the sample set.
   Restore both the pinning AND blend state after (SSR/fog/tonemap follow).
3. **DoF/SSAO coupling:** none — they own separate blur programs, and bloom_width/height stay
   the shared half-res constants (the pyramid only mips DOWN from them).
4. **Old-look parity is not a goal:** off-state is byte-gated; on-state is *supposed* to look
   better. The A/B judges "wider + smoother + comparable energy," not equality.
