# Spec 11.39 — D2: cloud shadows and local fog volumes

## Context

Roadmap D2, both halves, agreed. Two gaps in the shipped atmosphere that share one integration
point, `froxel_inject_frag.glsl`:

- **Cloud shadows.** B2 shipped volumetric clouds and explicitly deferred their shadows
  (`specs/11.0-volumetric-clouds.md:251-258`, a bare naming with no design), so the sky has
  weather and the ground does not know. Clouds reach lit surfaces today *only* through the env
  bake, as ambient, on the slider-release cadence. The roadmap calls this "the highest
  look-per-line item left in the atmosphere stack".
- **Local fog volumes.** B1's froxel volume carries one global medium, so a smoky room, a dust
  shaft or a mist pocket cannot be authored — only the whole world's fog can change.

**Scope agreed:** both halves. **Cloud shadows ride the existing `--clouds` flag** rather than
their own — a cloud that casts no shadow is wrong rather than un-featured — with
`--no-cloud-shadows` as the bisect lever.

**Explicitly out of scope:** sampling the cloud shadow in `pbr_frag` for direct sun occlusion.
That half needs a `pbr_frag` sampler and is hard-blocked on D0 (`roadmap:848-852`). The roadmap's
own instruction is to do the froxel half first and *measure whether the surface half is still
worth a unit* — so this spec must end with that measurement.

State: `master` at `de171a9`, clean, **12 commits ahead of `origin/master`, not pushed**.
151/151 gate arms, 23/23 goldens.

## What exploration established, because it reshapes the work

**1. The temporal accumulator will ghost this, and that is the main risk.** The froxel volume has
its own accumulator, ungated on TAA, with `fog_temporal_blend = 0.9` (`postfx.c:648`) — 10% new
per frame, ~29 frames to 95%. Reprojection is **camera-only** (`froxel_inject_frag.glsl:296-316`)
and there is **no history rejection**: line 313 is an unconditional
`mix(result, history, temporalBlend)`. The 2D accumulator clamps history to a 3×3 neighbourhood
for exactly this reason; the 3D one cannot afford 26 fetches × 921,600 cells.

Static media are free — that is the recorded argument for water at `:205-208`. **Wind-driven
cloud shadows are not static**, so they will trail a visible half-second smear. This is a
pre-existing latent defect that D2 is the first feature to expose, and it needs its own phase.

**2. The cloud deck is camera-anchored in XZ.** `cloud_march` sets `ro = vec3(0.0, obsAlt, 0.0)`
(`clouds.glsl:122`) and is fed only an altitude, so camera translation produces no cloud parallax
— documented at `clouds.glsl:13-22` as a deliberate compromise. A world-locked shadow therefore
cannot agree with the deck overhead. Decided below.

**3. Everything else is precedented.** `cloudDensity` (`clouds.glsl:63`) is a pure function of
position and samplers — no screen state, no history, no camera — and `sky_env_clouds_frag.glsl:34`
already calls the march from a non-screen pass, so a second consumer is proven. World-space `P`
is already in hand at `froxel_inject_frag.glsl:166`. Sampler units 0 and 4-15 are free in the
inject program, ~700 of 1024 uniform components are free, and UBO binding 5 is free.

## Phase 1 — the cloud shadow map

**A `Sky`-owned low-res 2D transmittance texture, built once per frame.** Owner is `Sky`, not
PostFX: Sky owns the noise, the sun and the wind clock. `sky_update_aerial` + `sky_publish_to_postfx`
(`engine.c:1757-1759`, `sky.c:331-339`) is the exact precedent — a sky-owned GL pass whose result
is handed to postfx one line later. It runs long before froxel injection (`postfx.c:2386`).

**Build:** one fullscreen pass over a ~256² `GL_R16F` texture. Each texel marches the cloud shell
(`CLOUD_BOTTOM_KM 1.5` → `CLOUD_TOP_KM 4.0`) along `sky->sun_dir`, accumulating optical depth from
`cloudDensity` and storing transmittance. Call `cloudDensity` directly rather than `cloud_march` —
no phase, no ambient, no LUT taps needed for a shadow.

**Parameterisation.** The layer is a horizontal shell, so transmittance along the sun ray depends
only on where that ray crosses the shell: a 2D map indexed by the crossing point is *exact* for
any receiver below it. Lookup for a froxel at `P` is `P.xz` sheared by the sun direction over
`(shellY - P.y)` — a couple of ops, no matrix, and correct at every altitude below the deck.

**The anchoring decision, and it is a real one.** The shadow map is **world-anchored**, the deck
stays camera-anchored, and they will not agree.
- World-anchored is required for the deliverable: a dapple that *slides across the terrain as you
  walk* is unmistakably wrong, and camera-anchoring would do exactly that.
- The deck's own anchoring is a pre-existing documented compromise, and the mismatch is only
  observable by cross-referencing a cloud overhead against its own shadow underfoot, which nobody
  does precisely.
- **File the fix rather than doing it here:** feeding the camera's world XZ into the march's sample
  position un-anchors the deck and makes both consistent — a small change that moves the cloud
  goldens and belongs in its own spec.

`sky->world_units_per_km` (`sky.h:128`) converts the km-space shell into world units;
`sky_aerial_far_units` (`sky.c:16-18`) is the existing pattern. **Sun convention:** `sky->sun_dir`
points *toward* the sun while `fog_light_dir` is travel direction — two conventions are live, so
the new code states which it uses at every boundary.

**Consumption** in `froxel_inject_frag.glsl`: multiply the directional light's contribution at line
217 by the sampled transmittance. One new sampler (unit 4), one new matrix-free lookup.

**Off-gate discipline.** Clouds off must allocate nothing and diff 0 px — the shipped pattern for
that is *two programs*, not a uniform branch (`sky.c:621-629`). Either follow it or prove the
`cloudShadowEnabled == 0` path inert at 0 px.

## Phase 2 — a history clamp for the froxel accumulator — **NOT DONE, premise measured false**

The plan asserted "phase 1 looks wrong without this". Measured, it does not, and the reasoning
that predicted the ghost was scoped to the wrong quantity.

The prediction came from the shadow map's own geometry: an 8 km noise tile against a 0.9 blend,
~29 frames to 95%, so a wind-driven pattern should smear visibly. What actually sets the scale is
the **fog volume's depth**, which the plan never looked at. On the aerial fixture:

| quantity | value |
|---|---|
| `fog_far` (`render.c`, `scene_radius * 5`, radius 128,090) | 640,453 units = **640 km** |
| cloud shadow tile | 8,000 units = **8 km** |
| history time constant | ~0.48 s |
| smear at a 10 km/s stress wind | 4.8 km = **0.75% of the volume span** |

Shadow-signal contrast (σ of the on/off difference over the sky band, 60 frames, exposure pinned):

| wind | σ |
|---|---|
| still | 0.0103 |
| 1 km/s | 0.0108 |
| 10 km/s | 0.0103 |

Flat across four orders of magnitude of stress. The wind is live over that range and not the
thing being missed — the deck itself moves 889,661 px at 1 km/s and 889,256 px at 10 km/s against
the still frame, so the field really is translating; the shadow's contrast simply does not care.

**Both ends of the scale range are safe, for opposite reasons, and nothing sits between them.**
In a large scene the volume spans many tiles, so a smear of a few km is nothing against it. In a
metre-scale scene `fog_far` is tens of metres, so `cloudSun` is spatially near-CONSTANT across the
whole volume — a uniform dimming that lags slightly in time, with no dapple to smear. A scene has
to be one or the other.

So the clamp is deferred rather than built. It was proposed to fix an artifact, the artifact does
not occur, and adding an unmeasurable correction to a temporal filter is how a filter acquires
behaviour nobody can account for later. If a future medium DOES change fast in a spatially varying
way — a light switching, a density animated per frame — this is the affordable fix and the
measurement above is the protocol for confirming it is needed first.

**Still open, and separately real:** nothing invalidates the history when fog parameters change,
so dragging the density slider lags ~29 frames. `fx->froxel_prev_frame = -1` is the existing
one-frame-reset idiom (`postfx.c:1015`). Interactive-only, not on any measured path here, filed.

## Phase 3 — local fog volumes

**Scene-owned boxes, published to PostFX.** The water publish idiom (`water.c:349-382`) is the
pattern: a subsystem writes flat POD onto PostFX each frame and PostFX never learns about the
subsystem. But **water is not a template for the medium itself** — it is a world-Y half-space that
*replaces* air rather than composing with it, and exits early (`froxel_inject_frag.glsl:196-212`).

**Authoring:** a **top-level `fogVolumes[]`** block in `.cscn`, not `post.fog.volumes`. The rule is
recorded at `cscene.c:373-378`: fog is a field on PostFX, but a volume is a scene-graph citizen with
a transform, so it belongs beside `water` and `wind`. Copy `lights[]`'s cap-and-warn array parsing
(`cscene.h:222`).

**Delivery:** a plain uniform array for N ≤ 8 to start — 8 AABB tests × 921,600 cells is cheap
beside the 9 cascade taps and 128 clustered-light iterations already there. Bin into the cluster
grid only if profiling says so; the froxel grid already shares that grid's depth slicing, so
`clusterLightListUv` is the upgrade path.

**Combination, and this is the part with a real trap.** The integrate pass treats `cell.rgb` as the
medium's *source function*, not as pre-scaled radiance (`froxel_integrate_frag.glsl:66-68`). So:
- a box that only changes **density** is a one-liner at `froxel_inject_frag.glsl:186`:
  `sigma += boxDensity`;
- a box with its own **tint or albedo** must combine as a σ-weighted average,
  `S = (σ_air·S_air + σ_box·S_box) / (σ_air + σ_box)`. Adding radiances double-counts.

**Arming, and the lesson this repeats.** A box must **not** set `fog_enabled` — that is spec
11.33's defect #1, a permanently latched flag. Add a term to the pass gate at `postfx.c:2371-2372`:
`(fog_enabled || water_medium != 0 || local_fog_count > 0)`, with count-zero as the single off
state.

`upload_fog_uniforms` (`postfx.c:2147-2197`) is the single edit site for fog uniforms, by its own
stated contract.

### As built

Shipped as planned, with three things the plan did not anticipate.

**A volume carries a TINT, not its own radiance**, and that is what keeps it to a single lerp. The
plan's σ-weighted form needed an `S_box`, which reads as "evaluate the lighting again for the box".
It does not have to: the box stands in the same sun, sky and clustered lights as the air around it,
so it re-weights the source already computed and the combination collapses to
`S *= (σ_air + Σ σ_i·tint_i) / σ`. Emission — a volume that glows on its own — is the case this
shape cannot express, and is not modelled.

**The weight is the box's exact signed distance**, not a per-axis product. A product feathers the
corners twice and pinches them, which is visible on any volume whose feather is a real fraction of
its size — and a dust shaft's is, because the soft edge is the whole point of it.

**`fog_enabled` had to be narrowed, and the gate change is what forced it.** Once the pass runs for
media the app did not ask for, uploading `fog_density` unconditionally puts the app's height fog in
every frame that merely has a box in it. So the density now uploads as zero when `fog_enabled` is
false: that flag means "the global height medium exists", the gate means "some medium does". Before
there was only one medium the two were the same statement.

**The 0 px golden run originally cited here as evidence was vacuous, and the correction is worth
keeping.** The upload only happens inside `postfx_build_fog_volume`, which only runs when the pass
is armed; with `fog_enabled` TRUE the expression is unchanged. The only frames the narrowing can
move are `fog_enabled == false && water_medium != 0` — submerged ones — and no golden is submerged.
The 0 px was guaranteed whatever the change did. The behaviour that actually changed is real and is
a fix (`fog_density` defaults to 0.02, so before this every submerged frame carried unrequested air
haze above the waterline), but it remains **unmeasured**: a submerged fixture is the missing
instrument, and it is filed rather than claimed.

**Not a scene-graph node**, despite the plan calling a volume "a scene-graph citizen with a
transform". It is a world-space AABB on the Scene, exactly as water is a world-Y level on the
Scene — neither needs a node, and an oriented box costs the shader a matrix per volume that nothing
has asked for.

## Phase 4 — fixtures, gates, and the D0 measurement

**Cloud shadows** need a fixture where the dapple is visible and deterministic. `cloud_fixture`
exists; a fog-plus-clouds variant gives a froxel volume for the shadow to land in. The arm asserts
the ground under a cloud is *darker than* the ground beside it — an in-frame ratio, not a stored
image.

**Local fog volumes** need a box over a known backdrop: the arm reads inside-box against
outside-box, and a second arm asserts the count-zero path is **0 px** against `--no-fog`.

**The measurement the roadmap asks for:** with cloud shadows live in the froxel volume, judge
whether the `pbr_frag` surface half is still worth a sampler unit and record the answer. That is
D2's stated exit condition, and it decides whether D0 gets scheduled.

### As built — seven arms

**`cloud-shadow`, on `aerial_fixture` with `--clouds --fog`.** The plan's arm — "the ground under a
cloud is darker than the ground beside it" — **does not exist to be written**, and finding that out
is the phase's main result. The froxel half shadows in-scattered light, so it lands where the sight
line crosses the most air: sky band RMSE 0.0353 against the ground's 0.0013. There is no ground
dapple to read. The arms read the sky band instead, across eight boxes:

| arm | measured | threshold |
|---|---|---|
| `cloudshadow-dark` — the deck removes light | shaded/lit **0.8469** | ≤ 0.99 |
| `cloudshadow-vary` — it removes DIFFERENT amounts | shortfall spread/mean **0.9013** | ≥ 0.15 |
| `cloudshadow-nofog` — no medium, no effect | **0 px** | 0 |

`cloudshadow-vary` is the load-bearing one and it is the arm that was missing from the plan. Every
plausible failure of this feature — a broken shear, an unbound texture, a wrap that clamps — returns
a CONSTANT, which still darkens the frame and still passes the first arm. Only the spread reads the
map's contents. `cloudshadow-nofog` also proves the extra 256² pass perturbs nothing on its own: it
is still built on that arm, and the frame is byte-identical.

**`fog-volume`, on the new `assets/fog_volume_fixture`.** One emissive backdrop, two boxes of equal
density differing only in tint, and a gap of bare backdrop between them that is the control:

| arm | measured | threshold |
|---|---|---|
| `fogvol-density` — a box reaches the medium | box/gap **0.5904** | ≤ 0.92 |
| `fogvol-neutral` — a white tint is an identity | spread **exactly 0.0000** | ≤ 0.01 |
| `fogvol-tint` — colour at fixed amount | B/R **0.9164** vs white's 1.0000 | ≤ 0.985 |
| `fogvol-off` — `--no-fog-volumes` releases the pass | box/gap **exactly 1.0000** | 1.0 ± 0.01 |

The two identities landing exactly is the useful part: a white tint changes nothing, and switching
the volumes off returns the frame to no medium — which also proves the volume ARMED the pass, since
this scene authors no global fog at all. `--no-fog-volumes` is new and is the only way off, since a
volume has no CLI counterpart to omit; `--no-water` set that precedent.

**The fixture runs 60 frames, not the suite's 30, and this is a real finding rather than a knob.**
At 30 frames two runs of ONE build differ by 3/255 across the whole frame; at 60 and 120 they are
byte-identical and the gap reads the exact no-medium value, so the transient is the froxel
accumulator settling. **The classic `--fog` arming is 0 px at 30 on the same scene**, so the
instability is specific to arming by a per-frame published count, and it is NOT explained. Filed
rather than guessed at — the mechanisms considered (σ exactly zero outside the boxes; the integrate
pass dividing; a skipped first frame) were each checked and none of them is it.

### The D0 verdict

**The surface half is still worth a unit, and the case is stronger than D2 assumed.** The roadmap
called the froxel half "where the visible payoff is". That is right about payoff per line and wrong
about *which* payoff: what ships is weather in the haze, and the moving dappled light on terrain —
the thing the entry actually promised — is entirely on the far side of D0, at a measured ground
RMSE of 0.0013. D0 is therefore not just a dependency of D1/D2's remainder; it is the only thing
between the engine and the look D2 was written to deliver.

## Verification

Baseline: **151/151 gate arms, 23/23 goldens 0 px** at `de171a9`.

- **Determinism is a hard gate here.** Every cloud golden claims byte-determinism ×2, and the wind
  clock rides `engine->render_delta`, which is fixed-step headless. Any wall-clock or
  non-frame-index randomness in the new pass breaks all of it.
- **Goldens at risk:** `cloud_fixture`, `cloud_fixture_lowsun`, `aerial_fixture`, `froxel_fog`.

## The review round — eight agents, and what they found

Two fanouts over `git diff master...HEAD`: four thermo-nuclear (structural code judo, boundaries,
duplication, GL lifecycle) and four `/simplify` (reuse, simplification, efficiency, altitude). The
second set was scoped off the first's ground so the two produced complementary findings.

**Three of them found the same defect, and it was real: local fog volumes were completely dead
under `--no-ssao`.** `postfx_wants_aux_gbuffer` carried the same medium union as the pass gate and
never gained the volume term; the atmosphere pass returns early without the aux buffer, so a scene
whose only medium is a volume never got the depth it indexes by. It worked only because GTAO
defaults on. **Every one of the four new arms passed over the top of it**, because none passed
`--no-ssao`. Fixed by making the union one predicate, `postfx_has_medium`, called from both sites —
and the arms now run without GTAO, so they test their own subject rather than riding on it.

That is the shape of most of what the round found: not wrong arithmetic, but **green results that
could not have gone red.**

| what was claimed | why it proved nothing |
|---|---|
| four gate arms on the volumes | none ran `--no-ssao`, so the feature could be dead and pass |
| "23 goldens 0 px" for the `fog_enabled` narrowing | no golden is submerged; the 0 px was guaranteed |
| `cloudshadow-nofog` "perturbs nothing" | about pixels only — the pass costs 0.20-0.32 ms and was never priced |
| the fixture reads the sigma-weighted fold | it authors no air, so the fold degenerates to `S *= tint` |

### The reframe

**The cloud shadow is not a fourth medium; it is a visibility term for one light.** Saying it that
way deleted a uniform, a per-cell divide, a magic `0.999` threshold, and a dot/step/mix. The shear
(`sun.xz / sun.y`) is a per-frame constant that was being recovered per froxel cell, and the sun is
now named by slot — `cloud_shadow_light`, with `-1` for "the sun is not in this list", a state a
direction compare cannot express at all.

Air likewise stopped being a special case: seeding the tint accumulator with `vec3(airSigma)` makes
the fold `S *= sigmaTint / sigma` with no reference to air at the combination site. Two reviewers
disagreed about the guard — one wanted it gone as bit-identical, one measured that removing it pays
a `vec3` divide on ~921,600 cells in the common no-volume case. Guarding on `localFogCount`, a
uniform, gets both: coherent branch, no cost when there are no volumes, NaN still caught.

### Two defects in the low-sun path

**A comment asserted something `sky.c` does not do.** It claimed `sky_apply_sun_to_light` clears
`cast_shadows` under ~3 degrees; it clears it at elevation <= 0 and merely *fades intensity* below
3. So between 0 and 2.87 degrees the sun was a live shadow-casting directional at up to 96% strength
while the map returned a uniform 1.0 — clouds stopped shadowing in a step, in a band `apps/tree`'s
0.8-degree default sits inside. Now a `smoothstep` ramp, and the comment says what the code does.
This is the house rule about never narrating another file's causal chain, broken exactly as the rule
predicts.

**And the march used the step schedule `clouds.glsl` explicitly rejects.** Uncapped, `span =
thickness / sinEl`, so at the floor `dt` reached ~2 km against an 8 km noise period — under four
samples per period, with every tap weighted by `dt`, so a single `d = 0.3` sample contributed
`tau ~ 15.6` and blacked the texel. `clouds.glsl:161` rejects precisely this for its own sun march.
Now capped at half the tile, with the cap deliberately set ABOVE the shell thickness so it cannot
truncate an overhead sun's vertical path. Verified at 5 degrees: signal present, mean 0.0179,
max 0.063, no speckle.

### Measured, and acted on

- **Binding texture 0 to a live sampler is slower than binding a real one** — 3.15 ms against
  4.12 ms on the atmosphere pass, with a coverage-0 control proving it is the bind and not the
  shading. This hit the pre-existing `--fog` path, not just the new feature. Now a 1x1 white R16F
  stand-in, which is also the transmittance identity.
- **The shadow build cost 2-3x the cloud march it rides on** and was 100% waste on `--clouds`
  without fog. Its inputs are camera-free by construction, and wind is still by default, so a
  400-frame run rebuilt a bit-identical texture 400 times. Now cached on an 8-float compare.
- **The `snprintf` uniform loop was NOT a cost problem** — three reviewers said switch, the one that
  measured found it runs once per frame at ~3 us, and that the value cache makes the per-element
  form issue *zero* GL calls for a static volume where the ranged form re-uploads every frame.
  Switched anyway, for consistency with the block eight lines below and to become eligible for
  `warn_if_array_shorter`, but **not for speed** — it is marginally slower.

### Filed, not fixed

- **No arm can see the sigma-weighted combination.** The obvious repair fails, and the reason is
  recorded in `gates.py`: adding global fog dilutes the source function toward white AND raises the
  strip's optical depth so more of the pixel is tinted in-scatter, and the second effect dominates
  and moves the read the wrong way. Measured 0.9159 with no air against 0.8917 with air. A valid
  instrument must hold the depth mix fixed while varying only the air fraction, which this fixture's
  geometry cannot express. Two attempts at a bound were derived wrongly before this was understood;
  a third guess would have been worse than the gap.
- A submerged fixture, for the `fog_enabled` narrowing above.
- The debug tile for the shadow map: `sky_debug_draw` already serves three sky LUTs, the cloud noise
  and the GI atlas, and this is the only 2D LUT in the stack with no viewer.
- `fog_volume.h/.c` as its own module, so the GPU packing leaves `scene.c`.

**158/158 gate arms, 23/23 goldens 0 px** across the whole round.
