# Spec 11.40 — closing 11.39's four filed items

## Context

Spec 11.39 (cloud shadows + local fog volumes) merged to master at `099a6e8`, 158/158 gate arms
and 23/23 goldens. Its review round — eight agents — left four items filed rather than fixed. Two
are genuine holes where something shipped is unguarded or unmeasured; one is a missing diagnostic;
one, on investigation, **should not be done at all** and needs closing with a record instead.

The through-line of that review was not wrong arithmetic. It was **green results that could not
have gone red** — four gate arms that passed over a feature dead under `--no-ssao`, a 23-golden run
cited as evidence for a change no golden could see. Three of the four items below are the remaining
instances of exactly that, so this spec is about making existing claims falsifiable rather than
adding behaviour.

State: `master` at `099a6e8`, clean, and pushed — `origin/master` is at the same commit.

## Item 1 — an arm that can see the σ-weighted fold

**The hole.** `froxel_inject_frag.glsl:379` combines media as `S *= sigmaTint / sigma`, where
`sigmaTint = vec3(airSigma) + Σ tint_i·σ_i`. The spec calls this "the part with a real trap" —
adding radiances instead would count the light once per medium. But `fog_volume_fixture` authors no
global fog, so `airSigma == 0` in every cell and the fold degenerates to `S *= tint` **exactly**.
A plain multiply — the implementation the spec argues against — passes all four arms identically.

**Why the obvious repair failed** (measured, recorded at `gates.py:2948-2963`): adding global fog
changes two things at once. It dilutes the source function toward white, and it raises the strip's
optical depth so more of the pixel is tinted in-scatter and less is untinted backdrop. At air ≈ box
density the second effect wins and the read moves the *wrong* way — B/R rel 0.9159 with no air
against 0.8917 with air.

**The approach, cheapest first.**

**1a. Push air far above the box density instead of near it.** The two effects scale differently.
At `--fog-density 2.0` against `BOX_DENSITY 0.5` the box is 20% of the medium, so the σ-weighted
fold predicts a tint excursion roughly a fifth of the no-air one, while a plain multiply predicts
the *same* excursion regardless. Push further and the backdrop stops contributing at all
(transmittance → 0), which removes the depth-mix confound entirely because both strips become pure
in-scatter. Exploration confirms the knobs are exact: `--fog-density D` is used verbatim and
self-implies `--fog` (`render.c:837-843`), and `--fog-height 1e6` drives the exponential profile
asymptotically flat over the fixture's ~5-unit Y span (`froxel_inject_frag.glsl:222`).

Sweep density on the existing fixture, find a value where the box still registers but air dominates,
and assert the tint excursion **shrinks in proportion to the box's σ share**. That single assertion
fails a plain multiply, which predicts no shrink.

**1b. Fall back to matched total σ if 1a cannot separate them.** Two `.cscn` variants from the same
generator with the *same* total extinction — air 0 / box D, against air D/2 / box D/2 — so
transmittance and therefore the depth mix are identical and only the dilution differs. Requires the
box to span the full camera-to-backdrop depth so no part of the ray sits outside it
(`BOX_HALF_Z 0.6` today, needs ~3.5), which is a generator change, not new machinery.

**Caveat found in exploration:** `fog_floor_y` is **not CLI-settable** and for this fixture is
−3.0, not 0 — `scene_floor_y = bb_min[1]`, and a `.cscn` forces `no_recenter` so there is no offset
(`render.c:2564`, `cscene_apply.c:69`). Below that Y the density term is hard-zero
(`froxel_inject_frag.glsl:222`). The measured strips sit well above it; downward rays do cross it,
so the discontinuity must not be allowed to reach a read band.

**Files:** `scripts/gates.py` (the arm + constants), possibly `assets/gen_fog_volume_fixture.py`.

## Item 2 — a submerged golden, so the `fog_enabled` narrowing is measurable at all

**The hole.** `postfx.c:2184` now uploads the global density as `fog_enabled ? fog_density : 0.0f`.
That can only move frames where `fog_enabled == false && water_medium != 0` — a submerged camera.
`water_fixture`'s eye is at y 1.35 above a level of 0.0, so **no golden is submerged** and the 0 px
result I cited as evidence was guaranteed whatever the change did. The behaviour that actually
changed is real and is a fix (`fog_density` defaults to 0.02, so before this every submerged frame
carried unrequested air haze above the waterline) and it remains unmeasured.

**The approach.** A `water_submerged` sibling recipe in `scripts/goldens.py`, on the existing
`assets/water_fixture.cscn`, using the configuration **already proven to render** by the gate arms:
`--water-level 1.9` puts the still plane above the fixed eye (`gates.py:3193`, justified
geometrically at `:3183-3192`). `cloud_fixture` / `cloud_fixture_lowsun` are the precedent for two
recipes on one scene (`goldens.py:63-68`).

A golden rather than a gate arm, deliberately: the claim is "this frame does not carry haze the app
never asked for", which is a cross-build statement, and a stored image is the only instrument that
catches a future re-widening of the density upload.

**Two decisions exploration surfaced:**
- The existing submerged *gate* arms pass `--no-shadows` because this fixture's sky puts a shadow
  catcher over ~62% of the frame; the existing `water_fixture` golden does not. The sibling should
  match the golden's flags, not the gate's, so the two goldens differ in one variable.
- `goldens.py --rebake` refuses any recipe whose two renders differ by even 1 px (`:270-277`), and
  the submerged path arms the froxel volume, which no golden currently exercises. **Determinism ×2
  must be measured before baking**, and the frame count raised if 30 is not enough — 11.39 found
  the volume-armed route unstable at 30 frames while the `--fog` route was stable.

**Files:** `scripts/goldens.py`, plus a baked `assets/water_submerged_golden.png`.

## Item 3 — a debug tile for the cloud shadow map

**The hole.** `sky_debug_draw` already serves three sky LUTs, and `sky_debug_draw_noise` the two
cloud noise volumes (`sky.c:702-744`); `gi_volume_debug_blit` reuses the same program
cross-subsystem. The cloud shadow map is the only 2D LUT in the atmosphere stack with no viewer, so
when `cloudshadow-vary` fails there is no way to tell a bad map from a bad lookup — which is exactly
the bisect `--no-cloud-shadows` was added to support, stopping one step short.

**The blocker, and the one real decision here.** `sky_debug_frag.glsl:15` is
`texture(lut, TexCoords).rgb * scale` with no swizzle, and the shadow map is `GL_R16F` / `GL_RED`
(`sky_clouds.c:236-237`). It would render as a **red-only** tile, not grayscale. The shader is
shared by `--sky-debug` and `--gi-debug` and its own comment (`:5-7`) asks that it stay free of
consumer-specific code.

**The approach.** Add a `mono` uniform to `sky_debug_frag.glsl`, defaulting to 0, that replicates
red across the tile. That describes the *texture* rather than either consumer, so it respects the
shader's stated constraint — and `cloud_noise_debug_frag.glsl:16` already establishes single-channel
grayscale display as the house reading for scalar fields. Then one `sky_debug_draw` call inside the
existing `sky_debug_blit_luts` block, gated on `clouds.shadow_tex` being live.

Layout: column 1 is occupied to `H-502` and column 2 to `H-404`, so a 256² tile at `x = 532`,
`y = H-670` (below the detail tile) fits without overlap. `scale = 1.0` — the values are
transmittance in [0,1].

**Files:** `cetra/shaders/sky_debug_frag.glsl`, `cetra/src/sky.c`.

## Item 4 — **do NOT move the packing; close it with a record**

The review flagged that `scene_publish_fog_volumes_to_postfx` encodes the froxel shader's vec4
layout inside `scene.c`, and proposed three different fixes: a `fog_volume.h/.c` module, moving the
pack into `postfx.c`, or leaving it. **Exploration says the third was right and the second would
actively make things worse.**

- `postfx.c` includes `stdio/stdlib/postfx.h/profiler/texture/uniform/util/log`, and **none of them
  reaches `scene.h` transitively**. It has zero visibility of anything scene-side. Moving the pack
  in would require postfx.c to include `scene.h`, inverting the exact dependency the publish block
  is built on — `engine.c:1752` states the intent as "without postfx learning about Scene".
- `shadow_publish_to_postfx` (`shadow.c:1494`) **packs GPU layouts more aggressively than mine**: it
  builds the clustered path's `x = 1/range²` attenuation vec3 (`:1507-1514`) and computes the
  flattened cascade stride `layer = slot * cc + c` (`:1552-1554`), preceded by three
  `_Static_assert`s in exactly the shape `scene.c:406` uses. It lives in the producer and includes
  `scene.h`.

So the current shape is the **conventional** one for this codebase, with a direct precedent. The
work here is to record that in the spec and drop it from the roadmap's open list, so the next
reviewer does not re-raise it.

**Files:** `specs/11.40-*.md`, and the 11.39 spec's filed list.

## Verification

- **Item 1:** the new arm must FAIL against a deliberately broken shader — temporarily replace the
  fold with `S *= tint` and confirm red, then restore. An arm that has never been seen to fail is
  the failure mode this whole spec exists to address.
- **Item 2:** determinism ×2 at the chosen frame count BEFORE `--rebake`; `--rebake` enforces it
  anyway, but measuring first tells us the frame count rather than the tool refusing.
- **Item 3:** visual — the tile must show a recognisable cloud pattern, not a flat field. Confirm it
  costs 0 px when `--sky-debug` is absent.
- **Item 4:** no code change; verification is that the reasoning is written down.
- Full suite after each item: gates and goldens, no other GPU work alongside. Baseline to beat is
  **158/158 arms, 23/23 goldens 0 px**. Items 1-3 add arms/goldens; no existing one should move.
  `prepass-crossover` is the known-flaky timing arm.
