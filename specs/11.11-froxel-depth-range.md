# Give the fog volume its own depth range and distribution

## Context

The spores flashlight shows hard blocky facets at the beam, and turning fog off in the
GUI removes them. The froxel machinery itself is standard and intact -- lighting once
per cell, Halton jitter inside the cell, reprojection off the unjittered centre,
`mix(result, history, 0.9)` -- which is exactly the Wronski/Frostbite design. Our grid
is 160x90x64, which IS Frostbite's shipped froxel resolution, so the grid is not
undersized.

What is wrong is **where the slices land**. `include/froxel.glsl` distributes them
exponentially between `nearZ` and `fogFar`:

```
z(s) = near * pow(fogFar/near, s / slices)
```

and every froxel shader recovers `nearZ` from the projection matrix -- the CAMERA's
near plane. spores sets `set_camera_perspective(cam, 0.9f, 0.1f, 200.0f)`, so near is
0.1 against a `fog_far` of 40. Exponential means equal depth RATIOS get equal slices,
so:

| slices | depth covered |
|---|---|
| 0 -> 32 | 0.1 -> 2.0 u |
| 56.6 -> 64 | 20 -> 40 u |

Half the volume's depth resolution is spent on air in the first 2 units in front of the
lens. The camera sits ~24 u out, so the room and the whole beam get **about 7 slices**,
each ~3 u thick. A 2-degree cone penumbra has nowhere to be placed. That is also why a
wide cone hides it (the feature grows past the cell) and why no clamp, shadow flag or
intensity change moved it -- none of them touch slice placement.

`froxel.glsl` already makes this exact argument, but only at the far end:

> Depth range is [near, fogFar], not [near, far]: fog is a short-range effect, so
> spending slices out to the camera far plane would waste almost all of them on air the
> fog never reaches.

Right reasoning, applied at one end. The camera's near plane is a triangle-z-precision
concern; UE and Frostbite both treat the volume's depth range as a property of the fog.
UE additionally ships `r.VolumetricFog.DepthDistributionScale` precisely so the curve
can be biased without giving up close-range fog.

**Status: this diagnosis is arithmetic read off the code, and is NOT yet proven to cause
the artifact.** Three earlier hypotheses this session (temporal disocclusion, the
`WS_MEDIA_MAX` clamp, bloom) were each disproved by measurement. Phase 1 below exists to
prove or kill this one before any further work lands.

## Phase 1 -- prove it first

Add `fog_near` only, as a `PostFX` field, and thread it through the three froxel
shaders in place of the projection-recovered `nearZ`. Set it to ~2.0 for spores, render
at the reported camera:

```
--cam-eye 14.467,12.566,-14.330 --cam-target 0,4,0 --fov 51.6
```

(currently hardcoded into `spores.c:205-206` as a diagnostic; before/after crops live in
the session scratchpad as `usercam.ppm`).

**If the blocks do not visibly change, stop and re-diagnose. Do not proceed to phase 2.**

## Phase 2 -- the parameters

### PostFX fields (`cetra/src/postfx.h`, beside `fog_far` at :242)

| field | meaning | default |
|---|---|---|
| `fog_near` | volume front face, in world units | `0` = derive as `fog_far/50` |
| `fog_depth_distribution` | slice bias exponent `k` | `1.0` = today's curve |
| `froxel_grid_x/y/z` | grid dims, promoted from the `#define`s at :84-86 | 160 / 90 / 64 |
| `fog_temporal_blend` | history weight, currently the literal `0.9` in the inject shader | `0.9` |

`fog_near = 0` meaning "derive" mirrors the `light->range = 0` convention already in
`light.h`, so existing scenes improve without being edited.

### The distribution function (`cetra/shaders/include/froxel.glsl`)

Generalise the mapping with one exponent, chosen so `k = 1` reproduces today exactly and
both directions stay cheap and invertible:

```
forward:  t = s/N;  z = near * pow(far/near, pow(t, k))
inverse:  t = log(z/near)/log(far/near);  s = N * pow(t, 1/k)
```

`k > 1` pushes slices toward the far end, `k < 1` toward the camera.

Signatures gain `near`/`k` explicitly rather than reading a global:
`froxelSliceToViewZ`, `froxelViewZToSlice`, `froxelViewPos`, `froxelSampleMedium`.

### The trap: aerial perspective must NOT inherit the fog's near

`aerial_lut_frag.glsl:38` builds the aerial volume from the camera near, and
`froxel_composite_frag.glsl:59-64` currently passes **one** `nearZ` to both
`froxelSampleMedium` calls. Once fog owns its near, the composite must pass fog's near +
`k` for the fog volume and the camera near + `k = 1` for the aerial volume. Getting this
wrong makes aerial perspective silently sample the wrong slices -- it will not error, it
will just read as haze at the wrong distance.

### Grid dims at runtime

`postfx_ensure_froxel_targets` allocates the volumes and `971aa9b` already split
teardown from forgetting-they-existed, so a dimension change reallocates through the
existing seam. The `#define`s stay as the defaults the fields initialise from.

### GUI (`engine.c:2031-2043`, the "Volumetric Fog" group)

Add sliders for near, distribution, temporal blend, and the grid dims, beside the
existing density/anisotropy/ambient. This is how the artifact gets swept interactively
rather than through a rebuild per value.

## Phase 3 -- the .cscn schema and files

Scene files currently expose only `enabled` / `density` / `anisotropy` / `ambient`
(`cscene.c:305-314`). Add the depth-geometry trio: **`near`, `far`, `depthDistribution`**.

Grid dims deliberately stay OUT of `.cscn` -- they are a quality setting like MSAA, not a
property of the scene.

The established route for a scene fog field is five files, following `fog_density`:
`cscene.h` (value + `has_` flag) -> `cscene.c` (`get_float`) -> `cscene_apply.c` (into
`args`, guarded so CLI wins) -> `render_args.h` -> `render.c` (args onto PostFX).

Then add the new keys to the three files that define fog:

- `assets/froxel_scale_fixture.cscn`
- `assets/postfx_convergence_fixture.cscn`
- `assets/abandoned_window/abandoned_window.cscn`

## Verification

**The artifact** -- phase 1's render at the reported camera, compared against
`usercam.ppm`. Blocks gone at the unchanged 18->20 degree cutoff. The cone must not be
widened; widening it is the masking fix this plan exists to avoid.

**Aerial not disturbed** -- render a sky+aerial scene before and after. With fog off the
aerial path must be **0 px** changed; that is the check that the two-near split in the
composite is right.

**Goldens will move, legitimately** -- every fog-lit fixture re-distributes its slices.
Diff first (`magick compare -metric AE`), confirm the delta is confined to fogged
regions, then re-bake `froxel_fog_golden.png` and any fixture above that uses fog.

**Gates** -- `python3 scripts/gates.py`. The `fog` scale-invariance gate runs
`froxel_scale_fixture.cscn`, which this plan edits, so it is both a regression check and
a thing whose baseline may legitimately shift. It currently passes at 3 px.

**Determinism** -- spores headless x2 at the same frame count must stay 0 px; slice
placement is frame-independent so this should be untouched.

## Out of scope

- `HistoryMissSupersampleCount` (UE's disocclusion supersample). A real algorithmic
  addition, not a parameter, and unrelated to slice placement.
- The remaining unexposed look params (`heightFalloff`, `floorY`, `sunBoost`) in `.cscn`.
  They are look knobs, not grid geometry; worth doing, but a separate mechanical pass.
- `fog_sun_boost` being an "artistic multiplier" where Frostbite has a physical
  scattering albedo. A media-model change, its own spec.
