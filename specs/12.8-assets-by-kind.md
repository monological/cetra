# Spec 12.8 — Reorganise `assets/` by file kind

## Context

`assets/` holds **255 top-level files** in one flat directory: 64 `.cscn`, 61 `.gltf`, 58
`.png` (33 of them goldens), 54 `gen_*.py`, plus `.fbx`, `.ies`, `.cube` and one `.r16`.
It is no longer scannable — finding the four files belonging to one fixture means reading
255 names, and adding a fixture means adding four more to the same pile.

The chosen layout is **by file kind**: `scenes/`, `models/`, `textures/`, `goldens/`,
`generators/`, `lut/`, `ies/`, `data/`.

**The thing that makes this risky is not the moving.** Every failure mode in both
verification suites is a silent `SKIP`, never a `FAIL`:

- `goldens.py:441` prints `SKIP no golden committed` when a golden PNG is not where it
  expects — a moved golden reads as "not baked yet".
- `gates.py` prints `SKIP (missing …)` throughout (`:15578`, `:610`, `:1052`).
- `run_fixture_gen_gate` discovers generators with a **non-recursive**
  `glob.glob("<ROOT>/assets/gen_*.py")` (`gates.py:17224`) and **asserts nothing about the
  count**. Move the generators and the gate finds zero, compares nothing, and prints
  **PASS**.

So a reorganisation that silently deletes most of the corpus's coverage would leave both
suites green. **Phase 0 exists to close that before a single file moves.**

## Target layout

```
assets/
  scenes/      64  *.cscn
  models/      61  *.gltf, 7 *.fbx, and the two assimp sidecars c64.fbm/ room.fbm/
  textures/    25  *.png that are generator inputs / fixture maps
  goldens/     33  *_golden.png  + area_light_goldens.md
  generators/  54  gen_*.py      + fixture_paths.py (new)
  lut/          4  *.cube
  ies/          5  *.ies
  data/         1  terrain_fixture.r16
  abandoned_window/  ivy_arcade/  raiden/      <- self-contained, UNCHANGED
```

`c64.fbm/` and `room.fbm/` are assimp's sidecar convention, bound to `c64.fbx` / `room.fbx`
**by basename**. They move with their model or the model silently loses its skin; nothing in
any source file expresses that coupling (only `README.md:211` documents it).

## The four couplings that must be handled

**1. Generators resolve output against `__file__`.** All 54 use
`os.path.dirname(os.path.abspath(__file__))`; none writes outside its own directory. That is
deliberate — `run_fixture_gen_gate`'s docstring states it is what lets the gate sandbox a
generator by copying it into a scratch tree. So the fix must stay `__file__`-relative:

Add `assets/generators/fixture_paths.py`, one small module:

```python
# Route an emitted asset to its kind directory, relative to THIS file, so a
# generator copied into a scratch tree still writes inside that tree.
HERE = os.path.dirname(os.path.abspath(__file__))
KIND = {".gltf": "models", ".cscn": "scenes", ".png": "textures",
        ".cube": "lut", ".ies": "ies", ".r16": "data", ".fbx": "models"}
def out_path(filename):
    return os.path.join(HERE, os.pardir, KIND[os.path.splitext(filename)[1]], filename)
```

Each generator's output join becomes `out_path("foo.gltf")`. Mechanical, one or two lines
each. Three generators also read *sibling inputs* (`gen_hair_fixture.py:57`,
`gen_texcomp_fixture.py:229`, `gen_cornell_rooms.py:432`) — those take an `in_path` of the
same shape.

**2. Three generators reach outside `assets/` with `..`** — `gen_hair_fixture.py:96` and
`gen_ies_fixture.py:135` load a module from `../tools`, `gen_purkinje_fixture.py:77,105`
reads `../cetra/shaders/include`. One directory deeper means `../..`. Only these three.

**3. glTF image URIs are bare siblings** (`parallax_fixture.gltf:14`). The committed bytes do
**not** change; `find_existing_subpath` (`util.c:309`) probes *under* the texture-pool
directory and cannot climb out of `models/`. Fix is a `-t <ROOT>/assets/textures` argument in
the three render helpers — `goldens.py:_render` (`:390`), `gates.py:render` (`:224`),
`gates.py:_run` (`:281`). `.cscn` material textures already resolve through the same pool, so
they are covered by the same flag; `.cscn` **model / env-hdr / IES / LUT** paths resolve
against the scene file's own directory (`cscene.c:1293-1317`) and so must be rewritten from
bare names to `../models/x.gltf`, `../lut/x.cube`, `../ies/x.ies`.

**4. A model and its `.cscn` must share a directory and stem** — `cscene_apply.c:34-56`
auto-loads `<model>.cscn` beside a bare model. Splitting `scenes/` from `models/` **breaks
that auto-load**. Every affected gates/goldens invocation already names the `.cscn`
explicitly with `-m`, so the auto-load path is only used interactively; record it as a
deliberate loss in the spec and in `docs/cli-reference.md`, or pass the `.cscn` directly.

## Phases

Each phase ends with the suites green; each is independently revertable. Use `git mv`
throughout so history follows the files.

**Phase 0 — harden the instruments (no files move).**
- `run_fixture_gen_gate`: assert the generator count is what the tree holds, and that
  `compared` and `binary` are non-zero. A gate that finds nothing must FAIL, not PASS.
- `goldens.py:cmd_check`: a missing golden becomes a FAIL, not a SKIP, unless a new
  `--allow-missing` is passed for a genuinely unbaked recipe.
- Run both suites; confirm still green. This phase is worth keeping whatever happens next.

**Phase 1 — `goldens/`.** 33 PNGs + `area_light_goldens.md`. One line: `goldens.py:349`
`golden_path`. Nothing else references a golden by path. Smallest possible proof that
Phase 0's assertions bite.

**Phase 2 — `generators/`.** Move the 54, add `fixture_paths.py`, update each generator's
output join, fix the three `..` depths, and rework `run_fixture_gen_gate`:
discovery glob → `assets/generators/gen_*.py`; input collection → `assets/textures/*.png`;
the scratch mirror must **preserve directory structure** rather than flattening
(`shutil.copy2` into a mirrored subtree); write-detection → `os.walk` rather than
`os.listdir`; comparison → route the emitted basename to its kind directory.
Also `_import_fixture_gen` (`gates.py:19137`) and `FOGDEPTH_GEN` (`:7845`), and the
`gen_water_fixture.py` out-dir call at `gates.py:10341`.

**Phase 3 — the asset kinds.** `scenes/`, `models/` (+ the two `.fbm` sidecars),
`textures/`, `lut/`, `ies/`, `data/`. Add the `-t` flag to the three render helpers. Rewrite
the `.cscn` model/IES/LUT paths to `../<kind>/<file>` — note these are **generator outputs**,
so the generators emit the new form and `fixture-gen` proves all 64 reproduce byte-identically.

**Phase 4 — the reference sweep.** ~182 `assets` references in `gates.py` (155 inline
`os.path.join(ROOT, "assets", X)`, ~60 bare-filename constants, 8 raw `"assets/..."`
literals at `:129-134`, `:14930`, `:15894-15896`, 4 directory uses), 31 `scene` strings in
`goldens.py`, and the C literals: `gametest.c:93` (`assets/puppet.gltf`), `gametest.c:3953`
(`assets/strut_walk.fbx`). Opportunistically fix `shapes.c:21`, whose
`"./models/room.fbx"` names a directory that does not exist.

**Phase 5 — docs.** `docs/verification.md` (44 lines, including the whole per-asset ledger
`:205-247`), `AGENTS.md:1339,1443,1486`, `docs/cli-reference.md`, `README.md:211`,
`docs/build-vms.md`, `.gitignore`'s two `assets/ivy_arcade/` rules and their comment.

**`specs/*.md` are NOT rewritten** — 341 references across ~120 files. A spec is a record of
what was true when it was written; rewriting the paths would falsify that record. State the
rename once in the new spec and leave history alone.

## Verification

Per phase:

```bash
python3 scripts/gates.py --only fixture-gen     # the phase-0 assertions are the instrument
python3 scripts/gates.py --only gate-docs       # docstring/arm order still matches
python3 scripts/goldens.py                      # all 33; menu/menu_focus flake, re-run before believing
```

End of job:

```bash
./build.sh
python3 scripts/gates.py                        # full suite, ~7 min
python3 scripts/goldens.py
grep -rn "assets/[a-z_]*\.\(gltf\|cscn\|png\|fbx\|cube\|ies\)" scripts apps cetra docs AGENTS.md
```

The last grep is the "nothing stale" check — every surviving match must name a path that
exists. **A green suite is not sufficient evidence on its own** given how much of this
degrades to SKIP: read `fixture-gen`'s printed counts (expect 54 generators, 108 text
assets, 27 binary) and `goldens.py`'s count of compared images (expect 33, zero skipped).
Those two numbers are what prove the corpus did not shrink.
