# 11.49 — Emissive geometry becomes an LTC area light (roadmap C2)

## Context

An emissive mesh lights nothing today. It is bright in the frame, it feeds bloom, and its only
path into the lighting solution is a 16²-face DDGI capture that converges over seconds and
resolves no detail. Practicals, screens, strip lights and neon — the entire vocabulary of
interior lighting — are therefore decorative.

C2 is the last unbuilt entry in the roadmap's own five-item shortlist and the only one that
needs nothing from Wall 1. It is a **fit plus a registration**: plane-fit an emissive mesh's
dominant quad, convert its emissive to a radiance, and hand the result to the packed light array
A1 already uploads. `Light` (`light.h:33-86`) carries every field the fit produces — `position`,
`direction` (panel normal), `up`, `size`, and an `intensity` whose canonical unit for
`LIGHT_AREA` is already **nits**.

**This feature touches no shader.** `ltcPanel` (`include/ltc.glsl:122`) and the area branch in
`pbr_frag.glsl:1584-1649` already shade any panel that arrives through the cluster list. So a
scene with no emissive material is byte-identical by construction, and the off-gate is a CPU
early-out rather than a shader claim.

### The finding that shapes the verification

`assets/cornell_box.gltf` already contains this feature's ground truth, and the fixture says so
out loud — `gen_cornell_rooms.py:141` calls the emissive quad "the source" and notes "the .cscn
area light mirrors it".

| | emissive quad (`cornell_light`) | authored `.cscn` area light |
|---|---|---|
| centre | (0, 1.97, 0) | `[0.0, 1.97, 0.0]` |
| normal | −Y | `[0, -1, 0]` |
| size | 0.7 × 0.7 | `[0.7, 0.7]` |
| colour | `emissiveFactor [1.0, 0.95, 0.88]` | `[1.0, 0.95, 0.88]` |
| radiance | ~**1.0** nit | `intensity` **18.0** |

**The geometry is exactly derivable and the radiance is off by 18×.** That is not a bug in
either — the quad's emissive was authored for how the source *looks* and the light for how the
room *reads*, and nothing ever forced them to agree. It is the calibration this item has to
state rather than discover later, and it means "does the derived frame match the golden" is the
wrong acceptance test. The right one is an A/B where the only variable is **who created the
light**, with both sides at the same radiance.

### Corrected after review, before any code

Two things in the first draft were reasoned from the fit's side and were wrong. Both are kept
visible below rather than quietly replaced, because the second one is the more useful finding.

1. **Derived panels were going into a private array.** They are ordinary `scene->lights` entries.
   The private array made them invisible to `find_light_by_name`, the GUI, the light overlay, the
   shadow assignment and — decisively — to `light_overrides`.
2. **Shadows were going on the material.** They go on `light_overrides`, which already exists and
   is already per-lamp. Materials are deduped at import, so a material key is a per-lamp-*type*
   decision and cannot express "this one casts".

`specs/11.49-…` was committed with the first draft and needs amending to match.

## What ships

- Every emissive mesh that fits a rectangle gets an LTC panel, **on by default**, with
  `--no-emissive-lights` as the escape hatch (the `--no-water` / `--no-fog-volumes` idiom).
- One new material key, `emissiveLight`, an INT enum with **two** states — the `windMode`
  precedent at `material.c:83-85`:

  | value | name | meaning |
  |---|---|---|
  | 0 | `light` | derive a panel (default, and calloc-safe) |
  | 1 | `off` | emit visually, light nothing |

  Adding a row to `MATERIAL_PARAMS` (`material.c:41-85`) buys `.cscn` authoring **and** an
  ImGui control in one edit. Note this retires a stale claim in CLAUDE.md — that table already
  carries ~25 keys including `emissive` and `emissiveStrength`, not "only sss and windResponse".
- **Enum labels become authorable as strings**, so a fixture reads `"emissiveLight": "off"`
  rather than `"emissiveLight": 1`. Today a string in a material block is routed to
  `CSceneMaterialTexture` and `cscene_apply.c:480-486` rejects it as "not a texture key" — the
  key and the string are both already there, so this is one branch at that existing type check:
  an INT row with `enum_labels` matches the string against them first. `windMode` gets it too.
  `CSCENE_MAX_MATERIAL_TEXTURES` rises from 2, since a label string occupies a texture slot.
- `--emissive-light-probe`, which prints every derived panel and is what the gate reads.

## Design

### The fit runs in LOCAL space once, and is transformed per frame

The expensive half (a plane fit over every vertex) is gated on `scene_graph_epoch()`
(`draw_list.h:115`) — the existing primitive, bumped by exactly the mutations that would
invalidate a fit. The cheap half (three vector transforms through the node's
`global_transform`) runs every frame.

That is strictly better than the roadmap's sketch, which proposed a static fit at load and
excluding animated emitters: **a lamp on a moving node works, for free**, because the epoch does
not bump on a transform change and does not need to. It also settles where the fit hooks in.
Derived lights are *not* attached to a `SceneNode`, so `apply_transform_to_nodes`
(`scene.c:808-861`, which rotates `original_direction` → `direction` only for `node->light`)
never sees them — they get `global_position` / `direction` / `up` written directly in world
space.

### Where it hooks

`render.c:1041-1054`, between `engine_build_draw_list` and `light_cluster_build_and_upload`.
Transforms are current there (the app's `apply_transform_to_nodes` has already run inside its
render callback), the flattened `DrawList` is the walk to iterate, and it is immediately
upstream of the only consumer. Doing it in `scene_sync_materials` instead would read **last
frame's transforms** — the same latent bug the roadmap books under "shadows read last frame's
transforms".

### The fit itself

Per mesh, over triangles in local space:

1. **Area-weighted normal** `n = Σ nᵢAᵢ`, **area-weighted centroid** `c = Σ cᵢAᵢ / Σ Aᵢ`.
2. **Planarity** `|Σ nᵢAᵢ| / Σ Aᵢ` — exactly 1 for a flat quad, ~0 for a closed emissive box.
   One number that rejects everything a rectangle cannot describe. Below ~0.9, skip and log:
   a glowing cube and a curved neon tube are both out, which is the v1 limit the roadmap already
   states, now with a test behind it rather than an assumption.
3. **In-plane orientation** from the 2×2 covariance of the projected vertices, closed form. This
   is what makes a diagonal strip light fit tightly instead of getting an oversized
   axis-aligned box.
4. **Extents** from the projected min/max along those two axes.

Roughly 120 lines, cglm only, no new dependency.

### Radiance → intensity

`render.c:154-161` already computes the emitted radiance: `emissive_hdr = emissive ×
emissive_strength`, uploaded as `emissiveFactor`, and `pbr_frag.glsl:2147` multiplies it by
`preExposure` — so **emissive is scene radiance, i.e. nits**, the same space `LIGHT_AREA`
intensity lives in. The conversion is therefore a split, not a guess:

```
intensity = 0.2126·R + 0.7152·G + 0.0722·B     // photometric luminance, real nits
color     = emissive_hdr / intensity           // unit-luminance tint
```

`color × intensity` reconstructs `emissive_hdr` exactly (`_pack_cluster_light` premultiplies at
`light_cluster.c:212`), and `intensity` reads as a number an author can check against a
datasheet — which is what 9.9/10.0 bought and what a `color = emissive_hdr, intensity = 1`
shortcut would throw away.

**Emissive textures**: `Texture` (`texture.h:13-31`) keeps no CPU pixels, but material textures
already get `glGenerateMipmap` (`texture.c:473, 544`), so the **1×1 top mip IS the mean colour**
— one `glGetTexImage` at the last level, once per material at fit time, never per frame. Without
it a mostly-black emissive atlas under a bright factor over-lights by the ratio, which is most
real screen and sign content.

### Storage and ownership — CORRECTED, and the correction is the interesting part

**An earlier draft of this plan put derived panels in a private `scene->emissive_lights[]`
array**, by value, to avoid needing a removal API on `scene->lights` (which has none). That was
reasoned from the fit's side and it is wrong, because it makes derived lights invisible to
everything that already knows how to talk about a light. The cost list is what settles it: a
second loop in `_gather_lights`, a second loop in `find_light_by_name`, no GUI row, no
`--show-lights` overlay, no shadow assignment, and — the one that actually bites — **no reach
from `light_overrides`**, which is the block that already exists for saying "this light casts".

**Derived panels are ordinary `Light` objects in `scene->lights`.** Then every one of those
paths works with no new code, and what it costs instead is a removal API and a reconcile, which
is the smaller and more honest half of the trade.

- **Identity**: `Light.emissive_source_id`, the source mesh's `id` (`mesh.h`: "Creation order …
  Assigned once and never reused") — the stable key the reconcile needs, and *not* a `Mesh*`,
  which is dangling by the time the epoch tells us the mesh is gone. 0 means "authored", so
  nothing the reconcile does can touch a hand-made light.
- **Name**: the owning node's name. `import.c:1626` names imported nodes from the file, and the
  cornell glTF names its node `cornell_light` (`gen_cornell_rooms.py:281`), so a derived panel is
  addressable the moment it exists.
- **Reconcile, not rebuild**: add for emissive meshes with no light, remove for lights whose
  mesh is gone, keep and re-place the rest. A surviving light is the *same object*, so anything
  set on it — an override included — persists across a graph change. Removal shifts rather than
  swaps, because `_gather_lights` documents its walk order as what makes packing deterministic.

Skip thresholds, each with a stated reason: planarity < 0.9 (not a rectangle), area ≤ 0 (nothing
to emit from), luminance < 1e-3 nits (cannot light anything, and would still cost a cluster
slot). Overflow past `LC_MAX_CLUSTER_LIGHTS` (128) is already logged by `light_cluster.c:258`.

### `remove_light_from_scene` — the missing half of an API, not an emissive-specific hook

`add_light_to_scene` (`scene.c:285-300`) has no counterpart. A light can go in and never come
out, which is why the first draft reached for a private array instead: it dodged writing this.
The dodge cost five integration points, so the function gets written.

```c
// Unlink and free. The Scene owns its lights (free_scene at scene.c:100), so an
// unlink-only form would leak by default, which is the wrong default for the one
// caller that removes anything at all.
int remove_light_from_scene(Scene* scene, Light* light);
```

**Order-preserving, and that is load-bearing rather than tidy.** `light_cluster.c:243` states
its walk order as what makes the packing — and so the shading loop order — deterministic, and
every 0-px golden rests on that. So removal SHIFTS the tail down; a swap-with-last would
reorder the light list on any graph change and move pixels for no reason anyone could find.

**The hazard, stated rather than defended against.** A `SceneNode` *borrows* a light and does
not free it, so removing one a node still points at leaves `node->light` dangling. This is the
mirror of the invariant the particle system already carries ("never free a `SceneNode` whose
particle system is still registered on the `Scene`"), and it goes in `scene.h` in the same
shape. Walking the graph to clear matching `node->light` pointers was considered and rejected:
it is O(nodes) per removal to defend against a caller this codebase does not have.

**For this feature the hazard is structurally absent**, which is worth saying because it is what
makes the invariant safe to ship rather than merely documented: the reconcile only ever removes
lights it created — `emissive_source_id != 0` — and those are exactly the lights with no node.
An authored light cannot be reached by it at all.

### Shadows come from `light_overrides`, not from the material

`.cscn` already has the block (`cscene.c:285-302`, applied at `cscene_apply.c:255-284`):

```json
"light_overrides": [ { "name": "cornell_light", "cast_shadows": true } ]
```

That is **per lamp**, which is what this decision is. A material cannot be: `import.c` dedups
materials, so one `Material*` is shared by every mesh using it, and 40 ceiling strips sharing a
`strip_light` material would all ask for a map against A7's pool of **8**. `off` is the opposite
case and stays on the material, because "this emissive is decorative" genuinely is a fact about
the surface and applying it to every instance is correct rather than a footgun.

**Ordering, which is the one thing this needs and does not have.** `apply_cscene_light_overrides`
runs once at init (`render.c:2707`), and a per-frame fit would not have produced anything yet.
It resolves because the fit splits cleanly: **the local-space fit needs no transforms at all**,
only mesh vertices, so it can run at init. The app calls `scene_build_emissive_lights(scene)`
after `apply_transform_to_nodes` (`render.c:2575`) and before the override call.

That call is an **ordering convenience, not a correctness requirement** — the engine's per-frame
reconcile is the authority and builds the same lights on frame 1 regardless. An app that forgets
it gets the lights anyway and loses only the override, which the existing "matches no light"
warning already reports. That is what keeps this out of the forgettable-rule trap `draw_list.h:110`
warns about.

Note the placement half must NOT be hoisted to init with the fit: `render.c:2590-2600` recentres
the model *after* transforms are resolved, and the offset rides the per-frame model matrix. An
init-time world position would be pre-recentre and wrong. Local fit at init, world placement per
frame, is what makes both correct.

## Phases

**P0 — the instrument and the calibration, no look change.** `--emissive-light-probe` prints
each derived panel: source mesh and material, centre, normal, up, size, planarity, colour, nits,
and why any candidate was skipped. Nothing consumes the lights yet, so the frame is provably
0 px. This is the 11.47 `--water-foam-debug` discipline — the fit is measured against the
cornell quad's known geometry *before* anything shades from it, so a bad fit cannot hide inside
a plausible image. **P0 is what settles whether the 18× above is the whole story.**

**P1 — the fit.** `cetra/src/emissive_light.c/h`, epoch-gated, local-space, transformed per
frame. Still nothing consumes it; P0's probe is how it is read.

**P2 — registration.** Derived panels enter `scene->lights`: `emissive_source_id`, the
order-preserving removal, the reconcile, `scene_build_emissive_lights` and its init call, the
`emissiveLight` material row, string-valued enum labels, `--no-emissive-lights`. Nothing in
`light_cluster.c` — a `scene->lights` entry is already packed. This is the commit where the
picture changes, and where `light_overrides` starts reaching derived panels.

**P3 — emissive textures.** The 1×1 mip readback.

**P4 — fixture and gates.** Below.

**P5 — the DDGI double count, measured before it is fixed.** A probe capture runs the full
forward shader, so it sees the emissive surface as radiance *and* sees surfaces lit by the new
panel — the first bounce lands twice. It only bites under `--gi-volume` (`scene->gi_volume` is
NULL by default, `scene.c:66`). `engine->capturing` already exists and suppressing derived
panels during capture is one branch, but **which way it should go is a measurement, not a
guess**: cornell_box with and without `--gi-volume`, derived vs authored. Do not build the
suppression before that A/B says the error is visible.

## Fixture and gates

`.cscn` can author `emissiveStrength` (it is a `MATERIAL_PARAMS` row), so **no new glTF is
needed** — the variant is a `.cscn`, in the `_water_cscn_variant` idiom the water group already
uses. Note the one-level-merge trap recorded there: a flat `dict.update` on a nested block drops
the fields it does not name.

| arm | what it reads |
|---|---|
| `emissive-fit` | the probe against the quad's known geometry: centre (0, 1.97, 0), normal (0, −1, 0), size 0.7 × 0.7, planarity 1.0. Tight tolerances — this geometry is exact, not approximate |
| `emissive-vs-authored` | **the acceptance test.** `cornell_box` variant with `emissiveStrength: 18` and no `lights[]` (derived) against stock `cornell_box.cscn` with `--no-emissive-lights` (authored 18 nits). Floor and wall boxes, **excluding the ceiling panel**, whose own pixels legitimately differ 18× between the two. Same room, same radiance, only the light's provenance changes |
| `emissive-off` | `--no-emissive-lights` on the derived variant → the room goes dark. An arm that can fail: "off is off" passed against a deliberately broken composite in 11.21 because both sides took the same path |
| `emissive-optout` | `emissiveLight: "off"` on `cornell_light` returns the stock fixture to **0 px**. Authored as the label string, so it also covers the `cscene_apply` change |
| `emissive-override` | a `light_overrides` entry naming `cornell_light` with `cast_shadows` reaches the derived panel — the arm that proves a derived light is addressable by name at all, and that the init ordering holds |
| `emissive-reject` | a non-planar emitter (a glowing box) is skipped, and the probe says why. Nothing in the corpus is one — `gen_cornell_rooms.py` can emit it |
| `emissive-occluded` | `cornell_leak`'s own question asked of the derived panel: the right half stays dark. **This arm is expected to be the one that fails first** — see below |

**Goldens.** Three cornell goldens exist. `cornell_box` and `cornell_leak` carry an emissive
panel and will move with on-by-default — the quad now lights the room it stands in, which is the
honest outcome — so they re-bake with the delta quoted. `cornell_point` has its panel removed
(`build_box_room(with_panel=False)`) and must stay **0 px**, as must every other golden: no
shader changed and nothing else in the corpus is emissive. Anything else that moves is a
finding, not a re-bake.

**`cornell_leak` is the sharpest risk in this item and it is worth naming before P2, not
after.** It exists to prove light does NOT arrive where it has no path: an emissive panel over
the left half only, a partition, and a right half reachable only around the open front. An LTC
panel with no shadow map **ignores occluders entirely** — that is A2's shipped behaviour and the
whole reason A7 exists — so a derived panel there will light the right half straight through the
partition and invert what the fixture measures. Two candidate resolutions, and P0's probe plus
one A/B decides between them rather than taste:

- `emissiveLight: off` on that fixture's panel, treating it as the DDGI instrument it is. Keeps
  the golden at 0 px and makes `cornell_leak` a second user of the opt-out.
- A `light_overrides` entry giving it `cast_shadows`, which is now a one-line scene-file change
  rather than a design question — and which makes `cornell_leak` the fixture that proves the
  override path reaches a derived light at all.

The second is the better outcome if the shadow is affordable there, because it keeps the fixture
measuring light transport rather than measuring an exclusion. Either way this is the case that
shows an unshadowed analytic panel is not a free upgrade over an emissive surface, and the plan
should not pretend the default is obviously right until that frame has been looked at.

## Verification

```bash
./build.sh
./out/bin/render -m assets/cornell_box.gltf --emissive-light-probe -x -f 2   # P0
python3 scripts/gates.py --only emissive                                     # after each phase
python3 scripts/gates.py                                                     # ONCE, at the end
python3 scripts/goldens.py
```

- **Measure the noise floor at the cornell framing first.** Two runs of one build must print
  `0 (0)` before any comparison means anything.
- Pin exposure (`--no-auto-exposure -E 1.0`) on every A/B — unpinned moves 99.77% of pixels and
  tells you nothing.
- P0 and P1 must leave **all 24 goldens 0 px**; nothing consumes the lights yet.
- A/B crops at the cornell framing before committing the P2 look change.
- `--profiler` after P2. The fit is epoch-gated so the steady-state cost is a handful of vector
  transforms, but that is a claim to check rather than assert.
- Reviews (`/thermo-nuclear-code-quality-review`, `/simplify`) in **background** agents, all
  finished before anything is applied.

## What v1 deliberately does not do

- **One rectangle per emissive mesh.** A curved tube, a sphere or a closed box is rejected by the
  planarity test with a log, not approximated.
- **Single-sided**, inheriting A2's convention — `ltcPanel` returns zero behind the plane
  (`ltc.glsl:123`). A double-sided emissive quad lights only the side its winding faces.
- **No emissive-texture spatial detail.** The panel takes the texture's mean; a screen showing a
  bright corner on a dark field lights as a uniformly dim screen.
- **No DDGI reconciliation** until P5 measures it.
