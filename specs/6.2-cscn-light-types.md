# Full `.cscn` light-type support

## Context

The `.cscn` scene format authors only **point** and **area** lights (`cscene.h:34-37`,
`cscene.c:112-122`, `cscene_apply.c:147-158`). It cannot express **directional** or **spot**
lights, or a `cast_shadows` flag. That gap forced a hack in the render app during A3: to give
the contact-shadow fixture a shadow-casting directional, I made the no-IBL fallback key light
cast shadows (`render.c:1835-1841`) — a special case bolted onto a shared code path. The right
fix (and the user's ask) is to make the format carry all four light types as data, then let the
fixture author its own sun via a sibling `.cscn`, and revert the render.c hack.

Engine light types: `LIGHT_DIRECTIONAL, LIGHT_POINT, LIGHT_SPOT, LIGHT_AREA` (`light.h:8`).
Only directional (cascaded, up to `MAX_SHADOW_LIGHTS=3`) and the *first* spot cast shadows
(`shadow.c:514,523`); point/area cannot. All the engine setters already exist.

Spec home: this extends `specs/6.0-cscene-format.md` (no new numbered spec). The 6.0 update is
the "spec first" commit; no separate plan-copy file.

## Verified facts (current master)

- **Enum/struct** `cscene.h:34-55`: `CSceneLightType {POINT, AREA}`; `CSceneLight` has
  name/type/position/color/intensity + area-only direction/size/up(+has_up). No fields for
  attenuation, range, spot cone, or cast_shadows. `memset`-zeroed per light (`cscene.c:107`),
  so new fields default to 0. Cap `CSCENE_MAX_LIGHTS 16`.
- **Parser** `parse_lights` `cscene.c:96-152`: maps `"area"`/`"point"`, rejects everything else;
  requires `position` unconditionally; requires `direction`+`size` only in the area block.
  Helpers: `get_vec3`, `get_float`, `get_floats(obj,key,out,n)`, `get_bool` (all require exact
  presence/shape).
- **Applier** `add_cscene_lights` `cscene_apply.c:134-165`: area vs point branches only; never
  calls `set_light_cast_shadows`/`set_light_cutoff`/`set_light_attenuation`/`set_light_range`.
- **Setters** (`light.c`): `set_light_direction` (writes original+current), `set_light_cutoff`
  (stores **cosines** of half-angles), `set_light_attenuation(c,l,q)`, `set_light_range`,
  `set_light_cast_shadows`, `set_light_type`. Conventions: `direction` = **travel** direction;
  spot cutoffs are **cosines** (author in degrees → `cosf(glm_rad(deg))` at apply, the
  `spores.c:186` idiom); attenuation/range have engine defaults so "absent = keep default".
- **Load order** `render.c:1670`: `add_cscene_lights` runs BEFORE the sky/IBL/fallback lighting
  decisions, and each authored light increments `scene->light_count`, so a cscn directional
  makes `light_count > 0` and the three-point fallback (`render.c:1829`) is skipped. Invariant
  comment at `render.c:1666-1669`.
- **Sibling load**: `cscene_setup` (`cscene_apply.c:39-48`) probes `foo.gltf → foo.cscn` via
  `cwk_path_change_extension` + `path_exists` unless `--no-scene-file`. `contact_fixture.cscn`
  will auto-load for `-m contact_fixture.gltf`. `.cscn` shape: `{version, models:[{path}],
  lights:[...], post:{...}}` (`area_light_fixture.cscn`).
- **The hack to revert**: `render.c:1835-1841` (the `find_light_by_name("key_light")` +
  `set_light_cast_shadows` added after `create_three_point_lights`); revert leaves only
  `create_three_point_lights(scene, 3.0f);`.

## Design

### 1. Data model — `cscene.h`
- Enum: add `CSCENE_LIGHT_DIRECTIONAL`, `CSCENE_LIGHT_SPOT`.
- `CSceneLight` new fields (comments note which type uses each):
  `bool has_attenuation; float attenuation[3];` (point/spot: constant,linear,quadratic),
  `bool has_range; float range;` (point/spot), `float cone[2];` (spot: inner,outer **degrees**),
  `bool cast_shadows;` (directional/spot). `direction[3]` comment changes area-only →
  "directional/spot/area (travel direction)".
- Rewrite the header comment block (`cscene.h:39-44`) to describe all four types.

### 2. Parser — `cscene.c parse_lights`
- Type map: add `"directional"`, `"spot"`; reject message → "(point/area/directional/spot)".
- `position`: required for point/spot/area; for directional read it if present but don't require
  it (a directional has no meaningful position).
- `direction`: required for directional/spot/area (lift the area-only requirement into a shared
  check); point ignores it.
- `cast_shadows`: `get_bool(l, "cast_shadows", &out->cast_shadows)` (inert on point/area).
- `attenuation`: `out->has_attenuation = get_floats(l, "attenuation", out->attenuation, 3);`
  `range`: `out->has_range = get_float(l, "range", &out->range);` (both optional, point/spot).
- Area block: unchanged (size required + positive, up optional).
- Spot block: `cone` required — `get_floats(l, "cone", out->cone, 2)`; validate
  `0 < inner <= outer < 90` (else warn+skip).

### 3. Applier — `cscene_apply.c add_cscene_lights`
Replace the area/point `if/else` with a `switch (sl->type)`:
- **AREA**: unchanged.
- **DIRECTIONAL**: `set_light_type(LIGHT_DIRECTIONAL)`, `set_light_direction`, and
  `if (sl->cast_shadows) set_light_cast_shadows(light, true)`.
- **SPOT**: `set_light_type(LIGHT_SPOT)`, `set_light_direction`,
  `set_light_cutoff(light, cosf(glm_rad(cone[0])), cosf(glm_rad(cone[1])))`,
  optional attenuation/range, optional cast_shadows.
- **POINT** (default): `set_light_type(LIGHT_POINT)`, optional attenuation/range.
- One `printf` per type (mirror the existing area/point log lines). Ensure `<math.h>` + cglm are
  included (cglm already is; add math.h if `cosf` is unresolved).

### 4. Revert the render.c hack
`render.c:1835-1841` → back to just `create_three_point_lights(scene, 3.0f);`. Drops the now
unused `find_light_by_name`/`set_light_cast_shadows` there.

### 5. `assets/contact_fixture.cscn` (new, sibling to the gltf)
```json
{ "version": 1,
  "models": [{ "path": "contact_fixture.gltf" }],
  "lights": [
    { "name": "sun", "type": "directional",
      "direction": [-0.4, -0.8, -0.45],
      "color": [1.0, 0.97, 0.92], "intensity": 3.5, "cast_shadows": true }
  ],
  "post": { "tonemap": "neutral", "exposure": 1.0 } }
```
Then `-m assets/contact_fixture.gltf --contact-shadows` self-lights (auto-loads the sibling),
casts a directional shadow, and engages contact shadows — no `--sky`, no render.c special case.
Camera stays a CLI arg in the golden command (as the area fixture does).

### 6. Docs
- `specs/6.0-cscene-format.md`: schema `lights` line (point/area/directional/spot), the new keys
  (`direction`, `cone` deg, `attenuation`, `range`, `cast_shadows`), the cosine-vs-degrees note,
  and the "only directional + first spot cast shadows" rule. Remove the stale "point lights only".
- the contact-shadow golden doc: fixture is now cscn-lit (no `--sky`/`-e`), drop `--no-scene-file`
  from the command (we WANT the sibling), regenerate the golden.

  --contact-shadows` logs 1 directional caster (`clustered: 1 directional …`), and on-vs-off

- **Spot smoke test**: hand-author a temp `.cscn` with a `type:"spot"` (cone [15,20],

- **Regression**: `area_light_fixture` and `abandoned_window` renders 0 px vs pre-change build
  (parser/applier changes must not perturb existing area/point authoring).
- **A3 gates still hold**: off-gate raiden 0 px; determinism (fixture, feature on) 0 px;

- **Build**: `./build.sh`; tree/spores smoke.

## Notes / out of scope

- Point/area `cast_shadows` is inert (shadow.c can't cast from them); the flag is only applied on
  directional/spot. A cscn that sets it on a point light is harmless, not honored.
- The `import.c` spot cutoff stores **radians** while cscn/engine use **cosines** — a pre-existing
  inconsistency in the import path, left alone (not this task).
