# 5.4 Subtle sunbeam dust in the abandoned-window scene

## Context

"The window asset" is `assets/abandoned_window.glb` (+ `abandoned_window.cscn` + `_env.hdr`) — a
mossy, ivy-covered sash window lit by a warm `SunKey` **directional** light, loaded through the
**render app** (`render assets/abandoned_window.cscn`). The goal: subtle floating dust motes that
catch the sun streaming through the panes (and darken where the muntins/frame shadow them),
**always on** whenever that scene is loaded — no flag.

Two facts make this clean:
- The particle **billboards are already lit by the scene's first directional light + its shadow
  maps** (`particle_renderer.c:133-141`, `particle_frag.glsl`), and their HDR color blooms. The
  window's `SunKey` is that directional light → dust visibly catches the sunbeam for free.
- **Gap:** the render app calls `engine_run(engine, NULL, render_scene_callback)` (render.c:2067)
  with a NULL update, so scene particle systems are **rendered** by the engine but never **ticked**
  (only the game loop ticks them, `game.c:209`). So the render app needs a per-frame particle tick.

## Design (both changes in `apps/render/src/render.c`)

### 1. Tick particles in the render app (general; no-op without particles)
Replace the `NULL` update in `engine_run` with a small callback:
```c
static double g_particle_time = 0.0;
static void render_frame_update(Engine* engine, float dt) {
    Scene* s = get_current_scene(engine);
    if (s) scene_update_particle_systems(s, dt, (float)g_particle_time);
    g_particle_time += dt;
}
...
engine_run(engine, render_frame_update, render_scene_callback);   // was NULL
```
`scene_update_particle_systems` (`scene.c:330`) loops the scene's particle systems — zero systems →
no-op, so this is safe for every other model the render app loads. This is the same tick the game
loop already does, just supplied through the render app's own update hook (no engine change, so the
game loop's fixed-step particle tick is untouched — no double-tick).

### 2. Auto-attach subtle dust when the abandoned-window scene is loaded
After the scene load + bounds computation (`scene_center`/`scene_radius`/`scene_floor_y` are already
computed and printed at render.c:~1720-1735), detect the window scene and attach a dust system:
```c
if (args.model_path && strstr(args.model_path, "abandoned_window"))
    attach_window_dust(engine, scene, scene_center, scene_radius);
```
`attach_window_dust` is a small static helper reusing the spores pattern
(`apps/spores/src/spores.c` on_init), dialed **way down** for subtlety:
```c
create_particle_program() + add_shader_program_to_engine(engine, prog);
ParticleSystem* sys = create_particle_system("window_dust");
particle_system_set_backend(sys, create_tf_particle_sim_backend());
ParticleEmitter* em = create_particle_emitter("dust", CAP);           // CAP >= rate*max_life (~1500)
particle_emitter_set_renderer(em, create_billboard_particle_renderer(prog));
particle_emitter_add_module(em, particle_module_spawn_rate(~60.0f));   // sparse
// spawn box from the bounds: center +/- ~0.6*radius, floored above scene_floor_y
particle_emitter_add_module(em, particle_module_init_box_location(min, max));
particle_emitter_add_module(em, particle_module_init_lifetime(15.0f, 30.0f)); // long, drifty
particle_emitter_add_module(em, particle_module_init_size(0.004f, 0.018f));   // tiny motes
particle_emitter_add_module(em, particle_module_init_color((vec4){0.8f,0.8f,0.8f,0.5f}, 0.05f));
                                              // near-white/low-alpha; the warm SunKey tints it
particle_emitter_add_module(em, particle_module_update_curl_noise(0.3f, 0.06f, 0.05f)); // faint swirl
particle_emitter_add_module(em, particle_module_update_drift((vec3){0,0.004f,0}));       // barely rising
particle_emitter_add_module(em, particle_module_update_integrate(0.99f));
particle_system_add_emitter(sys, em);
add_particle_system_to_scene(scene, sys);      // scene owns it (freed in free_scene)
SceneNode* n = create_node(); set_node_particle_system(n, sys); add_child_node(scene->root_node, n);
```
Exact spawn-box, rate, size, and color tuned from a capture (see Verification). No colliders — it's
passive ambient dust.

## Files
- `apps/render/src/render.c` — the `render_frame_update` tick callback (swap the `NULL`) and the
  `attach_window_dust` helper + its gated call after the bounds block.

## Reuse (don't reinvent)
- The whole dust recipe from `apps/spores/src/spores.c` on_init (create_particle_system / emitter /
  the `particle_module_*` stack / `create_tf_particle_sim_backend` / `create_billboard_particle_renderer`).
- `scene_update_particle_systems` (`scene.c:330`), `get_current_scene`, `add_particle_system_to_scene`
  / `set_node_particle_system` (`scene.h`).
- The already-computed `scene_center`/`scene_radius`/`scene_floor_y` (render.c:~1720-1735) to size the
  spawn box — no new bounds math.
- The engine's automatic particle **render** (`cetra/src/render.c:748-764`) and the billboard's
  directional-light + shadow lighting (`particle_renderer.c` / `particle_frag.glsl`) — the dust
  catches `SunKey` with zero extra wiring.

## Verification
1. `./build.sh` clean.
2. **The window** — `./out/bin/render assets/abandoned_window.cscn --headless --frames 300 --screenshot dust.ppm`:
   subtle motes drifting in the room, brightening in the sun shafts through the panes and dropping to
   ambient where the muntins/frame shadow them. Tune spawn_rate / init_size / init_color / the spawn
   box across a couple captures until it reads as "a few dust specks in the light," not a cloud.
3. **No regression** — `./out/bin/render <some other model> --headless --frames 60 --screenshot r.ppm`:
   no dust (the `abandoned_window` gate is false), and the new tick callback is a no-op with no
   particle systems. Confirm identical to before.
4. Optionally `--cpu`-equivalent isn't exposed in render; the TF backend is fine here.

## Risks / notes
- **Filename gate** (`strstr(model_path, "abandoned_window")`) is a scene-specific special-case in a
  generic viewer — accepted per the "always-on for the window" choice. A more robust signal would be
  a characteristic node (e.g. `find_node_by_name(root, "SashPane_0")`), swap to that if the filename
  proves brittle.
- **Headless determinism**: the dust animates off an accumulated wall-clock `t`, so `--dust`-style
  window screenshots aren't byte-deterministic across runs. Fine — it's a look, not a CI target; all
  other render screenshots are unaffected (no particles → the tick is a no-op).
- Billboards are lit only by the **first directional** light — the window's `SunKey`. The `.cscn`
  `BounceFill` **point** light won't light the motes (consistent with how spores' spot doesn't light
  its dust). Sunbeam-catching dust is exactly the intent.
- Fresh branch off master.
