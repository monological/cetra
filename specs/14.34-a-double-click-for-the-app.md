# cetra 14.34: a double click for the app

## Context

pcb 7.5 routes by hand, and its layout tells a double click from two clicks: a click on a
segment of a trace picks the segment, a double click the trace whole. cetra counts runs of presses
already -- a text field's and the code editor's double click selects a word, the editor's triple
click a line -- but in `ui_typing.h`, which no app may name, so pcb keeps a copy of its own: the
same 0.4 seconds and 4 points, the same test, a second home for what a double click is.

pcb's AGENTS.md says that where cetra's UI cannot do something, pcb stops and asks rather than
working round it. Asked, the user chose a public counter in cetra over pcb's copy (pcb 7.5, phase
16). pcb keeps its copy, timed on `UIInput.time`, until this spec reaches cetra's master and its
pin is bumped.

Branch and spec: `14.34-a-double-click-for-the-app`, off cetra's master (`ec2c2777`).

## The design

In `ui.h`, beside the input:

```c
// A run of presses: the last one's time, on UIInput.time, and place, and how many so far.
typedef struct UIPresses {
    double time;
    float x, y;
    int count;
} UIPresses;

// A press at (x, y) at `time` counted into the run when it is close enough to the last in time
// and place: how many the run now holds, from 1 -- 2 a double click, 3 a triple -- back to 1
// after `cycle` when it is not 0.
int ui_presses_add(UIPresses* run, double time, float x, float y, int cycle);

// The run ended, so the next press begins one.
void ui_presses_end(UIPresses* run);
```

- **One home for what a double click is.** `UI_TYPING_PRESS_SECONDS` and `UI_TYPING_PRESS_POINTS`
  move beside `ui_presses_add` in `ui.c`, private to it; `UITypingPresses` and `ui_typing_press`
  go, and the text field and the code editor count their presses with the public calls. What they
  select by one, two or three presses does not change.
- **On `UIInput.time`**: the wall clock in a window, the frame count times the fixed step headless,
  so a scripted double click is the same on every run.
- **Ended by the app**: a press that is not part of a run -- another button, a modifier the app
  reads otherwise, a press on nothing -- ends it with `ui_presses_end`, so a quick press after it
  is not a second.

## Phases

0. **The spec**, this file, committed alone.
1. **The counter**: `UIPresses`, `ui_presses_add` and `ui_presses_end` in `ui.h`; the text field
   and the code editor on them, `ui_typing_press` gone; a gate arm, `ui-presses`, in the UI's
   probes (`apps/gametest`), holding the count -- a quick second press 2, a third 3, a late or a
   far one back to 1, `cycle` wrapping, `end` beginning again -- and falsified; the arms of the
   field's and the editor's double and triple clicks unchanged; `docs/ui.md`'s input,
   `docs/modules.md`'s row, and 14.34 in `docs/eda-roadmap.md`. As built.
2. **Reviews**: `/simplify`'s and the thermo-nuclear review, background agents at effort high,
   applied once all are back. As built.

**Then**, with the user's say-so, master fast-forwards; pcb's pin is bumped from master with its
own say-so, and pcb's copy goes for one `UIPresses` and the route its first press was on.

## Not in this spec

A press count in `UIInput` itself, every app counting the same run whether it wants one or not;
long presses; a double click's time from the platform's setting rather than cetra's 0.4 seconds.
