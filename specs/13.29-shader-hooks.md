# Spec 13.29 -- app shaders at named points (then 13.30, static on silent's television)

## Context
The user wants the living-room television in silent (`apps/silent/src/home.c:841-864`) to show
realistic analog CRT static. Per-field noise on an emissive surface does not survive TAA: silent
always runs TAA, the history weight is 0.97 (`taa_resolve_frag.glsl:23`), and a 3x3 neighbourhood
of noise spans the whole range, so the clamp passes the history and the static averages to grey.
The first plan added a TV module to the engine. The user rejected that: each new effect would
become another engine module. They asked for the general mechanism instead, the way Unreal has
it: material domains and blend modes, a translucency pass of "Before DOF", "After DOF" or "After
Motion Blur", and post-process materials at named Blendable Locations. They also asked for a
fixture that exercises every hook point.

So 13.29 is engine work. An app, or a `.cscn`, can now put its own GLSL at four places, with no
engine change for each new effect:

| Hook | What it is (Unreal analogue) | Difficulty, from the code |
|---|---|---|
| **App GLSL** | Engine includes usable by app shaders | Easy. A runtime include resolver, an include table, two public vertex stages, a CMake helper |
| **Post passes** | Post-process material at a Blendable Location | Moderate. GL 4.1 has no texture barrier and no canvas ping-pong, so each pass draws to an engine-owned scratch and blits back (the motion-blur idiom, `postfx.c:1413`). After-tonemap needs the CRT's intermediate (`postfx.c:2383`) |
| **Late lane** | Translucency Pass "After Motion Blur" | Moderate. A draw-list lane is cheap, because camera passes name their lanes positively. The draw path is new: a colour-only post-res target, render-res depth, unjittered projection, fog applied by the shader |
| **Surface hook** | A surface material graph feeding the engine's lighting | Hard. The gather in `pbr_frag` is split by the alpha test and the prepass exit (1197-1545). The variant cache key is family + mask only (`program.c:630`). Opacity and vertex offset must reach five hand-matched programs plus a CPU bound |

The TV static then becomes silent's own shader on a late-lane material: spec 13.30.

## Phase 1 -- app GLSL can use the engine's includes
- **Runtime include resolver.**
  - `gen_shader_header.py` also emits a table of the `include/` chunks, as name and source. Today
    chunks never become variables (`gen_shader_header.py:85`).
  - `create_program_from_source` expands `#include "x.glsl"` against that table: include-once,
    nested, with `#line` directives so compile errors name the app file's lines.
  - Engine shaders are already expanded at build time, so for them it is a no-op and the goldens
    stay at 0 px.
  - A `.cscn` can then name a `.glsl` file at load.
- **Public vertex stages for app fragments.**
  - `create_post_pass_program(engine, name, frag)` pairs an app fragment with `post_vert`.
  - `create_late_surface_program(engine, name, frag)` pairs it with a new `late_surface_vert.glsl`.
  - Apps cannot name `post_vert_shader_str` today (`program.c:11-17`).
- **`cetra_embed_shaders(target dir)`**, a CMake function defined in `cetra/CMakeLists.txt`.
  - It captures the generator's path when it is defined, so it also works from a parent project
    that uses cetra through `add_subdirectory`.
  - It turns an app's `shaders/*.glsl` into a header of strings.
  - The generator gains a no-expand mode, because includes resolve at runtime.
- **A new `shaders` asset kind.** `fixture_paths.asset_subpath` maps `.glsl` to `assets/shaders/`.
  A `.cscn` names `../shaders/<x>.glsl`, resolved like a model path.
- **Per-material shader parameters.**
  - `material_set_shader_param(m, "name", vec4)`, up to 8 per material.
  - Uploaded by name wherever the material's program is bound: `_update_program_material_uniforms`
    (`render.c:195`), the late lane and the shadow variants.
  - In a `.cscn`: `"shaderParams": {"name": [x, y, z, w]}`, a compound key parsed like `sss`
    (`cscene.c:1703`).

## Phase 2 -- post passes at named points
- `PostFXPass* postfx_add_pass(fx, PostFXLocation at, ShaderProgram* program)`. The pass carries a
  SETTINGS `enabled` and shader params. Several passes may share a location and run in the order
  they were added.
- **Three locations**, each at a real stage boundary:
  - `POSTFX_AT_BEFORE_DOF`: after the late draw (`postfx.c:3876`). Linear HDR, fogged, with the
    late surfaces in it. Unreal: Scene Color Before DOF.
  - `POSTFX_AT_BEFORE_BLOOM`: after DoF and before the meter (`postfx.c:3922`), so it is metered.
    It reads `scene_tex`, whichever buffer that is. Unreal: Scene Color Before Bloom.
  - `POSTFX_AT_AFTER_TONEMAP`: display-referred, before the game UI overlay.
    - The tonemap writes into the CRT's picture intermediate and skips the dither.
    - The app passes run.
    - Then either the CRT or a new present-with-dither pass writes framebuffer 0, so dither stays
      last (spec 11.24).
    - Unreal: Scene Color After Tonemapping.
- **What each HDR pass does.** It reads its input, draws into an engine-owned post-res RGBA16F
  scratch, and blits back. Allocated lazily, so a frame with no passes is unchanged.
- **Inputs, bound by name** when the program declares them: `sceneColor`, `sceneDepth` at render
  res, `texelSize`, `time`, `frame`, and the pass params. `ViewParams`, including `preExposure`,
  is already wired automatically (`ubo_wire_blocks`).
- **Replacing the tonemapper is booked, not built.** It is not a stage boundary: the curve is
  `toneSelect()` inside a 15-sampler shader that also composites AO, contact shadows, bloom,
  flare and glare, and that shader runs the curve at the 5 sharpen taps.
- **In a `.cscn`:** `post.passes: [{"at": "beforeBloom", "shader": "...", "params": {...}}]`.

## Phase 3 -- the late lane (After Motion Blur)
- `Material.pass` takes `MATERIAL_PASS_MAIN` (0, the default) or `MATERIAL_PASS_LATE`.
- **Routing.** `classify` (`draw_list.c:110`) routes a late material to a new `DRAW_LANE_LATE`.
  - Camera passes, captures and occlusion skip it with no change, because they name their lanes.
  - `caster_set_wants` (`shadow.c:858`) excludes it explicitly, so it casts nothing.
  - A late material whose program is not a late-surface program is refused by name at build.
- **Drawing.** `_engine_late_draw` (`engine.c:2251`) calls an exported `render_late_items(engine,
  scene, late)`.
  - Late items draw first, then fire and rain, which are translucent and must composite over a
    screen.
  - Items are sorted back to front, with the unjittered `view_proj`.
  - The publish condition (`engine.c:2302`) also turns on when the lane is non-empty.
- **`include/late_surface.glsl`**, so no late shader re-derives these:
  - `lateOccluded(viewDepth)`: a soft compare against render-res `sceneDepth` through `gl_FragCoord
    / viewport`, as `fire_card_frag.glsl:61` does. The canvas has no depth attachment, and Unreal
    disables the depth test in this pass for the same jitter reason.
  - `lateFog(radiance)`, over `froxelSampleMedium`.
  - The `preExposure` multiply.
- **Bound by name:** `sceneDepth`, `viewport`, the fog volume and its parameters, `time`, `frame`,
  `cameraPos`, and the material's params.
- **Additive blending is allowed to go negative** on the RGBA16F canvas. That is what lets a
  late surface carry a correction on top of a main-pass mean, as 13.30 does.

## Phase 4 -- the surface hook, fragment half
- **API.** `ShaderHook* create_shader_hook(engine, &(ShaderHookDesc){name, surface, offset,
  offset_bound, animated})`, owned by the engine. `material_set_shader_hook(m, hook)`.
- **The contract, in `include/surface_hook.glsl`:** a struct `CetraSurface`.
  - Inputs: `uv`, `worldPos`, `viewDir`, `geomNormal`, `vertexColor`, `time`, `frame`.
  - Outputs, initialised to the engine's own gather: `albedo`, `alpha`, `normal`, `roughness`,
    `metallic`, `ao`, `emissive`.
  - The app writes `void cetraSurface(inout CetraSurface s)`. It may sample the textures the
    material binds.
  - Sheen, clearcoat, transmission, subsurface, IOR and anisotropy stay material settings. The
    header says so, because they are read raw late in the shader (`pbr_frag` 1708-1964).
- **Variant.** A new bit, `PBR_FEAT_SURFACE_HOOK`. The hook's source is spliced at a marker after
  `pbr_frag`'s declarations. The existing splice point is the top of the file
  (`shader.c:32-103`), before anything the hook could name, so `shader_source_with_defines` gains
  a marker form.
- **Two call sites, one function.**
  - The first call comes before the alpha test (~1197). Its `albedo` and `alpha` feed the discard,
    decals, the albedo debug view and the binary prepass exit.
  - The second call comes after the prepass exit (~1546). Its `normal`, `roughness`, `metallic`,
    `ao` and `emissive` feed specular AA, wetness, rain, decal pass 2 and everything after.
  - The compiler drops what each call does not use.
  - Everything is under `#if CETRA_HAS(...)`, so unhooked variants are the same text and every
    golden stays at 0 px.
- **Cache key.**
  - `ShaderProgram` carries the hook, as it carries `pbr_family`.
  - `pbr_variant_name` becomes `<prefix>-<mask>-h<id>` (raise `PBR_VARIANT_NAME_MAX`).
  - `engine_resolve_material_variants` (`render.c:886`) keeps the hook. Without that, it would
    move a hooked material back to `pbr-<mask>` on the next frame.
- **No new sampler declarations and no new uniform block**, so the 16/16 and 10/12 ledgers are
  unchanged.
- **In a `.cscn`:** `"surfaceShader": "../shaders/x.glsl"` on a material.

## Phase 5 -- the surface hook, shadows and vertex offset
- **Offset.** `vec3 cetraOffset(CetraVertex v)` is spliced into `object_position.glsl`'s
  displacement under the hook bit in `pbr_vert` and `pbr_skinned_vert`. It is evaluated again at
  the previous frame's time for `PrevClip`, so motion vectors follow it.
- **The other programs** (`object_position.glsl:56-69` lists five):
  - The lean prepass: a hooked offset sets `depth_prepass_safe = false`, as fur does
    (`program.c:609`). The masked prepass already runs the material's own program.
  - Shadows: per-hook variants of `shadow_depth` and `shadow_absorb`, with the offset and the
    first-call alpha. The caster loop picks them for hooked items (`shadow.c:979-1150`), and
    cached tiles go through the same `_draw_shadow_items`.
- **CPU bound.** `draw_item_bounds` (`draw_list.c:389`) adds the hook's declared `offset_bound`,
  as wind, morph and fur do.
- **Cached tiles.** A hook declared `animated` is a mover for the kept faces, the swaying-mesh
  rule (spec 13.26).
- **In a `.cscn`:** `"offsetShader"` and `"offsetBound"`.

## Spec 13.30 -- static on silent's television (after 13.29)
- **What real static is**, and so what silent's `shaders/tv_static.glsl` draws:
  - A new field every 1/59.94 s, time-based and deterministic under the headless fixed clock.
  - About 480 lines of independent noise, each band-limited along the line to ~440 samples, so a
    speck is a short horizontal dash.
  - Monochrome at a ~9300 K white, because the colour killer turns chroma off without a burst.
  - Gaussian noise clipped at black and white, then through a 2.4 gamma: dark, with bright specks.
  - A hum bar rolling once every ~17 s (60 Hz mains against the 59.94 Hz field rate).
  - Rounded corners and a slight edge falloff.
  - Scanlines that fade in only when a line covers about 2 output pixels or more. When a pixel
    covers several lines, footprint taps, so a far set reads finer and greyer.
- **The mean and the noise are split.**
  - `MAT_SCREEN`'s emissive carries the static's mean, set each frame. So SSR on the glossy
    floor, the probes and TAA's history all see a lit screen.
  - A late-lane quad a millimetre in front of the glass adds `static - mean`.
  - The AGC level comes from one C function, read by the shader param, the material and the
    light.
- **The light.** `tv_glow` takes the static's colour, and its intensity follows the level, beside
  the tube flicker (`lights.c:284`).
- **The hiss.** A CC0 Freesound TV-static recording, looped by `tools/fetch_sounds.py`, chosen by
  the user with `--audition`. Positional, through `sounds.c`'s indoor gain. Procedural white noise
  only if no recording fits.
- **`--no-static`** for A/B.
- **No gates**, a demo app. The user looks at it from the sofa and close up.

- **Unreal's four slots**, for the names used below:
  - EMaterialTranslucencyPass: Before DOF, After DOF, After Motion Blur. The last disables the
    depth test, because TSR's jitter leaves the depth buffer unstable.
  - EBlendableLocation: Scene Color Before DOF, Scene Color Before Bloom, Replacing the
    Tonemapper, Scene Color After Tonemapping, SSR Input, and others.

    Interface) and Blend Mode (Opaque and Masked into the base pass; Translucent, Additive and
    Modulate into the translucency passes).

### Phase 1 -- app GLSL
- **The include table** is a second generated header, `shader_includes.h`, written by the same
  generator run (`--includes-out`) and included only by `shader.c`. A header of its own rather
  than rows in `shader_strings.h`, so the resolver does not compile every engine shader string
  into a second object, and "only program.c includes shader_strings.h" stays true.
- **The resolver** is `shader_source_with_includes` (`shader.c`), and `create_shader` runs
  every source through it, so every path to a program (from source, from paths, the hot
  reload) gets it with no call site changed.
  - Include-once and nested, with the generator's begin/end marker lines.
  - After each TOP-LEVEL include it emits `#line` back to the including file's numbering, so
    an error in an app's shader names its own line. Not inside chunks: a number there could not
    say which chunk, which is why the build-time expansion carries none.
  - A line naming no chunk, or malformed, fails the compile by name.
- **The generator escapes backslashes now**, which it never did. No engine shader contains one
  (checked), so no string changed; an app macro with a line continuation would have been
  silently broken by the old escaping.
- **`create_post_pass_program`** is public. **`create_late_surface_program` moved to phase 3**,
  with the vertex stage it needs, since nothing could call it before then.
- **`cetra_embed_shaders`** is defined in `cetra/CMakeLists.txt`, capturing the generator and
  the interpreter in cache variables. Its first caller is silent in 13.30.
- **Shader params:** `Material.shader_params` (8 named vec4s), `material_set_shader_param` and
  `material_upload_shader_params`, uploaded at the end of `_update_program_material_uniforms`.
  Nothing resets a name another material set on a shared program, which the header says.
  `shaderParams` in a `.cscn` parses to the runtime type, as roads do.
- **`.glsl` is an asset kind**, `assets/shaders/`.
- The resolver's first live use is phase 2's fixture shaders, each of which includes a chunk.
