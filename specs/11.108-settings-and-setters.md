# Spec 11.108 — Settings and setters

## Context

The third of the three API specs outlined in `specs/11.106-the-public-surface.md` (lines
461-580 carry the brief). 11.106 gave every created object a description struct and one naming
rule; 11.107 closed the silent failures and made the engine do the housekeeping. What is left is
the rule for a LIVE object: which of its fields an app writes directly, which it writes through a
function, and which it never writes. Today that rule exists only in prose on two headers
(`camera.h:61-71`, `light.h:148-150`) and in `config_snapshot.c`'s `apply == NULL` convention;
five Engine setters store a value and nothing else (`engine.c:1243, 1625, 1631, 1746, 1752`),
`engine_set_taa` stores into another struct's field that the engine itself writes directly in
four places (`engine.c:1011, 1678`, `render.c:2037, 2135`), `mesh_set_draw_mode` has two callers
and one statement, six `transform_set_*`/`transform_add_*` functions have no caller at all, the
XYZ gizmo's program is propagated into every node once and so misses every node created after it
(pcb's X key draws the root's gizmo and none of the twenty parts: `scene_set_xyz_program` runs at
`main.c:392`, every part is created at 394-454), the fog's ambient colour has three hand-written
owners that agree by convention (`gui.c:981`, `config_snapshot.c:305`, `render.c:3862`) and two
that do not know the sky stamps over them (`forest.c:2671`, `spores.c:154`), and the two 2D apps
carry thirty identical lines of canvas code each. The policy that settles all of it is one
sentence, and the work is making the headers say it.

Measured before writing: no struct in the list is hashed, `memcpy`'d or `memcmp`'d by bytes, and
none has a positional initialiser anywhere (only `CameraDesc`/`LightDesc`, designated); the
config table is `offsetof` at compile time and the GUI writes by address, so reordering fields
survives a recompile; the snapshot reader names an unknown key and continues
(`config_snapshot.c:1513`), so a retired row costs a warning, not a refusal.

**Where this plan departs from the 11.106 brief, and why** (each also in the ledger):

- `show_wireframe` becomes a SETTING (§3): the frame top already re-applies its polygon mode
  from the field every frame, and the cull toggle joins it there. The brief kept the function.
- `engine_set_taa` is deleted (§1): its body is one store into `postfx->taa_enabled`, a field
  the engine writes directly in four places. The brief listed TAA among the rebuilds.
- `SceneNode.xyz_shader_program` is deleted rather than given a fallback (§2): nothing writes it
  but the propagation, so the scene's program is the only one.
- `Camera.height`, `amplitude`, `horizontal_fov` are deleted with their two snapshot rows (§1):
  nothing reads them, and the reader warns on an unknown key and continues.
- `PostFX`, `Engine`, `ShadowSystem`, `Water` and `Material` are NOT reordered into three
  sections; they get one banner stating the rule by kind (below).
- `canvas_set_zoom_range` is not added (§8): its two fields are settings.
- The 2D preset keeps setting the linear tone curve (§7): the brief's "does not touch the
  tonemap" is read as "this spec does not change that", since `engine.h:519-528` and
  `AGENTS.md:293-295` both describe the curve as part of the preset.

## Scope

The three-role rule stated in every public struct; the plain-store setters deleted; the reacting
writes that lacked a function given one (`postfx_set_fog_ambient`); the XYZ gizmo de-propagated;
the node and particle helpers; the 2D preset and a canvas controller; header overviews and the
docs. **Non-goals:** any new gate group or golden; any rename (11.106's table is final); any
change to what the config snapshot carries beyond the two dead camera rows it loses; the
pose-pair setter (`camera_set_pose(eye, target)`) that 11.107's review raised — the banner marks
distance/theta/phi as derived, which is what the review wanted said, and the transient
`position == look_at` fallback in `_camera_sync_orbit` is one frame of a drag.

## The policy, in words

Every public struct's fields play one of three roles, and the header says which under one of
three banners, in this order inside the struct:

```c
    // ENGINE-OWNED: derived state, GL names, resources. Read freely, never write.
    ...
    // BY FUNCTION: each of these reacts. Write it through the function named beside it.
    ...
    // SETTINGS: plain stores. Write them directly, at any time.
    ...
```

1. **Description** — what an object is created from (`EngineConfig`, `CameraDesc`,
   `LightDesc`; done in 11.106).
2. **By function** — a write that must be validated, ordered, propagated or followed by a
   re-derive. The test is whether the LIBRARY has to react, not who writes: a setter that only
   stores is ceremony and is deleted. The empirical list is the union of `config_snapshot.c`'s
   fourteen `CFG_ROW_FN` rows (`:410-696`) and `gui.c`'s thirteen function calls (the GUI is the
   wider instrument: `light_set_intensity_units`, `camera_set_look_at`, `camera_orbit` react
   with no table row). Eight of the fourteen rows are the sun and cloud fields on `SkyAtmosphere`
   / `CloudLayer`, which react through `sky_update_sun` and `scene_environment_changed`
   (`config_snapshot.c:1649-1661`); their banner names those two, as the brief asks. Every entry
   has a function after this spec, and the hooks call it.
3. **Settings** — everything else: the tuning blocks (PostFX, Exposure, ShadowSystem, Water,
   Wind), the content (a material's parameters, a mesh's arrays), the overlays and the run's
   settings on the Engine. No setter exists and none is added, because the GUI and the config
   table already reach them by address, and `wind.h:38` already says so for one struct.

A field under ENGINE-OWNED has a function if an app may change it (`engine_set_msaa_samples`,
`scene_set_root`) and none if it may not (`aspect_ratio`, `gpu_vertex_count`). There is no fourth
role and no plain-store setter survives on any struct, which is what makes the rule legible from a
header without reading a `.c`.

**Two banner styles, by how a struct reads.** A struct whose fields can be gathered into the
three sections without losing their reading gets the three banners, reordered: `Camera`,
`Light`, `Mesh`, `SceneNode`, `Scene`, `Exposure`, `Wind`, `InputState`, `MouseDragController`,
`CanvasController`, `SkyAtmosphere`, `CloudLayer`. A struct organised by FEATURE, where tuning
and resources interleave per feature under comments that read as a unit and that order is the
useful one (`Engine` at ~390 lines, `PostFX` at ~304 fields, `ShadowSystem`, `Water`, and
`Material`, whose layers block at `material.h:271-344` holds a texture setter, a layer index and
its settings together), keeps its feature order and gets ONE banner at the top of the struct
stating the rule by kind — "SETTINGS throughout, except: every GL name, every `PingPong`
history, every `*_ready`/`*_failed`/`*_built` latch, the published blocks (each marked at its
declaration), and the fields listed here BY FUNCTION" — followed by the explicit by-function
list with its functions. The reader of a feature-organised struct is looking for a feature, and
a `GLuint` announces itself; the reader of `Camera` is looking for what they may write. A
reorder that is only churn (304 fields moved to say what a type already says) is refused.

### 2. The XYZ gizmo stops propagating

Today: `engine_set_show_xyz` walks every scene writing `node->show_xyz`;
`scene_set_xyz_program` walks once writing `node->xyz_shader_program`; the draw-list build pushes
a gizmo when both node fields are set (`draw_list.c:280`); `_render_xyz` reads the node's program
again (`render.c:739, 742`). A node created after either walk is missed — every content node in
pcb, shapes and gametest, and the light nodes in render.

After: `SceneNode.xyz_shader_program` is deleted (`scene.h:72`, `scene.c:788`, the static walk
at `scene.c:994-1004`; its readers are exactly `draw_list.c:280`, `render.c:739, 742`,
`scene.c:38, 80, 748-754`), and the program is the scene's alone (`Scene.xyz_shader_program`,
installed by `scene_set_xyz_program`, which stays; `node_set_program(s)` never touched it). The
draw-list build takes the engine's flag as one `bool` argument — `draw_list_build`
(`draw_list.c:292`) has one caller, `engine_build_draw_list` (`render.c:856-873`), which every
builder goes through (shadow, cull view, capture, the frame), so the flag is consistent across
the stamp-deduped early return (`draw_list.c:295`) — and pushes a gizmo for `node->show_xyz` only
when it is on, so a frame with the overlay off appends nothing where an unconditional push would
append every node every frame. `_submit_gizmos` takes the scene's program with the VAO
(`render.c:1191, 1595`), and `_render_xyz` draws with it. `engine->show_xyz` is then a SETTING
(the master switch), `node->show_xyz` a SETTING (the opt-out, default true from `create_node`),
and nothing is propagated. `engine_set_show_xyz` and `node_set_show_xyz` go. The X key in render,
tree, shapes and pcb becomes `engine->show_xyz = !engine->show_xyz` and works on every node. The
`engine.overlays.xyz` snapshot row (`config_snapshot.c:421`) is a plain store today that skipped
the propagation; it is truthful after.

11.107's risk row about per-node gizmo buffers was retired by 11.107 itself (the VAO is on the
engine); this is the flag half only.

### 3. Wireframe becomes a setting

`engine_set_show_wireframe` stores and toggles `GL_CULL_FACE` immediately (`engine.c:1839`); the
frame top already re-applies `glPolygonMode` from the field every frame, before the shadow pass
and the scene (`engine.c:2637-2643`). The cull toggle moves into that block (`glDisable` under
the wireframe arm, `glEnable` under the other); the frame-end restore at `:2832` stays polygon
mode only (ImGui saves and restores culling itself; the post passes are fullscreen). The
mid-frame GL write from `gui.c:288` goes. **The two-sided restore learns the frame's state**:
`submit_draw_run` disables culling for a `doubleSided` material and re-enables it
unconditionally after (`render.c:926-927, 949-950`), so today a wireframe frame is back-face
culled from its first two-sided draw on — the setter's disable suffered the same. `SubmitState`
(`render.h:163-167`) gains `bool cull`, set at pass start from `!engine->show_wireframe`, and the
restore re-enables only when it is set. The `engine.overlays.wireframe` row
(`config_snapshot.c:420`) is a plain store today that skipped the cull toggle; truthful after.
The one other behaviour change: a probe or GI capture (`render.c:2044`, inside
`scene_capture_faces`) no longer leaves wireframe mode culled for the rest of the session.
Verified by hand on the render app (W key), which no golden or capture can see.

### 4. `postfx_set_fog_ambient`, and the ownership flag lives beside the value

The sky stamps its zenith radiance over `fx->fog_ambient` every frame (`sky_publish_to_postfx`,
`sky.c:560`, from `engine_present_frame` at `engine.c:1891`) while `sky->publish_fog_ambient` is
set; three sites clear the flag by hand after writing (`gui.c:981`, `config_snapshot.c:305`,
`render.c:3862`), two write without clearing (`forest.c:2671`, `spores.c:154`), and `tree.c:662`
exposes the flag as a checkbox; those six are every reader. The flag belongs beside the value it
protects: `PostFX.fog_ambient_from_sky` (a SETTING, default true: "the sky's zenith radiance is
copied here every frame; clear it to own the value"), `SkyAtmosphere.publish_fog_ambient`
deleted (`sky.h:294`, `sky.c:71`), and

```c
// Stores the colour and takes ownership: clears fog_ambient_from_sky, so the sky stops
// stamping over it. A direct write to fog_ambient is stamped over while that flag is set.
void postfx_set_fog_ambient(PostFX* fx, const vec3 rgb);
```

packages the pair so a writer cannot forget the second half, which is the failure mode two apps
have today. `_apply_fog_ambient` calls it (still a `CFG_ROW_FN`; the deferred sun re-bake never
writes `fog_ambient`, `sky.c:561` is the only writer, so row order is irrelevant); `render.c`'s
`.cscn` path calls it; `spores.c:154` calls it (no sky there, so nothing moves); the GUI's
colour picker writes by address as it does and clears the flag on edit
(`if (igColorEdit3(...)) fx->fog_ambient_from_sky = false;` — a local would break
`config-coverage`); `tree.c:662` binds `&fx->fog_ambient_from_sky` directly.

**`forest.c:2671` becomes `if (g_args.no_sky) postfx_set_fog_ambient(fx, ...)`.** With the sky
(`forest.c:2264`, the default) the authored value has never reached a pixel and resurrecting it
would change forest's look; under `--no-sky` (`forest.c:172, 2517-2520`, `g_scene->sky` NULL)
it is live today and stays. The default capture at its floor is the proof for the first half; a
`--no-sky --frames 30` capture before and after, byte-identical, for the second.

### 6. The billboard renderer's lighting is per renderer

`particle_renderer.c:13-14` holds `PARTICLE_AMBIENT_FLOOR 0.18f` and
`PARTICLE_SOFT_FADE_DIST 0.5f` as file constants, already annotated "promote to per-emitter
renderer config if a second emitter needs a different look". `BillboardRenderer` gains
`ambient_floor`, `soft_fade_dist` and `lit` (defaults 0.18, 0.5, true, set in
`create_billboard_particle_renderer` beside `hdr_gain`), and:

```c
// The floor a mote falls to in full shadow (0..1) and the world-space band over which it
// fades into the surface behind it. Defaults 0.18 and 0.5.
void billboard_renderer_set_lighting(ParticleRenderer* r, float ambient_floor, float soft_fade_dist);
// false = the authored colour times hdr_gain reaches the framebuffer untinted: no key-light
// lookup, no ambient floor. Default true.
void billboard_renderer_set_lit(ParticleRenderer* r, bool lit);
```

**The unlit path is two uniform values and no shader edit.** `particle_frag.glsl:85-86`
computes `bright = uAmbient + (1 - uAmbient) * sun` and `tint = mix(1, uSunColor, 0.4 * sun)`;
with `uAmbient = 1.0` and `uSunColor = (1,1,1)` both are exactly 1.0 whatever `sun` holds, so the
unlit draw sets those two and skips `scene_key_directional`. **It keeps
`bind_shadow_maps_to_program`**: that call sets the `shadowMaps` sampler to unit 10 before its
early return (`shadow.c:517`) and uploads `numShadowLights = 0` for a disabled system
(`:548`); skipped, `shadowMaps` sits at unit 0 beside `uSpriteTex` whenever no sprite is bound
(`particle_renderer.c:135-137`), two sampler types on one unit, `GL_INVALID_OPERATION` at the
draw and no motes — a failure sprites' capture would not see because sprites binds a sprite. A
shader branch on a "lit" uniform was the alternative and is refused on the rule
`glsl-branch-not-byte-identical`: the lit path is spores' capture, and a branch re-lowers it.
The header documents what 11.105's ledger recorded as four surprises: size is a HALF-width
(`particle_vert.glsl:31-33`), the life fade is in over the first 10% and out over the last 30%
(`particle_frag.glsl:68-71`), and the key tint's 0.6 floor (`mix(1, 0, 0.4)` with no key).

sprites calls `billboard_renderer_set_lit(renderer, false)` and its white key light with its
node (`sprites.c:224-233`, which exists only to make the tint the identity; `uSunColor` is the
key's `color` unscaled, `particle_renderer.c:154-156`, white by default) goes **if the capture
proves it**: today's path is `bright = 0.18f + 0.82f * 1.0`, which rounds to exactly `1.0f` in
single precision, so 0 px is the expectation; the capture against the phase-2 reference is
measured and recorded either way.

### 8. A canvas controller, the 2D twin of `MouseDragController`

shapes (`shapes.c:33-36, 45-64, 66-111`) and pcb (`main.c:37-40, 126-142, 144-212, 214-240`)
carry the same three statics, the same `pan_canvas`, the same press/release latch and the same
picked-node drag, byte-for-byte in logic. pcb alone has zoom, with its own window→framebuffer
conversion (`main.c:221-224`) — the engine's THIRD copy of that conversion (`engine.c:1133-1134`
in the cursor callback, `1168-1169` in the button callback). Into `app.h`:

```c
typedef struct CanvasController {
    // ENGINE-OWNED (by the controller): the engine and the pan in flight.
    Engine* engine;
    bool panning;                 // a drag that started on empty space
    vec3 pan_start_look_at, pan_start_position;
    // SETTINGS
    float zoom_min, zoom_max;     // ortho_height range; both 0 = unclamped
    float zoom_step;              // ortho_height factor per scroll notch, default 0.9
} CanvasController;

CanvasController* create_canvas_controller(Engine* engine);
void free_canvas_controller(CanvasController* ctrl);
// The world point under a framebuffer position on a square-on orthographic camera:
// look_at + (fb - fb_centre) * (ortho_height / fb_height). What both 2D apps computed.
void canvas_world_under_cursor(const Engine* engine, double fb_x, double fb_y, vec3 out);
// Press: pans when the engine's pick found nothing; release: stops. Returns whether a pan is on.
bool canvas_on_button(CanvasController* ctrl, int button, int action, int mods);
// Drags the picked node on the drag plane (x and y; z untouched), else pans.
void canvas_on_cursor(CanvasController* ctrl, double fb_x, double fb_y);
// Zooms ortho_height by zoom_step^yoffset about the point under the cursor, within the range.
void canvas_on_scroll(CanvasController* ctrl, double xoffset, double yoffset);
```

The engine's cursor callback hands the app FRAMEBUFFER coordinates with +Y up
(`engine.c:1133-1134, 1147`), returns early when the GUI wants the pointer (`:1122`), and the
scroll callback forwards `(engine, xoffset, yoffset)` raw (`:1228-1229`);
`engine_mouse_to_drag_plane` takes framebuffer coordinates (`:2861-2885`). The scroll handler
needs the cursor's position, so **`engine_cursor_fb(const Engine*, double* fb_x, double* fb_y)`**
(query + convert) replaces the three copies of the conversion: the cursor callback, the button
callback and pcb all call it. No new `InputState` field. `canvas_on_button` needs no position:
the press already wrote `input.center_fb_x/y` (`:1186-1187`), which is what pcb reads at
`main.c:191`. The picked-node drag uses `node_set_position` with z read back from the local.

pcb keeps its corners: its press callback runs its own picking first and, on a corner or quad
hit, records the drag and clears `engine->input.selected_node` as it does today WITHOUT calling
`canvas_on_button` (so no pan starts); on a miss it calls it. Its cursor callback tries
`drag_corner` and `drag_quad` first, then `canvas_on_cursor`. Its release clears its state, then

## As built

Five commits on `11.108-settings-and-setters`: the spec, then one per code phase, then the
docs, the ledger and the review fixes together. Every phase's gate ran as written; nothing was
re-baked.

**What matches the plan.** The three-role rule and the two banner styles; every deletion in the
§1 table with its site counts (58 lines rewritten by the script and read line by line, the
GUI's two local-variable checkboxes made direct binds with their two `CONFIG_GUI_LOCALS`
entries removed); the gizmo de-propagation with `SceneNode.xyz_shader_program` deleted and the
build taking the engine's switch; wireframe's cull toggle at the frame top;
`postfx_set_fog_ambient` with the flag beside the value and the sky's deleted;
`node_set_position`; the unlit particle path as two uniform values with the shadow bind kept;
the canvas controller and `engine_cursor_fb`; the ten overviews and the docs. What the plan
drew and the reviews then took away or reshaped is under "The reviews", below.

**What deviated, and why.**

- `SkyAtmosphere` and `CloudLayer` took the by-kind banner, not the reorder: both are
  feature-organised with essays that read as a unit, which is the plan's own criterion for the
  by-kind style; the plan had listed them under the reorder group.
- `Scene` was reordered after all, the registries gathered under BY FUNCTION and the settings
  at the end, with the origin-shift essay kept with the two fields it describes.
- The two picked-node drag sites (shapes, pcb) were ported to `node_set_position` inside the
  canvas controller in phase 4 rather than in phase 3, since the block moved there.
- The importer's write of `Camera.aspect_ratio` went with `horizontal_fov`: the aspect is
  re-derived from the framebuffer every frame and the banner says never write it.
- The three renderer setters carry their guard inline: a shared `_billboard_of` helper was
  written and withdrawn when cppcheck asked for its parameter to be const, which would have
  made the public mutators const in turn.
- forest's fog-ambient write survives under `--no-sky` only, through the setter, as the plan's
  review found: with the sky it never reached a pixel.

**Caught live.**

- **Nothing in the frame ever enabled back-face culling.** It came from the IBL bake's
  unconditional `glEnable` after a prefilter (`ibl.c`), a probe or GI capture, a two-sided
  draw's restore, or an app calling the wireframe setter with `false` at startup. spores had
  none of those and rendered its sphere unculled: a flat dark disc where the shaded sphere
  and its floor shadow now are. The frame top enabling the state each frame moved that capture
  by 1,232,820 px (33.4%) to the picture the scene describes; forest `--no-sky`, with no IBL
  bake either, moved 39 px the same way. Every scene with an environment had the state on by
  accident and is byte-identical.
- The `config-coverage` arm's two `CONFIG_GUI_LOCALS` entries (`taa`, `wireframe`) would have
  failed the phase-2 gate as stale once the checkboxes bound the fields directly; the plan's
  review caught it and the entries went in the same commit.
- forest's `--no-sky` path was the one place its authored fog ambient reached a pixel; the plan
  had it deleted outright, the review found the path, and it survives there.
- The unlit particle path must keep the shadow bind: that call parks the cascade sampler on
  its own unit, and without it the array and the sprite share unit 0 as two sampler types,
  which is an invalid draw sprites' capture could not see because sprites binds a sprite.
- The plan's `node_set_transform` was dropped before it was written: the only whole-matrix
  copy in any app is a composed translate-rotate-scale, and a one-caller `glm_mat4_copy`
  wrapper is the shape the six deleted `transform_*` functions had.
- The engine's overlay rows in the snapshot (`engine.overlays.xyz`, `.wireframe`) were plain
  stores that skipped the setters' side effects; both are truthful now, and were used as the
  headless check of the two paths (a snapshot with `xyz` on draws the gizmo, one with
  `wireframe` on draws every edge with no culling).

**Measured.** 30 goldens at 0 px after phases 2, 3 and 4. Captures against the spec-commit
reference: sprites, network, tree and pcb byte-identical at every phase (sprites with the unlit
renderer and no key light: 0 px, so the light went); spores byte-identical after phase 2's
culling change (1,232,820 px, above) and through phases 3 and 4; forest at its floor

culling change) then 0 and 6 px against an 8 px run-to-run floor. `gates --only

config,forest,island,exposure` after phase 3 (198 controls, 252 rows: the two sliders and two
rows gone). pcb built against phases 2, 3 and 4 from its submodule and captured byte-identical
each time; shapes and pcb launched to a window. The 11.107 consumer harness rebuilt against the
branch through `add_subdirectory` with one line changed (its frame limit is a field write) and
reproduced every 11.107 behaviour.

**The reviews** (four simplify angles and the thermo-nuclear audit, all in background agents and
all finished before a line moved) changed more than 11.107's did, and each item is a departure
from the plan's own text:

- `SubmitState.no_cull` went. `render.h` already states that `two_sided` is resolved by the
  caller so a pass running with culling off is not toggled mid-pass, and the shadow pass
  already did it; the two scene-pass callers now resolve `DRAW_DOUBLE_SIDED && !show_wireframe`
  and the tracker keeps its charter. The GI capture and the probe capture, which enable culling
  inside the frame window, now put it back as found instead of relying on the frame top.
- `engine_cursor_fb` had the cursor callback discard GLFW's event position and re-query the
  pointer, under a comment claiming the two were equal; they are equal only with the cursor
  disabled. A static `_window_to_fb` converts the callback's own arguments, and the query
  wrapper serves the button callback and the scroll handler, which have no position.
- The preset's two overlay writes were dead: both fields default off at creation, and the only
  effect was forcing two apps to move a line. They went, with the sentences that described
  them; the brief's item is answered by the defaults it assumed were on.
- `billboard_renderer_set_lighting` had no caller, in a branch that deletes six functions for
  the same reason; it went, and the two tunables are the constants they were. `set_lit` stays.
- `SceneNode.show_xyz` had no writer once the propagation was gone: a constant true under a
  banner. It went; the gizmo gate is the engine's switch and the scene's program, so a scene
  with no program appends nothing either.
- The role vocabulary was applied inconsistently in its own headers: the camera's orbit triple
  was "never write" over a comment saying how to write it, and the sky filed the same
  write-then-call shape under BY FUNCTION. BY FUNCTION now reads "through, or followed by, the
  function named" and the triple sits under it; `is_skinned` moved to SETTINGS, since only the
  importer set it and the upload gates on it; a node's name and the scene's origin callback
  moved under BY FUNCTION beside their functions; the five subsystem pointers say "installed
  once" rather than "at any time", since nothing frees a replaced one.
- The rule reached edges the spec had not walked: `scene_set_cameras` / `scene_set_lights`
  (uncalled, and a foreign array into an owned registry), `postfx_set_exposure` /
  `postfx_set_profiler` (installs only the engine called), `text_mesh_set_transform` (a copy,
  no caller) and four `entity_set_*` copies went; `game_set_physics_world` /
  `game_set_entity_manager` free what they replace, which earns them their function; and
  `light_set_position` mirrors `light_set_direction`, because a light on no node is never
  re-derived by the walk and a direct write to its authored position never reached a pixel --
  the importer now goes through both.
- `PostFX.fog_ambient_from_sky` gained its snapshot row and the ambient row became a plain
  store: a sky-driven session used to restore pinned, since the apply hook cleared the flag.
- `camera_translate` is the one "eye and target by one vector" that four camera moves and the
  two controllers' pans and the zoom wrote out seven times; the canvas pan is now the
  world-under-cursor function applied twice, and the drag controller's button hook drops the two
  cursor arguments it never read, with the four apps' dead GLFW queries.
- `canvas_on_button` returns nothing (no caller read it); the zoom range clamps each bound on
  its own; `node_set_position` is a cglm copy; the ten overviews lost what their banners
  already said.

Declined: reusing the engine's ray unproject for `canvas_world_under_cursor` (the zoom anchors
per wheel notch against the LIVE camera, where the engine's matrices are last frame's);
`_billboard_of` (cppcheck, above); the drag controller's two install hooks and the three
embedder hooks as fields (installs of borrowed state are a statement about ownership a field
write does not make, and 11.106 kept them by name); moving `engine_set_render_time` internal
(its header documents a foreign loop as its caller).
