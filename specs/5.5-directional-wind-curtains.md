# 5.5 First-class directional wind + curtain sway (WPO cloth)

## Context

The `abandoned_window` scene has two **static, unrigged** sheer curtains — `Curtain_L`
(material `LaceCurtain`) and `Curtain_R` (material `SheerCurtain`), ~2.5 m-tall flat sheets,
~2200 verts each, tops pinned at y≈3.03, hems at y≈0.5. The goal: make them **gently blow back
occasionally**, as if a draft comes through the window.

The engine has **no cloth simulation** reachable today: Jolt soft-body cloth is vendored but the
JoltC create functions are commented out and no cetra soft-body layer or per-frame vertex-writeback
exists (a large three-layer gap, in the game/physics subsystem -- wrong tool for an ambient viewer
effect). Springbones need a `Skeleton` (return NULL without one) and only move bones through
skinning; the curtains have no rig. There is no existing wind/morph vertex path -- `pbr_vert.glsl`
declares `uniform float time` but never uses it.

**Chosen approach: procedural vertex-shader wind (World-Position Offset)** -- the modern-engine
standard for ambient, non-interactive cloth/foliage -- architected the proper way: wind is a
**first-class scene object** (like UE `WindDirectionalSource` / Unity `WindZone`), the curtain
**materials opt in** with a response weight + pinning mask, and the displacement stays
**motion-vector-correct** so TAA/motion-blur don't smear it. Not material-baked.

## Design

### 1. New `Wind` scene object -- `cetra/src/wind.c` / `wind.h`
`Wind` struct: `char* name; WindType type` (WIND_DIRECTIONAL for v1); `vec3 direction` (world,
normalized blow dir); `float strength, speed, gust_frequency, gust_amount, turbulence`.
`create_wind(name)` / `free_wind()` / `wind_default_params()`. A location-guarded
`wind_upload_to_program(const Wind*, UniformManager*)` uploads `uWindDir/uWindStrength/uWindSpeed/
uWindGustFreq/uWindGustAmount/uWindTurbulence` -- **mirrors `shadow_upload_cascade_uniforms`**. Add to
CMake (`cetra/CMakeLists.txt`).

### 2. Scene ownership -- `cetra/src/scene.c` / `scene.h`
`Wind* wind;` on `Scene` (a single dominant directional wind -- an environmental property like
`sky`/IBL, not node-borrowed). `set_scene_wind(scene, wind)` takes ownership; freed in `free_scene`.
(Array / localized winds are a clean later extension.)

### 3. Material opt-in -- `cetra/src/material.c` / `material.h`
Add `float wind_response;` (0 = rigid) and `float wind_mask_min_y, wind_mask_max_y;` (pinned top =
max_y, free hem = min_y; derived from the mesh AABB at config time). Zero-initialized in
`create_material` so every existing material is inert.

### 4. Shader -- WPO with correct motion vectors -- `cetra/shaders/pbr_vert.glsl` (+ `pbr_skinned_vert.glsl`)
New uniforms: the six `uWind*` globals, the three per-material (`uWindResponse`, `uWindMaskMinY`,
`uWindMaskMaxY`), and `uDeltaTime` (global; `time` already exists).
```glsl
vec3 windOffset(vec3 p, float t) {
    if (uWindStrength <= 0.0 || uWindResponse <= 0.0) return vec3(0.0);
    float h    = clamp((uWindMaskMaxY - p.y) / max(uWindMaskMaxY - uWindMaskMinY, 1e-4), 0.0, 1.0);
    float mask = h * h;                                   // pinned top, hem swings most
    float gust = mix(1.0 - uWindGustAmount, 1.0, pow(0.5 + 0.5*sin(t*uWindGustFreq), 3.0));
    float ph   = t*uWindSpeed + p.y*2.0 + p.x*1.3;
    float sway = 0.5 + 0.5*sin(ph);                       // forward push 0..1
    float amp  = uWindStrength * uWindResponse * mask * gust;
    return normalize(uWindDir) * (sway*amp) + vec3(sin(ph*3.1)*uWindTurbulence*amp*0.3);
}
```
Apply to **both** positions: current `vec3 pc = aPos + windOffset(aPos, time);` feeds `worldPos`
(line 59, -> clip + CurrClip + view); previous `vec3 pp = aPos + windOffset(aPos, time - uDeltaTime);`
replaces the bare `aPos` in `PrevClip` (line 64). This keeps the motion vector honest (no
TAA/motion-blur ghosting). Normals left static (fine for gentle sway; perturbing them is a follow-on).
Exact sway math tuned against captures. Regen `shader_strings.h` (build runs `gen_shader_header.py`).

### 5. Uniform plumbing -- `cetra/src/render.c`
- **Global wind + dt**: in `_render_node`'s program-switch block (~line 347-365, next to `time` at
  :361) call `wind_upload_to_program(scene->wind, u)` and `uniform_set_float(u, "uDeltaTime",
  (float)engine->delta_time)`. When `scene->wind == NULL`, upload `uWindStrength = 0`.
- **Per-material response**: in `_update_program_material_uniforms` (:154) upload the three
  `uWind*` per-material values from the `Material` fields. It runs on every material switch, so
  non-cloth materials upload 0 and self-reset -- nothing else can move.
- The curtains are `ALPHA_BLEND` -> they draw through this same `_render_node` with
  `mat->shader_program` (the PBR program) in the OIT/late pass (:340), so the wind uniforms reach
  them with no special-casing.

### 6. Data-driven config via `.cscn` -- `cetra/src/cscene.h`/`.c`, `apps/render/src/cscene_apply.c`, asset
- `CetraSceneDesc`: add a wind block mirroring the fog fields' `has_*`+value pattern
  (`wind_enabled`, `has_wind_direction` + `wind_direction[3]`, `wind_strength`, `wind_speed`,
  `wind_gust_frequency`, `wind_gust_amount`, `wind_turbulence`). `CSceneMaterialOverride`: add
  `bool has_wind_response; float wind_response;`.
- `cscene.c`: parse a `"wind"` object and a material `"windResponse"` (reuse `get_float`/`get_vec3`).
- `cscene_apply.c`: if `wind_enabled`, `create_wind` + `set_scene_wind`; for each material override
  with `wind_response`, set `material->wind_response` and derive `wind_mask_min/max_y` from the
  `mesh->aabb` (local Y) of the mesh(es) using that material.
- `assets/abandoned_window/abandoned_window.cscn`: author `"wind": { direction, strength, speed,
  gustFrequency (low -> occasional), gustAmount (high -> calm between gusts), turbulence }` and
  `"windResponse": 1.0` on `LaceCurtain` + `SheerCurtain`. **Coordinate with the uncommitted
  edits to this file -- fold in additively, do not clobber.**

## Reuse (don't reinvent)
- `shadow_upload_cascade_uniforms` (`shadow.c`) -- template for the location-guarded
  `wind_upload_to_program`.
- `uniform_set_float`/`uniform_set_vec3` dynamic cache (`uniform.c`) -- new uniforms need no
  registration.
- `time` uniform (already uploaded, `render.c:361`) + `engine->delta_time` (`engine.h`) -- the WPO
  clock and the motion-vector dt.
- The fog block + `CSceneMaterialOverride` parsing (`cscene.c`) -- template for the wind block +
  `windResponse`.
- `mesh->aabb` (`mesh.h`, already computed for culling) -- the height-mask range.
- Sky/IBL scene-ownership pattern -- model for `scene->wind`.

## Verification
1. `./build.sh` clean (shader header regenerates).
2. **The look** -- `./out/bin/render assets/abandoned_window/abandoned_window.cscn --headless
   --frames 400 --screenshot-every 80 /tmp/.../wind.ppm`, tile the frames: curtains hang still,
   swell into the room on a gust, settle. Tune direction/strength/gust in the `.cscn` across a few
   captures until it reads as "occasional gentle billow," hems moving most, tops pinned.
3. **Motion vectors** -- `--taa --motion-blur` run: no smear/ghost trails on the moving curtain
   (proves the previous-position displacement).
4. **No regression** -- `render <other model>`: `scene->wind` NULL + all materials `wind_response` 0
   -> zero displacement, output identical to before. In the window scene, walls/ivy/rod stay static.
5. Confirm the BLEND curtains actually receive the wind uniforms (drawn via `mat->shader_program`).

## Risks / notes
- **Transparent pass**: curtains are `ALPHA_BLEND`; confirm the wind uniforms reach the program they
  draw with (same PBR program via `_render_node` -- expected). If OIT ever uses a distinct vertex
  program, mirror `windOffset` there.
- **Uncommitted `.cscn`**: `abandoned_window.cscn` is modified in the working tree -- fold the wind
  block in without disturbing those edits.
- **Normals static** in v1; billow-lit normals are a follow-on.
- **Determinism**: wind animates off wall-clock time -> window screenshots aren't byte-deterministic
  (a look, not a CI target); scenes with no wind are unaffected.
- **Payoff of first-class**: the same `scene->wind` can later drive foliage, more cloth, and even
  advect the window dust -- the reason for not baking it into the material.
