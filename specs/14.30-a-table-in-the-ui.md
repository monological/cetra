# cetra 14.30: a table in the UI

## Context

pcb 7.4.2's board modal shows a board's stackup as rows: each layer's number, the stackup's
thickness beside them, a picture of the layer, its name, weight, net and thickness, and under an
impedance profile each line's width, gap, impedance, deviation and delay. The UI has nothing that
lines columns up across rows, so pcb draws every row with a draw hook and lays the columns out by
hand (`board.c`'s `Widths` and `columns_of`): it measures each column's widest text over every row,
works out where each column starts, and draws each word there. Looked at, the result is poor: a
profile's numbers are run together into one line (`w 10.11mil*  g 6mil  90.00 ohm (35.40
common)  +0.0%`), no column is named, and the drawing column is squeezed to a strip by the words
beside it. Every list pcb is to show after it -- its parts, its nets, its checks -- would lay its
columns out by hand again.

What the UI has falls short of a table:

- **A row of labels per row**, in a scrolling pane. Each row lays out its own children, so a column
  lines up only where the app gives the same cell in every row a FIXED width it measured itself:
  the hand layout above, repeated in every app.
- **Virtual rows** (`ui_scroll_set_rows`, spec 14.2) build only the rows in view, so a column fitted
  to its widest cell cannot see a row not built, and building every row to measure it is what
  virtual rows exist to avoid.
- **A header** that stays while the rows scroll has to be a sibling outside the pane, its columns
  kept in step with the rows' by hand, and the pane's bar then runs beside the rows alone.
- **A cursor** on a row -- the row a key moves, which the rest of a view follows -- is the app's
  state, drawn and moved by its own hook, and shown by scrolling to a row that may not be built.

`ui.h` keeps the element list closed: "Another kind is a later spec with its own argument." This is
that spec. The argument is the four points above, and the precedent is the code editor (spec 14.4):
a kind with state of its own, reached through `UIWidgetOps`, drawing many rows it never makes
elements for.

Branch and spec: `14.30-a-table-in-the-ui`, off cetra's master (`9568472e`).

## The model

Three borrowings, one for each part of the table:

- **Its columns' widths are CSS grid's**: each column a track sized across every row, in cetra's own
  four modes. FIT is the column's widest cell over all the rows, its title among them (grid's
  `auto`); FIXED its length in points; SHARE that share of the table's width less its gaps (a
  percentage); GROW an even part of what the others leave (grid's `1fr`). SHARE is settled before
  GROW, as it is for elements (spec 14.9), so a GROW column takes exactly the rest.
- **Its API is `NSTableView`'s and Qt's model/view**: the app says how many rows there are and the
  table asks for what it shows -- a cell's text, a cell drawn by a callback, a row's height,
  whether the cursor may stand on a row. No element is made for a cell, so a list of 100,000 rows
  costs its measures and nothing per row it does not show.
- **Its behaviour is Dear ImGui's tables', as far as pcb needs it now**: a header that stays put
  while the rows scroll; a cursor the keys move; a cell drawn by a callback. Resizing, reordering,
  sorting and hiding columns wait for a list that needs them.

Rejected: **columns as a property of the scrolling pane**, its rows' children taking a shared
column's width. A FIT column still needs the rows not built, so the pane would need a measure
callback over every row -- a source -- and the header and the cursor would still be the app's. The
source is the table. **Dear ImGui's tables themselves**: an immediate API over a retained tree, and
a second UI in one window, with its own fonts, theme, focus and keys. **Fitting a column to the
widest cell seen so far**, as ImGui does: the columns widen as the person scrolls. Every row is
measured, once, and only the rows that change are measured again.

## The design

### The element (`ui.h`)

`UI_TABLE`, a kind after `UI_EDITOR`, and its constructor beside the scrolling pane's:

```c
// A TABLE (spec 14.30): rows the app's source fills, lined up in columns sized across every row,
// under a header that stays while they scroll, with a cursor on a row the keys move. Its calls are
// ui_table_*, in ui_table.h. Give it a height -- grown or fixed -- or let it fit its rows up to its
// max_size, past which it scrolls.
UIElement* ui_table(UIElement* parent);
```

It holds no elements: one made under it is refused by name. It is focusable, takes the keys while it
holds the focus as a text field does, and takes a key hook (`ui_set_on_key`), which is handed each
key first, as a field's is. `UIElement` gains `struct UITable* table`, ENGINE-OWNED beside `field`
and `editor`; `_ops` picks `ui_table_ops` for it.

### Its calls (`ui_table.h`, a public header)

```c
#define UI_TABLE_COLUMNS_MOST 32

// A column, copied when set.
typedef struct UITableColumn {
    const char* title; // the header's words, copied; NULL for none. No column with one, no header
    UISize size;       // FIT, FIXED, SHARE or GROW, across every row
    float length;      // FIXED's points, SHARE's share (0 to 1); FIT and GROW ignore it
    UIAlign align;     // its cells' text across them: START, CENTER or END
    bool drawn;        // its cells drawn by the source's `draw` rather than as text
} UITableColumn;

// A cell's text as the source gives it, read before the source is asked again.
typedef struct UITableCell {
    const char* text; // UTF-8, its lines broken at '\n'; NULL or "" for none
    vec4 colour;      // alpha 0 = the table's text colour
} UITableCell;

// What the table asks the app, `user` handed back to each call.
typedef struct UITableSource {
    // Row `row`'s cell in a column not drawn.
    void (*cell)(int row, int column, UITableCell* out, void* user);
    // A drawn column's cell, clipped to `cell`, in window points; `cursor` true on the cursor's
    // row. NULL with no column drawn.
    void (*draw)(UIDrawList* dl, UIRect cell, int row, int column, bool cursor, void* user);
    // Row `row`'s height in points; NULL for its tallest cell's lines.
    float (*height)(int row, void* user);
    // Whether the cursor may stand on row `row`; NULL for every row.
    bool (*holds)(int row, void* user);
    void* user;
} UITableSource;

// The columns, copied, every row measured again at the next layout. Refused by name: none, more
// than UI_TABLE_COLUMNS_MOST, a drawn column sized FIT, which has no text to fit, and a call on
// anything not a table.
void ui_table_set_columns(UIElement* table, const UITableColumn* columns, int count);
// `count` rows read through `source` (copied): every row measured at the next layout, the cursor
// on none and the scroll at the top. Refused by name for a count below 0 or a source with no `cell`.
void ui_table_set_rows(UIElement* table, int count, const UITableSource* source);
// The rows grown or shrunk at their end, keeping every measure: only the rows added are measured.
void ui_table_set_row_count(UIElement* table, int count);
// Rows `first` to `first + count` changed: measured again at the next layout and drawn as the
// source now gives them.
void ui_table_rows_changed(UIElement* table, int first, int count);

// The cursor's row; -1 for none.
int ui_table_cursor(const UIElement* table);
// The cursor put on `row`, or on none for -1, and the least scroll that shows it; no on_cursor,
// since the app did it. Refused by name for a row out of range or one the source says cannot hold
// it.
void ui_table_set_cursor(UIElement* table, int row);
// The cursor moved `by` rows that can hold it, stopping at the first and the last, as the keys move
// it: on_cursor follows. What a host's own keys call -- pcb's j and k.
void ui_table_move_cursor(UIElement* table, int by);
// Once after a pass in which the person moved the cursor: a key, a press, ui_table_move_cursor.
void ui_table_set_on_cursor(UIElement* table, UIActionFn on_cursor, void* user);

// The least scroll that shows row `row`, easing there.
void ui_table_scroll_to_row(const UISystem* ui, UIElement* table, int row);
// Where row `row`'s cell in `column` stands, in window points, as the last layout placed it, the
// whole row's for column -1; false for a row not in view.
bool ui_table_cell_rect(const UIElement* table, int row, int column, UIRect* out);
```

### Columns and rows

- **Measured once.** A cell is measured when its row is first laid out, through the UI's one text
  walk (`ui_text_make`, `ui_text_widest_line`), so a cell's width and its glyphs agree as a label's
  do: its lines and its widest, kept per row and column. A FIT column is the widest kept in
  it, its title's included. The measures are kept until the columns, the rows, the font or its size
  change, or the app marks a row changed, which measures that row alone; a row that was a column's
  widest and shrinks narrows its column, its widest found again over what is kept. The cells
  measured count into the element's `measures`, which the arms read.
- **The columns across.** In the table's content rect: FIXED and FIT first, then SHARE of what is
  across less the gaps, rounded down to a whole point, then GROW evenly over what is left, each
  column's start on a whole point. The gap between two columns is the element's `spacing`. Columns
  wider than the table run past it and are clipped; a table that fits its content (FIT across)
  measures its columns' sum and its gaps.
- **A row's height** is the source's `height`, or its tallest cell's lines at the theme's line
  height, plus `UITheme.table_row_padding` above and below. Rows meet with no gap, so a drawn column
  runs on from row to row, as pcb's via and thickness do.
- **The header** is one row at the top of the content rect, each title in its column's alignment,
  in `UITheme.table_header`, with a one-pixel rule under it in the same colour. It does not scroll;
  the rows scroll under it, and the bar runs beside the rows alone.

### Drawing

Only the rows in view are drawn, found by a binary search of the rows' starts. Behind the cursor's
row, `UITheme.table_cursor`. A cell's text is drawn line under line, centred down the row, across it
by its column's alignment, in its own colour or the table's, clipped to its cell. A drawn cell is
handed its rect, clipped to it, after the cursor's fill and before the next cell. The table's
background, its border and its focus border are its `UITheme.table` style's, as a text field's are.

### The cursor, the keys and the pointer

- **Keys, while it holds the focus**, after its hook declines them: Up and Down move the cursor by
  one row that can hold it, Page Up and Page Down by a view's rows, Home and End to the first and
  the last; each shows the cursor's row. Any other key is not used and goes to the screen, Esc and
  Tab among them, as a text field's do.
- **A press on a row** puts the cursor there if the row can hold it, and takes the focus. A press on
  the header does nothing.
- **The wheel and the bar** scroll the rows through `UIWidgetOps.scroll`, `scroll_to` and
  `scroll_by`, as the editor's do.
- **No cursor until one is set or moved to.** The first Down puts it on the first row that can hold
  it, Up on the last.

### The theme (`UITheme`)

```c
// A table (spec 14.30): `bg` behind its rows, `fg` its text, FOCUS its border while it takes the
// keys.
UIStyle table[UI_STATE_COUNT];
vec4 table_header;       // its header's titles and the rule under them; alpha 0 = its text at 60%
vec4 table_cursor;       // behind the cursor's row; alpha 0 = the selection colour
float table_row_padding; // points above and below a row's lines; 0 = 2
```

## Tests

In the `ui` group, through gametest's `--ui-probe` (no window, no GPU) for the layout and the input,
and `apps/canvas` headless for the picture, each arm's docstring in the group's list:

- `ui-elements-closed`: `_UI_KINDS` gains `ui_table`.
- **`ui-table-columns`**, as exact rects at two widths: a FIT column as wide as its widest cell,
  which is row 90,000 of 100,000; a FIT column narrower than its title, as wide as the title; a
  FIXED column its length; a SHARE of 0.3 that share of the width less the gaps, rounded down; two
  GROW columns halving the rest; the gaps the element's spacing. Falsified by measuring only the
  rows in view: the first FIT column comes out narrower.
- **`ui-table-measure`**: 100,000 rows of 4 columns measure 400,000 cells once; laying out again
  measures none; a row marked changed measures 4; the widest cell shrunk narrows its column to the
  next widest; a new row count measures only the rows added. Falsified by measuring at every layout.
- **`ui-table-heights`**: a row of one line and a row of three are their lines at the line height
  plus the padding; a source's `height` wins; the rows meet with no gap; the header stays at the
  top with the rows scrolled 1,000 points.
- **`ui-table-view`**: of 100,000 rows only those in view are drawn, counted by the source's calls
  in a draw; scrolled to row 50,000 it shows that row.
- **`ui-table-cursor`**: Down from none puts the cursor on the first row that holds it; Down and Up
  skip the rows that cannot; End and Home reach the last and the first; Page Down moves by a view;
  each move shows the cursor's row and calls on_cursor once a pass, `ui_table_set_cursor` none. A
  press on a row that holds it moves the cursor there and one on a row that cannot does not. The
  hook is handed each key first: a hook taking Down leaves the cursor where it was. Falsified by
  ignoring `holds`: the first Down lands on a row that cannot hold the cursor.
- **`ui-table-refused`**: no columns, 33 columns, a drawn FIT column, a cursor out of range or on a
  row that cannot hold it, and an element made under a table, each refused and leaving the table as
  it was.
- **`canvas-ui-table`**, in the `canvas` group: `apps/canvas --ui-table` headless, a table of 500
  rows with a header, a FIT name column, END-aligned number columns, a GROW column, a drawn column
  and the cursor on row 3: the header's rule and the cursor's fill where the probe says they are, and
  no glyph's pixels past its cell.

The `ui`, `canvas` and `gate-docs` groups pass as they are: no existing element changes.

## Not in this spec

Resizing, reordering, hiding and sorting columns, and a press on the header; a row activated by
Enter or a double press; editable cells, and cells holding elements; styled runs within a cell;
text cut short with an ellipsis; a cell spanning columns; columns scrolled sideways; more than one
row selected.

## As built

### Phase 1: columns and rows

- `UI_TABLE` after `UI_EDITOR`; `ui_table` beside `ui_scroll` in `ui.h`; `UIElement.table`; the
  theme's `table[]`, `table_header`, `table_cursor` and `table_row_padding`; `ui_table.h` public in
  `cetra/CMakeLists.txt`. The default look is the editor's surface, padding 6.
- `ui_table.c` keeps each cell's widest line (`float`, rows times columns), each row's height, and
  the rows' tops as doubles: 100,000 rows run to millions of points, past where a float holds a sum
  to a point. A row to measure is flagged; a change of the columns, the rows or the style (face,
  size, tracking, line spacing, row padding) flags every row and title. Each column's widest is
  found again over what is kept whenever any row was measured or rows were taken off.
- `UIWidgetOps` gains `content`, what an element's content measures along an axis, which
  `_intrinsic` asks: a FIT table measures its FIT and FIXED columns and the gaps across, and its
  header and rows down; a growing one its header alone down, as a growing pane asks nothing of its
  parent. `ui_element_spacing` and `ui_scroll_step` share `ui.c`'s rules with the table.
- Departure: the source's `height` is the row's **whole** height; the padding is added only to a
  height made of lines. A source drawing a picture row says the height it draws.
- A FIT column's width is exact (its widest line); each column's start is the floor of the running
  sum, so starts stand on whole points of the content while the widths stay what was measured.
- `_new_element` refuses a child of a table, and so does `ui_move`.
- Arms: `ui-elements-closed` (ten kinds, `ui_table` after `ui_scroll` as `ui.h` declares it),
  `ui-table-columns`, `ui-table-measure`, `ui-table-heights`, `ui-table-refused`. The heights arm's
  "the header stays with the rows scrolled 1,000 points" waits for phase 2, which draws the header
  and scrolls. The cursor's refusals wait for phase 3.
- Verified with the arms the diff reaches: the five above, and `ui-scroll-wheel`,
  `ui-scroll-into-view`, `ui-scroll-bar`, `ui-editor-bar-room`, `ui-field-select` and `gate-docs`
  for the shared lines (`_ease` now eases any scroll short of its target, the bar runs down a strip
  its place may name, a widget's drag may be NULL). All pass.
- Falsified: measuring only the first 20 rows makes column 0 44.03 wide against 207.63
  (`ui-table-columns` fails); measuring every row at every layout measures 400,000 again where 0 is
  wanted (`ui-table-measure` fails).
