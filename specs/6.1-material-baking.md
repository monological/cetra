# 6.1 Material baking — Blender exporter bakes procedural materials to texture sets

**Status: shipped.** As-built deltas from the plan below:
- **TEXCOORD_0 discovery:** engines read UV channel 0, but adding `cetra_bake`
  alongside existing layers exported it as TEXCOORD_1 — walls striped with
  atlas gaps. Fix: `strip_superseded_uvs` removes baked meshes' prior UV
  layers (default-cube or absent, superseded by the bake) so `cetra_bake` IS
  channel 0.
- Stepwise driving API for MCP/interactive runs: `prepare_bake(out)` +
  `bake_one(i)` keep individual calls short; `export()` then hits the cache.
- Cycles ran on Metal GPU; 8 samples sufficed (value maps). Full scene bake:
  9 materials, ~100 bake ops, a few minutes; cached export ~0.6 s.
- Bake set detected automatically exactly as designed (floor skipped: its
  image feeds Base Color directly). Emission strength is normalized to 1.0
  during EMIT bakes and restored as a factor (PNG would clip HDR radiance).
- Acceptance render confirmed: walls carry baked peel/dirt/plaster, curtains
  their weave, frame its distressed paint — `FLATTEN_OVERRIDES` deleted.

## Context

Milestone 1 (6.0, shipped) moves everything glTF can't carry through the `.cscn` scene file — except
surfacing. Procedural node graphs (peel/dirt/plaster on walls, lace weave, leaf veins) cannot cross
glTF, so `tools/cetra_export.py` currently flattens listed materials to flat colors via the
`FLATTEN_OVERRIDES` table — the documented stopgap and the dominant remaining gap between cetra's
render and the Blender viewport (flat beige walls vs textured decay).

6.1 replaces the table with real baking inside the exporter: procedural materials are baked to
diffuse/roughness/normal (+alpha, +emissive) texture sets with generated UVs, materials are rewired to
the baked images for the duration of the export, and the GLB ships fully textured. **Cetra needs zero
engine changes** — its textured glTF path is proven (the PolyHaven-textured floor and fixtures already
render correctly, embedded images included).

All work lands in `tools/cetra_export.py` (+ spec). Blender-side facts that shape the design:

- **Cycles is required for baking** and is currently *disabled* in the user's Blender (engine enum
  showed only `BLENDER_EEVEE`; the addon exists on disk). The exporter must enable it
  (`addon_utils.enable("cycles")`), switch the scene engine for the bake, and restore afterward.
- **UVs mostly don't exist.** Curtains/leaves/curls/vines were built via `from_pydata` (no UV layers);
  the walls are primitive cubes whose default UVs overlap (every face maps to the full 0-1 tile), which
  corrupts bakes. Everything baked needs a dedicated non-overlapping `cetra_bake` UV layer.
- **Materials are shared across many meshes** (plaster on 8 walls, PaintFlake on 47 curl meshes) and
  use Object-space procedural coordinates, so each user surface looks different. One texture set per
  *material* therefore requires packing all its user meshes into a shared atlas and accumulating
  per-object bakes into the same image (`bake(..., clear=False)` per object, disjoint UV regions).
- **Instanced meshes collapse variation.** The 483 leaves share one mesh datablock + material whose
  per-leaf hue comes from `Object Info → Random`; a bake evaluates one instance, so per-leaf variation
  is lost. Accepted v1 limitation (leaves keep SSS + one baked vein/mottle set; the alternative — 483
  textures — is absurd).

## Design

### 1. Bake-set detection (replaces FLATTEN_OVERRIDES)
A material needs baking iff its Principled inputs are *not* glTF-expressible: Base Color / Roughness /
Normal driven by anything other than (unlinked value | direct Image Texture). Flat materials (vines,
buildings) and already-image-based ones pass through untouched. Manual opt-out via material custom
property `cetra_no_bake`. The scan yields `{material: [user mesh datablocks]}` (unique mesh *data*, not
objects — instances bake once).

### 2. UV pass
For every mesh in the bake set: add UV layer `cetra_bake`, Smart UV Project (angle limit 66°, island
margin 0.02) into it. Then, per material, pack all its user meshes' islands into disjoint regions of
the shared 0-1 atlas (`uv.pack_islands` across joined selection, or per-mesh sub-rects assigned by
area). Original UV layers untouched; `cetra_bake` becomes the active-render layer only during bake and
export.

### 3. Bake passes (Cycles, per material)
Create images `textures/<mat>_<pass>.png` next to the GLB (resolution policy: walls/floor-class 2048,
default 1024, small props 512 — by summed surface area). Per user mesh: select, add temp Image Texture
node targeting the atlas image (active node = bake target), run passes with `clear=False` accumulation:
- **DIFFUSE** (color only — direct/indirect disabled) → baseColor
- **ROUGHNESS** → glTF metallicRoughness green channel (metallic factor stays 0)
- **NORMAL** (tangent space) → normal map — captures the procedural bump chains (peel ridges, plaster)
- **EMIT** where the material has emission (SkyGlow gradient)
- **Alpha** for materials with non-trivial alpha (curtains' woven noise, glass smudge): temporary
  emission-rig trick — wire the alpha chain into an Emission shader, EMIT-bake to a grayscale image,
  then write it into the baseColor PNG's alpha channel via `image.pixels` (numpy, no external deps).
Bake settings: 16 samples (denoised passes are value maps, not light), margin 8px.

### 4. Rewire + export
Build baked stand-ins (name-preserving, exactly like the current flatten swap): Principled with
Image Texture nodes (baseColor+alpha, roughness, Normal Map node, emission) reading `cetra_bake` UVs.
Swap → glTF export (embeds images; `cetra_bake` set as active render UV so TEXCOORD_0 matches) →
restore originals. `FLATTEN_OVERRIDES` and its restore machinery are **deleted**; the manifest prints
per-material bake results instead.

### 5. Caching
Baking ~9 materials × 3-5 passes ≈ 1-3 min. Skip a material's bake when all its PNGs exist and the
manifest hash file (`textures/<mat>.bakeinfo`: material name + resolution + pass list) matches;
`-- --rebake` (and `REBAKE = True` constant) forces. First export bakes everything; iteration exports
stay fast.

### 6. Scope cuts (stated, not hidden)
- Per-instance variation (Object Info Random) collapses to one bake — leaves go uniform; hue variety
  can return later via vertex colors if missed.
- SSS remains scene-file data (`materials{}.sss` in the .cscn) — baking doesn't touch it.
- Displacement/POM not baked (no height pass in v1).
- The bake evaluates one representative object per shared *instanced* mesh; per-mesh-datablock
  differences are preserved (47 curls each get their atlas region).

## Verification

1. Run the exporter in the live Blender MCP session on the window scene. Confirm manifest: bake set
   detected (plaster, distressed planks, sill, lace, sheer, leaf, flake, glass, skyglow), UVs
   generated, passes baked, cache files written; originals restored; Cycles/engine state restored.
2. Inspect 2-3 baked PNGs directly (plaster diffuse should show peel wounds + dirt; lace baseColor
   alpha should show the weave).
3. `./out/bin/render assets/abandoned_window.cscn -x --frames 150 --screenshot ...` with zero look
   flags → walls show peel/dirt texture, curtains weave, leaves veined; compare against the Blender
   viewport shot — this is the milestone's acceptance image.
4. Re-run the exporter → cache hit, export completes in seconds.
5. Regressions: `sss_fixture.gltf`, `light_import_fixture.cscn`, `room.fbx` unchanged (no procedural
   materials → empty bake set → exporter behaves exactly as 6.0).
6. Blender session left clean: engine restored to EEVEE, no `cetra_bake` layers active for render, no
   stray `.cscn_orig` materials.

## Out of scope
Height/POM baking; per-instance variation preservation; bake-time AO maps; texture compression (BCn)
and the offline cook step; GUI round-trip.
