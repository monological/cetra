# 14.3: the UI's follow-ups from 14.2

## Context

14.2's closing reviews (four `/simplify` reviewers and a correctness pass) left fifteen suggestions
that were not applied. They are recorded in `docs/eda-roadmap.md`, item 5, "Next: spec 14.3". The
call was to do them properly now, before the code editor (item 6) builds on the same UI, rather
than as each first gets in the way. pcb calls none of the APIs that change, so renaming or
reshaping them now costs nothing outside this tree.

**What "properly" means here: a clean API that is cetra's own.** Each change is designed from the
problem it solves and cetra's rules: plain C, a retained tree, plain fields, a closed list of
elements, names subject first. UIKit, Cocoa and Dear ImGui are a check afterwards, for a case we
missed or a reason to choose one shape over another. They are never a template, and a comparison
is written down only where it changed a decision. The roadmap entry written before this was
settled names items after UIKit calls; its wording is corrected in this spec.

**What is decided:**
- Items 1–9 are built.
- Items 10–14 are measured, and you choose which to build from the numbers.
- Item 15 (clearing keys pressed during a loading screen) is not done: it could swallow the press
  that starts silent.

## The changes

### 1. A field's placeholder of its own

Today the dim "Type a command" hint rides the element's `text`. That costs a special case in the
layout, which must not size a field by it, and another in `ui_set_text`, which must not clear the
field's runs.

- `ui_field_set_placeholder(UIElement* field, const char* text)`: copied, NULL for none, held in
  the field's own state. A field's `text` stays NULL.
- `ui_set_text` on a field is refused by name, pointing to `ui_field_set_text` and
  `ui_field_set_placeholder`. One call, one meaning.
- Both special cases go.

### 2. A maximum size on any element

The palette list should be as tall as its rows, up to 12, then scroll. Today the app switches the
list between fitting and fixed on every keystroke to fake that.

- `float max_size[2]` on `UIElement`, under SETTINGS: the most it measures along each axis, in
  points; 0 = no most.
- It applies to FIT and GROW. FIXED is its own size.
- A pane whose content passes it scrolls. Anything else draws past it, as an overflowing element
  does today.
- The palette sets `max_size[1]` once and stops switching modes.
- **The arrange shares the room again.** A GROW child held at its most takes no more. The room it
  leaves is shared among the children still growing, round by round. What is left after that is
  placed by `align_main`, rather than left as a gap at the end. Across the axis, a stretched child
  is clamped before the cross alignment places it.
- **A field has both caps, and the smaller wins.** `max_rows` is in rows, which is a field's
  natural unit; `max_size` is in points, for every element.

### 3. `ui_scroll_into_view`, tested

Nothing calls it and no arm holds it. It is kept, since an app showing one element of a pane
(rather than a row) has no other way, and the `scroll-into-view` probe case gains a reveal by the
app with no focus moved.

### 4. A field's row cap means what its zero says

`max_rows` 0 means 6 today, so the history writes `max_rows = 1000` to mean "no cap".

- `max_rows` 0 = no most, for any field, as `max_size`'s 0 is.
- A multi-line field then grows to fit unless it sets a most. The canvas input line already sets
  6, and the probe's chat field sets one too; the history's 1000 goes.
- Page Up and Page Down page by the rows the field shows, always. Today a field held to a fixed or
  grown height pages by `max_rows`, whatever it shows.
- `FIELD_ROWS_DEFAULT` goes.

### 5. Changing a built row in place, and appending to a field

A streamed reply rebuilds its whole message row at every word: a walk of the message each time,
and any selection in it dropped.

- `UIElement* ui_scroll_find_row(const UIElement* pane, int index)`: row `index`'s container
  while it is built, NULL while it is not (silent, as `find` is). It is valid until the next
  layout, which frees a row marked by `ui_scroll_rows_changed`. The three row calls then each do
  one thing: `rows_changed` builds a row again, `to_row` scrolls to it, `find_row` reaches it.
- `bool ui_field_append(UIElement* field, const char* text, const UITextRun* runs, size_t
  run_count)`:
  - adds `text` at the end, with its own styled runs counted from the start of `text`. They are
    checked as `ui_set_text_runs` checks runs, and refused on an editable field, which stays in
    one style. A streamed message then looks as the same message does built later.
  - the caret, the selection, the scroll and undo stay, and there is no `on_change`. Undo is safe:
    stb's records point only at bytes before the old end.
  - only the last line is broken again; the merged runs keep the rows' cache.
  - refused whole past `FIELD_MAX_BYTES` (1 MiB), returning false.
- The new height is taken at the next layout, since a built row is measured at every one (14.2),
  so nothing is rebuilt. The anchoring and `follow_end` keep the view where it should be.
- Inside `ui_draw.c`, breaking again from a given line is one function. Item 13, if built, extends
  it.
- `apps/canvas`'s streaming appends to the built row when there is one. The message array stays
  the source for a row built later.

### 6. The pointer from the engine

Every app gathers presses, releases and modifiers from its own callbacks to feed the UI, as
`apps/canvas` does with `g_ptr_*`. pcb would copy that.

- **The engine records the pointer as it records the keys.** `InputState` gains:
  - `pointer_fb_x`, `pointer_fb_y`: the cursor in framebuffer pixels, +Y up, the struct's own
    space, updated on every move, the script's included;
  - `pointer_pressed`, `pointer_released`: the left button since the previous frame ended,
    latched on the keys' schedule and cleared in `_engine_clear_latches`;
  - `press_mods`: the modifiers held at the press. It replaces `shift_held`, which is one bit of
    the same fact and has one reader (`app.c`).

  The button held stays `is_dragging`. `center_fb_*` is a different fact (where a drag began) and
  stays. Moves and presses the debug GUI takes are not recorded, as keys are not. The game
  layer's own polled mouse is left alone.
- **`ui_input_read(UIInput* in, const Engine* engine)` replaces `ui_input_add_keyboard`.** It fills
  the pointer (in window points, top-left), its edges and modifiers, the wheel, the keys and the
  clock. It leaves `nav_*`, `accept` and `back` as they were, so an app may set those from its own
  bindings before or after.
- `apps/canvas` drops `g_ptr_*` and fills the UI's input with the one call.
- Game apps (silent, gametest) build their input from the game layer's actions and are unchanged.

### 7. `fuzzy_match` says what it wrote

```c
typedef struct FuzzyPositions {
    size_t count;               // one a codepoint of the query
    size_t at[FUZZY_QUERY_MAX]; // byte offsets into the name
} FuzzyPositions;
// The score, higher better, or -1; `positions` NULL for the score alone. Its count is 0 on -1
// and for an empty query.
int fuzzy_match(const char* query, const char* name, FuzzyPositions* positions);
```

The cap argument goes (the query's most is the struct's size). The canvas palette and the probe
stop walking the query again to count.

### 8. One home for UTF-8, in `text.c`

Today the decoder is there, the encoder is inside the field, and the "starts a character" test is
written out in `ui.c` and in `ui_field.c`.

- **One codepoint type, `uint32_t`, across `text.h` and its callers.** Today the decoder returns
  `int`, the fonts take `int`, and `InputKeyEvent.codepoint` is `uint32_t`.
  - The font calls (`font_get_glyph`, `font_advance`, `font_kern_advance`), `GlyphInfo.codepoint`,
    the UI's glyph walk, the canvas's text and the matcher all move to `uint32_t`.
  - stb_truetype's `int` is met only inside `text.c`.
- `uint32_t text_utf8_next(const char** s)`, the pointer changed from `const unsigned char**`.
  - Its 11 call sites lose their casts.
  - It decodes as U+FFFD, one byte at a time, everything `encode` refuses: overlong forms,
    surrogates, lead bytes F5 to FF, values past U+10FFFF. Today it accepts them.
- `uint32_t text_utf8_prev(const char** s, const char* start)`: the codepoint ending before `*s`,
  which moves back to its start.
  - The cursor comes first, as in `next`. At `start` it returns 0 and does not move.
  - It mirrors `next` exactly: `prev` after `next` lands where it began, at every byte of
    malformed text too. Today's walk back in the field skips any run of continuation bytes, where
    `next` steps one byte.
- `size_t text_utf8_encode(uint32_t codepoint, char out[4])`: the bytes, 1 to 4, or 0 for a value
  that is no character.
- `bool text_utf8_is_continuation(char byte)`: a plain byte test, so a character starts at byte
  `i` exactly when it is false.
- The field's encoder and its walk back, and `ui.c`'s boundary test, go to these.

### 9. One way a label lays out its text

A label has three paths today: no lines, lines broken only at '\n' (runs without wrapping), and
wrapped lines.

- Every label with text keeps its lines: broken at its width when it wraps, at INFINITY otherwise.
- `_emit` always draws the lines, and `_intrinsic` counts them, so its own '\n' count and the
  `ui_draw_text` fallback for labels go.
- Buttons, toggles and the rest keep `ui_draw_text`.
- No pixel moves: both paths place each line by its own width through `ui_text_draw_span`.

### Two of 14.2's additions, settled

14.2 added these without your approval. They're kept, and made consistent:

- **`ENGINE_MOD_SHORTCUT` and `ENGINE_MOD_WORD` become `INPUT_MOD_SHORTCUT` and `INPUT_MOD_WORD`**,
  in `input.h` beside `INPUT_KEYS`. They are bits of `InputKeyEvent.mods`, so they belong with
  it. They are literal values, held to GLFW's by a `_Static_assert` in `engine.c`, as `INPUT_KEYS`
  is.
- **A negative padding means none, as a negative spacing does.** An element's zero padding is the
  style's, so "no padding" could not be said on an element at all. Both of an element's
  inheritable lengths now say "none" the same way, and `padding[]` follows the rule per side.

### 10–14. Measured first, then built where the numbers justify it

**The bench.** `gametest --ui-bench` (no gate arm, since timing does not travel) prints the timings
below. It runs on a release build (`./build.sh --release`, `out/release/bin`) headless, five runs
each, the median quoted with the spread between two whole runs as the noise floor.

| # | What is measured | Build it if (my proposed bar) |
|---|---|---|
| 10 | Both layouts of a drawn frame, on pcb-sized screens: the history at 200 and 4,000 messages, the palette over 5,000 names, a 40-element settings screen | over 1 ms a frame |
| 11 | The share of that spent measuring labels' text | over a quarter of it |
| 12 | The share of a text walk spent in `font_kern_advance` | over a quarter of it |
| 13 | One keystroke in a multi-line field of 1 KB, 20 KB and 1 MB | over 1 ms at 20 KB |
| 14 | `load_font` for Roboto at 64, and its time a glyph | over 100 ms a face |

The bars are judgments, mine, for you to change.

**The numbers come to you before any of 10–14 is built.** The report gives each item's number, its
bar, and a recommendation. If an item is built, its design is:

- **10, laying out only when something changed:**
  - Apps keep writing fields directly; no setters come back.
  - Before laying out, the UI hashes every field that shapes the layout, plus the window's size,
    the theme and the focused element (a pane of rows keeps the focused row built). When the
    hash is last time's, the rects stand.
  - It is taken after the layout, which writes scrolls and row heights itself.
  - What changes only through a function (text, runs, style, children, a field's edits, rows)
    stamps the element from one counter for the whole process. It is never hashed by address,
    and never counted per element, since a freed element's address can come back with its count
    starting at the same value.
  - A selector's borrowed options are hashed by their contents, since they set its width.
  - The list of hashed fields is one function in `ui.c`, with a `_Static_assert` on
    `sizeof(UIElement)` beside it, so a setting added later cannot be left out of it silently.
- **11:** a label's widest line and longest word kept in its lines, under their key. Item 9 gives
  every label lines to keep them in.
- **12:** a kerning pair table on the `Font`, filled on first use. The UI and the canvas's text
  both read through `font_kern_advance`.
- **13:** a field breaks again from the line holding an edit, and stops where its breaks rejoin the
  old ones. It extends item 5's function.
- **14:** cooked through `cook.c` (keyed by the font's bytes, size, field parameters and the
  character set), built in bands across threads, or built on first use. The report recommends one
  from the numbers.

### Not done

Item 15, clearing keys pressed while a loading screen is up. They arrive together in the first
frame, but silent's loading screen takes the press that starts the game through that same poll.

## As built

### Phase 1: UTF-8, one codepoint type, and the matcher (`209745ce`)

- **`text.c` holds every UTF-8 rule.**
  - `text_utf8_next` takes `const char**` and returns `uint32_t`.
  - It now refuses, one byte at a time as U+FFFD: overlong forms, surrogate halves, lead bytes C0,
    C1 and F5 to FF, and values past U+10FFFF. It used to decode them as characters, so `"\xc0\x80"`
    read as a NUL.
  - `text_utf8_prev(&s, start)` finds the character ending at `*s`: the nearest byte before it that
    is no continuation, if a whole sequence from there ends exactly at `*s`, and otherwise the
    byte before `*s` alone. That mirrors `next`, because a byte that is no continuation is always
    a place `next` stops.
  - `text_utf8_encode` and `text_utf8_is_continuation` are the other two.
  - The field's encoder, its walk back (which skipped any run of continuation bytes where `next`
    steps one) and `ui.c`'s boundary test went to these.
- **One codepoint type, `uint32_t`**, through:
  - `GlyphInfo.codepoint`, with the glyph hash keyed by `sizeof(uint32_t)` since uthash's `_INT`
    helpers take an `int`;
  - `font_get_glyph`, `font_advance`, `font_kern_advance`;
  - the UI's walk, the canvas's text and glyph table, the input script's typing, the matcher.

  stb_truetype's `int` is met only inside `text.c`, at its calls.
- **`fuzzy_match(query, name, &positions)`**: `FuzzyPositions` holds `count` and `at[]`, the
  count 0 for no match or an empty query. The canvas palette and the probe stop walking the query
  to count. The header's example was the 14.2 plan's wrong one ("rtnt"); it now uses "st" in
  "fast stop".
- **Arms**:
  - `ui-utf8`: 7 edge codepoints round-trip; 3 non-characters refused; 16 malformed bytes give
    16 U+FFFD; `prev` mirrors `next` at all 15 steps of a mixed string; at the start it returns 0
    and does not move.
  - `ui-match` checks the counts.
- **Falsified**: the decoder without its overlong check gave 13 U+FFFD from the 16 bytes, and a
  `prev` that skips every continuation byte was off at 5 of the 15 steps. Both failed `ui-utf8`.
- **Gates**: `ui`, `canvas`, `idle` and `gate-docs` pass.

### Phase 2: the field and the rows (`0c198cf7`)

- **`ui_field_set_placeholder`**: the hint is held in the field's own state, and a field's `text`
  stays NULL.
  - `ui_set_text` on a field is refused by name.
  - Both of 14.2's special cases went: the layout's "a field's text sizes nothing", and
    `ui_set_text`'s "leave a field's runs alone".
  - The canvas app's input line and palette set their hints through the new call.
- **`max_rows` 0 = no most.** `FIELD_ROWS_DEFAULT` is gone, and the history's 1000 with it.
  - The probe's chat field now sets 6, as the canvas input line already did.
  - Page Up and Page Down page by the rows the field shows. That's its content height over its line
    height, so `ui_field_key` now takes the field's content box, as the press and drag calls do.
- **`ui_field_append(field, text, runs, count)`**, returning bool:
  - the runs count from the start of the appended text, and are checked by `ui_text_runs_check`,
    which is now shared with `ui_set_text_runs`;
  - the merged runs and the text are given to the field's measuring text, so the layout's next
    break finds the rows current;
  - only the last line is broken again, through `ui_lines_break_from`, which breaks from a given
    line (its own function, so item 13 can extend it);
  - refused whole past the field's 1 MiB, and for runs on an editable field.
- **`ui_scroll_find_row`**: silent, valid until the next layout.
- **The canvas history streams by appending.** `message_runs(m, from, runs)` makes a message's
  runs from byte `from` on, for a row built whole and for a word appended alike.
- **Arms**:
  - `ui-field-placeholder`: a hint wider than its field sizes nothing; 50 dim glyphs while empty,
    none once typed into; `ui_set_text` refused.
  - `ui-field-append`: the row found and none past it; text joined; the selection kept; the
    appended run at byte 6; the row grown, not built again; past the most refused; runs on an
    editable field refused.
  - `ui-scroll-into-view`: the app showing row 2 scrolls to its top (76) and keeps the focus.
  - `ui-field-multiline`: with no most, 5 rows in 126 points; Page Down over the 3 rows shown
    moves 3.
- **Falsified**: an appended run left unshifted (at byte 1) failed `ui-field-append`, and paging
  by two rows more than shown (it moved 4) failed `ui-field-multiline`.
- **Gates**: `ui`, `canvas`, `idle` and `gate-docs` pass.
- **Look**: the headless history picture is unchanged, the reply streamed whole by appending and
  the input line's hint showing. Holding a selection in a streaming reply is yours to try in a
  window: `./out/bin/canvas --sheet board --history`, Enter, type, Enter, then select in the reply
  as it arrives.
