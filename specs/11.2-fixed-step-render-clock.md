# 11.2 — Fixed-step render clock, FBX import gate, roadmap bookkeeping

## Context

Three pieces of recorded debt, one branch:

**1. Fixed-step producer render clock.** Headless renders are only deterministic
today for consumers someone individually gated: skeletal animation overrides its
dt to 1/60 in the render app, the cloud scroll carries its own
`headless ? 1/60 : render_delta` ternary, and everything else — particles, the
game loop's step count — still reads the wall clock, which is why wind/particle
assets (abandoned_window, tree, spores) are recorded as "unusable as baselines"
in CLAUDE.md. Exploration found the fix is small because the producer seam
already exists: `Engine.render_time/render_delta` plus a substitutable
`render_clock`, latched exactly once per frame in `engine_run`
(engine.c:2333-2338), and wind + clouds already ride it. Making the producer
itself fixed-step in headless (time = frame_index/60) and rerouting the four
bypassing consumers retires the whole hazard class at the source — the clouds
spec named this the strongest next-spec candidate. Bonus finding: CLAUDE.md's
determinism table is stale in three rows (auto-exposure is already per-frame,
not delta-scaled; wind's hazard is the producer, not the consumer; springs are
already deterministic via the animation dt).

**2. FBX import gate in gates.py.** Spec 11.1's as-built records the gap: no
gate has ever exercised the FBX light-import path (how the c64 black-render
class went unnoticed), and the engine mirrors assimp's raw×0.01 UnitScaleFactor
conversion with nothing pinning it against vendor changes. Exploration proved
an ASCII-FBX fixture is fully feasible: the vendored assimp 6.0.5 reads text
FBX through the identical UnitScaleFactor path, a worked syntax example exists
in its test tree, and a text fixture written by a stdlib-only generator beats
any binary blob on the repo's own regenerability rule. The gate clones the
`run_range_gate` shape — a 2-frame render, no screenshot, log assertions.
One hard constraint found: the import path has no GenNormals and derefs
`mNormals` unconditionally, so the fixture must author normals.

**3. Roadmap bookkeeping.** docs/aaa-rendering-roadmap.md's interlude still
says "B2 clouds remains the next unstarted Tier-1 item" (B2 shipped, spec 11.0)
and the 10.9 bullet says the fog-golden drift "needs an owner" (it got one —
the 11.0 phase-0 bisect resolved it). 11.1 isn't in the series list.

## Settled design

**Clock (spec 11.2, Part A):**
- **The latch splits.** The reroute targets are update callbacks, which run
  BEFORE today's sole latch (engine.c:2333-2338) — as-is they'd read the
  previous frame's clock. So: `render_clock == NULL` (render/tree/shapes)
  latches BEFORE `update()` from the already-computed wall sample — in headless
  producing `render_time = total_frames * (1/60)`, `render_delta = 1/60`
  (frame-index-pure, no float accumulation; `total_frames` verified 0-based at
  that point); an installed clock (game framework) latches AFTER `update()`
  exactly as today. Still one latch per frame, still `engine_run` alone;
  engine.h:187-198 contract comment rewritten to say so.
- `update()` receives the produced `frame_dt` (headless ? 1/60 : wall) — no
  consumer needs wall time (verified), live behavior bit-identical, and the
  game loop's accumulator then takes exactly one fixed step per frame headless,
  which is what makes spores deterministic.
- `#define ENGINE_FIXED_FRAME_DT (1.0 / 60.0)` in engine.h replaces the two
  scattered 1/60 literals (sky_clouds.c:302, render.c:1189).
- `mouse_drag_update` deliberately stays wall-clock at all four sites — it's
  input damping, not scene content (a paused game must still orbit); the
  invariant becomes "no glfwGetTime() in scene-animation paths" (survivors:
  drag input, bake profiling timers, the splash demo's own loop).
- Reroutes: (1) the latch split + headless base in engine.c; (2) update() gets
  frame_dt; (3) sky_clouds.c:301-302 scroll ternary collapses to plain
  `render_delta` (numerically identical headless, newly correct under pause);
  (4) render.c:1165-1168 particles → `render_delta`/`render_time` instead of
  wall dt + glfwGetTime(); (5) render.c:1179-1189 animation dt →
  `render_delta`, headless 1/60 override deleted (the engine now provides it);
  (6) tree.c:1184-1187 particles → same; (7) game.c unchanged. Verified:
  nothing else consumes `engine->delta_time` for rendering; the probe-capture
  render_time save/zero/restore is unaffected.
- **Wind-determinism vehicle: the tree app** (full headless CLI, fixed seeds,
  wind + grass + particles at once) — its promotion from "never a baseline" is
  the headline win. abandoned_window (once observed bistable, 269k px, cause
  unknown) is a 3-render investigation probe only; promoted only on pairwise-0
  proof, else reworded to "wind no longer the blocker, scene quarantined".

**FBX gate (same spec, Part B — 11.1's recorded debt, closed with a pointer
added to 11.1's as-built):**
- `assets/gen_fbx_unit_fixture.py` writes `assets/fbx_unit_fixture.fbx` as
  ASCII FBX 7.4 (stdlib text only — no struct.pack/base64/Blender; best on the
  regenerability rule), cribbed structurally from the in-tree worked example
  `ext/assimp/test/models/FBX/cubes_nonames.fbx`. UnitScaleFactor 1 (the wild
  cm default → 0.01×). One 100 cm cube WITH authored LayerElementNormal
  (mandatory — no GenNormals in the import flags, unconditional mNormals
  deref) + one point-light Model at Lcl Translation (0, 200, 0) cm → expected
  world (0, 2, 0) m. Arriving engine intensity pinned empirically once at
  authoring (FBX Intensity/100 folds into color; import re-normalizes), with
  the derivation in the generator docstring. No .cscn sibling (nothing
  pixel-measured; the latent .cscn+FBX interplay stays deliberately untested).
- `run_fbx_unit_gate()` in scripts/gates.py clones the run_range_gate shape:
  `render -m fixture -x -f 2`, no screenshot, log assertions — (i) the
  unit-scale line says "file declares 0.01x, applied 0.01x"; (ii) the
  `<Light ...>` print shows global_position (0, 2, 0) ±1e-3 and the pinned
  intensity; (iii) the `clustered:` line reports ≥1 clusterable light (the
  exact silently-black symptom); (iv) a second render with `--no-unit-scale`
  shows position.y = 200 (the mechanical-twin idiom via the escape hatch).
  ERROR (no light line) vs FAIL (wrong value) distinguished. Blocking from
  day 1 — the report-only-first convention applies only to pixel-churn
  thresholds; exact log math always blocked immediately.

## As-built (11.2)

Shipped in six commits on `fixed-step-render-clock` (spec, engine producer,
app reroutes, fixture, gate, docs). The design's latch-split prediction held
exactly; no departures from the plan. Measured:

- **The producer.** With no substituted clock, engine_run latches
  render_time = total_frames * ENGINE_FIXED_FRAME_DT and delta = the fixed
  step when headless, BEFORE the update callback; an installed clock still
  latches after. update() receives the produced dt, so the game loop's
  accumulator takes exactly one fixed step per headless frame.
- **spores** (game loop, particles): x3 all pairwise 0 px. On master, two
  runs happened to be byte-identical and the third differed by 357,016 px —
  step-count luck, now step-count law.
- **tree** (wind + grass sway + falling-leaf particles): x2 0 px, from
  308,456 px run-to-run on master. Promoted to baseline-grade.
- **abandoned_window** (wind curtains via .cscn): x3 pairwise 0 px, from
  ~2M px. The previously recorded "bistability" (269k px, cause unknown)
  did not reproduce — consistent with it having been wall-clock wind phase
  all along, not a real bistability.
- **raiden**: recipe 0 px vs the pre-change baseline; WITH springs x2 0 px
  both before and after (the springs row was stale on master already —
  springs ride the animation dt, which headless already fixed; the producer
  made it structural). --no-springs demoted to an isolation flag.
- **Goldens**: all 0 px at every phase (cornell box the standing 4 px at
  1 LSB). Gates green throughout.
- **The FBX gate** (Part B, paying 11.1's debt): assets/fbx_unit_fixture.fbx
  is ASCII FBX 7.4 from a stdlib-only generator — 2,027 bytes, human-readable,
  regenerable by anyone. First run arrived exactly as derived: declared and
  applied 0.01x, light at (0, 2, 0) m, 50 cd (FBX 5000/100 folded into color,
  re-expressed as intensity), 1 clusterable. The gate asserts all four plus a
  --no-unit-scale twin (raw read must place the light at 200 cm), and was
  proven able to fail: --import-scale 2 moves the light to (0, 4, 0) and
  rewrites the scale line. Blocking from day one — exact log math, no
  tolerance to season.
- **Docs**: CLAUDE.md's determinism table rewritten against measurements —
  the auto-exposure "adapts on frame delta" claim was stale (per-frame blend
  + snap since 10.x; the cross-build residual is async-load arrival order),
  wind/springs/particles rows promoted to deterministic, tree/spores/
  abandoned_window asset rows promoted per the numbers above. Roadmap
  interlude corrected (Tier 1 complete, A5 next; the 10.9 fog-drift open
  item resolved by 11.0's bisect) and 11.1/11.2 added to the series.
