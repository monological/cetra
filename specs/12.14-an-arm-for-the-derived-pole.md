# Spec 12.14 — an arm for the derived IK pole

## Context

Spec 12.11 changed which way a knee bends. `ik_add_foot` had taken the bend direction from
its caller — `knee_forward`, a vector in the HIP's frame — and every caller in the tree passes
the `+Z` that suits the generated puppet. On a rig whose thigh binds 178° away from that one,
the same vector points backwards and the knee folds under on every stance frame, with every
chain resolved and nothing warning. So the pole is now taken from the RIG: the perpendicular
part of the bind knee's offset from the hip–ankle line, rotated into the hip's bind frame,
with `knee_forward` kept as the fallback for a rig that binds straight and has no direction to
offer.

**That change has no instrument.** `ik-pole` — the one arm that reads the pole at all — runs
on the generated puppet, whose three leg joints share one x and one z *to the digit*. Its
bind knee sits exactly on the hip–ankle line, so it takes the FALLBACK path, and every number
the arm prints is the behaviour that existed before 12.11. Deleting the derivation entirely
leaves all 21 `ik` arms green.

That is the gap this closes, and it is the shape of failure this repo keeps hitting: a fix
whose own arm cannot see it.

**Outcome: the derivation is asserted by an arm that fails against the code it replaced.**

---

## The assertion, and why it is decisive

**Reuse `--ik-probe pole` completely unchanged.** That case already registers the foot twice
with opposite `knee_forward` (`+Z`, then `−Z`) and reports each resulting knee-z plus the span
between them. It needs a rig, and the rig is the only new thing.

On a rig whose bind knee sits off the line, the derived pole must beat **both** stated
vectors, so the case's own output inverts:

| | straight-binding puppet (today) | bent-binding fixture (new) |
|---|---|---|
| `fwd` (caller says `+Z`) | **+0.1786** | **negative** |
| `back` (caller says `−Z`) | **−0.1786** | **negative** |
| `span` | **0.3573** | **≈ 0** |

The fixture's knee is displaced **−0.06 in z**, and that sign is the whole point: the derived
pole comes out `(0, 0, −1)`, which **disagrees with the caller's `+Z`**. So "both legs put the
knee at negative z" says the rig's own bind beat the argument in the one case where the two
conflict. Against the pre-12.11 code the same run gives +0.1786 / −0.1786 / 0.3573 and the arm
is red.

Arithmetic, computed from the committed `BONES` table rather than from a run:

```
hip (0.10, 0.90, 0)   ankle (0.10, 0.08, 0)   span 0.82   threshold = IK_POLE_BEND * span = 0.0082

knee (0.10, 0.48,  0.00)  ->  perpendicular 0.0000  ->  FALLBACK   (today's puppet)
knee (0.10, 0.48, -0.06)  ->  perpendicular 0.0600  ->  DERIVED, pole (0, 0, -1)
```

---

## The fixture

A second rig, `assets/models/puppet_bent.gltf`, emitted by `assets/generators/gen_puppet_fixture.py`
beside the puppet it already writes. Only the two knee rows of the `BONES` table move
(`LeftLeg`, `RightLeg`, z −0.06); everything else is the same rig.

**The original puppet must not change at all.** Its pure-translation bind is load-bearing and
depended on by name in three places — the animation debugging recipe (`AGENTS.md:1507`), spec
12.1, and `anim-retarget` (`gates.py:15486`), which reads it as "the puppet rests in pure
translation". A separate file is the requirement, not a convenience.

**A displaced knee is still a pure translation**, so the generator's inverse-bind computation —
which states that assumption at `gen_puppet_fixture.py:159` — holds unchanged for the variant.
That is what keeps this a table edit rather than a maths change.

Only a `.gltf` is needed, no `.cscn`: `--puppet` takes a MODEL path (`gametest.c:133`), and
`run_ik_probe` loads it with `create_scene_from_model_path`.

---

## The plumbing

`gametest --puppet <rig> --ik-probe pole` **works today with no C change** — `--ik-probe`
dispatches after the parse loop (`gametest.c:6480`) and `run_ik_probe` reads the global
`puppet_path`.

On the Python side `_gametest_probe_text` already takes an `extra` list
(`gates.py:14814`), but the `_gametest_probe` wrapper does not pass it through, and `_ik_probe`
is `@functools.cache`d on the case alone. Rather than thread an argument through a memoised
helper that seventeen call sites share, give the one bent-rig call its own small uncached
runner beside `_ik_probe_run`.

---

## What this arm does NOT cover, stated rather than implied

The derivation has two halves and this asserts one of them.

- **Covered: the offset is read and beats the caller.**
- **NOT covered: the rotation into the hip's bind frame** (`glm_quat_inv(hip_rot, ...)`). The
  puppet's hip binds unrotated, so `hip_rot` is identity and a wrong frame conversion passes.
  Testing it needs a rig whose HIP binds rotated, which breaks the pure-translation assumption
  the generator's inverse-bind maths rests on and is a materially larger fixture.

That half is the subtler one and is where a real bug would hide, so it is filed rather than
quietly omitted. It is deliberately out of scope here: this spec closes the gap that the
derivation is untested at all, and the frame conversion wants a fixture designed for it.

## Files

| File | Change |
|---|---|
| `assets/generators/gen_puppet_fixture.py` | emit `puppet_bent.gltf` beside the puppet; the two knee rows offset in z |
| `assets/models/puppet_bent.gltf` | the generated fixture, committed |
| `scripts/gates.py` | `ik-pole-derived`, plus its line in `run_ik_gate`'s docstring arm list |

Two things `gate-arm-docs` will fail on if missed — it reads the arm list out of the function
source and failed exactly this way in 12.11: the new arm must be added to the docstring **in
run order**, and the docstring's "Eighteen arms" count and its "on the puppet whose limb
lengths the fixture generator states" preamble both need amending for a second rig.

## Verification

```bash
python3 scripts/gates.py --only fixture-gen   # the new fixture reproduces byte-identically
python3 scripts/gates.py --only ik            # the new arm, and the existing 21 unmoved
python3 scripts/gates.py --only anim          # anim-retarget reads the ORIGINAL puppet
python3 scripts/goldens.py --only puppet      # 0 px: the committed rig is untouched
```

**The arm must be falsified, not just seen to pass.** Stub the derivation back out — make
`ik_add_foot` always take `knee_forward` — and confirm `ik-pole-derived` goes red while
`ik-pole` stays green. An arm for a fix that passes against the code the fix replaced is the
thing this spec exists to avoid, so this step is the deliverable and not a formality.

The existing 21 `ik` arms must print **identical digits**, since the original puppet is
untouched and takes the same fallback path it always did.

## Out of scope

- **The hip-frame rotation half**, above — filed, with the reason it costs more.
- **Re-measuring the refused extension soft-clamp.** `docs/foot-locking.md` records that the
  refusal is "a property of a bind pose that is exactly straight, not of the method" and asks
  for a re-measure "on a rig that binds bent". This spec produces such a rig, so that becomes
  possible — but it is a separate question about IK behaviour, not about this arm.
- **Pointing any other `ik` arm at the bent rig.** They assert the solver's arithmetic, which
  the bind pose does not change.
