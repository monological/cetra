# 4.12 — Separable Screen-Space Subsurface Scattering (Jimenez)

## Context

Cetra's current "SSS" is a **dormant** back-light-transmission hack (`pbr_frag.glsl:387` — dead
wrap-lighting code + an unfed thickness term; no scalar/color/radius, no glTF import, no toggle, no
asset uses it). Skin reads like hard plastic. 4.12 replaces it with **Jimenez separable screen-space
SSS**: separate the diffuse lit irradiance, blur it in screen space with a depth-aware per-channel
diffusion profile (red scatters farthest), and recomposite with the **specular kept razor-sharp** —
the film/skin standard.

Two decisions settled up front:
- **Proper diffuse separation.** `pbr_frag` writes skin diffuse irradiance to a new **gated 5th MRT
  attachment** (`DiffuseOut`, 0 on non-skin so it doubles as the mask). The SSS pass blurs only that
  and composites `hdr + blur(diffuse) - diffuse`, so specular/IBL/SSR stay sharp. (Chosen over a
  masked-composite blur, which would soften specular into waxy skin.)
- **Procedural SSS fixture.** No skin/translucent asset exists (raiden = chrome, c64 = plastic), so
  `gen_sss_fixture.py` (translucent sphere + backlight, skin/wax preset) is the A/B + byte-gate
  subject, mirroring the glass fixture from §4.9.

## Recon (verified against source)

- Diffuse is NOT separated today: analytic `kD*albedoMap/PI` + IBL `irradiance*albedoMap` are summed
  with specular into `Lo`/`ambient`/`color` → one `FragColor`. MRT 0..3 = color / normal+marker / aux
  (motion.xy, linZ.z, rough.w) / albedo+metal.
- The 4-attachment cap is self-imposed (four `_add_msaa_color_attachment` calls + fixed `[4]` arrays
  in `engine_set_scene_draw_buffers`, gated by `normals/aux/albedo_this_frame`), NOT hardware — GL 4.1
  guarantees >= 8 draw buffers; add a `GL_MAX_DRAW_BUFFERS` query + assert.
- Linear depth for the profile is in `fx->aux_texture.z` (RGBA32F, full-res, NEAREST, always resolved
  when aux written) -- the same buffer GTAO/motion-blur read.
- Chain insertion: composited linear HDR after fog, before DoF (`postfx.c:1531`). Read-write hazard:
  fog folds a delta into `hdr_fbo` via additive blend; the SSS composite is an additive delta
  (`blur-D`), so it uses the same additive-blend fold (no scratch/blit).
- Two-pass precedent: `run_atrous` ping-pong + `PingPong`/`create_pingpong`; `postfx_run_dof` is the
  multi-stage-scratch model.
- AO is a per-pixel multiply at tonemap, never baked into `hdr_texture` -- sits after the SSS blur, no
  conflict.

## Design

1. **`DiffuseOut` = attachment 4, `GL_RGBA16F`, gated on `sss_this_frame`** (mirrors albedo-on-SSGI).
   `pbr_frag` accumulates a `sssDiffuse` local from the SAME diffuse sub-expressions already in the
   `Lo`/`ambient` path and writes `DiffuseOut = vec4(subsurface * sssDiffuse, 1.0)`. **`FragColor`'s
   expression is left byte-for-byte unchanged**; the accumulator + output are guarded by
   `uniform int sssEnabled` so the OFF path DCEs. `subsurface` (0 on non-skin) makes `DiffuseOut` zero
   off-skin -> it is both the diffuse signal AND the mask.
2. **Composite `hdr + blur(D) - D`** where `D = subsurface*diffuse`. Since `hdr` already holds the full
   sharp diffuse, this yields `spec + diffuse*(1-subsurface) + blur(D)` -> specular sharp, diffuse
   blended sharp<->blurred by `subsurface` (a natural strength knob), identity when `subsurface=0`.
   Applied as an additive-blend fold of `blur(D) - D` into `hdr_fbo` (fog idiom; RGBA16F blends the
   signed delta fine).
3. **Separable depth-aware blur:** two fullscreen passes (H then V) over a `PingPong`, each a 1D kernel
   whose screen-space pixel width = `subsurfaceRadius * projScale / max(-viewZ, eps)` (fixed
   world-radius -> shrinks with distance), per-channel-scaled by `subsurfaceColor` (R widest). Reject
   taps across depth discontinuities (relative `aux.z`) so skin doesn't bleed onto the background.
4. **`float subsurface` (0=off) + `vec3 subsurface_color` (~(1.0,0.3,0.2) skin) + `float
   subsurface_radius`** on `Material`; existing `subsurface_scattering_tex.r` stays as an optional
   per-pixel strength/thickness modulator. Engine `sss_enabled` (global) + `sss_this_frame`
   (attachment gate). Guard the whole path with `sssEnabled>0 && subsurface>0`.

## Byte-identity strategy (central risk — this touches the core PBR shader)

Unlike motion blur, 4.12 edits `pbr_frag`, so the blast radius is every asset.
- OFF gate = `--no-sss` (`sssEnabled=0`): attachment 4 is `GL_NONE`, the SSS pass is skipped, the
  guarded `sssDiffuse`/`DiffuseOut` code DCEs. Target: c64/raiden/fixture `cmp`-exact vs master.
- **Never touch `FragColor`'s expression or grouping** (the clearcoat/sheen float-reassociation
  gotcha) -- add only a separate accumulator + a new gated output, reusing existing sub-expression
  values without re-parenthesizing the `Lo`/`ambient`/`color` math.
- Verify empirically after M1: if the added code perturbs `FragColor` codegen (a sub-ulp drift, as
  guarded POM code did to raiden 2px/6.2M), isolate via `git checkout master -- pbr_frag.glsl` +
  rebuild to confirm it's the shader, then restore exact grouping or accept + document as benign.

## Risks

1. **Core-shader byte-identity (highest):** editing `pbr_frag` risks a sub-ulp OFF-path drift on ALL
   assets. Leave `FragColor` grouping exact, guard the new code, verify + isolate + document. Make-or-
   break gate for M1.
2. **5th MRT attachment:** widen the hardcoded `[4]` arrays/allocs/resolves consistently; assert
   `GL_MAX_DRAW_BUFFERS >= 5`; keep gated. An un-widened resolve/destroy site is a leak/crash.
3. **Separable profile is an approximation** (Jimenez fit); depth-aware rejection prevents
   cross-silhouette bleed; the multi-Gaussian (M4) makes the falloff skin-accurate.
4. **No skin asset:** the fixture is the only SSS subject; its quality/backlight determines whether the
   effect reads.
5. **Blur-width scaling:** screen-space radius from world radius / depth / projection must scale with
   render resolution + `ss_scale` (SSAA).
