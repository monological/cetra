# B6 — Moment-based OIT (Münstermann 2018)

## Context

Transparency today is weighted-blended OIT (spec 4.17, `--oit`, off by default):
each fragment's occlusion is approximated by a depth-weight curve, summed
order-independently. It is cheap and stable, but the weight is a heuristic, and
4.17's own deferred list names the defect and the successor:

> the McGuire depth weight **saturates for near-camera fragments** (the fixture
> quads all hit the ceiling), so it is *effectively uniform weighting* there
> — `specs/4.17-oit.md:141-143`
> moment-based OIT or dual-depth peeling for exactness — `:152-155`

MBOIT replaces the guess with a measurement: pass 1 accumulates a compact
statistical summary of absorbance along each pixel's depth axis (4 **power**
moments + total optical depth `b0` — power, not trigonometric, because trig
moments need complex arithmetic and the whole shader tree is pinned at
`#version 330 core`, all 78 files). Pass 2 reconstructs transmittance at each
fragment's own depth from those moments and weights its colour by it.

Roadmap row 16, effort L, unparked since Tier 2 landed with 11.13. Stated best
customer: **hair card tips (B8)**, whose plan already has soft tips opting into
MBOIT while the rest rides alpha-to-coverage.

## Two findings that shape this

**1. The existing fixtures cannot judge it.** `oit_fixture.gltf` is three quads at
nearly one depth — precisely where 4.17 measured the weight already saturating to
uniform, so WBOIT and MBOIT will agree there by construction. It is a
no-regression check, not a demonstration. What discriminates is **depth spread**,
not layer count. Hence Phase 0.

**2. `pbr_frag` has no free texture unit, and the escape is already load-bearing.**
All 16 are taken, pinned by a `_Static_assert` chain (`render.c:32-59`). But the
OIT accumulate is routed to `is_blend && !is_transmissive` (`render.c:314-319`),
so a fragment in that pass **cannot** be sampling `TEXUNIT_SCENE_COLOR` (unit 6,
the refraction resolve) — transmission wins over OIT and takes the other path.
Unit 6 is therefore free *by construction* during exactly the pass that needs it,
enforced by existing routing rather than by convention. The moments bind there.

## Design

**Moment generation gets its own FBO, mirroring `_ensure_oit_targets`
(`engine.c:2458-2484`) line for line.** `pbr_frag` already declares outputs at
locations 0-7 — the entire GL 4.1 guaranteed draw-buffer budget — split across the
scene FBO (0-4, 7) and the OIT FBO (5, 6). Locations 5/6 are the only free
fragment outputs, and a 4-moment MBOIT needs exactly their shape:

| location | moment FBO | matches |
|---|---|---|
| 5 | RGBA16F — power moments `b1..b4` | `oit_accum` format exactly |
| 6 | R32F — optical depth `b0` | `oit_revealage`'s slot, widened for conditioning |

So: no change to `GBUFFER_DRAW_BUFFER_SLOTS`, no change to
`engine_set_scene_draw_buffers`, no new output locations in `pbr_frag`.

**Three transparent traversals, not two.** Today OIT already draws transparents
twice (`render.c:847-874`) — once into the OIT FBO, once into the scene FBO for
transmissives. The moment pass slots in as a third bracket *before* the
accumulate, with `current_program = 0; current_material = NULL;` between brackets
— that reset is load-bearing, it is what forces `oitPass` to re-upload
(`render.c:395`).

**Reuse, don't invent:** `oit_mesh_count` (`scene.h:118`) gates it unchanged — the
mesh set is identical. The `oit_enabled`/`oit_this_frame` intent-vs-actual split
(`engine.h:131,179`) is copied exactly; 4.17's R-phase found a real bug from
keying routing on intent, and transparents vanished when the toggle was on but the
pass did not run (`specs/4.17-oit.md:126-130`). The resolve is a postfx pass built
like `create_oit_resolve_program` (`program.c:945-947`), where units are per-program
and ~13 are free. The gate is threaded as a folded FBO handle
(`moment_this_frame ? moment_fbo : 0`), matching `engine.c:2262-2264`.

## Phase 0 — a fixture that can tell the two apart

`assets/gen_oit_cards_fixture.py` → `oit_cards_fixture.gltf` + `.cscn`: ~12 thin
quads, alpha ~0.15, **staggered across a large depth range** (the discriminating
variable, per finding 1), viewed near-grazing. Approximates hair-card tips, which
is what B6 exists for.

Its correct composite is analytic: for N layers of uniform alpha `a` over a
background, transmittance is `(1-a)^N` and the composite is a geometric series —
a number, not an eyeball. Gate asserts measured-vs-analytic, following
`run_skin_offpath_gate` (`gates.py:343-402`), including **its inverse half**: an
opted-in fixture must differ, "else the zeros prove nothing."

Pin `--exposure 0.08` — 4.17 records that lit flat quads blow out otherwise
(`:115-117`).

Gate: WBOIT's error against analytic is *measured and recorded* here, before any
MBOIT exists. That number is what MBOIT has to beat.

## Phase 1 — moment generation

- `_ensure_moment_targets` cloned from `_ensure_oit_targets`; fields beside
  `engine.h:112-115`, zero-init beside `engine.c:183-187`, **teardown beside
  `engine.c:484-488`** — mandatory, the FBO aliases `depth_renderbuffer` and a
  missed teardown leaves a dangling attachment after any resize or MSAA change.
- `engine_begin_moment_pass` / `engine_end_moment_pass`; additive blend on both
  slots, depth test live via the shared depth RB, `glDepthMask(GL_FALSE)` already
  set by the caller.
- `include/mboit.glsl`: absorbance → moment vector. Shared-include idiom so a
  constant cannot drift between generation and reconstruction (precedent:
  `include/preintegrated_skin.glsl`, designed that way in `specs/11.13:266-270`).
- `oitPass` extends to a 3-value mode (0 off / 1 accumulate / 2 moments).

Gate: moments render; off path still 0 px; fixture unchanged.

## Phase 2 — reconstruction and the weighted colour pass

- Hamburger 4-moment solver in `include/mboit.glsl` — biased Cholesky, the
  standard conditioning fix for the moment problem.
- Resolve moments MSAA→single-sample with `resolve_color_attachment`
  (`postfx.c:1908-1915`), then bind on **unit 6** for the accumulate pass.
- Accumulate weights colour by reconstructed transmittance instead of
  `oitWeight()` (`pbr_frag.glsl:718-723`), into the existing accum/revealage
  targets, so the existing composite (`postfx_run_oit`, `postfx.c:2554`) is reused
  unchanged.

Gate: the Phase 0 analytic error must beat the WBOIT number recorded there.

## Phase 3 — toggle, and off is byte-identical

`--oit-moments` following `--oit` exactly: `render_args.h:115` → usage
`render.c:167` → parse `render.c:752-755` → apply `render.c:1803-1805` →
`engine.h:179` → `igCheckbox` in the feature block `engine.c:2069-2078`. Docs:
`CLAUDE.md` toggle list, pass order, postfx chain, shader index; README bullet.

**The hard rule, from 4.17's biggest recorded risk (`:98-99, :65-67`): never touch
`FragColor`'s expression or grouping.** Everything new goes behind a
uniform-guarded `if` so it dead-code-eliminates on the off path. Reassociating
that expression shifts every golden by an LSB.

## Risks, with the measurement that settles each

| Risk | Settled by |
|---|---|
| **MSAA resolve bias.** `glBlitFramebuffer` box-averages samples. Moments *sum* linearly, but reconstruction is nonlinear, so averaged moments ≠ average of reconstructions — biased at every silhouette crossing an MSAA edge, i.e. exactly hair tips. | Ship the blit first (mirrors WBOIT, cheapest), **measure on the Phase 0 fixture**. If it fails, the fallback is already built: single-sample moments over `engine_resolve_scene_depth` (`engine.c:2399-2449`), which the particle pass already uses. Third option, `sampler2DMS` in the resolve, would be the corpus's first — avoid. |
| **Is 4 moments enough for 12 layers?** | The Phase 0 analytic number answers it directly. If not, 6/8 moments need a third target and exceed the free-slot budget — that is a re-plan, not a tweak. |
| **Memory.** Roughly doubles OIT's footprint (~100 → ~200 MB at 1080p/4×). | Logged at allocation like the shadow budget does. |
| **Ordering vs shadow catcher.** OIT composites after the scene FBO resolves, so translucency behind the catcher lands in front (`4.17:144-147`). MBOIT inherits it. | Out of scope; recorded, not fixed. |

## Verification

1. **Off → 0 px** on `oit_fixture`, `oit_sphere_fixture`, `cornell_box`, and the
   raiden recipe, against a build of the base commit — not against committed
   images. `--no-auto-exposure -E 1.0` is load-bearing (`AGENTS.md:548-568`:
   auto-exposure moved 99.77% of pixels on a provable no-op).
2. **`python3 scripts/gates.py`** green, including the new analytic OIT gate.
3. **Determinism ×2** — headless bit-identical.
4. **Orbit strip** on `oit_sphere_fixture` (`--screenshot-every`): layering stable,
   no popping, matching 4.17's own ON-path protocol (`:86-94`).
5. **First OIT golden** — there is none today. Bake one once MBOIT is trusted, and
   verify it differs from `--no-oit` by a large margin, so it cannot pass by
   pinning a frame where the feature does nothing (`specs/11.14:295-303`).
