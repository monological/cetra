# Plan: GPU particle simulation via transform feedback (scalable emit/simulate foundation)

## Context

The CPU particle sim slows to a crawl as the live count climbs. Root cause (confirmed):
the per-particle **curl noise** -- `noise_curl3` runs **12 `noise_perlin3` evaluations per
particle per step** (finite differences, `noise.c:82-87`) -- over a steady-state ~18k spore
population, single-threaded, and amplified by the fixed-timestep catch-up loop
(`game.c:257`) once a step exceeds 16.7ms. macOS caps at **OpenGL 4.1 -- no compute
shaders** (`engine.c:317-319`), so the GPU route is **transform feedback** (core since GL
3.0, available on 4.1).

This is deliberately **not spore-specific**: it is the general, scalable particle
foundation the `ParticleSimBackend` vtable and the `ParticleInstanceView.gpu_instance_vbo`
field (`particle_sim.h:28`) were already designed as the seam for. It is **additive** --
the CPU backend stays as the reference / gameplay / deterministic path; the TF backend is a
sibling chosen per system via `particle_system_set_backend`.

## Architecture: CPU emits, GPU simulates

The general split (fits GL 4.1, scales to 100k+):
- **CPU owns emission + lifecycle** -- reuses the existing spawn/init modules to decide how
  many to spawn and to initialize new particles. Cheap O(n) scalar work (a float add + a
  compare per particle); trivial even at 100k.
- **GPU owns the expensive update** -- curl noise + integration, run as a transform-feedback
  vertex shader over two ping-ponged state buffers. This is the part that was crawling; it
  moves off the CPU entirely, with no readback.

**Emission via a ring buffer (v1 = continuous rate).** The pool becomes fixed-slot (drop
swap-remove compaction). Each frame the existing `spawn_rate` module yields K; the CPU inits
K new particles (existing init modules) at ring slots `[head, head+K) mod C`, uploads just
that contiguous range via `glBufferSubData`, and advances `head`. The sizing invariant
**C >= rate x max_lifetime** guarantees `head` only laps back onto already-dead slots, so no
free-list and no death-readback are needed -- recycling "emerges" from the ring (this is the
self-recycling behavior, driven by CPU emission so it stays general). Burst/curve emission
and a free-list (for out-of-order lifetimes) are later modes on the same seam.

**Death on the GPU.** The update shader ages each particle and, past its lifetime, sets
size->0 (invisible, frozen) until the ring re-inits that slot. Draw all C instances (dead
ones degenerate to nothing); a live/high-water count is a later optimization.

Authoring stays **module-based**: spawn/init modules run unchanged on the CPU; only the three
*update* modules (`curl_noise`, `drift`, `integrate`) get a GPU counterpart -- a baked update
shader whose params the backend reads from those modules.

## Changes

**New `cetra/shaders/particle_sim_vert.glsl`** -- the TF update shader (`#version 330 core`;
auto-generated symbol `particle_sim_vert_shader_str`). Inputs = state attributes; outputs =
the same state as TF varyings, tight-packed as **5 x vec4 (80 bytes)** matching
`ParticleGpuState`. Ports `noise_perlin3`/`noise_curl3` to GLSL as **hash-based** gradient
noise (no perm-table upload; exact CPU match not required). Per particle:
`if (age < lifetime)` integrate (curl*strength*dt + drift, damp, `pos += vel*dt`),
`age += dt`, `params.z = age/lifetime`; else keep size 0. Uniforms: `dt`, `time`,
`curlScale/curlStrength/curlTimescale`, `drift`, `drag`.

**`cetra/src/particle_sim.h`** -- add `ParticleGpuState` (5 x vec4, 80 bytes; the first 48
bytes are `center/params/color` at the SAME offsets as `ParticleInstanceData` so the renderer
binds slots 9/10/11 identically -- only the stride differs; the tail carries `velocity`,
`age`, `lifetime`). Declare `create_tf_particle_sim_backend(void)`. Document the
varying<->struct packing contract.

**New `cetra/src/particle_sim_tf.c`** -- the TF backend (implements the existing vtable):
- Holds the shared sim `ShaderProgram*` (built once via `create_particle_sim_program`).
- Per-emitter GPU state on `emitter->sim_state`: `GLuint vbo[2]`, `GLuint sim_vao[2]` (each
  VAO points its state attributes into its own vbo -- GL 4.1 has no `glBindVertexBuffer`),
  `int parity`, `size_t head`, `size_t capacity`, and the update params read from the
  modules. Both buffers allocated **zeroed** (all slots start dead).
- `simulate`: run spawn modules -> K; init K ring slots via init modules; `glBufferSubData`
  them into `vbo[read]`; then the TF pass -- `glEnable(GL_RASTERIZER_DISCARD)`,
  `glUseProgram(sim)`, set uniforms, `glBindVertexArray(sim_vao[read])`,
  `glBindBufferBase(GL_TRANSFORM_FEEDBACK_BUFFER, 0, vbo[write])`,
  `glBeginTransformFeedback(GL_POINTS)`, `glDrawArrays(GL_POINTS, 0, C)`, end,
  `glDisable(GL_RASTERIZER_DISCARD)`; swap parity. **Fully bracket/restore** the TF +
  rasterizer-discard state -- `render.c:742-764` assumes normal rasterization.
- `acquire_instances`: `out->gpu_instance_vbo = vbo[parity]`, `out->cpu_instances = NULL`,
  `out->count = C`.
- Registers a `sim_state` free callback deleting the 2 VBOs + 2 VAOs.

**`cetra/src/particle_emitter.{h,c}`** -- add `void* sim_state;` and
`void (*sim_state_free)(void*);` (mirrors `ParticleRenderer.impl`/`free_fn`); init NULL in
`create_particle_emitter`; invoke `sim_state_free` in `free_particle_emitter`.

**`cetra/src/program.{h,c}`** -- add `create_particle_sim_program(void)`, built from the
public primitives: `create_program` -> `create_shader(VERTEX)`+`compile_shader`+
`attach_shader_to_program` -> **`glTransformFeedbackVaryings(id, N, names,
GL_INTERLEAVED_ATTRIBS)`** -> `link_program` -> `setup_program_uniforms`. (Cannot reuse
`create_program_from_source`: it rejects a NULL fragment source and has no attach<->link
seam. A vertex-only program links fine via the primitives.)

**`cetra/src/particle_renderer.c`** -- GPU path in `billboard_prepare`: when
`view->gpu_instance_vbo != 0` (and `cpu_instances == NULL`), skip the `glBufferData` upload
and re-point slots 9/10/11 to that VBO with stride `sizeof(ParticleGpuState)` (factor the
slot-9/10/11 wiring out of `billboard_setup` into a helper taking `(buffer, stride)`); set
`upload_count = view->count`. `billboard_draw` is unchanged (it already draws from the VAO
and ignores `view`).

**`cetra/src/particle_module.h`** -- expose the three *update* param structs (`CurlParams`,
`DriftParams`, `IntegrateParams`), or add small getters, so the TF backend reads them by
`module->name` to set the sim uniforms. Spawn/init module params stay private (they run on
the CPU as-is).

**`apps/spores/src/spores.c`** -- set the spore system's backend to
`create_tf_particle_sim_backend()`; size the emitter capacity to `>= rate x max_lifetime`
(~32k). Keep `create_cpu_particle_sim_backend()` selectable via a `--cpu` flag for A/B
comparison. Same modules; only the backend differs.

**CMake** -- `particle_sim_tf.c` is picked up by the existing `src/*.c` glob and the new
`.glsl` by the shader glob (both via `./build.sh`); no manual list edits expected (verify).

## Reuse (don't reinvent)
- Backend seam: `ParticleSimBackend` vtable + `particle_system_render`'s acquire->prepare->
  draw (`particle_system.c`) -- unchanged.
- Ping-pong idiom: `postfx.c`'s `PingPong` (parity `write=n&1; read=write^1`, batched
  `glDelete*`), extended with a per-buffer VAO.
- Opaque per-object GL state: `void* impl`/`free_fn` (`particle_renderer.c`), `void* params`
  (`particle_module.c`).
- Program primitives + location-guarded uniforms (`program.c`, `uniform.c`) -- so
  `setup_program_uniforms` is harmless on the sim program.
- Emission: existing `spawn_rate` + `init_box_location`/lifetime/size/color modules
  (`particle_module.c`), unchanged.

## Verification
1. `./build.sh` clean.
2. Look: `./out/bin/spores --headless --frames 600 --screenshot tf.ppm` -> steady green haze
   comparable to the CPU version (`magick tf.ppm tf.png`; exact match not expected -- different
   noise).
3. Perf: time `--frames 1200` for `--cpu` vs TF at the same capacity. TF should be much faster
   and **flat** as the pool fills, where the CPU version's per-frame cost climbs with count.
4. Correctness: `check_gl_error` after the TF pass; confirm `GL_RASTERIZER_DISCARD` and TF
   binding points are restored (the shadow-catcher pass drawn right after particles must
   render normally).
5. Transform routing: move the spore node and confirm the cloud follows (ring init uses the
   emitter's `local_to_world`).

## Risks / notes
- **TF varying <-> struct packing** must match exactly (GL 4.1 has no `xfb_offset`;
  interleaved feedback packs tightly). Keep `ParticleGpuState` as 5 x vec4 and the varyings in
  the same declared order.
- **Ring sizing invariant** `C >= rate x max_lifetime` -- document it. Out-of-order lifetimes
  or bursts that break it need a free-list (later mode).
- **Draw-all-C** wastes vertices for mostly-dead pools (early ramp, or bursty emitters that
  stop). A live/high-water count via `GL_TRANSFORM_FEEDBACK_PRIMITIVES_WRITTEN` is a later
  optimization.
- **Generality boundary (v1):** the update is a *baked* GLSL shader (curl+drift+integrate)
  reading module params -- not generic module->GLSL codegen. New update modules need a shader
  edit until codegen lands. Burst/curve emission + free-list are the next modes on the same
  seam.
- **Fixed-timestep amplifier** (`game.c:257`) matters far less once a step is cheap; ticking
  particles once per frame with clamped dt is an optional orthogonal cleanup, not in this plan.
- **CPU backend stays** -- this is purely additive.
