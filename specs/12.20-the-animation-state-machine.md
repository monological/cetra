# Spec 12.20 — The animation state machine

## Context

`docs/game-engine-roadmap.md:274` says the animation state machine is **Absent by design and still
absent**, and hedges: *"Whether it belongs in the engine is a real question; that it is missing is
not."* `animator.h:27` states the non-goal it is hedging about, verbatim:

> There is no state machine here. A game decides what plays and when; this fades, blends and reports.

That sentence is still true and stays true — this spec closes the gap from **outside** `animator.c`
rather than by amending it.

The roadmap's evidence is that `gametest` hand-rolled one anyway. That is weaker evidence than
12.19's was: the camera row had **four** copies of the same orbit maths, and this row has **one**
machine in **one** app (`apps/render` plays what the CLI tells it and has no states). So the
argument cannot be deduplication. It has to be what the survey actually found, which is worse than
the roadmap knew.

### Three live defects, all verified, none visible to 552 gate arms

**1 — the jump→fall hand-off is lost or doubled at any frame rate but one.**
`animator.c:657` clears `a->finished = false` unconditionally at the top of `animator_update`, which
runs **once per rendered frame** (`game.c:291`). Its only reader is `gametest.c:3294`, inside
`on_update` — the **fixed step**, which runs 0, 1 or N times per frame. A zero-step frame drops the
edge and the rise stays held at its last tick for the whole descent; a two-step frame reads it twice
and plays the fall clip twice, the second landing mid-fade so `switch_source` cross-dissolves the
fall into a frozen still of itself.
**No arm can see this**: `engine.c:2949` uses `ENGINE_FIXED_FRAME_DT` (1/60) as the headless frame
dt, and `game.c:38` defaults `fixed_timestep` to the same value — so *the entire suite runs at
exactly one fixed step per rendered frame*, and both failing cases are structurally unreachable
headless.

**2 — a ragdolled corpse plays footsteps forever.**
Nothing gates `animator_update` on the ragdoll: `update_all_animators` (`game.c:291`) is
unconditional, `gametest` never writes `player_animator->playing` and never calls `animator_stop`.
`animation.c` replaces the pose downstream so nothing is *visible*, but the clock keeps turning, the
clip's own events keep firing through `on_anim_event` (`gametest.c:2290-2294` →
`audio_sound_play(step_sound)`), and `root_accum` hoards with nobody draining. There is no revive
path (`ragdoll_kill_player`, `:3903`, is the only writer), so press **K** while running and the body
keeps making footstep sounds until the process exits. Audible in five seconds; invisible to every
arm.

**3 — the swim mislabel.** `gametest.c:3265` guards the AIR leg on `clip_fall` existing and guards
the WATER leg on nothing, while `player_medium = want` (`:3271`) is unconditional. The comment four
lines above states the correct rule and the code applies it to one medium of two. On a `--puppet`
rig with its own idle/walk/run and no swim clip, submerging sets `MEDIUM_WATER` while the
**locomotion** space actually plays; `:3304` then pins `speed = 1.0f` and `:3220`'s `LOCO_TRAVEL`
branch is skipped. Because root motion is live and velocity is then scaled by `GROTTO_SWIM_FRACTION`
0.4, `param = 0.4 × travel(param)` closes a loop whose only fixed point is **zero** — the character
decelerates to a standstill and floats there for as long as it is submerged. No committed rig
reaches it (the generated puppet carries `swim`; `SHARED_CLIPS` carries `swim_cycle`), so nothing
can currently go red on it.

`docs/verification.md:759-763` has already booked the missing instrument, in the repo's own words:

> **None of that has an arm.** The `anim` and `ik` groups assert the measurement and the blend; what
> nothing asserts is that the medium state machine picks the right SOURCE — the sequence was read off
> `--trace-player` by eye and photographed, which is evidence and not a regression test. An arm here
> would read the trace's source column the way `anim-trace-idle` already reads its weight column.

**Outcome: what plays and when becomes a table a machine can read, an app cannot mis-guard, and a
gate arm can assert with no window.**

## Decisions taken (do not relitigate)

- **The table is C only.** A borrowed const table declared beside the app's clip discovery —
  `input.h`'s `InputAction` shape exactly. No file format, no loader, no versioning. Retuning a fade
  means a rebuild; a file format half-does the job the separate scripting row exists for.
- **The base layer only.** The override layer (gametest's wave) stays the one line it is today. Four
  reasons, stated in the header: its mask is a **bone name**, which is rig-specific in exactly the way
  `--puppet` breaks; `animator_layer_finished` is a **latch** where `animator_finished` is an **edge**,
  so one condition cannot mean both; there is exactly **one** layer, so a second machine over it would
  have no vocabulary for what beats what; and a non-looping layer clip already releases itself.
- **gametest's chain is deleted.** `PlayerMedium`, `player_medium`, `player_jumped`'s medium role,
  `chaser_in_swim_clip` and the twelve clip-presence guards go. One decider.
- **Defect 3 is fixed by the rewrite, not before it.** It costs nothing here: no committed rig reaches
  it, so Phase 0's recording is byte-identical either way. A `--no-swim` flag creates the repro and
  `graph-no-swim` asserts it.
- **`animator_play_once` is KEPT.** Deleting it was proposed and is wrong: `animator_play_space`
  `memset`s a fresh space (`animator.c:330`), so a graph row re-entering `locomotion` **restarts the
  clock from zero**, where `play_once`'s resume restores the outgoing space *including its `time`*
  (`:353`). Restarting the walk phase on every landing moves every foot lock under it — spec 12.9 and
  12.10 ride that phase. What changes is that the return becomes **named in the table** instead of
  implied by a hidden depth-1 stack.

## Design

### `cetra/src/anim_graph.c/h` — a new public header

Engine-level, on `CETRA_PUBLIC_HEADERS`. No GL, no physics, no clock, no `game/` type — `camera_rig.h`'s
rule for `camera_rig.h`'s reason, so most arms need no window. It names **one** engine type,
`Animator`, and that is a stated departure from 12.19: a machine over playback that cannot ask what
is playing is not one.

**A graph is a parameter block, a current state, and how long it has been in it.** What is *playing*
is the Animator's (`animator_source_name`, `fading`, `base.time`) and is deliberately not mirrored —
two records of one fact is how a load restores one of them and not the other.

**Sources are registered by the app**, not declared in the table: an entry carries a measured stride
(12.10) or a stated travel (12.18), and `build_locomotion` is 90 lines of judgement only the app can
make. A single clip is a one-entry source.

**Parameters** are a declared table of named floats, bools and triggers, written by name on every
write (`input_action_value`'s shape — no ids, no cache, no ordering). An undeclared name logs once by
name, spec 11.107's rule.

**States**: `{name, source, param, rate, kind, looping}`. `param` and `rate` name the parameters
written to `animator->param` and `animator->speed`. `kind` is `LOOP`, `EXIT` (non-looping, left by a
row of its own) or `RETURN` (non-looping, resumes the previous source at the clock it left — this is
`animator_play_once`, named). A state with **no source stops the animator**, which is what defect 2
needs: not touching it is not the same as stopping it.

**Transitions**: `{from, to, conditions[4] ANDed, fade, guard}`, one table, evaluated in order, first
match wins. `guard` is an optional predicate — the single escape hatch, `ui.h`'s closed-list-with-a-way-out
shape — and sits LAST for `input.h:98-101`'s positional-initialiser reason.

**Conditions** are a closed vocabulary: `GT/GTE/LT/LTE/EQ/NEQ/TRUE/FALSE/TRIGGER`, plus two that read
the machine rather than a parameter — `FINISHED` and `ELAPSED`. `EQ`/`NEQ` are in because every game
has a *category* parameter (medium, stance, weapon, gait) and `GT 0.5 && LT 1.5` is what a vocabulary
without them makes people write.

### Five rules that are not implementation details, and belong in the header

1. **A transition whose `to` is the current state is never taken.** Without it, `{ANY, "water", ON(submerged)}`
   matches every tick while swimming and re-issues its play forever — and `gametest.c:187` already
   names that failure: *"re-issuing a play every step restarts the clip continuously and it never
   advances past its first tick."*
2. **At most one transition per tick; no chaining.** Chaining reaches a state whose entry conditions
   were never true, and costs one `animator_play` per link in one frame, every one after the first
   freezing the screen pose.
3. **`from == NULL` is for INTERRUPTS only.** A fallback must name its `from`, because an ANY row's
   condition is a superset of the specific rows' preconditions and eats them on their first frame:
   `{NULL, "air", {OFF(grounded)}}` placed anywhere at all cuts a jump's rise one frame after it starts.
4. **`FINISHED` is LATCHED on state entry, not read live.** `animator_finished` is a per-frame edge
   that never re-arms, so a row ANDing it with anything else would lose the edge the first frame the
   other condition failed and park the graph on a held clip forever — which is defect 1 reproduced
   inside the new subsystem.
5. **A `FINISHED` row out of a `RETURN` state is refused at bind**, because the animator already
   resumes on that exact frame (`animator.c:739-746`) and the two would be two writers in one frame
   that do different things.

### Binding resolves against the rig

`anim_graph_bind(graph, animator, start)` resolves each state's source against the registry. A state
whose source never registered is **unreachable**: every transition into it is pruned and the set is
reported **once, by name**. That is the twelve clip-presence guards collapsed into one rule applied
once — and it is defect 3 refused by construction rather than fixed by a term. Bind also reports a
state left with **no live exit**: forward reachability is half the analysis, a trap state is the
silent half. A graph is refused **whole** for an authoring error (a row naming an unknown state or
parameter, `from == to`, an op a parameter's kind cannot answer), `input_bind`'s rule.

### The seam

`anim_graph_update` runs **once per rendered frame, immediately before `animator_update`**, from
inside `update_all_animators` — so the ordering is a fact of the component and not of each app.
The position is load-bearing three ways: it is the one cadence the animator's clocks agree with; it
reads `animator_finished` exactly once per edge produced; and it sits after the fixed steps have
drained root motion and before the next accumulation, so a switch costs at most **one rendered
frame** of travel. `anim_graph_update` stays public for an app with no game framework.

**This is a real behaviour change**: the decision moves from the fixed step to the frame. It is what
fixes defect 1, and headless the two cadences are identical — see the honesty section.

## Phases

Branch `12.20-the-animation-state-machine` off master; the spec commits first, alone. Each phase ends
with its arms green, and with the app **run by a human** where it changes what is drawn.

**Phase 0 — record what must not change, and write one red arm.** Author three pad scripts (there are
no script *files* in this tree — they are inline Python literals beside `_MOVES_SCRIPT`,
`gates.py:15059`) and record the `--trace-player` **source column** plus `param`, `fade_weight` and
`speed`, at `--trace-every 1`, over: ground (walk, lunge, spin), air (walk, jump, land), water (walk
off the plate, fall, land, walk into the pool, swim). None of the six existing scripts jumps, lands
or reaches water. **Measure the frame indices rather than predicting them** — the plate lip, the drop
and the pool edge are all functions of an eroded height field with two noise warps. Also record: both
menu goldens at 0 px **individually re-run**, the `Jump!`/`Caught!` counts, and the init lines. Then
write `graph-order` against a header that does not exist: it must be **red**.

**Phase 1 — the table and the evaluator.** Pure over a parameter block, no Animator: states,
transitions, the closed vocabulary, first-match ordering, ANY, ELAPSED, triggers, and rules 1–3.
Arms: `graph-order`, `graph-any`, `graph-and`, `graph-trigger`, `graph-elapsed`, `graph-disabled`,
`graph-instances`. No window, no GL, no engine.

**Phase 2 — binding.** The registry, resolution, the unreachable report, the trap-state warning, the
three authoring refusals. Arms: `graph-unreachable`, `graph-authoring`. Still pure — binding resolves
against a registry of **names**, not a `Skeleton`, which is what keeps these arms windowless.

**Phase 3 — playback.** `FINISHED` latched off `animator_finished`, the fade reaching
`animator_play`/`animator_play_space` verbatim, the `LOOP`/`EXIT`/`RETURN` split and rule 5. Arms:
`graph-finished`, `graph-fade`, `graph-guard`, `graph-return`, **`graph-identity`** — a one-state
graph is bit-identical to `animator_play_space` called directly, max bone-matrix diff **0.0 exactly**,
the `shake_scale = 0` precedent. It lands here, not at the end: if it is not true now it will not
become true later.

**Phase 4 — gametest, the player.** The conversion. Deletes the transition block (`:3219-3306`),
`PlayerMedium`, the one-shot gate (`:3457-3462`) and the statics. `player_jumped` becomes a measured
float (vertical speed) so nothing is remembered. The ragdoll becomes a source-less `dead` state,
which stops the animator and fixes defect 2. `--trace-player` gains ` graph <state> <elapsed>`
**appended after `yaw`** — verified safe against all six trace regexes, which are unanchored at the
right, with the caveat that no state may be named containing `" yaw "` (`_GAMETEST_YAW` is greedy).
`--no-swim` is added to create defect 3's repro. Arms: `graph-parity-ground`, `graph-parity-air`,
`graph-parity-water`, `graph-no-swim`. **Then run it**: walk, jump, land, lunge, spin, wave, walk off
the plate, swim, press K — and listen for the footsteps that should now stop.

**Phase 5 — gametest, the chaser.** The two-state machine at `:3485-3492` becomes a second `AnimGraph`
over its own const table and its own registry. This is the phase that proves the table is borrowed
and the instance carries no statics; `graph-instances` was written in Phase 1 so it is not
written to fit.

**Phase 6 — the group.** New `graph` group in `GATE_GROUPS`, placed after `anim` and before `ui`.
The docstring arm list must be in **run order at exactly two-space indent** or `gate-arm-docs` goes
red.

**Phase 7 — the docs.** Roadmap row `:274` → Done, keeping its own diagnosis quoted; Part 3's ordering
line `:387`; `AGENTS.md`'s Key Files (a new `anim_graph.c/h` row, the `animator.c/h` row saying where
the state machine went, the gametest app row's `PlayerMedium` paragraph); `animator.h:27` keeps its
sentence and gains one line pointing here; `docs/cli-reference.md`'s gametest probe family and the
trace tail; and `docs/verification.md:759-763`, the booked paragraph — rewritten to say what is
covered **and what still is not**.

## What this spec must NOT claim

**It proves the machine is the same, not that it is right.** Three parity arms assert the new machine
reproduces a sequence the old one produced. `docs/verification.md:759` says plainly that sequence was
only ever *"read off `--trace-player` by eye and photographed"*. If it was wrong, the new one is wrong
identically and every arm is green.

**The frame/step re-cadencing is asserted by nothing.** Moving the decision from the fixed step to the
frame is the largest behaviour change here and the fix for defect 1 — and **headless the two cadences
are identical**, one step per frame, which is the property every gametest arm in the suite rests on.
Every parity arm passes over the change without seeing it. A human has to play it at an uncapped frame
rate and at a throttled one. No arm in this suite can be made to see it.

**Defect 3 has no repro on any committed asset.** `graph-no-swim` exists only because `--no-swim` is
added to create one. That flag simulates a third-party rig; it is not one, and the real configuration
has never been run in this app.

**Nothing here is authorable.** A graph is a C table in an app. No file format, no editor, no hot
reload, no way for a designer to add a state.

**By line count this does not delete complexity — it moves it.** Roughly 95 lines and six statics
leave `gametest.c` against ~640 new lines of engine. The case is not the count; it is the twelve
clip-presence guards collapsing into one bind-time rule, the three live defects (two of them refused
structurally rather than fixed), and the first instrument in this repo's history that can drive an
animation machine with no window. If a reviewer rejects that trade, the honest answer is that the row
should stay open — not that the numbers should be re-argued.

**And the roadmap's `~1 week` is wrong.** 12.19 budgeted a week and cost two. This is a new public
header, 18 arms, three pad scripts, a ~740-line region rewritten across ~21 statics, two graph
instances and eight document sites. Budget two weeks, and expect the conversion — not the header — to
be where the time goes.

## Out of scope

- **A file format, an editor or hot reload** for graphs. That is the scripting row.
- **The override layer**, argued above. If layers become plural that is a change to the *Animator* and
  this follows it.
- **Sub-state machines, 2D blend spaces, additive layers, pose matching.** One source per state, and a
  source is `ANIMATOR_SPACE_MAX` entries on one axis.
- **The graph state as a signal for other systems.** `gametest.c:3871` already refuses `player_medium`
  for the camera and states why; a graph state is rig-dependent by construction, since bind prunes it
  against the rig. It is for a trace, a HUD and a save.
- **Saving the graph.** `save.c` restores the animator by source name and knows nothing about a graph;
  a load would leave the two disagreeing. `anim_graph_enter` is the seam that makes the fix possible
  and this spec does not take it.

## As built

### Phase 0 — what the machine actually does

Three pad scripts, run headless at `--trace-every 1` with `--no-crates --no-chaser`, reading the
source column (`animator_source_name`) off `--trace-player`. Every frame index below is MEASURED,
and two of them refute what the plan predicted.

**Ground** (`0-59 idle / 60-179 ly=-1 / 180-182 rt=1 / 183-259 idle / 260-262 lt=1 / 263-330 idle`),
331 frames on the default puppet:

```
step   0 -> locomotion
step 180 -> lunge        (36 steps, 0.60 s)
step 216 -> locomotion
step 260 -> spin         (60 steps, 1.00 s)
step 320 -> locomotion
```

**Air** — and here the plan was wrong. **The generated puppet has no `fall_cycle`, no `touch_down`
and no `float_idle`** (`gen_puppet_fixture.py:364-383` carries idle, walk, run, jump, wave, hold90,
rest, swim, travel_walk, travel_run, lunge, spin). So `clip_fall` is NULL, **`MEDIUM_AIR` is
unreachable on the committed default rig**, and a jump takes the no-fall-loop path at
`gametest.c:3443` instead:

```
step   0 -> locomotion
step 120 -> jump         (60 steps, animator_play_once, the resume path)
step 180 -> locomotion
```

The full air path needs a rig with no locomotion of its own, which takes `SHARED_CLIPS`. Run the
same script under `--puppet assets/models/t_pose.fbx` — a committed asset, and the one `anim-retarget`
already uses — and all four states appear:

```
step   0 -> fall_cycle   (the player spawns at y=4 above a plate at y=2)
step  27 -> touch_down
step  91 -> locomotion
step 121 -> jump_start
step 171 -> fall_cycle   <-- the animator_finished hand-off, gametest.c:3294
step 182 -> touch_down
step 246 -> locomotion
```

So `graph-parity-air` runs on `t_pose.fbx`, not on the default rig, and the step-171 edge is the one
defect 1 drops on a zero-step frame.

**Water** (`0-59 idle / 60-900 ly=-1`), 901 frames. The plate lip, the 178-unit fall and the water
are all reached by walking forward and never stopping:

```
step   0 -> locomotion
step 762 -> swim         (y = -180.190, water plane at -180)
step 805 -> locomotion   (y = -179.864)
step 862 -> swim         (y = -180.148)
step 899 -> locomotion   (y = -179.864)
```

### A fourth live defect, found by the recording: the medium CHATTERS at the waterline

`grotto_submerged` (`gametest.c:1425-1427`) is a hard `p[1] < level` test with no hysteresis, and
`grotto_float_velocity` (`:1440-1452`) drives the capsule toward that same plane. The two make a limit
cycle by construction: the float overshoots about 0.2 above the surface, gravity returns it about
0.2 below, and the medium flips with it — **every ~50 steps, indefinitely**. Each flip re-issues a
0.25 s crossfade, so a character treading water cross-dissolves between its swim stroke and its walk
cycle roughly once a second, forever. It reproduces exactly across runs, it is visible, and nothing
in the suite reads it.

**This is why `submerged` must not be a bool parameter.** The fix belongs in the table, not in a
second predicate: the app writes a `depth` FLOAT (metres below the surface) and the graph carries two
rows with two numbers — enter the water below `depth > 0.35`, leave it above `depth < -0.05`.
Hysteresis expressed as two thresholds is what the closed vocabulary is for, and a bool cannot say it
at all. The pure arm is `graph-hysteresis`, added to Phase 1's list by this finding.

### The red arm

`graph-order` is written and **FAILS**: `--graph-probe` is not a flag `gametest` has, the probe
returns non-zero, and the arm reports `the probe failed or measured nothing`. One group of 84.

### Also recorded, as the things a conversion loses silently

- Both menu goldens at **0 px**, re-run individually.
- The ground script's lunge and spin return to `locomotion` through `animator_play_once`'s resume,
  which restores the outgoing space INCLUDING its clock — the property that rules out replacing
  `play_once` with a graph row.

### Phases 1-3 — the table, binding, and the seam

`cetra/src/anim_graph.c/h`, 380 and 310 lines. Sixteen arms, eleven of which need no window, no GL,
no rig and no clip -- because a graph binds to a **NULL animator** and a state may name **no
source**, so the table is exercisable as the pure function over named values it is. That was not in
the plan and is the thing that made the arms cheap.

Five design points moved during implementation, each because writing an arm exposed them:

- **A source whose clip is missing refuses to register**, and that is the feature rather than a
  guard. An app finds its clips by name on whatever rig it was handed, so a missing one arrives as a
  NULL entry; refusing there is what turns "this rig has no stroke" into "this state is unreachable"
  into "every row into it is pruned", with nothing for the caller to check. This is the twelve
  presence guards collapsing.
- **`FINISHED` is latched on entry**, not read live. `animator_finished` is a per-frame edge that
  never re-arms, so an AND with a condition that fails on that frame would lose it permanently.
- **A RETURN state leaves by itself**, following the animator rather than a row. The animator resumes
  inside its own update with the graph standing still; a graph that did not follow would name the
  one-shot while the walk was already playing, undetectably.
- **`EQ`/`NEQ` are in the vocabulary.** Every game has a category parameter, and `GT 0.5 && LT 1.5`
  is what a vocabulary without them makes people write.
- **`animator_play_once` is kept**, and `graph-return` is why: a returning state resumes the outgoing
  clock at **416.67** where a row re-issuing the space restarts it at **16.67**. Four hundred ticks
  of walk phase, and every foot lock rides it.

`graph-identity` is **0 exactly** on both the pose and the clock over 120 ticks.

**One arm was refused by the suite and the suite was right.** The first draft printed the nine verdict
lines through a helper, and `gate-arm-docs` reported the group as listing arms it could not verify --

### Phase 4 — the player

`PlayerMedium`, the if/else chain, `player_jumped`, and twelve clip-presence guards deleted; the app
now writes nine parameters and owns none of the decision. Net +400/-123 across `gametest.c`,

**Parity, at every step.** On the ground the two authored moves enter one step later and return on

**The waterline band had to be re-measured.** Phase 0's 10-step sampling suggested a bob of
+0.19/-0.14 and the first band (0.35 / -0.05) still chattered. Sampled every step once settled, the
capsule swings **0.83 under to 0.80 over** -- so the band is 1.0 / -1.0. With it, the water state is
entered **once** and never left.

**The bob is its own defect, and the first diagnosis of it here was wrong.** This section said
`grotto_float_velocity` "calls itself critically damped and is not", drag 6 against the 8.49 that
`2*sqrt(18)` needs. The arithmetic refutes it: 6/8.49 is a damping ratio of **0.707**, whose
overshoot is `exp(-pi)` -- **4.3% per half cycle**, which cannot sustain an amplitude at all. A
reviewer caught it. The cause is the **discontinuity**: below the plane the capsule is a spring,
above it there is no restoring term, so it leaves at `rise_max` and coasts `4.0^2/(2*9.81)` =
**0.815 m** against the **0.802** measured -- two figures, and raising the drag would not move it.
Fixing it means making the vertical response continuous across the surface, which changes how the
water feels and belongs to whichever spec owns that.

**The ragdoll fix is visible in the trace**: after the kill the source name is empty, every weight is
0, and the clock has stopped -- so no footstep event fires from a body nobody is drawing and nothing
accumulates undrained.

**`--no-swim` reaches the swim defect**, which no committed rig does. The run names the three states
it cannot play and prunes every row into them, and the character keeps walking at **4.38 m/s**. The
old path's loop is `param = 0.4 * travel(param)` on an axis where `travel(p)` is about `p` -- a
geometric decay to zero. That side is read from the code, not measured: it needs the code this
branch deletes.

### What seven reviewers found

Three thermo-nuclear passes (module structure, the conversion, boundaries and gates) and four
`/simplify` angles, all in background agents, all read before anything was applied. They found
**four defects, three of them introduced by this spec**, and each was reproduced before being
fixed.

**A freed graph left a dangling back-pointer.** `free_anim_graph` was `free(graph)`; the animator
kept the pointer and `update_all_animators` dereferenced it every frame. Under Guard Malloc,
`--graph-probe finished` and `--graph-probe return` are **SIGSEGV with zero output**, while
`--graph-probe guard` -- same free, no tick afterwards -- is clean. It survived ordinarily only
because the next `calloc` reclaimed the block, which also meant two legs of `graph-finished` were
not running the same experiment. Severed from either end now, which also retires the free-ordering
comment the app was carrying.

**`--no-swim` was inert on the rig it was invented for.** The flag was read in one branch of the
space-versus-clip question, so a rig given `SHARED_CLIPS` -- which carries a stroke *and* a float --
swam normally under it. Confirmed: `--puppet t_pose.fbx --no-swim` pruned only `lunge` and `spin`.
That is the same one-of-two asymmetry this spec deleted from the medium test, re-created two
screens below the claim. Withheld once now, at the clip lookup, where everything downstream follows.

**The rig probe ticked the graph twice per animator update** -- once itself, once through the
component that is the seam under test.

**A corpse could leave `dead` and start swimming.** The ragdoll state was a peer of the interrupts,
so the any-state water row matched it like any other; past a metre of depth the two rows would
alternate every frame. The fix is not another condition: **the animator stands itself down while a
ragdoll owns the pose**, in the engine, so no game authors a state to play nothing in and the one
that forgets no longer has a corpse playing footsteps. `dead`, the `ragdolled` parameter and the
row all left the app with it.

**Three arms could not fail.** `graph-order`'s fade leg read a constant back out of the probe's own
table. `graph-any`'s third leg started in the destination of the row it meant to observe, so it read
the same whether the row fired or was skipped as a re-entry -- it would have passed with the row
deleted. And `graph-authoring`'s trap leg asserted only that bind succeeded, which stays true with
the entire no-way-out analysis removed; it asserts the warning text now.

**The waterline diagnosis was wrong**, refuted by its own arithmetic -- see the correction above.

**And the decision had moved to the frame while the evidence had not.** The parameters were written
and the triggers fired from the fixed step, which runs zero, one or several times a frame, while the
graph decides once. So a frame that ran no step never saw a lunge press at all, and the levels were
whatever the last step left. That is defect 1's own shape surviving inside the thing that fixed it.
The step now latches and `on_pre_render` publishes once, with `rise` taking the frame's peak rather
than its last.

Also applied: a row between two returning states is refused at bind (the animator keeps ONE return
point, so the two layers would disagree about where it leads); the three tables are refused after
bind, because everything bind settled is an index into them; `_check_row`'s trap scan no longer
clears a true it already found; six exports with no callers became four deletions and two things made
live (`--print-graph`, and the guard's `user` pointer, which no arm had exercised); `grotto_depth` is
one subtraction where three consumers had spelled it three ways; and the parity runs render at
160x100 rather than 1280x720, for a byte-identical trace -- the arms read a text column and every
pixel was thrown away. Measured here at **43 s to 21 s** on the 901-frame water leg; the review
that found it measured 58.6 to 22.9 on a quieter machine. Same direction, same factor of two.

**Not taken, and why.** `animator_finished` should be a latch cleared on the next play, the shape
`animator_layer_finished` already has in the same file -- it has exactly one consumer now, so the
change is cheap, and leaving an edge nobody can read safely means the next consumer repeats this
spec's first defect. It is a change to spec 12.1's published contract and is recorded in
`animator.h` where the next reader meets it rather than made here. Likewise the waterline: making
the vertical response continuous would let all four consumers share one threshold again, and it
changes how the water feels.

### Final verification

```
572 gate arms, 0 failures, all 84 groups
33/33 goldens at 0 px
```

Both after the review fixes, on a clean build. The five rig probe cases run clean under Guard
Malloc, where two were SIGSEGV before.

**What this does not cover, restated because it is the important half.** The parity arms prove the
new machine reproduces the sequence the old one produced -- not that the sequence is right. The
re-cadencing from the fixed step to the rendered frame is the largest behaviour change here and
**no arm in this suite can see it**, because headless is always exactly one step per frame; it wants
a human at an uncapped frame rate and at a throttled one. And nothing here judges how a transition
READS: whether a fade is the right length for the move it covers, whether the landing lands on the
beat, what a swim looks like.
