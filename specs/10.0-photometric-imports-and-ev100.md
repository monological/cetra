# Photometric imports and an EV100 camera

## Context

Spec 9.9 made punctual falloff inverse-square and `intensity` candela, but only
migrated the two `.cscn` fixtures. Three gaps were recorded and are now in scope:

1. **`import.c` reinterprets, it does not convert.** glTF `KHR_lights_punctual`
   already specifies candela (point/spot) and lux (directional), and `import.c`
   knows this — `is_gltf_path` (`:90`) gates a `/683.0f` divide at `:1241-1246`
   that pushes those values down to the old arbitrary renderer scale (~1-10),
   backed by `IMPORTED_LIGHT_INTENSITY_MAX = 100` (`:99`). Under 9.9 that scale no
   longer exists: `intensity` is candela. So every imported light is now off by
   ~683x, silently, and FBX/GLB is the primary asset path.
2. **The legacy `constant/linear/quadratic` triple is inert but still plumbed** —
   `light.h:37-39`, `set_light_attenuation`, `import.c:1220-1224`, and callers.
   Read by nothing since 9.9.
3. **Exposure is a bare multiplier.** Real candela values are hundreds to
   thousands; a 1000 cd lamp at 3 m is ~111 lux, ~25x over white. Auto-exposure
   absorbs that, a pinned exposure does not — which is every golden.

(1) and (3) are coupled: honest import units are unusable without a camera that
expresses exposure in the same system. That is why they land together.

## Approach

### 1. EV100 exposure (do first — everything else depends on it)

Standard photographic exposure, per "Moving Frostbite to PBR" (Lagarde & de
Rousiers), which the 9.9 spec already cites:

```
EV100    = log2(N^2 / t * 100 / ISO)        // N = f-number, t = shutter seconds
exposure = 1 / (1.2 * 2^EV100)
```

- Add `aperture`, `shutter_speed`, `iso` to `PostFX` beside the existing
  `exposure` (`postfx.h:144`), plus `bool physical_exposure` to select between
  the new path and today's linear multiplier.
- When physical, `exposure` becomes an **EV bias** in stops, which is already how
  `postfx.h:144` documents it under auto-exposure — so the field keeps one meaning
  across both modes rather than gaining a second.
- Auto-exposure keeps working: metering produces an EV100 the camera settings bias,
  rather than a multiplier.
- `.cscn` gains an optional `post.camera` block (`aperture`/`shutter`/`iso`).
  Absent = linear mode, so every existing scene is untouched.
- Sanity anchors for the defaults: sunny-16 (f/16, 1/125, ISO 100) is EV100 ~15;
  a lit interior (f/2.8, 1/60, ISO 400) is EV100 ~6.9.

### 2. `import.c` — convert instead of rescale

- Delete the `/683.0f` block (`:1241-1246`). glTF candela is candela; glTF lux is
  lux. Keep `is_gltf_path` — it now selects "already photometric, pass through"
  versus "unspecified units, needs the heuristic".
- Raise/retire `IMPORTED_LIGHT_INTENSITY_MAX`: 100 was a renderer-scale ceiling and
  is below a domestic bulb in candela. Non-glTF formats still need a guard, so keep
  one but at a photometric magnitude, and only for the unspecified-unit path.
- Import glTF `range` into `Light.range` so the window has a bound; absent means
  unbounded inverse-square, which is the KHR default.
- Keep the Blender colour-bakes-power normalisation (`:1229-1235`) — it is
  orthogonal and still correct.

### 3. Delete the legacy attenuation triple

Pure removal; the compiler finds every caller. `Light.constant/linear/quadratic`,
`set_light_attenuation`, the `import.c` sanitise block, the `.cscn` `attenuation`
key and its warn branch, and `CSceneLight.has_attenuation`.

### 4. Per-light GUI selection

`igCombo` over `scene->lights[]` writing the selected light only. Both Intensity
and Range currently broadcast to every light, so a drag flattens any key/fill
ratio — and Range is also the cull radius.

## Verification

Same-build noise floor first: two runs must compare 0 px before any A/B counts.

1. **EV100 arithmetic against known values, not by eye.** Sunny-16 must produce
   EV100 15.0 +/- 0.05; f/2.8, 1/60, ISO 400 must produce ~6.9. A wrong exponent
   sign looks plausible on screen and is unmissable here.
2. **Linear mode is bit-identical.** With no `post.camera`, every golden stays
   0 px — that is the guard that the new path is opt-in.
3. **Import round-trip.** A glTF authored at a known candela must arrive at that
   number on `Light.intensity` — assert on the log line, not the image.
4. **Physical end-to-end.** *(Expectation corrected once the arithmetic existed.)*
   The original claim here — a 1600 lm bulb at 2 m landing mid-grey under a
   lit-interior camera "without hand-tuning" — is wrong, and measuring it is what
   showed that. 127 cd at 2 m off an 0.18 surface is 1.8 nits; EV100 6.88 meters
   for a scene averaging `0.125 * 2^EV100` = ~14.7 cd/m2, so it lands ~3 stops
   under grey (0.013). That is correct photographic behaviour, not a bug: one bulb
   at that distance is a dim room, and real interiors reach 14 nits through several
   fixtures, closer throw and bounce.

   What the change actually buys is that intensity and exposure are finally in the
   same system, so a scene is matched by choosing a *camera* rather than by
   retuning every light. The real test is therefore: pick settings from the scene's
   real-world equivalent and check the frame is close, not that any default works
   everywhere. Scenes are expected to author `post.camera`.
5. Fixtures adopting `post.camera` regenerate their goldens, inspected at 1:1 per
   the 9.2/9.4/9.6 rule.

Goldens pin exposure and so cannot catch an auto-exposure regression; the metering
path needs an interactive check.
