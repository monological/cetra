# 10.6 — Stochastic PCSS: rotate the kernel, let TAA average it

## Context

At macro viewing distances the PCSS penumbra shows discrete banding: the
penumbra is built from 16 fixed Poisson-disk taps, so it renders as 16
overlaid copies of the caster silhouette at 1/16 opacity each (reproduced on
`dir_shadow_fixture`'s pillar-tip shadow at the user's close-up camera; clean
with `--no-pcss`).

Per-pixel kernel rotation alone was tried before and rejected — the comment
at `pbr_frag.glsl:454-459` records why: static rotation turns banding into
per-pixel noise that "rides the sharp specular lobe into a field of bright
speckle on the metal." The missing half is temporal accumulation: rotate the
kernel per pixel AND per frame, and let TAA average the noise to the true
mean. `ssr_frag.glsl` already ships exactly this contract (`ssrStochastic` +
`ssrFrameIndex`, interleaved-gradient noise, per-frame seed frozen to 0 when
TAA is not resolving — `postfx.c:1639-1651`). This plan ports the treatment
to the cascade PCSS kernel.

Scope facts, verified by direct reads:
- The punctual path (`include/punctual_shadow.glsl`) has **no Poisson loops**
  — PCSS lives only in `pbr_frag.glsl`'s `cascadeShadowTap` (blocker-search
  loop at ~:572, filter loop at ~:597). Cascade-only change.
- Unlike SSR, the shadow term is computed in the forward pass and embedded in
  scene color — there is no separate buffer to accumulate. **The accumulator
  IS TAA.** That suffices: the render app forces TAA on for every windowed
  session, and the stochastic mode is gated off whenever TAA jitter is not
  live, so headless/gate/golden renders stay bit-identical.

## Design

### Gating decision (deliberate divergence from SSR, record it)

SSR splits its two knobs: spatial jitter (`ssrStochastic`) is gated on the
a-trous DENOISER (`fx->ssr_denoise`, `postfx.c:1639` — "no TAA required"
because a-trous resolves it spatially every frame), while only the per-frame
seed advance freezes without TAA (`postfx.c:1645-1651`). The shadow term has
no spatial denoiser — its only resolver is TAA — so for PCSS **both the
rotation and the advance gate on one condition: TAA jitter live this frame.**
The comment at the upload site must record this divergence so nobody
"harmonizes" it back to the SSR shape.

### Shared noise include — `cetra/shaders/include/noise.glsl` (new)

The IGN hash is already copy-pasted in four places (`ssr_frag.glsl:134,135,
285-286`, `motion_blur_frag.glsl:22-25` — already a named `ign(vec2)` there —
`contact_shadow_frag.glsl:122`). Do not add a fifth copy: create
`include/noise.glsl` holding motion_blur's exact
`float ign(vec2 p) { return fract(52.9829189 * fract(dot(p, vec2(0.06711056, 0.00583715)))); }`
and include it from `pbr_frag.glsl`. Switch `motion_blur_frag.glsl` to the
include (bit-identical function, provable 0 px). Migrating ssr_frag /
contact_shadow_frag copies is deferred — noted in the spec, not done here.
The generator handles nested includes and include-once (`gen_shader_header.py`).

### Shader — `cetra/shaders/pbr_frag.glsl`

- New uniforms beside `pcssEnabled`/`pcssSoftness` (:139-140):
  `uniform int pcssStochastic;` and `uniform int pcssFrameIndex;`
- In `cascadeShadowTap`, after the `pcssEnabled == 0` and emitter-too-small
  early-outs: when `pcssStochastic == 1`, build a per-pixel per-frame
  rotation (same frame-advance idiom as `ssr_frag.glsl:133`):
  ```glsl
  vec2 rotCS = vec2(1.0, 0.0);
  if (pcssStochastic == 1) {
      vec2 fc = gl_FragCoord.xy + vec2(float(pcssFrameIndex) * 5.588238);
      float ang = 6.2831853 * ign(fc);
      rotCS = vec2(cos(ang), sin(ang));
  }
  ```
  and apply it to every tap in BOTH loops (blocker search :572-582 and
  filter :597-601):
  `vec2 p = vec2(dot(POISSON16[i], vec2(rotCS.x, -rotCS.y)), dot(POISSON16[i], rotCS.yx))`
  — same rotation for both loops so the blocker estimate and filter stay
  coherent within the fragment. With the uniform at 0 the offsets are the
  untouched constants — the deterministic path must stay bit-identical and
  pay no trig.
- The per-frame advance also jitters `zBlocker` and the penumbra radius; TAA
  averages those too.
- Rewrite the POISSON16 comment (:454-459): the unrotated-disk rationale
  gains its second half — rotation is admissible exactly when a temporal
  accumulator is running, and the uniform gate enforces it.
- `PCSS_MAX_RADIUS_UV` unchanged in this plan (raising it becomes viable once
  rotation ships, but that is a separate measured decision).

### Engine wiring

- `cetra/src/shadow.h` — two ShadowSystem fields with contract comments:
  `int pcss_stochastic;` (1 = rotate the PCSS kernel; set only while TAA
  accumulates) and `int pcss_frame_index;`
- `cetra/src/render.c` `render_current_scene` (:682-694): hoist the existing
  TAA-jitter predicate into a bool — it is already spelled there for the
  jittered `draw_projection`:
  `render_mode == RENDER_MODE_PBR && postfx_taa_active(engine->postfx) && (!engine->headless || engine->headless_jitter)`
  — reuse it for the projection jitter AND set
  `scene->shadow_system->pcss_stochastic` from it, with
  `pcss_frame_index = (int)(engine->total_frames % 4096)` (bounded so the
  float hash stays well-conditioned; `total_frames` is the same counter the
  Halton jitter reads at :686). Zero both when the predicate is false or the
  shadow system is absent. Set BEFORE pass 1 (`_render_scene_iterative`,
  :711) — the per-program upload happens on program switch inside that walk.
  Bonus: probe capture forces TAA off (render.c:976-1092), so captures get
  the deterministic kernel for free.
- `cetra/src/shadow.c` `bind_shadow_maps_to_program` (:398-400): upload the
  two uniforms beside the existing pcss pair (they sit after the
  no-directional-casters early return at :387, correctly — PCSS is unread
  then). shadow.c keeps never learning about Engine/PostFX — it uploads
  fields render.c set, same layering as `directional_count`.
- No uniform.c changes: `uniform_set_int` caches by name lazily (pcssEnabled
  itself is not in the pre-warm list either).

## Not touched

Punctual lookup, 3x3 PCF fallback, blocker classification, receiver-plane
bias, TAA resolve itself, no new buffers.

## Verification

1. **Determinism proof (the load-bearing one):** with TAA off the change is a
   0-pixel no-op. Base vs branch builds: cornell_box, cornell_leak,
   contact_fixture, and the raiden recipe, headless without `--taa` —
   `magick compare -metric AE` prints 0 for each. Full gate suite passes with
   byte-identical numbers (every positional gate runs without `--taa`).
2. **The banding repro:** pillar-tip close-up (`dir_shadow_fixture.gltf`,
   `--cam-eye -2.952,3.184,-0.168 --cam-target -2.966,3.107,-0.231 --fov 55`)
   with `--taa --headless-jitter -f 120`: stepped ghost outlines replaced by
   a smooth gradient in the converged frame. An early frame (f 2) shows noise
   instead of bands — expected; that is the trade being made.
3. **Specular speckle (the original rejection reason):** the raiden recipe
   plus `--taa --headless-jitter -f 120` — converged frame must show no
   speckle field on the metal vs the same render on base.
4. **Churn gates (measure, decide by numbers):** dir-shadow churn and catcher
   churn run under `--taa --headless-jitter`, where stochastic is now LIVE —
   the rotating kernel refreshes the shadow input every frame, so post-TAA
   residual flicker may lift the churn numbers. Run the suite; if a churn
   gate fails, inspect the dilated diff for visibility and either record a
   measured tolerance change with its reason, or fall back to per-pixel-only
   rotation (no per-frame advance) — decided by numbers, recorded in the
   spec.
5. Interactive: the user's judgment on the pillar close-up and
   contact_fixture.
