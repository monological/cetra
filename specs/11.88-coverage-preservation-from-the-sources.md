# Spec 11.88 — coverage preservation, from the sources this time

## Context

Spec 11.87's shader half is sound and stays. Its last commit (`a29f252e`, mip alpha coverage
preservation) shipped a regression — distant alpha-tested surfaces render **solid** — and its
review left a **HIGH** unbuilt. Both are on master.

**I wrote that mip code from memory of the technique, not from the sources.** Going to the
sources changed the diagnosis, and it overturned both my proposed fix and the review's
counter-proposal. That is the reason this spec starts by committing the references.

### What the references actually do

| | chain | coverage measure | search | applies |
|---|---|---|---|---|
| Castaño 2010 (blog prose) | cascade | hard count `Σ(a>Aᵣ)/N` | — | — |
| **NVTT** (shipped code) | cascade, in **float32** | **4×4 supersampled** over the bilinear reconstruction | 10-step bisect [0,4] | **best error**, seeded at 1 |
| **DirectXTex** | **pristine** `srcImages[level]` | **8×8 supersampled**, same shape | 10-step bisect | **best error** |
| Yuksel 2018 | **independent per level** | (different method entirely) | — | — |
| **cetra 11.87 (mine)** | cascade, in **uint8** | **hard count** | 10-step bisect [0,4] | **converged**, not best |

Sources: `FloatImage::alphaTestCoverage` / `scaleAlphaToCoverage` in
`castano/nvidia-texture-tools`; `CalculateAlphaCoverage` /
`EstimateAlphaScaleForCoverage` / `ScaleMipMapsAlphaForCoverage` in
`microsoft/DirectXTex/DirectXTexMipmaps.cpp`; Yuksel, *Alpha Distribution for Alpha Testing*,
I3D 2018 §3.

**My implementation differs from every shipped reference on three axes, and the coverage measure
is the root one.**

1. **Coverage is not a texel count.** Both shipped implementations reconstruct the image the way
   the GPU samples it — take each 2×2 texel neighbourhood, bilinearly interpolate an N×N grid of
   subsamples inside it, and count the subsamples that pass. NVTT uses N=4, DirectXTex N=8.
   NVTT even carries the naive count as dead code under `#if 0`. Castaño's *blog* states the
   naive form; his *code* does not ship it.

   This is not a refinement, it is the thing that makes the method work. A texel count is a
   **step function** of the scale with wide plateaus and gaps; the supersampled measure is
   effectively continuous. Every downstream property depends on which one you have.

2. **The applied scale is the best-error one, not the converged one.** Both track
   `bestAlphaScale`, seeded at `1.0`, updated whenever `|coverage − target|` improves, and apply
   *that*. Mine applies whatever the tenth bisection midpoint happened to be — a value it never
   evaluated.

3. **Nobody cascades in 8 bits.** NVTT cascades but its chain is `FloatImage` — float32
   throughout, so there is no quantization inside the loop. DirectXTex and Yuksel derive every
   level from the pristine source. Mine cascades through `uint8`, which puts a clamp at 255 and
   two roundings **inside a feedback loop**: a texel that should be 300 stores 255, its child
   averages low, the search demands more boost, more texels clamp.

### How that produces a solid image

Replaying the shipped C arithmetic against the committed fixture (`assets/alphacov_dots.png`,
512², level-0 coverage 0.1133 at cutoff 0.5) — cumulative *effective* scale:

| level | per-level | **cumulative** | coverage out |
|---|---|---|---|
| 1 (256²) | 0.9990 | 0.9990 | 0.1250 |
| 2 (128²) | 1.1436 | 1.1424 | 0.1875 |
| 3 (64²) | 2.5615 | 2.9264 | 0.2500 |
| **4 (32²)** | 1.5068 | **4.4096** | **1.0000 — alpha 128 everywhere** |
| 5+ | 0.9990 | 4.4053 | 1.0000, and uniform is a fixed point of the box filter |

The per-level cap is 4. Cascading lets the *product* reach 4.4096, and 128/29 = **4.41** is
exactly what it takes to lift that uniform level over the threshold. Note the search itself is
self-correcting — level 3's 2.5615 times its parent's 1.1424 is 2.9264 against the pristine
chain's 2.9072, the same answer. **What cascading defeats is the clamp, not the search.**

### Two things I had wrong, and one the review had wrong

- I first wrote that the cascade double-applies the correction. It does not; the box filter is
  linear, so the search measures the boosted level and finds only the residual.
- I then proposed a guard: *keep the best scale tested, ranked by distance to the target,
  seeded at 1.* A reviewer argued it was a bad objective and I simulated it and agreed — it
  returns scale 1.0 at every level and switches the feature off. **We were both wrong about
  why.** That objective is *exactly what NVTT and DirectXTex ship.* It degenerates only against
  my hard-count coverage, whose reachable values on this fixture are `{0, 0.0625, 0.1875, 0.25}`
  — a target of 0.1133 falls in a gap and rounds to the wrong side. With the supersampled
  measure the target is essentially always reachable and the objective is fine.
- So the histogram-based selection the review proposed instead is an **invention that is no
  longer needed**, and it is dropped.

### The known ceiling, recorded up front

Yuksel §2 says of this whole family: *"Castaño suggests scaling the alpha values… This simple
fix can help in some cases, but it does not always improve the results,"* and Figure 1 shows it
failing. So the target here is **a correct implementation of a technique with known limits**,
not a solved problem. Alpha distribution (error diffusion / alpha pyramid) and hashed alpha
testing are the successors; both get roadmap rows, neither is built here.

### The second defect: two materials, one image, a race

Verified by parsing `my_models/raiden/source/raiden_textured_rigged.glb`:

```
Hair_1   MASK   cutoff=0.5   tex=23   image=14
Hair     BLEND               tex=24   image=14
```

`load_embedded_texture` keys the pool on `"*14"` — the *image* index — so both materials reach
one `Texture` and one mip chain, and only the first loader's `TextureDesc` survives. It is not
even traversal order: materials build lazily in mesh order (`import.c:1618-1626`) and compressed
embedded textures load async through three dedup layers, each discarding the loser's desc —
`submit_load`'s pool check (`async_loader.c:562`), `inflight_join_or_claim` (`:590`, where a
joining caller is recorded as a bare `{callback, user_data}` and its desc is never captured at
all), and a third re-check before publish (`:685`).

**Coverage preservation is a property of the IMAGE and 11.87 plumbed it through the MATERIAL.**
Unity ships it as a texture *import* setting for exactly this reason. glTF has nowhere to put
it, so inferring it from the material is the only route — but the inference is underdetermined
the moment two materials use one image differently.

11.87's own proposed mitigation (store the cutoff on `Texture`, warn on mismatch, per the
`is_srgb` / `wrap_s` precedents at `texture.c:1145` and `:748`) is **the wrong shape and is not
being built**. Those warn because the *asset* contradicts itself. A hair texture used once as a
cutout and once as a blended layer is legitimate authoring; the contradiction is in the engine's
inference, and it can be resolved before the chain exists rather than detected after.

### 1. The arm that fails on master

### 2. Bring `texture.c` in line with the references

Three changes, and **none of them is an invention** — each has two shipped implementations
behind it. Land as one commit; they are one algorithm.

**a. Coverage becomes the supersampled measure.** Rewrite `texture_alpha_coverage`
(`texture.c:990`) in the NVTT / DirectXTex shape: iterate `(w-1) × (h-1)` 2×2 neighbourhoods,
bilinearly interpolate an N×N subsample grid, count subsamples passing, divide by
`(w-1)(h-1)N²`. **N = 4**, matching NVTT — DirectXTex's 8 is 4× the work for a smoother estimate
and this runs per level per bisection step. Saturate each tap after scaling, as both do.

This also dissolves the `round`-vs-`ceil` threshold finding: the comparison moves to normalized
floats against `cutoff` directly, which is what the shader compares, instead of a byte against
`round(cutoff*255)`.

**b. Apply the best-error scale.** Track `best_scale` seeded at `1.0f`, update on strict
improvement of `fabsf(coverage - target)`, apply `best_scale`. This is NVTT and DirectXTex
verbatim, and it fixes three separate things: the applied scale is one that was actually
measured; an unreachable target resolves to the nearest achievable rather than to an arbitrary
bisection midpoint; and the 1×1 tail stops being decided by bisection precision.

**c. Stop cascading.** Derive each level from the pristine parent, as DirectXTex and Yuksel do.
NVTT cascades and gets away with it because its chain is float32; this chain is `uint8`, so
cascading puts a clamp and two roundings inside a feedback loop. **No new allocation** — at the
point a scratch copy is wanted, `texture_box_halve` has returned so `src` is spent, and the
buffer the loop is about to swap into (`(dst == a) ? b : a`) is either that spent `src` or, at
level 1, the never-touched `b`:

```c
unsigned char* out = dst;
if (keep_coverage) {
    unsigned char* cov = (dst == a) ? b : a;   /* spent src, or never-used b */
    memcpy(cov, dst, (size_t)dw * dh * channels);
    texture_preserve_alpha_coverage(cov, dw, dh, desc.coverage_cutoff, target);
    out = cov;
}
/* upload `out` */
src = dst;                                     /* pristine, unrescaled */
dst = (dst == a) ? b : a;
```

`cap` is sized for level 1 so every later `memcpy` fits; no third OOM path. **The default path
is byte-identical** — with `keep_coverage` false, `out == dst` and the swap is what it is today.

Also make the range `[1/4, 4]`; `[0, 4]` is asymmetric in log space and the zero end is useless.
And delete the comment at `texture.c:564-573` that documents the cascade as intentional — it is
the fossil of the bug.

### 3. Ask the whole scene what an image is for, not one material

**`cetra/src/import.c`, one pure function, no new state:**

```c
static float coverage_cutoff_for(const struct aiScene* s, const char* tex_path);
```

Every material votes on its own albedo texture path:

| material | vote |
|---|---|
| `ALPHA_MASK` | this cutoff |
| `ALPHA_BLEND` | **veto** — it reads alpha as opacity, so a rescale changes its translucency |
| `ALPHA_OPAQUE` | abstain — glTF ignores alpha, so a rescale cannot reach it |

Any veto, or two masked votes at different cutoffs, resolves to **0** (no rescale) and logs by
name in the `texture.c:1145` idiom. Re-walking rather than caching is the point: the answer
becomes a pure function of the file, so it cannot depend on mesh order or on which worker won.
**No new parameter on either function** — `ai_scene` already reaches both `process_ai_material`
and `load_material_texture`. A materials-by-textures walk is a few thousand string compares
against a PNG decode.

The reads are self-contained and liftable as they stand: `aiGetMaterialString(m,
AI_MATKEY_GLTF_ALPHAMODE, ...)` and `aiGetMaterialFloat(m, AI_MATKEY_GLTF_ALPHACUTOFF, ...)`
(`import.c:351-365`), plus `aiGetMaterialTexture` in the shape the existing loop uses
(`import.c:677`) against **both** albedo rows of `texture_mappings` — `aiTextureType_BASE_COLOR`
and `aiTextureType_DIFFUSE` (`import.c:230,242`).

At the call site it **replaces** the material test rather than adding to it:

```c
/* today */
if (material->alpha_mode == ALPHA_MASK && setter == set_material_albedo_tex)
    desc.coverage_cutoff = material->alphaCutoff;
/* after */
if (setter == set_material_albedo_tex)
    desc.coverage_cutoff = coverage_cutoff_for(ai_scene, tex_path);
```

**No field is added to `Texture`** — there is no collision left to detect. Nothing outside the
assimp path changes: `.cscn` cannot author an alpha mode at all (`CSceneMaterialOverride` has no
such field, deliberately — `material.h:384-388`), and `apps/tree` / `apps/forest` atlas keys
(`"proc_leaf_albedo"`, `"forest_leaf_albedo"`) are each requested from exactly one call site.

Residuals, stated not fixed: two model files sharing a texture path in one scene still race
(the query is per-`aiScene`), and two raw paths normalising to one file miss each other.

### 4. `mask-samples` has a hole big enough to drive the original bug through

My own arm from 11.87. `gates.py:10910-10912`:

```python
ratio = gone4 / gone1 if gone1 > 0 else float("inf")
ok = lit and ratio <= MASK_SAMPLE_RATIO_MAX and gone4 <= MASK_GONE_CEIL
```

**No absolute ceiling on `gone1`**, and `lit` reads the ref/kept boxes only. So `gone1 = 0.47` —
the below-cutoff quad rendering *fully visible* at one sample, the exact failure the group exists
to catch — passes as long as `gone4` is suppressed. The arm asks whether the two counts agree and
never asks whether either is right. `mask-cutoff` carries that ceiling but on a `--taa` render;
bare `--msaa 1` is a configuration no other arm exercises. Add `gone1 <= MASK_GONE_CEIL`.

**The `inf` fallback is inverted**: `gone1 == 0` is the *ideal* and the arm fails on it. Gate on
`lit` separately, as `run_alphacov_gate` already does.

### 5. The rest

- **`alphaMaskCoverage` with `cutoff <= 0`** (`alpha_coverage.glsl:41`) returns 0.5 for a fully
  transparent texel where the binary branch returns 1.0. glTF says `alpha >= cutoff` is opaque,
  so the binary branch is right. Take `step` when the cutoff cannot produce a gradient. Latent —
  nothing in tree authors `alphaCutoff: 0` — but it breaks the file's own claim that the
  branches agree.
- **`--texture-compress-colour` invalidates the guarantee and is not being fixed.** A masked
  albedo takes DXT5, whose alpha is two endpoints and a 3-bit index per 4×4 block, applied
  *after* the rescale. Inherent to CPU coverage matching plus lossy alpha; the flag is off by
  default. Documented at the hook with the option named (refuse colour compression on a
  coverage-preserved texture), not taken.
- **The POM-plus-MASK precondition has no enforcement.** `alpha_coverage.glsl:21-28` records
  that `fwidth` needs dynamically-uniform flow and a masked material with a height map breaks
  it. None exists in tree, but a `.cscn` override can attach one. One `log_warn`.

## As built — the falsification matrix, and what it corrects in this spec

Each of the three parts was reverted in isolation against the shipped other two:

| measure | chain | applied | alphacov-far | alphacov-mip |
|---|---|---|---|---|
| per-texel | cascade | converged | **1.0000** | 0.784 PASS | ← 11.87 as shipped |
| per-texel | pristine | best | 0.0000 | **0.619 FAIL** |
| supersampled | cascade | converged | 0.0000 | 0.932 PASS |
| supersampled | cascade | best | 0.0000 | 0.928 PASS |
| supersampled | pristine | converged | 0.0000 | 0.926 PASS |
| supersampled | pristine | best | 0.0000 | 0.911 PASS | ← as built |

**Two things this spec said are wrong, and the sequencing advice was one of them.**

*"2a lands alone and first. It is the fix to the shipped regression and the one
falsifiable checkpoint that does not depend on 2b being right."* Un-cascading is **not** the
fix — restoring the cascade against the shipped measure leaves the far band at 0.0000. The
saturation needs the texel count **and** the cascade together: a texel count makes coverage a
step function the search cannot land on, so it applies wild scales (2.9, 4.0 on this fixture),
and cascading is what lets those compound past the per-level bound to an effective 4.41. Fix
either and it goes quiet. **The measure is the whole fix**; the other two are defensive.

*"Phase 2's three parts land together... splitting them produces states no reference
implements."* True as written but for the wrong reason — the states are not dangerous, they are
merely unobservable.

**So two of the three changes have no arm**, and that is recorded in `run_alphacov_gate`'s
docstring rather than papered over. The pristine chain and the best-error scale are
correctness-by-reference: they matter where a target is unreachable, which this fixture's
content stops being once the measure can hit it. Adding a fixture that isolates them was
considered and not done — it would be content built to exercise a defensive branch rather than
content anyone renders, and the honest record is cheaper than a fixture that exists to make a
matrix full.

## Said out loud

- **This is an M.** Phase 2 is a rewrite of the measure, not a patch; phase 3 is real design.
- **Phase 2's three parts land together.** They are one algorithm and splitting them produces
  states no reference implements — best-error against a step-function coverage is precisely the
  combination that reads as the feature being switched off.
- **The spec records both wrong turns**, because both are the obvious thing to try: that the
  cascade double-applies (it does not), and that best-error is a bad objective (it is what
  everyone ships — it was my *coverage measure* that made it look bad). Without that written
  down the next person re-derives both.
- **The honest ceiling is Yuksel's**: this family "does not always improve the results". We are
  implementing it correctly, not solving alpha testing.
- **The raiden fix costs the feature nothing measurable** — image 14 takes scale exactly 1.0000
  at the levels that matter, because soft edges are near-symmetric about the threshold. So
  refusing a contested image is cheap, where a per-cutoff pool key would pay a full 1024² of
  VRAM for it.
