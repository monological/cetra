# Spec 11.103 — The AA mode each app actually chooses (roadmap row 65, G4)

## Context

Row 65 was booked at the close of 11.102 from a review finding: the engine's anti-aliasing default
is **4x MSAA with TAA off** (`engine.c:168`, postfx's `taa_enabled`), which is the HEADLESS
configuration, and only render, forest and tree override it. The row says the other five —
spores, gametest, shapes, pcb, splash — each pay four-sample rasterisation on the full
six-attachment G-buffer with no temporal filter in every windowed session, and that the case is
proven for the two 3D ones and unexamined for the three 2D ones.

**Exploration overturned the row twice, and both corrections change the work.**

1. **`apps/splash` never enters the post chain at all.** It does not call `engine_run`; it has its
   own loop that clears and swaps the **default framebuffer** (`splash.c:133-153`) and draws SDF
   text straight to FBO 0. `engine->framebuffer` is built by `init_engine` and never bound. So its
   four samples come from `glfwWindowHint(GLFW_SAMPLES, 4)` (`engine.c:448`), **not** from
   `engine.c:168`, and no app-side sample count reaches it. The row's claim about it is false. It
   is out of scope, and so is its screenshot path — the engine's capture lives inside `engine_run`,
   which splash bypasses.
2. **`apps/shapes` and `apps/pcb` use ORTHOGRAPHIC cameras, and the TAA jitter is derived for
   perspective.** `render.c:1401-1402` adds the offset to `draw_projection[2][0]`/`[2][1]`, the
   element that multiplies view-space z into clip x/y. Under perspective `clip.w = -z_eye` divides
   it back out to a constant sub-pixel NDC shift. Under `glm_ortho` (`camera.c:279`) `clip.w = 1`,
   so the shift **scales with depth**: at these apps' 300-unit camera distance it is ~0.19 in NDC,
   about **150 pixels** at a 1600-wide framebuffer, re-rolled every frame from the Halton sequence.
   Enabling TAA there would not smear, it would destroy the frame. Nothing can currently reach it:
   `set_camera_orthographic` has exactly two callers (`shapes.c:256`, `pcb.c:226`), neither has
   headless capture, and `import.c:1641` pins every imported camera to perspective.

Two further facts that shape the per-app answer:

- **Particles write no motion vectors.** `particle_frag.glsl:14` declares one output, location 0,
  and `particle_vert.glsl` carries no clip/prev-clip pair, so `velocity.glsl`'s contract cannot be
  satisfied. `apps/spores` is 32,000 curl-noise motes over five static meshes. Under TAA those
  motes reproject through whatever the geometry BEHIND them wrote — zero, for a static camera — so
  the history is fetched from the wrong place and only the neighbourhood clamp bounds the ghost.
  The `shape` and `text` programs are in the same position (`shape_frag.glsl:3`,
  `text_frag.glsl:6`: single unqualified output).
- **TAA is a cost, not a no-op, and it drags eight consumers with it.** `postfx_wants_aux_gbuffer`
  returns true when `taa_enabled`, forcing attachment 2 to be written and resolved every frame;
  `taa_resolving` additionally arms contact shadows, GTAO, spec-occ, SSGI, SSR, SSS and the fog
  composite. On a static 2D scene that buys nothing, because nothing moves and the jitter is the
  only signal to integrate.

So the deliverable is not "switch five apps". It is: fix a real engine defect and make it
reachable, switch the two apps that have a case, and record the decision for the rest.

## The design

**1. The orthographic jitter, fixed and instrumented.**

In `render.c`'s `taa_jitter_live` block, branch on `engine->camera->is_orthographic` and put the
offset on the TRANSLATION element instead:

```c
if (engine->camera && engine->camera->is_orthographic) {
    draw_projection[3][0] -= jx * 2.0f / (float)rw;
    draw_projection[3][1] -= jy * 2.0f / (float)rh;
} else {
    draw_projection[2][0] += jx * 2.0f / (float)rw;
    draw_projection[2][1] += jy * 2.0f / (float)rh;
}
```

**The sign is inverted and that is the part to get right.** Perspective's added term becomes
`jx' * z_eye / (-z_eye)`, so the raster moves `-jx` pixels; the ortho term arrives undivided, so
an unnegated offset moves `+jx`. `taau_jitter_px` is published in PIXELS
(`render.c:1406-1407`) and the TAAU resolve un-applies it, so a sign error is **invisible at
render scale 1 and doubles the error under `--render-scale`** — exactly the silent-failure shape
this engine keeps finding. Motion vectors are unaffected either way: `pbr_vert` reprojects through
`uCurrViewProjNoJitter`.

**Instrument: `--ortho <height>` on the render app**, calling the existing
`set_camera_orthographic` on the scene camera. This is what makes the defect reachable — one
binary that already has headless capture, TAA and `--headless-jitter`, now with the camera mode
that breaks. Roughly 15 lines, and useful beyond this spec.

**Gate arm `taa-ortho`**, in whichever group owns temporal behaviour: render an existing
high-contrast fixture under `--ortho <h> --taa --headless-jitter`, take two adjacent frames from
ONE process (the `_ladder_pair` / `_taa_churn` arrangement, since two jittered processes are not
byte-comparable), and bound the churn. Broken, adjacent frames are two different pictures ~150 px
apart and the count is most of the frame; fixed, it is the ordinary TAA residual. Measure the
before-number on the unfixed build and set the bar with stated margin, 11.88-style.

**2. `apps/gametest` — the clean case, which needs plumbing before it can be judged.**

Meshes only, every material on `pbr` (`gametest.c:276`), so full motion vectors. It also has **no
argv loop at all** (one positional HDR path at `gametest.c:596-599`), no headless, and zero gate or
golden coverage. Add the game-framework capture route — `config.headless`,
`exit_after_frames`, `screenshot_path`, `screenshot_every`, the four branches `apps/spores` already
has (`spores.c:372-388`) — preserving the positional HDR argument, then the AA policy in forest's
shape:

```c
if (!args.headless || args.force_taa) {
    config.msaa_samples = 1;
    config.taa_enabled = true;
}
if (args.msaa > 0) config.msaa_samples = args.msaa;
```

`GameConfig` already carries both fields (11.102), and `create_game` applies the count before
`init_engine` and the switch after it. ~35 lines total, all in the app.

**3. `apps/spores` — the same policy, plus the escape hatches its A/B needs.**

It already routes all four capture flags through `GameConfig`. It has no `--msaa`, `--taa` or
`--headless-jitter`, which means the promoted path is **unreachable headless** and the change could
only be judged in a window. Add those three (forest's set), then the same policy block.

**The hold point is here.** With 32,000 motes carrying no motion vectors, the crops decide whether
the switch is kept: static-camera capture at 4 samples with no TAA against 1 sample with TAA, 300%
point-filtered on the mote field and on the moving glass sphere, plus a churn number from adjacent
frames. If the motes ghost, spores keeps four samples and the finding is recorded as an argument
for particles writing motion vectors — a bigger question than an AA default, and not this spec's.

**4. `apps/shapes`, `apps/pcb` — decided, not changed.** Both are static 2D line art under an
orthographic camera. With the jitter fixed, TAA becomes *available* to them and is still the wrong
default: nothing moves, so the accumulator has only its own jitter to integrate, while the aux
G-buffer, the resolve and eight temporal consumers all switch on. Multisampling is the natural
anti-aliasing for line art. They keep 4x MSAA, and the reason goes in a comment at each app's
engine setup so the next reader does not re-open it. **No headless plumbing for these** — 40-60
lines each for a decision that is not changing.

**5. `apps/splash` — out of scope, with the row corrected.**

## Phases (one commit each; scoped gates between; full suite + goldens at the end)

1. **Spec**, committed alone on the branch.
2. **The ortho jitter + `--ortho` + `taa-ortho`.** Falsify by reverting the branch and watching the
   arm fail. Verify the sign under `--render-scale 0.67`, where a flipped sign doubles rather than
   cancels. Goldens byte-identical.
3. **gametest**: capture plumbing, then the policy. Hand A/B from the new headless path.
4. **spores**: the three escape flags, then the policy. **Stop and show the mote crops** before
   keeping it. `--only transform` must stay green (its arms read probe rows, not pixels).
5. **shapes / pcb comments**, and the docs: row 65 rewritten with both corrections and closed,
   `docs/cli-reference.md` gaining `--ortho` and the new app flags, `AGENTS.md`'s TAA paragraph
   gaining the orthographic constraint, `docs/verification.md` noting gametest and spores are now
   capturable. Full suite + 29 goldens.

## Verification

- **Noise floor first** at every framing, per the house rule; `--no-auto-exposure -E 1.0` on any
  A/B. Two runs of one configuration before any pixel count is quoted.
- `taa-ortho` fails on the unfixed build and passes after phase 2 — the arm's whole point.
- 29 goldens 0 px after every phase.
- Crops: `magick out.ppm out.png`, then `-crop WxH+X+Y +repage -filter point -resize 300%` and
  `+append` for the pair. The tree records the conversion and strip recipes
  (`AGENTS.md`) but no crop invocation; this spec writes one down.
- **A look call is the user's**, per the standing habit and 11.102's own hold point.

## Risks

- **The ortho sign.** Wrong, it is invisible at scale 1. Phase 2 checks `--render-scale 0.67`
  explicitly, and the arm runs at both scales.
- **Spores ghosting.** The likeliest refusal in the spec, and it is a hold point rather than a risk
  to mitigate. Recorded either way.
- **gametest has no coverage at all**, so its A/B is the first thing that has ever looked at it.
  Expect to find unrelated defects; book them, do not fix them here.
- **`--ortho` on a scene whose camera the app auto-frames** may need the framing recomputed for an
  ortho volume. If it fights the auto-framing, pass the height explicitly and say so.
