# Spec 13.50: silent's pause menu -- Resume, Settings, Quit to Title, Exit to Desktop

## Context

silent has no in-game menu. Escape only frees the mouse when nothing is open, or closes the bag or
the map. Spec 13.49 gave silent saves and a title. The user now wants an Escape menu that pauses the
game.

**What the user chose:**
- **The Escape menu holds Resume, Settings, Quit to Title and Exit to Desktop,** and it freezes
  everything, the rain included. New Game and Load stay on the title.
- **The title gains Settings and Exit to Desktop** under Load Game.
- **Settings holds:**
  - one Volume slider (silent plays everything on the effects bus and has no music);
  - Display: window mode and vsync;
  - Look: sensitivity and invert;
  - Field of view.
- **The title keeps its 13.49 behaviour:** the game is held while the weather keeps moving.

**What exploration found:**
- **Taking the bag or the map deletes its node.** A played world cannot be put back, so Quit to
  Title followed by New Game would keep the flashlight and the map, and so would a Load. Both takes
  must become reversible.
- **Some state survives a load,** none of it in a save:
  - the cat's brain internals: its RNG, cooldowns and stale latches such as `want_stretch` and
    `startled`;
  - the HUD's thought, hint and save mark;
  - `cursor_wanted`;
  - the basement drip's `next_drip`;
  - door and cat poses, which are drawn a step late while the game is held.
- **The engine's settings** (`cetra/src/game/settings.c/h`, `settings_apply`) already do volume,
  window mode, vsync, FOV, look scale and invert, and applying twice is safe. But:
  - its one `settings.json` is shared by every app;
  - it applies look to whichever rig is installed, which at the title is the title's rig.
- **silent un-pauses every frame while playing** (`hold_game(game, !playing)`), so the pause has
  to go into that rule.

## Design

### The pause menu (`apps/silent/src/pause_menu.c/.h`, new)

**The screens.** A modal screen built like the title:
- `hud_modal_screen` with a dim backdrop;
- items drawn as words on nothing, with a plate behind the focused one.

The item drawing moves out of `title.c` into `hud.c` (`hud_item`) so both screens use it.

**The items:**
- **Resume** closes the menu.
- **Settings** opens the settings screen, which is opaque over the menu.
- **Quit to Title** appears only on a run that has a title.
- **Exit to Desktop** calls `game_quit`. `on_shutdown` writes the quit save, since the run is still
  playing.

**The keys.** A new non-UI action, `pause_menu`: Escape and pad Start.
- **Opening:** it opens the menu while playing with nothing up. Being non-UI, it reads nothing
  while the bag or the map holds the input, so there Escape stays their back.
- **Closing:** Escape and B use the UI's own back, as the bag does. Start is `menu_accept`, so on
  Resume it closes the menu too.
- **The cursor:** `release_cursor` loses Escape. The menu frees the cursor, because input is held,
  and resuming takes it back.

**The pause.** `hold_game` becomes a three-way rule:
- not playing: the game is held, and `g_held_clock` is the render clock (13.49, unchanged);
- playing with the menu up: frozen. `game_pause`, the sim clock stays the render clock (so the rain
  freezes), and `look_dt` is 0;
- otherwise: played.

### Settings (`apps/silent/src/settings_menu.c/.h`, new)

**The file.** It is silent's own: `save_default_path(path, cap, "silent-settings")`, which gives
`<per-user dir>/silent-settings.json` and honours `CETRA_SETTINGS_DIR`. It goes through the engine's
`settings_load` and `settings_save`, so gametest's file is untouched.

**Startup.**
- The file is loaded in `main` before `create_game`. The window mode, monitor and vsync go into
  `EngineConfig` for windowed runs, so the window opens as chosen.
- `fov_degrees == 0` loads as 68, silent's current FOV, so the slider shows what the player sees.
- `apply()` runs `settings_apply(&s, audio, engine)` (volume, FOV, window, vsync), then writes
  `look_scale` and `invert_pitch` onto `g_player.rig` itself.
- It is applied once audio exists and before `--mute`, so the flag still wins. `--fov` wins over the
  file.

**The screen.** One screen, opened from the title or the pause menu; it is opaque, and back returns
to where it was opened from. Its rows are the engine's own elements, so input and focus are the
UI's, drawn in silent's look with `ui_set_draw`:
- Volume: a slider, 0 to 1;
- Display: a selector, windowed, fullscreen or borderless;
- VSync: a toggle;
- Look speed: a slider, 0.25 to 3;
- Invert look: a toggle;
- Field of view: a slider, 50 to 100;
- Back.

Each row is its label on the left and its value on the right. A slider's track is drawn where the
element's drag maps the pointer (`ui.c`'s `_slider_track`).

Every edit applies at once. The file is written when the screen closes, by any route; gametest's
`ui_settings_dirty` is the pattern to follow.

### The title (`title.c`)

- **Settings and Exit to Desktop** go under Load Game. Exit asks silent to quit through a `quit`
  choice, which silent reads like the others.
- **The rig is installed when the title is shown** (`title_show(t, engine)`), so a return to the
  title puts it back. A titled run still installs it at init, so the view loads round the title's
  eye.

### Quit to Title and the world put back

**The flow.** A new run state, `RUN_RETURNING`.
1. **Quit to Title:**
   - writes the save now, with `save_game_quit`, so closing the window mid-fade loses nothing;
   - stops autosaving, with `save_game_begin(NULL)`;
   - pops every screen down to the HUD.
2. **The fade.** `RUN_RETURNING` is not playing, so the game is held, the weather moves and the
   view fades to black.
3. **At black:** `reset_world()`, then the title's rig, then `title_show` and `RUN_TITLE`. The title
   reads the games again, so the one just saved is Continue.

**`reset_world()`,** in `silent.c`:
- **The cat's mind, made afresh.**
  - `entity_remove_component(cat->entity, COMPONENT_BRAIN)` frees the brain, and
    `cat_mind_create` is called with the run's seed, as at init.
  - The save's rows point into `g_mind` by address, so they stay valid.
  - This resets the RNG, the cooldowns and every latch in one place.
- **The world's start, loaded:** `save_game_load(SAVE_GAME_START)`. This is a snapshot written at
  the end of `on_init` (`save_game_write_start()`) for runs that have a title. It is outside
  silent-1 to silent-8, so the list never shows it.
- **The HUD cleared:** a new `hud_clear` empties the thought, the hint and the save mark.
- **The cursor let go:** `player_release_cursor`. A fresh run takes the cursor on a click.
- **The basement's drip:** a new `basement_reset_drip` puts back its first-drip timer and its seed.
- **The poses brought up to date:** `sync_entity_transforms(game->entity_manager)`, so the doors and
  the cat are drawn where they now are while the game is held.

**The takes become reversible.** This is also what makes a Load over a played world right.
- **The bag:**
  - `backpack_take` detaches the bag's node, with `node_remove_child`, and keeps it.
  - `backpack_restore(…, taken = false, …)` puts it back under the scene's root and clears `taken`,
    `held`, `cell` and `rows`.
  - `backpack_free` frees a detached node.
- **The map:**
  - `FridgeMap` gains `taken`.
  - `fridge_map_take` detaches its node, and a new `fridge_map_put_back` reattaches it.
  - The reach offer keys on `!taken` instead of on the node.
  - A new `fridge_map_free` is called in `on_shutdown`.
- **`apply()` puts the map back** when the bag does not hold it, and otherwise takes it as now.

New Game from the title still loads nothing: after a reset, or on a first launch, the world is
already its start.

### Headless flags

`--pause-screen menu|settings` opens the pause menu, or settings over it, once the game is played,
for a headless picture. It works like `--title-screen`.

## Not in this spec

- Music.
- A UI volume.
- Reduce motion: silent has no camera shake.
- Key rebinding.
- A monitor picker.
- A confirm on quitting: every way out saves first.

## As built

### Phase 1: the pause menu and the freeze

**The menu,** `pause_menu.c/.h`.
- **The screen:** a modal screen dimmed to 0.45, with "Paused" over Resume and Exit to Desktop.
- **Resume** pops the screen, the same as the UI's back on Escape or B.
- **Exit** leaves a `PAUSE_EXIT` choice, which silent takes after the UI's pass and answers with
  `game_quit`. The quit save follows, since the run is still playing.

**The items are one look.** `hud.c` holds what the title had to itself:
- `hud_item`, `hud_item_shown`, `hud_column` and `hud_words`;
- the item colours, exported as `HUD_ITEM_FG`, `HUD_FOCUS_FG`, `HUD_DISABLED_FG` and
  `HUD_HEADING_FG`.

The title now uses them.

**The keys.**
- **`pause_menu`** is a game action on Escape and pad Start. It reads nothing while a screen holds
  the input, so Escape there is still that screen's back.
- **The menu goes up after the UI's pass.** Start is also `menu_accept`, and before the pass the
  press that opened the menu would have chosen Resume on the same frame.
- **`release_cursor` is gone,** along with its read in `player.c`. The menu frees the cursor by
  holding the input, and the cursor comes back when the menu goes.

**The hold has three states,** chosen at the end of the frame input, once the frame's screens are
known:
- **`HOLD_PLAYED`;**
- **`HOLD_FROZEN`:** the game is paused, and the sim clock stays the render clock, so the rain hangs
  in the air;
- **`HOLD_HELD`:** 13.49's held clock.

`look_dt` and `look_time` now key on `g_looking`, the held clock being installed, rather than on
the pause. While frozen they read the sim, which stands still.

**The fade eases by the frame's own length** (`frame_dt`, the UI's rule: a fixed step headless, the
wall clock windowed). It used to ease by the sim's frame clock, which is 0 while paused, so a menu
up during the fade-in left the world black behind it; `--pause-screen` showed exactly that.
`hold_game`'s held clock now takes its step from `frame_dt` too.

**`start_play()`** is the one way into `RUN_PLAYING`, from loading or from the black, and opens the
menu when `--pause-screen menu` asks for a picture of it.

**Checked headless,** outdoors at -40,0, with the menu up from the start:
- Two frames 20 apart, after the fade had finished, differ by 1.8% of their pixels. The amplified
  difference is black but for a few specks at the lamp heads.
- After Resume, two frames differ by 11.9%, the difference all rain streaks.
- Exit to Desktop (down, then A) quit at once, with only frame 50 written of 400, and wrote the save
  on the way out.

### Phase 2: settings

**The screen,** `settings_menu.c/.h`.
- **It is opaque,** dimmed to 0.55, and opened over the pause menu or the title, which each take a
  `SettingsMenu*`. Back, or the UI's own back on Escape or B, returns to whichever it came from.
- **Its rows are the UI's own elements:** a slider for Volume (0 to 1), a selector for Display
  (windowed, fullscreen, borderless), a toggle for VSync, a slider for Look speed (0.25 to 3), a
  toggle for Invert look, and a slider for Field of view (50 to 100).
- **Each row draws itself in the menus' look** (`row_draw`): its name on the left, its value on the
  right (a percentage, a factor, degrees, On or Off, or `<   Windowed   >`), a plate behind the
  focused row, and under a slider a track filled to its value with a knob.
- **The track is drawn from the row's bottom up,** at its padding, which lands it exactly on the
  rectangle `ui.c` measures a drag along. That needs no font, since a slider's height is its line
  plus the track.

**The file** is `silent-settings.json` in the per-user directory (`save_default_path`), read and
written through the engine's `settings_load` and `settings_save`, so gametest's `settings.json` is
untouched.
- **Loaded in `main`,** before the game is made. A windowed run hands its mode, monitor and vsync to
  `EngineConfig`, so the window opens as chosen.
- **A FOV of 0 loads as `SETTINGS_FOV`,** 68 degrees, silent's own, so the slider shows the view.
- **Applied once the player's rig exists:** `settings_apply` for the audio, the window, vsync and
  the FOV, then the look speed and invert written onto the player's rig, which `settings_apply`
  cannot reach while the title's rig is installed.
- **`--mute` is a field of the menu** (`mute`), so every apply holds the volume at 0. The early
  mute in `on_init` is gone. `--fov` is put back over the camera after the first apply.
- **Every edit applies at once.** The file is written once the screen has gone, if anything changed
  (`settings_menu_frame`, gametest's pattern).

**The pause menu** gains Settings, and the world stays frozen while the settings are up over it.

**The title** gains Settings and Exit to Desktop under Load Game. Exit is a new `TITLE_EXIT`
choice, which the title's run state answers with `game_quit`. `choose` takes a NULL slot for it.

**`--pause-screen settings`** opens the settings over the pause menu.

**Checked headless:**
- With settings over the pause menu, a pad script took Volume down twice, Look speed up twice and
  turned Invert look on, then went back. The file then held master 0.9, look_sensitivity 1.275 (two
  steps of 5% of its range) and invert true.
- A second run read it back: 90%, 1.28 and On.
- Pictures of the screen, of the pause menu after Back, and of the title with its five items.

### Review of phases 1 and 2

Five background reviews: the thermo-nuclear one and `/simplify`'s four (reuse, simplification,
efficiency, altitude). What changed:

**Engine** (`ui.c/h`)
- **`ui_on_stack(ui, screen)`:** whether a screen is on the stack at all, not only on top. The
  freeze is now `pause_menu_up`, the pause menu anywhere on the stack. It used to be "the pause
  menu or the settings on top", which knew that the settings were the one screen opened over it.
- **`ui-on-stack` holds it.** Falsified by asking only the top: "under-a=0".
- **`ui_slider_track` is public,** `_slider_track` renamed. The settings rows draw their track from
  the UI's own rectangle, so their copy of `UI_TRACK_H` and the geometry are gone.

**silent**
- **The menus' look is shared in `hud.c`:**
  - `hud_item_look`: the plate, the words' style, and the inset rect;
  - `hud_dress`, which `hud_item` and the settings rows both use;
  - `hud_back_item` (Resume, Back, No), `hud_quit_item` (Exit to Desktop) and `hud_heading`;
  - `hud_on_top` and `hud_show`;
  - `HUD_HEADING_SIZE`, `HUD_ITEM_SIZE`, `HUD_ROW_SIZE`, `HUD_MENU_WIDTH` and `HUD_LIST_DIM`,
    replacing a set of each in three files.

  `HUD_DISABLED_FG` is no longer exported.
- **Exit and Settings are items, not choices.** `hud_quit_item` calls `game_quit` itself, and
  `settings_menu_item` opens the settings. This deleted:
  - `PauseChoice`, `pause_menu_take` and silent's poll of it;
  - `TITLE_EXIT`, its arm in `RUN_TITLE` and `choose`'s NULL slot;
  - both menus' `on_settings` and `on_exit`;
  - the `SettingsMenu*` the title and the pause menu each kept.
- **One rule for the screens' keys** in `on_frame_input`:
  - with no modal screen up, the game's keys (the pause menu first);
  - the map, then the bag, with their own;
  - every other screen goes back on its back, except the title's first screen.

  This replaced a branch per screen in a careful order, and `title_backs`. The pause menu now opens
  in that chain, and the press that opened it is kept from being an accept.
- **The settings are applied by one call,** `settings_menu_apply`:
  - `--mute` and `--fov` go into `settings_menu_load` and are put over a copy of what is chosen, so
    no edit undoes them. Before, the first edit put the file's FOV back over `--fov`.
  - It runs after `settings_menu_start` and again in `enter_game`, when the player's rig is
    installed, so `settings_apply`'s write of the installed rig reaches it. The menu's own write of
    the player's rig, its `look` field and the rig parameter are gone.
  - The camera starts at `SETTINGS_FOV` rather than a second 68.
- **Settings changed and then lost** if the window shut over them: `settings_menu_save` now runs in
  `on_shutdown` too.
- **Smaller changes:**
  - `g_looking` is gone; `looking()` reads the engine's own render clock.
  - `--pause-screen` is taken once, so a later return to play does not open the menu again, and
    only `menu` or `settings` opens anything.
  - `held` is now `modal_up` and `paused` is `pause_up`.
  - The screens' table and the usage text are put right.

**Not taken:**
- **A mute stage in the engine's audio.** It is the deeper fix, and gametest's first settings edit
  still un-mutes `--mute`. But it is an engine change outside this diff.
- **One resolver for the per-user directory** (`save.c` and `settings.c` each have one), or a
  settings file named per app.
- **An early-out in `engine_set_vsync`,** and asking `engine_set_window_mode` about the monitor only
  past its early-out. Each costs microseconds per frame of a slider drag.
- **The frame's length published by the engine.** `ui.c` and silent's `frame_dt` each compute it.
- **Window-mode display names exported** beside `EngineWindowMode`.
- **A back that pops only modal screens,** with a per-screen opt-out, in `ui.c`. The one rule in
  `on_frame_input` takes most of what it would delete.
- **Display applied only when the settings close,** so that stepping through the options does not
  switch the window at each one. The spec chose every edit at once.

**Checked:**
- `gates.py --only ui,gate-docs` passes.
- Headless:
  - the freeze is unchanged (1.8% of pixels paused, 11.9% resumed);
  - the settings pad script writes master 0.9, look 1.275 and invert true;
  - Exit (now two presses down, past Settings) quits at once with the save;
  - the pictures of the settings, the pause menu and the title are unchanged.

### Phase 3: Quit to Title

**The item.** `pause_menu_start` takes a `UIActionFn to_title`, and leaves Quit to Title out for
NULL. It sits between Settings and Exit to Desktop. silent passes its `quit_to_title` only on a run
with a title whose start was kept, so a run without one keeps Exit two presses down.

**The flow.**
- **`quit_to_title`,** in the UI's pass:
  - writes the quit save;
  - stops autosaving with `save_game_begin(NULL)`;
  - pops the pause menu;
  - sets `RUN_RETURNING`.
- **`on_frame_input` reads the run state again after that pass,** so the frame that chose Quit to
  Title runs no step. It used to hold the game by the state read at the frame's start.
- **`RUN_RETURNING` is not playing,** so the game is held, the weather moves and the view fades to
  black.
- **At black:**
  - `reset_world`;
  - the title's rig installed in place of the player's;
  - the run back to `RUN_LOADING`. The title comes up there once the lighting round its view is
    in, as at launch.

  The plan had `title_show` install the rig. That would have shown the title before the lighting
  round its view was in, if the player had been far from it, so `title.c` is unchanged.
- **`--title-screen` is taken once,** as `--pause-screen` is, so a return does not open the list
  again.

**The start** is `silent-start.json`, beside the slots and outside silent-1 to silent-8, so no list
shows it.
- **`save_game_keep_start`** writes it on a titled run. It is called where the pause menu is made,
  which is after everything a save holds exists.
- **If it cannot be written,** the run says so and Quit to Title is left out.
- **`reset_world` puts it back with `save_game_load(SAVE_GAME_START)`.** The engine's section takes
  the sim clock back to 0 with every body, and silent's sections put back the bag, the map, the
  finds, the marks, the doors, the flashlight, the draft and the cat.

**`reset_world`** puts back what no save holds:
- **The cat's mind is made afresh:** a new `cat_mind_free` takes its brain off the cat's entity,
  then `cat_mind_create` runs with the run's seed. That resets its random stream, its cooldowns and
  every latch at once, and the save's rows still point into the same `CatMind`.
- **`hud_clear`** empties the thought, the hint and the save mark.
- **`basement_reset_drip`** puts the drip's first-drop time and its stream back as
  `basement_start` set them, and `basement_start` now calls it. On a clock taken back to 0, a drip
  timed for the played game's clock would not have sounded for that long.
- **`cursor_wanted` is cleared,** so a click takes the cursor as at the start. It is a plain field;
  no `player_release_cursor` was needed.
- **`sync_entity_transforms`** puts the doors' and the cat's nodes where the load put them, since a
  held game runs no step to do it, and the title shows the house.

**The takes are reversible,** which is also what a load over a played world needed.
- **The bag:**
  - `backpack_build` always builds it, even under `--backpack`, and takes it at once when told.
  - `backpack_take` takes it off the graph with `node_remove_child` and keeps it, under the scene's
    root that `Backpack.root` remembers.
  - `backpack_restore` puts it back on the bed, empty, before taking it again when the save says so.
  - `backpack_free` frees it wherever it is.
- **The map:**
  - `FridgeMap` gains `taken` and `root`. `fridge_map_build` always builds it.
  - `fridge_map_take` takes it off the graph; the new `fridge_map_put_back` and `fridge_map_free`
    put it back and free it.
  - The reach offers it on `!taken`.
  - `apply()` puts it back when the bag does not hold it.

**Checked headless,** with the saves in a scratch directory:
- **Run 1** used `--backpack --map --slot silent-1`, standing in the hall facing the bath door. It
  saved silent-1 on quitting.
- **Run 2** was titled and driven by a pad script:
  1. Continue, which loaded silent-1;
  2. X, which opened the bath door;
