# 11.54 — The bound gets a probe, the box gets operations, the hash gets a home

## Context

Three follow-ups 11.53 booked and deferred, in descending order of value. Two are real gaps; the
third is smaller than it was booked as, and the exploration corrected me on which half.

**P1 is the one that matters.** `wind_bounds.glsl` stops the shared *coefficients* drifting between
C and GLSL. It does nothing about the *arithmetic*: `windOffset` computes a displacement in GLSL and
`wind_max_offset` computes an upper bound on it in C, written independently. Add a term to
`windOffset` — a new octave, a mode 3 — and the bound silently stops being conservative, and culling
then drops geometry that is on screen. **Nothing catches that**, and the failure is invisible in every
frame that does not happen to contain the affected mesh at the affected phase.

`cull-margin` looks like coverage and is not. It pins two quads at one camera, one frame, one wind
field, with the quads placed 0.30–0.35 of their travel outside the frustum. A new term smaller than
that slack, or pointing anywhere the fixture does not probe (−X, ±Y, ±Z), leaves all six `cull` arms
green. Nothing anywhere compares `wind_max_offset`'s number against a measured `windOffset` value.

**P2 is debt with a known shape.** `AABB` is a bare struct with **no operations** — no function in the
tree takes or returns one. So every consumer hand-rolls empty-fill, expand-by-point, union,
emptiness-test and inflate, and 11.53 added nine more such sites plus a `FLT_MAX` sentinel now shared
*by hand* across two files. That convention already produced one bug (a redundant `has_bone_rest`
flag beside an uninitialised box), and `scene.c` still carries the identical `bool* initialized`
out-param idiom that the 11.53 review deleted from `mesh.h`.

**P3 is smaller than booked, and my first reading of it was wrong.** I argued the five
`fract(sin(dot(…)) * 43758.…)` sites were "different functions sharing folklore, so a shared helper is
relocation not reuse." Half right: `hash21` has **two** real callers (`water_frag`, `tonemap_frag`),
which is reuse; and `wind.glsl` is included by four vertex programs that must agree bit-for-bit, so a
shared chunk is structurally safer than an inline copy. The exploration also found a **sixth** copy
nobody had listed.

## Status

P1 done. Branch `11.54-the-bound-gets-a-probe` off master (clean at `1918067`, 11.53 merged).

### P1 — as built

`wind_probe_vert.glsl` includes the same `wind.glsl` chunk the four rasterizing vertex programs do
and writes `windOffset(...)` as a transform-feedback varying. Every input is an **attribute**,
including `t` and `origin` — both are already parameters of `windOffset`, so feeding them per-vertex
is the identical function and one draw covers the whole grid. Batched at 65,536 vertices so the
upload and readback are bounded by the batch rather than by the grid.

**The TF reading reproduces the discarded C port to six decimal places** — 0.9617 / 0.9618 cloth,
0.8407 / 0.9664 vegetation. That agreement is worth recording: it says the port was a faithful
mirror, and that the two independent routes to the same number agree.

| falsification | C port | transform feedback |
|---|---|---|
| a term added to the **C model** | 1.258 (caught) | n/a — no model to add to |
| a term added to the **GLSL shader** | **0.966, unmoved** | **1.258 (caught)** |

The second row is the whole argument. The identical edit that a port reads straight through is the
one this design exists to catch, and `cull-bound` names the offending rows when it fails
(`cull_vegetation/mesh,cull_vegetation/sweep`).

`cull-bound` asserts both directions: `measured <= bound` is correctness, and `tightest sweep >=
CULL_BOUND_FLOOR` (0.85) is the instrument checking itself — the worst case IS reachable, so a
correct grid lands near 1.0 and a reading of 0.3 means the grid got coarser rather than the bound
safer. It reads `max_abs`, not `max_l2`, because the margin inflates the AABB per axis.

Seven `cull` arms green, `gate-arm-docs` still matching, 24 goldens 0 px.

### P2 — as built

Five `static inline` helpers on `AABB*` in `mesh.h` beside the typedef. Every hand-rolled
empty-fill, expand-by-point, union, emptiness-test and inflate in `mesh.c`, `draw_list.c` and
`scene.c` now goes through them — `grep FLT_MAX cetra/src/mesh.c` returns nothing.

**The typedef now carries the two-conventions warning**, which is the part that stops the next
mistake: an *accumulator* starts empty at ±FLT_MAX, a *stored geometry bound* does not, and
`Mesh.aabb` is the second kind because five readers consume it with no emptiness guard.

`scene.c`'s `bool* initialized` out-param is gone — the last instance of the flag-beside-a-box idiom
11.53's review deleted from `Mesh`, replaced by the sentinel it should always have been.

Two things deliberately left alone, with the reason now at the code: the 8-corner walk is **not**
unified with `aabb_transform` (the Arvo centre/extents form is a conservative superset under
rotation, so the scene box would grow and take GI fit, probe proxy, fog anchor and camera framing
with it), and cglm's `box.h` is cited as naming precedent but not adopted (no `add_point`, no
`expand`, and a different frustum test at exactly the edge `wind_cull_fixture` parks meshes on).

One behaviour change, recorded rather than discovered: `aabb_add_point` folds via cglm's `glm_min`,
not `fminf`. They differ on NaN — a NaN corner now poisons the scene box instead of being quietly
dropped. Nothing in the corpus produces one, and a box built from a NaN transform is better loud
than plausible.

Also fixed in passing: `_item_bounds`'s doc comment had been orphaned onto `_posed_bounds` when
11.53's review extracted that helper, and its closing line ("no test in the corpus would catch it")
was made false by P1.

24 goldens 0 px; `cull`, `forest`, `submission`, `wind-uv`, `draw-list` and `lod` all green.

### P3 — as built

`hash13(vec3 p, vec3 k)` and `hash21(vec2 p, vec2 k)` in `noise.glsl`, with **`k` as a parameter**.
That is the whole reason all three migrations are free: water keys off `(127.1, 311.7)` and tonemap
off `(12.9898, 78.233)`, and sharing one constant would have changed one of their patterns for
nothing. What was actually duplicated is the *form*, and the form is what is now shared.

Verified as a real assertion, not a formality — both consumers are uncovered by goldens, so they were
A/B'd by hand against a pre-migration build:

| path | before vs after |
|---|---|
| `--grain 0.03` on `flare_fixture` | **0 px** |
| `--water-bed dome --water-waves gerstner` on `beach_fixture` | **0 px** |

Two declined, with the reason now at the function: `particle_sim_vert`'s `hash33` (vec3→vec3, three
distinct constant vectors, a signed remap, one caller — promoting it puts a private helper in a
shared header) and `stochastic.glsl`'s `_stochasticHash` (vec2→vec2, and its chunk declares
`stochasticLut`/`stochasticScale` and uses `dFdx`/`dFdy`, so it must never be the *source* of a
shared hash even though it could become a consumer).

**The finding worth carrying is the sixth copy.** `contact_shadow_frag.glsl` inlined IGN in the
identical explicit-multiply-add form `ssr_frag` measured at 31,800 px, carried **no note saying
why**, and unlike ssr **is** covered by the `contact_debug` golden. It now says so. `noise.glsl`'s
directive is widened to name the three helpers by arity and record both standing exemptions by file,
so the file no longer states a rule two shaders silently break.

24 goldens 0 px; `cull`, `wind-uv` and `water` green, `beach-shoreline` at its known 6 of 18.

## P1 — `--wind-bound-probe`

### What it asserts

`measured <= bound`, where `measured` is the true maximum of `windOffset` over a sweep and `bound` is
`wind_max_offset`'s answer. Plus a tightness read, because a bound 50× the truth culls nothing.

### It measures the REAL SHADER, by transform feedback — not a CPU port

A C port was built first and rejected on evidence. It works for what it covers — falsified at
**1.258** by adding a term to the model without updating the bound — but it compares *bound vs C
model*, leaving the GLSL a third hand-mirrored artifact. A term added to `windOffset` alone left the
probe reading **0.966**, unmoved. That is precisely the failure this spec exists to catch, so the
port is deleted rather than shipped.

Instead: a vertex-only program that `#include`s the same `wind.glsl` chunk the four real vertex
programs do, and writes `windOffset(...)` straight out as a transform-feedback varying. Precedent is
`create_particle_sim_program` (`program.c:455`) — assembled from primitives because
`create_program_from_source` requires a fragment shader, with `glTransformFeedbackVaryings` **between
attach and link** — and `particle_sim_tf.c:256-281` for the draw: `glEnable(GL_RASTERIZER_DISCARD)`,
`glBindBufferBase`, `glBeginTransformFeedback(GL_POINTS)`, `glDrawArrays`, fully bracketed so no
state leaks.

**There is then no third copy at all**, and two of the three problems a port had simply vanish:

- **`t` needs no uniform.** `windOffset` already takes it as a *parameter*, so feeding it per-vertex
  is the identical function and the whole grid — positions, UVs, times — goes in one draw.
- **The `objPhase` hash needs no sweeping.** The GPU computes its own, from an `origin` fed per
  vertex. A CPU port could not reproduce `fract(sin(x)·43758.5453)` bit-for-bit and would have had to
  sweep the phase to stay honest; measuring the shader makes that a non-question.

What remains true, and shapes the grid:

1. **There is no period.** `windOffset` mixes `t·speed`, `·0.35`, `·1.7`, `·1.3`, `·6.0` and
   `t·gustFreq` — six incommensurate rates, plus a `pow(…,3)` gust envelope beating at `gustFreq`.
   The window and step are parameters, and the probe **prints them** so a reviewer can judge whether
   a measured max is credible.
2. **Four inputs are per-vertex** — `p` (via both height masks and the leaf flutter's argument),
   `uv1.x` (branch phase), `uv1.y` (flex), `uv0.y` (leaf weight).

### Two row kinds, because they answer different questions

Both are built as attribute buffers and captured by the same draw; only the vertex set differs.

- **`sweep`** — synthetic grid over `p` ∈ the mesh's own `aabb` extent, `uv1.x` ∈ [0,1),
  `uv1.y` ∈ [0, `wind_flex_max`], `uv0.y` bounded so `uv1.y · uv0.y ≤ wind_leaf_max`, `t` over the
  window, and a spread of `origin`s. Using the mesh's **measured** maxima as ceilings is what makes
  this a test of `wind_max_offset`'s actual inputs rather than of a guess, and keeps the grid inside
  vertices the mesh could really have.
- **`mesh`** — the real `Mesh.vertices` / `tex_coords` / `tex_coords2`, swept over `t`. Proves the
  shipped fixture; all three arrays are retained on the CPU after upload (`mesh.c`, freed only in
  `free_mesh`).

The C-port build already showed why both are needed: on `cull_vegetation` the sweep reached
**0.9664** of the bound where the real vertices reached only **0.8407**. The mesh alone would have
reported comfortable headroom that the parameter space does not have.

### Print both norms

`_item_bounds` inflates the AABB by `margin` on all six faces, so what culling needs is
`max(|off.x|,|off.y|,|off.z|) <= bound`; the bound is derived as an L2 magnitude. Print `max_abs`,
`max_l2` and `bound` on one row so the arm can assert the operational one and a reader can see the
slack.

### Quality bar — and it is already met once

Cloth's `mask·sway = 1` is genuinely reachable (at the hem, at the right phase), and so is the
vegetation `h²` lean — so a correct sweep reports ratios **near 1**, not 0.3. A probe reporting 0.3
everywhere is sweeping too coarsely to be a gate. Two turbulence terms use `vec3(sin a, 0, cos b)`
with arguments differing by 3.1/2.7 (cloth) and 1.7/1.3 (vegetation); the sweep must let those
decorrelate or it under-measures by up to √2 and gives false confidence.

The C-port build cleared that bar at a 40 s span in 4,000 steps with a 5×5 position grid and 5×5 UV
grid — **0.9617 cloth, 0.9664 vegetation**, all under 1.0. The TF version should land in the same
place; a materially lower ratio means the grid regressed, not that the bound got safer.

### Shape and wiring — copy the house idiom exactly

Line format `wind-bound-probe <tag> k=v k=v`, stdout, header **first** with `available=` and a
`reason=` on decline (`water_fft_probe`'s shape; the emissive probe prints its header last for a
reason that does not apply here). Four-part CLI wiring in `apps/render/src/render.c` +
`render_args.h`, mirroring `--water-fft-probe` verbatim: args field, usage line, parse arm, call
after `engine_run`. Gates parse it with the existing shared `_probe_render(workdir, scene, flag,
prefix, …)` — no new parser.

The bound side needs only what is already resident: `scene->wind`, `mesh->wind_flex_max` /
`wind_leaf_max`, and `mesh->aabb` (the mask bounds). The measured side needs a **live GL context**,
which is why the call sits after `engine_run` beside `--water-fft-probe` rather than before it.

The wind uniforms go up through the existing `wind_upload_to_program` (`wind.c`), so the probe
program is fed by the same function the real passes are — and `uWindResponse`, `uWindMode` and the
two mask bounds are set per mesh exactly as `render.c` sets them. **`wind->direction` is not
normalized in C and the shader normalizes it**; routing the upload through the shared function is
what makes that a non-issue rather than a trap.

### Arm

`wind-bound` joins the existing `cull` group (shared fixture). `run_gate_docs_gate` checks the
docstring's arm list against printed literals **in order**, so the list gains the name in position.

## P2 — `AABB` gets operations

Five `static inline` helpers in `mesh.h`, **immediately below the typedef**, taking `AABB*` /
`const AABB*` (settled): `aabb_empty`, `aabb_is_empty`, `aabb_add_point`, `aabb_union`,
`aabb_expand`.

`mesh.h` and not `intersect.h`: the type lives there, `mesh.h` already ships this exact pattern twice
(`mesh_lod_range`, `mesh_index_total` — copy their "read these through X, never directly" comment
style), and `FLT_MAX` plus every `glm_vec3_*` already arrive via `<cglm/cglm.h>`, so zero new
includes. `intersect.h` is a deliberate leaf that forward-declares `struct SceneNode` "to avoid
header dependency issues"; making it include `mesh.h` would drag `glew`, `material.h`, `texture.h`
and `program.h` into all six of its includers, `light_cluster.c` among them.

`AABB*` absorbs the `(float*)` const-stripping casts that three call sites currently document inline.
`_item_bounds` gets a local `AABB box`; `box.min`/`box.max` still decay for
`frustum_test_aabb_transformed`.

### THE CONSTRAINT — `mesh->aabb` keeps the ZERO convention

`mesh->aabb` is seeded to the **zero box**, and five readers consume it with **no emptiness guard**:
`_item_bounds` (copies it straight into the cull bounds), `ray_aabb_intersection`, the two
`uWindMaskMinY/MaxY` uploads, and `scene.c`'s corner walk. Migrating it to `±FLT_MAX` makes
`aabb_transform` compute `extents = -inf` and poisons the scene box, GI volume fit, probe proxy box,
fog anchor and camera framing. `ground.c:339` and `geometry.c:91` both document the current zero-box
failure mode as observed and deliberate. **Say this at the typedef.** The sentinel is for
*accumulators*, not for stored geometry bounds.

### Migrate (behaviour-neutral)

`mesh.c`'s three empty-fills and three expand-by-points; `draw_list.c`'s empty-fill, two
emptiness-tests, two unions and the inflate; and **`scene.c`'s `bool* initialized` out-param → the
sentinel + `aabb_is_empty`**, which retires the last instance of the flag idiom the 11.53 review
deleted.

### Do NOT, and record why

- **Do not adopt cglm's `box.h` wholesale.** It is compiled in and used zero times, layout-compatible,
  and `glm_aabb_invalidate` is bit-for-bit our sentinel — but it lacks `add_point` and `expand` (the
  two most needed), and `glm_aabb_transform`/`glm_aabb_frustum` are **different arithmetic** that
  would move the cull decision at the frustum edge, which is exactly where `wind_cull_fixture`
  deliberately parks meshes. Cite it as naming precedent, in one comment.
- **Do not unify `scene.c`'s literal 8-corner walk with `aabb_transform`.** The latter is the Arvo
  centre/extents bound — a conservative *superset* under rotation — so the scene box would grow,
  moving GI fit, probe box, fog anchor and auto-framing. Golden-moving; separate decision.
- **Do not convert `scene.c`'s `fminf`/`fmaxf` to `glm_vec3_minv`** without noting it: cglm's
  `glm_min` is `if (a < b) return a; return b;`, which differs from `fminf` on NaN — reachable from a
  zero-scale node.
- **Leave `light_cluster.c`'s ±1 sentinel** (doubles as the NDC clamp) and `emissive_light.c`'s 2D
  scalar quadruple (not a `vec3` box) alone.

### Hot path

`draw_list_build` runs every frame (the stamp folds `total_frames`, so the early-out never fires
across frames), and `draw_item_visible` runs per item **per pass**. `static inline` in a header is the
right form and is already proven here. Verify codegen did not change rather than assuming.

## P3 — the hash gets a home, and two exemptions get written down

Promote **`hash13(vec3)`** and **`hash21(vec2 p, vec2 k)`** into `noise.glsl`. The constant is a
*parameter*: `water_frag` uses `(127.1, 311.7)` and `tonemap_frag` uses `(12.9898, 78.233)`, so
parameterising is what lets both migrate with **no value change anywhere**. (`43758.5453` and
`43758.5453123` round to the same float32 — that difference was never real.)

Migrate three: `wind.glsl:38`, `water_frag.glsl:391`, `tonemap_frag.glsl:436`. `noise.glsl` is pure
arithmetic — no uniforms, no samplers, no `gl_FragCoord`, no derivatives — so it is safe in the four
vertex programs `wind.glsl` reaches, and `tonemap_frag` already includes it.

Decline two, **with the reason at the function**:

- `particle_sim_vert.glsl:43` `hash33` — vec3→vec3, three distinct constant vectors, a signed
  `-1+2·fract` remap, one caller. Promoting it puts a private helper in a shared header.
- `stochastic.glsl:40` `_stochasticHash` — vec2→vec2, and the chunk carries
  `uniform vec3 stochasticLut[64]`, `uniform float stochasticScale` **and `dFdx`/`dFdy`**. Splicing it
  into a vertex stage may not even compile. It could later *consume* a shared `hash21`; it must never
  be the source.

**And write down the two standing exemptions**, which is the part that prevents the next bug:

- `ssr_frag.glsl:191` already has its note and its number (31,800 px). Leave it exactly as is.
- **`contact_shadow_frag.glsl:122` has neither** — a sixth inline copy, in the identical
  explicit-multiply-add form ssr measured, and unlike ssr it **is covered by the `contact_debug`
  golden**. Add a one-line comment pointing at `ssr_frag.glsl:187-190`. Do not migrate it.

Then widen `noise.glsl`'s directive: it currently reads as a general rule ("New stochastic code
includes this file rather than inlining another copy of the hash") when `ign` is *screen-space dither*
and is no substitute for hashing a world position. Name the helpers by arity and record both
exemptions by file:line — otherwise the file's own comment describes a rule two shaders silently break.

**Not in scope, and worth its own row:** replacing `fract(sin(x)·k)` with a PCG/Wang integer-bit hash.
GLSL 330 has `uint` and bitwise ops, and it would be exactly reproducible rather than
precision-sensitive — a real improvement, with its own pixel cost wherever a hash is live.
