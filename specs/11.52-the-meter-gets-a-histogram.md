# 11.52 — The meter gets a histogram

## Context

Roadmap item 27 (E3). Cetra's auto-exposure is a **whole-frame log-average** — the tier UE calls
*Basic* and recommends moving off. Every comparable engine ships histogram metering with percentile
rejection as the default: UE5 (Low/High percent, min/max EV100, separate speed up/down, metering
mask), Unity HDRP (histogram + percentile clamping + metering modes), Frostbite (Lagarde &
de Rousiers 2014, the reference the roadmap already cites). This closes that gap.

**One correction to the roadmap's stated reasons, so this spec does not claim something its own
verification would refute.** E3's entry argues from a defect that has since been defended twice:
`lum_measure_frag.glsl` already uses a geometric mean (its comment: "robust to a few very bright
pixels, unlike an arithmetic mean") and already clamps (`lum = clamp(lum, autoKey, 1.0e6)`, comment:
"stops one sun pixel from crushing everything else" — a ceiling already raised once from 10000 after
exactly this class of bug). And the determinism claim may be collected by `EXPOSURE_ADAPT_SNAP`,
added so "steady state is a pure function of the scene".

So the claim here is **capability parity**, not bug-fixing, and the determinism effect is *measured*
rather than assumed.

**What is genuinely missing today:** percentile (scene-relative) rejection, any metering mask or
weighting, min/max EV clamps, separate adaptation speeds, any exposed control beyond one slider,
any readout of the metered value — and any test coverage at all.

## The coverage gap, which is the strongest single finding

- **0 of 24 goldens** run a live meter. All 24 pin with `--no-auto-exposure`.
- **0 of 38 gate groups** assert anything about metering. `SCALE_GATES` runs on fixtures that pin via
  `post.exposure`, so it is inert here too.
- Nothing asserts that auto-exposure **only darkens**, converges, or is stable run to run.
  `EXPOSURE_ADAPT_RATE`, `EXPOSURE_ADAPT_SNAP`, the metering floor and `EXPOSURE_MAX_STOPS_DOWN` are
  all untested — and the comments record that **two of those values shipped wrong** (6 stops; a
  10000 ceiling that made "an exterior meter as overcast no matter how bright it actually was"),
  both found by hand.
- `assets/postfx_convergence_fixture.cscn` already exists, is the **only** fixture with
  `"auto_exposure": true`, was written for exactly this gate, and **no script references it**.

Auto-exposure is the least-tested subsystem that ships on by default.

## Design

### Where it plugs in

The integration point is narrow. The GPU produces one scalar and `exposure_submit_measurement()`
consumes it; a new metering strategy changes *what number is produced*, not the plumbing.

| | |
|---|---|
| owner | `cetra/src/exposure.{c,h}` — single source since 10.1/10.2 |
| meter input | scene HDR **post-DoF**, pre-exposure divided out → absolute cd/m² |
| current meter | 64×64 `GL_R16F` → `glGenerateMipmap` → `glGetTexImage` of mip 6 (1×1) |
| CPU blend | rate 0.04 **per frame**, snap 0.01 |
| gain | `key / metered`, capped at 1.0 (only darkens), floored 2^-20 |
| readback | **deliberately blocking** (5.253 ms vs 0.033 for PBO+fence) — traded for headless determinism |

### The histogram, as raster (GL 4.1: no compute, no atomics, no SSBO)

The source is only **4096 texels**, so a *gather* histogram is trivial and no scatter/blend trick is
needed:

1. **Bin pass** → `N×1` `GL_R32F` target, one fragment per bin, each looping the 64×64 source and
   counting membership. 64 fragments × 4096 fetches.
2. **Reduce pass** → `1×1`, one fragment walking the bins, discarding the low/high percentile tails
   by population and averaging the survivors. Emits `log2` luminance — **the same contract
   `exposure_submit_measurement` already takes.**
3. Read back the 1×1 with the existing blocking `glGetTexImage`. This **deletes** the
   `glGenerateMipmap`.

Reuse: `create_color_fbo` (`postfx.c:30`), `draw_fullscreen_quad` (`util.c:78`),
`create_post_program` (`program.c:965`). Targets are resolution-independent, so they allocate beside
`lum_fbo` and free only in `free_postfx` — **not** in `postfx_free_targets` /
`postfx_invalidate_targets`.

### The hard constraint: scale-covariance

`SCALE_GATES` scales emitters ×1000 and exposure ÷1000 and demands **1 LSB peak**. Today those
fixtures pin exposure via `post.exposure`, so the arms are inert — but the new `exposure` group (P5)
runs the same comparison with metering **live**, where it is a real constraint.

A fixed-bin histogram is not covariant: ×1000 is ~9.97 stops, a **non-integer** number of bins, so
the two histograms are not shifted copies and percentile selection can land differently. Two
mitigations, both cheap, and P1 must demonstrate the property rather than assume it:

- bin the range in EV with **linear interpolation inside the bin** at the percentile boundary, so
  the answer is continuous under a fractional shift; and
- size the range from the min/max EV clamps, wide enough that ±10 stops stays interior.

### Other invariants that must not break

1. **No feedback ratchet.** `exposure.h:23-28`: anything upstream of the meter must be a fixed
   multiple of **radiance**, never of white, or the exposure ratchets instead of settling.
2. **Auto-exposure may only darken.** The floor-at-key makes that structural rather than a rule the
   C side remembers. Percentile selection must preserve it.
3. **Per-frame, not per-second**, adaptation — headless determinism depends on it. Speed up/down
   become two per-frame rates, not seconds.
4. **`engine->capturing → pre = 1.0`** must stay; probe captures render at unity.
5. Metering does **not** run in a debug render mode (the block is inside `postfx_run`'s
   non-passthrough arm), so adaptation freezes there. Worth a note, not a change.

## Phases

**P0 — the instrument, and the docs that are already false.**

`--exposure-probe`: metered luminance, adapted value, gain, EV100 and the histogram bins, in the
`--water-fft-probe` / `--emissive-light-probe` idiom. **Nothing today can observe the metered
value** — no log line, no GUI readout. 11.49's lesson applies exactly: a wrong exposure hides inside
a plausible image, so the instrument ships before the change. Record the baseline with it: does
exposure converge (snap) within golden frame counts, and what is the current `SCALE_GATES` margin
under live metering.

Fix the four documentation claims that are **known false today**, independent of anything this spec
concludes — leaving them in place while working in exactly this area is how the next reader gets
misled:

## P0 as built — the instrument, and three things it measured

`--exposure-probe` prints one line per metered frame: `raw_log2`, `raw_nits`, `adapted_nits`,
`gain`, `camera`, `pre_exposure`, `ev100`, `key`, `valid`. The flag lives on `Exposure` rather than
on PostFX, because that struct is "the one place that decides what the exposure is" and a report
assembled anywhere else would be re-deriving it from the pieces. It is silent on a pinned frame —
there is no measurement on a pinned frame, and that silence is the honest answer.

Both halves of the exposure print separately as well as their product, because they fail
differently and the frame only ever shows the product: `camera` is free of scene content and
identical across runs, `gain` is the half that adapts.

### 1. The snap works, and it works by frame 12

On `postfx_convergence_fixture`, `adapted` reaches `raw` exactly at **frame 12** and stays there —
the residual 2e-6 is the `exp2`/`log2` round trip through `adapted_luminance`, not drift. After the
snap the adaptation holds **no history at all**: exposure becomes a pure function of *this frame's*
measurement.

That is `exposure.c`'s own claim ("snapping inside ~1% makes steady state a pure function of the
scene") confirmed rather than assumed, and it is why **E3's determinism justification is
essentially already collected**. A perturbation of the approach path — async texture arrival, the
mechanism AGENTS.md names — cannot survive past the snap. What remains exposed is only a capture
taken *before* convergence.

### 2. Two runs of one build are bit-identical

200 frames, every field, both runs. (The only diff was a logger line spliced into the probe's
stdout by a `2>&1` shell redirect — an artefact of the capture, not the engine; `gates.py`
concatenates the two streams separately and is immune.)

### 3. Metering is NOT scale-covariant, by 1.61 stops — and the floor is why

The finding that reshapes P1/P2. `SCALE_GATES` scales emitters ×1000 and exposure ÷1000 and demands
1 LSB, but its fixtures pin exposure via `post.exposure`, so **it has never tested the meter**. With
the meter live, on `cornell_point`, fully converged:

| | `raw_log2` | `gain` | `pre_exposure` |
|---|---|---|---|
| 1× | −2.263672 | 0.864382 | 8.64e-1 |
| 1000× | +6.093750 | 0.002636 | 2.64e-6 |

**8.357 stops apart where covariance demands 9.966.** The cause is provable rather than suspected:
`0.208241 / 68.296989 × 1000 = 3.049`, whose log2 is `1.608` — exactly the deficit. That scene
meters 0.208 nits against a 0.18 key, so most of the frame is **below the metering floor and clamps
up**, inflating the 1× mean 3.05×. At 1000× nothing clamps, and 68.297 is 1000 × the true
uninflated mean of 0.0683.

Read at frame 29 the deficit is 1.85 stops and appears to grow with scale, which invites the wrong
diagnosis (the ceiling). It does not: only the 1× case had snapped by then, and the meter reads a
*pre-exposed* frame, so `raw` sits inside a feedback loop until it converges. **Measure covariance
only on converged frames.**

**The absolute floor-at-key is the non-covariant element**, and percentile rejection replaces it
with a relative one. So scale-covariance is not merely a risk P1 must avoid breaking — it is
something P2 can *fix*, and the only-darkens invariant survives without the floor because
`exposure_auto_gain` already caps the gain at 1.0 on the C side, which `exposure.c` notes it does
"anyway, because that invariant lives in a shader and this is the code depending on it".

This also gives P5 an arm that is falsifiable by construction: scale-covariance under live metering
**fails on today's code** at 1.61 stops and should pass after P2.

24 goldens 0 px; `SCALE_GATES` green (its pinned path is untouched).

# As built — P1 to P6

## P1, the histogram

Two raster passes replace `glGenerateMipmap`. Bins carry **count and sum**, not count alone, so
keeping the whole population reproduces the old mean with no resolution lost to binning — a no-op by
construction rather than by tolerance, and the reason a percentile cut is later exact for every
whole bin and interpolated only across the two the cuts fall in.

The one delta: `raw_log2` moved 0.000904, which is **half an fp16 ULP near 2.0**. The old chain
averaged in R16F at all six mip levels and accumulated the rounding; this sums 4096 values in fp32
and divides once. The new reading is the more accurate one.

## P2, percentiles — and the invariant this spec had wrong

**The `SCALE_GATES` shape cannot test a live meter.** Scaling emitters by K while dividing the
camera by K double-compensates once metering is on — the camera divides by K and the meter responds
to the same K — so `pre_exposure` lands ~K² off. Those arms are only meaningful with exposure pinned,
which is how they are written. The Design section above was rewritten around this.

The invariant that holds is **meter linearity**: emitters ×K with exposure *left alone* must move the
raw metered value by exactly log2(K). Measured on `cornell_point`, converged:

| metering | linearity error |
|---|---|
| floor at key (before) | −1.6084 stops |
| percentiles 0.10 / 0.90 | −6.1180 stops |
| percentiles 0.50 / 0.95 | −0.1337 stops |
| **shipped, 0.70 / 0.95** | **−0.0046 stops** |

Two absolute thresholds broke it, not one. The floor at the key inflated a dim scene's mean 3.05×.
Removing it exposed the second: **exactly-zero background**, where no geometry was drawn, which never
scales — so a low percentile that does not clear that population leaves the meter measuring
background, which is why 0.10 reads *worse* than the floor did. That is the reason UE's Low Percent
defaults to 80.

**The ceiling was doing real work and had to come back**, as a bound on the metered scalar rather
than a per-texel clamp. Without it, a bright scene drives the gain to the 20-stop floor,
`pre_exposure` collapses past fp16 subnormals in the HDR buffer, and the meter — which divides
`pre_exposure` back out — amplifies the remainder to **1.15e7 nits** and pins there. A stable fixed
point, and wrong.

Only-darkens now rests entirely on `fminf(gain, 1.0)` in `exposure_auto_gain`. Verified, not assumed:
forced to meter 1e-8 nits, fifteen stops under the key, the gain reads exactly 1.000000.

**Cost accepted, not hidden:** the sky-lit convergence fixture goes 0.61 stops darker.

## P3, the mask

Uniform, centre-weighted, spot. The weight multiplies a texel's contribution to the **population**,
not its value — so weighting a flat frame any way still meters the same luminance, which is what
makes a mode a framing choice rather than an exposure offset. It lives in the histogram pass, the
one pass that already knows where a sample came from.

Verified as a pure re-weighting: a spot wide enough to cover the frame reads **bit-identical** to
uniform (−1.446155 both). Modes separate on a real frame — gain 0.490 uniform, 0.531 centre, 0.842
spot.

## P4, the controls

GUI readout (metered luminance, gain, EV100) plus a Metering node; a `post.metering` `.cscn` block
with per-key presence flags and unknown-key warnings; six CLI flags.

And `-E` could not express a **negative EV bias**, which under a physical camera is stopping down —
half the range the GUI slider always had. The check could not have been correct where it was: a
camera arrives only from a `.cscn`, parsed after argv, so at parse time there was nothing to test
against. It moved to where the mode is settled. That needed a real presence flag, because **six sites
used the sign of `exposure` to mean "was it given"**, which cannot work once negative is legal. All
24 goldens pass `-E`, so every one exercises the replacement.

## P5, the coverage

Six arms, each paired with the reading that stops it passing vacuously. `postfx_convergence_fixture`
is wired after nine specs unreferenced.

**One arm was wrong first and is worth recording.** `exposure-tail` was written against
`flare_fixture` — the obvious small-bright-on-black instrument — and passed while comparing two
values pinned at the shader's 1e-8 numeric guard, 0.3 stops apart at 2^-26. That frame is too black
for the meter to be on live values at any percentile. It now reads the convergence fixture and
carries a floor asserting both readings are live, which is the real assertion.

`exposure-linear` is fail-first by construction: tolerance ±0.05 stops against −1.61 on the meter it
replaced.

## P6, the documentation

Roadmap E3 and Tier-4 row 27 marked done, keeping the original text as a quote because **the
correction is the useful part**: both stated reasons had been overtaken by commits that fixed them,
and the item was right anyway on parity grounds. AGENTS.md's shader inventory, determinism section
(the 99.77% figure predates the snap and is marked as such), the new flags, and a fixture row.
