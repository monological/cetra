# 11.65 — making the gate suite cheap enough to run often

## Context

`scripts/gates.py` has grown past its remembered 7 minutes — full-suite runs this session exceeded a
600 s foreground timeout — for 265 arms across 51 groups. The standing advice ("`--only <group>`
between phases, whole suite once at the end") is a symptom: a suite you avoid running catches
things later than it could.

**This spec does not parallelise.** Everything here is about doing less; parallelism stays
available afterwards, on a smaller base. **And nothing here may weaken an arm** — two arms shipped
inert this cycle (`quadtree-render`, `region-shift`), so "still green" is not evidence a cut was
safe. Every changed frame count gets a comment naming its floor; every touched arm gets its
falsifying mutation re-run.

## What the investigation established (source-read, line-cited by the two survey reports)

- **~339 renderer processes per run** (~284 `render`, ~55 `forest`) + 44 Python fixture
  generators + ~114 ImageMagick launches (`compare()` spawns two per call). At the suite's wall
  clock that is roughly **1.2 s per process while the median process renders 30 frames of 0.36
  requested Mpx** — per-process fixed cost dominates, not pixels.
- **Every requested pixel is 16 shaded samples**: HiDPI doubles each dimension
  (`engine.c:479-481`) and headless defaults to **4x MSAA** (`render.c:3400-3403`) unless `--taa`
  or `--msaa 1`.
- **The suite runs the DEBUG binaries** — `out/bin` hardcoded at `gates.py:39`, `:4252`,
  `goldens.py:46`; `CMakePresets.json` pins that dir to `-O0`. Forest startup measured 6.57 s
  debug / 1.40 s release. The erosion bake is 5x slower in debug (2.3 s vs 452 ms), and 9-12
  launches erode.
- **~37 shader programs compile+link per process, no cache** (`engine.c:1307-1492`, plus ~39 at
  PostFX init) — ~12,500 GLSL compiles per suite run. NOTE: the obvious fix, `glProgramBinary`,
  is almost certainly DEAD on this platform — Apple's GL driver reports zero binary formats.
  Verify with a three-line probe before anyone builds a cache; the viable alternative is LAZY
  program creation for off-by-default passes, for which `postfx_ensure_taau_program`
  (`postfx.c:357`) is the in-house precedent.
- **`-f 30` is the file's most-repeated number (~130 of ~339 processes) and is never justified
  once in 12,480 lines.** The engine audit found no mechanism that produces 30:
  - With no `--taa`, every shared temporal accumulator (TAA, GTAO, SSGI, SSR, SSS, fog layer,
    contact) is off AND force-invalidated per frame (`postfx.c:3333` et al.).
  - Pinned exposure skips metering entirely (`postfx.c:3493`) — zero frame requirement.
  - Animation/wind/particles/water are pure functions of the frame index headless
    (`engine.c:2461-2468`).
  - The one unconditional floor is the async loader at **5 texture uploads/frame**
    (`engine.c:2612`) — and the corpus barely triggers it (25 of 40 PNGs are goldens; most
    fixtures load 0-1 textures).
  - The genuinely load-bearing counts are **60** (froxel fog + clouds: alpha=0.1 EWMA, sub-1/255
    first at N~54; 30 retains 4.2%), **150** (exposure converges at 91 on its fixture; water foam
    ramps ~150), **240/400** (`--trace-player` prints every 30 steps; the region walk needs cells
    crossed). None is 30.
- **Frame-0 froxel bug found in passing**: `froxel_prev_frame` initialises to `-1` and frame 0's
  continuity test `-1 == frame_index - 1` MATCHES, so frame 0 blends against zero-cleared history
  and fog starts at 10% strength (`postfx.c:721`, `:2575`). `sky_clouds.c:329` carries the
  `>= 0` guard the fog path lacks. One-line fix.
- **Two resolutions the code itself retracted** (`gates.py:434-448`, `:1078-1084`): the skin arms'
  1200x750 existed for a pixel-cap lever spec 11.14 removed — the comments say resolution
  "creates no slack at any size". Six renders, 162 Mpx-frames, to sample eight pixels.
- **`_raiden_render` x3 inherits the app's default 1920x1080** (no `-W/-H` passed) x 120 frames,
  loading an 8K HDR and two FBX clips each time — ~12 G shaded samples serving ONE arm
  (`prepass-masked`), whose `-f 120` is inherited from the AGENTS.md recipe, not required.
- **Exact duplicates and dead output**: 4 byte-identical command pairs across groups (dir-shadow ~
  origin, flare pt0 ~ base, translucent on ~ offpath on, a third `--no-oit` render), 3 near-dups
  foldable with `--screenshot-every` or an added probe flag, and ~55 launches that write `-S`
  screenshots nothing ever opens (`_terrain_run` already dropped its `-S` with the reason
  written; the pattern was never propagated).
- **`--screenshot-every` works in every app since 11.62** and the suite uses it twice.

## Step 0 — reconcile the arithmetic (first, cheap, blocking)

The inventory's own sanity check does not close: 55 forest launches x 6.57 s ~ 361 s. Before
acting: **(a)** time one bare `render` and one bare `forest` launch, debug and release, `-f 1`
smallest fixture; **(b)** wall-clock the current full suite once as the baseline number every
later commit quotes; **(c)** `grep` one forest log for the sky-bake timings it already prints
(`sky.c:480,652`) and difference a `--no-sky` run — that prices the sky/IBL chain for free;
**(d)** difference a run against `out/release/bin` to price the debug tax per app. Report before
cutting.

## Step 1 — zero-risk harvest (no behaviour question at all)

1. **Delete the 4 duplicate renders** (dir-shadow/origin `r40_cc1`~`org_home` + the `--no-shadows`
   pair, flare `pt0`~`base`, translucent `on`~`live_on`, the third `--no-oit` render) and fold the
   3 near-dups (`water-surf` via `--screenshot-every -f 44`; `_emissive_probe`'s log-line read onto
   the existing render's stdout; prepass-identity reusing `gpu_submit_base.ppm` the way
   `inst-identity` already does).
2. **Drop `-S` from every launch whose screenshot nothing reads** (~55; probe/table readers).
   `_terrain_run:7580` is the precedent with the reason already written.
3. **Retracted resolutions**: skin-offpath/skin-handoff 1200x750 -> 400x300; re-check `ae > 0`
   still holds and the wrap/lit sample stays stable.
4. **Cap `_raiden_render`** with an explicit `-W 640 -H 400`; keep `-f` for now (its floor and the
   `<= 2000` bound are measured in-arm, so they re-calibrate, but re-measure and rescale the
   bound in the same commit).

## Step 2 — opt-in render sharing (the footgun named)

Generalise `_FOREST_RUN_CACHE` into one memo keyed on the full command minus `-S` — **opt-in at
named call sites, never automatic**. A command-keyed cache applied blindly would collapse the
deliberate a/b determinism pairs (same command run twice to MEASURE the run-to-run floor:
`_gpu_table full/full2`, `submit base/again`, `rai_off/rai_off2`, water `a/b` and `fa/fb`,
quadtree `on/on2`, exposure `stable_a/b`, every `list-identity` pair) into `compare(x, x) == 0`,
which is the inert-arm failure mode this cycle already shipped twice. Those pairs stay
process-per-call by construction, listed in a comment beside the memo.

## Step 3 — frame counts, floor by floor

Reclassify the ~130 `-f 30` launches into the engine audit's classes, each with the floor named in
a comment:

| class | floor | why |
|---|---|---|
| stdout integers only | **1** (4 if reading GPU milliseconds — `PROFILER_RING`) | submission counts exact per frame, force-latched |
| pixels, no fog, pinned exposure, no `--taa` | **5** | async loader ceil(N_tex/5); accumulators dead+invalidated |
| pixels with a medium (fog/clouds) | **60 — unchanged** | froxel EWMA, documented |
| metered exposure | **150 — unchanged** | converges at 91 on its fixture |
| pose/travel-at-N arms (wind-uv, water-surf, anim) | **unchanged** | N is floor AND ceiling — the printed value is a function of N |
| trace/walk arms | **unchanged this pass** | cadence and geometry priced; forest-rest 240->180 is possible but small |
| `_taa_churn`'s settle-to-90 | **sweep, then set** | only the 30-frame GAP is justified; the settle is a bare number |

Rule: an arm whose printed measurement is time-dependent by design keeps its count. Every arm
whose count changes gets its falsifying mutation re-run — the specific mutation failing, not the
suite green.

## Step 4 — samples per pixel

`--msaa 1` on launches that read only text (`_forest_run`, `_probe_render`, `_exposure_probe`,
`_region_run`, `_grid_tiles`, `_import_log`, non-identity `_profiled_run`s) — a 4x shading cut on
~100 processes. **Hazard is documented in-suite**: overdraw's budget was once double under a
sample-count change (`gates.py:7885-90`), so run `overdraw`, `submission`, `cull`, `profiler`
before/after and require identical integers before applying broadly. The 800x500 f30 family
(flare, catcher, oit, tsl) is a candidate second pass, arm by arm.

## Step 5 — the build-type decision (on Step 0's numbers)

Plumb one env var / `--bin-dir` through `gates.py` and `goldens.py` (three hardcoded paths)
regardless — it makes the question testable. The decision stays what it was: `-O2` changes CPU
float results, goldens re-bake once (`--rebake` exists, bakes twice and demands agreement), and
release becomes the reference build for verification while `build.sh` defaults to debug. Decide
per the measured suite delta, not the forest-startup figure. If wholesale switching is declined,
the `terrain` group alone (erosion at 5x in debug) is a candidate for a targeted exception.

## Step 6 — engine-side items (each contingent, each its own commit)

1. **Fix the froxel frame-0 sentinel** (`postfx.c:721`): adopt `sky_clouds.c:329`'s `>= 0` guard.
   Changes only the cold-start ramp (frame 0 fog 10% -> 100%); at frame 60 the difference is
   sub-LSB, so fog goldens and `FOGVOL_FRAMES` arms should be unmoved — verify, don't assume.
2. **Only if Step 0 shows compile dominates**: extend the `postfx_ensure_taau_program` lazy
   pattern to the off-by-default post passes. First check `GL_NUM_PROGRAM_BINARY_FORMATS` — if
   macOS reports 0, as expected, say so in the commit so nobody re-files a binary cache.

## Verification

```bash
./build.sh
python3 scripts/gates.py     # same 265 arms; every PASS line's numbers identical for unchanged-
                             # count arms; wall clock recorded before/after in the commit
python3 scripts/goldens.py   # 25/25 at 0 px
```

Per-commit: touched groups re-run with numbers compared, not verdicts; falsification mutations
re-run for any arm whose inputs changed; the suite wall clock quoted in each commit message so the
spec ends with a measured total, not an estimate.
