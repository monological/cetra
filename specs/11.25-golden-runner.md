# 11.25 — scripts/goldens.py, one recipe table for the golden corpus

Filed by spec 11.21; the cost re-paid by 11.24.

## Context

A golden is a stored PNG reference; checking it means re-rendering the same scene and requiring
**0 differing pixels** (`magick compare -metric AE`). The check is objective. What is missing is
any single place recording *which 19 images exist and what command makes each one*.

Today each recipe lives in whichever spec introduced it — a dozen markdown files — plus one
ad-hoc ledger, `assets/area_light_goldens.md`. 11.21 named the fix ("a committed
`scripts/goldens.py` with one recipe table and `--check` / `--rebake` is the natural sibling to
`gates.py`") and did not build it.

**The cost is not hypothetical — the scattering has produced false conclusions three times.**
11.17 recorded three goldens as having "no recipe recorded anywhere"; 11.21 repeated it and
added a fourth; 11.24 concluded six of nineteen were unreproducible and wrote that into the
roadmap. **All three were wrong**, and every one of the six was verified reproducible while
planning this item:

| golden | where the recipe actually was | reproduces |
|---|---|---|
| `flare_fixture` | `area_light_goldens.md` (`--flare 0.15 --chromatic-aberration 12`) | **0 px** |
| `backface_dark` | `area_light_goldens.md` | **0 px** |
| `guard_thin_panel` | `area_light_goldens.md` | **0 px** |
| `roughness_sweep` | `area_light_goldens.md` | 2 px (the known-stale pair 11.21 recorded) |
| `cloud_fixture` | nowhere — but it is not a file. It is `aerial_fixture.gltf --clouds` | **0 px** |
| `cloud_fixture_lowsun` | same, plus `--sun-elevation 5` | **0 px** |

So **all 19 are reproducible**, the corpus is healthy, and the only real defect is that finding
that out took a research session. That is what one table fixes.

## Second problem this closes

Dither (11.24) is default-on, and **12 goldens were re-baked with it while 6 were not** — those
6 reproduce only under `--no-dither`. The corpus is currently half dithered, half not, and since
their recipes do not carry `--no-dither`, a `--check` today would report six large diffs that
are not regressions.

## Design

A self-contained runner, sibling to `gates.py` and deliberately **not** wired into it: gates are
self-verifying (two renders of one build, no stored reference, CI-able), goldens need a
committed "before" and are not.

One module-level `RECIPES` list, one entry per golden: `name`, `scene`, `flags`, and the stored
PNG's pixel `size`. `-x` and `-S <out>` are added by the runner.

Commands: `--check` (default, exit non-zero on any mismatch), `--rebake [name ...]`, `--list`,
`--only <name>`.

**Three properties, each from a defect this repo has already hit:**

1. **`--rebake` renders twice and requires 0 px before writing.** A non-deterministic golden
   reproduces on the machine that baked it and nowhere else.
2. **`--rebake` must not rewrite a byte-identical file.** Several goldens legitimately do not
   move (a `--cs-debug` view never reaches the finishing block; a pure-black frame is unaffected
   by the dither taper). Re-encoding is meaningless churn at ~1 MB per file.
3. **A HiDPI guard.** The stored PNGs are the *framebuffer* size, 2x the requested `-W/-H` on a
   Retina display. On a 1x machine every render returns half-size and the compare fails on
   dimensions. `size` lets the runner name the mismatch as an environment problem rather than
   emit 19 confusing regressions — the same class of bug 11.24's review found in the dither
   gate's absolute pixel bounds.

**Reuse:** `compare` from `gates.py`. Not `gates.render()`, which hardcodes `-f 30 -W 400
-H 300`; every recipe here carries its own full flag list.

## Work

1. `scripts/goldens.py` with all 19 recipes.
2. Re-bake the 6 pre-dither goldens so the corpus is uniformly current.
3. `assets/area_light_goldens.md`: command blocks → a pointer at the runner. **All prose kept** —
   what to look for, why `--no-scene-file` is load-bearing, the zoom-in warning, and the E1/E2
   energy checks, which are not goldens at all.
4. Correct `docs/aaa-rendering-roadmap.md` (live document) and append a correction to
   `specs/11.24-output-dither.md`. 11.17 and 11.21 keep their wrong conclusions — specs are
   history.

**Not in scope:** CI wiring (there is none), and any change to the gates.

## Verification

1. `python3 scripts/goldens.py --check` → **all 19 at 0 px**. Never before possible in one
   command.
2. **Falsify the checker**: corrupt one golden, confirm it and only it is reported and the exit
   code is non-zero; drop one flag from one recipe, same.
3. **Falsify the determinism guard**: force the two renders to differ, confirm `--rebake`
   refuses to write.
4. **Falsify the HiDPI guard**: halve one recipe's `-W/-H`, confirm it reports an environment
   mismatch naming both sizes rather than a regression.
5. `python3 scripts/gates.py` still 45/45 — this touches no gate.
