# Spec 13.44: a capture burst keeps the punctual shadow array

## Context

In silent's basement, the log fills with `Punctual shadow array:` lines that flip several times a
second between two shapes:

- 6 layers at 4096², 384 MB;
- 53 layers at 1024², 212 MB.

Every flip frees and reallocates hundreds of megabytes. It also carries the kept candle and lamp
tiles across by blit and throws away every store cell. You feel this as stutter while captures are
running.

**Cause, a regression from 13.42:**

1. The array's edge is chosen per shadow pass from the number of per-frame shadowed light layers
   (`punctual_edge_for`, `cetra/src/shadow.c:292`): one layer gives 4096, none gives the 1024
   minimum.
   - The cached tiles' layer count is derived from that same edge (`tiles_layout`, `shadow.c:1831`).
   - Any change of edge rebuilds the array (`init_punctual_shadow_array`, `shadow.c:318`) and
     migrates the tiles.
2. A capture burst holds the scene at rest and runs its own shadow pass (`scene_capture_begin`,
   `cetra/src/render.c`).
   - Silent's rest turns the flashlight off by setting `cast_shadows = false` (`lights_apply`,
     `apps/silent/src/lights.c:309`).
   - So every frame that runs a burst with the flashlight on, the burst's pass shrinks the array to
     the 1024 shape, and the frame's own pass grows it back to 4096.

The engine already holds the rule this breaks. The burst forces the cascade count to 1 and turns
MSM off, and the cascade array is grow-only, "to keep the probe's capture-time force to count 1
realloc-free". The punctual array needs the same treatment.

**Intended outcome:** a capture burst never changes the punctual array's edge while the burst's
lights fit the budget at it. No rebuild happens between a burst and its frame.

## Step 2: the fix, in `cetra/src/shadow.c`

- **New helper `punctual_edge(ss, light_layers, burst)`.**
  - Outside a burst, or before the array exists, it is `punctual_edge_for(light_layers)`, as now.
  - Inside a burst, it keeps `ss->punctual_map_size` when the burst's layers fit the budget at
    that edge: `light_layers == 0 || punctual_size_for(light_layers) >= punctual_map_size`.
  - Only a burst that needs more than the frame's edge affords takes the smaller one.
  - Its comment cites the cascade array's precedent.
- **One edge per pass.** `render_shadow_depth_pass` computes the edge once, with
  `burst = engine->capture_kind != SCENE_CAPTURE_NONE` (set before the burst's pass, `engine.h:94`).
  - It passes that edge to both `tiles_layout` and `init_punctual_shadow_array`, so the tiles'
    layer count and the array cannot disagree.
  - Both functions take an edge in place of a light-layer count.
- **The rain pass** (`shadow_render_rain_layer`) passes `punctual_edge(ss, layer, false)`, the
  same edge the frame's own pass chose.
- **Out of scope, noted in the spec:**
  - A rest that turns per-frame shadowed lights ON would still rebuild once each way. Nothing does
    that today.
  - The flashlight's 18 m cluster overflow, and the store pool filling, are separate warnings.
    Look at whether the stores warning remains once the array stops being rebuilt.

## As built

### Step 1: the arm, red

- `--capture-rest-unshadow <light>` on the render app installs a capture rest hook,
  `_rest_unshadow`, that sets the light's `cast_shadows` to `!rest`. It refuses, with a warning, a
  light that does not cast.
- `capture-keeps-shadow-array` in `lighting-stream` runs `cornell_rooms.cscn` with `--gi-volume`
  for 60 frames at the paced budget, with `RoomsLampB` put away at rest.
  - It counts the `Punctual shadow array:` lines.
  - It checks the volume is still sweeping near the end, so the bursts did run a probe a frame.
- **On the engine before the fix: 120 builds in 60 frames.** The array alternated between 1 layer
  at 4096 (the burst's one spot) and 2 layers at 2048 (the frame's two), while the volume took
  one probe a frame, 50 by frame 50.
- The fixture is the arm's own (`LSTREAM_REST_FIXTURE`). `CORNELL_FIXTURE` is `cornell_box`.

### Step 2: the fix

- `punctual_edge(ss, light_layers, burst)`: inside a burst, once the array exists, it keeps
  `punctual_map_size` while `light_layers == 0` or the budget still affords that edge. Otherwise
  it returns `punctual_edge_for`, as before.
- `render_shadow_depth_pass` computes it once, with `burst` as
  `engine->capture_kind != SCENE_CAPTURE_NONE`. It hands the result to both `tiles_layout` and
  `init_punctual_shadow_array`, which now take an edge in place of a light-layer count.
- The array's log line reads the pass's count from `punctual_light_layers`.
- The rain pass asks `punctual_edge(ss, layer, false)`: it is drawn by the frame, never by a burst.
- **The arm: 2 builds in 60 frames.** The first frame's burst builds the array at its own edge
  before the frame's pass, which builds it once more at the frame's. After that nothing does.
  The pace is unchanged, 50 probes by frame 50. `LSTREAM_REST_MAX_BUILDS` is 2 for that first
  frame.

### Step 3: docs

`AGENTS.md`'s shadows bullet states the rule: the edge follows the per-frame layers, and a burst
keeps it. `docs/cli-reference.md` has the flag.

### The reviews

The four `/simplify` angles ran: reuse, simplification, efficiency and altitude. The tool
reserves `/thermo-nuclear-code-quality-review` for the user to invoke, so it did not run here.

**The altitude review found the fix at the right depth**, and the other three alternatives worse:

- **A hold or hysteresis in the edge policy itself.** It would strand a lone spot at 2048 after
  its neighbour goes, or hold about 120 MB more while the flashlight is off. Its narrow form does
  not cover the arm's two-to-one case.
- **A ShadowSystem field the burst sets.** That is a second record of `capture_kind`, which
  shadow.c already reads to ask whether a burst is running. It would also put an engine-owned
  value in render.c's hands.
- **The app's rest zeroing the intensity instead.** That leaves the trap for every other rest
  hook, and draws a layer for a light that emits nothing.

**Fixed:**

- **One function both passes ask.** `punctual_edge(engine, system)` sits beside
  `punctual_capacity` and reads the per-frame count from `rain_layer_index`, so the shadow pass
  and the rain pass cannot ask with different counts.
  - The rain pass's constant `false` and the redundant `light_layers == 0` clause went with it:
    `punctual_size_for(0)` is the largest edge already.
- **The edge policy's comment** moved from `init_punctual_shadow_array` onto `punctual_edge_for`,
  where the policy is. The parameter is `edge` throughout.
- **No app named in engine code.** The new comment's "silent puts its flashlight away" is gone.
  The MSM array's comment no longer claims to be the only allocation keyed on a per-frame count.
- **The capture key folds the punctual edge whenever a light still casts at rest.**
  - Such a light is drawn at the edge the frame chose, which the frame's own casters decide and
    no other part of the key states.
  - Silent folds 0, since nothing casts per-frame at rest, so its cook is unaffected.
  - Both kinds fold inside their burst: GI at its fetch and store, probes at theirs.
- **`--capture-rest-unshadow` refuses an unknown or non-casting light, exiting 1.** The arm no
  longer matches a warning's wording, which could have let it pass with no hook installed.
- **The arm** reads the stream period from `LSTREAM_PACED_EVERY`. Its locals no longer shadow the
  group's `held()` helper and `paced` list.
- **`render_args.h`'s new field** moved below `stream_probe`, so the aligned comments are untouched.

**After the fixes**, `shadow-tiles`, `rainfall`, `probe-set`, `lighting-stream` and `gi-cook` pass,
85 arms, and the arm still counts 2 builds. An unknown light exits 1 with the error.

**Skipped, with the reason:**

- **The second burst in a frame repeats the first's shadow pass.** This dates from 13.42 and is
  outside this diff. It is the same finding 13.42 recorded.
- **The first frame still builds the array twice** when a burst runs before the frame's first
  pass. It happens once, at load, and silent installs its GI at frame 2.
- **A rest that turns a per-frame caster ON still rebuilds.** The hold only works one way.
  Nothing does this today, and a fix needs state carried across passes.
- **Pressing F in silent still rebuilds the array once a press.** That is outside bursts. Keeping
  the edge with no per-frame light would cost about 170 MB while the flashlight is off, which is
  the user's call.
