# 10.7.1 — Reference-exact sheen IBL: Charlie-prefiltered environment + lambda visibility

## Context

10.7 made the sheen BRDF math spec-exact (alpha², E-LUT albedo scaling), but
the ENVIRONMENT half kept a shortcut inherited from the original sheen ship:
the sheen env term samples the **GGX** prefilter chain at the sheen
roughness. The Charlie kernel blurs far more than GGX at equal roughness, so
under a studio HDR the softboxes stay spot-shaped on the velvet spheres —
the user's close-up exposed exactly this, and the bar is now
reference-exact ("bulletproof"). The Khronos reference renderer filters the
environment through the Charlie NDF into a dedicated chain; that is the fix.
The user also chose (AskUserQuestion) to adopt the reference's
**Charlie-lambda visibility** over the current Ashikhmin form.

Scoping facts (verified by direct reads on branch `sheen-spec-conformance`):

- **All 16 sampler units of the PBR program are occupied** — unit 14 is
  `giAtlasTex` there (per-program units; skybox's 14 is a different
  program). A 17th sampler cannot link. The unit must be *reclaimed*: the
  two LTC tables (`ltcMatTex` unit 7, `ltcAmpTex` unit 9 — same dimensions,
  both engine-owned float LUTs, bound in `ltc.c:48-54`) pack into ONE
  `sampler2DArray` with two layers, freeing **unit 9** for the Charlie
  cubemap. The assert ledger at `render.c:32-60` pins this and must be
  updated.
- Latent bug this fixes structurally: under a reflection probe,
  `pbr_frag.glsl:1441` samples the PROBE's GGX chain for sheen (probe.c:142
  rebinds unit 12 after `bind_ibl_textures`), with `maxReflectionLOD` that
  is wrong by one mip for the probe's 8-mip chain. A dedicated Charlie
  sampler on unit 9 is never overridden by the probe.
- `ibl_bake_from_cubemap` has exactly two callers (HDR path `ibl.c:657`,
  procedural sky `sky.c:508`), so a Charlie bake inside it covers both with
  no sky.c edit. `probe.c` bypasses it (calls `ibl_prefilter_cubemap`
  directly) and deliberately gets NO Charlie chain — recorded decision.
- Reference math (fetched verbatim): Charlie importance sampling is
  `sinTheta = pow(Xi.y, alpha / (2*alpha + 1))`, `phi = 2*PI*Xi.x`, with
  alpha = sheenRoughness² — the squaring our `include/sheen.glsl` already
  owns. The lambda visibility is the `lambdaSheen` piecewise-exp form from
  the KHR spec / sample renderer `brdf.glsl` (exact fit constants to be
  copied verbatim from that file at implementation time).

## Design

### 1. Reclaim unit 9: pack the LTC tables into one sampler2DArray

`ltc.c`: allocate one `GL_TEXTURE_2D_ARRAY` (2 layers, same dims/format as
today, LINEAR + CLAMP_TO_EDGE — the data-LUT policy), upload inv-M to layer
0 and amp/Fresnel to layer 1; bind once on unit 7. `include/ltc.glsl`: one
`uniform sampler2DArray ltcTex` fetched with `vec3(uv, 0.0)` / `vec3(uv,
1.0)`. `common.h`: `TEXUNIT_LTC_MAT 7` becomes `TEXUNIT_LTC 7`; unit 9's
define is replaced by `IBL_CHARLIE_TEXTURE_UNIT 9` (in ibl.h with the other
IBL units). Update the render.c static-assert ledger. Bilinear within an
array layer is identical to a plain 2D fetch, so this is a **0-px change**,
proven on cornell_box (the suite's LTC/area-light scene).

### 2. Charlie-prefiltered environment chain

- **Shader** `cetra/shaders/ibl_charlie_prefilter_frag.glsl`: same contract
  as `ibl_prefilter_frag.glsl` (vertex `ibl_cubemap_vert`; uniforms
  `environmentMap`, `roughness`, `resolution`; N=V=R), but importance-samples
  the Charlie NDF: `alpha = max(r*r, 1e-4)`, `sinTheta = pow(Xi.y,
  alpha/(2*alpha+1))`, H in the tangent basis, `L = 2*dot(V,H)*H - V`,
  weight by NdotL, and the same solid-angle mip-selection trick as the GGX
  filter with `pdf = distributionCharlie(N, H, roughness) * NdotH /
  (4*VdotH)` — `distributionCharlie` comes from `#include "sheen.glsl"`, so
  the filter kernel IS the shading lobe by construction. 1024 samples.
- **Driver**: generalize `ibl_prefilter_cubemap` to take the
  `ShaderProgram*` (today it reads `ibl->prefilter_program` internally); the
  four call sites (ibl.c GGX, probe.c ×2, new Charlie) pass theirs
  explicitly. New program `"ibl_charlie_prefilter"` created in program.c
  (mirror `create_ibl_prefilter_program`, program.c:565) and registered in
  engine.c beside it; the new .glsl needs no CMake edit (glob).
- **Bake site**: in `ibl_bake_from_cubemap`, right after the GGX prefilter
  (`ibl.c:580-581`), filter `environment_cubemap` into a new
  `ibl->charlie_prefilter_map` at `IBL_CHARLIE_PREFILTER_SIZE 256`,
  `IBL_CHARLIE_PREFILTER_MIPS 6` (Charlie output is blur-dominated; 256 is
  enough even for the 1024 HDR chain), storing `max_charlie_lod = 5.0`.
  Freed in `free_ibl_resources`. This rides the existing capture FBO, cube
  VAO, seamless-cubemap enable, and state save/restore already in scope
  there. Cost note: the sky path re-bakes on sun moves; this adds roughly
  one more 256-chain prefilter per re-bake.
- **Bind**: `bind_ibl_textures` binds it on unit 9 + uploads
  `maxCharlieLOD`; the no-IBL else-branch in render.c (:392-399) pins the
  new sampler's unit like the others.

### 3. Point the sheen env fetch at the Charlie chain

`pbr_frag.glsl` sheen IBL block (:1433-1444): `sheenPre =
textureLod(charliePrefilteredMap, R, sheenRough * maxCharlieLOD)`; comment
rewritten — the "GGX chain understates Charlie's blur" approximation note
dies, replaced by the probe note (sheen reads the GLOBAL env's Charlie
chain even when a probe overrides unit 12; probes carry no Charlie chain).

### 4. Charlie-lambda visibility (user-selected)

Replace `visibilityAshikhmin` in `include/sheen.glsl` with the reference
`lambdaSheen` piecewise form (`V = 1 / ((1 + lambda(NdotV) + lambda(NdotL))
* 4 NdotV NdotL)`, clamped, alpha = r² shared with D; exact numeric-fit
constants copied verbatim from the sample renderer's brdf.glsl via
WebFetch at implementation time). Both consumers — the analytic lobe in
pbr_frag and the E integration in ibl_brdf_frag — swap automatically via
the include, so the E-LUT stays consistent with the shaded lobe by
construction. This CHANGES the analytic sheen look (softer,
energy-conserving) and therefore requires re-baking
`assets/sheen_fixture_golden.png`.

## Not touched

Probe capture path (no Charlie chain — recorded), GGX prefilter math, E-LUT
integration structure, punctual/shadow paths, `SHEEN_MIN_ROUGHNESS`, the
analytic Charlie D.

## As built

Implemented as planned, on top of the 10.7 commits; measurements from the
final reviewed build.

**LTC pack (own commit, proven alone):** cornell_box (the suite's area-light
scene) compared 0 px against the pre-pack build; the pack is a strict win
(one bind instead of two per program switch, unit 9 freed).

**Charlie chain + lambda visibility:** cornell_box, cornell_leak,
contact_fixture, and raiden all 0 px vs the master base build -- raiden's
environment bakes the Charlie chain and its pixels still do not move, which
pins the whole unit-9 replumb as invisible outside sheen materials. Gate
suite passes with byte-identical numbers (three runs across the branch).
Visual outcome on the fixture under the studio HDR: the sharp softbox spots
on the velvets are gone, replaced by the broad grazing sheen the Charlie
kernel produces; the satin keeps its tight ring. The env fetch needed no
LOD bias -- the correct kernel made the question moot.

**Cost (measured by the efficiency review):** the Charlie chain adds
~2.3-2.5 ms to each `ibl_bake_from_cubemap`, which the sun-drag sky re-bake
pays per drag frame (total bake ~12 ms of a 16.7 ms budget). Acceptable;
the recorded lever if it ever tightens is dropping the prefilter's
SAMPLE_COUNT to 256 (the Charlie kernel is blur-dominated and mip-fed, so
variance is low by construction) -- measure against a golden before taking
it.

**Golden:** unchanged from the 10.7 recipe bake at 800x450; verified 0 px
against the final build (the NaN fix below does not land at that
resolution's rounding).

## Review outcomes

Five background reviews (thermo-nuclear + four /simplify angles). Applied:

- REAL BUG (thermo): `lambdaSheen` could NaN via `pow(negative, 0.198)`
  when NdotV/NdotL round above 1 -- the same driver failure the iridescence
  path documents. `visibilitySheen` now caps both dots at 1. Confirmed
  empirically: exactly one fragment on the satin sphere at near-normal
  incidence changed (1 px in the 3840x2160 no-env render); everything else
  0 px.
- `sheenAlpha()` in sheen.glsl: the r-squared+floor mapping existed in three
  places (D, V, the prefilter's importance sampler); now one function
  enforces the one-lobe-width invariant mechanically.
- Stale-comment sweep: the E-integration doc named the retired Ashikhmin
  visibility; common.h's unit-budget prose contradicted its own defines;
  ibl.c's prefilter doc said "GGX-prefilter" for a now kernel-agnostic
  driver; ibl.h/sky.h bake docs gained the Charlie chain; sampling.glsl's
  header stopped naming its consumers; CLAUDE.md's sampler ledger and
  shader inventory and both roadmap docs' unit ledgers corrected
  (units 7/8/9).
- Dead code: the unreachable `if (!ltc->tex)` check and ltc.c's dead
  texture.h include; the `max_charlie_lod` field (only ever one
  compile-time value -- the bind site now uses the constant); the
  render.c assert made redundant by the new unit-9 sandwich.

Recorded, not done (with reasons):

- Sharing the tangent-basis builder and the solid-angle mip-selection math
  between the GGX and Charlie prefilter shaders: rejected for this branch --
  it edits the GGX prefilter text, putting every environment bake's
  byte-identity at the mercy of compiler regrouping (the clearcoat B3
  reassociation lesson) for a four-line dedup with no behavior gain. The
  duplication is deliberate and documented in the Charlie shader's header.
- A `create_texture_2d_array_float` helper for ltc.c: reviews split
  (reuse: extract; thermo/simplify: house precedent inlines per-site array
  creation since every site's sampler policy differs, and the helper would
  have one caller). Kept inline.
- Collapsing the five `create_*_program` cubemap-shader constructors into a
  `create_cubemap_program(name, frag)` factory: family-wide cleanup, out of
  scope here.
- Hoisting the loop-invariant `lambdaSheen(NdotV)` half out of the light
  loop: the compiler's LICM already does this for pure inlined math;
  code churn for a guarantee nothing measures.
