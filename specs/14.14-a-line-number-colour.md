# cetra 14.14: a line-number colour

## Context

pcb is getting a theme: a file of its own S-expressions, `~/.config/pcb/theme`, opened in a code
pane and read again each time it is saved, naming every colour the window draws (`code.background`,
`schematic.symbol.outline`, `schematic.highlight.chosen`, ...). Every name reaches something cetra
already exposes -- `UITheme`'s styles and editor styles, `engine->clear_color`, `canvas_set_style`,
a canvas view's background, the canvas's tags -- and all of them take effect on the next frame,
since an element's style is resolved from the theme each time it is drawn.

The focus rings are two of those names, and need nothing new: `window.pane-focus-ring`, round the
pane that has the keys, is `theme.panel[UI_STATE_FOCUS].border` and `theme.editor[UI_STATE_FOCUS]
.border` (today the focus blue at 60%); `window.input-focus-ring`, round the `:` line and the
palette's box while one is typed in, is `theme.text_field[UI_STATE_FOCUS].border` (the same blue at
100%). Each is drawn as the theme states it, and the widths stay cetra's.

All but one. The code editor draws its line numbers in its text colour at 38%
(`ui_editor.c:2540`, `dim`), and nothing in `UITheme` reaches them. A theme can make the code
background light and the text dark, but the line numbers can only ever be a fraction of the text,
which is the one colour every editor theme sets apart.

Branch and spec: `14.14-a-line-number-colour`, off cetra's master (`9f68d5df`).

## The design

One field in `UITheme`, beside the editor's others:

```c
vec4 line_numbers; // the code editor's line numbers; alpha 0 = its text at 38%
```

- **Alpha 0 is the default**, as `selection` beside it says "alpha 0 = the engine's". A zeroed
  theme draws exactly what it draws now, so `ui-theme-identity` and every golden are untouched.
- **One colour, not one per state.** The editor's text changes with its state; its line numbers in
  a set colour do not. The default keeps following the text, as now.
- `_draw` in `ui_editor.c` takes `t->line_numbers` when its alpha is above 0, and the text at 38%
  otherwise. Nothing else reads `dim`.

Not in this spec: the fallback selection colour, written three times (`ui_editor.c:2543` at 0.45,
`ui_field.c:856` at 0.55, `ui_editor_probe.c:1763`). It changes nothing pcb's theme needs, since
pcb sets `theme.selection`.

## Tests

**`ui-editor-line-numbers`**, a new arm in the `ui` group beside `ui-editor-shapes`, from a new
`editor-line-numbers` case in `apps/gametest/src/ui_editor_probe.c` (the `probe_editor_shapes`
shape: `editor_fixture`, `editor_pass`, the draw list read back with `ui_draw_list_quad`, glyphs
being kind 2). The glyph quads left of the text's first column are the line numbers. Flags:
- `default`: with `line_numbers` zeroed, every line-number glyph is the editor's resolved `fg` at
  0.38 of its alpha;
- `set`: with `line_numbers` red at 1, every line-number glyph is red, and the code's glyphs are
  their colour as in `default` -- the field reaches the numbers and nothing else;
- `cleared`: the theme put back, the numbers are `default`'s again.

`gates.py` reads it with `doc_flags`, the line count asserted.

## Phases

0. **Spec**: this plan into `specs/14.14-a-line-number-colour.md` on the branch, committed alone; a
   task list.
1. **The field**: `UITheme.line_numbers` in `ui.h`, `_draw` reading it, the probe case and the arm.
   Build with no warnings; `scripts/gates.py --only ui,gate-docs`, nothing else rendering.
   **Falsified**: `_draw` ignoring the field, the arm fails on `set`. **Look**: `apps/canvas
   --editor` headless before and after, rendered twice first for the noise floor -- by default the
   picture is unchanged. A set colour is seen in pcb, whose theme sets it. As built, committed.
2. **Docs**: `docs/ui.md`, the editor section (the line numbers in `theme.line_numbers`, the text at
   38% when its alpha is 0); `docs/eda-roadmap.md`, a bullet under "Not among the nine" for 14.14,
   for pcb's theme, and the "Specs 14.7 and 14.9 to 14.13" line; the spec. Committed.
3. **Review**: one thermo-nuclear review agent in the background at effort high, applied once
   back.

**Then, with the user's say-so**: cetra's master fast-forwards and the branch is deleted; pcb's
theme branch moves `extern/cetra` to it and maps `code.line-number` onto `theme.line_numbers`.
