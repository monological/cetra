# 9.5 — B1 Froxel volumetric fog

## Context

Fog today (`specs/4.5`) is a **screen-space raymarch** — each pixel marches its own view ray at
half res in `fog_frag.glsl`. That was correct when it shipped, and the 4.5 spec records why:
one shadow-casting key rig and no transparents, so a froxel grid's wins never activated, while
its costs (the codebase's first 3D texture, N slice passes on Apple GL-on-Metal) were the exact
driver edge that bit in 4.4.

**A1 (clustered forward, spec 9.1) changed that premise.** The engine now culls up to 128
point/spot/area lights into a 16×8×24 grid. The screen-space march cannot use that list — it
would pay per light, per step, per pixel. A froxel volume evaluates lighting **once per cell**,
so local-light scattering becomes affordable and cost stops scaling with screen resolution.
`lights_ubo.glsl:11-12` already documents the slice inverse "for volume passes marching the same
slices (froxel fog, B1)" — the integration seam was designed for this.

Roadmap item B1 (`docs/aaa-rendering-roadmap.md` Tier 1 #4). Aerial perspective was split out to
B9 (spec-to-be) so this item keeps a clean A/B against the existing pass.

## Design

### Volumes

Two `GL_TEXTURE_3D` RGBA16F volumes at **160×90×64** (~7.4 MB each), plus a history volume:
- `froxel_scatter` — per-cell in-scatter radiance (rgb) + extinction σ (a)
- `froxel_integrated` — front-to-back (inscatter.rgb, transmittance.a); composite samples this
- `froxel_history` — previous frame's scatter volume for temporal reprojection

**`GL_TEXTURE_3D` is genuinely required** (not the established `GL_TEXTURE_2D_ARRAY` idiom):
the composite's single **trilinear** tap must filter *across* slices, which array textures do
not do. This is the one piece of net-new machinery the feature needs.

### Depth mapping — reuse A1's slicing, own range

Exponential slices over `[near, fog_far]`, not the camera far plane, so resolution lands where
fog is visible. `include/froxel.glsl` holds the froxel↔view-Z mapping in the same Doom-2016 form
`lights_ubo.glsl:8-12` documents. `fog_far` is already a PostFX field; **`near` is recovered from
the projection matrix** (`near = P[3][2]/(P[2][2]-1)`) — the exact trick
`contact_shadow_frag.glsl` already uses, so no new publish.

64 froxel slices deliberately do *not* match `CLUSTER_Z`(24): the froxel shader converts its
slice → view Z and calls the existing cluster lookup, which handles any mapping.

### Pass 1 — inject + light → `froxel_scatter`

Per cell: world position from (x, y, slice), then the lighting **ported verbatim** from
`fog_frag.glsl`:
- `sigma = density · exp(-max(P.y − floorY, 0)/heightFalloff)`
- 3-caster CSM via `fogVisibility()`: affine `lsBase + t·lsDelta`, first in-bounds cascade in
  index order, `proj.z − shadowBias > depth`, outside-all ⇒ lit
- the shadowed spot: linear cone ramp, `1/(c+l·d+q·d²)`, perspective `w>0` + `xyz/w·0.5+0.5` tap
- `phaseHG(c,g) = (1−g²)/(4π(1+g²−2gc)^1.5)`, `sunBoost`, unshadowed/unboosted `ambientColor`
- **new**: clustered point/spot scattering via the cluster list + `lightIndexAt`

Two ports change by necessity: the directional phase and the light-space `lsBase/lsDelta` were
hoisted per *pixel* in the screen-space march (valid because a pixel has one ray); a froxel has
no single ray, so phase uses the froxel-centre view direction and the light-space projection is
evaluated per cell. Cost is once per cell, not per step.

**Cluster UBOs need zero C plumbing** — a postfx shader that `#include "lights_ubo.glsl"` gets
all three blocks bound automatically (`program.c:176-177` → `:415-418`).

Fog sun/ambient stay **app-set**; sky-published is B9, deferred so this pass keeps a clean A/B.

### Pass 2 — integrate → `froxel_integrated`

Slice `k` gathers slices `0..k` front-to-back with the energy-conserving form already specced in
4.5: `stepTrans = exp(−σ·dt); L += T·(1−stepTrans)·S; T *= stepTrans`.

Reads volume A, writes volume B — **no read-write hazard**, which is what makes the simple
O(n²) gather (~30 M taps) legal without `glTextureBarrier` (GL 4.5). *Documented alternative:*
the (S,T) composite operator is associative, so a 6-pass Hillis-Steele scan would cut this to
~5.5 M taps — rejected for now because it costs 6× the draw calls at this volume size, but it is
the lever if the gather ever profiles hot.

### Pass 3 — composite

One trilinear tap of `froxel_integrated`, blended into `hdr_fbo` at full internal res with the
**existing** idiom that already yields `scene·T + inscatter`:
`glEnable(GL_BLEND); glBlendFunc(GL_ONE, GL_SRC_ALPHA)` + the same restore
(`postfx_run_fog`, `postfx.c:1316-1329`). Same seam in the chain (after SSGI composite, before
SSS/DoF, `postfx.c:1852`) so shafts still defocus, meter, and bloom.

Deletes the half-res fog buffer, its 3×3 tent upsample, and `fog_history` on this path.

### Volume draws — slice loop

`draw_volume_slices()` loops 64 times: `glFramebufferTextureLayer(...)` to attach the slice, set
`uniform int sliceIndex`, `draw_fullscreen_quad`.

This **is the codebase's established idiom** — `shadow.c:186-215` attaches one cascade layer per
pass, `mask_array.c:170-181` attaches one array layer per draw, `ibl.c:387-393` one cube face per
draw. It reuses `post_vert.glsl` and `draw_fullscreen_quad` verbatim, so no `volume_vert/geo.glsl`
and no new shader stage.

Correcting the roadmap sketch: `gl_Layer` needs no version bump — only `layout(invocations=N)`
would force 400. The layered-GS path is a legitimate draw-call optimization behind the same
`draw_volume_slices()` seam, but it needs a GS *and* `gl_InstanceID`, both net-new to a tree where
all 60 shaders are `#version 330 core` and no shader uses `gl_InstanceID`.

### Temporal — and why it is not optional

The cascade tap is **binary** (one tap, no PCF, inherited from the march), and the volume evaluates
it once per cell. At 160×90 that puts a shadow boundary on a cell edge and stair-steps it: the
screen-space march hid the same hard taps by averaging 24 of them along every ray, and the volume
has nothing equivalent. The replacement is a sub-cell sample offset that moves **laterally as well
as in depth**, averaged across frames — a depth-only jitter leaves the lateral stepping untouched,
which is exactly the bug that shipped first.

The offset is a Halton sequence, identical for every cell, so successive frames supersample the
grid rather than adding per-cell noise. Accumulation is **not** gated on TAA, unlike every other
accumulator here: this one owns a history volume and reprojects through its own stored camera, so
it needs nothing from the TAA resolve, and gating it would leave headless renders (and therefore
the golden) showing raw stair-stepped shadows that no interactive user sees. Determinism survives
because the jitter is a function of the frame index — frame N is identical on every run.



The inject shader samples `froxel_history` at the cell's **reprojected** previous-frame position
and blends 90/10, then writes the blended value — no separate accumulate pass. The shared 2D
`temporal_accum_program` is not reusable *for the volume*: it reprojects by the screen-space
velocity buffer, which is meaningless for a volume of air.

*(As built: PostFX keeps its own `froxel_prev_view`/`froxel_prev_proj` rather than consuming a
published `prev_view_proj`, because `engine->prev_view_proj` already holds THIS frame's matrix by
the time postfx runs. No engine-side publish was added. And the jitter is **not** frozen when TAA
is off — this accumulator was deliberately un-gated, see above; determinism survives because the
jitter is a function of the frame index.)*

**The composited 2D layer is a separate problem with the opposite answer.** The volume accumulator
does nothing for the jitter the *composite* inherits from the aux depth, which shipped as a ~3×
flicker regression against the screen-space march. That one does reuse `temporal_accum_program`,
gated on TAA — the composited layer is surface-attached, so velocity reprojection is correct for
it even though it is wrong for the volume. See `specs/9.5.1`.

(`render.c:2107-2119`) are untouched.

**Docs** — as-built updates to `docs/aaa-rendering-roadmap.md` (tick B1) and

## Milestones (commit each; `git commit -S`)

- **M0 — de-risk.** `create_texture_3d`, `create_volume_fbo`, `draw_volume_slices`, a constant-
  writing inject, and the composite. No lighting. *Gate:* it renders on macOS at all — the named
  reason froxels were deferred; fog-off 0 px vs baseline.
- **M1 — port the march.** Height fog + CSM + spot + HG into inject; real integrate.
  *Gate:* the volume reads like the march (shafts, haze, spot cone) at 1:1; determinism 0 px.
- **M2 — clustered local lights.** `clusterLightListUv` + point scattering in inject.
  *Gate:* a local-light scene scatters; with no clustered lights, output matches M1.
- **M3 — temporal.** Reprojected 90/10 blend against the previous frame's volume.
  *Gate:* headless byte-deterministic; stable under orbit.
- **M4 — golden + docs + default flip.** Golden to `assets/*_golden.png`; roadmap updates.
- **M5 — delete the march.** Both implementations shipped behind a toggle through M4 so the
  froxel path had an A/B oracle; once it was verified against it the toggle, `fog_frag.glsl`,
  `fog_program`, `fog_steps`, the half-res targets, `--fog-debug` and `POSTFX_DEBUG_FOG` all
  went. Carrying two meant every fog parameter change had to land in two shaders — which had
  already produced one false claim in a comment.

## Verification

There are **no fog goldens today** and no test harness — verification is headless screenshot
diffing per `CLAUDE.md`, so measure the same-build noise floor first and pin exposure
(`--no-auto-exposure -E 1.0`) or auto-exposure drift masks everything.

1. **Off-gate 0 px** — no `--fog` vs pre-branch baseline.
2. **Determinism 0 px** — two headless runs with `--fog`.
3. **Golden 0 px** — `assets/froxel_fog_golden.png` reproduces.
4. **Spot regression** — `./out/bin/spores -x -f 300 -S p.ppm`: the beam must still be cut by the
   glass sphere (`specs/4.5.1`). Also smoke `tree` (has `--no-fog`).

While both implementations shipped (M0–M4) two more gates ran and stayed green: the legacy path
byte-identical to the pre-branch `--fog`, and the A/B between them inspected at 1:1 — never a
thumbnail (the 9.2/9.4 lesson). Both retired with the march.

Golden: `assets/froxel_fog_golden.png`, regenerated with

```
./out/bin/render -m assets/contact_fixture.gltf --fog --no-aerial -x -f 30 \
    --no-auto-exposure -E 1.0 -W 640 -H 400 -S /tmp/fog.ppm
magick /tmp/fog.ppm assets/froxel_fog_golden.png
```

`--no-aerial` was added by 9.6 and keeps this a *fog* golden. The fixture is
sky-lit, so aerial perspective also contributes to it — about 1 LSB on 4% of the
rock pixels at the default 1-unit-is-1-metre scale, plus a handful of pixels
seeing genuinely distant backdrop through gaps. Correct, but it is 9.6's
contribution, and folding it in would make this image test two features at once.

The image itself was regenerated once, by 9.6's final milestone: the fog's
ambient in-scatter used to be a hardcoded grey and is now the sky's own zenith
radiance, so the haze picks up a blue skylight cast instead of a neutral one
(RMSE 0.0066). That is an intended improvement to what this golden tests, not
drift. Before that change the byte-identical reproduction of the original
capture under `--fog --no-aerial` is what proved 9.6's composite restructure
altered no fog maths.

The rock fixture is used because it is self-contained (its sibling `.cscn` supplies the sky, sun,
and camera) and deterministic. Reproduces 0 px.

## As built

Shipped as planned, with these deltas found during implementation:

- **`prev_view_proj` is not publishable.** The plan called for publishing the engine's matrix,
  but the scene pass overwrites it with the current frame's at its end (`render.c`), so by the
  time postfx runs it is useless for reprojection. PostFX keeps its own `froxel_prev_view` /
  `froxel_prev_proj` instead — self-contained, no engine change.
- **History is a parity-indexed scatter pair**, not a separate history volume, so a frame reads
  the previous one without copying 7.4 MB.
- **Spots are skipped in the cluster loop.** The scene's first spot is published to `fog_spot_*`
  *and* appears in the cluster list; scattering both would double it. The one volumetric spot
  keeps its shadow-mapped path; further spots go unscattered, exactly as before.
- **`clusterLightListUv`** was added to `include/lights_ubo.glsl` (with `clusterLightList`
  delegating to it) because `clusterParams.zw` bakes in the scene-pass framebuffer size, which a
  160×90 volume has no pixel coordinate in.
- **Below the fog floor the medium is explicitly zero.** The march encoded that by clamping
  downward rays at the floor plane; a volume cannot, and without the explicit zero those cells
  sit at the density formula's maximum and fog the ground from underneath.
- **No `create_volume_program`** — all three passes are ordinary fullscreen quads, so
  `create_post_program` covered them and `volume_vert/geo.glsl` were never needed.

Measured: froxel vs legacy RMSE 0.44% on the sky-lit rock scene; the froxel sun edge is visibly
smoother (the half-res dither banding is gone). Cost is ~128 extra draws/frame plus ~30 M
integrate taps — **static counts, not timings; no frame time has been measured**, so the
integrate rewrites sketched above should be profiled before being chosen between.

Two composite bugs were found in review after the milestones and fixed (the A/B moved 0.51% →
0.44%, i.e. toward the independent legacy reference):

- The composite indexed the volume by **Euclidean distance** where slices are constant-**depth**
  planes, over-reaching by 1/cos off-axis — 1.38× at the corner of a 50° 16:9 frame.
- It sampled `(slice + 0.5)/depth` when layer *s* holds the integral to the FAR face of slice *s*
  (the integrate ends at *s+1*), so every pixel read one slice too deep. Correct is
  `(slice - 0.5)/depth`.

Both pushed the same way, so they compounded into over-fogging worst at frame edges. The
integrate's `dt` was also a depth difference where extinction needs path length, now scaled by
the ray's 1/cos.

## Risks

- **macOS GL-on-Metal 3D textures** — the named reason froxels were deferred; M0 hits it first.
- **Banding at 160×90×64 without TAA** — frozen jitter keeps headless deterministic; levers are
  slice count or dither strength, not TAA.
- **O(n²) integrate** — 30 M taps; the associative-scan rewrite is the documented fallback.
- **`prev_view_proj` publish** is new surface area on the engine→postfx seam; keep it additive so
  the existing publishes (and contact shadows' dependency on them) are unaffected.
