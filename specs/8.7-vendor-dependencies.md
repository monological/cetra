# 8.7 Vendor the Third-Party Dependencies

## Context
Cetra's four external libraries — glfw3, glew, cglm, assimp — are the only deps *not*
vendored (Jolt, cimgui, stb, cwalk, cJSON already live in `cetra/src/ext/`). They are
resolved per-platform from system package managers: pkg-config/Homebrew on macOS,
pkg-config/apt on Linux, vcpkg on Windows (`8.0-windows-portability`). Nothing is pinned,
so the *same source* builds against materially different versions per platform:

| lib | macOS (brew) | Linux (apt) | Windows (vcpkg) |
|---|---|---|---|
| glfw3 | 3.4.0 | 3.3.10 | unpinned |
| glew | 2.3.1 | 2.2.0 | unpinned |
| cglm | 0.9.6 | 0.9.2 | unpinned |
| assimp | 6.0.5 | 5.3.0 | unpinned |

This is a reproducibility hazard and it already broke the Linux build: Ubuntu's Assimp
5.3.0 declares `aiGetMaterialFloat` as a C11 `inline` with no exported definition, so it
fails to link at `-O0` where macOS's 6.0.5 links fine.

Requirement (from the maintainer): dependency versions must be **100% identical on every
platform**, **upgradeable on demand**, and **statically linked**. System package managers
cannot pin versions; vcpkg can but adds tooling on every machine. The chosen approach is
**vendoring** — the game-engine norm (Unreal, Godot) and already Cetra's pattern for Jolt.

## Approach
Add the four libraries as **pinned git submodules** under `cetra/src/ext/`, built from
source via `add_subdirectory`, **static**, on all three platforms. The pinned commit *is*
the version; it is identical everywhere by construction, and upgrading is a submodule bump.
This removes both the pkg-config and the vcpkg dependency paths.

Submodules (pin to release tags; confirm exact tags at implementation):
- `cetra/src/ext/glfw`  — github.com/glfw/glfw @ `3.4`
- `cetra/src/ext/cglm`  — github.com/recp/cglm @ `v0.9.6`
- `cetra/src/ext/assimp`— github.com/assimp/assimp @ latest `v6.0.x`
- `cetra/src/ext/glew`  — github.com/Perlmint/glew-cmake @ `glew-cmake-2.2.0`
  (the upstream GLEW repo ships no generated `glew.c`; this fork ships pre-generated
  sources + CMake, so it works as a submodule without a perl/python codegen step.)

## Changes

### `CMakeLists.txt`
- **Remove** the vcpkg toolchain chainload (lines ~5-14) and the entire `CETRA_DEP_PROVIDER`
  provider switch (the `pkg_check_modules` and `find_package(... CONFIG)` blocks, ~85-129).
- **Replace** with static vendored builds on `cetra_deps`. Set `BUILD_SHARED_LIBS OFF` and
  per-library options before each `add_subdirectory`, disabling their examples/tests/tools/
  install to keep build time and surface down:
  - glfw: `GLFW_BUILD_EXAMPLES/TESTS/DOCS OFF`.
  - glew (fork): `glew-cmake_BUILD_SHARED OFF`, `ONLY_LIBS ON`; link `libglew_static`
    (carries `GLEW_STATIC` as an INTERFACE define — verify; add if missing).
  - cglm: header-only interface target (`cglm_headers`) — no compiled lib needed.
  - assimp: `ASSIMP_BUILD_TESTS/ASSIMP_BUILD_ASSIMP_TOOLS/ASSIMP_INSTALL OFF`,
    `ASSIMP_WARNINGS_AS_ERRORS OFF`; link `assimp::assimp`.
- Keep `find_package(OpenGL/Threads)`, the `m` link on UNIX, the Apple frameworks, and all
  the WIN32 / MSVC compile-definition and Jolt-runtime blocks unchanged (those are about the
  engine/Jolt, not the four deps). The MSVC dynamic-CRT pin still applies and now governs the
  vendored deps too (all `/MD`), which is consistent.
- Exact vendored target names (`glfw`, `libglew_static`, `cglm_headers`, `assimp::assimp`)
  confirmed at implementation.

### `CMakePresets.json`
- `windows-base`: drop `toolchainFile` (vcpkg) and `VCPKG_TARGET_TRIPLET`; keep `clang-cl` and
  the x64 architecture. Windows now builds the vendored static deps with clang-cl against the
  system SDK — no vcpkg.

### Removed
- `vcpkg.json` (manifest no longer used).

### `.gitmodules`
- Four new submodule entries.

## Verification
Build all three targets from the Mac via `build.sh --target`:
- **macOS** (local, fastest loop): `./build.sh` → clean link; run one app.
- **Linux**: `./build.sh --target linux` → the Assimp `inline` link error is gone (Linux now
  builds vendored 6.0.x, not apt's 5.3.0); `out/bin/*` produced.
- **Windows**: `./build.sh --target windows` → clang-cl builds the vendored static deps, no
  vcpkg; `out/windows-debug/bin/*.exe`.
- Confirm identical versions: the submodule SHAs are the single source of truth; `git
  submodule status` is the pin. First clean build is slower (assimp compiles from source, like
  Jolt); incremental unaffected.

## Notes
- assimp from source adds build time (comparable to the already-vendored Jolt). Importer set
  can be narrowed later (`ASSIMP_BUILD_*_IMPORTER`) if build time matters; default keeps all.
- System libraries stay dynamic and correct: OpenGL (the GPU driver), X11 on Linux, the Apple
  frameworks, the Windows CRT. "Static" scopes to the four vendored deps only.
- Upgrading a dep: `cd cetra/src/ext/<lib> && git checkout <newtag>`, commit the submodule bump.
