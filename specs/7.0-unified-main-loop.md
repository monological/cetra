# Plan: Unify the two main loops (engine owns the frame; run_game becomes a thin wrapper)

## Context

cetra has two independent, hand-copied main loops:
- `run_engine_render_loop` (engine.c:1964) — used by render / shapes / tree.
- `run_game` (game.c:193) — used by spores / gametest.

They duplicate the whole frame skeleton (dt, FPS, GUI-frame open, shadow pass, present,
screenshot, swap/poll) and have already drifted:
- **Two FPS counters** (`engine->fps` vs `game->fps`) -- the reason the FPS overlay didn't
  work in spores without a shuttle.
- **`run_game`'s render setup is a degraded copy**: it does a plain `glClear` and SKIPS the
  supersampled viewport, the G-buffer draw-buffer selection, the mask-array build, and the POM
  resolve that `run_engine_render_loop` does (engine.c:2024-2072). So game apps silently run a
  reduced pipeline -- GTAO/TAA/SSGI/SSS can't engage because their G-buffer attachments never
  get written.

Goal: **one loop in the engine** (`engine_run`) that owns the frame skeleton and takes an
optional per-frame update callback. `run_game` becomes a thin wrapper over it and the render apps
call it directly (the old `run_engine_render_loop` is deleted). This kills the drift, makes the FPS overlay work in game apps for free, and
upgrades game apps to the full render pipeline.

## Design

New engine entry point (cetra/src/engine.{h,c}):
```c
typedef void (*EngineUpdateFunc)(Engine* engine, float dt);     // once/frame, before render; may be NULL
typedef void (*EngineRenderFunc)(Engine* engine, Scene* scene); // once/frame
void engine_run(Engine* engine, EngineUpdateFunc update, EngineRenderFunc render);
```
`engine_run` is `run_engine_render_loop`'s old body with two changes: (a) an optional
`update(engine, dt)` call once per frame right after the GUI-frame open and BEFORE the shadow
pass (so physics/transform updates land before shadows + render); (b) engine-owned frame-limit
via a new `exit_after_frames` field. `dt` is the honest (unclamped) frame time -- `engine->delta_time`
holds it, and only the FPS average uses a local 0.1s-clamped copy, so a game can apply its own
`max_frame_time` clamp.

**No `void*` in the callback signatures** (as-built; the original plan threaded a `void* user`).
Context flows through a GLFW-style engine user pointer instead: `engine_set_user_data` /
`engine_get_user_data` over a new `Engine.user_data` slot. The render callbacks stay the clean
`(Engine*, Scene*)` shape the apps already use.

**`run_engine_render_loop`, `RenderSceneFunc`, and `engine_capture_screenshot` are DELETED** (all
dead after the merge -- no back-compat wrapper). The render apps call
`engine_run(engine, NULL, render_scene_callback)` directly with their unchanged `(Engine*, Scene*)`
callbacks. (Untracked apps are updated the same way but do not appear in the diff.)

**`run_game` becomes thin** (game.c). It stashes the `Game*` on the engine user pointer, then
plugs its per-frame sim + render into `engine_run`:
```c
static void game_frame_update(Engine* engine, float dt) {
    Game* g = engine_get_user_data(engine);
    input_update(&g->input);                                              // once/frame, BEFORE the accumulator
    if (input_key_pressed(&g->input, GLFW_KEY_ESCAPE)) glfwSetWindowShouldClose(engine->window, GLFW_TRUE);
    float ft = dt; if (ft > g->max_frame_time) ft = g->max_frame_time;    // game's own spiral clamp
    if (!g->paused) { g->accumulator += ft;
        while (g->accumulator >= g->fixed_timestep) { /* fixed-timestep sim body verbatim */ } }
}
static void game_scene_render(Engine* engine, Scene* scene) {
    (void)scene; Game* g = engine_get_user_data(engine);
    if (g->on_render) g->on_render(g, g->accumulator / g->fixed_timestep); // alpha derived, not stored
}
void run_game(Game* game) {
    if (!game || !game->engine) return;
    if (game->on_init) game->on_init(game);
    engine_set_user_data(game->engine, game);
    engine_run(game->engine, game_frame_update, game_scene_render);
}
```
(on_init runs before engine_run; engine_run's pre-loop GL-state setup is behavior-neutral for
on_init, which only builds/uploads geometry. on_shutdown stays in free_game.)

**Engine-owned frame-limit + screenshot** (unifies both CI paths): add `int exit_after_frames`
to `Engine` + `set_engine_exit_after_frames`. In `engine_run`, after `total_frames++`: if
`exit_after_frames > 0 && total_frames >= exit_after_frames` -> `glfwSetWindowShouldClose(true)`.
The existing final-frame screenshot on `glfwWindowShouldClose` (engine.c:2094) then fires for
both frame-limit and normal quit. `create_game` maps `config.exit_after_frames`/`screenshot_path`
-> `set_engine_exit_after_frames`/`set_engine_screenshot_path`. The render app's `--frames` now
routes through `set_engine_exit_after_frames` too (dropping its own `max_frames` static), so there
is ONE frame-limit mechanism.

**Game struct cleanup** (game.h): drop the fields that duplicate engine state --
`last_time`, `delta_time`, `fps`, `frame_count`, `fps_timer`, `exit_after_frames`,
`screenshot_path`, `total_frames`, and `running` (loop control is now `glfwWindowShouldClose`;
`game_quit` -> `glfwSetWindowShouldClose(true)`). `game_get_fps` returns `engine->fps`. Map
`config.show_debug_gui` -> `set_engine_show_gui` (the render alpha is derived in
`game_scene_render`, not stored). Keep the genuinely
game-specific fields: `fixed_timestep`, `accumulator`, `time`, `max_frame_time`, `paused`,
`input`, the four callbacks, `user_data`, `scene`, `physics_world`, `entity_manager`.

**FPS overlay returns for free**: spores just calls `set_engine_show_fps(engine, !engine->headless)`
in `on_init`; the unified loop opens the GUI frame + computes `engine->fps` + presents. No
public `engine_begin_gui_frame`, no `engine->fps = game->fps` shuttle (both were the reverted
band-aid).

## Changes (files)
- **cetra/src/engine.{h,c}** -- add `engine_run` + the two `void*`-free callback typedefs; DELETE
  `run_engine_render_loop` / `RenderSceneFunc` / `engine_capture_screenshot` (all dead); add
  `exit_after_frames` + setter and `user_data` + `engine_set/get_user_data`; drop the vestigial
  `draw_gui` param from `engine_present_frame`; insert the update-callback call before the shadow
  pass; keep the GUI-frame-open inline inside `engine_run` (no public helper).
- **cetra/src/game/game.{h,c}** -- `run_game` -> thin wrapper; add `game_frame_update` /
  `game_scene_render`; drop the duplicate fields; `game_get_fps` -> `engine->fps`; `game_quit`
  -> windowShouldClose; `create_game` maps config -> engine setters (incl. the user pointer).
- **apps/spores/src/spores.c** -- `set_engine_show_fps(engine, !engine->headless)` in on_init.
- **apps/{render,shapes,tree}/src/*.c** -- call `engine_run(engine, NULL, render_scene_callback)`
  directly (callbacks unchanged); the render app also drops its `max_frames` static for
  `set_engine_exit_after_frames`. (Untracked apps get the same treatment locally.)
  splash keeps its own hand-rolled loop (separate; migrating it is an optional later follow-up).

## Reuse (don't reinvent)
- `engine_run` IS `run_engine_render_loop`'s existing body -- reuse `engine_present_frame`
  (engine.c:1660), `render_shadow_depth_pass`, `engine_set_scene_draw_buffers`,
  `mask_array_ensure_built`, `heights_ensure_resolved`, the G-buffer draw-buffer/clear block
  (engine.c:2030-2058), `_save_framebuffer_ppm`, `set_engine_screenshot_path`/`_every`.
- The fixed-timestep accumulator body (game.c:247-291) moves verbatim into `game_frame_update`.

## Risks / notes
- **Game apps now run the full render pipeline** (G-buffer, SSAA viewport, mask, POM) -- the
  intended upgrade, but it CHANGES spores/gametest rendering vs today's reduced path. Verify
  look (steps 3, 6). Biggest single risk.
- **dt clamp**: engine passes real dt; the game re-applies its `max_frame_time` clamp inside
  `game_frame_update`, preserving spiral-of-death protection. FPS uses the engine's own clamp.
- **input_update stays once-per-frame, before the accumulator** (edge-detection semantics), and
  **escape-to-quit stays game-side** (not hard-coded in `engine_run`, so render apps are
  unaffected).
- **Scroll-callback conflict** (`input_init` at input.c:25 clobbers the engine's scroll callback)
  is pre-existing and out of scope; note for later.
- **gametest** cannot be headless-verified here -- needs an interactive check.
