# Spec 12.11 — Cross-rig retargeting, and saying when it did not happen

## Context

Spec 12.10 made `--puppet` accept any rigged humanoid: `skeleton_resolve_bone` finds the IK
chains on a rig that names a foot `leg left ankle`, and a rig with no clips of its own is
given the committed set. A 122-bone third-party character now loads, resolves every bone the
solver wants, and **lies on its face**, with a measured stride of 0.12 m/s where the
reference humanoid reads 0.93.

**The cause is that retargeting silently does nothing.** With no source rest pose,
`import.c:1262-1263` seeds `source_local_rest` *from the target's own rest*:

```c
versor source_local_rest;
glm_quat_copy(target_local_rest, source_local_rest);
```

so `import.c:1288-1290` computes `delta = inv(target) * target` — **identity by
construction**, for every bone. The global-space path that is the only code capable of
reconciling two rigs' rest orientations (`animation.c:874-926`) arms only inside
`if (source_skeleton)` at `import.c:1265`, so it never runs either. The clip's raw local
rotations are then written verbatim into bones whose rest frame is nothing like the source's,
underneath a `root ground` parent carrying a 180° Z-up→Y-up flip.

**Nothing says so.** The bone table prints `0.0 deg [R]` per bone, where `[R]` is
`needs_retargeting` — set unconditionally for every matched channel (`import.c:1296`) — and
the summary says `52 channels, 52 matched, 52 retargeted`. The one true signal, the
`log_warn` at `import.c:1402`, is a single line in a busy startup log and was read past.

The clips are exported **Without Skin**, so `process_ai_skeleton` finds no `mNumBones > 0`
mesh to synthesise a source from (`import.c:1391-1396`) and the fallback cannot fire.

Outcome: an arbitrary rigged humanoid stands up and walks, and a retarget that cannot work
says so in terms that cannot be read past.

---

## The change

### 1. Supply the source rest pose

`gametest` loads `assets/models/t_pose.fbx` once at init and passes its skeleton as
`source_skeleton` for every SHARED clip load. That file is the rig those clips were authored
on — 65 bones, `cetra_rig:` names, and the clips' channel names match it exactly, so
`find_matching_bone_smart` on the source resolves and `use_global_retarget` arms.

- The site is the `SHARED_CLIPS` loop in `on_init`, currently
  `load_animations_from_file(scene, skeleton, SHARED_CLIPS[i], true, NULL)`.
- The puppet's OWN clips need no source: same rig, and a source would be a no-op at best.
- Follow `apps/render`'s precedent (`render.c:3759-3771`): `create_scene_from_model_path`,
  take `skeletons[0]`.

**Three hazards, and the second is the one that will bite.**

1. **Lifetime.** `render.c` imports a whole scene for `-s` and never frees it, on the belief
   that the skeleton is borrowed. Determine whether it actually is: each channel stores
   `source_bone_index`, `source_parent_bone_index` and `source_local_rest` **by value**
   (`import.c:1276-1278`), and `animation.c`'s PASS 0 appears to rebuild the source hierarchy
   from the channels alone. If so the source scene can be freed straight after the loads and
   `render.c`'s leak is a separate small fix; if not, it has to outlive the clips and that
   must be said where the pointer is held.
2. **One `TexturePool` per `AsyncLoader`.** `async_loader.h:140-142` states it: keys match
   across the whole loader, and embedded keys (`"*0"`, `"*1"`, …) collide between any two
   imported scenes. Holding the puppet's scene and a source scene open on one loader is
   outside that contract. **Drain the loader to idle before importing the source**, and again
   before freeing it — reusing the drain 12.10 added on the reject path, hoisted into one
   helper rather than written three times.
3. Freeing any imported scene runs into the uncancellable `Material*` callback
   (`import.c:679-689`); the same drain covers it.

### 2. Say when a retarget did not happen

Three edits in `import.c`, all about the same lie:

- **Count what actually happened.** `retargeted_channels` increments for every matched
  channel. It should count channels that got a non-identity correction or the global path;
  a run that retargeted nothing should say `0 retargeted`.
- **Warn by name, once per clip**, when retargeting was asked for and no source rest pose was
  available — naming the clip and what the consequence is, not just that a file lacked a
  skeleton. The existing `log_warn` is the right content in the wrong register.
- **`[R]` in the bone table** should mean a correction was computed, not that the flag is set.

### 3. Fix the reversed header comment

`animation.h:126` documents `rotation_delta` as `target_rest * inv(source_rest)`; the code
computes `inv(source_rest) * target_rest` (`import.c:1290`, cglm's `glm_quat_mul(p,q,dest)`
being `dest = p*q`). The in-line comments agree with the code; the header is backwards.

### 4. An arm, on a fixture that cannot be removed

The defect needs a rig whose rest orientation genuinely differs from the clips'. The
third-party character cannot be that fixture — it is not committed and will not be.

**Add a Z-up variant to `assets/generators/gen_puppet_fixture.py`**: the same generated
puppet with its root carrying the 180°-about-(0,1,1) rotation a Blender Z-up export bakes in.
That is exactly the shape that breaks, it is deterministic, it costs one small `.gltf`, and
`fixture-gen` proves it reproducible.

Then `anim-retarget` asserts, through a new `--anim-probe retarget` case:

- loading a clip onto that rig with **no** source yields an identity delta on every channel
  and a hips global whose Y axis is **not** up — the failure, pinned;
- with `t_pose.fbx` as the source, the deltas are non-identity, `use_global_retarget` is on,
  and the hips' Y axis IS up.

The up-axis test is the one that matters: it is rig-agnostic, it is what a person sees, and
it fails on exactly the defect this spec fixes.

## Verification

```bash
python3 scripts/gates.py --only anim        # the new arm, and the existing 16
python3 scripts/gates.py --only ik          # the stride measurement rides on the retarget
python3 scripts/gates.py --only fixture-gen # the new fixture reproduces
python3 scripts/goldens.py --only puppet    # must be 0 px: the generated rig is untouched
```

**The numbers that decide it:**

- the Z-up fixture's hips Y axis, with and without a source — the second must be up
- the max delta angle across channels: identity without a source, non-identity with one
- `steady_run`'s measured stride on the third-party rig, against the 5.01 m/s the reference
  humanoid reads — currently 0.12

**The watch**, which no arm replaces, on the local uncommitted character:

```bash
./out/bin/gametest --puppet <path>            # stands, walks, feet locked
./out/bin/gametest --puppet <path> --no-lock  # the two told apart
./out/bin/gametest                            # the generated puppet, unchanged
```

## Out of scope

- **`scene_import_model`.** I claimed in conversation that `take_puppet_root` drops the
  model's root transform; **that is wrong and worth correcting here.** gametest does not
  re-parent into a second scene — it *adopts the model's scene as the game scene*
  (`gametest.c:2326-2333` then `game_set_scene`), precisely because a material belongs to the
  scene that registered it. The wrapper is added back under the same root, so the root stays
  an ancestor and nothing is lost. Two real costs remain, neither of them this bug: the
  model's root matrix applies to **everything the app adds afterwards** — floor, hearts,
  player holders — which is inert for the generated puppet's identity root and live for an
  FBX puppet whose root carries the axis and unit conversion; and the named-`"puppet"`-node
  branch *does* discard every ancestor transform between the file root and that node.
  A real `scene_import_model` has three blockers to solve first — `Material.owner`
  (`scene.c:413-419`, `draw_list.c:230-232`), one `TexturePool` per `AsyncLoader`, and the
  importer's registry writes CLOBBERING rather than appending for lights and cameras
  (`import.c:1482-1483`, `1641-1642`). Its own spec.
- **A cancel in the async loader.** The drain is a caller-side workaround for a missing API.
- **Two structural caveats the exploration surfaced**, neither triggered here and both worth
  writing down rather than fixing blind: `process_ai_skeleton` enumerates only skinned bones,
  so an unskinned ancestor's transform is absent from the local chain while present inside
  `inverse_bind_pose`; and both retarget passes assume parent-before-child bone order, which
  nothing guarantees.
- **An arm for the medium state machine** (12.10's own owed item).
