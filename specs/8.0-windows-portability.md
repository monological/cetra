# Plan: Make cetra buildable on Windows (portability groundwork)

## Context

Cetra is portable in principle — GL 4.1, GLFW, GLEW, cglm, Assimp, Jolt, ImGui, stb and cwalk are all
cross-platform — but has only ever been built on macOS. The goal is **not** to ship a Windows game; it
is to remove the platform assumptions between the current code and a Windows build, so a port becomes
compile-and-fix rather than archaeology.

Four surveys found the surface is **small and concentrated**: ~14 of ~50 non-vendored files need any
change, and `cetra/src/util.c` alone carries the CPU query, every filesystem call, all path
normalization, and 5 of the 7 existing platform conditionals. There is no `fork`/`exec`/`dlopen`/
`mmap`/`signal`/socket use anywhere, no directory enumeration, and shaders are already embedded as C
strings so there is no runtime shader-file dependency.

**Two things make this harder than a flag-flipping exercise:**

1. **The worst bug is silent.** `cwalk` picks its separator style from a compile-time global
   (`ext/cwalk.c:12-16`), so on Windows `cwk_path_normalize` (`util.c:337`) emits **backslashes** —
   but `convert_and_normalize_path` assumes forward slashes and `find_existing_subpath` scans for
   `'/'` (`util.c:266`). That scan finds nothing, the recovery loop dies on its first iteration, and
   textures fail to resolve inside a worker thread. It compiles without a warning. A port that only
   chases compiler errors ships this.
2. **`pthread_t` is in a public header.** `async_loader.h:5` includes `<pthread.h>` and the
   `AsyncLoader` struct exposes `pthread_t*`, `pthread_mutex_t`, `pthread_cond_t`. This is the single
   largest item on the critical path, and no build-system trick fixes it.

## Decisions taken

- **Toolchain:** clang-cl (MSVC ABI, clang frontend — handles the existing gnu11 code with least friction).
- **Build/verify:** a Windows KVM guest. No CI yet; macOS can't be virtualized there anyway, and CI is
  for *keeping* the port working, which can wait until it exists.
- **Dependencies:** vcpkg manifest mode on Windows, existing pkg-config retained on macOS/Linux.
- **macOS is the primary platform and must not regress.**

## Workstream 1 — Threading shim

**Why a shim, not C11 `<threads.h>`:** verified by compile that the **macOS SDK does not ship
`threads.h`**. Adopting C11 threads would break the primary platform.

All **51 pthread call sites use only the common subset** — no `pthread_cancel`, `detach`, custom
attrs, recursive/timed locks, TLS, `once`, rwlocks, barriers or spinlocks. Every mutex is `NULL`-attr,
every thread explicitly joined. Mechanical mapping, no redesign.

Add `cetra/src/thread.h` (header-only, static inline):

| Shim | POSIX | Win32 |
|---|---|---|
| `cetra_thread_t` / create / join | `pthread_t`, `pthread_create/join` | `HANDLE`, `_beginthreadex` / `WaitForSingleObject` |
| `cetra_mutex_t` / init destroy lock unlock | `pthread_mutex_*` | `SRWLOCK` + `Acquire/ReleaseSRWLockExclusive` |
| `cetra_cond_t` / init destroy wait signal broadcast | `pthread_cond_*` | `CONDITION_VARIABLE` + `SleepConditionVariableSRW` / `Wake*` |
| `cetra_sleep_ms` | `nanosleep` | `Sleep` |

`SRWLOCK`/`CONDITION_VARIABLE` over `CRITICAL_SECTION` (lightweight; destroy becomes a no-op).
`_beginthreadex`, not `CreateThread`, so the CRT initialises per-thread state. The shim absorbs two
mismatches: the worker entry is `void*(void*)` (`async_loader.c:200`) vs Win32's `unsigned __stdcall`,
and the code tests `!= 0` for init/create failure.

**This also removes `pthread_t` from the public header** — which is the real fix for risk #1, and the
reason not to paper over it with vcpkg's `pthreads4w` port.

**Files:** `async_loader.h` (5 members), `async_loader.c` (44 sites), `texture.h` (1), `texture.c` (8),
`probe.c:94-95` (the one `nanosleep`), `cetra/CMakeLists.txt:67`.

**Already portable, not in scope:** the 17 C11 atomics (MSVC ≥ VS2022 17.5), `get_cpu_cores()`
(`util.c:128-154`, already `_WIN32`-aware), and stb's thread-local flip flag (already has an MSVC path).

## Workstream 2 — Paths, filesystem, libc

**Pick one internal representation and enforce it.** Windows file APIs accept forward slashes, so keep
the engine forward-slashed and call `cwk_path_set_style(CWK_STYLE_UNIX)` explicitly at engine init.
That kills the cwalk landmine at the root and preserves every `'/'`-scanning code path, instead of
scattering `#ifdef`s.

Then fix the boundary, where Assimp returns backslashed FBX/OBJ paths:

- **`convert_windows_path_to_unix` (`util.c:278-301`) strips the drive letter** (`C:\...` →
  root-relative). Harmless on macOS, actively wrong on Windows. Preserve the drive there.
- Replace the **12 hand-rolled `/` operations** with the cwalk equivalents already compiled in and
  bypassed: `util.c:253` (join), `util.c:266` (split), `import.c:55` (dirname), `import.c:1406`
  (basename), `cscene.c:19` (is-absolute — currently `path[0] == '/'`, which misses `C:\`),
  `cscene.c:22` (join), `cscene.c:304` (dirname).

**Filesystem — 3 sites, all in `path_exists` (`util.c:199-218`).** `lstat` + `S_ISLNK` + `stat`. MSVC
has `_stat` but neither of the others. Add a `_WIN32` branch using `GetFileAttributesW` (test
`FILE_ATTRIBUTE_REPARSE_POINT`), following the pattern `get_cpu_cores()` already set in this file.

**libc gaps.** Split by fix type:
- `strdup` (~18 files) → **`safe_strdup` already exists** (`util.c:110`); use it. Fixes portability and
  an existing inconsistency at once.
- `M_PI` (6 files) → covered by the `_USE_MATH_DEFINES` compile definition (Workstream 3).
- `strcasecmp` ×10 / `strncasecmp` ×1 → needs a small source shim (`compat.h`) mapping to
  `_stricmp`/`_strnicmp`. Not solvable from the build system.
- Drop `<strings.h>` (`import.c:2`, `cscene.c:4`) and the duplicate `<unistd.h>` (`util.c:15,17`).

## Workstream 3 — Build system

The spine is **one `INTERFACE` target, `cetra_deps`**, populated by exactly one of two discovery
blocks, so `target_link_libraries(cetra PUBLIC cetra_deps)` appears **once** and the raw-name lists at
`cetra/CMakeLists.txt:60-97` disappear. A sibling `cetra_warnings` carries per-compiler flags.

**Discovery.** A `CETRA_DEP_PROVIDER` cache variable (`auto|pkgconfig|cmake`) rather than a raw
`if(WIN32)` — so the vcpkg path can be tested *on macOS* before the VM exists. pkg-config branch uses
`pkg_check_modules(... IMPORTED_TARGET GLOBAL ...)` → `PkgConfig::GLFW` etc. `GLOBAL` is mandatory
(imported targets are directory-scoped; `cetra_deps` is consumed from subdirectories). This
**structurally fixes the `_LIBRARY_DIRS` bug** — the imported target carries link dirs. vcpkg branch:
`find_package` → `glfw`, `GLEW::GLEW`, `assimp::assimp`, `cglm::cglm`.

**The highest-value single change:** make deps `PUBLIC` on `cetra` and **delete the global
`include_directories`/`link_directories` at root `:29-30`**. Today `engine.h:5-7` publicly includes
`<GL/glew.h>`, `<GLFW/glfw3.h>`, `<cglm/cglm.h>` while those includes are `PRIVATE` — apps compile
only because Homebrew's prefix is on every target's path. Deleting it turns the leak into a compile
error, which is the point. Strictly more correct on macOS too.

**Symlink replacement.** `file(CREATE_LINK ... SYMBOLIC)` (`cetra/CMakeLists.txt:5-12`) needs Developer
Mode on Windows and is load-bearing for 91 include lines across all 7 apps. Replace with a
configure-time tree of **one-line forwarding headers** via `file(CONFIGURE)`: `#include "<abs path to
real header>"`. Quoted includes resolve relative to the *real* header's directory, so nested includes
keep working with no extra `-I`; edits propagate instantly; `file(CONFIGURE)` only rewrites on change.
Must be recursive over `src/`, `src/game/`, `src/ext/` (non-recursively — skip JoltC/cimgui).

**Shader generation.** `find_package(Python3 COMPONENTS Interpreter)` → `${Python3_EXECUTABLE}`; bare
`python3` on Windows commonly hits the Store stub that exits 9009 with an empty header. Rename target
`shaders` → `cetra_shaders`. Move output into the generated include tree.
**Non-negotiable guard:** a leftover `cetra/src/shader_strings.h` will silently shadow the generated
one (quoted include searches the including file's dir first) for `shader.h`/`ibl.c` but not
`render.c` — half the program with stale shaders. It's gitignored, so *every existing checkout has
one*. Add a configure-time `FATAL_ERROR` if it exists, and drop `.gitignore:7`.

**Compiler flags.** For clang-cl, `MSVC` is TRUE while `CMAKE_C_COMPILER_ID` is `Clang` — branch on
`MSVC` as the umbrella, not on compiler ID, or GNU flags get fed to a `/`-style driver. Replace
`-Wall -g` with `/W4` + selective `/wd` on MSVC, `-Wall -Wextra` otherwise. **Drop `-g` entirely** —
it was always redundant with `CMAKE_BUILD_TYPE`. Set
`CMAKE_MSVC_DEBUG_INFORMATION_FORMAT` to `Embedded` (`/Z7`), not `/Zi`: with Ninja, concurrent writes
to a shared `.pdb` are a known source of flaky failures. Requires `CMP0141 NEW`.

**Vendored-dep forcing (before `add_subdirectory(JoltC)`):**
- `USE_STATIC_MSVC_RUNTIME_LIBRARY OFF` + `CMAKE_MSVC_RUNTIME_LIBRARY` dynamic → resolves the
  **`/MT` vs `/MD` mismatch** (Jolt forces static, everything else defaults dynamic — a guaranteed
  `LNK2038`). Triplet `x64-windows-static-md`: static deps, dynamic CRT, no DLLs to deploy beside
  `out/bin/*.exe` (which matters because apps are launched from the repo root with cwd-relative assets).
- `ENABLE_ALL_WARNINGS OFF` — Jolt's MSVC branch is `/Wall /WX`, which clang-cl maps to
  `-Weverything -Werror`. Will fail the build.
- `INTERPROCEDURAL_OPTIMIZATION OFF` — clang-cl LTO emits bitcode `.lib`s that `link.exe` can't consume.
- **`USE_AVX2`/`USE_F16C`/`USE_FMADD`/`USE_LZCNT`/`USE_TZCNT` OFF** — these default ON, and QEMU's
  default CPU model doesn't expose them. **Manifests as `SIGILL` at the first physics tick, not at
  build time.** Alternatively set `-cpu host` in the guest. Keep SSE4.1/4.2.

**cimgui.** Must use the **plain** `target_link_libraries` form (`target_link_libraries(cimgui
cetra_deps)`) — cimgui's own CMakeLists uses the plain signature, and CMake hard-errors on mixing.
On Windows, filter-and-replace its `PUBLIC IMGUI_IMPL_API=...__declspec(dllexport)` (it exports even
in the static config we force).

**`_POSIX_C_SOURCE`** → `$<$<PLATFORM_ID:Linux>:_POSIX_C_SOURCE=200809L>`. Linux-only, not
"not-Windows": it's actively counterproductive on macOS (it's *why* `util.c:7` has to re-enable
`_DARWIN_C_SOURCE`), and removing it there only widens declaration visibility.

**`CMakePresets.json`** — `macos-debug/release`, `linux-debug`, `windows-debug/release` (clang-cl,
vcpkg toolchain, `x64-windows-static-md`), with `hostSystemName` conditions.
**Keep `macos-debug` at `binaryDir = ${sourceDir}/out`** so `out/bin/<app>` — which AGENTS.md and all
muscle memory depend on — is preserved. `build.sh` becomes an argument translator over presets,
keeping the submodule bootstrap and replacing the direct `ninja -C out` call with
`cmake --build --preset`.

**`vcpkg.json`** at repo root: glfw3, glew, cglm, assimp, pinned by `builtin-baseline` (a real 40-char
`microsoft/vcpkg` SHA). That's the determinism Homebrew doesn't give — assimp moved 6.0.2 → 6.0.5
under this build today with nothing noticing. Expect a long first configure; assimp's default feature
closure is large.

## Workstream 4 — Windows VM

Windows 11 KVM guest. Install **VS Build Tools** (needed for the Windows SDK and MSVC headers/libs
*even with clang-cl*), **LLVM/clang-cl**, **Ninja**, **CMake**, **Python 3**, **vcpkg**, **git**.
Snapshot once working — that image is the reproducibility boundary for the pinned-toolchain layer.

**Configure and build must run from an x64 Native Tools prompt** (or after `Enter-VsDevShell`). CMake
can find `clang-cl.exe` but cannot synthesize the SDK's `INCLUDE`/`LIB` paths, and presets have no
mechanism for it. This is the most common first-day failure with clang-cl + Ninja.

Set `-cpu host` in the guest config if you'd rather keep Jolt's AVX2 path.

---

## Implementation order

**Steps 1-6 are pure macOS refactors with zero Windows content** — deliberately, so any regression is
caught while the change is small. Each must build clean on macOS before the next.

1. `CMakePresets.json` + `build.sh` delegation. No logic change; verify `out/bin/*` unchanged.
2. `cetra_warnings`, drop `-g`.
3. **`cetra_deps` (pkg-config path only), deps go PUBLIC, delete global include/link dirs, delete the
   stale `X11 GL ncurses` block.** Highest-risk macOS step — the include leak closing surfaces real
   errors. Do it alone.
4. Header shim tree replacing `CREATE_LINK`; drop `apps/CMakeLists.txt:10-12`. Verify all 7 apps.
5. Shader gen: `Python3_EXECUTABLE`, rename target, move output, add the stale-file guard.
6. Scope `_POSIX_C_SOURCE` to Linux.
7. **Workstreams 1 + 2** (thread shim, paths, libc shim) — still verifiable entirely on macOS.
8. `vcpkg.json` + toolchain bootstrap + provider switch. Test with `-DCETRA_DEP_PROVIDER=cmake` **on
   macOS** first to shake out target-name mistakes without the VM.
9. Jolt/cimgui Windows forcing block. Inert on macOS.
10. Windows presets, first configure in the guest, iterate.

## Verification

**macOS must not regress — the gate on every step.** The harness already exists:

1. `./build.sh` clean, no new warnings.
2. `./out/bin/render assets/abandoned_window/abandoned_window.cscn --headless --frames 2` — compare
   against the current ~4.7s and pixel-diff a screenshot. **The measured run-to-run noise floor is
   0.79% RMSE**; under that is indistinguishable, well above it is a real change.
3. **`./out/bin/render -m assets/parallax_fixture.gltf --headless --frames 30`** — *the* regression
   test for Workstream 2. The only fixture with external file textures, so it exercises
   `convert_and_normalize_path` → `find_existing_subpath`: exactly the path the cwalk landmine breaks.
   Also confirms aliased slots still share one decode and POM height resolution still runs.
4. `./out/bin/render -m assets/c64.fbx --headless --frames 30` — textures deliberately missing, so it
   exercises the *failure* paths through path resolution and the async loader without hanging.
5. All 7 apps at least link (step 3 and 4 can break apps without touching the library).

**Windows, once the VM is up:** the same commands. Milestone is `render --headless` producing an
`abandoned_window` screenshot matching the macOS capture within the noise floor. Missing or scrambled
textures mean the path work is incomplete — which is why step 3 matters far more than "it compiled".

## Top risks

| Risk | Why it bites | Mitigation |
|---|---|---|
| `pthread_t` in public `async_loader.h` | No build-system fix exists | Workstream 1 shim (not vcpkg pthreads4w) |
| Stale `src/shader_strings.h` shadows generated one | Quoted include prefers the including file's dir; every checkout has one | Configure-time `FATAL_ERROR` |
| clang-cl + Ninja without VS dev environment | CMake can't synthesize SDK paths | Document the Native Tools prompt |
| Jolt `/Wall /WX` under clang-cl | Becomes `-Weverything -Werror` | Force `ENABLE_ALL_WARNINGS OFF` |
| Jolt AVX2 in a KVM guest | `SIGILL` at first physics tick, *not* a build error | Force ISA options OFF, or `-cpu host` |
| Deleting global Homebrew include dirs | Masks the PUBLIC/PRIVATE leak; something may depend on it | Isolated commit, build all 7 apps |
| cimgui plain-vs-keyword `target_link_libraries` | Hard CMake error | Plain form for cimgui only |

## Explicitly out of scope

- **Asset path resolution for packaging.** Assets are entirely cwd-relative with no resolution seam;
  `splash.c:21` and `shapes.c:25-26` bake source-tree-relative literals into binaries. Blocks a `.app`
  bundle or Windows install dir, but that's packaging, not portability.
- CI, installers, code signing, notarization, Steamworks.
- Raising the GL 4.1 ceiling (a macOS constraint that need not bind Windows).
- Unifying `C_EXTENSIONS` (gnu11 on Unix vs `/std:c11` on Windows) — changing macOS's dialect risks
  regressions for no Windows benefit.
