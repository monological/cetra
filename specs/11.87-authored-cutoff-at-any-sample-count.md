# Spec 11.87 — the authored cutoff, at any sample count

## Context

An alpha-masked material renders a **different silhouette at 1 sample than at 4**.

`pbr_frag.glsl:396`:

```glsl
return a < (alphaToCoverage > 0 ? A2C_MIN_ALPHA : alphaCutoff);
```

`A2C_MIN_ALPHA` is 0.02; both leaf materials in this tree author `alphaCutoff` 0.4. Under MSAA
the authored cutoff is discarded and the sprite's whole soft alpha falloff — a band around every
leaf that the single-sample path deletes — shades and contributes coverage. On `apps/tree`'s
backlit sunset it reads as a bright orange outline on every leaf against the dark sea.

**Measured on `apps/tree`, default view, 640x400, against a 0 px floor:**

| test | rim px | brighter than the local max |
|---|---|---|
| stock, 4x MSAA | 14,618 | 5,223 |
| **alpha-to-coverage off**, still 4x MSAA | 6,235 | **1,187** (−77%), visually gone |
| `centroid` on Normal / TexCoords / TBN | 14,564 | 5,114 (**no effect**) |
| sun 0.8° → 40° | — | 35.7% → 16.0% |

The centroid result **falsifies varying extrapolation**, which was the first diagnosis and the
one `--render-mode 12` appears to support. That correlation is coincidental.

**This is a known consequence, not a discovery.** `render.c:404-407` says it outright — "with it
on everywhere `alphaCutoff` is meaningless, since only `A2C_MIN_ALPHA` is ever compared against"
— and spec 11.31:438 defers the remedy to hashed alpha testing. What neither anticipated is that
the *shadow* disagrees too: `shadow_depth_frag.glsl:48` tests the authored cutoff unconditionally
(shadow maps are single-sampled), so under MSAA **a leaf is drawn at 0.02 and its own shadow cast
at 0.4**. The leaf and its shadow are different shapes.

**The bug in one sentence: the 0.02 is in the wrong space.** `water_frag.glsl:979` uses 0.02 as a
floor on **coverage** after a remap; `pbr_frag` uses it to threshold **raw alpha** before any
remap. Discarding a 2%-covered pixel is right; thresholding at 2% alpha renders the whole
falloff.

## The two fixes, and why both

**Sharpening fixes the transition's WIDTH. Mip coverage preservation fixes its POSITION.** They
are orthogonal and this spec does both.

### The rule is already in this engine

`water_frag.glsl:971-978` implements exactly what is wanted, today:

```glsl
float edge = signedPath - WATER_MIN_PATH;
coverage = clamp(edge / max(fwidth(edge), 1e-5) + 0.5, 0.0, 1.0);
...
if (alphaToCoverage == 0)
    coverage = step(0.0, edge);
```

Both branches cross at `edge == 0`, so the silhouette is **identical at any sample count by
construction**. That is the property the masked path lacks. This applies water's own rule rather
than importing a technique — though it is also the standard answer (Golus, *Anti-aliased Alpha
Test*; Unity's alpha-to-mask sharpening): dividing distance-to-threshold by `fwidth` expresses it
in PIXELS, so the band is one pixel wide whatever the texture's falloff looks like.

### Coverage preservation is newly possible

Spec 11.85 moved mip generation off `glGenerateMipmap` onto a CPU chain. Castaño's rescale
(Unity's "Mip Maps Preserve Coverage") could not have been done before.

## Phases

Branch `11.87-authored-cutoff-at-any-sample-count` off master; spec committed alone first.

### 1. The arm that fails on master

**No new fixture is needed.** `assets/mask_fixture.cscn` already carries an opaque reference, a
MASK quad at alpha 0.6, one at **0.2 — below the 0.4 cutoff** — and a backdrop. And
`apps/render` parses `--msaa`, applying it *after* the TAA policy (`render.c:4119-4122`), so
`--msaa 1` against `--msaa 4` varies exactly one thing.

Add `mask-samples` to `run_mask_gate`: `_box_luma(MASK_GONE_BOX)` must stay under
`MASK_GONE_CEIL` at **both** sample counts, with the existing `MASK_LIT_FLOOR` liveness guard on
the kept and reference boxes so a failed load cannot satisfy an "absent" assertion. `run_sss_tag_gate`
is the template — it already renders the same scene at 4 and 1 and asserts a defect present at one
and absent at the other.

**On master this fails**: 0.2 > 0.02, so the below-cutoff quad survives at 4 samples. Record the
reading. Do NOT use `--taa` for the 1-sample leg — it changes three things at once.

Two stale claims to fix here, both of which are why this was unreachable:
`gen_mask_fixture.py:34-39` still says "Deliberately NOT a golden" (it is one), and
`run_mask_gate`'s docstring declares the 1-vs-4 divergence wholly legitimate. It is legitimate in
*kind* (coverage dither) and not in *magnitude* (a quad below the authored cutoff appearing at all).

### 2. One rule, one include

New `cetra/shaders/include/alpha_coverage.glsl`, shaped like water's:

```glsl
// Coverage from a masked alpha: one pixel wide, centred on the AUTHORED cutoff.
// Without a2c this is the binary test, and both cross at a == cutoff, so the
// silhouette does not depend on the sample count.
float alphaMaskCoverage(float a, float cutoff, int a2c) {
    if (a2c == 0)
        return step(cutoff, a);
    return clamp((a - cutoff) / max(fwidth(a), 1e-4) + 0.5, 0.0, 1.0);
}
```

**One edit site in `pbr_frag.glsl`** — between `:1103` and `:1106`, rewriting `texAlpha` in
place. That propagates to the discard (`:1106`), `coverage` (`:1292`), `finalOpacity` (`:1536`)
and every A2C alpha write, and is upstream of **both** prepass exits (`:1192`, `:1565`) and the
moment exit (`:1547`). It must stay above `:1192` or the binary prepass and the shading pass
disagree and `GL_LEQUAL` deletes the samples they differ on.

**Gate it on `alphaMasked > 0`.** `finalOpacity` also feeds the OIT moments and accumulate for
ALPHA_BLEND materials, which must be untouched.

`A2C_MIN_ALPHA` becomes a floor on the returned COVERAGE — the 0.02 moves into the space water
already keeps it in.

`shadow_depth_frag.glsl:48` takes the `a2c == 0` branch (0 px by construction, since
`alpha < cutoff` and `step(cutoff, alpha)` are the same test) so the rule is stated once and the
camera silhouette comes to match the shadow's rather than the reverse.

**Derivative safety holds**: every branch enclosing the alpha fetch is on a `uniform int`, so
`fwidth` is legal there. One asterisk worth a comment — a POM'd masked material would have a
fragment-varying `discard` upstream at `:1009`; no such material exists in-repo (only `bark` has
a height map, and it is opaque).

**Prepass consistency is automatic and needs no work**: `depth_prepass_frag.glsl` is empty and
masked geometry is prepassed by *its own pbr program* in depth-only mode (`render.c:916-943`), so
both passes run this code.

### 3. Mip alpha coverage preservation

`TextureDesc` gains `float coverage_cutoff` — **0 means off, which is a safe zero**, so not one
existing call site changes.

`import.c` is already correctly ordered: `extract_material_properties` reads the cutoff at `:654`,
*before* the texture loop at `:668`, so `desc.coverage_cutoff = material->alphaCutoff` for an
`ALPHA_MASK` albedo is a two-line change. `apps/tree` and `apps/forest` bake their atlases before
their materials exist, so each shares one constant between the bake and the material rather than
repeating 0.4.

The hook is **`texture.c:549`**, between `texture_box_halve` and either upload — the only correct
position, since `texture_upload_compressed_level` encodes and uploads in one step and nothing
decodes. Measure the reference coverage once from level 0 before the loop; per level,
binary-search a scale `k` so `fraction(alpha*k > cutoff)` matches it, and apply in place.

Three things to get right:
- **Alpha is already averaged as stored, not through the sRGB LUT** (`texture.c:302`,
  `:287-288`), which is exactly what a coverage search needs.
- **The dilate must precede the rescale** and already does on all three producers. Its solidity
  seed is `alpha >= 8/255`; scaling alpha up first would promote garbage-RGB texels into colour
  *sources*. Worth a comment at the hook, because the constraint is invisible from the three
  files that invoke the dilate.
- **`proc_leaf_sprite` is excluded**: it goes to the billboard renderer, whose shader is
  premultiplied-alpha blending with a 0.02 degenerate reject, not an alpha test. Rescaling it
  would change density with no silhouette to preserve.

The pool keys on PATH, so two materials sharing one image at different cutoffs get the first
one's chain. Store the baked cutoff on `Texture` and warn by name, exactly as the existing
`is_srgb` mismatch warning does (`texture.c:1049-1054`) — and unlike `is_srgb` it is not
recoverable from the internal format, which is why it has to be stored.

Beneficiaries are three textures: tree's leaf atlas (4096x512, 13 levels), forest's (2048x256,
12) and `ivy_leaf_base.png` (219x424, 10). All three have a genuinely soft ~1-texel edge.

### 4. Measure, and re-bake deliberately

**`mask_fixture`'s golden currently BAKES the defect** — it is the only golden rendering visible
MASK geometry, it renders at 4 samples, and its 0.2-alpha quad survives. It will move, and that
movement is the fix. Re-bake with the number recorded.

Re-measure the tree rim with the same script: `rim px` and "brighter than the local max" should
collapse toward the alpha-to-coverage-off readings (6,235 / 1,187). Measure `apps/forest`, and
raiden's groom (ALPHA_MASK at glTF's default 0.5), whose look will change.

Full `gates.py` + `goldens.py`. AGENTS.md's masked-geometry paragraph; a roadmap row, since
anti-aliased alpha test is booked nowhere and E6 only mentions the prepass/A2C interaction in

## Verification

- **Noise floor first** at every framing. `apps/tree --player` is 0 px; its orbit path is 0 px at
  640x400/30 frames, which AGENTS.md's 31,034 px figure does not predict.
- **`mask-samples` fails on master** and passes after phase 2. Falsified by restoring
  `A2C_MIN_ALPHA`.
- **Phase 2 must be 0 px at `--msaa 1`** on every golden — the single-sample path takes the
  `step` branch and is unchanged by construction. Anything that moves there is a defect in the
  change. `mask_fixture` is the one golden expected to move at 4.
- **Phase 3 must be 0 px on every texture whose material is not ALPHA_MASK**, since
  `coverage_cutoff` 0 skips it.
- Coverage arms must be **bounded, not equated**, under `--texture-compress-colour`: DXT5's alpha
  is a lossy BC4 block applied after the rescale. Colour compression is off by default, so the
  default path gets an exact rescale.
- `./build.sh` throughout; full suite + goldens at the end.

## Said out loud

- **This is an M**, and phase 3 is the larger half — it plumbs a material property into a
  deliberately material-agnostic loader, a boundary this repo has defended before.
- **The look changes on purpose.** Every masked material's MSAA silhouette becomes the one it
  authored, so leaves get *thinner* than they render today. If that reads as too sparse the
  answer is the leaf material's cutoff, not the coverage rule.
- **`--msaa 1` frames must not move at all**, which is the strongest available check that this
  is a unification rather than a new behaviour.
- **Only two authored masked materials exist in-repo** — tree's and forest's leaves, both at 0.4
  — plus glTF imports (`mask_fixture` 0.4, `ivy_arcade` 0.4, raiden's groom at the 0.5 default).
  Grass is a terrain splat layer, not cutout geometry.
- Rejected: hashed alpha testing (Wyman & McGuire 2017), which spec 11.31 deferred to, and
  Unreal's dithered opacity + TAA. Both are legitimate and both *replace* the masked path;
  A2C is already here and is one line from correct.
