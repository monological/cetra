# 11.72 — one chain for the environment, and the clouds a restore silently dropped

## Context

`gui.c` carries a file-static `_sky_release_rebake`, and its comment says what it is:

> The one "environment changed on release" chain, shared by the sun sliders and the cloud
> controls **so the downstream consumers cannot drift apart**

It does three things: re-bakes the env cube **with the cloud deck** when there is one, refreshes an
environment-only reflection probe, and re-arms the GI volume.

Spec 11.71's config restore is a second caller of that idea and does not use it. It calls bare
`sky_update_sun`, which is `sky_update_sun_dir` + `sky_bake` + `sky_apply_sun_to_light` — and
`sky_bake` is `sky_bake_ex(..., false)`. So a restored sun does not merely skip the deck, it
**strips the deck out of an env cube that had it**, refreshes no probe, and re-arms no GI. Every
`sky.clouds.*` row is a plain store with no hook at all, so restoring a cloud change re-derives
nothing.

That is the failure this codebase already records against `punctualAngular`: a comment claiming all
callers go through one place while one of them does not, so the next reader trusts the comment and
edits one site.

**And it compounds into a silent defect.** `--clouds` is not in the snapshot's `source` block, and
`sky_bake_cloud_noise` early-outs on `!clouds.enabled`. So `render --config s.json` on a snapshot
taken with `--sky --clouds`:

- startup bakes no cloud noise, and bakes the env cube without a deck;
- the restore stores `clouds.enabled = true`;
- `sky_clouds_march` refuses on `!noise_baked`, `cloud_shadow_terms` refuses, the GUI cloud panel
  never appears — a clear sky;
- `--config-dump` then writes `enabled: true` straight back out, so **`config-roundtrip`'s
  byte-identity assertion passes on a restore that produced the wrong frame.**

No arm can see it: the config fixture is `cornell_rooms` (no sky) and `config-sun` runs
`layer_fixture --sky` with clouds off.

## The fix

**Promote the chain out of `gui.c`.** Not to `sky.c` — `sky_bake_ex` takes `IBLResources*` and
`Engine*` and deliberately does not know `Scene`, while the chain touches `scene->ibl`,
`scene->probe_set` and `scene->gi_volume`. It goes to `scene.c`, beside the other three-subsystem
coordination that file already owns:

```c
// scene.h
// The one "the environment changed" chain: re-bake the env with the deck when
// there is one, refresh probes that only mirror the sky, re-arm the GI sweep.
void scene_environment_changed(Scene* scene, struct Engine* engine);
```

`gui.c`'s two call sites become calls to it. `config_snapshot_apply_file` calls it too, which is
what makes the claim in its comment true for the first time.

**Cloud rows get a hook**, mirroring `_apply_sun_angle`: store, then flag `env_changed` **on an
actual change**, so the common restore-onto-itself case pays no bake and no probe re-capture.

**`clouds` joins the `source` block**, so a restore can arm the noise bake at startup rather than
storing a flag nothing can honour. And `sky.clouds.enabled` **refuses by name** when the noise was
never baked, in the IES refusal idiom, rather than silently rendering a clear sky.

## Gates

New arm `config-clouds` on `layer_fixture --sky --clouds`: dump, restore with `--config` alone,
compare against the flag leg; plus the negative half — a restore whose session has no cloud noise
must WARN rather than store a flag nothing honours.

Must stay green: **config** (10 arms), **gate-docs**, and `goldens.py` — the chain moves but no
default path changes, so all 27 stay 0 px.

## Falsification

| mutation | arm that must fail |
|---|---|
| restore calls bare `sky_update_sun` again | `config-clouds` |
| cloud rows lose their hook | `config-clouds` |
| `clouds` dropped from the `source` block | `config-clouds` (negative half) |
| the refusal removed | `config-clouds` (negative half) |
