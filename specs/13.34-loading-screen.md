# Spec 13.34 -- the CETRA loading screen

## Context
Silent is slow to start, and the window gives nothing back while it loads:
- **`on_init` (seconds).** It runs synchronously (`game.c:342`) after `create_engine` has already
  shown the window (`engine.c:600`). Nothing polls events or swaps, so the window shows garbage
  and macOS beachballs.
- **Settling (seconds more).** `engine_run` starts and the view is held black (`grade_gain` 0,
  `silent.c:955-962`) until the lighting round the eye is captured (`lit`, `silent.c:945`), then
  fades in over 1 s.

The user wants the ENGINE's own loading screen over both stretches: CETRA on top and ENGINE
underneath, each CETRA letter rotating in and then ENGINE appearing, 70s colours, a strong CRT.
The references are a station ident or film logo on a worn tape: phosphor glow, a visible mask,
chroma bleed, tracking noise. This is a first pass to see the look.

The user's question gets a yes: it is in the engine, as API calls. It is the engine's mark, so
any cetra game gets it with three calls.

It is a new design and does not use `apps/splash`, a demo of a pixel font under a plasma effect.

It replaces the 13.34 sketch in the 13.32 spec:
- **What it drops:** the load-step table, the general "settled" call and the `-f` offset.
- **Draw calls at the seams replace the step table.** `on_init` stays one function, and the kits
  need no statics.
- **Silent's own `lit` test** says when to lift.

## The API -- `cetra/src/loading_screen.h` (public; add it to `CETRA_PUBLIC_HEADERS`)
```c
void engine_show_loading_screen(Engine* engine);   // from now on the window shows it
void engine_draw_loading_screen(Engine* engine);   // before engine_run: draw it now, answer the window
void engine_hide_loading_screen(Engine* engine);   // lift once the ident has played
bool engine_loading_screen_shown(const Engine* engine); // true until the switch-off finishes
```
- **Engine fields:**
  - `LoadingScreen* loading_screen`, ENGINE-OWNED: made on first show, freed in `free_engine`.
  - `int loading_palette`, a SETTING: 0 is the default.
- **Inside a frame:** `engine_present_frame` draws it while it is shown, after the CRT or present
  pass has written the window (`engine.c:2425-2426`) and before the GUI. So the screenshot path
  (`_save_framebuffer_ppm`, FB0's back buffer) captures it, and the debug GUI stays on top.
- **`engine_draw_loading_screen` outside a frame:**
  - It polls events and draws into FB0 at the framebuffer size.
  - It swaps at swap interval 0 and then puts back the engine's vsync, so a draw never waits on
    the display.
  - It draws at most 60 times a second, so an app may call it as often as it likes, including
    inside loops.
  - Inside `engine_run` it does nothing, since the frame draws the screen; a flag set by the
    loop tells the two apart.
  - It leaves FB0, the viewport, program 0 and VAO 0 bound, through `gl_pass_begin`/`gl_pass_end`.
- **The clock:**
  - Windowed, each draw advances it by the real elapsed time, capped at 0.1 s, so a long stall
    pauses the animation rather than skipping it.
  - Headless, it takes the engine's fixed dt, so captured frames are exact.
- **Hiding is a request.** The screen lifts only once the ident has finished (about 3 s), then
  switches off over 0.4 s. `shown` stays true until that ends.

## The look (first pass)
Two passes and the CRT, at half the framebuffer size:
1. `loading_logo_frag.glsl` draws the mark.
2. `loading_tape_frag.glsl` wears it like tape.
3. A CRT of the screen's own (`create_crt`/`crt_present`, unchanged) shows it in the window.
   The picture is display-encoded, as the CRT expects (`displayEncode`).

**The letterforms** are designed, not typed:
- **Skeletons.** Each letter is a monoline skeleton of segments and arcs, as a GLSL table:
  - C: an arc open on the right.
  - E: the round 70s E, an arc plus a bar.
  - T.
  - R: a stem, a bowl and a leg.
  - A: a triangle with a low bar.
  - N, G and I, for ENGINE.
- **Stroke.** The stroke is a tube round the skeleton. Its colour comes from bands of the
  distance to the skeleton: concentric stripes (cream core, mustard, orange, red, brown edge),
  which merge cleanly where strokes join.
- **Block shadow.** A 70s block shadow runs down and to the right in the darkest colour: the
  same distance taken along an offset, six taps.
- **Glow.** A phosphor glow comes from the same distance.
- **ENGINE.** The same alphabet with a thinner stroke, in cream, spaced to CETRA's width.

**The ident timeline** (seconds; each value is a constant to tune):
- **0.0-0.5:** switch-on. A bright line opens to the full picture over static.
- **0.5-2.0:** C, E, T, R, A flip in about their vertical axes, 0.18 s apart.
  - Each is a damped spring from 180 degrees to 0. The back face is drawn dark, like a card.
  - Real perspective: each pixel's ray meets each letter's rotated plane.
- **2.1-2.6:** ENGINE's letters light one by one, each a phosphor flash settling.
- **2.6-3.0:** a four-colour stripe rule draws out from the centre beneath ENGINE.
- **Hold:** a light sweeps back and forth along the rule, which is the "still loading" sign. The
  glow breathes, and a short tracking glitch comes every few seconds, deterministic from time.
- **Switch-off on lift:** the picture collapses to a line, the line to a dot, and the dot fades.

**The tape pass:**
- R and B offset horizontally;
- a rolling tracking band that shears the lines and brightens the noise;
- small per-line jitter;
- the head-switching tear at the bottom edge;
- static from `frameNoise` (`include/noise.glsl`);
- a warm vignette.

**The CRT** is stronger than the game's: 240 lines, scanlines 0.7, mask 0.6, curvature 0.6,
bleed 0.8. Values are checked against `crt.c`'s ranges when written.

**Palettes** are a table indexed by `loading_palette`, so the look can be played with. Each is a
background plus five stripe colours:
- 0 sunset (default): `#140A06` behind `#F4E4BC` `#F0B23A` `#E5702A` `#B83A26` `#5C2E1C`.
- 1 harvest: avocado, harvest gold, burnt orange, chocolate.
- 2 phosphor: green, as in the first reference.
- 3 broadcast: blue, violet and cream, as in the Fox references.

## Phases
**Phase 0 -- measure silent's startup.**
- Time each `on_init` step with `startup-ms` lines (forest's pattern, `forest.c:312-321`),
  windowed.
- Also time frame 0 and the frames to `lit`.
- The gaps say where the draw calls go, and whether any single step is too long to reach.

**Phase 1 -- the look and the API.**
- **New files:**
  - `cetra/src/loading_screen.c/h`;
  - the two shaders;
  - their constructors in `program.c/h`, beside the CRT's (`create_post_program`).
- **`engine.c/h`:** the fields, the present hook and the free.
- **Preview in the render app:** `--loading-screen` shows it and never hides it, and
  `--loading-palette N` picks a palette.
  - Windowed: number keys switch palette and a free key replays it, so it can be played with
    live.
  - Headless: `render -m assets/scenes/cornell_box.cscn --loading-screen -x -f 240 -S
    <scratch>/ls.ppm --screenshot-every 12` gives a frame-exact strip.
- **The user looks:**
  - a contact sheet of the strip for each palette, opened with `open -a Preview`;
  - the command to run it windowed from the worktree.
  Changes to the look go in here, before phase 2.

**Phase 2 -- silent loads through it.**
- **`on_init` shows it** first, only when windowed and not `--no-loading-screen`.
- **Draw calls.** `on_init` calls `engine_draw_loading_screen` after each of its steps (about 15
  seams), and inside the long loops phase 0 finds. Goal: no gap the app can reach over about
  0.25 s.
- **`on_pre_render`:**
  - When `lit` first holds, hide the screen.
  - The fade, and the drop to the play capture budget, start when
    `lit && !engine_loading_screen_shown(engine)`.
- **Input.** While the screen is up, player input is suppressed (`input_set_suppressed`), so
  nobody walks blind.
- **Headless silent is unchanged:** no screen, the same frames as master.
- **`LOADING_CAPTURE_MS` sets how smooth the screen is while settling.** Measure the screen's
  frame rate and the time to `lit` at 100 ms and at about 33 ms, and give the user the trade.
- **The user launches it windowed:**
  - the screen from the first moment, with no beachball;
  - the ident;
  - the lift into the fade.
- **For the user's ear:** whether silent's rain and wind should be held silent under the screen.

**Phase 3 -- docs and as-built.**
- AGENTS.md:
  - a Key Files row for `loading_screen.c/h`;
  - the shader inventory;
  - a line in step 10 of the frame;
  - silent's row.
- `docs/cli-reference.md`:
  - render: `--loading-screen` and `--loading-palette`;
  - silent: `--no-loading-screen`.
- The spec's as-built: phase 0's timings and the gaps left after phase 2. Frame 0's stall is one
  of them, since the variant compiles and tile placement sit inside a single engine frame.

## As built

### Phase 0 -- silent's startup (master `07a86cde`, headless, `--capture-budget-ms 100`)
Measured headless, with the windowed loading budget pinned, from `startup-ms` rows: each
`load_seam` in `on_init` prints the time since the one before, and the held frames print their own.

| Stretch | ms | |
|---|---|---|
| `on_init` | about 3,500 | materials 967, cat 834, audio 792, `kit_finish` world 180, doors and prompt 142, every other step under 100 |
| frame 0 | 2,072 | lit-surface variants compiled and every cached tile placed, in one frame |
| frames 1-2 | 118, 173 | |
| to `lit` | 33,204 | 154 frames, the slowest 405 ms |

The profiler over the first 150 frames: 169 ms a frame on average, of which GI capture is about
103 ms (the 100 ms budget and its last unit's overrun) and the game's own frame about 60 ms --
opaque 27.6 ms GPU, atmosphere 5.8, SSS 5.2, the moving shadows 4.9, SSR 2.4. Its picture is held
black the whole while.

**What it changes.** A screen drawn once a frame would move about five times a second while the
game settles, and stand still for up to a second at a time in `on_init` and for two in frame 0.
So phase 2 draws it from where the time goes:
- inside the engine, between capture units and between variant compiles, wherever 16 ms have
  passed since the last draw;
- inside silent's three slow steps (materials, cat, audio), as well as at the seams;
- and while it covers the window, the frame skips its own camera pass and post chain, which no
  one sees: about 60 ms a frame back to the captures. The scene is drawn again from the frame
  the switch-off starts, under black, so whatever it still has to compile does so there.
