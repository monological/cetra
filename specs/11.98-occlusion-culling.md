# Spec 11.98 — Occlusion culling: a CPU masked occlusion buffer

## Context

Roadmap **row 37 (E7)**, the last unbuilt rendering item besides the asset cook. Object-level
rejection of what is behind other geometry — the complement to E6, which rejects fragments after the
vertex and submission cost is already paid. 11.89 measured the frame as submission+shading bound;
occlusion culling removes exactly the submission and vertex cost of hidden objects, which E6 still
pays in full.

**The design is the Frostbite / Intel-MOC family, and on this platform it is not the fallback.**
GL 4.1 has no compute and no multi-draw-indirect, so a GPU two-phase HZB (UE5's shape) would move
the culling decision onto the GPU while keeping every scrap of the per-draw CPU cost it exists to
eliminate — that architecture is inseparable from MDI. The CPU masked rasteriser is what DICE
shipped for a decade, and here it is strictly better: **current-frame by construction** (occluders
rasterised from THIS frame's camera before the list is culled — no one-frame latency, no popping,
the same guarantee UE5's two-phase reaches without compute), **no readback** (the one existing
mid-frame readback documents itself as carrying the whole frame's outstanding GPU work),
**deterministic** (golden-coverable), and **a pure function** (the safety property is provable, not
tuned).

**Four properties are the spec.** (1) Authored occluder proxies that sit INSIDE real geometry — an
asset contract, the only path to a wrong pixel. (2) A masked hierarchical depth buffer — a partially
covered tile can hide nothing. (3) Conservative raster — depth rounds toward far, coverage rounds
down. (4) Conservative test — AABB nearest depth vs tile farthest depth, full coverage required.
Together: **zero false negatives by arithmetic**, before the asset contract is even invoked.

## The module — `cetra/src/occlusion.c/h`

Plain module, **no vtable** — the `lod.c`/`cluster_build.cpp` precedent (two free functions, caller
falls back by hand); particles' vtable came with a written second-backend spec we don't have. Joins
the build by glob (`cetra/CMakeLists.txt:63`; needs a reconfigure). `OcclusionContext` owned by
**Engine** beside `light_cluster`, mirroring the `LightClusterContext` charter
(`light_cluster.h:178-236`: fixed working set, allocated once, owns its buffers, accessors not
struct reaches). `create_occlusion_context()` in `init_engine` (`engine.c:868`), freed in
`free_engine` (`:375`).

**Buffer: 256×144 `uint16_t` (72 KB, L2-resident), 8×4 tiles (32×36).** Fixed-res in NDC, so
render-scale/TAAU/resize/supersample never touch it. **Depth is fixed-point** — NDC z → `[0,0xFFFE]`
— because `-O2` moves CPU float results (the erosion-digest precedent) and integer state is what
probes can digest. **`0xFFFF` is the EMPTY sentinel**: the per-pixel buffer IS the coverage mask —
`tile_zmax = max` over a tile's 32 pixels, so one uncovered pixel poisons the tile and nothing can
test ≥ it. Per pixel: MIN (nearest) occluder front-face depth, GL_LESS semantics, so overlapping
occluders merge trivially right.

API (frame protocol `begin → add_box ×N → finish → cull_list`):
`occlusion_begin(ctx, view_proj)` / `occlusion_add_box(ctx, min, max, transform)` (NULL = world box)
/ `occlusion_finish(ctx)` (folds tiles, sets `active` = any fully covered tile) /
`occlusion_test_aabb(ctx, wmin, wmax)` (pure, const) / `occlusion_cull_list(ctx, list, view)`.
Probe hooks: `occlusion_rasterize_box_into(depth, w, h, vp, ...)` — the SAME clip/round/fill path at
caller-chosen resolution (the reference twin) — plus `occlusion_rasterize_mesh_into` (triangle-exact
over the mesh's CPU arrays, which survive upload — `mesh.c` never frees vertices; validates the
interior-box contract), and integer accessors (`depth_pixels`, `tiles`, counts).
`OCCLUSION_MAX_OCCLUDERS 256`, warn-once on overflow.

## The raster

**Six faces, not a silhouette polygon** — front-facing faces of a box ARE the silhouette, each is
planar (one conservative depth per face is honest), and near-clipping a convex quad is four
Sutherland-Hodgman edges. Per box: 8 corners through transform then `view_proj` (per-corner
`glm_mat4_mulv`, the `light_cluster.c:134-140` idiom); face visibility from world planes
(winding-agnostic — orientation fixed by the opposite corner, so negative scale needs no case);
**camera inside all six planes → skip the box** (from inside, a proxy proves nothing); clip each
front face against `w >= 1e-6` and `z + w >= 1e-6` (partial polygons keep their in-front part);
divide to NDC.

**Rounding rules, the conservatism contract, stated once in occlusion.c's header:**
- Occluder depth: `ceil` toward far, max over clipped vertices per face.
- Occluder coverage: a pixel fills only if its ENTIRE footprint square is inside every edge
  (incremental edge functions, scalar — no hand SIMD exists in this tree; rows are disjoint bands,
  so `cetra_bake_bands` is the future primitive, noted not built).
- Occludee depth: `floor` toward near, min over the 8 world-AABB corners.
- Occludee footprint: NDC rect expanded OUTWARD to tile boundaries.
- Test: hidden ⟺ every overlapped tile has `item_q >= tile_zmax`. The inequality chain makes false
  negatives impossible by arithmetic.

## Integration

**Frame site: `render.c:1246`** — inside `render_current_scene`, right after `engine_build_draw_list`
and before the emissive-panels scope. Three reasons over the engine.c site: `engine->view_proj` is
published UNJITTERED one statement earlier (`render.c:1217`; jitter lands later in
`draw_projection`); the bits live on the list this build call finalises (an epoch bump in
`pre_render` rebuilds here, so bits computed earlier would be silently zeroed); and capture gating is
the one flag `engine->capturing`, the same shape as the sort/prepass exclusions at `render.c:1405/1443`.
Wrapped in a `"occlusion"` CPU profiler scope. Static helper `render_occlusion_pass(engine, scene, &cull)`:

1. `if (!engine->occlusion_cull_enabled) return;`
2. **Zero-cost path**: `if (scene->occluder_count == 0 && list->occluder_flag_count == 0) return;`
   — an unoccluded scene pays two integer compares (`occluder_flag_count` maintained by the build's
   `push`).
3. begin → add authored boxes (`scene->occluders`, NULL transform) → add flagged items
   (`DRAW_OCCLUDER`, box = `mesh->aabb`, transform = `node->global_transform`) → finish.
4. `if (!occlusion_active(ctx)) return;` — all occluders clipped/behind costs no item walk.
5. `occlusion_cull_list(...)` → 6. `cull.occlusion = true;`

**The bit: `uint8_t occluded` on `DrawItem`** (after `lod`; struct stays 24 bytes — 3 payload bytes
after two pointers today, verified). NOT a `flags` bit — the flags charter is "material facts decided
at build" (`draw_list.h:41-48`) and this is a per-frame camera answer. It survives
`draw_list_sort_lane`'s whole-item copy (`draw_list.c:427`, verified) and shadow's `caster_order`
indexing, which a side array indexed by list position would not. Zeroed at build by the designated
initializer.

**The switch: `bool occlusion` on `CullView`** — false from `render_cull_view` (the one constructor,
`render.c:76-80`, the one place `frustum_cull_enabled` is read; update its comment); set true ONLY
by step 6. Shadow layers (`shadow.c:1029/:1336`) and captures rebuild views through the same
constructor and never flip it — **camera-pass-only is structural**, not policed.

**The predicate** (`draw_item_visible`, `draw_list.c:322-330`): `if (view->occlusion &&
item->occluded) return false;` before the frustum test — one load, valid independently. Every
existing `meshes_culled` counter site absorbs the rejection, so `meshes_seen == instances +
meshes_culled` and every submission gate keep working untouched. `draw_run_can_join` inherits it, so
run cuts stay consistent (the `draw_list.h:147-151` contract). `_count_late_meshes` silently stops
counting an occluded transmissive → the refraction resolve is skipped when nothing samples it —
intended, stated.

**`occlusion_cull_list`**: per item — `draw_item_bounds` (the exported `_item_bounds`; false =
"unboundable" = never occlusion-cull, wind/morph margins included as for frustum) → `aabb_transform`
world box → 8 corners projected; any `w <= 1e-6` or `z + w <= 0` → bail visible (the
`light_cluster.c:121-130` conservative-bail idiom) → outward tile rect + floor depth → all tiles
pass → `item->occluded = 1`. World-box hoisting into the frustum test is noted, not taken (occlusion
runs once/frame; the frustum test runs per pass).

## Authoring — two channels

**(a) `.cscn` top-level `occluders: [{boxMin, boxMax}]`** — world-space interior boxes, "a thing
placed in the world" (the probes precedent, `cscene.c:702-739`): closed key list +
`warn_unknown_keys`, both keys REQUIRED (a defaulted box is a silent hole), inverted boxes warned and
dropped, `CSCENE_MAX_OCCLUDERS 64`. Owned by Scene as a flat array beside `fog_volumes`
(`scene.h:222`), applied app-side beside `apply_cscene_fog_volumes`. Doc comment carries the
contract: *an authored box must sit entirely inside opaque geometry; the raster is conservative, so a
violated contract is the only path to a wrong pixel.*

**(b) Material row `occluder`** in `MATERIAL_PARAMS` (`material.c:117-119` precedent), labels
`{"off","on"}`, calloc default off — buys `.cscn` + GUI + config-snapshot for free. The charter
(`material.h:375-413`) gets an honest paragraph: unlike `foliageShadows`, a violated contract here
costs pixels on OTHER meshes; admission rests on the use-site guards plus probe verifiability.
**Guards in `classify()`**: `DRAW_OCCLUDER` flag set iff opaque lane ∧ not masked ∧ not skinned ∧
`morph_max_offset == 0` ∧ `wind_response == 0` (moving geometry breaks interiority in the direction
that matters — note `_item_bounds` ADDS those margins for occludees; an occluder would have to
shrink). Double-sided allowed (a closed crate occludes; openness is the author's contract, and the
probe's box-vs-mesh raster check catches it). **Box raster, not triangles, in v1**: at 256×144 the
coverage-rounds-down rule erases most real triangles anyway; the enum grows a `"mesh"` label later
without touching consumers.

**Levers**: `engine->occlusion_cull_enabled` default true beside `frustum_cull_enabled`
(`engine.h:181-195`), `--no-occlusion-cull` (parse beside `--no-frustum-cull`, `render.c:793`),
config row in `"engine.draw"` (`config_snapshot.c:450`), GUI checkbox (`gui.c:1021-1026`).

## Edge cases (each handled structurally, enumerated in the spec)

Camera inside a box → box skipped. Occluders all behind/clipped → `active` false, no item walk.
Box crossing near plane → clipped, in-front part contributes. Occludee crossing near plane → bail
visible. Unboundable → bit never set. **Origin shift → `scene_apply_origin_delta` must shift
occluder boxes exactly beside the fog-volume shift (`scene.c:559-560`)** — an unshifted occluder
occludes at its old address, a wrong-pixel bug; node-attached occluders shift free via the tree.
Captures → pass skipped, rebuilt views carry `occlusion=false`, stale bits unread. Ortho cameras →
projection-agnostic math. **Terrain → booked, not built**: coarse patches are CPU-resident
world-space soup, but a conservative terrain occluder must SUBTRACT `morph_max_offset`; the
`classify` guard is the fence until that phase.

## Verification

### Fixtures — `assets/gen_occlusion_fixture.py` (two layouts, two .gltf, four .cscn)

**A. Portal room** (`occlusion_fixture.*`): four wall slabs framing a doorway (material `occl_wall`,
wound toward camera — asserted), ~300 distinct ~2k-triangle meshes behind it named `occl_hidden_NNN`
(~600k hidden triangles), ≥3 visible through the gap (`occl_door_N`), one `occl_door_marginal`
within a few mask texels of the jamb but outside the conservative expand. Camera DERIVED from
geometry. Casting directional light (a `shadow cascades` row must exist), pinned exposure.
Variants: primary (`occluders:[]` = 4 interior boxes), `_bare` (no occluders key — the empty-context
path no flag reaches), `_mat` (no boxes; `occl_wall` material row instead). Camera-inside-the-room is
**flag-driven** (`--cam-eye/--cam-target`, coordinates asserted by the generator).
Generator asserts, each naming its arm: every node in-frustum (culls attributable to occlusion
alone); every hidden projection inside the wall solid with ≥N-texel margin; door meshes inside the
gap; boxes ⊆ slabs shrunk by ε; nearest hidden mesh's depth gap > quantisation ε; inside-camera in no
box; ≥3 members per counted class.

**B. Scatter twin** (`occlusion_scatter.*`): ONE shared mesh instanced ~90× in a row at constant
depth (one long instanced run) + a sparse pillar fence hiding every 3rd — occlusion ON cuts ⅓ of
triangles but splits the run ~1→~30 draws. The measured LOSS for roadmap row 37.

### Probe — `--occlusion-probe` (post-loop block, beside `--wind-bound-probe`, `render.c:4224`)

The **brute-force twin**: exact per-pixel edge-function raster of the same boxes via
`occlusion_rasterize_box_into` at full/mask resolution with unquantised float depth — shares inputs,
none of the hierarchy/quantisation. Plus a seeded LCG sweep of ~2048 frustum-distributed AABBs.
Rows: `occlusion-probe header available=… / item hier=… ref=… name=… / violation … / sweep
ref_hidden=… hier_hidden=… violations=… catch=… / summary …` (k=v, name last, `available=0
reason=<word>`). **Two-sided**: (1) safety — `violations == 0` (hier-hidden ⟹ ref-hidden), zero
exceptions; (2) efficacy — `catch >= OCC_CATCH_FLOOR` with a vacuity guard `ref_hidden >= 200`
(the `CULL_BOUND_FLOOR` pattern; floor calibrated from measurement, recorded in the spec). Also:
every `occl_hidden_*` reads `ref=1 hier=1`, every `occl_door_*` reads `hier=0`; `_bare` reads
`available=0 reason=nooccluders`.

## The review record (seven agents, after Phase 10)

Three thermo-nuclear and four simplify reviewers over the branch diff, all held until all seven
reported. One correctness defect, a set of latent defects none of the arms could reach, and a
structure pass; every accepted finding applied, re-gated, and the changed mechanisms re-falsified.

**The defect: the near-plane regime, and the plan was wrong about the fix's shape.** This spec's
raster section says "camera inside all six planes → skip the box" and rasterises all six faces on
the min-merge argument. An adversarial-camera probe found the regime both miss: with the eye a
near-plane's depth from a wall slab, the renderer near-clips the shell OPEN and shows the room
through it, while the raster — front face clipped away, eye still outside the box so the skip never
fires — stands the BACK face across the frame. **118,794 px (24.7% of frame) of visible scene
culled** at a camera derived from the left slab band's own geometry. The fix is classification, not
another guard: only a face whose outward side holds the eye rasterises (orientation fixed against
the opposite corner, so winding-agnosticism survives), which keeps exactly the region the renderer
keeps and makes the inside-a-box skip a THEOREM — from inside, no face qualifies — so
`eye_inside_box` is deleted rather than corrected. At the defect camera the buffer now honestly
reads `available=0 reason=inactive`.

**The regime got a fifth variant and an eleventh arm**, because the defect was invisible to every
existing camera — front faces cover whatever a back face would, everywhere else. `occl-near` is
`identity_pair` over `occlusion_fixture_near.cscn` (eye derived to the hand-found coordinates
exactly: the slab band centre at z = 0.03). New ledger rows, run against the committed fixes:

| F9 | face classification deleted (every oriented face stands) | near red | **near RED at 118,794 px, culled 308 vs 215** — the defect verbatim, and the ONLY red arm of eleven, which is the measurement that says this camera was missing |
| F1' | F1 re-run (test returns visible unconditionally) | hidden, material red | **five reds**: hidden, material, probe (catch 0.0000), **fragment** — now exact, so it bites where the old floor form did not — and crossover (−0%, separated=False) |

**The latent defects, none reachable by an arm today.** Float edge functions cancel at pixel scale

**Structure.** `project_occludee` extracted as the shared occludee prologue of the real test and
the probe's reference twin; `probe_proxies` extracted with its buffers hoisted; five dead accessors

determinism the sweep depends on).

## What this deliberately does NOT do (stated in the spec)

No golden. No cross-build determinism promise beyond the quantised buffer (fixture keeps counted
