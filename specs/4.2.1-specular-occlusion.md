# Tier 2 · 4.2.1 — Specular occlusion + edge-aware AO filtering (the GTAO-on-specular fix)

## Context

With GTAO on, a bright near-clipped specular surface (the KHR specular/sheen fixture spheres) shows
a **shimmering, jagged blue/white "coastline"**; `--no-ssao` removes it. Root cause is two-fold,
confirmed by code trace + the AO debug buffer:

1. **GTAO multiplies the whole composited HDR** — `tonemap_frag.glsl:147` (`sceneToToned`):
   `min(hdr, 60000) * aoFactor`, specular and reflections included. Screen-space AO approximates
   *diffuse* occlusion; multiplying a clipped-bright specular by a temporally-noisy AO flips pixels
   across the clip threshold → the shimmering boundary. (Same anti-pattern one level down: the
   material `aoMap` dims diffuse+specular ambient equally in `pbr_frag.glsl:1027` — a documented
   follow-up, NOT this fix.)
2. **The AO signal is jagged/bleedy at silhouettes**: half-res R8 visibility with a per-frame
   golden-ratio-rotated 4×4 noise tile (`gtao_frag.glsl:117`) → a **plain, non-edge-aware 4×4 box
   blur** (`ssao_blur_frag.glsl`, exists to cancel the noise tile) → optional temporal accumulation
   (R16F, TAA-gated) → **plain bilinear upsample** at the tonemap fetch. Cross-edge bleed + jaggies
   at the sphere rim are baked in before the multiply.

**Recon facts the design builds on (verified first-hand):**
- **Per-pixel roughness does not exist at post time.** `NormalOut.a` is the SSR reflective marker
  (0 model / −1 floor / +alpha A2C hair — the "+ roughness" comments in engine.h/tonemap/catcher are
  stale). `AlbedoOut.a` is metallic. **`VelocityOut.w` is a free full-float channel**, written as
  literal `0.0` (`pbr_frag.glsl:1141`) and read by nothing.
- `roughnessMap` is a live main-scope local at the `VelocityOut` write → the export is a one-word change.
- **NdotV is properly reconstructable**: `gtao_frag.glsl:48-52` `viewPosFromLinZ(uv, linZ, invFocal)`
  + `V = normalize(-P)`; `invFocal` = projection `[0][0]/[1][1]` terms, uploaded at `postfx.c:1080`.
  Copy that math + uniform into tonemap; no `n.z` approximation.
- Tonemap already binds the resolved view-space normals (unit 3). Aux (`fx->aux_texture`, full-res,
  NEAREST) is *not* bound to tonemap yet; **unit 9 is the next free tonemap unit** (one-time setup
  block `postfx.c:421-430`, per-draw binds `postfx.c:1326-1347`).
- **Safe-by-construction edge cases** (all reach the apply with ao=1 → Lagarde saturates to 1 → no-op):
  sky (aux clear .z=0 → GTAO early-out), the shadow-catcher floor (`catcher_frag.glsl:99`
  `AuxOut = vec4(0.0)` → GTAO sees sky), A2C hair (zero-normal marker → GTAO writes 1). SSR is NOT
  composited in tonemap (sampler is debug-only) → no SSR interaction.
- `albedoTex` (metallic in .a) is bound to tonemap **only when SSGI writes attachment 3**
  (`postfx_wants_albedo`, `postfx.c:801`); an unbound sampler reads alpha=1 → a naive metallic read
  would be falsely 1. Must be uniform-gated.
- AO pipeline wiring: `gtao_active = ssao_enabled || ssgi_active` (`postfx.c:1052`); the `ssao_blur`
  pass runs only on the visibility texture (`ssao_texture[0]→[1]`), gated on `ssao_enabled`; SSGI's
  GI radiance takes an entirely separate path (`ssgi_accum` + `ssgi_atrous`, its own buffers), so the
  bilateral change to `ssao_blur_frag` cannot touch SSGI. AO defaults: `ssao_enabled = true`,
  `ssao_strength = 0.8` (`postfx.c:163-165`).
- **`ssao_blur_frag` is a plain 4×4 box** (`result += texture(aoTex, TexCoords+offset).r` ×16,
  `/16.0`) that exists *only* to cancel the 4×4 noise-rotation tile — so a bilateral version must keep
  ~uniform weights WITHIN a surface (gentle sphere depth-gradient across the tap window stays under
  tolerance) and only reject the silhouette cliff. **`temporal_accum_frag`** reprojects history by
  motion vectors and clamps it to the current 3×3 neighborhood (`nmin/nmax`, `FEEDBACK=0.9`): at a
  hard AO edge the 3×3 spans the cliff → loose clamp → jittering history passes → shimmer. Softening
  that edge in the blur (SO3) tightens the neighborhood and calms the accumulator indirectly, so the
  accumulator is left as-is (Risk 3).

## Design decisions

- **Specular occlusion is computed at the tonemap AO-apply** (composite time), not in `gtao_frag`
  (a second channel would widen R8→RG8 through blur + accum + 3 shaders) and not on the material
  `aoMap` (different problem; follow-up). Lagarde/Frostbite form, from the *final upsampled* ao:
  ```glsl
  // inside if (aoEnabled == 1), replacing the plain aoFactor mix:
  float ao = texture(aoTex, TexCoords).r;
  float aoVis = ao;
  vec4 nrm = texture(normalsTex, TexCoords);           // already bound (unit 3)
  // guard: any real model surface -> non-zero normal (excludes sky/hair zero-marker) AND not the
  // reflective floor (a == -1). nrm.a > -0.5 is robust to the MSAA resolve drifting a off exact 0.
  if (specOccEnabled == 1 && dot(nrm.xyz, nrm.xyz) > 0.01 && nrm.a > -0.5) {
      vec4 aux = texture(auxTex, TexCoords);           // NEW bind, unit 9 (.z linZ, .w roughness)
      vec3 P = viewPosFromLinZ(TexCoords, aux.z, invFocal);  // copied from gtao_frag:48-52
      float NdotV = clamp(dot(normalize(nrm.xyz), normalize(-P)), 0.0, 1.0);
      float so = clamp(pow(NdotV + ao, exp2(-16.0 * aux.w - 1.0)) - 1.0 + ao, 0.0, 1.0);
      float metallic = specOccHasMetallic == 1 ? texture(albedoTex, TexCoords).a : 0.0;
      float fresnel = 0.04 + 0.96 * pow(1.0 - NdotV, 5.0); // dielectric spec fraction
      float specWeight = mix(fresnel, 1.0, metallic);
      aoVis = mix(ao, so, specWeight);                 // spec-dominant pixels get spec visibility
  }
  aoFactor = mix(1.0, aoVis, aoStrength);
  ```
  Why this kills the shimmer: at moderate+ `NdotV` with near-1 ao, `so` **saturates at 1** — the
  temporal AO noise is absorbed by the clamp, so the clipped-bright specular stops flickering across
  the threshold. `specWeight` (Fresnel grazing + metallic) confines the change to spec-dominant
  pixels; diffuse-dominant pixels keep plain diffuse AO.
- **Roughness rides `VelocityOut.w`** (`vec4(screenVelocity(), ViewPos.z, 0.0)` →
  `..., roughnessMap)`). Nothing reads .w today → final frames must stay `cmp`-exact.
  *Fallback if the compiler-reassociation gotcha trips the gate:* pack roughness into `NormalOut.a`
  for non-A2C surfaces instead (SSR's check is `> -0.5`, unaffected) — but aux.w is preferred; it
  leaves the delicate A2C alpha contract untouched.
- **Metallic is opportunistic, not forced**: used only when SSGI already writes attachment 3
  (`specOccHasMetallic` uniform = albedo bound). Forcing the albedo attachment on for AO would cost
  a full-supersampled-res RGBA8 write+resolve every frame for a subtle metal-center gain — not worth
  it; fresnel-only is the honest dielectric default (metals: rim improved, center = status quo).
- **Edge-aware AO filtering** fixes the false silhouette ring/jaggies via a depth-aware (bilateral)
  weighting of the existing 4×4 box in `ssao_blur_frag`. Bind the full-res aux (linear-Z in `.z`) as
  a second sampler; weight each of the 16 taps by depth similarity to the center and renormalize:
  ```glsl
  float zc = texture(auxTex, TexCoords).z;              // center linear view-Z (negative, RH)
  float tol = max(0.05 * abs(zc), 0.02);                // ~5% depth-relative, small abs floor
  // per tap:
  float zt = texture(auxTex, TexCoords + offset).z;
  float dz = (zt - zc) / tol;
  float w  = exp(-dz * dz);                             // Gaussian; center w=1, cliff w→0
  result += texture(aoTex, TexCoords + offset).r * w;   wsum += w;
  // FragColor = result / wsum;   (wsum >= 1, center tap always contributes)
  ```
  On a surface all 16 taps share ~`zc` → weights ≈ 1 → it reduces to the plain box → the noise tile
  still cancels; only the silhouette cliff (relative Δz ≫ tol) is rejected. The half-res blur sampling
  the full-res aux by the same `[0,1]` UV (NEAREST) is resolution-independent; the `tol` band absorbs
  the sub-texel mismatch. **A joint-bilateral upsample at the tonemap fetch is deferred to
  SO4-decides**: the bilateral blur + the SO2 saturate together should kill the visible ring, so the
  extra 4 full-res aux taps only land if SO4's A/B still shows a residual upsample-bleed band.
  Temporal accumulation is left alone (see wiring note above — softening the blur edge calms it).
- **Two orthogonal kill-switches, both default ON** (this is a bug fix), each with the 7-point spine
  (postfx field + default, uniform, `--no-*` app triple, GUI checkbox next to the SSAO controls):
  - `spec_occlusion_enabled` / `specOccEnabled` / `--no-spec-occlusion` — the tonemap term
  - `ao_edge_filter_enabled` / `edgeAware` / `--no-ao-edge-filter` — the bilateral blur (+upsample)
  With **both off, output is `cmp`-exact vs master (AO on)** — the byte gate; each flag then A/Bs its
  own effect. New debug view `POSTFX_DEBUG_SPEC_OCC = 7` (renders `aoVis` / the spec-occ visibility)
  next to the existing AO view 1.

## Budgets & risks

- **Cost:** SO2 adds ~1 texture fetch (aux; +albedo only if SSGI already bound it) + ~15 ALU per
  pixel inside the AO branch of tonemap; SO3 adds ~4-8 aux taps at half-res in the blur (and 4+4
  taps at full-res IF the upsample lands). No new render targets, no new attachments, no format
  changes, zero new samplers in the material shader. Tonemap sampler count 9→10 (post shaders are
  nowhere near the 16 ceiling).
- **Risk 1 — aux.w write perturbs pbr compilation** (the house reassociation gotcha) → SO1's `cmp`
  gate catches it immediately; fallback: roughness in `NormalOut.a` for non-A2C surfaces (SSR's
  `> -0.5` check unaffected; A2C ternary keeps hair's alpha contract).
- **Risk 2 — bilateral blur breaks the 4×4 noise-tile cancellation** within surfaces → residual
  noise. Mitigation: generous relative-Z tolerance (down-weight, don't hard-reject), renormalize
  weights, and gate the whole thing behind its flag with an A/B; the legacy box path stays
  byte-exact.
- **Risk 3 — residual rim shimmer** at the outermost 1-2 px silhouette (false ring survives
  filtering; `so ≈ ao` at NdotV→0). Accepted, documented residual; escalation path is the temporal
  accumulator's edge handling (only if SO4 shows it still objectionable).
- Half-res↔full-res aux coordinate mapping in the blur is approximate (NEAREST full-res at tap
  centers) — tolerance sized to absorb it.
- TAA-resolved color vs current-frame G-buffers at tonemap: a known, pre-existing 1-frame mismatch
  GTAO already lives with; spec-occ inherits it (no action).
