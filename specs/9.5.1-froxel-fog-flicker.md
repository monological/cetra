# Froxel fog — fix the flicker

## Context

Spec 9.5 replaced the screen-space fog raymarch with a froxel volume. The volume is correct, but
the fog **flickers** under TAA, and it is a measured regression against what it replaced.

Static camera, consecutive frames, identical scene/flags, clean full builds
(`--fog --fog-density 0.35 --taa --headless-jitter --cam-eye 0,1.2,6 --cam-target 0,1.0,0
-x --no-auto-exposure -E 1.0 -W 500 -H 380`, frames 60 vs 61):

| path | RMSE | PAE |
|---|---|---|
| legacy screen-space march | **0.0024** | **0.149** |
| froxel @ 906bde1 (before the jitter work) | 0.0077 | 0.325 |
| froxel @ HEAD 86bd1f4 | 0.0074 | 0.329 |

**Root cause, stated precisely.** The froxel volume is *jitter-blind*: `froxel_inject_frag.glsl`
reads only `projection[0][0]/[1][1]/[2][2]/[3][2]`, and TAA jitters `[2][0]/[2][1]`
(`cetra/src/render.c:639-640`). So `froxel_composite_frag.glsl` pairs an **unjittered** volume
lookup (`uvw.xy = TexCoords`, `:41`) with a **jittered** depth read (`linDepthTex` at `:24`,
sourced from `fx->aux_texture`). `postfx_run_fog` runs at `postfx.c:1942`, *after* the TAA resolve
at `:1714`, so that inconsistent fog amount is laid over a colour layer TAA has already
stabilised, with nothing downstream to filter it.

The volume's own temporal accumulation does not touch this — it filters a different noise source
(binary cascade taps + Halton lateral jitter, both inside the volume). That is why the earlier
jitter/centre-reprojection work only moved 0.0077 → 0.0074.

**Already ruled out.** Spatial softening in the composite: TAA jitter is a whole-frame *constant*
sub-pixel offset, so the induced error is spatially correlated across the whole image, and
spatial filtering only suppresses spatially-decorrelated noise. Compositing before the TAA
resolve: it would land fog before SSR/SSGI, and both read `hdr_texture` as their radiance source
(`postfx.c:1489`, `:1855`), so reflections would double-apply fog.

## Approach — cheapest root-cause fix first, then measure

I originally proposed going straight to a 2D temporal accumulator (the mechanism the legacy path
had). Review turned up something better to try first: **the coordinate inconsistency above is
directly correctable, in the fog shader alone, with no new C plumbing and no new memory.** An
accumulator built first would average that inconsistency away well enough to *look* fixed — and
we would have shipped 50–200 MB and two full-res passes to hide a one-line coordinate error.

So: Stage 1 alone may be the whole fix. Stages 2–3 are fully specified but **conditional on
Stage 1's measurement**.

> **Outcome: Stage 1 was built, measured, and rejected** — the numbers and the reason are recorded
> below. It was still the right thing to try first: it cost four builds and it falsified the
> cheap explanation before any memory or passes were committed to the expensive one. It also
> sharpened the diagnosis for Stage 3.

---

### Stage 1 — jitter-compensate the depth read (do this first, then measure)

`postfx_run` already receives the **jittered** matrix (`engine.c:1791` passes
`engine->draw_projection`). A symmetric `glm_perspective` has `[2][0] == [2][1] == 0`, so
`vec2(projection[2][0], projection[2][1])` *is* this frame's jitter in NDC — recoverable from a
uniform `froxel_composite_frag.glsl` already declares (`:16`). NDC→UV halves it, so the depth for
the scene point at unjittered UV `u` lives at `u ± 0.5 * vec2(proj[2][0], proj[2][1])`.

Two things this needs, both local to the fog composite:

- **A manual bilinear fetch of `.z`.** `fx->aux_texture` is `GL_NEAREST` by deliberate shared
  policy (`postfx.c:438-444`) — a sub-texel offset would otherwise snap back to the same texel and
  do nothing. Implement as `textureSize` + 4 `texelFetch` + 2 `mix`, inside this shader only. Do
  **not** change the sampler state; GTAO/CS/SSS/a-trous all depend on it being NEAREST.
- **Sign resolved by measurement, not by derivation.** The wrong sign doubles the error, which is
  unmistakable — try one, measure, flip if it got worse.

#### Result: implemented, measured, REJECTED — reverted

Built and measured on `assets/contact_fixture.gltf`, matched baseline captured from the same
build methodology on the same scene:

| variant | RMSE | PAE |
|---|---|---|
| baseline (no compensation) | 0.0073782 | 0.329412 |
| offset `TexCoords - jitterUv`, plain bilinear | 0.0248591 | 0.866667 |
| offset `TexCoords + jitterUv`, plain bilinear | 0.0289924 | 0.866667 |
| offset + **discontinuity-guarded** bilinear | 0.0073781 | 0.329412 |

**Both signs are ~3.4× worse, and their PAE is identical** — which rules the sign out as the
driver. The damage is the interpolation itself: aux stores `0` as a *sky sentinel*, not a depth
(`engine.c:2174-2182`), so a 2×2 window straddling a silhouette blends a real depth with a
sentinel and invents a depth lying on neither surface — and the invented value swings with the
jitter fraction every frame, which is the opposite of the intent.

Guarding the interpolation (reject the window if any tap is sky or the spread exceeds 2% of the
centre depth, fall back to the nearest tap) returns the metric to **0.0073781 vs the baseline's
0.0073782** — a no-op to seven significant figures, for five extra texel fetches per pixel.

**Why it cannot work, in hindsight.** The jitter is sub-pixel *by construction*, so the corrective
offset is always within ±0.5 texel — and the depth buffer holds exactly one sample per pixel,
taken at that jittered position. Where the depth field is locally planar the resample is valid but
changes almost nothing (smooth depth ⇒ smooth fog ⇒ little flicker there to remove). Where the
flicker actually lives — silhouettes and sky edges — the unjittered depth was never sampled and
simply is not recoverable from this buffer. Sub-pixel jitter of a one-sample-per-pixel depth
buffer is not invertible across a discontinuity.

**The useful finding:** since correcting the smooth-gradient case changed nothing measurable, the
entire 0.0074 is silhouette- and sky-edge-driven. That is good news for Stage 3 — those are
exactly the pixels where `temporal_accum_frag.glsl`'s 3×3 neighbourhood clamp is widest, so
history passes through and gets averaged rather than being clamped away.

Reverted; no Stage 1 code shipped. Proceed to Stages 2–3.

---

### Stage 2 — fix `texelSize` on the shared accumulator (prerequisite for Stage 3 only)

`postfx.c:622` seeds `temporal_accum_program`'s `texelSize` **once** to `ao_texel` (half res), and
`run_temporal_accum` (`:1241-1258`) never updates it. Every full-res consumer today — full-res SSR
(`:1552`), contact shadows (`:1793`), the SSS delta (`:939`) — therefore clamps history against a
neighbourhood sampled at ±2 full-res texels instead of ±1. That is a real pre-existing defect, and
fog would inherit it.

The trap to avoid: "fixing" it by setting `texelSize` before the fog call would **persist on the
shared program object into next frame's** contact-shadow and AO accumulations, silently loosening
their clamps. Cross-frame state leak, no error, no visible cause.

Correct fix: set `texelSize` from `(w, h)` **inside** `run_temporal_accum`. Bit-identical for AO
(`1/ssao_width == ao_texel`), SSGI (same value, `:632`) and TAA (already set full-res at `:1712`);
it changes only SSR-full-res, CS and SSS, all of which it *tightens*. Land as its own commit with
its own before/after numbers — do not fold it into the fog change.

---

### Stage 3 — 2D temporal accumulation of the composited layer (only if Stage 1 leaves a regression)

Fog is the only jitter-sensitive consumer in the chain with no 2D accumulator. `run_temporal_accum`
is used, gated on `taa_resolving`, by SSS (`:939`), SSR (`:1552`), CS (`:1793`), GTAO (`:1887`),
SSGI (`:1904`). Two leftover comments from the deleted legacy path already describe fog as a
consumer and are currently false: `temporal_accum_frag.glsl:11` ("volumetric fog its
(inscatter.rgb, transmittance.a)") and `upsample_tent_frag.glsl:8-10` ("fog draws (inscatter,
transmittance) with (GL_ONE, GL_SRC_ALPHA)"). This makes both true again.

**Shape it like `postfx_run_sss` (`postfx.c:890-947`), not like SSR.** SSS already solves the
important part: on `!taa_resolving` it sets `history.valid = false` and folds straight into HDR
(`:925-930`). Applied to fog, the `!taa_resolving` path keeps today's direct-to-`hdr_fbo`
composite (`:1397-1413`) **byte-for-byte**, so headless and the golden never pay an fp16
round-trip for a path that does no work. Only the TAA path allocates the targets or runs the
extra passes. (`postfx_run_fog`'s `taa_resolving` parameter at `:1342` is currently dead — it was
threaded in waiting for exactly this.)

On the TAA path, three steps:

1. **Produce** — render `froxel_composite_frag.glsl` unchanged into a full-res RGBA16F
   `fog_layer` FBO, blending off. No clear needed (fullscreen quad, unconditional `FragColor`,
   no discard).
2. **Accumulate** — `run_temporal_accum(fx, fx->temporal_accum_program, &fx->fog_history,
   fx->width, fx->height, fog_layer_tex)`. Reused verbatim; no new accumulation logic.
3. **Apply** — blend into `hdr_fbo` with the existing `GL_ONE, GL_SRC_ALPHA` + restore idiom,
   reusing the **`upsample_tent_program` PostFX already owns**, with `texelSize = (0, 0)`.

   That is what makes this need **no new shader and no new program registration**. The tent kernel
   is `0.25/0.5/0.25` separably, so the nine 2D weights sum to exactly 1.0; at `texelSize = (0,0)`
   every tap reads the same texel and the pass is an identity. A *real* 1px tent would not be free
   here the way it is for SSR: on a **non-premultiplied** `(inscatter, transmittance)` pair,
   transmittance jumps hardest at silhouettes and a non-depth-aware tent puts a 1px fog halo
   around every object. Disabled, with a one-line comment saying why, or it reads as magic.
   (Adding a dedicated passthrough program instead costs seven edit sites for a shader body of
   `FragColor = texture(src, uv)`.)

**GL state — `run_temporal_accum` restores nothing.** It leaves FBO = `pp->fbo[write]`, viewport
= `(w,h)`, program = `temporal_accum_program`, and **active unit = `GL_TEXTURE2`** (`:1252`). The
apply step must therefore do, in order: bind `hdr_fbo` → `glViewport` → `glUseProgram` →
**`glActiveTexture(GL_TEXTURE0)`** → bind. Omit the FBO bind and you sample `pp->tex[write]` while
it is still the draw target; omit the unit reset and the tent samples whatever sits on unit 0.
SSR does exactly this at `:1577-1587`, SSS at `:942-944`.

**Targets** — `fog_layer_fbo`/`fog_layer_texture` + `PingPong fog_history`, at `fx->width/height`
(`= window × ss_scale`, `:244`), via the existing `create_color_fbo` / `create_pingpong` helpers.
Put them in their own `postfx_ensure_fog_layer_targets` called from the `taa_resolving` branch —
**not** in `postfx_ensure_froxel_targets`, whose doc comment (`:700-703`) explicitly says the fog
targets are deliberately *not* sized by render resolution. That also matches the file's
one-guard-per-feature pattern and stops headless runs allocating memory they never touch.

Cost: 3 × `width` × `height` × 8 B — ~50 MB at 1080p, ~199 MB at `--ssaa 2`. Full res rather than
legacy's half res is deliberate: the composite picks its slice from a per-pixel depth, so at half
res a texel straddling a silhouette gets one fog value for a 2×2 block and fringes — trading the
artifact this change exists to fix for a different silhouette artifact.

Teardown in `free_postfx`: delete the FBO + texture and `free_pingpong(&fog_history)` (a safe
no-op on a never-allocated calloc'd struct, already relied on for `cs_history` at `:1103`). Do not
reproduce the file-wide retry-leak pattern in the new ensure function.

**The resulting asymmetry must be commented**: the volume accumulator is *not* gated on TAA (its
noise exists with TAA off), the 2D accumulator *is* (its only target is jitter-induced). Without a
note the two look inconsistent.

  gitignored) no longer calls fog "the one exception" — it now describes both fog accumulators and
  why they are gated oppositely. `specs/9.5`'s Temporal section was corrected on three counts: the
  shared 2D accumulator is not reusable *for the volume* (it is for the composited layer), the
  jitter is not frozen when TAA is off, and no `prev_view_proj` publish was ever added.
  `postfx.c:611-613` no longer says "fog at half-res". `temporal_accum_frag.glsl` and
  `upsample_tent_frag.glsl` both named fog in their headers while nothing called them for it —
  true again now, and the tent's "sets it once at init" claim is corrected.
  `postfx.h`'s debug-view gap comment no longer claims there is no 2D fog buffer to blit.

## Verification

Every build a **complete** `./build.sh` — never piped through `head` (SIGPIPE leaves a stale
binary and fabricates results).

1. **Flicker (the target metric).** The Context measurement, re-run after each stage:
   consecutive frames 60 vs 61, `magick compare -metric RMSE` and `-metric PAE`.
   **Target: legacy's 0.0024 / 0.149.** Report the number after every stage, including if it
   fails to move.
2. **Golden.** `assets/froxel_fog_golden.png` is captured headless *without* `--taa`
   (`specs/9.5:204-210`). Stage 1 should be a no-op there (zero jitter); Stage 3's `!taa_resolving`
   path is byte-for-byte today's code. So the golden should reproduce **0 px with no
   regeneration** at every stage — if it moves, something changed that should not have.
   ```
   ./out/bin/render -m assets/contact_fixture.gltf --fog -x -f 30 \
       --no-auto-exposure -E 1.0 -W 640 -H 400 -S /tmp/fog.ppm
   magick compare -metric AE /tmp/fog.ppm assets/froxel_fog_golden.png null:
   ```
3. **Headless determinism 0 px** — two identical runs with `--fog`, with and without
   `--headless-jitter`.
4. **Fog-off 0 px** — no `--fog` vs pre-change.
5. **Stage 2 re-measure** — SSR / contact shadows / SSS each move (the clamp tightens); confirm
   each is an improvement or neutral, not a regression.
6. **Silhouettes at 1:1, under motion.** `temporal_accum_frag.glsl:42-53` clamps rgb and alpha
   independently, so at an edge it can take inscatter from one side and transmittance from the
   other. Fog's alpha multiplies the *entire* scene, so inspect edges directly — not just the
   aggregate numbers, and never a thumbnail (the 9.2/9.4 lesson).
7. **Spot regression** — `./out/bin/spores -x -f 300 -S p.ppm`: the beam must still be cut by the
   glass sphere (`specs/4.5.1`).

## As built

Stage 1 rejected (measured above). Stages 2 and 3 shipped.

| | RMSE | PAE |
|---|---|---|
| legacy screen-space march (the target) | 0.0024 | 0.149 |
| froxel, before this spec | 0.0073782 | 0.329412 |
| after Stage 2 (`texelSize`; fog untouched, as expected) | 0.0073804 | 0.329412 |
| **after Stage 3** | **0.0024357** | **0.14902** |

A 3.03× improvement, landing on the legacy march's numbers on both metrics. The regression
spec 9.5 introduced is closed.

Gates, all green:
- Golden `assets/froxel_fog_golden.png` reproduces **0 px, no regeneration**, at every stage — the
  no-TAA path is byte-for-byte the pre-change code.
- Headless determinism **0 px** on the new accumulator path (two runs, `--taa --headless-jitter`).
- Fog-off unaffected: `postfx_run_fog` returns before any new code when `fog_enabled` is false.
- `spores` spot regression clean — cone, floor pool, and the glass sphere's cut through the beam
  all intact.
- Silhouettes at 1:1: the thin dark rims that outlined every sphere are gone, with no ghosting,
  halo, or smearing, and the fog gradient preserved.

Total cost: **no new shader and no new program**. The composite is unchanged; the layer routes
through the existing `run_temporal_accum` and folds in via the existing `upsample_tent_program` at
a zero texel. Three full-res RGBA16F targets, allocated only on the first TAA frame with fog on.

  without explicit per-instance permission.
- **Not done, still available:** restore `POSTFX_DEBUG_FOG = 6`. `fog_layer_texture` is now a

- **Drive-by defect found while surveying, not in scope:** `fx->ssr_hiz_program` is created
  (`:490`) and dereferenced (`:552`, `:1441`, `:1459-1464`) but missing from the NULL-check chain
  at `:505-516`, so a compile failure there is a NULL deref rather than a clean bail. Separate
  one-line fix; flagging, not bundling.
- **Rejected:** aliasing an existing idle full-res RGBA16F (`ssr_atrous`, `oit_accum`,
  `taa_history.tex[read]`) to save the `fog_layer` allocation. Each is conditional on another
  feature's flag or parity internals, so fog would silently get a wrong-sized or live target when
  an unrelated setting changed.
