# Spec 11.31 — masked geometry in the prepass, and the blend defect underneath it

## Context

Spec 11.30 (E6) shipped a depth prepass and front-to-back opaque ordering, and closed with one thing
named as unfinished: **alpha-masked geometry sits the prepass out**. That exclusion is what caps the
result. `abandoned_window_shadowed` reaches depth complexity **exactly 1.00** (31.5 → 11.2 ms, −64%),
the theoretical floor; `apps/forest` stalls at **2.80**, because foliage is where its overdraw lives
and foliage is masked. The roadmap records the limit as "the masked exclusion, not the prepass".

This spec takes that, plus the four other loose ends 11.30 left: the A2C/blend defect, the prepass's
default, the crossover that was looked for and not found, and `overdraw-probe`'s soft margin.
Occlusion culling (E7) is deliberately not here — it gets its own plan.

**Intended outcome:** masked geometry prepasses on every configuration, the opaque lane stops blending
geometry that is not translucent, and both defaults are decided against a measurement rather than
carried forward on caution.

## What the exploration established

Fourteen findings. All verified in the tree; the first four are why this is a spec and not a patch.

**1. 11.19 rejected the blend fix on a null measurement.** Section 2.3 measured the A2C/blend
double-apply at **393,554 px (20.5%)**, then re-measured under `--taa --headless-jitter`, got **0 px**,
and concluded "TAA already resolves it". But the recorded patch is bracketed by `if (use_a2c)`, and
`use_a2c = DRAW_ALPHA_MASKED && a2c_capable` where `a2c_capable = msaa_samples > 1`
(`render.c:304`, `:507`) — while the same `if` that enables TAA sets `msaa_samples = 1`
(`apps/render/src/render.c:2853`, `apps/forest/src/forest.c:1037`). **Under TAA the patch is dead
code.** The 0 px measured that a disabled patch does nothing. The spec recorded its own unease —
*"0 px under TAA is itself suspicious. A systematic `a` vs `a^2` bias should not survive temporal
averaging"* — and attributed it to a different mechanism.

**2. The defect is not confined to A2C.** On the shipping TAA path a leaf texel at alpha 0.6 clears
the 0.4 cutoff, writes `FragColor.a = 0.6` (`pbr_frag.glsl:1925`), and slot-0 `SRC_ALPHA` blends it
60/40 against **the clear colour** — the opaque pass runs before the skybox, which is the whole point
of leaving uncovered samples open. Single-apply, still wrong, live in exactly the configuration 11.19
declared clean. glTF says `MASK` is binary: fully opaque above cutoff. This is conformance, not taste.

**3. The root cause is altitude, not a missing bracket.** `glEnable(GL_BLEND)` is global
(`engine.c:447`) and `engine_set_scene_draw_buffers` disables it only for attachments >= 1
(`engine.c:1717-1758`, loop starts at `i = 1`). So the opaque lane inherits `SRC_ALPHA` blending it
never asked for. No engine does this; blend state is a property of the pass. 11.19's per-draw bracket
patches the symptom.

**4. The sort already pays for this, and the engine says so.** `engine.c:243-250`: *"Unlike
`--no-instancing` this one is NOT a 0 px flag, and the reason is a defect it did not cause: masked
materials still blend into attachment 0."* Commit `682d6bb` goes further — *"Ordering does not merely
coexist with the A2C blend defect, it maximises it."*

**5. `fresnelOpacity` short-circuits.** `if (materialOpacity >= 1.0) return coverage;`
(`pbr_frag.glsl:816-817`) — the default, and the case for effectively all foliage and hair. The normal
map, TBN and NdotV are dead for those materials. `depth_prepass_frag.glsl:7-12` states the pessimistic
case as if it were the general one.

**6. The discard does not include the opacity layer.** `alphaBelowCutoff(texAlpha)` at `:938` runs ~70
lines before `coverage *= maskArray[opacityLayer]` at `:1014`. The opacity layer only ever reduces A2C
coverage, never discards.

**7. A2C coverage comes from `NormalOut`.** The driver reads the last bound output carrying alpha;
attachment 7 is `R11F_G11F_B10F` and has none, so it falls to attachment 1
(`pbr_frag.glsl:1927-1947`). Measured there: forcing that alpha to 1.0 moved 8,580 px of masked hair.
A depth-only pass that writes no colour has nothing for the hardware to read.

**8. `pbr_frag` already has the early-out seam this needs.** The OIT moment-generation mode returns at
`:1156-1158`, where `coverage`, `materialOpacity`, `iorF0` and `NdotV` are all in scope and
`fresnelOpacity` is called. A depth-only mode returns at the same point, with no restructuring.

**9. And it already makes this spec's argument.** `pbr_frag.glsl:236-242`: *"Generation is a mode in
this shader rather than a program of its own on purpose. A separate program would have to reproduce
the UV transform, POM, the mask-array opacity chain and the Fresnel... a drift there mis-weights every
layer silently, where a mode cannot drift at all."* That is the case against a hand-written
`coverage.glsl`, made in this codebase before this spec existed.

**10. `assets/gen_overdraw_fixture.py` was specced by 11.30 and never written.** Its Files table lists
it — *"N opaque quads stacked so depth complexity is exactly N"* — and Phase 0 used `apps/forest`
instead.

**11. `overdraw-probe`'s 1.05 has two causes, and neither is the threshold.** Its `base` run carries no
`--taa`, so forest keeps 4x MSAA and `budget = rw*rh*msaa_samples` (`engine.c:2267`) quadruples the
divisor; and the sort is on by default. The arm reads the wrong configuration twice over.

**12. `instancing_fixture`'s −10% is unexplained.** It was included at complexity **0.71** expecting
the prepass to lose, and it won. At that complexity there is nothing hidden to reject. Candidates: the
shading pass running `GL_LEQUAL` against a filled buffer, or cache warming. Nobody looked.

**13. The depth-complexity counter is blind to what this spec targets.** `profiler.h` records it: it
counts samples that *pass*, and a fragment that `discard`s costs a full shader invocation while
passing nothing. It **understates the work exactly where masked foliage dominates.** So this spec's
success criterion is GPU milliseconds; the counter will move less than the clock does.

**14. `shadow_depth_frag.glsl:13` is a fifth divergent copy of the alpha decision** — raw `TexCoords`,
no UV transform, no vertex-colour alpha, no opacity layer. Any leaf with a KHR texture transform casts
a wrong-shaped shadow today. Recorded; see Deferred.

## Design

Four phases, each ending at a measurement. **The blend fix goes first**, because it decides what
"identical picture" means for every arm after it, and because the prepass work would otherwise be
measured against a frame that is wrong.

### Phase 1 — blend state belongs to the pass

The opaque lane draws opaque and masked geometry. Neither is translucent. Disable blending for the
lane rather than bracketing individual draws:

```c
// _submit_lanes, entering the opaque lane
glDisable(GL_BLEND);
  ... opaque + masked draws ...
glEnable(GL_BLEND);
```

A no-op for genuinely opaque materials (alpha 1 makes the blend an identity), the fix for masked ones,
one state change per pass instead of two per draw. **Scope it to the lane, not to
`engine_set_scene_draw_buffers`** — 11.19 records that a first attempt did the latter and blacked out
60% of the frame, because the skybox rides the same state.

This is also Godot's `ALPHA_ANTIALIASING_ALPHA_TO_COVERAGE_AND_TO_ONE`, which exists for exactly this
trap. So it **repairs** A2C rather than working around it: covered samples get `src` directly and MSAA
foliage edges stop being darkened toward the clear colour.

Correct 11.19's record in `specs/11.19-coverage-vs-translucency.md` — the rejection stands as written
history, with a dated note that the "windowed, TAA on -> 0 px" row is a null measurement and why.

**Expected movement:** every ALPHA_MASK material in the tree, and nothing else. `apps/forest` leaves
(`forest.c:648-656`), `apps/tree` leaves (`tree.c:1006-1007`), raiden's `Hair_1`, and the
`translucent_shadow` golden — whose `tsl_ramp` panel sweeps every fractional alpha across u, making it
the corpus's most sensitive stored instrument for an `a` vs `1` change. Re-bake it.

**Arms:**
- `mask-opaque` — on a MASK fixture, texels above the cutoff must match an OPAQUE material with the
  same albedo. A real invariant, not a band: it is what "MASK is binary" means.
- `sort-identity` — re-check. If masked geometry stops blending, the sort should become a 0 px flag.
  `cornell_box`'s 1 px will remain: that is a coplanar depth tie broken by draw order (`render.c:1043`),
  a different cause.

### Phase 2 — the depth-only mode, and masked geometry in the prepass

**One source, two permutations** — what UE and Godot do, and what `pbr_frag.glsl:236` already argues
for. `pbr_frag` gains a `depthOnly` uniform and returns at the existing OIT early-out point
(`:1156`), after the discard and after the outputs that carry coverage are written. No hand-copied
`coverage.glsl`; no second chain to keep bit-agreed.

The prepass then binds **two programs**:

| geometry | program | why |
|---|---|---|
| opaque, not masked | `depth_prepass_vert` + `depth_prepass_frag` | nothing to evaluate; stays lean |
| masked | `pbr_vert` + `pbr_frag` with `depthOnly = 1` | position and coverage agree *by construction* |

For masked draws this dissolves three problems at once. Positions agree because it is the same program,
not two programs plus an `invariant` promise. Coverage agrees because it is the same code. And the TBN
and `WorldPos` are present, so **POM works and A2C works** — no carve-outs, nothing deferred.

The cost is `pbr_vert` twice on masked draws (wind for two frames, motion vectors, the tangent basis).
Leaves are fragment-bound — that is E6's entire premise — and the fragment side returns immediately
after the discard. Paying a vertex shader twice to avoid shading a leaf twice is the trade this whole
line of work is built on.

Changes:
- `item_is_prepassable` (`render.c:624-639`) drops its `!(item->flags & DRAW_ALPHA_MASKED)` clause.
- `_submit_depth_prepass` switches program per item class, hoists `camPos` / `parallaxEnabled` /
  `mask_array_bind` to its program-switch scope, and reuses `_update_program_material_uniforms` for
  masked draws. Uniform writes are location-guarded (`uniform.c:93-119`), so what the lean program
  does not declare no-ops — the pattern `shadow.c:495-498` already relies on.
- The A2C bracket (`glEnable(GL_SAMPLE_ALPHA_TO_COVERAGE)`) must appear in the prepass too, on the
  same `a2c_capable` derivation, or the two passes disagree about `alphaCutoff` vs `A2C_MIN_ALPHA`.
- With the whole lane prepassed, `glDepthMask(GL_FALSE)` on the shading pass becomes correct — 11.30
  Phase 3 specified it and it was never implemented. `GL_EQUAL` also becomes available, but programs
  with `depth_prepass_safe == false` (`shape`) still sit out, so **keep `GL_LEQUAL`** unless Phase 4
  says otherwise.

**Two things to verify rather than assume**, both testable by `prepass-identity`:
- that `glColorMask(GL_FALSE)` does not suppress A2C coverage evaluation;
- that the hardware's alpha -> sample-mask function is deterministic across two passes at equal alpha
  and equal position.

**Arms:**
- `prepass-masked` **flips from a band to 0 px.** Its own comment asks for this: *"The band catches...
  the day masked geometry joins the prepass and this drops toward 0 -- at which point the flag becomes
  a 0 px flag and this arm should be replaced by prepass-identity on raiden."* It runs headless at 4x
  MSAA, which under this design is a configuration where the masked prepass is live — so no relocation
  is needed, and the arm tests the A2C path specifically.
- `prepass-identity` — extend to a masked subject, not only `instancing_fixture`.
- `prepass-equal-guard` — keep; it is what proves the identity arms can fail.

**Bar:** GPU milliseconds on `apps/forest` and `abandoned_window_shadowed`, not depth complexity
(finding 13). Report both, and say which one is the claim.

### Phase 3 — the fixture 11.30 specced and never built (items 5 and 6)

One generator, `assets/gen_overdraw_fixture.py`, two layouts. Model it on `gen_oit_fixture.py`
(85 lines, stdlib only, single base64 buffer) with a hand-authored sibling `.cscn` like
`instancing_fixture.cscn`.

- `--layers N` — N full-frame opaque quads stacked at staggered depths. Depth complexity is **exactly
  N**: an integer with no noise floor, at 400x300 instead of a forest render.
- `--tiles M` — an M x M grid of small non-overlapping opaque quads covering the frame. Complexity
  **1.0** with real submission and vertex cost, and nothing to reject. This is item 5's expected loser.

Then:
- **Re-point `overdraw-probe` at the stacked fixture.** It stops depending on forest's AA mode and on
  the sort's default, and it retires a forest render rather than adding one. Assert
  `complexity == N` within tolerance, and 0 aimed away.
- **`prepass-crossover`** on the tiled fixture: the prepass should cost time here. It needs its own
  repeat-run noise floor — `gpu-scale` (`gates.py:2535-2565`) is the template, and it is the only arm
  in the suite that measures variance before claiming a delta.
- `_profiled_run` gains `tables["shading"] = _shading_block(text)` — one line, no existing caller.
- **Chase finding 12** while the instrument is in hand. If the tiled fixture also fails to lose, the
  −10% is a real mechanism and worth naming, not a rounding artefact.

### Phase 4 — measure, and decide both defaults (item 3)

Phase 2 reopens a question Phase 4 of 11.30 answered under the old exclusion. Re-run its four-config
matrix on the shipping AA path, plus `abandoned_window_shadowed` and both new fixtures:

| config | 11.30 measured | after Phase 2 |
|---|---|---|
| neither | 397 ms @ 3.87 | — |
| sort only | 255 ms @ 2.17 | — |
| prepass only | 355 ms @ 2.80 | **the load-bearing row** |
| both | 234 ms @ 1.94 | — |

**Both defaults are live questions now**, and they interact:
- Phase 1 may make the sort a 0 px flag, which removes the reason it shipped on with a caveat.
- Phase 2 may make the sort redundant — that was 11.30's hypothesis, rejected only because masked
  foliage sat the prepass out. Prepass-only reaching ~1.0 would restore `forest-order` and
  `forest-batch` to their un-excluded form and un-do `cornell_box`'s coplanar tie.

**Report and ask. Do not flip either default unilaterally** — including the case where the numbers
look decisive.

## Verification

- **Measure the noise floor first, every time, at the exact configuration.** `apps/forest` is **not**
  pixel-deterministic — 34,991 px at 60 frames / 3200x1800, 7,134 at 20 / 1600x900, the Hillaire sky.
  A pixel count without its floor is not a measurement; 11.30 quoted one before checking.
- Exposure pinned (`--no-auto-exposure -E 1.0`) on every cross-configuration comparison. `apps/forest`
  pins its own.
- **21 goldens at 0 px after every phase except Phase 1**, where exactly one (`translucent_shadow`)
  may move and is re-baked. A second golden moving is a finding, not a re-bake.
- The raiden recipe at 0 px after Phases 2-4; it moves in Phase 1 and that movement is the deliverable.
- `--no-sort-opaque` and the prepass-off path must reach the pre-change frame at 0 px in Phases 2-4.
- Phase 2 must be 0 px with `--depth-prepass` off, since it touches `pbr_frag` unconditionally. Use the
  stronger check: unescape `cetra/src/shader_strings.h` before and after and diff comment-stripped.

# As built

## Phase 1 — what moved, and what could not see it

Raiden moves **1,058,960 px (12.8%)** at PAE 103/255, and the diff map is the hair groom and nothing
else. Both directions, both correct: brighter where a strand was being lerped toward the clear
colour, darker where a dark strand now fully occludes a bright one rather than half-showing it.
Binary masking means the nearer card wins outright.

**No golden moved, and that is a finding rather than a relief.** `translucent_shadow` was predicted to
move and did not: its `tsl_ramp` MASK panel is a *caster held above the frame* — the generator derives
a camera that frames the ground and excludes the canopy — so what the golden measures is its shadow,
which comes from the shadow depth pass. **No golden in the corpus contains visible masked geometry.**
All 21 passing was never evidence the change was safe; it was evidence nothing stored could see it.
That is how the defect survived two specs, and it is why `mask_fixture` exists.

**One regression, caught in review rather than by a gate.** With the lane no longer blending, the GUI
material editor's `opacity` slider became a silent no-op: `MATERIAL_PARAMS` carries `opacity` but not
`alpha_mode`, and `material_finalize_alpha_mode` was only ever called by the two importers, so a
C-built or GUI-edited material with a fractional opacity stayed in the opaque lane. Fixed by deriving
the lane in `classify()` instead of mutating the material at load — which deletes that function and
both call sites, covers `.cscn` overrides for free, and let the `gametest` patch be reverted.

## Phase 2 — the prediction that was wrong

Forest's depth complexity falls **1.95 → 0.72** with masked geometry admitted (numbers corrected per
Phase 3; they read 3.90 → 1.44 before the instrument was fixed).

**`--depth-prepass` did NOT become a 0 px flag.** Raiden holds at **395 px**, and admitting masked
geometry moved *none* of it. The cause is inherent to having a prepass at all: the shading pass must
test `GL_LEQUAL`, so two surfaces at exactly equal depth both pass and the last drawn wins, where
`GL_LESS` rejected the second. Same mechanism as `cornell_box`'s 1 px coplanar tie. What the old
46,314 px band was mostly measuring was the *blending*, which Phase 1 removed.

Both A2C unknowns resolved by measurement: `mask_fixture` compares **0 px** between prepass on and off
on the 4x MSAA path, so `glColorMask(GL_FALSE)` does not suppress coverage evaluation and the
hardware's alpha-to-samplemask function is deterministic across the two passes.

**`glDepthMask(GL_FALSE)` was specified and is not shipped.** The plan justified it with "the whole
lane is prepassed", which is false while a program can opt out via `depth_prepass_safe` — `shape`
does, and still has to write its own depth.

## Phase 3 — the instrument was wrong, on the path that ships

The fixture's first run read **2.00 for a single full-frame quad**, which must read 1.00. The budget
was `rw * rh * engine->msaa_samples`, but **ask this driver for a 1-sample multisample target and it
returns a 2-sample one**, so `GL_SAMPLES_PASSED` counted two samples per pixel against a budget that
said one. That is the TAA path — the path both the render app and forest ship — so every
depth-complexity reading taken there was exactly double. It now reads `GL_SAMPLES` back from the bound
framebuffer.

**This invalidates 11.30's Phase 4 magnitudes**: its 3.87 / 2.80 / 2.17 / 1.94 were really about
1.94 / 1.40 / 1.09 / 0.97. Every *direction* in that spec survives — both levers remove most of the
redundant shading — and so does every ratio, since both halves of each pair were doubled. Only the
absolute numbers were inflated. Below 1.0 is normal for a frame whose sky shades nothing opaque.

It survived because the counter had only ever been pointed at `apps/forest`, a scene with no knowable
correct answer. `overdraw_layers` has one by construction: N full-frame opaque quads submitted
far-to-near are covered exactly N times. Far-to-near is load-bearing — near-to-far, the first quad
occludes the rest and the fixture would read 1.00 at any N.

## Phase 4 — as measured, and the defaults do not change

`apps/forest`, 1600x900, 60 frames, TAA path, against a **0.23%** run-to-run floor:

| config | opaque GPU | complexity | opaque CPU | draws |
|---|---|---|---|---|
| neither | 306.0 ms | 1.93 | 8.2 ms | 1287 |
| **sort only** | **168.6 ms (-45%)** | 1.08 | 9.9 ms | 1127 |
| prepass only | 173.2 ms (-43%) | **0.72** | 13.0 ms | 2574 |
| both | 173.0 ms (-43%) | 0.72 | 16.4 ms | 2254 |

**11.30's "they are worth more together" is withdrawn.** That was measured when masked geometry sat
the prepass out, so the prepass could not do its job on foliage. Now that it can, the two are
**substitutes rather than complements**: both drive complexity to ~1, and once either has, the other
has nothing left to remove. Adding the prepass on top of the sort buys nothing (173.0 vs 168.6, and
that difference is 2.7% the wrong way, an order of magnitude above the floor) while costing 6.5 ms of
CPU and 1127 extra draws.

**The prepass reaches a better depth complexity and is still slower**, which is the whole lesson:
0.72 against the sort's 1.08, and it loses on the clock because a full extra geometry pass costs more
than the shading it saves. Depth complexity is the diagnostic; milliseconds are the claim.

It never wins anywhere measured:

| scene | prepass vs the same config without it |
|---|---|
| forest 1600x900, on top of the sort | **+2.7%** (floor 0.23%) |
| `abandoned_window_shadowed`, TAA | **+6.7%** (floor 0.04%), and it reaches complexity 1.00 |
| `abandoned_window_shadowed`, 4x MSAA | **+16.8%** |
| `overdraw_tiles` (complexity 1.00 by construction) | **+8 to +14%** (floor 0-1%) |

**11.30's -64% on `abandoned_window_shadowed` does not reproduce** at either AA path here; that scene
now costs 9.0 ms where the spec reported 31.5, so it was measured at a configuration this run does not
match. Rather than chase it, the interior is recorded as a scene where the prepass costs 6.7% while
achieving a perfect depth complexity.

**At 3200x1800 the measurement cannot decide anything**, and that is worth writing down rather than
quoting a number from it: the run-to-run floor is **11%** (sort-only read 360.3 then 400.1 ms), which
swamps every gap between sort, prepass and both. Only "neither" (639 ms) separates. Every conclusion
above rests on 1600x900, where the floor is 0.23%.

**Defaults: unchanged, now for measured reasons rather than caution.** Sort **on** — the larger win,
the cheapest CPU, the fewest draws. Prepass **off** — it has no configuration in this corpus where it
pays, and one gate arm (`prepass-crossover`) that asserts it costs.

## Deliberately deferred

- **Occlusion culling (E7).** Its own plan. Phase 3's fixture is the instrument it will want, and
  Phase 4 should re-price it again.
- **`shadow_depth_frag.glsl`'s divergent alpha test** (finding 14) — a real defect: raw `TexCoords`,
  so any leaf with a KHR texture transform casts a wrong-shaped shadow. Cheap once the depth-only mode
  exists, but it is a shadow-correctness change wanting its own arm and its own golden movement.
- **`list-identity`'s false A2C claim.** `gates.py:3509` says `hair_fixture.cscn` exercises
  alpha-to-coverage draw order; its only material declares no `alphaMode`, so it is OPAQUE and A2C
  never fires. The repo has **zero** coverage of A2C ordering. Worth a MASK variant of that fixture.
- **Hashed / stochastic alpha testing.** The TAA-era replacement for what A2C buys, and it prepasses
  cleanly. The right answer for foliage edge softness on the 1-sample path, and out of scope here.
- **`GL_EQUAL` for the shading pass.** Available once the lane fully prepasses, but `shape` and any
  other `depth_prepass_safe == false` program still sit out. Decide it on Phase 4's numbers.
  **Closed by Phase 4 rather than decided: the prepass is off by default and loses everywhere
  measured, so there is nothing to tune.** `GL_LEQUAL` also carries the 395 px raiden delta and
  `EQUAL` would not fix it — both admit coincident surfaces the old `GL_LESS` rejected.
- **A pass-policy struct** owning depth func, depth write, blend, cull and colour mask across all three
  draw loops. Phase 1 is the first move toward it; the refactor itself is too much to carry here.
- **`glDepthMask(GL_FALSE)` behind the prepass**, which the plan called for and this spec does not
  ship. Its premise — that the whole opaque lane is prepassed — is false while a program can opt out
  through `depth_prepass_safe`, and `shape` does.
- **Why the prepass loses, mechanically.** Phase 4 establishes *that* it costs more than it saves at
  every point in this corpus, not *where* the cost sits: the extra pass's own GPU time is not broken
  out from the shading it shields, since both land in the `opaque` scope by design. Splitting them
  would say whether the cost is vertex, submission or the second depth write, and would be the first
  thing to measure if anyone wants to revive it.
- **A scene where the prepass should win but was not built.** Everything here is either
  fragment-light (the interior at 9 ms) or already handled by the sort (forest). The case the textbook
  promises — deep opaque overdraw with heavy per-fragment shading and geometry too cheap for the extra
  pass to matter — has no representative in this corpus, and `overdraw_layers` could become one by
  giving its quads an expensive material.
