# cetra 14.41: pictures read back, and an element over its parent

## Context

pcb 9.1 (pcb's `specs/9.1-agents-connect.md`) lets an agent in Claude Code reach the running pcb
through MCP. Its `look` tool answers with what the window shows, and with pictures:
- **a pane as the person sees it, or the whole window**;
- **the agent's own view**: a layout or a schematic sheet (a canvas view), or the board in 3D (a
  scene view), framed on what the agent names, drawn off the screen so the person's panes do not
  move;
- **refused while pcb is minimized**, saying why, with every other call still answered.

pcb's Space i shows every pane's number large in its middle, over the pane dimmed. pcb's AGENTS.md
says where cetra's UI cannot do something, the missing piece goes to cetra in a spec of its own:
the UI has no element laid over another's box, so it is here, with the pictures, since pcb 9.1
needs both.

pcb 9.1's plan settled this spec's scope with the user on 2026-11-18 ("pictures inside 9.1": cetra
14.41 planned, built and landed on the user's word, pcb pinning it before `look`'s pictures).

Branch and spec: `14.41-pictures-read-back-and-an-element-over-its-parent`, off cetra's master
(`1b379cc7`).

## What exists (explored)

- **The headless screenshot** (`engine.c`, `_save_framebuffer_ppm`): `glReadPixels` of the whole of
  framebuffer 0's back buffer, rows flipped, taken after `_engine_present_frame` -- every view
  copied in, the app's overlays, the UI, the present pass, the debug GUI -- and before
  `glfwSwapBuffers`. No rectangle, no call for an app, no picture in memory.
- **Points and pixels**: `win_width`/`win_height` are points, `fb_width`/`fb_height` pixels
  (`engine.h`); the UI, canvas views and scene views place rectangles in points, top-left, +Y down.
  `engine_fb_per_point` (`scene_view.c`) is internal.
- **`canvas_draw`** (`canvas.c`): the view's rectangle rounded to pixels by the window's ratio, the
  layers drawn into the canvas's own RGBA8 target (grown to the largest view drawn, never shrunk),
  then copied opaque by the composite program into the framebuffer bound at the call. It draws
  nothing while the window has no area.
- **A scene view** (`scene_view.h`): `x, y, width, height` in points, `hidden` (neither drawn nor
  shown); `finished` when its average is complete and it rests. `scene_view_fb_rect` sizes its
  targets from the window's ratio. Every drawable view is copied into the window by
  `_engine_copy_view`. Its picture is `state->postfx->picture`, internal.
- **A window that cannot draw** (`engine.c`, the loop's `!_engine_frame_renderable` branch, a
  framebuffer of no area): no hook runs, the latches clear, and the loop waits on events for 0.1 s
  at a time. `engine_request_frame` wakes only idle mode's wait (`wake->waiting` is raised only
  there). On macOS a minimized window keeps its framebuffer (GLFW's Cocoa iconify sends an event
  and nothing else), so the branch is never taken there: the loop draws on, throttled. cetra sets
  no iconify callback.
- **The UI** (`ui.h`, `ui.c`): `UIElement.fill` takes an element out of the flow and lays it over
  the whole screen; nothing lays one over its parent. Children paint in tree order after their
  parent. A panel or label claims no pointer. `UIStyle.bg` is a `vec4` (see-through fills blend);
  `UIStyle.font_size` is per element, SDF fonts staying sharp large.

## The design

### Pictures

- **`Picture`** (`util.h`): `int width, height; uint8_t* rgba;` -- rows from the top, four bytes a
  pixel, as the window shows them (display-encoded RGBA8, alpha 255). Made by the reads below on
  the heap, freed by `free_picture`.
- **The window read back**: `bool engine_read_window(Engine* engine, float x, float y, float width,
  float height, EnginePictureFunc done, void* user);` -- a rectangle in window points, top-left,
  read once the frame being made is drawn, before it is shown: at the screenshot's place, so the
  picture is exactly what the screenshot of that frame holds there. `done(engine, picture, user)`
  gets the picture, the callee's to free, or NULL when the window could not be read (it could not
  draw, below; the engine freed). The rectangle is clipped to the window, in framebuffer pixels by
  the window's ratio as a scene view's is. It asks for a frame, so an idle loop draws one. False,
  logged, for a rectangle with no area inside the window, or when 8 reads already wait.
- **A canvas view off the screen**: `Picture* canvas_read_picture(Canvas* canvas, const CanvasView*
  view, float pixels_per_point);` -- the view drawn now, at `pixels_per_point` (0 = the window's),
  into a picture of its own and read back, the window untouched. Its size is the view's rectangle
  rounded as `canvas_draw` rounds it at that ratio, so a view read at the window's ratio is the
  pane's pixels exactly. It shares `canvas_draw`'s body: the layers into the canvas's target, then
  the composite into the picture's target instead of the bound framebuffer. It works with the
  window minimized or headless. NULL, logged, when its targets cannot be made.
- **A scene view off the screen**: two new SETTINGS on `SceneView`,
  `bool offscreen; // drawn, never shown in the window; read with scene_view_read_picture` and
  `float pixels_per_point; // an offscreen view's resolution; 0 = the window's`. An offscreen view
  is drawn as any view -- averaged and resting by its own `accumulate_frames`, waking idle mode
  until it rests -- at `width`, `height` times its ratio, wherever its rectangle is; it is never
  copied into the window, takes no pointer, and is never the focus a pointer or a pick finds.
  `Picture* scene_view_read_picture(const SceneView* view);` reads the picture it last drew (or
  rests on); the app reads it once `finished`, or after a frame for a view that does not average.
  NULL, logged, before the view has drawn. A view shown in the window can be read too, the picture
  being the one copied in.
- **Rejected**: a read handed a buffer the app owns (the size is the engine's to round, so the app
  would ask twice); reads through a pixel-buffer ring (`layers_vt.c` has one): a picture is asked
  for rarely, by a person or an agent, and a blocking read of one rectangle costs well under a
  frame; a scene view sized in pixels (`width_px`), which would split a view's size between two
  units where a ratio keeps the rectangle in points as everywhere else.

### The window that cannot draw

- **`bool iconified; // the window is minimized`**, ENGINE-OWNED on `Engine`, set by an iconify
  callback (`glfwSetWindowIconifyCallback`).
- **A minimized window cannot draw**: `_engine_frame_renderable` is false while `iconified` too, so
  macOS takes the same branch as the other systems, and a minimized window draws nothing anywhere
  (on macOS it drew throttled frames nobody saw).
- **The update hook runs while the window cannot draw**: on that branch the loop calls `update`
  with the frame's `dt`, then waits: idle mode until a request, a timed wake or an event (a view
  not at rest does not keep it awake, since it cannot draw), any other loop 0.1 s or until a
  request or an event, as now; passed wakes are dropped. Nothing else runs: no pre-render hook, no
  view, no overlay. So an app's calls from other threads are still answered, and a game's update
  can read `iconified` to pause.
- **Window reads waiting** when a turn of the loop cannot draw are answered NULL then.
- **Rejected**: a separate hook for the undrawn turns, which every app answering calls would point
  at its update anyway; leaving macOS drawing throttled, which a picture read back from a minimized
  window would then read as if the person saw it.

### An element over its parent

- **`bool over; // out of the flow, laid over the parent's box, drawn after its other children`**,
  a SETTINGS field on `UIElement` beside `fill`. An element `over` takes no room in its parent's
  layout and is arranged to the parent's whole rectangle (its own margin inside it); it scrolls
  with nothing; it paints after every other child of the parent, those `over` in their order, and
  hit-tests first, as the last painted. Its children lay out inside it as any element's.
- A dimmed pane with its number large in the middle is then a panel `over` the pane, its `bg`
  see-through, centring a label whose `font_size` is the size wanted.
- **Rejected**: a z-index (one more order beside the tree's, for one use); an absolute rectangle
  (the app would copy the layout it lays over); a second screen holding a tree of the panes'
  splits (the window's layout copied, the status line's height with it).

## What pcb does with it (pcb's, not this spec's)

After the landing pcb pins `extern/cetra`. `look` reads a pane through `engine_read_window` at its
element's `rect`, the whole window at the window's, the agent's own layout or sheet through
`canvas_read_picture`, its own 3D through an offscreen scene view waited on until `finished`; each
cut to at most 1500 pixels a side and sent as PNG. While `iconified`, `look` answers its state and
refuses pictures, saying why. Space i lays a panel `over` each pane.

## Phases

Each records "As built" in this file and commits it; verification is scoped to what the phase can
reach (`AGENTS.md`, Verifying).

0. **The spec**, this file, committed alone; `docs/eda-roadmap.md` gains a row for pictures read
   back, started, and the element over its parent under "Not among the nine".
1. **Pictures**: `Picture`, `engine_read_window`, `canvas_read_picture`, offscreen scene views and
   `scene_view_read_picture`; `apps/canvas` gains switches that read each kind and write it as a
   PPM beside its screenshot.
2. **The window that cannot draw**: `iconified`, the branch, the update hook on it, reads answered
   NULL.
3. **The element over its parent**: `over`, its layout, painting and hit order; `apps/canvas`
   gains a switch laying a dimmed panel with a large number over each of its panes.
4. **The gates**, in the canvas group, each falsified:
   - a window read: the rectangle's picture against the same rectangle cut from the run's
     screenshot, 0 px; a rectangle past the window's edge clipped;
   - a canvas picture: a pane's view read at the window's ratio against the pane's pixels in the
     screenshot, 0 px; at half the ratio, half the size; the window's screenshot unchanged by the
     read, 0 px;
   - an offscreen scene view: the window's screenshot against a run without it, 0 px; its picture
     at rest against the same view shown in the window and read, at the noise floor of two runs;
   - an element over its parent: its rectangle the parent's; the siblings' rectangles as without
     it; its colour at the parent's middle.
   The window that cannot draw cannot be reached headless; it is checked in the look.
5. **The look**: `apps/canvas` in a window with the panels over its panes, and its pictures written
   and opened; minimized while an `engine_request_frame_after` keeps asking, its update seen
   running, nothing drawn; shown to the user.
6. **The docs**: `docs/architecture.md` (pictures read back, the window that cannot draw),
   `docs/canvas.md` (a view read off the screen), `docs/ui.md` (an element over its parent),
   `docs/eda-roadmap.md` (the row built), `CHANGELOG.md`.
7. **The reviews**: code-quality reviews as background agents at effort high, applied once all are
   back; the canvas group whole; goldens.

**Then**, with the user's say-so, master fast-forwards and is pushed, and pcb pins `extern/cetra`
to it.

## Not in this spec

A picture read in the background without a frame drawn; pictures in a format other than RGBA8;
a scene view drawn off the screen without the window's context; a second window; a hook while the
window cannot draw other than the update hook.

### Phase 1: pictures

`9741fc23`. As designed, with these settled in the building:
- **`Picture` and `gl_read_picture`** (`util.h`): the one read every picture goes through -- a
  rectangle of a framebuffer, rows flipped to run from the top, alpha set to 255 as what is shown is
  opaque. `canvas.h` and `scene_view.h` name it `struct Picture`, so neither pulls GL in.
- **`engine_read_window`** keeps up to 8 reads on `Engine.reads` (BY FUNCTION) and serves them at
  the screenshot's place, after the frame's close and count and before the periodic and final
  screenshots: a read asked from a hook is that frame's. A read asked from a `done` waits for the
  next frame. A read still waiting when `engine_run` returns is answered NULL there, not when the
  engine is freed, so no callback runs during teardown.
- **`canvas_read_picture`** shares `canvas_draw`'s body (`_draw_view`, the rectangle rounded by
  `_view_pixels`): the layers into the canvas's target, then the composite program into the
  picture's own RGBA8 target at its origin instead of the bound framebuffer. A picture larger than
  any pane grows the canvas's shared target, which never shrinks, as a larger pane would.
- **An offscreen scene view** takes its pixels from `width`, `height` and its ratio, its rectangle's
  place unused; `fills_window` still wins. It is skipped by the window's copy and by
  `engine_view_at`. `SceneViewDesc` takes `offscreen` and `pixels_per_point` too, so a view is
  built at its size at once.
- **`scene_view_read_picture`** copies the shown picture -- the held TAA picture while a young
  average holds too few frames, as the window shows -- through the window's own present copy, the
  outline overlay laid on, into an RGBA8 target of its size, and reads that. A view's state gained
  `pictured`, set when its chain draws and cleared when its targets are remade, for "before the
  view has drawn".
- **`apps/canvas`**: `src/pictures.c`, the four switches (`--read-window`, `--read-canvas`,
  `--read-view3d`, `--offscreen-view`), each read from the overlay that draws the canvas and written
  as a PPM every frame, each saying once where its picture stands in the framebuffer.
- **Checked, headless, the board sheet with `--view3d`, 4 frames** (on the Mac's 2x framebuffer,
  1920 by 1200): the window read of 200 by 150 points at (10, 20) against the same 400 by 300
  pixels cut from the screenshot, the canvas picture at the window's ratio against its pane, the 3D
  pane's picture against its pane, and the offscreen view's picture against the 3D pane's: each 0
  pixels differ, the screenshot holding 19,291 colours. The screenshot with the offscreen view
  against one without it: 0 pixels. The canvas read at 1 pixel a point: 480 by 600, the board whole.

### Phase 2: the window that cannot draw

`e05adf87`. As designed, with these settled in the building:
- **`Engine.iconified`**, ENGINE-OWNED beside the sizes, set by `_engine_iconify_callback`; restored,
  the window asks for a frame, so an idle loop draws at once.
- **The branch** runs the update hook with the turn's `dt` (the fixed step headless, as a drawn
  frame's), answers the window reads waiting NULL, closes the frame's count, clears the latches and
  waits in `_engine_undrawn_wait`: until an event, another thread's request (it raises `waiting`, so
  `engine_request_frame` posts its empty event) or the soonest timed wake, at most 0.1 s for a loop
  not idle. Under idle mode a request already standing -- the update hook asking every turn, as the
  canvas app's does -- starts the next turn a frame's time after this one began, so it cannot spin
  a core. A loop not idle never clears its requests, so the wait reads them only under idle mode:
  read there too, every turn ran at the frame-time cap.
- **The game layer's update runs while minimized now on every system**, as it already did on macOS,
  where a minimized window drew on, throttled, with every hook. A game that should pause reads
  `iconified`.
- **A hidden window can be minimized on macOS**: headless, the callback comes and the branch runs.
  But it plays the Dock's animation on the person's screen, and a headless turn does not wait, so
  the frame limit comes before the restore's animation ends. So no gate minimizes; this is checked
  in a window instead.
- **`apps/canvas --minimize N`** minimizes the window after its second frame (asking frames until
  then, so an idle loop reaches it), asks a timed wake of 0.05 s every update and one window read,
  says each update with the time since the last and anything drawn meanwhile, restores after N and
  ends the run once drawn again.
- **Checked in a window**, 8 updates minimized: not idle, an update every 0.050 to 0.052 s, as the
  timed wake asks; under idle mode, every 0.017 to 0.035 s, at the cap, as the app's update asks for
  frames; in both, nothing drawn, the read answered NULL with `iconified` 1, and the window restored
  and drawn.
