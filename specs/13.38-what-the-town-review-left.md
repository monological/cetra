# Spec 13.38: what the town review left

## Context

Spec 13.35 (silent's town edges, merged at `11c0c820`) ended with eight items its review left for a
decision, each recorded in `specs/13.35-silent-town-edges.md` "For the user to decide". The user has
asked for all eight to be fixed:

1. **Conifer wind.** Two invisible anchor vertices give a conifer's bark and needles one Y range.
2. **Broadleaf leaf roughness.** The broadleaf atlas may have the grazing-sheen problem the needles had.
3. **Graph changes.** Adding or removing any node redraws every cached shadow face.
4. **Draw distance.** The engine has none.
5. **LOD bias.** Silent sets an engine-wide 0.045 that the GUI slider (floor 0.25) cannot reach.
6. **Tree colliders.** Silent's dead-tree, conifer and deadfall colliders disagree.
7. **TreeParams.** The struct mixes the recursive and conifer forms.
8. **Tree viewer.** It has no conifer controls.

Exploration found more than the list said:
- **Item 1 is two problems, not one.**
  - Lean is normalised by the plain mesh AABB (`wind.glsl:104-112`), the same box LOD reads.
  - A material's `wind_response` scales the whole sway. Silent's needles take 1.7x the wood, forest
    1.56x, the render app 2.9x. Equal ranges alone do not keep leaves on their branches.
  - **Decided with the user:** a tree's wood and leaves share one response. A new per-material
    **flutter** carries the leaves' extra motion as a pivot about each stem.
- **Item 3 needs a keyed diff.** The tile cache matches items by list position, so one insertion
  makes every later item look changed.
- **Item 4 is camera-pass only.** A distance cut on the kept tiles would make them depend on the
  camera and churn.
- **Item 6 is wider than 0.25 m.** Four of the six dead models get a collider 11-20% too thin, no
  box follows its tree's lean, and the conifer boxes have a fixed width.

Spec number: 13.34 is in flight (the loading screen), and 13.36/13.37 are reserved by 13.35 for the
street's dressing and the lake, so this is **13.38**.

## Phase 6: graph changes redraw only what they touch (item 3)

In `shadow.c`, `tiles_note_changes` (:2063-2083).

**Identity:**
- `SceneNode` gains an ENGINE-OWNED `uint64_t serial` from a global counter in `create_node`.
  Addresses can be reused after `free_node` (ABA), so they can't serve.
- `Mesh` gains an `upload_count` bumped by `mesh_upload`.
- `ShadowTileSeen` (`shadow.h:215-228`) records serial, `Mesh.id`, upload count, and the world box
  as drawn into the kept faces.

**On an epoch change, or a list differing in position:**
- Sort last pass's and this pass's KEPT casters by (serial, mesh id) and merge.
- A removed key marks INVALIDATE|UNSTORE at its recorded box.
- An added key does the same at its current box.
- A changed upload count marks both boxes.
- Items rejected as casters both before and after are skipped.
- Movers are matched by serial rather than pointer, and a vanished mover marks its last box.
- `tile_generation` is not bumped; it stays the lost-array signal.
- The full redraw remains only as the fallback for an unbounded item or OOM.
- The positional fast path stays for frames with no change.

**Cost:** compute each block's face frustums once per frame when a batch of boxes is marked.

**Comments:** fix the stale one at `scene.h:208-216`.

**Gate:** a render-app flag `--graph-churn N` hangs and unhangs a node every N frames. New
`shadow-tiles` arms:
- churn far from every cached light draws 0 faces again;
- churn inside one light's reach redraws only that light's touched faces, and the frame matches a
  fresh load at 0 px;
- remove plus add of the same mesh at a new place (the ABA case) moves its shadow.

Run `--only shadow-tiles lighting-stream`.

### Phase 6 as built (`d16d1431`)

**Identity:**
- `SceneNode.serial`, ENGINE-OWNED, from a counter in `create_node`.
- `Mesh.upload_count`, bumped by `mesh_upload`.
- **`create_node` is now `calloc`.** It used to `malloc` and set fields one by one, and it
  never set `capture_hidden`, so a fresh node's flag was whatever the allocator left there. That
  was a live bug found on the way, and it is fixed here by the same change that zeroes the new
  fields.

**`ShadowTileSeen`:**
- It holds no pointer any more. It records the node serial, the mesh id and upload count, the
  looks as before (lane, flags, shape hash, offset bound), whether a kept face takes the item,
  and the world box it was drawn in.
- The box is kept current in three places: at a graph-change record, when an item's look
  changes, and in the movers loop for every caster that moves (a still one that moved, and every
  non-still one each frame).
- `tile_movers` holds serials.

**`tiles_note_changes`:**
- With the same epoch and the same items in place, it is the positional path as before.
- Otherwise `tiles_mark_graph_change` runs:
  - it sorts both lists by (serial, mesh id) and merges them;
  - a gone item marks its recorded box INVALIDATE|UNSTORE, and a new one its current box;
  - a held item whose looks or upload count changed marks both;
  - movers whose serial is gone are let go;
  - `tile_generation` is not touched.
- The full redraw remains only for memory or a caster with no bound.

**The render app:**
- `--graph-churn <node> <out> <back>` takes a node out of the graph and puts it back, freeing it
  at exit if it is still out.
- `--graph-replace <node> <frame> <dx,dy,dz>` frees a node and hangs a new one with refs to its
  meshes, moved. It frees first, so the new node may take the old address.

**Arms, in `shadow-tiles`:** all pass, alongside the group's other 21 and `lighting-stream`'s 11.
- `tiles-graph-near`: 3 of 6 faces drawn again, generation 0, 0 px from the box removed at
  load.
- `tiles-graph-far`: the lamp moved to a corner with a 0.3 m reach; 0 faces.
- `tiles-graph-back`: 0 px from never taken out.
- `tiles-graph-replace`: 0 px from `--tiles-refresh`, with 111,856 px moved.

**Falsified** by putting back "a graph change draws every face": near and far each draw 6 of 6,
and every arm reads generation 2.

**On the way, a test that was mine, not the code's.** A first "far" lamp with a 0.15-0.3 m reach
at the room's centre still drew 2-3 faces. A temporary print showed the diff marking only the
removed box. The box test is conservative: an AABB against a frustum is rejected only when it is
wholly outside one plane, and this box straddled the faces' side planes while lying past their
far plane. That over-covers and never under-covers, which is the rule for those tests. So the
arm's lamp went to a corner 1.4 m away.
