# Fix inverted desaturation in PBR Neutral tonemap

## Context

`render -m assets/cornell_leak.gltf` blows the floor to a flat white plateau. Lowering the
spot intensity from 6.0 to ~4.15 makes it go away, and so does switching the tonemapper to
AgX. It reproduces only under PBR Neutral, which is the engine default.

Root cause: `pbrNeutralTonemap` in `cetra/shaders/tonemap_frag.glsl:89` has the
desaturation blend factor inverted against the Khronos PBR Neutral reference.

```glsl
// Khronos reference
float g = 1. - 1. / (desaturation * (peak - newPeak) + 1.);
// tonemap_frag.glsl:89
float g =      1.0 / (desaturation * (peak - newPeak) + 1.0);
```

`g` is the weight toward pure white in the `mix` on the following line. The reference wants
`g -> 0` (keep colour) when compression is slight, rising toward 1 only as the highlight is
pushed hard. Dropping the `1. -` reverses that, so the slightest compression desaturates
almost fully:

| peak | newPeak | reference g | ours |
|------|---------|-------------|------|
| 0.80 | 0.794   | 0.001       | 0.999 |
| 1.00 | 0.880   | 0.018       | 0.982 |

Everything above the `startCompression` threshold (0.76) is therefore snapped ~98-100% to
white. The curve behaves as a hard clip at 0.76 rather than the gentle highlight roll-off
it is documented to be at `tonemap_frag.glsl:69-71`. That is the plateau: below 0.76 the
function returns early (line 82) and looks correct, which is why dimmer surfaces are fine
and why reducing intensity "fixes" it.

This is a correctness bug against a published spec, not a look preference. It is also the
reason the earlier suspicion fell on lighting: intensity and exposure both only mattered
because they moved values across the 0.76 cliff.

## Approach

### 1. Fix the term

`cetra/shaders/tonemap_frag.glsl:89` — restore `1.0 -`:

```glsl
float g = 1.0 - 1.0 / (desaturation * (peak - newPeak) + 1.0);
```

Nothing else in the function deviates from the reference: the `offset`/black-point block,
`startCompression`, `d`, and `newPeak` all match. Only this line changes.

Add a short comment recording that `g` is the weight toward white and that the leading
`1.0 -` is load-bearing, since the inverted form is silently plausible and produces a curve
that still looks like tonemapping.

### 2. Regenerate the goldens this moves

NEUTRAL is the engine default and every fixture's `.cscn` selects it, so this moves any
golden containing values above 0.76 — expect most or all nine. This is a deliberate,
correctness-driven move, so follow the 9.2/9.4/9.6 rule already recorded in the specs:
inspect at 1:1 before regenerating, never from a thumbnail.

Confirm per golden that the change is highlight roll-off appearing where a flat white
plateau used to be, and nothing else. Anything below 0.76 must be **bit-identical** — the
early return at line 82 guarantees it, and that is a cheap, strong check that the fix is
scoped to highlights.

### 3. Out of scope, deliberately

- **Photometric light units.** Still a legitimate improvement — real engines (UE5, Unity
  HDRP, Frostbite) do pair physical units with an EV-based camera, and it would stop
  intensity being an unportable bare multiplier under the legacy
  `1/(constant + linear*d + quadratic*d^2)` at `pbr_frag.glsl:437-439`. But it is **not**
  the fix for this, and bundling it would hide a one-line correctness fix inside a change
  that moves every light in the project. Track separately.
- **`.cscn` silently disabling auto-exposure.** An authored `post.exposure` pins the frame
  (`cscene.h:133-135`, `render.c:1463-1466`) with no log, which is why the GUI checkbox
  read unchecked with no explanation. A real footgun, worth a log line and an explicit
  `auto_exposure` key, but independent of this bug. Track separately.

## Verification

Measure the same-build noise floor first — two runs must compare 0 px before any A/B means
anything.

1. **The reported repro** — `render -m assets/cornell_leak.gltf` at the fixture's authored
   intensity 6.0 under NEUTRAL. The floor must show a gradient into the highlight instead
   of a flat plateau, and must look comparable to what AgX already produces.
2. **Below-threshold invariance** — a scene whose peak stays under 0.76 must render
   bit-identical (0 px) before and after. `backface_dark_golden` is the natural candidate
   (its spheres are pure black). This isolates the fix to highlights.
3. **Curve sanity, not eyeballing** — evaluate the fixed `g` at several peaks and confirm
   it rises from ~0 at the threshold toward 1 only for strong compression, matching the
   table above. A quick host-side or shader-debug evaluation is enough; the failure mode
   was an inverted monotonic term, so checking the direction is the test.
4. **Cross-check against AgX** — with the fix in, NEUTRAL and AgX should disagree on look
   (different curves, as intended) but agree that the hotspot retains structure. If NEUTRAL
   still plateaus, the diagnosis is wrong.
5. Regenerate goldens only after 1:1 inspection of each.

Note headless goldens pin exposure with `--no-auto-exposure -E 1.0`, so they exercise the
tonemap curve directly and are a good test of this fix — unlike the auto-exposure issue,
which goldens cannot catch.
