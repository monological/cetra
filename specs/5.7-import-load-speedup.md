# 5.7 Speed up scene loading — dedup materials + stop re-decoding embedded textures

## Context

Loading the `abandoned_window` scene is slow, and `import.c` is a confirmed contributor. Two
redundancies on the main-thread load path:

1. **Embedded textures re-decoded per mesh.** The GLB embeds all 14 images (verified: 14
   `image/png` blobs, zero external `textures/*.png` URIs), so every texture takes the synchronous
   `load_embedded_texture` path (`import.c:356`), which calls `stbi_load_from_memory` (`import.c:381`)
   to fully decode the PNG **before** the texture-pool cache is consulted (the cache-check is
   downstream in `load_texture_from_memory`, `texture.c:395`). The `IvyLeafReal` material is **one**
   glTF material shared by **483 meshes**, so its embedded texture is decoded on the main thread up
   to 483x -- only the GL upload is deduped, not the decode.
2. **No material dedup.** `process_ai_node_async` (`import.c:1528-1541`) builds a **new** cetra
   `Material` per mesh -- 483 duplicate `IvyLeafReal` Materials, each redoing ~30 `aiGetMaterial`
   property queries + a 13-slot texture-resolution loop + an O(n) `add_material_to_scene` scan
   (`scene.c:453`) + a mask-array layer.

Both are pure redundancy: fixing them changes **nothing visually** and also cuts memory + material
bloat. The earlier review fix (moving the wind mask off the shared `Material` onto a per-mesh
uniform) already makes material sharing safe. (The GPU IBL/probe bake is a separate, larger,
quality-affecting lever -- deliberately out of scope: "import cleanups only".)

## Design -- two low-risk fixes in `cetra/src/import.c`

### 1. Cache-check before decoding embedded textures
At the top of `load_embedded_texture` (`import.c:356`), after the `tex_index` validation and
**before** the `stbi_load_from_memory` decode (`import.c:379-382`):
```c
Texture* cached = get_texture_from_pool(tex_pool, tex_path);
if (cached)
    return cached;
```
`get_texture_from_pool` (`texture.c:255`) keys by string, and `tex_path` (e.g. `"*5"`) is the same
key `load_texture_from_memory` already uses (`texture.c:395`) -- so the 2nd..Nth call for a shared
embedded texture returns the cached `Texture*` immediately, skipping the decode + dilate pass. Same
colorspace semantics as the existing (later) cache-check, just earlier. (Shared by both load paths,
since `load_embedded_texture` is common.)

### 2. Dedup materials by glTF material index
Thread a transient `Material** mat_cache` (size `ai_scene->mNumMaterials`, `calloc`'d) through the
node recursion:
- Add a `Material** mat_cache` param to `process_ai_node_async` (`import.c:1512`); pass it in the
  recursive child call (`import.c:1568-1569`).
- Replace the per-mesh build (`import.c:1536-1541`) with a cache lookup:
  ```c
  unsigned int matIndex = ai_mesh->mMaterialIndex;
  if (matIndex < ai_scene->mNumMaterials) {
      Material* mat = mat_cache[matIndex];
      if (!mat) {
          mat = process_ai_material_async(ai_scene->mMaterials[matIndex], tex_pool, ai_scene, loader);
          mat_cache[matIndex] = mat;
          add_material_to_scene(scene, mat);
      }
      mesh->material = mat;
  }
  ```
- In `create_scene_from_model_path_async` (`import.c:1583`) allocate `mat_cache` before the root
  `process_ai_node_async` call, pass it, `free` it after.

Collapses ~500 Material builds -> ~15 (IvyLeafReal 483 -> 1): eliminates the redundant property
extraction, texture-resolution loops, embedded decodes (compounding with fix 1), the O(n^2)
`add_material_to_scene` scans, and duplicate mask layers. Safe: meshes already share `Material*`
(textures refcounted; `add_material_to_scene` dedups by pointer; per-mesh AABB stays on the Mesh;
the wind mask is already a per-mesh uniform).

### 3. Mirror fix 2 in the sync twin
Apply the same `mat_cache` dedup in `process_ai_node` / `create_scene_from_model_path` (the
loader-NULL fallback) to avoid divergence. (Fix 1 is automatically shared.)

## Files
- `cetra/src/import.c` -- the only file changed: cache-check in `load_embedded_texture`; the
  `mat_cache` param + dedup in `process_ai_node_async`/`create_scene_from_model_path_async`, mirrored
  in the sync `process_ai_node`/`create_scene_from_model_path`.

## Reuse
- `get_texture_from_pool` (`texture.c:255`) -- existing pool lookup.
- `add_material_to_scene` (`scene.c:449`) -- already dedups by pointer; the cache just avoids building
  the dup. No new data structures beyond a transient `Material**` scratch array.

## Verification
1. `./build.sh` clean.
2. **Load time before/after**: `time ./out/bin/render assets/abandoned_window/abandoned_window.cscn
   --headless --frames 2` (and read the log timestamps). Expect the import/decode phase to drop
   substantially (the 483x ivy decode -> 1; ~500 material builds -> ~15).
3. **Identical look**: `--headless --frames 300 --screenshot after.ppm`, diff against a pre-change
   capture -- curtains (wind), ivy (SSS), dust, walls render identically.
4. **SSS intact**: the `configure_sss_materials` log now reports IvyLeafReal tagging ~1 material (not
   483), and the ivy still shows subsurface scattering.
5. **No regression**: load a multi-material model headless -- materials/textures still correct, no
   missing textures.

## Risks
- Material dedup relies on safe `Material*` sharing -- verified (per-mesh geometry on the Mesh, wind
  mask already a per-mesh uniform). Any future per-mesh material state would need per-mesh storage.
- Texture cache-check keyed by the embedded-index string, matching the existing downstream key -- same
  behavior, just earlier.
