# Spec 11.105 — An app outside the tree: cetra as a submodule

## Context

Every app that uses the engine lives inside its repository, and the one that does not
(`apps/pcb`) is smuggled in through `apps/.gitignore` and a manifest glob. Nothing documents how
a project of its own consumes the engine, and the three ways a reader might guess are in three
states: `add_subdirectory` works but nobody has said so; `install()` exists in
`cetra/CMakeLists.txt:131-141` but has no export set, installs none of the seven dependencies
the static library links, and does not install the generated shader header, so an installed tree
cannot even compile against; `find_package` does not exist. Three pre-existing sketches in
`../apps` (pcb, globe, network — 2023-2024, one file each, every CMakeLists fetching GLFW by hand)
are the first real consumers and will each become their own repository with cetra at
`extern/cetra`.

Exploration found three engine-side defects a consumer meets before writing a line:

1. **`cetra/src/shader.h:6` includes the generated `shader_strings.h`**, and `shader.h` is
   reached from `engine.h`, `scene.h`, `render.h` and `program.h`. Every TU that includes
   `cetra/engine.h` therefore compiles 2.1 MB of `static const char*` literals, a `.glsl` edit
   recompiles every such TU, and a consumer's object depends on a file nothing orders before it
   (in-tree, `apps/CMakeLists.txt:13`'s `add_dependencies(... cetra_shaders)` papers over exactly
   this). The only reader of those symbols is `cetra/src/program.c`.
2. **Output directories are written to `CMAKE_BINARY_DIR`** (`CMakeLists.txt:97-99`,
   `cetra/CMakeLists.txt:17`), which under a parent project is the CONSUMER's build root: the
   engine's `libcetra.a`, every vendored `.a`, the forwarding-header tree and the generated
   header all land in the consumer's `build/lib`, `build/bin`, `build/include`.
3. **`CETRA_BUILD_APPS` defaults ON** (`CMakeLists.txt:93`), so a consumer that forgets it builds
   all seven example apps into its own tree.

Decisions: **submodule / FetchContent only** (no install, no `find_package`; the half-built install
rule is deleted with the reason in the file); **port all three `../apps`** onto the new path, after
the engine change lands; and **nothing new in this repository beyond the fixes and the README
section** — no template project and no check script. The first draft of this spec carried both and
they were struck as bloat: the three ported apps are the proof, and the repo's own check is a
throwaway consumer built by hand, recorded below.

## The design

**Consumer contract, eight lines**, and it is the whole README section:

```cmake
cmake_minimum_required(VERSION 3.25)
project(myapp LANGUAGES C CXX)     # CXX too: Jolt, ImGui and draco are C++, and so is the link
set(CMAKE_C_STANDARD 11)
add_subdirectory(extern/cetra)
add_executable(myapp src/main.c)
target_link_libraries(myapp PRIVATE cetra)
```

`LANGUAGES C` alone fails at LINK, not configure: CMake picks the link driver among the languages
enabled in the consumer's directory, so a C-only project links Jolt/cimgui/draco objects with the
C driver and the C++ runtime is undefined. The README says so.

**What NOT to fix, recorded rather than churned**: `BUILD_SHARED_LIBS` forced OFF in the cache
(`CMakeLists.txt:150`) and cglm building a shared library nobody links — seven vendored builds on
three platforms are not worth touching for a consumer who can write `SHARED`. Two consumers in one
superproject collide on target names (`if(NOT TARGET cetra)` is their guard). **`CETRA_BUILD_JOLTC=OFF`
is not a working configuration today** — `cetra/src/game/physics.c:3` includes `JoltC/JoltC.h`
unconditionally and the include path is only added inside the `if` — so the README does not
advertise it; recorded as a finding, out of scope.

### Engine changes (four files)

- `cetra/src/shader.h`: delete line 6. `cetra/src/program.c`: `#include "shader_strings.h"` after
  `program.h` with a comment (the one TU that reads the generated strings; a public header that
  included it put 2 MB of literals into every consumer TU and rebuilt the world on a `.glsl` edit).
  `apps/render/src/render.c:44`: delete (vestigial, uses no symbol). `apps/CMakeLists.txt:10-13`:
  delete the `add_dependencies` and its comment — `add_dependencies(cetra cetra_shaders)` at
  `cetra/CMakeLists.txt:78` orders generation before `program.c`, and an app now reaches the header
  only through `libcetra`. `cetra/CMakeLists.txt:87-89`: the `${CETRA_PUBLIC_INCLUDE_DIR}/cetra`
  entry moves to `target_include_directories(cetra PRIVATE ...)`.
- `CMakeLists.txt:93`: `option(CETRA_BUILD_APPS "..." ${PROJECT_IS_TOP_LEVEL})`. In-tree unchanged
  (TRUE); under a parent OFF.
- `CMakeLists.txt:97-99` and `cetra/CMakeLists.txt:17`: `${PROJECT_BINARY_DIR}`. In-tree
  `PROJECT_BINARY_DIR == CMAKE_BINARY_DIR == out` at the root and in `cetra/` (no `project()` there),
  so `out/bin`, `out/lib`, `out/include` are byte-identical; under a parent they become
  `build/cetra/{bin,lib,include}`. **Line 212 `include_directories(${CMAKE_BINARY_DIR})` stays** —
  draco writes `draco_features.h` to `CMAKE_BINARY_DIR` (`contrib/draco/CMakeLists.txt:27`) and the
  two must agree; add the sentence. Nothing else references `out/lib` or `out/include`
  (`.clangd`, `gates.py:61-72`, `goldens.py:60` use `out` / `out/bin`; grep-verified).
- `cetra/CMakeLists.txt:90` (`$<INSTALL_INTERFACE>`) and `131-141` (both `install()` calls): deleted,
  replaced by a comment: no export set so nothing could `find_package` it; none of the seven
  dependencies installed while five of their own install rules (glfw, glew, cglm, cimgui, JoltC)
  were still live and would fire under a consumer's `cmake --install`; the generated header not
  installed. The supported path is `add_subdirectory`; a real install is its own spec.

## After the merge: the three ports (each its own repository, outside this repo's commits)

**Repository setup, per app**, in `../apps/<name>` (none is a git repo today; `../apps` is not either):

```
git init -b master
git -c protocol.file.allow=always submodule add <abs path of this checkout> extern/cetra
# edit .gitmodules -> url = https://github.com/monological/cetra   (the portable URL)
# .git/config keeps the local path: that is the override, so unpushed engine commits are
# reachable; never `git submodule sync` (it copies .gitmodules back over it); re-apply with
# git config submodule.extern/cetra.url <abs path>
git -c protocol.file.allow=always submodule update --init --recursive   # nested deps from GitHub, ~0.5 GB once per app
# CMakeLists.txt = the eight lines with project(<name>); .gitignore: build/ cooked/ imgui.ini
# cetra_config.json *.ppm .DS_Store; src/main.c
git add .gitmodules extern/cetra CMakeLists.txt .gitignore src ; commit
```

Build: `cmake -S . -B build -G Ninja`, `cmake --build build`, `./build/<name>`. Push cetra's master
before pushing any app repo (the pinned sha must be reachable on GitHub for anyone else). Bumping
the engine: checkout inside `extern/cetra`, `git add extern/cetra`, commit; a new engine commit needs a
manual reconfigure (a submodule's `.git` is a file, so `CMakeLists.txt:68-73`'s `CONFIGURE_DEPENDS`
on `.git/HEAD` is inert there).

**pcb** (~1 day). `src/main.c` from the local `apps/pcb/src/pcb.c` (already a cetra port: rects,
circles, beziers, ortho camera at z=300, canvas pan on empty-space drag, shape drag, 2D preset),
plus the two things the 2023 sketch has that it lacks: scroll zoom about the cursor
(`set_engine_scroll_callback`, `engine.h:512`: cursor → framebuffer pixels by the engine's own
`win_width`/`fb_width` formula, `engine.c:1109-1110` → world under cursor for the square-on ortho
camera `w = look_at + (fb - fb_size/2) * ortho_height/fb_height`; `h' = clamp(h * 0.9^yoffset, 5,
5000)`; shift `position` and `look_at` by `(w - look_at) * (1 - h'/h)`; `set_camera_orthographic`
and the existing pre-render rebuilds the projection), and per-corner handles (four filled circles at
z=+1 so the nearest-hit pick prefers them, four ring outlines, four two-vertex `MESH_LINES` edges each
with its own shape material for the sketch's per-vertex colours; drag a handle → move handle + ring
`original_transform[3]`, rewrite the two adjacent edges' vertices, `calculate_aabb`,
`upload_mesh_buffers_to_gpu`, which re-uploads in place, `mesh.c:327-345`). Then, one commit on
master: delete the two local files under `apps/pcb/` (plain `rm` of the named files, then `rmdir`;
never `rm -rf`), delete `apps/.gitignore` (its only line is `pcb`), keep `apps/CMakeLists.txt`'s
discovery mechanism and reword its comment to "a private app can be kept out with an `apps/.gitignore`
entry", and point AGENTS.md at the external repo. **The move precedes the delete**: `pcb.c` exists only
on this machine.

**globe** (½–1 day). Perspective camera 45° at `(0,0,5)`, radius 1 (the sketch's 0.2 is 10% of the
frame — a choice, say so). `create_particle_program` + `add_shader_program_to_engine` (`init_engine`
registers only pbr/shape/xyz; `spores.c:236-237` is the precedent); `create_particle_system` on
`create_cpu_particle_sim_backend()` — **custom modules run only on the CPU backend**
(`particle_module.h:66-68`); `create_particle_emitter("globe", 540)` with the billboard renderer,
`billboard_renderer_set_sprite(r, NULL, 1.0f)` to drop the 6.0 HDR gain; `particle_module_init_lifetime
(1e9f, 1e9f)` so slots stay stable; three app-side `ParticleModule`s (`particle_module.h:31-37`, the
function type at `:28`): spawn-once (540 on the first call), init-on-sphere (the sketch's
`acos(2u-1)-π/2`, `2πv` placement, base xyz + jitter state in the module's params), update (y = base
+ lerp(jitter, target, t) with the one-second retarget; rotate the base point about X by `ω·t` into
`pool->position` — particles are spawned into world space and do not follow their node,
`particle_system.h:39-44`, so the spin lives here; size from z; a fresh random colour per step). The
sketch's cumulative-angle bug is not reproduced; note it.

**network** (½ day). C on cglm. `generate_sphere_to_mesh` (`geometry.h:59-64, 79`), unique edges from
the triangle indices (pack `(min,max)`, `qsort`, dedupe) replacing `indices`, `set_mesh_draw_mode(mesh,
MESH_LINES)`, 1 px lines (`glLineWidth` is a core-profile error, as it was for the sketch). **The
rainbow shader survives**: `create_program_from_source("network", vert, frag, NULL)` (`program.h:91`)
with the sketch's GLSL unchanged — position is attribute 0 (`common.h:6`) and `render.c:483-484, 675`
set `model`/`view`/`projection` BY NAME while every other engine uniform is a silent no-op on a
program that lacks it (`uniform.c:96`); `add_shader_program_to_engine`; `set_material_shader_program`.
Per frame in the pre-render hook: `glm_rotate_make` + `glm_scale_uni` on the node's
`original_transform`, then `glUseProgram(prog->id)` and `uniform_set_float(prog->uniforms, "time",
engine->render_time)` (the cache's only contract is "set with the program bound", `uniform.h:27-30`;
the hook forbids drawing, not binding). `engine_set_2d_defaults` so the `sin()` colours land as
authored. Recorded alternative: the `shape` program for thick one-colour lines, refused because its
geometry shader expands in the XY plane (`shape_geo.glsl:16`) and looks wrong on a rotating sphere.

## Risks

- **FetchContent with `URL`** fails at the first vendored `add_subdirectory` — no submodules in a
  tarball — before the version check matters. README says `GIT_REPOSITORY`.
- **Cache pollution**: `BUILD_SHARED_LIBS`, `ONLY_LIBS`, `IMGUI_STATIC`, the Jolt `USE_*` ISA switches,
  `DEBUG_RENDERER_IN_DISTRIBUTION`, and on MSVC `CMAKE_MSVC_RUNTIME_LIBRARY` land FORCE'd in the
  consumer's cache. Only the first changes a consumer's own targets; documented.
- **Ninja is what is tested**; Xcode/VS generators are unverified and said so.
- **`build/draco/draco_features.h` and `build/compile_commands.json`** appear in the consumer's build
  root: draco writes to `CMAKE_BINARY_DIR`, and cetra's `CMAKE_EXPORT_COMPILE_COMMANDS ON` is
  directory-scoped, so the engine's own compile commands land there whatever the consumer sets.
- **Linux gcc rejects JoltC**; the README passes clang, as the presets do.

### Phase 4: docs, and the reviews

Two reviews in background agents, the strict quality audit and the four-angle cleanup pass, both
against the code diff. They agreed on four findings and all four were applied:

1. **The PRIVATE include directory hid one spelling, not the file.** The generated header was still
   written under the public include tree, so `#include "cetra/shader_strings.h"` resolved for every
   app and consumer, and three comments claimed a guarantee the layout did not give. Fix: the header
   is generated into `out/generated/` (under the parent, `build/cetra/generated/`), a directory only
   the library searches. Both reviews also corrected the spec's own reasoning: under Ninja a
   consumer's objects were already ordered after the library's, so the defect was the 2 MB copy and
   the rebuild-the-world on a `.glsl` edit, never a race.
2. **The `cetra_shaders` custom target had one consumer left.** Listing the generated header among
   the library's sources gives the same ordering; the target and the `add_dependencies` are gone.
3. **Five `$<BUILD_INTERFACE:>` wrappers were dead** once the last `INSTALL_INTERFACE` and the
   install rules went; bare paths now, as the rest of the file already used.
4. **The install comment's counts were wrong, and two of the hazards it described had switches.**
   Jolt has an install rule too, with `ENABLE_INSTALL` defaulting on, and GLFW has `GLFW_INSTALL`;
   both are forced off beside the other vendored switches in the root CMakeLists, the way assimp's
   and meshoptimizer's already were. The comment names the four that have no switch (GLEW, cglm,
   cimgui, JoltC) and carries no numbers.

Two doc corrections from the same pass: the engine does open a file of its own at runtime, Dear
ImGui's `imgui.ini` in the working directory, so the README says so; and `compile_commands.json`
lands in a consumer's build root regardless of what the consumer sets, since the switch is
directory-scoped in cetra's root — the risk row above had it backwards.

After the fixes: `./build.sh` clean; a fresh consumer build **669 steps, 35.7 s**, no `build/bin`
or `build/lib`, the header only under `build/cetra/generated/` and absent from the public tree,
`main.c.o` free of it, frame centre (255, 0, 0), corner (90, 90, 90).

### The ports, after the merge

Merged to master at `f919d02b`, fast-forward. Each of the three sketches in `../apps` is now a
git repository of its own: the sketch as it was is the first commit, the port the second, with
cetra as a submodule at `extern/cetra` pinned to `f919d02b`, the public URL in `.gitmodules` and

  unique edges, `time` set in the pre-render hook with the program bound. The frame shows the
  wireframe with the per-pixel sine colouring.

Nothing is pushed: neither master nor the three repositories. Pushing any app repo before master
leaves its pinned submodule commit unreachable for anyone but this machine.
