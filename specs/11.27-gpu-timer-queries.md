# E4 — GPU timer queries + per-pass HUD

## Context

**Wall 3 of the Tier 4 preamble: the GPU is unmeasured.** There is not one `glGenQueries`,
`GL_TIME_ELAPSED` or `glQueryCounter` in `cetra/src` outside the vendored deps, and the HUD shows
FPS and nothing else. Every perf number in every spec in this tree — 44 → 22 ms at 0.67 render
scale, the 73.6 ms cloud re-bake — is **wall-clock time measured around the whole frame**
(`engine.c:2077-2089`, a 0.5 s bucket average).

That was adequate while the question was "did this feature cost anything". It cannot answer "which
of these 33 post passes should lose 2 ms", which is what a Tier 4 perf budget asks. The roadmap
calls this the cheapest wall to remove and notes it **gates the honesty of everything in Track E's
tail** — E5 (instancing/LOD) is unmeasurable without it.

Intended outcome: a per-pass millisecond breakdown, in the HUD live and on stdout headless, at a
granularity that names every pass the renderer actually issues.

## The platform risk, and why the design has two backends

This engine runs `OpenGL 4.1 Metal - 90.5` on `Apple M1 Max` — Apple's OpenGL-over-Metal
translation layer, the only platform it targets. GLEW exposes the timer-query entry points and GL
4.1 core is well above the 3.3 that `ARB_timer_query` needs, so **it compiles**. Whether Apple's
driver returns real numbers rather than zeros is unknown until measured, and that is a known
failure mode of this driver.

So the profiler carries **one seam and two backends**, chosen by a probe at init:

| backend | how | when |
|---|---|---|
| `GL timer queries` | `glBeginQuery(GL_TIME_ELAPSED)` / `glEndQuery`, results read N frames later | probe says the driver works |
| `CPU + glFinish` | `glFinish()` then a CPU timestamp at each scope edge | probe says it does not |

The fallback **serializes the GPU**, so its absolute total is inflated and does not equal frame
time — but relative per-pass cost stays honest, which is the actual question. The HUD and the
stdout report both print which backend produced the numbers, so the two can never be confused:

```
GPU Timing  [backend: GL timer queries]
GPU Timing  [backend: CPU+glFinish -- SERIALIZED, totals inflated]
```

### Probe result — measured before any other code was written

| probe | result |
|---|---|
| `GLEW_ARB_timer_query` | **1** — present |
| `glGetInteger64v(GL_TIMESTAMP)` | **0**, twice, either side of a flush — **not implemented** |
| `GL_TIME_ELAPSED` around `engine_present_frame` | **14.6 ms**, stable across 6 frames, `glGetError() == 0` |
| the same, with `--no-bloom --no-ssao --no-ssr` | **0.118 ms** |

**`GL_TIME_ELAPSED` works on this driver; `GL_TIMESTAMP` does not.** The 124x collapse when three
post passes are switched off is what makes the first number a measurement rather than a plausible
constant — it was checked precisely because a resolution change did *not* move it, and a number
that does not move has not been shown to measure anything.

Two consequences:

- **The probe in the original design was wrong and would have failed the good path.** It tested
  `glGetInteger64v(GL_TIMESTAMP)`, which returns 0 here, and would have latched the serializing
  CPU fallback on a driver whose scoped queries are fine. The probe is instead: check
  `GLEW_ARB_timer_query`, then run real `GL_TIME_ELAPSED` scopes and fall back only if the first
  few instrumented frames come back all-zero. Capability is asserted from the primitive actually
  used, never from a neighbouring one.
- **Flat scopes were right for a second reason.** The nesting-capable primitive is the one this
  driver does not implement, so hierarchy was never on the table here regardless of preference.

The CPU+glFinish backend is still built, but as insurance for other drivers rather than the active
path on this machine.

## Design

### Flat scopes, not nested — and why

`GL_TIME_ELAPSED` queries **cannot nest** (one active query per target). `GL_TIMESTAMP` /
`glQueryCounter` can, and is the usual choice for hierarchical profilers — but it is the *less*
reliable of the two on Apple's driver, which is exactly the platform at risk.

Resolution: **a flat list of non-overlapping scopes in execution order.** SSR contributes either
one `postfx ssr` row *or* five sibling rows (`ssr hiz`, `ssr march`, `ssr accum`, `ssr atrous`,
`ssr composite`) — never both. This is sufficient for a per-pass budget, works identically under
both backends, keeps the sum meaningful, and deletes the nesting question. Hierarchy is listed
under *Deliberately deferred*.

### `cetra/src/gpu_profiler.h` / `.c` (new)

Modelled on `cetra/src/ltc.h` / `ltc.c` — the smallest complete subsystem in the tree: header
guard, a block comment stating why the thing exists at this lifetime, `create_*` returning NULL on
failure, `free_*` with the null-guard-then-delete shape, operations taking the struct first.

```c
struct GPUProfiler;                       // opaque; engine.h forward-declares like LightClusterContext

GPUProfiler* create_gpu_profiler(void);   // NULL on failure; runs the backend probe
void free_gpu_profiler(GPUProfiler*);

void gpu_profiler_begin_frame(GPUProfiler*);   // retires the oldest ready ring slot
void gpu_profiler_end_frame(GPUProfiler*);
void gpu_profiler_scope_begin(GPUProfiler*, const char* name);  // static literal, never copied
void gpu_profiler_scope_end(GPUProfiler*);

int         gpu_profiler_row_count(const GPUProfiler*);
const char* gpu_profiler_row_name(const GPUProfiler*, int i);
float       gpu_profiler_row_ms(const GPUProfiler*, int i);
float       gpu_profiler_total_ms(const GPUProfiler*);
const char* gpu_profiler_backend(const GPUProfiler*);
void        gpu_profiler_report(const GPUProfiler*);  // stdout table, for headless
```

- **Ring of 4 frames** of query objects. Results are read from frame *N−3* and only when
  `GL_QUERY_RESULT_AVAILABLE` — never a blocking `glGetQueryObject` on the current frame, which
  would stall exactly what it is measuring.
- **Fixed capacity** (`GPU_PROFILER_MAX_SCOPES 64`), names are static string literals stored by
  pointer. No allocation per frame, no strdup.
- **Smoothing matches the existing FPS idiom** — a 0.5 s latch (`engine.c:2085`), accumulating
  per-scope sums and dividing on expiry, rather than a per-frame raw number. A raw per-frame ms
  readout would be the first unsmoothed number in the HUD and is unreadable.
- **Disabled is free**: every entry point early-returns on a NULL profiler, and the profiler is
  only created when the flag is on. The off path issues no GL calls at all.

### Instrumentation sites

Scope names reuse the strings already passed to `check_gl_error` at each pass, so the table and the
error messages name passes identically.

| file | scopes |
|---|---|
| `cetra/src/engine.c` (`engine_run` :2062) | `gi capture` :2185, `shadows` :2190, `scene clear` :2229, `scene` :2256, `postfx` :2263, `gui` (in `engine_present_frame` :1668) |
| `cetra/src/render.c` (`render_current_scene` :688) | `cluster build` :727, `clouds` :816, `opaque` :836, `skybox` :846, `catcher` :874, `refraction resolve` :963, `moment gen` :995, `oit accum` :1004, `transparent` :1019, `depth resolve` :1041, `particles` :1049 |
| `cetra/src/postfx.c` (`postfx_run` :2666) | the ~33 passes, in order: MSAA resolve :2686, OIT composite :2693, the five G-buffer resolves :2721-2767, contact shadows :2789, GTAO :2865, AO accum/blur :2921-2946, spec-occ :2952, TAAU/TAA seam :2977-3003, SSGI accum/a-trous/composite :3013-3052, SSR :3030, atmosphere :3055, SSS :3062, motion blur :3068, DoF :3074, exposure metering :3096, bloom :3128, flare :3129, tonemap :3232 |
| `cetra/src/shadow.c` (`render_shadow_depth_pass` :1080) | `shadow cascades` :1335, `shadow punctual` :1350, `shadow msm` :1386, `shadow tsm` :1387 |

**Exposure metering gets its own scope and a comment.** It ends in a blocking `glGetTexImage`
(`postfx.c:3110`) that drains the pipeline; a scope spanning it absorbs the whole frame's drain and
would read as the most expensive pass in the renderer. It is scoped alone so the number is
attributable rather than smeared.

**Loops are one scope, not one per iteration** — bloom's mip chain, the a-trous 3 draws, the froxel
slice loops, the MSM per-layer loop. The row is the pass; iteration counts belong in the name if
they matter (`bloom pyramid`).

### HUD — the project's first ImGui table

A `"GPU Timing"` collapsing header inside `_engine_gui_panel` (`gui.c:258`), added after
`"Camera Transform"` (:817), with flag `0` (starts collapsed) matching the glance-at-occasionally
sections. `igBeginTable` / `igTableNextColumn` / `igEndTable` are **not used anywhere in this
codebase today** — this is the first. The API is available in the vendored `cimgui.h:4316`, and
`(ImVec2){0, 0}` compound literals work because `gui.c:30` defines
`CIMGUI_DEFINE_ENUMS_AND_STRUCTS`.

Two columns (pass, ms), `ImGuiTableFlags_RowBg | ImGuiTableFlags_SizingStretchProp`, a total row,
and the backend label in the header line. Format `"%.2f ms"`, matching the `"%.2f m"` / `"%.1f px"`
convention. `igText` with `%-18s` padding was considered and rejected: ImGui's proportional font
misaligns it, which is the argument for the table.

The section renders inside the existing panel, so **no change is needed** to the
`gui_frame_active` latch at `engine.c:2114` (that is only required for a new top-level window).

### CLI — `--gpu-profile`, through the eight-site pattern

Following `--translucent-shadows` exactly: field in `render_args.h:46`, help text in `print_usage`
(`render.c:83`), parse arm (`render.c:497`), application in `main`, backing field, GUI toggle.
Off by default — the profiler is created only when asked for, so the default path is untouched.

**Headless prints the table at exit**, between `engine_run` (`render.c:2823`) and `free_engine`
(`render.c:2833`) — after the last frame, GL context still alive. Body follows the
`--check-stretch` precedent (`render.c:1236-1307`): banner lines and one `printf` row per pass.

## Verification

Every arm below can fail. That is the bar this tree uses, and two arms in 11.26 shipped unable to.

| arm | asserts | catches |
|---|---|---|
| `gpu-off` | all 21 goldens **0 px** with the flag off | the profiler perturbing the frame it measures |
| `gpu-rows` | ≥ 20 named rows, all finite, none negative | the queries returning nothing |
| `gpu-nonzero` | total > 0 and each row ≥ 0 | a driver that accepts queries and reports zeros — **the platform risk, made a gate** |
| `gpu-sum` | Σ rows within 25 % of frame time, **GL backend only** | scopes that overlap or miss whole passes; skipped under the serializing fallback, where the identity does not hold |
| `gpu-dof` | the `dof` row is **absent without `--dof` and > 0 with it** | rows that are fabricated rather than measured — the inverse arm |
| `gpu-scale` | pre-seam rows drop ≥ 30 % at `--render-scale 0.5` | timings that are constant regardless of work, i.e. not attached to the GPU at all |
| `gpu-backend` | the report names its backend | a fallback silently reporting inflated numbers as if they were GPU time |

`gpu-dof` and `gpu-scale` are the load-bearing pair: without them every other arm passes against a
profiler that prints plausible constants.

**Manual check:** run windowed, toggle DoF/SSR/bloom in the HUD, watch the matching row appear and
the total move. Then `--gpu-profile -x` and read the table.

## Deliberately deferred

- **Nested / hierarchical scopes.** Needs `GL_TIMESTAMP`, the primitive least likely to work on
  this driver. Revisit only if the flat table proves insufficient.
- **Per-draw or per-material timing.** That is E5's question, not this one.
- **CSV / JSON export and perf regression gates.** Wait until the numbers are trusted; a perf gate
  on a flaky suite would be worse than none.
- **Instrumenting the app layer** (`apps/*`). The engine's passes are the budget.

## Process

Per `CLAUDE.md`: branch off master, copy this plan to `specs/11.27-gpu-timer-queries.md`, commit
the spec **before** any code, create the task list, then implement. Step 1 of implementation is the
probe — if Apple's driver reports zeros, that is measured and recorded in the spec before a line of
HUD code is written.
