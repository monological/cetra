# 11.7 — B4 TAAU: temporal upscaling, the perf lever

## Context

Frame cost on the M1 Max is fragment-bound: ~14.5M shaded pixels/frame at
Retina fullscreen, measured ~17 ms/frame at 1080p headless (≈15 fps scaled to
Retina — the user's reported pain). Every pass is a fullscreen raster pass
(GL 4.1, no compute), so cost scales ~linearly with shaded pixels. TAAU
renders the scene + screen-space stack at `render_scale` ∈ [0.5, 1.0] of
display resolution and reconstructs temporally at display resolution — at
0.67 that is ~2.2× fewer shaded pixels for the whole pre-seam chain; at 0.5,
4×.

The roadmap (B4, docs/aaa-rendering-roadmap.md:269-284) pre-settles: a
SEPARATE `taau_resolve_frag.glsl` program (taa_resolve untouched, so
scale == 1.0 stays byte-identical); history + output at display ("post")
res; current frame sampled at render res with jitter un-applied +
Blackman-Harris subpixel weight; Catmull-Rom + YCoCg clamp carried over
(clamp gathered in render-res space, blend scaled by sample-to-pixel
distance); Halton 8→16 phases at scale < 1; the render-res/post-res buffer
split; `--render-scale` CLI; PSNR ≥ 32 dB vs native as the TAAU acceptance
(reconstruction differs by design, so no pixel gate).

Recon established: velocity is built from UN-jittered matrices, so
reprojection never sees jitter (survives the split for free); the Catmull-Rom
history sampler already takes resolution as a parameter; the structural
obstacle is the resolve's same-size blit back into hdr_fbo; NO resize path
exists anywhere (PostFX created once); `fx->ssao_width` is a pure alias of
`bloom_width` and DoF sizes off `bloom_*` — three meanings share two names,
the likeliest wrong-size bug source; `run_temporal_accum` assumes in==out res
and binds aux for all seven consumers; gates.py churn gates pass no scale
flag; all 15 goldens are headless TAA-off.

## Settled design

**D1 — Three sizes, one canvas.**
- `width/height` = render res = fb × ss_scale × render_scale (meaning
  unchanged: what the scene rasterizes at; every render-res consumer keeps
  reading it, including `engine_render_size` which gains the scale factor).
- `post_width/post_height` (NEW) = fb × ss_scale — the TAAU output and
  everything downstream. == width/height at scale 1. New `engine_post_size`.
- `out_width/out_height` = display, unchanged; the tonemap still downsamples
  post → out by exactly ss_scale (the SSAA contract survives untouched).
- `half_width/half_height` (NEW) = render/2, the AO-family size. This kills
  the alias trap structurally: `ssao_*` = render/2, DoF coc/tile/gather
  re-key from `bloom_*` to `half_*`, and `bloom_*` re-derives from post/2.
  At scale 1 all values are equal — Phase 1 is a pure re-key.
- Rounding: at scale < 1, `render_w = ((int)roundf(post_w * scale)) & ~1`,
  min 2 (even sizes keep half chains exact). At scale == 1 the formula is
  BYPASSED — `render_w = post_w` verbatim, so odd framebuffer widths cannot
  perturb the byte-identical path.
- The canvas: new `post_fbo/post_texture` (RGBA16F), allocated only when
  scale < 1. postfx_run computes once:
  `taau_active = taa_resolving && render_scale < 1`;
  `canvas_fbo/tex = taau_active ? post_* : hdr_*`; `pw/ph = post_*`.
  At scale 1 these equal today's values exactly — the mechanism that makes
  the re-key provably 0 px.
- The seam replaces the TAA slot:
  `if (taau_active) run_taau_resolve + blit history→post_fbo; else if
  (taa_resolving) today's path VERBATIM; else invalidate`. taa_history
  allocates at post_* (== width at scale 1 — same allocation). Fallback: if
  TAA is GUI-toggled off at scale < 1, a bilinear blit hdr→post keeps the
  frame display-filling.

Per-pass disposition (unlisted = untouched): everything through the split
spec-occ composite stays pre-seam at render res (spec-occ pinned pre per
11.4's stabilize-as-one-image rationale). Post-seam: SSGI accum/atrous and
SSR hi-z/march/accum/atrous keep their render-res work — the SSR march binds
`canvas_tex` as its radiance source (normalized UVs; same texture id at
scale 1) preserving "post-TAA consumers read stabilized color"; the SSR
tent composite, SSGI composite, fog fold, and SSS fold re-target canvas_fbo
at pw×ph with their render-res inputs bilinearly magnified. **Fog stays
post-seam per 9.5.1's recorded rationale, with the fog layer + its history
kept at RENDER res** so the jitter-cancelling accumulator still reads aux
1:1 NEAREST — only the already-stabilized layer is magnified at the fold
(smallest diff, cheaper, and the NEAREST-velocity trap never fires). SSS
blur/delta/history stay render res (projScale stays fx->height — it scales
world radius to the res the blur runs at). Motion blur re-keys wholesale to
post_* (tiles ceil(pw/20), texelSize 1/post; velocities are UV-space so
magnitudes are res-independent; the same-size blit-back contract is
preserved post→post). DoF: coc/tile/dilate/gather stay render/2 (re-keyed
to half_*; coc reads canvas color + render depth), composite re-targets
post_* reading canvas + magnified near/far + render-res NEAREST depth for
CoC classification (blocky class edges softened by the existing 0.5–1.5
smoothstep — accepted v1). Metering (64×64) and bloom (post/2) read
scene_tex = canvas/dof. Tonemap unchanged (sharpen texelSize stays 1/out).

**D2 — taau_resolve_frag.glsl.** Uniforms: currentTex (render hdr, jittered
raster), velocityTex (render aux, NEAREST), historyTex (post), vec2
renderSize/postSize, vec2 jitterPx (this frame's Halton offset − 0.5, in
render px — newly published to postfx), int reset. Per post pixel:
`pos = uv * renderSize - jitterPx`; one 3×3 loop over render sample centers
does triple duty — Blackman-Harris-weighted reconstruction
(`w = exp(-2.29·d²)`, d = sample-to-pixel distance in render px), the YCoCg
clamp bounds (gathered in RENDER space), and `wmax` (nearest-sample
confidence). Then: velocity from the nearest sample; off-screen reject;
Catmull-Rom history fetch at postSize; clamp; motion feedback 0.97→0.9;
`alpha = (1-feedback) * mix(0.25, 1.0, wmax)` — when no render sample landed
near this display pixel this frame, the reconstruction is interpolation, not
information, so lean on history; inverse-luma weighted blend (firefly
damping kept). Catmull-Rom is COPIED v1 (hoist to an include is a follow-up)
so "taa_resolve untouched" stays trivially auditable. Jitter SIGN verified
empirically in Phase 3 (checkerboard flip-test; the wrong sign converges to
a half-pixel blur). The 0.25 confidence floor is a Phase-4 tuning seed.
Halton: `phases = scale < 1 ? 16 : 8` at the render.c jitter site —
bit-for-bit today's sequence at scale 1. Jitter published as
`fx->taau_jitter_px[2]` each frame from the jitter site.

**D3 — A dedicated driver, not an extended helper.** run_temporal_accum's
reason to exist is a one-site invariant for same-res consumers; TAAU
violates every axis (two resolutions, jitter uniform, sample semantics). A
private ~30-line `run_taau_resolve(PostFX*)` owns taau's units (0 current,
1 velocity, 2 history — same convention), sizes, and parity.
run_temporal_accum is not touched. `create_taau_resolve_program` compiled
only when scale < 1 (no cost on the default path).

**D4 — Knobs; v1 scope = CLI-only, fixed at startup.** Engine gains
`float render_scale` (default 1.0) + `set_engine_render_scale` (clamp
[0.5, 1.0], must precede init_engine — the ss_scale twin; warn + ignore
after). `create_postfx` gains the fourth parameter. CLI
`--render-scale <f>`; preconditions in the app: windowed already forces TAA
on; headless requires `--taa --headless-jitter` else warn + clamp to 1.0.
TAAU never rides the windowed-TAA auto-enable — the flag is the only way
in. **postfx_resize + a GUI slider are DEFERRED** (recorded follow-up): no
resize path exists anywhere today, a runtime resize touches ~40 targets +
seven ensure guards + every history, and none of it is needed to fix the
FPS. GUI shows a read-only "Render scale: N (set at launch)" line.

**D5 — Verification.**
- Master gate every phase: scale==1.0 byte identity — 15-golden sweep exact
  0, raiden byte-identical vs the Phase-0 baseline, determinism ×2,
  gates.py green (its churn gates pass no scale flag — verified by running).
- Clamp gate (Phase 2): `--render-scale 0.67` headless WITHOUT
  `--taa --headless-jitter` byte-identical to no flag (the warn+clamp path
  proven).
- PSNR gate (Phase 4): contact_fixture.cscn, 120 frames, 1920×1080,
  `--taa --headless-jitter --no-auto-exposure -E 1.0`, scale 0.67 vs native
  from the SAME build; `magick compare -metric RMSE` → PSNR = −20·log10(frac)
  ≥ 32 dB. Scale 0.5 reported, not gated. dof_fixture PSNR informational
  (the firefly torture case).
- Perf recipe: /usr/bin/time, 300 frames contact_fixture at 1080p, scales
  1.0/0.67/0.5, plus a windowed Retina FPS spot-check (the user's actual
  pain).
- **Phase-0 bottleneck proof (go/no-go): the same run at 960×540 must show
  ~4× frame-time scaling, confirming fragment-bound. If it does not scale,
  STOP and re-plan before building anything.**

**D6 — Invariants.** render_scale defaults 1.0 at every layer; the taau
program isn't compiled, its branch never taken, taa_resolve_frag and
run_temporal_accum unedited, the Halton sequence bit-identical at 1.0. All
15 goldens are headless TAA-off — doubly insulated.

Merge only on explicit permission.

## Risks

Ghosting/disocclusion (v1 = the shipped TAA's trio: render-space YCoCg
clamp — wider in display terms at 0.67, more ghost-tolerant — + motion
feedback + off-screen reject; history alpha reserved for a confidence
channel if Phase 4 needs it); thin-feature shimmer at 0.5 (16 phases +
wmax-scaled blend; 0.67 is the acceptance point, 0.5 reported); fireflies
(inverse-luma kept); the ssao/bloom alias (eliminated by name in Phase 1);
fractional-size drift (even-rounding never executes at scale 1); fog wobble
(9.5.1 loop untouched — layer stays render res); MB tilemax undersampling
over magnified velocity (same failure class as today's reduction, noted);
sharpen becomes the user-facing crispness lever at scale < 1 (docs note);
PSNR flakiness (same-build reference, frame-indexed jitter, pinned
exposure — reproducible by construction).

**Effort: L** (5 gated phases + reviews).

## Phase 0 — measured

Baselines on the unmodified build: 15-golden sweep all exact 0; gates all
green; raiden determinism x2 = 0 px (baseline tmp/taau_p0_raiden.ppm).

Bottleneck proof (contact_fixture, --taa --headless-jitter, pinned exposure;
per-frame cost = (t310f - t10f)/300, which subtracts startup):

| resolution | wall 310f | wall 10f | ms/frame |
|---|---|---|---|
| 1920x1080 | 19.05 s | 1.26 s | 59.3 |
| 960x540 | 5.71 s | 0.80 s | 16.4 |

Ratio 3.6x for exactly 4x the pixels — ~90% of frame time is
resolution-proportional, on a frame where CPU (user+sys) is under 10% of
wall. Fragment-bound confirmed: **GO.**

(Label correction, discovered in Phase 4: a hidden headless window still
gets the Retina 2x content scale, so "-W 1920" rows above are framebuffer
3840x2160 and "-W 960" rows are 1920x1080. The 4x pixel ratio and the
conclusion are unaffected.)

## Phases 3-4 — measured

Jitter sign flip test (dof_fixture zone plate, 1600x1000 fb, 120 f, TAAU
0.67 vs native TAA same build): minus 34.2 dB, plus 33.0 dB — minus wins,
agreeing with the projection algebra (a positive [2][0] increment lands in
x_ndc as -delta after the divide by w = -z). Near-identity probe at scale
0.98: 38.0 dB, monotone toward native as scale rises.

pinned exposure, vs native from the same build):

| scale | RMSE frac | PSNR | bar |
|---|---|---|---|
| 0.67 | 0.00781 | **42.1 dB** | >= 32 required — PASS |
| 0.5 | 0.01084 | 39.3 dB | report-only |

No tuning needed — the 0.25 confidence floor and the render-space clamp

| framebuffer | scale 1.0 | 0.67 | 0.5 |

Phase-0 baseline across all four builds).

## Phase R — reviews

Five background audits (thermo-nuclear quality, reuse, simplification,
efficiency, graphics correctness). No blockers; the correctness pass found
one real defect.

**The reconstruction window was off-centre.** `base` anchored on the
nearest render sample at or BELOW `pos`, so for the half of sub-texel
phases where `pos` sits low in its texel the 3x3 covered `{c-2, c-1, c}`
instead of `{c-1, c, c+1}` — dropping a neighbour worth up to 0.10 of the
kernel while admitting one worth under 0.01, in the reconstruction AND in
the YCoCg clamp bounds gathered by the same loop. The jitter moves `pos`
every frame, so the skew flipped per frame per pixel.

RMSE-vs-native initially argued AGAINST the fix (contact 42.13 -> 42.26 dB
improved, but the zone plate went 34.2 -> 33.5 and the 0.98 near-identity
probe 38.0 -> 37.3). That metric rewards sharpness against a sharp
reference, and the skewed window was sharper only because it dropped
kernel mass. The claim the fix actually makes is about temporal
stability, so it was settled by measuring that instead — frame-to-frame
churn, static camera, contact_fixture at 0.67, frames 120 vs 121:

| window | churn AE | churn RMSE |
|---|---|---|
| centred (shipped) | 107,245 px | 0.000404 |
| skewed (as first written) | 113,580 px | 0.000487 |

17% less flicker magnitude, and the official gate improved. Shipped
centred; crispness at a reduced scale is `--sharpen`'s job.

Also applied: `postfx_taau_active` replaces three spellings of "is TAAU
live" (the jitter site's Halton widening now asks the same predicate the
seam dispatches on, so the sequence cannot diverge from its consumer); the
seam's four branches collapse to two around one shared blit; the
headless-needs-jitter rule moved from the render app into `init_engine`,
where all three facts are known, so no future headless app rediscovers it;
`scene_capture_begin` saves/restores `taau_jitter_px`, closing a latent
hazard where a capture taken after the main raster would hand the resolve
a zero offset to un-apply against a jittered frame; both clamp doors now
round the same way; an out-of-range `--render-scale` says so instead of
silently rendering full res.

Deferred, with rationale: the two bandwidth wins (MRT dual-output to skip
the history blit, or reusing the history buffer as the canvas) each trade
the documented "post-seam composites never touch the history" invariant
for a subtler one, for ~1% of frame time on a feature that already
doubled it; the motion-blur tilemax oversamples ~1/scale^2 at reduced
scale (MB is off by default, and the fix widens its blur footprint —
a behaviour change, not a cleanup); the shader-include hoist should sweep
the copied feedback constants and inverse-luma blend along with the
Catmull-Rom sampler.
