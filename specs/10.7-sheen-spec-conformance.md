# 10.7 — Sheen spec conformance: alpha², baked Charlie E-LUT

## Context

The sheen fixture (`assets/sheen_fixture.gltf`) renders with pitch-black cores
and hard twisted crescents. Investigation isolated the artifact to the sheen
BRDF itself (identical with shadows / SSR / GTAO off), and comparison against
the KHR_materials_sheen spec found the implementation off-spec in two places,
plus one admitted approximation:

1. **Charlie alpha is not squared.** The spec's implementation appendix says
   verbatim `alpha_g = sheenRoughness * sheenRoughness` ("we use the mapping
   r = sheenRoughness² which results in more perceptually linear changes"),
   and the Khronos glTF-Sample-Renderer's `D_Charlie` does the same.
   `pbr_frag.glsl:381` divides by the UNSQUARED roughness — the lobe is far
   too broad, so sheen floods the whole ball instead of hugging the rim (the
   crescents are three lights' over-wide rim arcs overlapping). The comment at
   `:379` claiming "used directly as alpha, per the glTF/KHR reference" is
   factually wrong. Confirmed experimentally: rendering the fixture with
   pre-squared roughness values pulls sheen into tight rim arcs.

2. **Albedo scaling drops the E term.** Spec: `sheen_albedo_scaling =
   1 - max3(sheenColor) * E(VdotN)` where E is a baked directional-albedo
   table (small except at grazing). `pbr_frag.glsl:1290` and `:1443` use
   `1 - max3(sheenColor)` — E ≡ 1 — so the base layer is multiplied by 0.1
   (gold/blue) everywhere instead of ~0.95 at the sphere center: the black
   cores. Spec 4.10.1 already names "a baked Charlie E-LUT" as the documented
   follow-up (deferred then to keep the zero-new-sampler property — which
   this plan preserves by widening the existing LUT, not adding a sampler).

3. **IBL sheen weight is ad-hoc.** `pow(1 - NdotV, 2)` at `:1439` stands in
   for the integrated-BRDF term of a split-sum. Under an HDR env the satin
   sphere renders as chrome gold with a black hole. E(NdotV, shR) is exactly
   the split-sum scale this site wants (the sample renderer uses its Charlie
   LUT the same way).

No gate or golden covers sheen (verified: zero "sheen" hits in
`scripts/gates.py`; no committed golden renders it), so the suite must stay
byte-identical and the fixture gains a golden at the end.

## Design

### 1. Shared sheen include, alpha squared

New `cetra/shaders/include/sheen.glsl` (precedent: `include/noise.glsl` from
10.6) holding `distributionCharlie` and `visibilityAshikhmin`, moved out of
`pbr_frag.glsl`. In `distributionCharlie`:

```glsl
float alphaG = max(sheenRoughness * sheenRoughness, 1e-4);
float invAlpha = 1.0 / alphaG;
```

with the comment rewritten to cite the spec's actual mapping (perceptually
linear r²). The `sin2h` fp16 floor stays. Both `pbr_frag.glsl` call sites keep
their `clamp(shR, 0.07, 1.0)` floor (historically unjustified — now floors
alpha at 0.0049; recorded, re-measured only if satin needs tighter).
The shared include is what lets the LUT bake integrate the *identical* code
it will shade with.

Keep Ashikhmin visibility (spec-sanctioned cheaper option; recorded decision).
E is baked against Ashikhmin, NOT the sample viewer's lambda form — the
albedo scaling must match the lobe the engine actually evaluates.

### 2. Charlie E in the BRDF LUT's third channel, Engine-owned

`cetra/shaders/ibl_brdf_frag.glsl`: `out vec2` → `out vec3`; alongside the
untouched GGX A/B loop, add `E(NdotV, r) = ∫ Dcharlie·Vash·NdotL dωL` via
uniform-hemisphere sampling over L (pdf 1/2π — no half-vector Jacobian to
get wrong; the Charlie ring lobe converges fine), 2048 Hammersley samples,
one-time 512² bake. GGX math untouched → .rg byte-identical.

C side (`cetra/src/ibl.c:496-527`): `GL_RG16F` → `GL_RGBA16F` (RGB16F is not
reliably color-renderable; same 16F precision for rg). Update the
blend-disable rationale comment at `ibl.c:572-577` that describes the LUT as
RG-only.

**Ownership moves to Engine** (precedent: the LTC tables — baked BRDF data,
environment-independent, engine-bound). Today the LUT bakes inside
`ibl_bake_from_cubemap` (`ibl.c:590-594`) so it exists only when an
environment loads — but E must work in no-env scenes (the fixture render).
Bake once at engine init (the `ibl_brdf` program is registered at
`engine.c:1104-1106`; the bake keeps its transient-FBO pattern and gets a
transient VAO to match), store the GLuint on Engine, free at engine cleanup;
`bind_ibl_textures` (`ibl.c:744-747`) drops its LUT lines and render.c binds
unit 13 unconditionally (the no-IBL fallback at `render.c:391` already points
the sampler there). The stale "LUT is unbound" comment at
`pbr_frag.glsl:1027-1030` is rewritten; the `iblEnabled` gate on the GGX
fetch stays (energy comp / env specular remain IBL concepts — behavior
unchanged, noted follow-up).

### 3. Apply E at the three sites, hoisting the per-fragment constants

In `pbr_frag.glsl`, before the light loop (near the existing `brdf` fetch at
`:1025`), hoist what is per-fragment constant but currently recomputed per
light and again in the IBL block:

```glsl
bool sheenActive = sheenEnabled > 0 && maxComp(sheenColorFactor) > 0.0;
vec3 sheenColorPx; float shR; float sheenE; float sheenScale = 1.0;
if (sheenActive) {
    sheenColorPx = sheenColorAt(uv);
    shR = clamp(sheenRoughnessFactor, 0.07, 1.0);
    sheenE = texture(brdfLUT, vec2(NdotV, shR)).b;
    sheenScale = 1.0 - maxComp(sheenColorPx) * sheenE;   // spec's simplified VdotN-only form
}
```

- Analytic loop (`:1284-1291`): keeps only `Dsh`/`Vsh` per light, using the
  hoisted values. (Per-light `min` with E(LdotN) deliberately skipped — the
  spec sanctions the VdotN-only form; recorded.)
- IBL ambient dim (`:1443`): reuse `sheenScale` (was `1 - maxComp`).
- IBL sheen radiance (`:1439`): `sheenE` replaces `pow(1 - NdotV, 2)`.
  Env mip stays `shR * maxReflectionLOD` initially; if the gold sphere still
  reads chrome under the studio HDR, bias the LOD as a measured decision
  recorded in the spec (the GGX chain understates Charlie's blur).

## Not touched

Punctual shadow path, clearcoat, energy-comp gating (still `iblEnabled`),
`sheenTex` unit-8 status, fixture/generator values
(`assets/gen_sheen_fixture.py` stays as authored), GGX A/B integration.

## Verification

1. **0-px proofs (the load-bearing ones):** no scene in the deterministic set
   carries sheen, so base vs branch builds of cornell_box, cornell_leak,
   contact_fixture, and the raiden recipe must print `0 (0)` — this proves the
   LUT widening, the ownership move, and the hoist changed nothing outside
   sheen. Full `gates.py` suite passes with byte-identical numbers.
2. **Fixture before/after,** pinned exposure (`--no-auto-exposure -E 1.0`),
   no-env and `-e studio_small_03_8k.hdr`. Expected: tighter rim lobes
   (alpha²), centers dark-gray (0.03 base under diffuse) instead of pitch
   black (E-scaling), no chrome ring on satin under the env.
3. **Sanity on E itself:** white-sheen furnace reasoning — with
   sheenColor = (1,1,1), base retention is `1 - E` and the lobe adds ~E, so
   nothing can exceed unity by construction; plus optional cross-check of the
   fixture in the Khronos sample viewer web app (drag-drop the .gltf) for the
   user's judgment.
4. **Bake `assets/sheen_fixture_golden.png`** per the documented golden
   procedure and record its pinned recipe + numbers in the spec.

## As built

Implemented as planned; every measurement below is from the final reviewed
build (branch `sheen-spec-conformance`).

**Determinism (0-px proofs, pinned `--no-auto-exposure -E 1.0`, no TAA),
base = master build:** cornell_box, cornell_leak, contact_fixture, and the
raiden recipe all print `0 (0)` from `magick compare -metric AE`. Raiden is
the decisive one -- it runs the full IBL path, so the RGBA16F re-bake
provably left the GGX .rg channels byte-identical. Re-proven after the
review fixes, which were additionally proven neutral on the sheen fixture
itself (0 px vs the pre-review branch build, both env modes).

**Gates:** full suite passes twice (post-implementation, post-review) with
numbers byte-identical to master (dir churn 9245 px / floor 6698, catcher
104138 px / floor 101316).

**The fixture, before -> after** (pinned exposure): no-env delta 409,700 px;
studio-HDR delta 1,081,850 px -- all of it on the sheened spheres and their
bloom. Black cores are gone (bodies now read as the 0.03 base under diffuse
light; the old code multiplied the base by 0.1-0.2 everywhere), sheen sits
in rim/terminator arcs (alpha squared), and the satin-gold sphere under the
env lost the chrome-mirror ring and black hole (split-sum E replaced the
`pow(1-NdotV,2)` weight). The feared env-mip bias was NOT needed -- the
E-weighted term reads correctly with the GGX chain's `shR * maxReflectionLOD`
mip; recorded as acceptable, revisit only if a real asset shows otherwise.

**Golden:** `assets/sheen_fixture_golden.png`, baked with
`./out/bin/render -m assets/sheen_fixture.gltf -x -f 30 -W 800 -H 450
--no-auto-exposure -E 1.0 -S <tmp>.ppm` then `magick <tmp>.ppm
assets/sheen_fixture_golden.png` (retina backing store doubles -W/-H, so the
PNG is 1600x900).

## Review outcomes

Five background reviews (thermo-nuclear + four /simplify angles). Applied:

- `ibl_bake_brdf_lut` uses `create_texture_2d_float` (texture.c's LUT-policy
  helper, whose comment names this consumer) instead of a hand-rolled
  gen/params block.
- PI literals in `ibl_brdf_frag.glsl` replaced with `PI` from sampling.glsl.
  (sheen.glsl keeps its literal -- a self-contained include cannot define or
  include PI without colliding at the pbr_frag include site.)
- Dead CULL_FACE handling and dead `glClear` dropped from the bake; the
  function now declares an init-time-only contract (no state save/restore,
  unconditional blend re-enable -- the `ibl_bake_from_cubemap` precedent)
  instead of the half-restore shape the review flagged.
- Stale comments fixed: `ibl_bake_from_cubemap` no longer claims to bake the
  LUT; sky.c's `bake_lut_2d` no longer cites the deleted `render_brdf_lut`.
- The ownership rationale now lives ONCE at the implementation; ibl.h,
  engine.h, and render.c carry one-line contracts, and the engine.c call
  site carries none.
- The `iblEnabled` gate comment in pbr_frag was factually wrong ("energy
  compensation is an environment concept") -- energyComp multiplies ANALYTIC
  specular too. Rewritten to state the truth: the gate is a scope bound
  keeping no-env renders byte-identical, and hoisting the fetch + comp out
  of it is a recorded follow-up that moves no-env pixels.
- The 0.07 roughness floor is named once as `SHEEN_MIN_ROUGHNESS` in
  sheen.glsl (the bake/shading-shared home), referenced by the pbr_frag
  clamp, with the bake noting rows below it are outside the fetched domain.
  Dead initializers in the hoisted block became bare declarations.

Recorded, not done:

- Promote the transient-FBO 2D-LUT bake idiom (third instance:
  `ibl_bake_brdf_lut`, sky.c's `bake_lut_2d` x3 uses) to a util.c helper --
  deferred because the two sites carry genuinely different state policies
  (scratch-unit discipline vs init-time-only), and a policy-flagged helper
  is worse than the duplication.
- Hoist the GGX LUT fetch + energy compensation out of the `iblEnabled`
  gate so rough metals under analytic lights get multi-scatter energy back
  in no-env scenes. Moves no-env pixels; wants its own golden re-measure.
- Filament-style per-light `min(E(NdotV), E(LdotN))` albedo scaling -- the
  spec sanctions the VdotN-only form; revisit only with evidence.
