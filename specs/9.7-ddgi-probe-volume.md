# A4 — DDGI-style irradiance probe volume

## Context

Roadmap Tier 1 #6 (`docs/aaa-rendering-roadmap.md:128-146`), the track's stated long pole and
biggest visual payoff. Everything shipped recently improves *direct* light (A1 clustered forward,
A2 LTC area lights, A3 contact shadows) or *atmosphere* (B1 fog, B9 aerial perspective). None of it
makes an interior look right, because indirect diffuse is still one flat direction-only lookup —
`texture(irradianceMap, N)` at `pbr_frag.glsl:1209` — identical at every point in the scene. A room
lit through a window gets no bounce, no colour bleed, no falloff away from the opening.

A4 replaces that with an 8-probe trilinear sample from a grid of irradiance probes, each captured
by **rasterizing the real scene**. Because captures run the full forward shader, probes see
clustered lights, LTC panels, sky and emissive automatically — the argument for rasterized capture,
and why this was sequenced after A1+A2. Both are done.

**It also closes a loop from last session.** `:353-354` — *"when A4 lands, `froxel_inject` swaps its
ambient term for one GI-volume tap."* Spec 9.6 M5 just made the fog's ambient sky-derived; that was
the placeholder this replaces.

**Scope decision (user, this session): full — irradiance *and* visibility.** Leaking is what makes
DDGI read as broken rather than untuned.

### What exploration falsified

The roadmap entry reads as a design rather than a sketch, which makes it tempting to trust. Three
of its load-bearing claims do not survive the code — the same pattern as B1's layered-GS sketch and
B9's "owns no foundations".

**1. The cost model is wrong, and the design follows from fixing it.** The entry specifies 2
probes/frame × 6 faces = 12 full scene renders *every frame, forever*. Each `render_current_scene`
rebuilds the entire clustered light grid for its own view (`render.c:616-625`, deliberate per spec
9.1) — and the grid is a fixed 16×8×24 = 3072 clusters regardless of a 16² viewport. Per rebuild:
~150 KB of memset, ~74k cluster-loop iterations, 3 UBO orphan+upload (~444 KB churn). Meanwhile
`uniform_set_*` is a uthash string lookup plus an unconditional `glUniform` with no value caching
(`uniform.c:149-189`): ~50 uploads per program switch, **50 per material switch**, and 9 plus a CPU
`glm_mat4_inv` per mesh per pass (`render.c:412`). On a 7-draw fixture that is ~460 uploads per
render, ~5,500/frame for captures alone; on the 553-draw `abandoned_window`, ~390,000.

*Good news the roadmap also gets wrong:* `get_closest_lights` **no longer exists** — A1 deleted it,
so the per-node light cost cited at `:38-41` is already gone. That entry and "No UBOs exist
anywhere" are both stale.

**2. Three latent hazards in the capture path, inert only because capture runs once at load.**
- The particle pass calls `engine_resolve_scene_depth`, which sizes from the *main* render size and
  re-binds `engine->framebuffer` on exit (`engine.c:1960-1976`) — hijacking the capture target.
  `refraction_enabled=false` was added for exactly this class (`engine.c:1893-1901`); particles and
  OIT were never covered.
- `a2c_capable = engine->msaa_samples > 1` (`render.c:244`) reads the *scene* framebuffer's sample
  count, not the bound target's. Capturing into a single-sample FBO with MSAA on takes the
  alpha-to-coverage path with no coverage hardware — masked geometry renders as solid quads, the
  exact failure `render.c:240-243` describes. **This is a live bug in today's probe capture.**
- `render.c:837` clobbers `prev_view_proj` (TAA history). `probe.c` saves/restores it; anything
  capturing per frame must too.

**3. The atlas violates the codebase's one stated rule about this.** `render.c:391-394`: *"The probe
joins the scene only after its capture, so the capture pass itself never consumes it."* A GI atlas
must be sampled by the main pass *and* written by captures in the same frame. Verified safe anyway
— see Design — but it is a genuinely new hazard shape here, and there is **no sub-rectangle
rendering precedent** in the tree (every layered pass swaps attachment and uses a full-target
viewport at origin; `glTexSubImage2D` appears nowhere outside `ext/`). `glBlendColor` is unused but
unambiguously available in 4.1 core.

**Also:** no Cornell box, and **no enclosed scene of any kind** — all 13 generators emit open-backdrop
product shots; the only "wall" anywhere is a single quad in `gen_parallax_fixture.py`.
`abandoned_window` is explicitly ruled out as a baseline (bistable). The line citation for the
injection point is stale (1209, not 1169), and the swap is not one line: `kD * diffuse` is reused by
the **SSS tap at 1246-1248**, which must mirror or subsurface silently diverges.

## Design

### Cadence: converge, then idle. This is the central correction.

Not "2 probes/frame forever". The volume tracks a **dirty set**; probes are re-captured from a
budget only while dirty, and when the set empties the subsystem costs **zero**. A static scene —
which is every fixture in this repo — converges at load and then pays nothing.

Mirrors the sky exactly: `luts_baked` plus rebake-on-sun-move (`sky.c`), and it is the fix for
precisely the defect review found in B9 (per-frame rebuild of something the result doesn't depend
on). Dirty triggers: first frame (all probes), sun move (the roadmap's own
`:359-360` "sky dirty → raise probe budget" hook), light/material change, explicit GUI request.
`--gi-rate N` sets probes-per-frame while dirty (default 2); `--gi-rate 0` bakes at load only.

The startup burst uses hysteresis 0 so probes converge in one pass rather than fading in over
seconds.

### Ownership: a Scene citizen, mirroring Sky and Probe

`GIVolume* gi_volume` on `Scene`, `gi_volume.c/h`. Grid default 8×4×8 over the scene AABB. No
publish-to-postfx needed — unlike fog and aerial, this is consumed by `pbr_frag` in the *scene*
pass, so it binds through the existing `_render_node` program-switch block beside
`bind_ibl_textures` (`render.c:378-389`), which runs ~2-6×/frame, not per draw.

### The capture helper, and fixing the path first

Extract `scene_capture_faces()` from `reflection_probe_capture` (`probe.c:130-226`). On the probe
side this is clean — the core touches only `position` and the blit destination. The real cost is
that it saves/restores **14 pieces of engine and camera state** plus cascade count and render time,
and that face size is a `#define` (`probe.h:18`) needing parameterisation.

**Hard constraint:** `render_current_scene(Engine*)` resolves the scene itself via
`get_current_scene(engine)` — so the helper cannot render a `scene` argument, only the engine's
current scene. Take `Engine*` and document it rather than accepting a `scene` the helper ignores.

**M1 fixes the three hazards before anything depends on them**, because per-frame capture is what
makes them live. The a2c one is a bug fix that stands on its own merit.

### Atlas: one RGBA16F 2D texture, tiles written by viewport offset

Per probe: an **8×8 octahedral irradiance tile** and a **16×16 octahedral visibility tile**
(distance and distance² moments), each with a 1px gutter for correct oct-wrap under bilinear.
256 probes ≈ 0.4 MB. Written by `glViewport(x, y, w, h)` into the atlas FBO — new to this codebase
but ordinary GL; the gutter rewrite is a second small pass per tile.

**In-place blending with `glBlendColor` + `GL_CONSTANT_ALPHA` (hysteresis 0.97) is legal here**, and
I verified the hazard rather than assuming: the atlas is never bound for read while being the render
target. Capture reads the atlas (for multi-bounce) and writes a cube face; projection reads the cube
face and writes the atlas. Sequential, different targets — the same shape as the shadow-map pass,
which is the established precedent. This avoids ping-pong, which would otherwise require copying
254 untouched tiles to update 2.

### Sampling: `include/gi_volume.glsl`, beside `ltc.glsl`

`ltc.glsl` is the direct precedent — a lighting-model include declaring its own sampler, uniforms
and eval function, included by `pbr_frag` alone, added by a roadmap track item (A2). Same shape.

`giAtlasTex` takes **unit 14**, already reserved by the roadmap's global ledger (`:75-76`) and
verified free — it is `IBL_SKYBOX_TEXTURE_UNIT`, which `pbr_frag` never samples. It would be the
first genuinely new sampler added to `pbr_frag` since the 15-sampler limit was documented; the
`_Static_assert` chain at `render.c:36-53` gets a new link.

8-probe trilinear at `WorldPos + N*normalBias`, per-probe backface rejection, Chebyshev visibility
test from the moment tile. Replaces the diffuse term at `pbr_frag.glsl:1209` — **and its mirror in
the SSS tap at 1246-1248**. Specular IBL, clearcoat and sheen stay on the environment map.

A `giEnabled` uniform keeps the old path intact for the 0-diff gate, the way `specOccMode` does.

### The fixture

`assets/gen_cornell_box.py` → `cornell_box.gltf` (**not `.glb`** — all 13 generators emit `.gltf`
with an embedded base64 buffer, and correcting this is cheaper than being the odd one out) plus a
sibling `.cscn`. Five walls, two boxes, an emissive ceiling panel; red/green side walls are the
canonical colour-bleed test and are exactly what a flat irradiance map cannot produce.

Mechanically this is `gen_oit_fixture.py` scale (~85 lines) with more vertex bookkeeping — but two
things no generator has done: an emissive material, and an enclosed volume where camera placement,
near/far and corner-seam leakage must be reasoned about rather than eyeballed. B9's fixture took
three drafts; budget for that.

Note `.cscn` cannot express emissive (`cscene.h` materials carry only `sss` and `windResponse`), so
the panel's emission comes from the glTF's `emissiveFactor`.

## Verification

Complete `./build.sh` every time — never piped through `head`. Pin exposure with
`--no-auto-exposure -E 1.0`. Measure the same-build noise floor before trusting any comparison.

1. **Every existing golden 0 px with `giEnabled=0`** — `froxel_fog_golden`, `aerial_fixture_golden`,
   `contact_debug_golden`. The feature must be free when off. Runs from M3 on.
2. **`--probe` render 0 px across M1 and M2** — the hazard fixes and the extraction are both
   intended to be invisible. This is the gate that makes the refactor safe.
3. **The actual feature:** colour bleed on the Cornell box — red and green walls tinting the white
   floor and boxes. Compare M0 (no GI) against M4 at 1:1, never a thumbnail (the 9.2/9.4/9.6
   lesson).
4. **Leak rejection:** a thin wall between a lit and unlit region must not glow through. This is
   what the visibility tiles buy and the reason for full scope; test it deliberately rather than
   hoping.
5. **Headless determinism 0 px** — two identical runs. Captures are frame-count driven, so this
   must hold.
6. **Convergence cost.** Instrument or time the converged state: a static scene must do zero probe
   work per frame. Then measure the transient — how many frames to converge 256 probes at the
   default rate, and the frame cost while converging.
7. **Cost sanity on a real scene.** Time a capture burst on the Cornell box *and* on something with
   real draw counts. Given the per-material and per-mesh upload accounting above, report actual
   numbers rather than assuming the fixture generalises.
8. **Spot regression** — `spores`, `tree` smoke, and a `--fog` render (fog's ambient hook is
   adjacent to this work).

## As built

Shipped M0-M6. The design survived contact with the code; the cost model did not, and neither
did three of the roadmap's claims (see *What exploration falsified* above -- all three held up).

### What changed from the plan

**The gutter pass is gone.** The plan specified a second pass per tile that copies interior texels
into the 1px border. It was written, and then deleted: a border texel's value is a pure function of
a direction, so computing that direction inside the projection costs the same as copying the texel
holding it. That also removed a hazard the plan had not spotted -- the copy read the atlas while
the atlas was the render target, which GL 4.1 leaves undefined (no texture barrier). One pass, one
program, and `gi_border_frag.glsl` never reached master.

**Visibility moments are stored normalised by the far plane.** Not in the plan. The atlas is fp16
and the second moment is a squared distance: a scene barely 256 units across overflows 65504. The
consumer works in the same normalised units, so nothing multiplies back.

**The opening sweep runs in one frame, ignoring `rate`.** The plan had `rate` govern all
convergence. It cannot govern the first one: `gi_volume_active` withholds a half-swept atlas, so
amortising the opening sweep only delays GI appearing at all, and a headless run short enough to be
a golden finishes before it ever does. `rate` governs RE-convergence, where the previous atlas is
still sampleable and the cost genuinely wants spreading.

**`scene_capture_faces` stopped requiring IBL.** The `ibl` argument is only the scratch target the
supersampled path renders into; the direct (depth-keeping) path needs none. Relaxing the guard is
what lets a GI capture run in a scene with no HDR environment at all -- which the Cornell box is.

**A second ambient branch in `pbr_frag`.** The plan swapped the diffuse term inside the
`iblEnabled` block. That block is skipped entirely without an environment, so the Cornell box got
no GI at all. The interior case now has its own branch: same Lambert diffuse, no specular half,
all non-metal energy staying diffuse because there is no ambient specular lobe to take a Fresnel
share. The swap sits at the irradiance assignment rather than the ambient line, so the SSS tap
downstream follows the same term instead of diverging -- which is what the plan was worried about.

### Honest residuals

- **Probe-scale blotching** is visible on the Cornell back wall around the tall box, in the golden.
  8x4x8 over a 2 m room is 0.25 m spacing, and an 8x8 irradiance tile is coarse; the artifact is
  the grid, not a bug. Denser grids or an irradiance-space filter are the levers, neither taken.
- **The leak gate (verification 4) did not complete.** `cornell_leak` exists and the fixture is
  sound, but a staircase remains at the partition/back-wall corner that has not been root-caused.
  It is too coarse for the 2048 spot map (~2 mm texels there) and the dark half is lit only by GI,
  which points at the 16x16 visibility tile (~22 deg/texel) -- but that is a hypothesis, not a
  finding, and it is left open rather than claimed.
- **Two shadow faults were found and fixed en route**, both of which silently disabled the spot map
  rather than degrading it: the bind was gated on the DIRECTIONAL caster count, and the spot's
  light-space matrix used a fixed near/far of 1.0/55.0 that swallowed any room-sized scene. Neither
  is A4's, both blocked the leak fixture. Spot shadows also gained the 3x3 PCF the cascades have
  always had.
- **An area-light defect is open and unexplained**: a panel lights a flat wall whose normal points
  away from it and leaves it dark when it points toward it, reproducible from the CLI with
  `--area-light` and no scene file. Two hypotheses were tried and both refuted by measurement (a
  missing sign flip in the clipless LTC form, and the degenerate shading basis). The degenerate
  basis was a real latent bug and is fixed on its own merit; it is not this one.

## Review outcomes

Eight agents over the branch: four structural (subsystem, shaders, capture path,
app/fixtures) and four along the reuse / simplification / efficiency / altitude axes.
Applied in `0f4bf45`, `a3e623d`, `78985a1`, `90b7014`.

### What it caught that testing had not

One **live bug**: `scene_capture_faces` switched the G-buffer off by clearing three
`this_frame` flags. Attachment 4 (SSS) was added later without one, so a capture in an
`--sss` scene emitted a five-attachment draw list against a one-attachment FBO. Reachable
because `gi_volume_update` runs before `sss_this_frame` is recomputed, so a re-convergence
sweep inherits the previous frame's value. Fixed by asking `capturing` once inside
`engine_set_scene_draw_buffers`, which is correct for every future attachment too.

One **inverted invariant**: the sweep ended by disabling blend and calling that the engine
baseline. Blend is ENABLED at init and the G-buffer depends on it, so every frame after a
sweep ran with a context the rest of the renderer does not expect.

One **stale-uniform bug in the shadow bind**, pre-existing: the `else` branch set
`numShadowLights = 0` but left `spotShadowActive` and a stale depth texture bound, so
unticking Shadows in a spot-lit scene froze the spot's shadow on screen.

One **ordering bug**: `apply_model_recenter` sat inside the `--probe` block while the GI
volume fits its grid to `compute_scene_bounds`, which reads the transforms it applies --
so `--gi-volume` without `--probe` fitted to pre-recenter bounds, which is exactly how the
golden is generated. Invisible only because the Cornell fixture's offset is zero.

And **six comments that asserted things the code did not do** -- the `capturing` field
enumerated the wrong passes, the sample-cost figure was 5x low against the file's own
header fifteen lines above it, the self-gating claim held only on the first sweep, the
blend line above, the generator's docstring named a light type the fixture does not use,
and `--gi-rate 0` was documented in this spec while being unreachable in the app.

The pattern is worth naming: every one of those was a comment written confidently at the
time, and none of them was caught by any gate, because comments are not executable and the
goldens only cover converged frames.

### Open, deliberately

- **`scene_capture_faces` still branches on strategy.** Three of four reviewers argued for
  two entry points over a shared scope; one argued the shared body is large enough that
  splitting duplicates more than it removes. The `ss_factor` wart both sides agreed on is
  gone; the split is not taken because the disagreement is real and the function works.
- **An FBO is created and destroyed per probe** -- 256 pairs in the opening-sweep frame,
  free when the probe was the only caller and once-at-load. Caching it is a
  resource-lifetime change with no rendering consequence.
- **`iblIntensity` scales probe irradiance** as well as the environment's, so a scene with
  an HDR loaded arguably double-counts it. Correcting it moves pixels on the GI-plus-IBL
  path, which no golden covers.
- **Multi-bounce arrives by accident.** `gi_volume_mark_dirty` does not reset `first_pass`,
  so every sweep after the opening one samples the atlas it is overwriting. That is the
  standard DDGI feedback trick and is probably wanted, but it means a volume converged at
  load and one converged by moving the sun are different lighting models. Decide it.
- **The atlas layout law is written twice**, in C and GLSL, in two different
  parameterizations, linked only by a comment. A mismatch would be silent -- every probe
  reads a neighbour's tile, which looks like plausible-but-wrong bounce. The suggested cure
  is a layered texture array keyed by probe index, which deletes the addressing law
  entirely rather than single-sourcing it.
- **`minSpacing` keys the sample bias to the one reduction that collapses** on an
  anisotropic grid. Cubic fixtures hide it.
