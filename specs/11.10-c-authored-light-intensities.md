# Re-author the C-side punctual lights that missed the photometric migration

## Context

The spores flashlight stopped being visible. It was not deleted — it went ~450x dim
and nobody noticed.

`7a29f44` (spec 9.9) switched punctual lights from the fixed-function
`constant/linear/quadratic` denominator to windowed inverse-square, and redefined
`Light.intensity` as candela. Every intensity authored against the old denominator
became meaningless at that moment.

That commit re-authored the fixtures it moved (`cornell_leak` -> 160 lm,
`cornell_point` -> 30 lm). `7304f05` then closed the migration out — but its survey
was explicitly scoped to `.cscn` files:

> The remaining .cscn lights need no migration -- cornell_box and area_light_fixture
> are area panels [...] and contact_fixture is sun-only.

**Lights authored in C were never swept.** `810d3e9` later visited two of those call
sites to delete the now-dead `set_light_attenuation` calls, and added a `range` to
each — but left both intensities on the old scale.

Nothing caught it: `scripts/gates.py` drives `out/bin/render` exclusively
(`RENDER` is hardcoded at line 31), no golden covers spores or shapes, and the
falloff *math* is correct — what broke is an authored constant, which no pixel
comparison of the render fixtures can see. `810d3e9` conceded the gap in its own
verification note: *"spores exercises it and has none either, so that fix is
verified by construction only."*

## Findings

### 1. spores flashlight — ~450x dim (the reported bug)

`apps/spores/src/spores.c:184`. Spot at `(-14, 7, 19)` aiming down `(14, -7, -21)`,
landing on the floor near the origin: d ~= 26.2, d^2 ~= 686, `range` 40.

| | falloff | x 45 |
|---|---|---|
| old triple `(1, 0.018, 0.0012)` | `1/(1 + 0.018*26.2 + 0.0012*686)` = 0.436 | **19.6** |
| now (`lights_ubo.glsl:117`) | `(1/686)*(1 - (686/1600)^2)^2` = 9.71e-4 | **0.044** |

**~450x, ~8.8 stops.** The directional key at `spores.c:167` never consults distance
attenuation, so it kept its 3.0 lux exactly — the flashlight went from 6.5x the key
to 1.5% of it. The volumetric shaft died with it: `froxel_inject_frag.glsl:180` runs
the same `getDistanceAtt` against the same premultiplied `color * intensity`
(`light_cluster.c:212`).

### 2. shapes main_light — ~31x dim (found by the sweep)

`apps/shapes/src/shapes.c:155-156`. Point light at `(0, 50, 200)`, geometry at the
origin: d ~= 206, d^2 ~= 42500. Intensity 5000, colour `(100, 100, 100)`, and
**no `set_light_range`** — so `atten_cutoff.x` packs 0 and the window is disabled
entirely (pure `1/d^2`, no cutoff).

| | falloff | x 500,000 (5000 * 100) |
|---|---|---|
| old default `(1, 0.09, 0.032)` | `1/(1 + 0.09*206 + 0.032*42500)` = 7.25e-4 | **362** |
| now | `1/42500` = 2.35e-5 | **11.8** |

**~31x, ~4.9 stops.** Two things compound here beyond the falloff change:

- The colour is `(100, 100, 100)`, 100x outside the documented `vec3 (0.0-1.0)`
  convention. It is a second intensity multiplier in disguise, and it is currently
  load-bearing — normalising it to 1.0 without raising intensity makes shapes 100x
  darker again.
- With `i_eff = 500,000` and no range, `light_cull_radius` (`light_cluster.c:81`)
  returns `sqrt(500000 * 256)` ~= **11,314 units**. The light is assigned to every
  cluster in the frustum. Not a correctness bug, but it makes the light effectively
  uncullable.

### 3. render point-light grid — NOT a regression, no action

`apps/render/src/render.c:1450-1488`. Worth recording so it is not re-flagged: the
pre-`810d3e9` code computed a *self-normalising* quadratic,
`grid_q = (intensity * 256 - 1) / radius^2`, chosen so the light hit the 1/256
visibility floor exactly at the cull radius. It was never on a physical scale to
begin with. Under honest inverse-square with `range = radius` it now dies at exactly
the same place, by construction rather than by solve. This is a cluster-culling
stress test whose intensity is a CLI knob (`--point-light-grid n,radius,intensity`),
not a look fixture. Leave it.

## Changes

### `apps/spores/src/spores.c:184`

```c
-    set_light_intensity(flash, 45.0f); // candela
+    set_light_intensity(flash, 20000.0f); // candela
```

`19.6 / 9.71e-4 ~= 20,200`, rounded. Lands back on the authored look and is a
physically sane flashlight hot spot (a decent LED torch is 10k-25k cd), so the
migration's premise survives rather than being papered over. `range`, cone angles,
colour and shadow flag all stay as they are.

### `apps/shapes/src/shapes.c:155-156`

Two options; **recommend A** as the minimal in-scope fix.

**A — keep the geometry, re-author to photometric.** Restore the ~362 the scene was
lit at, normalise the colour to the documented convention, and give it a range so it
is cullable and the window is live:

```c
-    set_light_intensity(light, 5000.0f);
-    set_light_color(light, (vec3){100.0f, 100.0f, 100.0f});
+    set_light_intensity(light, 15400000.0f); // candela
+    set_light_color(light, (vec3){1.0f, 1.0f, 1.0f});
+    set_light_range(light, 400.0f);
```

`362 * 42500 ~= 1.54e7`. The number is large because the light genuinely sits 206
units from a unit-scale subject — that is the scene's geometry, not a unit error.
Range 400 covers the layout with headroom and drops the cull radius from 11,314 to
400.

**B — make it directional.** A 2D shape viewer has no reason to want distance
falloff at all, and `3052f4d` already moved the render app this way for the same
reason. `LIGHT_DIRECTIONAL` + `set_light_direction` + an intensity in lux removes
the distance term, the giant candela figure, and the culling cost together. Larger
behavioural change; call it if A looks wrong on screen.

## Verification

**spores** — headless, deterministic (`--frames` rides the fixed-step frame clock):

```
./build.sh
./out/bin/spores -x -f 200 -S /tmp/spores_after.ppm
magick /tmp/spores_after.ppm /tmp/spores_after.png
```

Look for: a bright elliptical pool raking the floor from the left, a visible cone
edge at the 18->20 deg band, and the volumetric shaft through the haze. Capture the
"before" from `HEAD` first for a side-by-side — no golden exists to compare against.

Note spores pins nothing: `spores.c:130` sets `exposure.multiplier = 0.15f` with
auto-adaptation live, and the arg parser (`spores.c:332-344`) accepts only
`--headless / --frames / --screenshot / --cpu`. Per CLAUDE.md's determinism table an
unpinned auto-exposure invalidates cross-build pixel comparison, so this is an
eyeball check by construction. Raising the flashlight ~450x will also pull the
auto-exposure down — expect the room to darken around the beam, which is the
intended low-key look, not a second bug.

**shapes** — no headless mode (CLAUDE.md app table: `Headless: no`), so it must be
run interactively and eyeballed:

```
./out/bin/shapes
```

Look for: the rect / circle / bezier primitives lit at roughly their former
brightness rather than near-black.

**Regression check** — the engine is untouched, so the existing suite should be
unmoved:

```
python3 scripts/gates.py
```

## Out of scope

- Adding a golden or gate for spores. Discussed and declined — it needs a
  `--no-auto-exposure` / `-E` pair on the spores CLI first, since an unpinned
  auto-exposure makes the capture compare as noise (measured 99.77% of pixels
  differing on a provable no-op).
- `cetra/src/light.c:36`, whose comment still reads
  `// 0 = derive from attenuation (light_cull_radius)`. There is no attenuation
  triple to derive from any more — it derives from `intensity * peak colour`. Stale
  one-line comment, unrelated to the visible bug; fold into the next lighting pass.
