# Spec 11.96 — The frame-stale scene graph

## Context

Roadmap **row 61**, split out of 11.94 as "an ARCHITECTURE defect mis-filed as a small win". It is
the only outright *bug* left on the roadmap.

`render_shadow_depth_pass` runs at `engine.c:2625`. All six apps propagate their scene graph inside
their RENDER callback, which `engine_run` invokes at `:2716`. So **every shadow in every app is drawn
from last frame's transforms**, and because the shadow pass is also the first thing to flatten the
draw list (`shadow.c:1429`, stamped per frame at `render.c:808`), **every LOD level is selected from
stale positions too** and the camera pass inherits that list.

Exploration corrected the row on five points, and each changes the work:

1. **There are TWO stale things, not one.** `apps/render` also steps the skeletal pose in its render
   callback — `animation_snapshot_prev_pose` + `update_animation` + `set_render_animation_state`
   (`render.c:2259-2273`) — and the depth pass draws skinned casters from that published state. A
   rig's shadow lags for the same reason its transform does.
2. **The row's two named apps are both wrong.** `apps/shapes` does not "animate its own matrix" — it
   builds a constant identity every frame, and the last `glfwGetTime()` read was removed in
   `45808f15`. `apps/render`'s matrix is non-identity but a **load-time constant** from model bounds.
   The unnamed app that actually passes a non-identity constant is **`apps/pcb`** `(0,0,-700)`.
   Nothing recomputes a root matrix per frame, so the row's reason for needing a per-app matrix hook
   does not exist.
3. **The hook the row proposes is the wrong one.** 11.94 records that `engine_run`'s update callback
   at `:2551` "is the right hook and already exists". It is not: `engine_apply_origin_shift` (2571)
   rewrites root-child `original_transform` and the whole tree's caches, and `sky_cycle_tick` (2597)
   rewrites `light->original_direction`, which the walk rotates. A walk at 2551 is undone by the
   first and strands a node-parented sun by the second. **The window is `engine.c:2604 → 2610`** —
   after the sky block, before the GI capture.
4. **The GI half is permanent, not one-frame.** `gi_volume_update` (2616) bakes probes a converged
   volume never re-bakes. Five of six apps never walk at load at all, so a GI volume in any of them
   would bake a scene collapsed at the origin, forever.
5. **The row's predicted fixture is static.** 11.94 expected `dir_shadow` to show the fix. It will
   not — nothing in the corpus is a moving rigid caster.

---

## The design: a pre-render hook, plus a stamp

**Insert at `engine.c:2605`**, between the sky block and the GI capture:

```c
if (shadow_scene && pre_render)
    pre_render(engine, shadow_scene);
if (shadow_scene) {
    profiler_cpu_scope_begin(engine->profiler, "transform walk");
    scene_propagate_transforms(shadow_scene, engine->total_frames);
    profiler_cpu_scope_end(engine->profiler);
}
```

Apps move their **camera update** and their **graph mutation** into the hook and stop walking; the
engine owns the single walk. `engine_run` grows a third callback positionally (a signature change,
not a setter, so all five callers must decide where the compiler can see it); the game framework
mirrors it as `game_set_pre_render`.

**The root matrix becomes the root node's own `original_transform`**, set once at init. Two apps need
a non-identity value, four keep `create_node`'s identity. `engine->model_matrix` is deleted — nothing
in `cetra/src` reads it.

**The stamp is what makes this safe and incremental.** New on `Scene`:

```c
uint64_t transform_frame;
bool transform_valid;          // false in create_scene
```

`scene_propagate_transforms(scene, frame)` early-outs when the stamp matches. **Not keyed on
`scene_graph_epoch()`** — the draw list must rebuild on a mutation, the walk must not, because
re-walking re-latches every unmoved node's `prev_global_transform` and zeroes the frame's motion
vectors. That distinction needs writing at the field. `apply_transform_to_nodes` keeps its exact
signature and never touches the stamp, so the load-time one-shots stay unstamped and frame 0 always
walks.

### Design B was considered and rejected

Moving the shadow pass into `render_current_scene` needs zero app changes — but that function is
**re-entrant**: `scene_capture_faces` calls it six times per probe (`render.c:1979`), and
`scene_capture_begin` deliberately forces one camera-independent cascade for the whole burst. It
would also leave the GI bake stale (permanent), leave the LOD stamp stale on capturing frames, and
leave frame 0 drawn from an identity graph in four apps. It stays the fallback if the migration
stalls; it buys the smaller half of the bug.

## Phases

### Phase 0 — the instrument, before any behaviour change

**The one fatal outcome of this spec is green across the whole suite**, and that is the sequencing
argument. If the engine walks while any app still walks, `prev_global_transform == global_transform`
everywhere: TAA stops reprojecting, motion blur dies. Nothing in the repo can see it —

- all 29 goldens are static scenes with a static camera, so `prev == global` is *already* true in
  every one and forcing it moves **0 px**;
- `origin-velocity` scores `vel[21] / max(vel[23], 1e-6)`, so a uniformly dead velocity buffer gives
  `0 / 1e-6 = 0` and **passes**;
- `water-fft-motion` measures shader-side spectral motion, not `prev_global_transform`.

So: a `moving-velocity` arm on `apps/spores`, whose `on_update` drives a node off `game->time` with
no wall clock (headless-deterministic), at `--render-mode 9`, asserting a minimum non-zero fraction.
`gates.py` already has mode-9 plumbing (`_origin_forest`, `:3151`). **Prove it goes RED by walking
twice with the stamp removed** before trusting a green run from it.

### Phase 1 — the stamp, no reordering

Add the two `Scene` fields and `scene_propagate_transforms`; convert all six app call sites to it;
move pcb's and render's offsets onto the root node's local; delete `engine->model_matrix`. Same walk,
same place, same composed matrix. **Predicted 0 px on all 29 goldens.** Flag D becomes
unrepresentable here, before anything can trip it.

### Phase 2 — the engine walks

Add `EnginePreRenderFunc`, thread `game_pre_render`, insert at `:2605`. Every app still calls
`scene_propagate_transforms` from its render callback and every one is now a stamped no-op. Still
predicted 0 px.

### Phase 3 — per-app migration, one commit each, ascending blast radius

`pcb` → `shapes` → `spores` → `gametest` → `tree` → `forest` → `render`.

The mechanical rule: **everything above `render_current_scene(engine)` moves to the hook; that call
and anything below it stays; the `reset_and_apply_transform` + `apply_transform_to_nodes` pair is
deleted.** Two apps need care:

- **`apps/forest`** — its three-way ordering moves verbatim and in order: camera block
  (`:2396-2446`) → residency/quadtree descent (`:2453-2472`) → return, engine walks. The comment at
  `:2448-2452` stays and gets stronger. `region_digest_authored`'s note about running before the
  walk (`:1697-1700`) stays true.
- **`apps/render`** — the animation must move **with** the walk and the pair must stay together:
  `animation_snapshot_prev_pose` is the skinned analogue of the node walk's `prev := global` latch
  and carries the identical double-call hazard. `apply_model_recenter` becomes a one-shot at load
  writing `root->original_transform`, left **unstamped** so frame 0 walks. `render_frame_update` does
  not move — its schedule is documented to fire before the camera update, and the hook is still after
  it.

### Phases 0-3: what they returned

**Phase 0's premise was proven on both halves, not argued.** Sabotaging `apps/spores` with a second
walk took `transform-moves` from PASS (2 of 10 rows moving) to **FAIL at 0 of 10**. Sabotaging
`apps/render` the same way and running the corpus left **all 29 goldens at 0 px** — so a build with
every motion vector dead, TAA no longer reprojecting, is completely green against this repository's
main instrument. That is the sequencing argument, measured.

**Phase 1 cost 732,291 px before it cost nothing.** The first shape put the root offset on the root
NODE's own local transform. A scene loaded from a model can already carry a non-identity root local,
and overwriting it loses the model's own placement — `guard_thin_panel` is the one fixture of 29 that
has one. `Scene.root_transform` seeds the walk instead, which preserves the old semantics exactly.
Worth recording because 28 of 29 fixtures said nothing.

**Phase 2 shipped a gate the plan did not have.** Making the engine's walk unconditional immediately
would have broken `apps/forest` for several commits: it attaches streaming regions and quadtree
patches inside its RENDER callback, deliberately, and with the frame already stamped its own call
would no-op and every newly resident patch would draw once at the origin. Gating the walk on the hook
made each app's migration independently safe, and the last app removed the gate.

**Phase 3's result, and it is the half the row never named.** `apps/render` carried TWO stale things:
the node transform, and the skeletal pose published by `set_render_animation_state`, which the depth
pass draws skinned casters from. Raiden, 120 frames, against a 0 px floor:

**227,349 px, 2.7% of frame, PAE 0.027** — structural, not last-bit, and spatially concentrated on
the rig's body and hair, which is where self-shadowing on an animated character changes. The shadow
now tracks this frame's pose instead of trailing it.

Of the 29 goldens only **`froxel_fog` moved, 51 px at PAE exactly 1/255**, and it is rebaked. Its
camera is static, so what moved is frame 0: the shadow pass now runs after the app has settled its
near clip rather than before, and sixty frames of the fog's temporal accumulator damp that into a
last-bit residue.

### Phase 4 — the fixture the corpus does not have

A `.cscn` **cannot express a moving object**; motion comes only from a skeletal clip, from wind
(vertex-stage, therefore not stale), or from app C code. `skinned_cull_fixture.cscn` is the template
— a moving caster is that fixture with `cast_shadows` flipped true and a ground plane added — and
`gen_dir_shadow_fixture.py` already carries the closed-form umbra ellipse to check against.

**The trap that would make this fixture green against the broken build:** driving the caster from a
schedule flag in `render_frame_update` puts the motion in a hook that *already* runs before the
shadow pass. The motion must be authored (a skeletal clip) so that **propagation** is the stale step.

Generator per `gen_skinned_cull_fixture.py`'s structure, with `assert`s that the per-frame
displacement exceeds several shadow texels — an arm that says "the shadow is near the caster" passes
on a one-frame lag. Clip still in motion across the read window, loop point far past it (the inverse
of that fixture's hold-the-pose note). `fixture-gen` byte-diffs the `.gltf`; hand-author the `.cscn`
and the generator must not write it.

Arm in the `origin-velocity` idiom: one process, `--screenshot-every 1`, index numbered PPMs, read
the umbra with `_term_reader` / `_crossing` against `_projector`, and pair it with a still control.

### Phase 4 result: the fixture, and the three ways it would have been green

**551 px on the fixed build, 0 px with the pre-fix ordering restored**, against a 0 px still-frame
control. `shadow_lag_fixture`, generated, with two arms in a `shadow-lag` group.

Three constraints shaped it, and each one is a way the obvious fixture passes against the bug it
exists for:

- **Constant velocity shows nothing.** A shadow one frame behind a body moving at a constant rate is
  displaced by exactly one frame's travel between consecutive frames — and so is a correct one. The
  clip HOLDS and then starts, and the arm reads the onset.
- **The body must be invisible.** In frame, its own motion dirties the comparison and the arm needs a
  region mask. Sun overhead, caster above the camera, camera on bare ground: the only thing that can
  change is the shadow, and the read is a whole-frame compare.
- **The motion must be an authored clip.** A `.cscn` cannot express a moving object, and a schedule
  flag driven from `render_frame_update` runs BEFORE the shadow pass. Being skinned, this covers the
  POSE half; the node-transform half stays with the CPU probe arms.

Two geometry lessons the corpus had never had to learn, both of which render as *nothing*: a single
quad casts no shadow, because the depth pass culls a face and a zero-thickness plane then writes no
depth; and the obvious winding over a ground quad's corners gives a **−Y** normal, so the plane is
culled from a camera above and the frame is empty background — which reads as a missing shadow and
sends you to the wrong pass.

### What the review changed

Seven review agents ran over the branch. Three findings were real and mine:

**Both gate arms were weaker than their docstrings.** `transform-stills` asserted nothing: its `bad`
list could not be non-empty (a `mat4` memcmp reporting equality makes `step` exactly 0), and what
remained was satisfied by nodes `create_node` left at identity whether or not the walk ran. It passed
**both** mutations it claimed to catch. `transform-moves` was bounded below only — dropping the latch
makes `step` GROW. Both fixes were already on the wire: the probe printed five fields and the arms
read two, and the three unread ones were the three missing assertions.

**The stamp was dead state guarding a real hazard at the wrong level.** One caller, once a frame,
monotonic counter — the early-out could never fire. But deleting it alone was wrong:
`apply_transform_to_nodes` fused `global := parent · local` (pure) with `prev := global` (temporal,
non-idempotent), and the stamp made the second safe by forbidding the first to re-run. **That is what
the whole `pre_render` contract was paying for.** Splitting the latch — the shape `prev_view_proj`
already had — made the walk idempotent and deleted two `Scene` fields, the stamp parameter, the
unread `bool`, the primitive/entry-point split, and the silent failure mode. Verified by walking
twice on purpose: green, where before it zeroed every motion vector.

**A latent bug the hook created.** `pre_render` can switch the active scene, after which the draw ran
on one no pass had prepared. Unreachable before the hook existed.

Plus eight stale comments, one of which — `render.c:1221` — **blessed the exact defect this spec
fixed** as correct behaviour, and a stale special case in `terrain_quadtree.c` defended by a hazard
this spec removed.

**Declined, with reasons:** hoisting the camera-matrix update into `engine_run` (real, deletes two
`pre_render` callbacks, but a behaviour change to every app that wants its own measurement); a
placement node instead of `Scene.root_transform` (two agents disagreed; the field has a measured
justification and now records that it is not origin-shifted); and an `EngineCallbacks` struct —
which is a genuine hole, since `EnginePreRenderFunc` and `EngineRenderFunc` are the same type and
slots 3 and 4 are silently swappable, undercutting this spec's own "the compiler forces a decision"
argument. All three are booked rather than done.

### Phase 5 — documentation

`AGENTS.md`'s per-frame loop, roadmap row 61 and the known-limitation entry (whose line number has
drifted — it says `engine.c:2231`), `render.c:1243-1246`'s emissive comment (which becomes false),
and 11.94's prediction that `dir_shadow` would show it.

## Verification

- **Phases 1 and 2 are 0 px on all 29 goldens** — they change no ordering, only ownership. Movement
  there is a bug, not a rebake.
- **Phase 3 moves pixels by construction** in every app that casts a shadow. Each app's commit names
  what it expects to move before it moves.
- **Noise floor first**, every time. `apps/forest` is not pixel-deterministic (34,991 px at 60
  frames); `apps/tree` only reaches 0 px under `--player --headless`.
- **Scoped groups during**: `cull`, `draw-list`, `lod`, `submission`, `origin`, `terrain`, `region`,
  `island`, `forest`, `dir-shadow`, `catcher`, plus `gate-docs` (which `--only` never reaches on its
  own). Whole suite once at the end.
- **`gate-arm-docs` format is exact**: indent-4 prose anchor, indent-6 arm names, verdict in one
  double-quoted literal. Never edit `gates.py` mid-run.
- Both new arms must **fail under a named one-line mutation**, stated before the bar is written.

## What this will NOT do

- **Use the update callback at `:2551`**, which 11.94 recommends on record. Flags O and S refute it.
- **Split the `prev` latch out of the walk.** It is fused on the same stack pop; a separate traversal
  doubles the walk to buy what the stamp already gives.
- **Key the propagation stamp on the graph epoch.** That would re-walk on mutation and zero the
  frame's motion vectors.
- **Move `scene_build_emissive_lights` or the particle tick.** Both become legal earlier; hoisting
  the emissive build would let a derived panel cast a shadow map, which is a feature, not this spec.
- **Fold `render_current_scene` into the engine.** `gametest` brackets it with cull state and
  `apps/render` draws bones after it — the render slot still has a job.
