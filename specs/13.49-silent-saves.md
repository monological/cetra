# Spec 13.49: silent saves -- a title over the town, autosaves, and a load list

## Context

silent saves nothing; quitting loses everything. The user wants autosaves only (no manual saves,
checkpoints maybe later), and a menu after the loading intro. Their choices:
- **The title sits over the foggy town**: the loading screen switches off onto a fixed view down
  the street with the menu over it.
- **Continue / New Game / Load Game.** Continue loads the newest game and is hidden when there is
  none.
- **One save per playthrough**, up to 8. New Game starts a game in a slot of its own, and its
  autosave overwrites itself. Load Game lists the games newest first, each with where, when, and
  play time.
- **Delete from the load list**, with a confirm.
- **The crouch is not saved**, unless standing would not fit where the player was.

The engine has had a save system since spec 12.3 (`cetra/src/game/save.h/.c`). Only gametest uses
it. Exploring it against silent turned up these gaps (references are from the exploration):
- **It writes EVERY entity** (`save.c:540`), and silent's kit colliders are 1,400+ static bodies
  whose names REPEAT across its five kits (`kit_col_N`; `kit_init` resets the counter). A load
  matches by name, so it would move one kit's colliders onto another's.
- **There is no way to read a save without applying it**, which a load list needs, and no
  timestamp in the file.
- **There is no field type for "one of these named things"** (the cat's place). Items, finds and
  per-place times do not need one: each gets a row keyed by its own id, so the file never holds an
  index that a new item would renumber.

## Design

### Engine (`cetra/src/game/entity.h`, `save.h/.c`)

1. **`Entity.unsaved`**, a SETTINGS bool: the entity is left out of a save, because the app rebuilds
   its state rather than restoring it. It defaults false (`create_entity` callocs), so gametest is
   unchanged. The writer also says so, by name, when two saved entities share one name, since a
   load cannot tell them apart.
2. **`SAVE_ENUM`**: an int written as the NAME at that index of a table the row carries
   (`SAVE_ROW_ENUM(key, struct, member, names, count)`). A name this build does not know leaves the
   field as it is and is counted in a new `SaveLoadResult.dropped_unknown_name`. That is the record
   rule: a patched game that renamed a place drops that one field, not the file.
   `config_snapshot.c`'s `CFG_ENUM` (1097-1107, 1473-1482) is the encoding to follow.
3. **`saved_at`**: `save_write` stamps the wall clock as a top-level number. An older file without
   one reads as 0.
4. **`save_peek(save, path, section, base, SavePeek* info)`**: reads one registered section's rows
   into a CALLER's `base`, with that section's migrations, and touches nothing live. It fills
   `info` with the file's version and `saved_at`. It refuses by name a table holding `addr` or
   get/set rows, since those write live state wherever they are pointed. It is built from
   `_section`, `_migrate_section` and `_read_field`.

No directory listing is added: the engine has none that is portable, and silent's slots are a
fixed set of names (`save_default_path` plus `path_exists`).

**Gate arms**, in the existing `save` group, through new `gametest --save-probe` cases:
- `save-unsaved`: an unsaved entity has no record, and a load leaves it where it is.
- `save-names`: two saved entities with one name are said by name at write.
- `save-enum`: a name round-trips, and an unknown name leaves the field and counts 1.
- `save-peek`: a scratch base is filled, nothing live moves, `saved_at` is present, and an `addr`
  table is refused.

Each arm prints its literal verdict for `gate-arm-docs`, and each is falsified after a commit.

### silent: what a save holds (`apps/silent/src/save_game.c/.h`, new)

One `SilentSave` struct, registered as offset-only tables over `static SilentSave g_save`.
`save_game_gather()` fills it from the live modules before `save_write`, and
`save_game_apply()` pushes it into them after `save_read`, so the derived parts (door poses, the
bag's grid, the cat's posture) are rebuilt by the module that owns them.

| Section | Rows | Applied by |
|---|---|---|
| `summary` | play seconds, the feet (vec3) | the load list, through `save_peek` |
| `player` | yaw, pitch | `player_restore`: aim the rig, reset `step_from`/`view`, and settle the stance (below) |
| `items` | per item id: the order it was had, 0 = not | `backpack_restore`: frees the bag's node if taken, sets `held`, packs again |
| `finds` | per place id: found; per place id: inked; the map opened | `finds` memcpy plus a re-entry settle; `map_screen_restore` |
| `doors` | per door name: travel, want | `door_set_travel`, a new public setter calling `door.c`'s static `place()` |
| `world` | flashlight on, the basement's draft time | `Lights.flashlight_on`, `Basement.drafted` (an absolute sim time; the engine's `world` section restores `Game.time`) |
| `cat` | its place (`SAVE_ENUM` over the place names), energy, boredom, alarm, affinity, per place `since` | `cat_place_at`, refactored out of `cat_create`'s placement so both use it; `cat_mind_restore` (`spot = -1`, interrupt the brain) |

**The player is the one saved entity.** The engine's walk restores its controller's position and
velocity. Kit colliders, the basement bar (derived from the bag every step), the doors and the cat
are marked `unsaved`: their state is in the tables above.

**The crouch is not saved.** On load the capsule is shrunk, which always fits, and then standing is
tried once. Where there is room the player stands. Where there is none, under the gallery sconces
or a future duct, they stay crouched, and the crouch step stands them up once they walk out.

**Re-entry latches are settled from the restored feet**, `Finds.here` and the basement's `at_foot`,
so a load inside a find's box thinks nothing. Fridge map: if the map is held, its node is freed.
The flashlight needs nothing: having it is the bag's contents.

**Slots** are `silent-1` .. `silent-8` under `save_default_path`. The list peeks each existing one,
newest first. "Where" is worked out at list time from the saved feet, through a new
`sounds_room_at(feet)` over `sounds.c`'s room table (last added wins, as the zones do). The label
reads "Home, kitchen", "Mansion, upstairs", "Cabin", or "Outside". Delete is `remove()` on the file.

**Autosaves** happen when the player:
- takes something;
- finds a place;
- changes room, no sooner than 10 s after the last save (judgement);
- quits (`on_shutdown`, while entities still live).

A trigger sets a pending flag, and the write happens in `on_pre_render`, timed and printed in one
line. If the write turns out to cost a visible hitch, it moves off the main thread. That gets
measured, not assumed.

### silent: the title (`apps/silent/src/title.c/.h`, new; flow in `silent.c`)

**States:** `TITLE_LOADING`, `TITLE`, `ENTERING` and `PLAYING`.
1. **Loading.** The loading screen runs as today. The camera is pinned to a title pose through the
   existing `player_pre_render(pin_eye, pin_target)` path. The pose is a fixed view across the
   street to the house under a lamp, constants in `title.c`, tuned by eye. The lit check is
   `scene_lighting_ready_in` at that eye. Once lit, the screen is HIDDEN at once. There is no PLAY
   prompt: the menu is the press. The `start` action and `--no-play-prompt` go.
2. **Title.** Once the screen has switched off, the view fades in on the street, and the title
   screen is pushed: modal, built like gametest's `ui_menu_panel`, styled after `hud.c`. The
   player's input is suppressed by the modal capture. The HUD's reach and prompt are skipped, so no
   "E Open door" shows over the title.
3. **Entering.** A choice fades to black on the grade gain. Then:
   - Continue or Load: `save_read` plus `save_game_apply`.
   - New Game: the new state is what init built.

   The camera returns to the player, and the slot is fixed. The wait is the lit check at the
   player's eye, then a fade in.
4. **Playing.** Autosave is armed, and play seconds count in the fixed step.

The fade becomes one value eased toward a target, replacing the fade-in-only `g_fade_seconds`.

**Screens:**
- `title`: Continue, New Game, Load Game. With 8 games kept, New Game shows a line saying to
  delete one in Load Game.
- `games`: one button per save, showing where, when and play time. Accept loads; back returns.
- `delete`: "Delete this game?", No then Yes. It is reached by a new `ui` action `menu_delete`
  (Delete, Backspace, pad X) on the focused row.

`on_frame_input` sets `UIInput.back` for these screens as it does for the bag and the map.

**Which sessions save:** a launch that goes through the title is a GAME and autosaves. Every other
start is a TEST session that does not, unless `--slot NAME` names one:
- headless;
- `--new-game`;
- any state flag (`--player-at`, `--found`, `--backpack`, `--map`, `--flashlight`, `--cat-at`,
  `--crouch`, `--cat-goto`, ...).

So a probe or a dev run never overwrites a player's game.

**New flags:**
- `--title`: show the title headless too, to photograph it.
- `--title-screen games|delete`: open that screen.
- `--load SLOT`: start from a save and skip the title.
- `--new-game`: skip the title.
- `--slot NAME`
- `--no-autosave`

## As built

### Phase 1: the engine

**`Entity.unsaved`** is honoured in both directions through one lookup, `_find_saved`: the first
entity by a name that takes saved state.
- **Writing:** the writer skips a marked entity. When `_find_saved` answers another entity for this
  one's name, it says so by name ("more than one saved entity is named 'X'; a load cannot tell them
  apart"). The plan said a load restores "the first", but that was wrong: every record by the name
  goes to the first entity, so it ends up with the LAST record's state.
- **Reading:** a record whose entity is now marked drops as missing, because an older file still
  names it.

**`SAVE_ENUM`** is written as the name.
- **An index outside the table** is the app's bug. It costs that one key, with a warning, and not
  the write: failing the whole save would cost a player everything for one bad field.
- **On read,** a name the table does not hold makes `_decode_value` return -1. `_read_field` now
  takes the `SaveLoadResult` so it can count `dropped_unknown_name`.

**`saved_at`** is `time(NULL)`, a top-level number. `save_peek` reads it as a double, because a
float misses the epoch by minutes.

**`save_peek`** shares two helpers with `save_read`. `save_read`'s parse and its table walk were
split out as `_parse_file` (the two file-level refusals) and `_read_table` (one section, migrated,
into any base).

**Gates:**
- `_save_probe_env` and `_save_probe_file` were factored out.
- `save-format` now reads its file through the latter.
- `save-names` reads the run's whole output through `_gametest_probe_text`, since what it asserts
  is a log line.
- The probe's enum row is a MUTABLE table, so swapping its names pointer between the write and the
  read stands in for a patched build.

**Falsified,** with one mutation per arm in one build. The four new arms went red and the other
eight stayed green:
- `save-unsaved`: `_find_saved` ignoring the mark. The marked entity came back to 4,5,6, and 2 were
  restored.
- `save-names`: the warning compiled out. 'twin' was named 0 times.
- `save-enum`: the index written as a number. 'attic' came back as 0, and nothing was counted.
- `save-peek`: the address refusal compiled out. player_yaw came back as 1.25.

### Phase 2: what silent keeps

**Sections.** Each row is keyed by the thing's own id or name:
- `summary`: played, feet;
- `player`: yaw, pitch;
- `house`: `flashlight_on`, `basement_draft`;
- `items`: `backpack` and one row per item id;
- `finds` and `inked`: one row per place id;
- `doors`: each door's name for travel, and `<name>.want`;
- `cat`: place as an enum over `CAT_PLACES`' names, then the four needs;
- `cat_since`: one row per place name.

There are nine sections plus the engine's `world`, against a cap of 16. The cat's two are
registered only when it has a mind; held on a clip or sent somewhere from the command line, nothing
about it is the game's.

**Differences from the plan:**
- **No "map opened" row.** `map_screen_inked` alone carries the state, so `map_screen_show`'s "a
  mark finished last time is whole now" now goes through it as well.
- **One engine function was added: `brain_stop`.** A cat put at a place by a load cannot keep the
  activity it was in. `brain_interrupt` only re-scores, after the running activity has stepped once
  more, toward a spot the cat is no longer near. The stop is on the ordinary cooldown, since the
  activity did not fail.
- **`cat_put`** shares `rest_at` with `cat_create`. It drains the root motion the old clip had laid
  down, or the next step would walk it off.
- **`player_restore`** reads the body from the controller the engine's section wrote. It resets the
  step and draw positions and the gait, aims the rig, then shrinks the capsule and tries to stand.
- **Re-entry latches** have their own settles: `finds_settle` and `basement_settle`. The basement's
  zone test is now one helper, `at_flight_foot`, shared with `basement_hold`.
- **`sounds_room_at` and `sounds_room_label`** share `room_boxes` with `sounds_start`, so a room's
  boxes, its tower and the mansion's move are worked out once.
- **Unsaved:** every kit collider, the doors, the basement bar and the cat. The player is the one
  entity in the file.
- **The title's camera (for phase 3):** a rig of its own, installed while the title shows, not the
  player's rig pinned. `camera_rig_set_pose` derives a distance and zeroes the lifts, so pinning the
  player's own rig would leave first person needing to be rebuilt afterwards.

**The write costs 0.4 ms** at a quit (the JSON with one entity, and the fsync), so it stays on the
main thread.

**Checked headless** with `CETRA_SETTINGS_DIR` set to a scratch directory:
1. `--backpack --map --found all --flashlight --player-at -52,30,90 --slot silent-1` wrote at exit.
   The JSON was read.
2. `--load silent-1`, with no state flags, came up at the same spot and facing with the flashlight
   on.

The two frames were compared side by side.

### Phase 3: the title

**States.** `RunState` is LOADING, TITLE, LEAVING, ENTERING and PLAYING. The plan had four: LEAVING
is the fade to black after a choice, before the game is put in place, since that cannot happen
while the title is still showing.

**The title's camera is a rig of its own**, posed at `TITLE_EYE` looking at `TITLE_TARGET` and
installed with `engine_set_camera_rig` from init, so the view loads round the title's eye under the
loading screen. Entering a game installs the player's rig. The plan's pin through
`player_pre_render` was not used, for the reason phase 2 gives.

**The fade** is one value eased toward up or down on the grade's gain, after the tonemap, so the
exposure and the day's meter never see it. Each frame's step is capped at 1/30 s, since a frame of
captures can be long.

**The screens** are three modal screens in the HUD's UI system: the title, the list and the
question. As built in this phase, each replaced the one it was opened from (a pop and a push), since
screens stacked draw beneath one another and the title's wordmark showed through the list's dim;
`title_input` put the one underneath back when the list or the question went. The review replaced
that (below).

**The UI gained `ui_set_focus` and `ui_focused`**, so a menu opens on its first item and the delete
key knows which row it is on. `ui-focus-set` holds it, falsified with a no-op setter: "focus -1 -> 0
-> 0 -> 1, reported 0".

**Which runs save** is as planned: a run that goes through the title autosaves; any other saves
only with `--slot`. Headless shows no title unless `--title` or `--title-screen`.

**The `start` action and `--no-play-prompt` are gone**, since the title is the press. `menu_accept`
gained Space and pad Start, and `menu_delete` is new: Delete, Backspace and pad X.

**Checked headless:** pictures of the title, the list and the question, opened in Preview.

### Review

Five background reviews: the thermo-nuclear one and `/simplify`'s four (reuse, simplification,
efficiency, altitude). What changed:

**Engine**
- **`ui_screen_set_opaque`.** An opaque screen hides every screen under it while it is on the
  stack, and `ui_build` draws from the highest one. The title's list and question are opaque and
  stack normally, so the UI's own back returns to the screen under, which kept its focus. This
  deleted the replacement, `title_input`'s repair, and the `up` and `doomed` fields. `ui-opaque`
  holds it: stacked plainly both screens draw, opaque the top one draws as it does alone, popped the
  one under draws as it did. Falsified by ignoring the flag: "opaque the top draws as it does alone
  (0)".
- **A second saved entity by one name is not written.** A load gives every record by a name to the
  first entity that has it, so the second record overwrote the first's state with its own. Only the
  first is kept now. `save-names` also counts the file's records. Falsified by writing it again:
  "2/1, want 1/1".
- **`_find_table`** is the one section lookup, used by registration and the peek.
- **An enum row with no names is refused at registration**, so the writer and reader no longer
  check for one.
- **`brain_stop`** lost `interrupted = true`. With nothing running, the next update chooses anyway.
- **`save_peek`** takes a const system.

**silent**
- **The save points at the modules' own fields.** Rows by address reach the rig's yaw and pitch,
  the flashlight, the draft, each door's travel and want, the finds and the cat's needs, so a
  missing section leaves the live value as it is. Only what no module holds as a field is kept in
  a struct of its own (`Kept`): the summary for the list, the bag and the order things were had,
  the marks written whole, and the cat's place. Each saved value used to appear four times (the
  struct, the row, the gather, the apply).
- **The doors are two sections**, `door_travel` and `door_want`, keyed by the bare name, so there
  are no composed keys.
- **One way into a game**, `enter_game(engine, load, slot)`, from init with the command line's
  slots and from the title with its choice. A failed `--load` no longer goes on to autosave into the
  slot it could not read.
- **The eye is the installed rig's pose**, so the title's view is stated once.
- **The capture budget is worked out from the run's state each frame:** high under the loading
  screen and in the black while a game comes up, the play budget otherwise. It used to be raised at
  the choice, during the fade out, and dropped as soon as the title's eye was lit, which outside
  every GI volume was at once.
- **`starts_elsewhere`** sits beside the arguments it reads, in place of the `test` field.
- **`save_game_moment` became `save_game_due` and `save_game_quit`.** The room rule is
  `save_game_frame`'s own. `save_game_slot` had no caller and is gone. The autosave path is
  resolved once, when a game begins, and not on every frame a write is due.
- **The rooms are a module of their own**, `rooms.c/h`: the table with each room's label, its boxes,
  and `room_at` through `aabb_dist_sq`. The sounds and the save list read it, and `SaveSlot` carries
  the label, so the title no longer includes the sounds.
- **Smaller changes:**
  - `hud_bare` replaces the bag screen's `bare()` and the title's `column()`. A see-through fill
    replaces the no-op draw, since a style can say `bg` alpha 0 without inheriting the theme's.
  - `cat_stand` replaces three copies of the half-height offset and the yaw.
  - `backpack_restore` goes through `backpack_take` and `backpack_add`.
  - `player_init` and `player_restore` share `stand`.
  - `finds_arrive` and `finds_settle` share `place_distance`.
  - The cat's "curled is asleep" rule is written once.
  - The title keeps no copy of its labels.
  - `focusable` is no longer toggled beside `disabled`.
  - Comments that named their callers were reworded.

**Not taken:**
- **Saving the capsule's height in the engine's character record.** It completes the record but
  changes its format, wants an arm, and deletes one line in silent.
- **Skipping the frame's draw while the screen is black.** It is a new engine path; a later spec if
  the wait under black is ever too long.
- **One name lookup in `json_util` for the three enum readers.** It is a loop of three lines whose
  policies differ, and not a cJSON shape.
- **A shared label helper for the title and the bag.** The two set different style fields.
- **Pausing the game behind the title.** The clock, the cat and the doors run while it is up, so a
  New Game starts wherever they had got to. Left for the user to decide.

**Checked headless:** the save and load round trip (the same place and facing, the flashlight on,
84 fields, nothing dropped), the title sheet, and a scripted pad through the delete flow. Two games
were deleted one after the other: the list came back on the game that took the first's place, and
then the title came back on New Game with Load Game greyed and Continue gone. Back on the title did
nothing. `gates.py --only save,ui,gate-docs` passes.

### The save mark

Asked for after the review: an autosave was silent, and with no manual saves the mark is the only
way a player knows a game is kept. It sits in the bottom right corner:
- **A three-branched candlestick on the left,** drawn by `shaders/candles_frag.glsl` over one quad
  through the UI's element program. Its candles light one after another, left to right, as `uFocus`
  goes from 0 to 3, and the lit flames flicker on the UI's clock.
- **The words on the right:** "Saving..." while the candles light, then "Saved". The mark is placed
  for the longer of the two, so the candlestick does not move when they change.
- **One colour,** the thoughts' own, for the candlestick and the words. A gap between each candle and
  its flame is what tells them apart.
- **Timing:** up over 0.25 s, the candles lit over 1.2 s, "Saved" for 1.6 s, gone over 0.8 s. The
  write itself takes under a millisecond, so "Saving..." is only there for the candles to light.
- **When it shows:** the HUD shows it when `save_game_frame` reports a write. A save while it is up
  says "Saved" again without going out first. The save on a quit shows nothing, since nobody sees
  it.
