# The API cleanup: specs 11.106, 11.107, 11.108

## Context

Cetra's API grew with its own apps. Three exploration passes over the nine in-tree apps and pcb
measured what that produced: 1,089 declared functions of which apps call 388 (204 from one file);
two naming conventions in equal use in `engine.h` (20 `set_engine_*`, 21 `engine_*`) and a dozen
pairs that say one thing two ways; 296 distinct struct fields apps write directly, some of which
carry invariants (`camera->distance` desyncs from `set_camera_position`, `headless_jitter` has an
ordering rule and no setter); 91 headers all exported, so a consumer sees the draw list and the
light cluster beside the engine, and `#include "cetra/engine.h"` pulls assimp and pthread into
every TU; and a set of silent failures a new app meets in its first hour: a mesh that was never
uploaded passes the draw list's filter (it tests `vao == 0`, but `create_mesh` already generates
the VAO) and dies as a `GL_INVALID_OPERATION` nobody checks; a triangle mesh on the `shape`
program does the same; a material with no program is dropped without a word; a program name typo
returns NULL without a log; a scene with no light is black; the clear colour is a literal.

Decisions made: **public functions are renamed freely** (every consumer is the user's, updated in
the same commit); **the API takes the hybrid shape modern C libraries converge on** (sokol,
Vulkan, WebGPU): an object is CREATED from a description struct filled with designated
initialisers and defaults by omission; a live object is MUTATED through a function wherever the
engine has to react (validate, order, propagate, re-derive); everything else, the tuning blocks
and the content arrays, is a documented public field. Structs stay visible; the GUI keeps its
direct writes; **no new instruments or docs files** — verification is the existing suites plus
every app building, and documentation goes into headers, README's consumer section and AGENTS.md.

The test that decides field versus function is not who writes the value but whether the library
must react when it changes. A setter that only stores is ceremony that hides nothing; a field
that needs a reaction is a bug waiting.

Three specs, in order, because B and C name functions and every name must be final first. Each is
a branch off master, spec committed alone, one commit per phase, scoped gates between phases,
goldens and the full suite at the end, reviews in background agents before applying anything.
After each merge, pcb gets one commit in its own repository: `src/main.c` updated and the
submodule bumped.

**Verification vocabulary** used throughout: *goldens* = `python3 scripts/goldens.py`, 30 at 0 px;
*captures* = `-x -f 2 -S` frames from sprites, network, spores, forest, tree and pcb, compared
byte-for-byte against the same capture at the previous commit (the 2D apps have no golden, so this
is their proof); *hand launch* = shapes, gametest and splash run to a window and recorded.

# Spec 11.106 — The public surface

## Scope

The header allowlist and a real include boundary; one naming convention with the rename done
once, everywhere; return conventions; program-name constants; the create/init collapse. Non-goals:
any behaviour change, any setter added or removed for a policy reason (11.108), any new logging
except the program-miss line (its silence is a return-convention defect).

## 1. The boundary

`cetra/CMakeLists.txt:26-35` globs every header into `include/cetra/`. It becomes an **allowlist**:
`set(CETRA_PUBLIC_HEADERS ...)`; a listed header forwards to `include/cetra/<name>.h`, every other
header under `src/`, `src/game/`, `src/procedural/`, `src/ext/` forwards to
`include-internal/cetra/internal/<rel>.h`. The internal tree is PRIVATE on `cetra` and added to
in-tree apps by `add_cetra_app` (`apps/CMakeLists.txt`); a consumer through `add_subdirectory`
never sees it. `src`, `src/ext`, `src/game` (`cetra/CMakeLists.txt:80-84`) go **PRIVATE** — apps
use only `cetra/...` includes (verified), and the one thing that breaks, `text.h:7 <uthash.h>`,
becomes `"ext/uthash.h"`. cimgui and JoltC dirs stay PUBLIC (tree's GUI uses `cimgui.h`).

**Public `src/*.h` (43):** animation, app, camera, common, compat, config_snapshot, cook, cscene,
decal, engine, exposure, geometry, gi_volume, ibl, ies, import, input, light, material, mesh,
mesh_builder, noise, particle_emitter, particle_module, particle_renderer, particle_sim,
particle_system, postfx, probe, probe_set, program, scene, shader, shadow, sky, springbone, text,
texture, transform, uniform, util, water, wind; all of `game/` and `procedural/`; `ext/log.h`,
`ext/cwalk.h`.

**Internal:** async_loader, cluster, draw_list, emissive_light, engine_internal (new), gui,
intersect, layers_vt, layers_vt_pages, light_cluster, lod, ltc, ltc_lut, lut,
material_texture_array, moon_map, moon_surface, occlusion, particle_pool, physics_cook,
probe_atlas, profiler, render, rigging, roads, shore_chain, shore_runup, texture_compress, thread,
ubo, and `ext/` except log and cwalk.

The rule, stated in the CMake comment and AGENTS.md: **the allowlist governs what an app may NAME
in an include, not what a public header's closure reaches.** `material.h` includes `roads.h`,
`texture.h` includes `thread.h`; that stays. An in-tree app may include `cetra/internal/`; an app
that must is a debug harness and says so in its header comment (render, forest); pcb includes none.

Apps that include internals today and what they become: render (`occlusion.h`, `light_cluster.h`,
`emissive_light.h`, `profiler.h`, `async_loader.h`, `render.h`, `shore_chain.h` → `cetra/internal/`),
forest (`cluster.h`, `lod.h`, `physics_cook.h`, `profiler.h`), sprites (`particle_pool.h`);
shapes/tree/render include `shader.h` vestigially (no `create_shader` call) — delete. Eight apps
include `render.h` for `render_current_scene` alone; it moves to `engine.h` as
`engine_render_scene(engine, scene)` (it re-looks-up the scene today, `render.c:1253`, while
`engine_run` hands the callback the scene it propagated — the pair can disagree) and they drop
`render.h`.

**`engine_internal.h`** takes the pass brackets no app calls: `engine_present_frame`,
`engine_set_scene_draw_buffers`, `engine_resolve_opaque_color`, `engine_resolve_scene_depth`,
`engine_begin/end_oit_pass`, `engine_begin/end_moment_pass`, `engine_upload_displacement_uniforms`,
`engine_render_size`, `engine_post_size`, `engine_pbr_variant`. Embedder hooks stay public with a
comment: `engine_set/get_user_data`, `engine_set_render_clock`, `engine_set_render_time`,
`engine_set_scene_by_index/name`, `engine_gui_wants_mouse/keyboard`.

## 3. The naming rule

**Subject first.** The first word is the type of the first parameter, lowercased (`engine_`,
`scene_`, `node_`, `mesh_`, `material_`, `camera_`, `light_`, `game_`, `mouse_drag_`,
`particle_emitter_`), then the verb, then the object. `create_X` / `free_X` are the one exception
(AGENTS.md's factory rule stays). Getters are `x_get_y`; lookups that may miss are `x_find_y` and
return NULL silently; an `x_get_y` that returns NULL logs. This is the convention the newer half of
the tree already uses (`engine_run`, `scene_propagate_transforms`, `mesh_ref`, `material_param_set`,
`particle_emitter_add_module`, `game_set_update`, `water_update`, `sky_bake`, `cook_init`).

**Rename table.** Everything an app calls in engine.h, scene.h, mesh.h, material.h, camera.h,
light.h, geometry.h, transform.h, app.h, game.h, wind.h, import.h. `del-B`/`del-C`: renamed here,

## 4. Return conventions

- **void** for a mutator whose only failures are a NULL argument or OOM: it logs and returns. All
  ten unbounded `add_*` (checked by zero app sites) become void.
- **bool** for a request that can be refused for a reason the caller can act on: the three bounded
  arrays, `node_remove_child`, the pass brackets, `engine_init` if it survives.
- **NULL on failure** for factories and lookups. `engine_get_program` logs
  `no program '%s' (%zu registered)`; `engine_find_program` is silent for the optional probes
  (`shadow.c:1114,1276,1278`) and the variant cache check (`engine.c:1591`). No `GLboolean` on the
  public surface.

## 5. Program names

Lookup by name stays (the variant cache formats `pbr-<mask>` at runtime, `program.c:587-593`; an
app's own program needs a name the engine never enumerated). `program.h` gains
`CETRA_PROGRAM_PBR "pbr"`, `_PBR_SKINNED`, `_SHAPE`, `_XYZ`, `_PARTICLE`; `pbr_variant_name` reads
the constant so the two cannot drift.

## 6. Creation takes a description: `EngineConfig`, `CameraDesc`, `LightDesc`

The three objects an app builds that carry derived state are created from a description struct,
named, with designated initialisers and defaults by omission (zero means "the default", the way
`EngineConfig.msaa_samples = 0` means 4). The desc is a separate type from the object: the object
keeps its derived state (matrices, orbit parameters, world-space direction) and the desc is what
the app authored. Material and Mesh do NOT get one: a material is seventy-six tuning fields a GUI
edits live and a mesh is content a generator fills, so both stay create-with-defaults then fields.

```c
CameraDesc desc = {
    .position = {0.0f, 2.0f, 5.0f},
    .look_at  = {0.0f, 0.0f, 0.0f},   // up defaults to +Y
    .fov      = glm_rad(45.0f),       // .ortho_height > 0 makes it orthographic instead
    .near     = 0.1f, .far = 100.0f,  // 0 = the engine's defaults
    .name     = "main",
};
Camera* camera = create_camera(&desc);

LightDesc key = {
    .type = LIGHT_DIRECTIONAL, .direction = {-0.25f, -0.75f, -0.6f},
    .color = {1.0f, 0.86f, 0.62f}, .intensity = 3.0f, .cast_shadows = true,
};
scene_add_light(scene, create_light(&key));
```

`CameraDesc`: name, position, look_at, up, fov, near, far, ortho_height, orbit distance/height/
speeds where an app sets them today. `LightDesc`: name, type, position, direction, up, color,
intensity + units, range, inner/outer cutoff, size, cast_shadows, ies profile. After creation the
builder setters are gone: `camera_set_up/perspective/orthographic/direction/name` and the twelve
plain `light_set_*` become field writes (`camera->fov_radians = ...`, re-derived every frame once
11.107 lands; until then the app's `engine_update_projection` call still does it). What survives
as a function is what reacts: `camera_set_position/look_at` (orbit sync), `light_set_direction/up`
(the authored-versus-world split), `light_set_intensity_units` (conversion). `create_camera()` and
`create_light()` with no argument mean "all defaults" (NULL accepted).

`EngineConfig` is the same idea one level up, and `GameConfig` (`game.h:33-71`) is the evidence
for it: ten of its fifteen fields exist because `create_game` owns the `init_engine` call and each
carries an ordering comment; `game.c:67` writes `headless_jitter` after init, which reads it at
`engine.c:977` — a live ordering bug the struct removes by construction.

```c
typedef struct EngineConfig {
    const char* title; int width, height;
    bool headless;        // hidden window, vsync off
    bool headless_jitter; // keep the TAA jitter under headless
    bool profiler;
    bool vsync;           // default true; ignored headless
    int msaa_samples;     // 0 = 4; the first build's count
    int ss_scale;         // 0 = 1
    float render_scale;   // 0 = 1
} EngineConfig;
EngineConfig engine_default_config(void);
Engine* create_engine(const EngineConfig* cfg);   // creates AND initialises; NULL on failure, logged
```

The config carries only what init reads and what the first target build is built at; msaa, ss and
render scale remain runtime setters too (they rebuild; a second meaning, not a duplicate).
`engine_set_taa` becomes store-and-apply, so the silent no-op at `engine.c:1630-1633` and the render
app's straddle (`render.c:2819-2841`) vanish. Deleted: `init_engine`, `engine_set_headless/profiler`.
`GameConfig` becomes `{ EngineConfig engine; fixed_timestep; max_frame_time; cook_dir; no_cook; }`;
its forwarders go and a game app writes runtime settings on `game->engine` after `create_game`.
Ten app startups change, each to the same few lines. Fallback if cut: keep `engine_init`, make
`engine_set_taa` store-and-apply anyway, and log from the pre-init setters when called late.

## As built

Six commits on `11.106-the-public-surface`: the spec, its revision to the hybrid shape (the first
draft had every field behind a setter and was withdrawn before a line moved), then one commit per
code phase. Every phase's gate ran as written; nothing was re-baked.

**What matches the plan.** The allowlist (43 `src/*.h`, all of `game/` and `procedural/`, `log.h`,
`cwalk.h`) and the two forwarder trees; the include hygiene table row for row; the rename table
(142 entries, one script, 62 files, the nine `render_current_scene` sites by hand); the return
conventions; the five `CETRA_PROGRAM_*` constants; `EngineConfig`, `CameraDesc`, `LightDesc` and
`GameConfig` as drawn; the seventeen builder setters deleted and the five reacting ones kept.

**What deviated, and why.**

- `EngineConfig.vsync` became `no_vsync`, because zero must mean the default and the default is
  vsync on. `engine_default_config()` was not built: with zero the default there is nothing for it
  to return.
- `LightDesc.type` zero is `LIGHT_DIRECTIONAL`, not `LIGHT_UNKNOWN`. A desc's zero is a default and
  "unknown" is not one. `LIGHT_UNKNOWN` stays in the enum for the importer.
- `ies_profile` is not a desc field. Index 0 is a valid profile, so zero cannot mean "none"; the
  plain field stays, initialised to -1 as before.
- `LightDesc.intensity` zero means zero, not 1. Two fixtures (`flare_fixture`, `oit_cards_fixture`)
  author `intensity: 0.0` as the idiom for declining the default rig, so zero is a value there;
  the first draft substituted 1 and the scene loader had to patch it back after creation, which
  the review read as the rule leaking into a caller. `create_light(NULL)` is now a light that
  emits nothing; the importer and sprites say `1` explicitly. Colour keeps white for zero (black
  is expressed by intensity), so an authored `color: [0,0,0]` in a `.cscn` reads as white where
  master read black; nothing in the corpus authors it.
- `LightDesc.size` is a `vec2`, mirroring the object field, because two in-tree callers set it
  on a DIRECTIONAL, where it is the PCSS emitter size and not a panel extent.
- `CameraDesc` lost `max_distance`, `zoom_speed` and `orbit_speed`: no app fills them, and they
  are tuning a GUI edits live, which is the spec's own reason for keeping Material out of a desc.
- `camera_set_position` / `camera_set_look_at` store; the orbit re-derive is 11.107's, and the
  header says so rather than claiming it early. `create_camera` DOES derive the orbit parameters
  from the pose (11.107's "distance = 2000 becomes the pose's distance", pulled forward), which
  nothing measured can see.
- The internal include tree is an INTERFACE target, `cetra_internal`, that `add_cetra_app` links,
  on the precedent of `cetra_warnings`; the first draft was a custom target property.
- `game_default_config` was not kept: under zero-means-default it returned a title every caller
  overwrote, and the loop defaults it restated live in `create_game`.
- `EngineConfig` is read inside init where each field is consumed, not copied onto the Engine
  first: the `taa_requested` store-and-apply the plan asked for was the fallback for keeping
  `engine_init` public, and with init absorbed there is no window for a request to arrive before
  the post chain exists. `engine_set_taa` is the post-chain write again. The run's settings (the
  frame limit, the screenshot path and cadence) stay outside the config, on the engine after
  creation: they describe the run, not the creation, and 11.108 makes two of them fields.
- `apps/render` includes `cetra/internal/render.h` for three debug entry points
  (`set_render_animation_state`, `render_skeleton_bones`, `render_cull_view`) and says so; the plan
  listed six other internals for it and those are as planned.
- `free_engine` takes an engine whose creation failed part-way, since `create_engine` owns the
  failure now: one teardown order, with the GL deletes guarded on the window and the ImGui
  shutdown on its context (the backends assert without one). The first draft was a second,
  shorter order behind an early return, and it disagreed with the first on the day it was
  written -- it freed the window title, which the full path had leaked since before this spec.
- `scene_capture_faces` takes the scene it renders, like its begin/end partners; it was the last
  render site through the engine's current-scene lookup after `engine_render_scene` stopped
  being one.

**Caught live.**

- `cscene_apply.c` compiled through `scene.h`'s closure for `ibl.h`, `probe.h` and `probe_set.h`;

- Dropping the assimp include from `import.h` exposed `scene.h` including GLFW before GLEW, which

# Spec 11.107 — Nothing fails silently

## Scope

The trapdoors: upload, normals, draw-mode/program compatibility, material without program, the
lightless scene, the clear colour, the assimp null deref; and the automatic parts: camera matrices,
spherical sync, material registration, a scene that renders itself. Non-goals: settings sections,
policy setters, the 2D preset (11.108).

## Design

- **Camera matrices derived by the engine.** `engine_run` computes view and projection immediately
  after `pre_render` returns (`engine.c:2662`), before the transform walk and the shadow pass
  (`:2688`, which reads `engine->view_matrix` at `shadow.c:1580`). The bodies are the two functions
  every app calls at the end of its pre-render today (`engine.c:1225-1251`, verbatim, guard
  included), so the result is bit-identical. Deleted: the public pair, the 12 app sites,
  `app.c:232-233`, `config_snapshot.c:1684-1685` and its deferral, `engine.c:1078`. Contract in the
  header: the frame renders the camera as it stands when `pre_render` returns.
- **Spherical sync.** `camera_set_position` and `camera_set_look_at` end with
  `camera_sync_spherical_from_position`'s body (`camera.c:250-264`, made static). Nothing in the
  render path reads distance/theta/phi, so no golden moves; the three hand syncs go
  (`render.c:1905-1911`, `tree.c:1225`, `player.c:128`); `create_camera`'s `distance = 2000` becomes
  the pose's distance.
- **Upload at attach.** `Mesh.gpu_vertex_count` (0 = nothing on the GPU) replaces the false
  `vao == 0` test. `node_add_mesh` uploads when `vertex_count > 0 && gpu_vertex_count == 0`; the GL
  context is live by construction (`create_mesh` needs it) and the epoch bump it already does
  (`scene.c:915`) covers the list. The importer calls `mesh_upload` after `mesh_build_lod_chain`
  (`import.c:1758`). `node_upload_meshes` is deleted (12 sites). **`mesh_upload` computes the AABB**
  (nothing else writes `Mesh.aabb`; same function, same data, 0 px) so the 15 redundant app calls go;
  `mesh_compute_aabb` stays public for an in-place edit. **Normals:** `mesh_upload` on a triangle
  mesh with `normals == NULL` computes area-weighted vertex normals and logs once; in-tree no
  triangle mesh lacks them, so 0 px. `import.c:1884` adds `aiProcess_GenSmoothNormals` and `:899`
  gets its NULL guard (a model without normals is a null deref today).
- **The draw list refuses loudly, once per mesh.** `Mesh.draw_refusal_logged`; the refuse branch at
  `draw_list.c:223-229` is the one place, naming the node and the reason: never uploaded, no
  material, no program, or geometry the program cannot take.
- **Draw mode vs program, declared by nothing.** `setup_program_uniforms` (`program.c:494-519`,
  where `instanced` and `sampler_count` are already resolved from the linked program) queries
  `GL_GEOMETRY_INPUT_TYPE` when a geometry stage is attached into `ShaderProgram.geometry_input`
  (0 = any); `program_accepts_draw_mode` maps LINES/TRIANGLES/POINTS input to the matching
  `MeshDrawMode` family; the draw list refuses a mismatch with the once-per-mesh log.
- **Materials attached mid-run register themselves**: `Material.registered`; `append_node`
  (`draw_list.c:221`) calls `scene_add_material` for an unregistered one — one branch per item, the
  scene in hand. `scene_mark_materials_dirty` leaves the public header.
- **Lightless scene**: first `engine_render_scene` of a scene with no lights, no IBL and zero
  ambient warns once. **Clear colour**: `Engine.clear_color`, default the measured 0.1 grey
  (`gates.py:16752`), read at `engine.c:2741`; sprites drops its backdrop quad and its capture is
  measured. **`engine_run` with `render == NULL`** renders the scene itself. **`create_scene`
  creates a root node**; `scene_set_root` frees the previous root when replacing.

## Phases (branch `11.107-nothing-fails-silently`)

2. Camera derive + sync. Gate: goldens; `gates --only transform,shadow-lag,ortho,taa-ortho,config`;
   captures; hand launch with the camera dragged.
3. Upload / AABB / normals / assimp. Gate: goldens;
   `gates --only import,lod,cluster,quadtree,forest,region,draw-list,submission,cull,occlusion`;

4. Compatibility + material logging + registration. Gate: goldens;

**Risks:** a camera moved from `render` (no app does) is a frame late, as the header says; the

reporting no geometry input type makes the check inert, not wrong; the sprites capture may move

# Spec 11.108 — Settings and setters

## The policy, in words

Three roles, and every public struct's header says which its fields play:

1. **Description** — what an object is created from: `EngineConfig`, `CameraDesc`, `LightDesc`
   (11.106). Designated initialisers, defaults by omission, one place per field to document it.
2. **Functions where the engine reacts** — a write that must be validated, ordered, propagated or
   followed by a re-derive is a function, because that is where the reaction lives. The fourteen
   `CFG_ROW_FN` rows in the config table (`config_snapshot.c:264-406`) are the empirical list;
   every one has or gets a function, and the hooks call it.
3. **Settings** — everything else: the tuning blocks (PostFX, Exposure, ShadowSystem, Water, Wind)
   and the content (a material's parameters, a mesh's arrays). Documented public fields under a
   banner, "SETTINGS: plain stores, write them directly at any time"; no setter exists and none is
   added, because the GUI and the config table (`config_snapshot.c:417-810`, by offset) already
   reach them that way and `wind.h:38` already says so.

Above the settings banner sit the engine-owned fields (derived, GL names, resources): read freely,
never write, each with its function if an app may change it. There is no fourth role: no
plain-store setter survives on any struct, which is what makes the rule legible from a header.

Consequences:

- **Engine.** Above: sizes, matrices, GL names, `postfx`, `camera`, msaa/ss/render scale/taa
  (rebuild), `show_wireframe` (GL state), `screenshot_path` (strdup), callbacks, clock, user data.
  Settings: the feature toggles, the draw levers, `layers_vt_*`, `show_gui/fps/camera_hud/bones/
  lights`, `show_xyz`, `camera_mode`, `screenshot_every`, `exit_after_frames`, `clear_color`,
  `current_render_mode`. Plain-store setters deleted: `engine_set_show_gui/fps/camera_mode/
  screenshot_every/exit_after_frames` (scripted to direct writes).
- **`show_xyz` and the xyz program stop propagating**: the gizmo submit reads
  `engine->show_xyz && node->show_xyz`, and `push_gizmo` (`draw_list.c:237`) falls back to
  `scene->xyz_shader_program` when the node's is NULL, so a node added later is not missed.
- **PostFX** (304 fields): settings throughout except `ssr_full_res`, `taa_enabled`, the SSS
  profile table, the LUT, the engine-owned targets; `fog_ambient` gets `postfx_set_fog_ambient`
  because the sky stamps over it (`config_snapshot.c:304-312`).
- **Scene.** Above: root, the arrays, `draw_list`, world origin, wind. Settings: `ambient_radiance`,
  `root_transform`, skybox and catcher fields. The sun/cloud fields name
  `scene_environment_changed` as the call that follows them.
- **Camera.** Created from `CameraDesc`. Functions: `camera_set_position/look_at` (orbit sync),
  the orbit/pan/zoom moves. Settings: `up`, `fov_radians`, `near/far_clip`, `ortho_height`,
  `is_orthographic`, `max_distance`, `zoom_speed`, `orbit_speed`; `aspect_ratio` engine-derived;
  distance/theta/phi marked "derived from the pose; written by the orbit controller".
- **Light.** Created from `LightDesc`. Functions: `light_set_direction/up`,
  `light_set_intensity_units`. Settings: colour, range, cutoffs, size, `cast_shadows`.
- **Material.** No desc (a tuning block). Functions: the texture setters (retain/release),
  `material_set_program`. Settings: every `MATERIAL_PARAMS` row, stated as the section, plus
  alpha mode/cutoff/double-sided. No `material_set_albedo`: the table forbids a second
  name-to-field binding.
- **Mesh.** Above: `gpu_vertex_count`, GL names, `aabb`, measurements, `refs`, LOD arrays.
  Settings: `material`, `draw_mode` (`mesh_set_draw_mode` deleted), `line_width`, the vertex
  arrays ("then `mesh_upload`").
- **SceneNode.** Settings: `original_transform`, `show_xyz`; helpers `node_set_position(node, vec3)`
  and `node_set_transform(node, mat4)` for the six apps writing `[3][x]` three lines at a time.
- **ShadowSystem, Exposure, Water, Wind**: settings throughout except the engine-owned targets;
  one banner each; the water fields that arm a bake name their existing function.
- **Particles**: `billboard_renderer_set_lighting(r, ambient_floor, soft_fade_dist)` replaces the two
  `#define`s; `billboard_renderer_set_lit(r, bool)` gives an unlit path whose output is the authored
  colour, which removes sprites' white key light if the capture proves it. The header documents:
  size is a half-width, the life fade, the key-light tint and its 0.6 floor.
- **The 2D preset** also sets `show_gui = false`, `show_fps = false`, and gives the scene a root if
  none. It does not touch the tonemap (shapes want LINEAR's encode, sprites wants PASSTHROUGH) or
  `clear_color`.
- **A canvas controller in `app.h`**, the 2D twin of `MouseDragController`, replacing ~30 duplicated
  lines each in shapes and pcb: `create/free_canvas_controller`, `canvas_world_under_cursor`,
  `canvas_on_button/cursor/scroll`, `canvas_set_zoom_range`. pcb's corner logic stays in pcb.
  `InputState` (`input.h:10-24`) gets a one-line contract per field.
- **Docs**: 15–30 line overviews at the top of engine.h, scene.h, mesh.h, material.h, camera.h,
  light.h, geometry.h, app.h, particle_system.h, game.h; AGENTS.md "Common Operations" rewritten to
  the minimal path; "Key Data Structures" gains the banner rule; README's consumer section shows
  the same path:

```c
EngineConfig cfg = { .title = "hello", .width = 1280, .height = 720 };
Engine* engine = create_engine(&cfg);
Scene* scene = create_scene();
engine_add_scene(engine, scene);

CameraDesc cam = { .position = {0, 2, 5}, .fov = glm_rad(45.0f) };
engine_set_camera(engine, create_camera(&cam));

LightDesc key = { .type = LIGHT_DIRECTIONAL, .direction = {-0.3f, -1, -0.5f}, .intensity = 3 };
scene_add_light(scene, create_light(&key));

Material* mat = create_material();
material_set_program(mat, engine_get_program(engine, CETRA_PROGRAM_PBR));
mat->albedo[0] = 1.0f;

Mesh* mesh = create_mesh();
mesh_generate_box(mesh, &(Box){ .size = {1, 1, 1} });
mesh->material = mat;

SceneNode* node = create_node();
node_add_mesh(node, mesh);
node_add_child(scene->root_node, node);

engine_run(engine, NULL, NULL, NULL);
free_engine(engine);
```

No init call, no upload, no AABB, no matrix pair, no render callback, no half-built object; and an
unlit scene says so.
