# The API cleanup: specs 11.106, 11.107, 11.108

## Context

Cetra's API grew with its own apps. Three exploration passes over the nine in-tree apps and pcb
measured what that produced: 1,089 declared functions of which apps call 388 (204 from one file);
two naming conventions in equal use in `engine.h` (20 `set_engine_*`, 21 `engine_*`) and a dozen
pairs that say one thing two ways; 296 distinct struct fields apps write directly, some of which
carry invariants (`camera->distance` desyncs from `set_camera_position`, `headless_jitter` has an
ordering rule and no setter); 91 headers all exported, so a consumer sees the draw list and the
light cluster beside the engine, and `#include "cetra/engine.h"` pulls assimp and pthread into
every TU; and a set of silent failures a new app meets in its first hour: a mesh that was never
uploaded passes the draw list's filter (it tests `vao == 0`, but `create_mesh` already generates
the VAO) and dies as a `GL_INVALID_OPERATION` nobody checks; a triangle mesh on the `shape`
program does the same; a material with no program is dropped without a word; a program name typo
returns NULL without a log; a scene with no light is black; the clear colour is a literal.

Decisions made: **public functions are renamed freely** (every consumer is the user's, updated in
the same commit); **structs stay visible**, with setters where a write needs validation, ordering
or propagation and explicit settings sections for the rest; the GUI keeps its direct writes; **no
new instruments or docs files** — verification is the existing suites plus every app building,
and documentation goes into headers, README's consumer section and AGENTS.md.

Three specs, in order, because B and C name functions and every name must be final first. Each is
a branch off master, spec committed alone, one commit per phase, scoped gates between phases,
goldens and the full suite at the end, reviews in background agents before applying anything.
After each merge, pcb gets one commit in its own repository: `src/main.c` updated and the
submodule bumped.

**Verification vocabulary** used throughout: *goldens* = `python3 scripts/goldens.py`, 30 at 0 px;
*captures* = `-x -f 2 -S` frames from sprites, network, spores, forest, tree and pcb, compared
byte-for-byte against the same capture at the previous commit (the 2D apps have no golden, so this
is their proof); *hand launch* = shapes, gametest and splash run to a window and recorded.

# Spec 11.106 — The public surface

## Scope

The header allowlist and a real include boundary; one naming convention with the rename done
once, everywhere; return conventions; program-name constants; the create/init collapse. Non-goals:
any behaviour change, any setter added or removed for a policy reason (11.108), any new logging
except the program-miss line (its silence is a return-convention defect).

## 1. The boundary

`cetra/CMakeLists.txt:26-35` globs every header into `include/cetra/`. It becomes an **allowlist**:
`set(CETRA_PUBLIC_HEADERS ...)`; a listed header forwards to `include/cetra/<name>.h`, every other
header under `src/`, `src/game/`, `src/procedural/`, `src/ext/` forwards to
`include-internal/cetra/internal/<rel>.h`. The internal tree is PRIVATE on `cetra` and added to
in-tree apps by `add_cetra_app` (`apps/CMakeLists.txt`); a consumer through `add_subdirectory`
never sees it. `src`, `src/ext`, `src/game` (`cetra/CMakeLists.txt:80-84`) go **PRIVATE** — apps
use only `cetra/...` includes (verified), and the one thing that breaks, `text.h:7 <uthash.h>`,
becomes `"ext/uthash.h"`. cimgui and JoltC dirs stay PUBLIC (tree's GUI uses `cimgui.h`).

**Public `src/*.h` (43):** animation, app, camera, common, compat, config_snapshot, cook, cscene,
decal, engine, exposure, geometry, gi_volume, ibl, ies, import, input, light, material, mesh,
mesh_builder, noise, particle_emitter, particle_module, particle_renderer, particle_sim,
particle_system, postfx, probe, probe_set, program, scene, shader, shadow, sky, springbone, text,
texture, transform, uniform, util, water, wind; all of `game/` and `procedural/`; `ext/log.h`,
`ext/cwalk.h`.

**Internal:** async_loader, cluster, draw_list, emissive_light, engine_internal (new), gui,
intersect, layers_vt, layers_vt_pages, light_cluster, lod, ltc, ltc_lut, lut,
material_texture_array, moon_map, moon_surface, occlusion, particle_pool, physics_cook,
probe_atlas, profiler, render, rigging, roads, shore_chain, shore_runup, texture_compress, thread,
ubo, and `ext/` except log and cwalk.

The rule, stated in the CMake comment and AGENTS.md: **the allowlist governs what an app may NAME
in an include, not what a public header's closure reaches.** `material.h` includes `roads.h`,
`texture.h` includes `thread.h`; that stays. An in-tree app may include `cetra/internal/`; an app
that must is a debug harness and says so in its header comment (render, forest); pcb includes none.

Apps that include internals today and what they become: render (`occlusion.h`, `light_cluster.h`,
`emissive_light.h`, `profiler.h`, `async_loader.h`, `render.h`, `shore_chain.h` → `cetra/internal/`),
forest (`cluster.h`, `lod.h`, `physics_cook.h`, `profiler.h`), sprites (`particle_pool.h`);
shapes/tree/render include `shader.h` vestigially (no `create_shader` call) — delete. Eight apps
include `render.h` for `render_current_scene` alone; it moves to `engine.h` as
`engine_render_scene(engine, scene)` (it re-looks-up the scene today, `render.c:1253`, while
`engine_run` hands the callback the scene it propagated — the pair can disagree) and they drop
`render.h`.

**`engine_internal.h`** takes the pass brackets no app calls: `engine_present_frame`,
`engine_set_scene_draw_buffers`, `engine_resolve_opaque_color`, `engine_resolve_scene_depth`,
`engine_begin/end_oit_pass`, `engine_begin/end_moment_pass`, `engine_upload_displacement_uniforms`,
`engine_render_size`, `engine_post_size`, `engine_pbr_variant`. Embedder hooks stay public with a
comment: `engine_set/get_user_data`, `engine_set_render_clock`, `engine_set_render_time`,
`engine_set_scene_by_index/name`, `engine_gui_wants_mouse/keyboard`.

## 3. The naming rule

**Subject first.** The first word is the type of the first parameter, lowercased (`engine_`,
`scene_`, `node_`, `mesh_`, `material_`, `camera_`, `light_`, `game_`, `mouse_drag_`,
`particle_emitter_`), then the verb, then the object. `create_X` / `free_X` are the one exception
(AGENTS.md's factory rule stays). Getters are `x_get_y`; lookups that may miss are `x_find_y` and
return NULL silently; an `x_get_y` that returns NULL logs. This is the convention the newer half of
the tree already uses (`engine_run`, `scene_propagate_transforms`, `mesh_ref`, `material_param_set`,
`particle_emitter_add_module`, `game_set_update`, `water_update`, `sky_bake`, `cook_init`).

## 4. Return conventions

- **void** for a mutator whose only failures are a NULL argument or OOM: it logs and returns. All
  ten unbounded `add_*` (checked by zero app sites) become void.
- **bool** for a request that can be refused for a reason the caller can act on: the three bounded
  arrays, `node_remove_child`, the pass brackets, `engine_init` if it survives.
- **NULL on failure** for factories and lookups. `engine_get_program` logs
  `no program '%s' (%zu registered)`; `engine_find_program` is silent for the optional probes
  (`shadow.c:1114,1276,1278`) and the variant cache check (`engine.c:1591`). No `GLboolean` on the
  public surface.

## 5. Program names

Lookup by name stays (the variant cache formats `pbr-<mask>` at runtime, `program.c:587-593`; an
app's own program needs a name the engine never enumerated). `program.h` gains
`CETRA_PROGRAM_PBR "pbr"`, `_PBR_SKINNED`, `_SHAPE`, `_XYZ`, `_PARTICLE`; `pbr_variant_name` reads
the constant so the two cannot drift.

## 6. create/init: `EngineConfig` (recommended, separable as its own phase)

`GameConfig` (`game.h:33-71`) is the evidence: ten of its fifteen fields exist because `create_game`
owns the `init_engine` call and each carries an ordering comment; `game.c:67` writes
`headless_jitter` after init, which reads it at `engine.c:977` — a live ordering bug the struct
removes by construction.

```c
typedef struct EngineConfig {
    const char* title; int width, height;
    bool headless;        // hidden window, vsync off
    bool headless_jitter; // keep the TAA jitter under headless
    bool profiler;
    bool vsync;           // default true; ignored headless
    int msaa_samples;     // 0 = 4; the first build's count
    int ss_scale;         // 0 = 1
    float render_scale;   // 0 = 1
} EngineConfig;
EngineConfig engine_default_config(void);
Engine* create_engine(const EngineConfig* cfg);   // creates AND initialises; NULL on failure, logged
```

The config carries only what init reads and what the first target build is built at; msaa, ss and
render scale remain runtime setters too (they rebuild; a second meaning, not a duplicate).
`engine_set_taa` becomes store-and-apply, so the silent no-op at `engine.c:1630-1633` and the render
app's straddle (`render.c:2819-2841`) vanish. Deleted: `init_engine`, `engine_set_headless/profiler`.
`GameConfig` becomes `{ EngineConfig engine; fixed_timestep; max_frame_time; cook_dir; no_cook; }`;
its forwarders go and a game app writes runtime settings on `game->engine` after `create_game`.
Ten app startups change, each to the same few lines. Fallback if cut: keep `engine_init`, make
`engine_set_taa` store-and-apply anyway, and log from the pre-init setters when called late.

# Spec 11.107 — Nothing fails silently

## Scope

The trapdoors: upload, normals, draw-mode/program compatibility, material without program, the
lightless scene, the clear colour, the assimp null deref; and the automatic parts: camera matrices,
spherical sync, material registration, a scene that renders itself. Non-goals: settings sections,
policy setters, the 2D preset (11.108).

## Design

- **Camera matrices derived by the engine.** `engine_run` computes view and projection immediately
  after `pre_render` returns (`engine.c:2662`), before the transform walk and the shadow pass
  (`:2688`, which reads `engine->view_matrix` at `shadow.c:1580`). The bodies are the two functions
  every app calls at the end of its pre-render today (`engine.c:1225-1251`, verbatim, guard
  included), so the result is bit-identical. Deleted: the public pair, the 12 app sites,
  `app.c:232-233`, `config_snapshot.c:1684-1685` and its deferral, `engine.c:1078`. Contract in the
  header: the frame renders the camera as it stands when `pre_render` returns.
- **Spherical sync.** `camera_set_position` and `camera_set_look_at` end with
  `camera_sync_spherical_from_position`'s body (`camera.c:250-264`, made static). Nothing in the
  render path reads distance/theta/phi, so no golden moves; the three hand syncs go
  (`render.c:1905-1911`, `tree.c:1225`, `player.c:128`); `create_camera`'s `distance = 2000` becomes
  the pose's distance.
- **Upload at attach.** `Mesh.gpu_vertex_count` (0 = nothing on the GPU) replaces the false
  `vao == 0` test. `node_add_mesh` uploads when `vertex_count > 0 && gpu_vertex_count == 0`; the GL
  context is live by construction (`create_mesh` needs it) and the epoch bump it already does
  (`scene.c:915`) covers the list. The importer calls `mesh_upload` after `mesh_build_lod_chain`
  (`import.c:1758`). `node_upload_meshes` is deleted (12 sites). **`mesh_upload` computes the AABB**
  (nothing else writes `Mesh.aabb`; same function, same data, 0 px) so the 15 redundant app calls go;
  `mesh_compute_aabb` stays public for an in-place edit. **Normals:** `mesh_upload` on a triangle
  mesh with `normals == NULL` computes area-weighted vertex normals and logs once; in-tree no
  triangle mesh lacks them, so 0 px. `import.c:1884` adds `aiProcess_GenSmoothNormals` and `:899`
  gets its NULL guard (a model without normals is a null deref today).
- **The draw list refuses loudly, once per mesh.** `Mesh.draw_refusal_logged`; the refuse branch at
  `draw_list.c:223-229` is the one place, naming the node and the reason: never uploaded, no
  material, no program, or geometry the program cannot take.
- **Draw mode vs program, declared by nothing.** `setup_program_uniforms` (`program.c:494-519`,
  where `instanced` and `sampler_count` are already resolved from the linked program) queries
  `GL_GEOMETRY_INPUT_TYPE` when a geometry stage is attached into `ShaderProgram.geometry_input`
  (0 = any); `program_accepts_draw_mode` maps LINES/TRIANGLES/POINTS input to the matching
  `MeshDrawMode` family; the draw list refuses a mismatch with the once-per-mesh log.
- **Materials attached mid-run register themselves**: `Material.registered`; `append_node`
  (`draw_list.c:221`) calls `scene_add_material` for an unregistered one — one branch per item, the
  scene in hand. `scene_mark_materials_dirty` leaves the public header.
- **Lightless scene**: first `engine_render_scene` of a scene with no lights, no IBL and zero
  ambient warns once. **Clear colour**: `Engine.clear_color`, default the measured 0.1 grey
  (`gates.py:16752`), read at `engine.c:2741`; sprites drops its backdrop quad and its capture is
  measured. **`engine_run` with `render == NULL`** renders the scene itself. **`create_scene`
  creates a root node**; `scene_set_root` frees the previous root when replacing.

# Spec 11.108 — Settings and setters

## The policy, in words

Every public struct's header has two banners. **Above the line** are fields that own a resource,
are derived by the engine, or propagate: each has a setter or is marked engine-owned (read freely,
never write). **Below the line, "SETTINGS: plain stores, write them directly at any time"**, are
the tunables; no setter exists for them and none is added, because the GUI and the config table
(`config_snapshot.c:417-810`, by offset) already reach them that way and `wind.h:38` already says
so. The line is drawn by one test: **does the config table need an apply hook for it, or does an
app follow the write with a call by hand?** The fourteen `CFG_ROW_FN` rows
(`config_snapshot.c:264-406`) are the empirical list of fields with an invariant; every one has or
gets a setter, and the hooks then call the setters. The builder idiom keeps its setters:
`create_X` then `x_set_*` for Light, Camera and Material is how an object is declared, and no new
plain-store setter is added to them.

Consequences:

- **Engine.** Above: sizes, matrices, GL names, `postfx`, `camera`, msaa/ss/render scale/taa
  (rebuild), `show_wireframe` (GL state), `screenshot_path` (strdup), callbacks, clock, user data.
  Settings: the feature toggles, the draw levers, `layers_vt_*`, `show_gui/fps/camera_hud/bones/
  lights`, `show_xyz`, `camera_mode`, `screenshot_every`, `exit_after_frames`, `clear_color`,
  `current_render_mode`. Plain-store setters deleted: `engine_set_show_gui/fps/camera_mode/
  screenshot_every/exit_after_frames` (scripted to direct writes).
- **`show_xyz` and the xyz program stop propagating**: the gizmo submit reads
  `engine->show_xyz && node->show_xyz`, and `push_gizmo` (`draw_list.c:237`) falls back to
  `scene->xyz_shader_program` when the node's is NULL, so a node added later is not missed.
- **PostFX** (304 fields): settings throughout except `ssr_full_res`, `taa_enabled`, the SSS
  profile table, the LUT, the engine-owned targets; `fog_ambient` gets `postfx_set_fog_ambient`
  because the sky stamps over it (`config_snapshot.c:304-312`).
- **Scene.** Above: root, the arrays, `draw_list`, world origin, wind. Settings: `ambient_radiance`,
  `root_transform`, skybox and catcher fields. The sun/cloud fields name
