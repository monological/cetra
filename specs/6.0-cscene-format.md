# 6.0 Cetra scene format (.cscn) — as built

The scene file owns the look and references model assets — the engine-native
data glTF cannot carry. Godot `.tscn` → `.glb`; Unreal `.umap` → meshes; glTF
is an asset format, not a level format. Shipped on branch `cscene-format`
(milestone 1: format + loader + render-app integration + Blender exporter;
material baking is milestone 2, see Deferred).

```
./out/bin/render assets/abandoned_window.cscn      # scene file as the input
./out/bin/render -m assets/abandoned_window.glb    # bare model auto-probes for a sibling .cscn
```

Dispatch is by extension (`.cscn`, case-insensitive). CLI flags always
override scene-file values (file = authored truth, flags = developer
overrides). `--no-scene-file` loads the referenced model but skips every look
field.

## Format v1 (JSON)

```json
{
  "version": 1,
  "models": [ { "path": "abandoned_window.glb" } ],
  "environment": {
    "mode": "hdr",                       // hdr | sky
    "hdr": "abandoned_window_env.hdr",
    "intensity": 0.15,                   // IBL/world ambient strength
    "probe_scene": true                  // capture scene into the local probe (interiors)
  },
  "lights": [                            // v1: point lights only (area-fill conversions)
    { "name": "BounceFill", "type": "point", "position": [2.4, 1.8, 0.35],
      "color": [1.0, 0.82, 0.42], "intensity": 5.94 }
  ],
  "light_overrides": [                   // matched against imported light names
    { "name": "SunKey", "size_from_angle": 0.11 }   // radians; optional "intensity"
  ],
  "post": {
    "tonemap": "agx",                    // agx | aces | neutral (validated at parse)
    "exposure": 1.3379,                  // LINEAR multiplier; pins auto-exposure off
    "bloom": { "enabled": true, "strength": 0.487, "threshold": 1.0 },
    "fog":   { "enabled": true, "density": 0.008, "anisotropy": 0.25 }
  },
  "materials": {                         // keyed by authored material name
    "IvyLeafReal": { "sss": { "color": [0.455, 1.0, 0.227], "radius": 0.06 } }
  },
  "camera": { "eye": [-0.02, 1.29, 2.36], "target": [2.02, 1.54, 0.37], "fov": 46.4 }
}
```

Conventions:
- All vectors are glTF Y-up world space. Relative paths resolve against the
  scene file's directory at load time.
- `models[]` is an array for forward compatibility; v1 reads the first entry
  and warns on extras.
- Light `type` other than `"point"` is warned and skipped (spot/directional
  land when the format carries their defining parameters — cutoffs,
  direction). Unknown tonemap values warn at parse.
- `version` other than 1 warns; parsing continues.
- `camera.fov` is vertical, in degrees.
- Material override names match the authored material name (Blender material
  → glTF → assimp `AI_MATKEY_NAME` → `Material.name`). Light override names
  match the Blender object name carried the same way.
- Scene files describe authored worlds: the viewer forces `--no-recenter` so
  camera/light positions stay valid.

## Architecture

| Layer | File | Role |
|---|---|---|
| Parser (engine) | `cetra/src/cscene.c/h` | `.cscn` → plain `CetraSceneDesc`. Vocabulary validation, per-field presence flags, warn-and-continue on malformed entries, paths resolved at load. Caps: 16 lights, 16 overrides, 8 materials. Zero application logic. |
| App policy | `apps/render/src/cscene_apply.c/h` | `cscene_setup` merges the desc into `RenderArgs` (CLI > scene file > default, via the args sentinels) so the existing CLI application blocks apply everything; `add_cscene_lights` runs before the auto-key-light decision so authored rigs suppress it; `apply_cscene_light_overrides` runs after global light sizing — penumbra = `tan(angle) * scene_radius`. |
| Args | `apps/render/src/render_args.h` | `RenderArgs` struct (moved out of render.c). Added for scene files: `bloom_enable/strength/threshold`, `fog_anisotropy`, `ibl_intensity` + CLI flags `--bloom-strength`, `--bloom-threshold`, `--fog-anisotropy`, `--ibl-intensity`, `--no-scene-file`. |
| SSS tagging | `apps/render` `configure_sss_materials` | Scene-file entries tag materials by name via the scene's material registry (`add_material_to_scene`); the two-sphere fixture table remains the no-scene-file fallback. |
| Exporter | `tools/cetra_export.py` | Blender → `name.glb` + `name.cscn` (+ HDR copy). See below. |

Supporting engine additions: `Material.name` (populated from `AI_MATKEY_NAME`,
enables name-keyed overrides), `read_entire_file` in util (canonical
whole-file reader; shader.c/text.c converted to it), vendored cJSON in
`src/ext`.

## Exporter (`tools/cetra_export.py`)

Run in Blender's Script editor (set `OUT_PATH`) or headless:
`blender -b scene.blend -P tools/cetra_export.py -- --out assets/name.glb`

Unit/concept conversions (the exporter is the unit-conversion layer):
- area lights → point entries (`intensity = watts * AREA_TO_POINT_K`)
- sun lamps → `light_overrides.size_from_angle` (Blender `light.angle`, radians)
- Principled Volume material → `post.fog` (density × `FOG_K`, anisotropy);
  volume objects excluded from the GLB
- world HDR → copied as `<base>_env.<ext>` (deterministic name, skipped when
  up to date); Background strength → `environment.intensity`
- view transform AgX/Filmic/Standard → tonemap agx/aces/neutral;
  view exposure (stops) → `2^x` linear
- compositor Glare(Bloom) → bloom strength (× `BLOOM_STRENGTH_K`) / threshold
- Principled `Subsurface Weight > 0` → `materials{}.sss`
- active camera → eye/target/vfov; the target is a real datum (DoF focus
  distance when authored, else scene-bounds center projected on the view ray)
- coordinates: Blender Z-up → glTF Y-up, once, here

Exclusions: custom property `cetra_exclude`, wire-display helpers, volume
materials, collection `_cetra_exclude`. Prints a manifest of everything
written, converted, excluded, and flattened.

**Known stopgap:** `FLATTEN_OVERRIDES` — procedural node graphs cannot cross
glTF, so listed materials export as flat stand-ins (originals restored after
export) and every run prints them as pending. Material baking (milestone 2)
deletes this table.
