# Spec 12.5 — What the IK review left

## Context

Spec 12.4 (two-bone IK / foot planting) merged to master at `d7bd1acf`. Its review pass
found nine quality items that were judged worth doing and deliberately **not** done, recorded
in the message of commit `779531c8` rather than dropped silently:

> Not applied, and recorded rather than quietly dropped. Memoising the probe runs would cut
> the group's wall time by about a quarter, but it touches every arm under an order-sensitive
> scan and this session has already cost three mis-anchored edits. ik-swing should tick through
> update_all_animators like every anim probe case [...] And six structural suggestions [...] all
> land outside this diff or change public API.

This spec closes them. Exploration since has **falsified two of the three reasons given there**,
and both corrections are load-bearing:

- The memoisation hazard does not exist. `gate-arm-docs` scans only `print(` sites
  (`gates.py:16222`), never probe calls, so caching is invisible to it. It is the cheapest of
  the eight, not the riskiest.
- The `ik-swing` reroute buys no coverage. `update_all_animators`
  (`animator_component.c:66`) is a thin fan-out over `animator_update`, and the IK solve rides
  inside that call either way (`animation.c:1050`). The probe still cannot call the app's
  `ik_update_targets` — it early-returns on three conditions a headless probe never satisfies.
  It is **dropped**; the real duplication it was standing in for (the bind-lift, in three places)
  is closed by `sole_offset` below.

**Naming.** `12.5`, not `12.4.1`. The tree has one sub-spec in 130-odd files (`9.5.1`, a flicker
bug fix) against a strong run of follow-ups that take the next whole number and are named for
what they close: `11.74-what-the-decal-review-left`, `11.86-what-the-texture-review-left`,
`11.61-post-11.60-cleanup`, `11.64-the-review-paydown`.

**Not in scope.** None of this closes the five debts `docs/verification.md:551` records against
the foot-planting path — those are "only a person watching can settle" items, and the verdict
line stays **Owed**. This spec is quality, not coverage.

## The eight changes

### Group A — `scripts/gates.py` only, no engine change

**A1. Memoise the probe runs — 15 spawns to 11.**
`run_ik_gate` spawns `gametest --ik-probe <case>` fifteen times for ten distinct cases:
`slope` four times (the `ik-plant` loop at `:22523`, `ik-slope` at `:22542`, and twice in
`ik-repeat` at `:22581`), `ground` and `step` twice each. `functools` is already imported
(`gates.py:23`) with a `@functools.cache` precedent at `:10846`.

**`ik-repeat` must bypass the memo.** Its entire assertion is that two separate process
launches print identical digits; served from cache it compares an object with itself and goes
permanently vacuous. Keep an uncached spawn path for it.

Three constraints on the edit, all verified against the checker's regexes:
- Keep exactly one `print(` per arm, arm name as **literal text** after `print(f"` + exactly
  two spaces, in documented order. `print(f"  {name} ...")` matches nothing and fails the group.
- Keep the verdict expression **single-quoted** inside the f-string (`{'PASS' if ok else 'FAIL'}`).
  Rewriting it with double quotes terminates `_ARM_PRINTED`'s `[^"]*PASS` and the arm silently
  stops being seen.
- Looping probe *execution* is fine (`:22522` already does it); looping *print sites* is not.

**A2. One `_gametest_probe`, and the timeout it unlocks.**
Five readers parse the same shape, one per group, differing only in a flag and a regex:
`_anim_probe_run` (`:14909`), `_ui_probe` (`:22226`), `_ik_probe_run` (`:22255`),
`_save_probe` (`:22620`), and `_audio_probe_run` (`:14762`). The file already proposes this fix,
names the signature, and gives the trigger (`gates.py:22242-22247`):

> Worth collapsing into a single `_gametest_probe(flag, rx, case, env)` the day a sixth arrives,
> or the day one of them needs a timeout and the other four silently do not get it.

- The **four** with identical grammar (anim, ui, ik, save) collapse to
  `_gametest_probe(flag, rx, case, env=None, extra=None)` with zero behaviour change.
  `_save_probe` becomes a two-line wrapper that builds its env from `workdir`; `_ui_probe`
  becomes a pass-through.
- **`_audio_probe_run` keeps its own parse.** Its grammar genuinely differs — a literal `rms`
  token, no key field, fixed arity of two, and `(\w+)` for the case class — and folding it in
  means re-indexing `run_audio_gate`'s five arm bodies for no gain. It shares the *subprocess*
  half instead, so it gets the timeout without its arms being touched.
- Add `timeout=` in the one shared place. No reader passes one today, so a hung `gametest`
  currently hangs the whole suite.

**A3. Two false comments, found while reading.**
- The `_SAVE_PROBE` comment block sits orphaned above `_IK_PROBE` (`:22242-22247`), describing a
  regex defined 370 lines later at `:22617`; the two comments run together.
- `_UI_PROBE`'s comment (`:22208-22209`) still claims *"the same shape the anim and audio probes
  print, so one reader serves all three."* Both halves are false — audio's grammar differs and
  three separate readers exist. This is the exact stale sentence the save comment says "used to"
  be there; 12.4 corrected one instance and left this one standing. A2 makes it true for the
  first time.

### Group B — engine, provably bit-identical

**B1. Delete `reach_limit`.** Three writes in the whole repo (`ik.c:27`, `gametest.c:1916`,
`:2062`), every one `1.0f`; two reads (`ik.c:251`, `:422`). `x * 1.0f` is exact in IEEE-754, so
inlining `(l1 + l2)` and `(norm(ab) + norm(bc))` is bit-identical everywhere. Its own header
comment says "Leave it at 1" — a knob documented as untouchable is not a knob.

**B2. Delete `has_applied`, and fix the bug under it.** One read (`ik.c:380`), one true-write
(`:384`). `ik_add_foot` does not set `needs_reset` and `ik_solve` clears it (`:455`), so a foot
registered *after* a solve has `applied_target == {0,0,0}` and eases in **from the model origin**
instead of snapping. `springbone.c:157` already solves this exact problem the right way:

```c
    // New joints must snap to their targets before simulating
    system->needs_reset = true;
```

Adopt it at the end of `ik_add_foot`; the per-foot latch then has no reason to exist.
`applied_weight` cannot serve as the sentinel — 0 is a legitimate value for a released foot.

### Group C — engine, shared helpers

**C1. One subtree mark, in `animation.h`.** Three copies exist: `ik.c:152` (`uint8_t`, root by
index), `animator.c:343` (`float`, root by name, returns a count, logs on miss), and
`springbone.c:74` (`bool`, starts at `root+1`, and **fuses two other computations into the same
pass** — `first_child[]` and a `new_joints` count).

- Extract an index-based core filling `uint8_t`, beside `skeleton_compute_bind_globals`
  (`animation.h:54`), which is the existing precedent for a skeleton-level utility at that level.
- `animator_mask_subtree` keeps its name/log/count wrapper and converts in a second pass.
  `uint8_t` 0/1 → `float` 0.0f/1.0f is exact, so `anim-mask` (`gates.py:15150`) and `anim-layer`
  (`:15085`) see identical bits.
- **Leave `springbone.c` alone** and say why in a comment. Its pass is not a subtree mark with
  extra steps; the extra steps are the reason it is one pass.

**C2. Hoist the write-back idiom as `static inline`.** `ik.c:209` (`rotate_global`) and
`springbone.c:337-342` are the same arithmetic: `glm_quat_mat4`, then `glm_mat4_mul` with the
rotation on the **left**, then overwrite the translation column and set `[3][3] = 1.0f`.
`ik.c`'s own comment already asserts the shared lineage.

**It must be `static inline` in `animation.h`, not an `extern` in `animation.c`.** The build pins
no `-ffp-contract` (verified: no such flag in `CMakeLists.txt`, `cetra/CMakeLists.txt` or
`cmake/`), so clang's default permits FMA contraction. `rotate_global` is currently `static` and
inlined into `solve_two_bone`; promoting it to a non-inline extern changes the inlining context
around `glm_mat4_mul`'s multiply-add chains, and contraction can follow. `static inline`
preserves the current inlining and sidesteps the question entirely.

Use a src/dest signature — `f(mat4 dest, mat4 src, versor q, const vec3 head)` — so springbone's
site is a structural identity with no added copy and ik's sites pass `m` for both. cglm documents
`glm_mat4_mul` as alias-safe (`mat4.h:300-308`).

**Know what you cannot verify here.** `springbone.c` has **no gate arm and no golden** — the only
two "spring" hits in 23k lines of `gates.py` are a flag that turns springs *off* and a prose
mention. It is not merely uncovered but inert in the corpus: `render.c:3800` registers chains only
under the prefix `"hair"`, and `puppet.gltf` contains no such bone, so `spring_bone_update` returns
at its first guard in every golden. The conversion is therefore justified by identical arithmetic
and preserved inlining, **not** by the suite. Record that as a debt rather than implying coverage.

### Group D — engine, public API

**D1. `sole_offset` on `IkFoot`.** The ankle's bind clearance above the sole exists in three
textual forms in `gametest.c`, all deriving the same quantity from the same bind pose:

| site | form |
|---|---|
| `:1124` | `ik_ankle_lift`, derived in `on_init`, applied at `:1622` |
| `:2142` | `bind_lift = ankle[1]`, the swing probe's local, applied at `:2155` |
| `:2272` | `lt[1] += ankle[1]` / `rt[1] += ankle[1]`, under a comment saying it must match the app's |

That comment — a copy warning that the third site must agree with the first — is the finding.
Move the offset onto `IkFoot` so the solver owns it and the three callers stop pre-baking it.

**One consequence to handle deliberately:** `ik_effective_weight` measures release against the
already-lifted target (`ik.c:356`, `lift = ankle[1] - f->applied_target[1]`). Moving the offset
inside the solver changes where it enters that subtraction and changes what `applied_target`
means. `ik-swing`'s band (`0.6 < ratio < 0.95`) and the roadmap's headline 89% figure both read
that path, so this phase re-measures them rather than assuming.

**D2. `max_pelvis_drop` as a fraction of leg length.** Currently metres, default `0.5f`
(`ik.c:28`), ≈0.61 of this rig's 0.82 leg length. `plant_fraction` is the in-file precedent for
both the units and the wording (`ik.h:49-51`, "as a fraction of the leg's own length, so it
carries across rigs and scales").

The conversion is nearly free: `norm(ab) + norm(bc)` is **already computed per foot inside the
drop loop** (`ik.c:421`), one line above the deficit. The cap is applied once, system-wide, after
the loop — so carry the **worst foot's** leg length out alongside `worst` and cap against that,
rather than capping per foot inside the loop (which would change the semantics from "cap the
drop" to "cap each foot's demand").

**Pick the default to be behaviour-preserving first.** `0.5 / 0.82 = 0.6098` reproduces today's
cap on this rig; land that, confirm nothing moves, and only then consider rounding it. The cap is
expected not to bind on the fixture at all — the ramp's ground differs by 0.05 m against a 0.82 m
reach, so `min(worst, cap)` returns `worst` either way — which is the hypothesis this phase tests
rather than assumes.

## Phases

Branch `12.5-what-the-ik-review-left`, off master, which is clean and at `d7bd1acf`.
Each phase ends green on its own gate; nothing is committed with a red suite.

1. **Spec.** Branch, copy this plan to `specs/12.5-what-the-ik-review-left.md`, commit it alone.
2. **A1 + A2 + A3** — `gates.py` only, no engine change, so the whole engine is a control.
   Green on: `--only ik,gate-docs,anim,ui,save,audio`.
3. **B1 + B2** — the two bit-identical engine deletions. Green on: `--only ik` and all 33 goldens
   (which must be **0 px**, since B1 is provably exact and B2 changes only an unreached path).
4. **C1 + C2** — the two shared helpers. Green on: `--only ik,anim` and all 33 goldens.
5. **D1** — `sole_offset`. Green on: `--only ik` and all 33 goldens; re-measure `ik-swing`'s
   ratio and reconcile the roadmap's 89% if it moves.
6. **D2** — `max_pelvis_drop`. The only phase that can move pixels, landed **alone** so any
   movement is attributable to exactly one change. Green on: `--only ik` and all 33 goldens.
7. **Docs + the full suite.** `AGENTS.md`'s `ik.c/h` row if the API changed; `ik.h`'s own
   comments; `docs/verification.md`'s foot-planting section for the springbone-coverage debt C2
   records; `specs/12.4-two-bone-ik.md:200`, which still describes the old clamp
   `[|L1-L2|*(1+1e-4), (L1+L2)*(1-1e-4)]` and is stale against the code. Full gate run and all 33
   goldens on the final build.

**Must not move, re-checked at every phase boundary rather than only at the end:** all 33
goldens (especially `menu` and `menu_focus`, which run the full app with IK live — neither passes
`--no-ik`), and the gate groups `ik`, `anim`, `ui`, `save`, `audio`, `gamepad`, `gate-docs`.

## Verification

```bash
./build.sh

# Per phase — scope to the blast radius, not the whole suite.
python3 scripts/gates.py --only ik,gate-docs
python3 scripts/gates.py --only ik,anim,ui,save,audio
python3 scripts/goldens.py                       # all 33, phases 3-6

# Phase 7 only.
python3 scripts/gates.py
python3 scripts/goldens.py
```

Two rules from `AGENTS.md` that bite here specifically:

- **Goldens run from a debug build.** `--bin-dir out/release/bin` is the fast path for gates and
  the wrong path for goldens — they are committed PNGs baked from a debug build, and `-O2` moves
  CPU float results. Phases 3-6 all assert on goldens.
- **Measure the noise floor before quoting any pixel count.** `menu` has a recorded bistability of
  exactly 752 px on two occasions against 0 px on six others, unexplained. If phase 6 moves a menu
  golden, that number is the first thing to rule out — and it sits inside whatever bar a pixel
  claim could set.

By eye, after phase 6, since no arm sees the drop as a silhouette:

```bash
./out/bin/gametest            # walk onto the ramp at +X, the stairs at -X
./out/bin/gametest --no-ik    # the same without planting, to tell the two apart
```

## What this deliberately does not do

- **The `ik-swing` reroute**, dropped on evidence above; `sole_offset` carries its payload.
- **`springbone.c`'s subtree walk**, which fuses two other computations into its one pass.
- **`_audio_probe_run`'s parse**, which is a genuinely different grammar.
- **A spring gate arm.** C2 establishes that `springbone.c` has no instrument of any kind. That is
  worth closing and is not this spec's job; record it in `docs/verification.md` as a debt.
- **Anything in `docs/verification.md:551`'s five foot-planting debts.** The verdict line stays
  **Owed. The solver is exact on ground nobody has walked across.**
