# Spec 11.38 — varyings are extrapolated where coverage is partial

## Context

With MSAA the fragment shader runs **once per pixel** while coverage is **per sample**. Every
varying is evaluated at one point, by default the pixel centre — and on a partly covered pixel
that centre can lie outside the triangle. Interpolating outside a triangle is extrapolation: the
barycentric weights go negative and every value leaves the range its three vertices bound.

Commit `35338e5` fixed exactly one varying this way: `centroid out vec4 VertexColor`, which was
`apps/tree`'s grass speckling. It closed with a promise it did not keep — *"The other varyings
are extrapolated too and that remains true; it wants its own change, with the re-bake and a
fixture that can see it."* Three things follow from that, and this spec is all three:

1. **The finding exists only in a commit message.** `grep centroid specs/ docs/` returns two
   unrelated hits. Nothing in `specs/` or the roadmap knows the mechanism, so the next person to
   meet it starts from zero — as this session did, through seven wrong fixes.
2. **There is no instrument.** Finding a bug whose signature is *"a value left the range its
   vertices bound"* took an entire session of elimination. A `length(Normal) > 1` test would have
   printed it in one frame. That test is sound and universal (below), and it does not exist.
3. **The roadmap is now wrong about it.** `docs/aaa-rendering-roadmap.md:39-60` attributes the
   tree "popping fireflies" to the MSAA-resolved SSS tag and depth. Elimination disproved that:
   the resolve was the **amplifier**, the extrapolated varying was the **cause** — the pyramid
   was faithfully spreading a genuinely out-of-range input. That block also cites
   `specs/11.36-water-clarity-at-world-scale.md` for the SSS recipe; the recipe is in **11.37**.

**The surface is larger than the three varyings this was scoped as.** The full interface
(`pbr_vert.glsl:29-38`) is `Normal`, `WorldPos`, `ViewPos`, `TexCoords`, `TexCoords2`,
`VertexColor` (centroid), `TBN` (mat3), `TangentW` (flat), `CurrClip`, `PrevClip`. Two of the
unqualified ones matter more than UVs: **`ViewPos` selects the light cluster and the shadow
cascade** (`pbr_frag.glsl:1304`, `:1313`), so its extrapolation is a *discrete jump*, not a
smooth error; and **`CurrClip`/`PrevClip` go through a perspective divide** into the velocity
buffer (`include/velocity.glsl`), which amplifies it before TAA reads it.

**The UV case is already shipping, not theoretical.** `apps/tree`'s leaf atlas is 4096×512, one
row of 8 cells (`tree.c:168-170`), with **zero gutter** (`vegetation_tex.c:526-529`), UVs
spanning exactly `[variant/8, (variant+1)/8]` (`tree_gen.c:609-611`), and `draw_leaf` already
paints sprigs across cell boundaries (`vegetation_tex.c:400-410`). So *any* U excursion crosses
into a different leaf cluster; at variant 0 or 7 it leaves `[0,1]` and GL_REPEAT wraps to the
opposite end of the atlas. It corrupts the **normal and roughness** maps from the same atlas,
not just colour.

**Decision taken up front: measure, then decide.** Qualifying every varying moved 22 of 23
goldens. Phases 1-3 build the instrument and the fixture and produce numbers; phase 4 qualifies
only what those numbers implicate and re-bakes only what that moves. 11.37 phase 3 (the
two-profile SSS MSAA fixture) stays in 11.37 — this fixture must be **opaque** for a reason
given below, and that is incompatible with it.

State: `master`, clean, **16 commits ahead of `origin/master` and not pushed** — do not push
without per-instance permission. Branch off `master` and commit the spec before any code.

## Phase 1 — the instrument

A debug render mode that reports, per pixel, how far each varying left the range its vertices
bound. No new varyings, so zero interface cost; a debug-mode early-out, so zero cost on the PBR
path.

**`cetra/src/common.h`** — add `RENDER_MODE_EXTRAPOLATION` at the end of `RenderMode` (:66-90),
so it is mode 12. `--render-mode` takes a raw `atoi` (`render.c:417-421`), so it is reachable
from the CLI with no parser change. `apps/tree/src/tree.c:1262-1265` clamps to
`RENDER_MODE_SSS_HOTSPOTS` — that clamp moves. Add it to the GUI combo in `gui.c` beside the two
hotspot modes.

**`cetra/shaders/pbr_frag.glsl`** — a new early-out in the block at `:819-884`. It must stay
**above** the depth-only exits, which `render.c:708-711` calls out explicitly. Three channels:

| channel | test | soundness |
|---|---|---|
| R | `max(0, length(Normal) - 1)` | **Exact, any asset.** `pbr_vert.glsl:102` is `Normal = normalize(...)`, so every vertex value is unit. Any convex combination of unit vectors has length ≤ 1 by the triangle inequality, with equality only when they are equal. So `> 1` *requires* a negative weight. No false positives. |
| G | `max(0, length(TBN[0]) - 1)` | **Exact, same argument** — `tbn.glsl:14` is `T = normalize(Tworld)`. |
| B | UV excursion outside `[0,1]`, max over components | **Fixture-scoped.** UVs are bounded only by what the mesh authors, so this is sound only where the asset authors UVs in `[0,1]`. True of the fixture, false of anything tiling. Say so in the shader comment; the arm reads it only on the fixture. |

`TBN[1]` is deliberately **not** a channel: it is `cross(N, T) * w`, whose vertex length is
`sin(angle between N and T)` — ≤ 1 but not 1, so `> 1` is not a sound test for it. The fragment
stage re-derives B anyway (`pbr_frag.glsl:967`).

Scale by a `GAIN` constant and clamp to 1. Load-bearing, not cosmetic: the MSAA resolve
(`postfx.c:2721-2726`) box-filters the debug frame *before* the passthrough blit, so a partly
covered pixel's excursion arrives multiplied by its coverage — and the excursion is largest
exactly where coverage is smallest. The 8-bit PPM then clamps. Start at 64 so a quarter-covered
pixel with a 0.002 excursion still clears the quantisation floor.

**`apps/tree/src/tree.c`** — add `--msaa`, which it does not have. It runs the engine default of
4× MSAA *and* enables TAA (`tree.c:1345`), which is why the specks surfaced there and why the
app cannot currently be A/B'd against 1 sample. Mirror the policy-then-override ordering at
`render.c:3037-3045` so `--msaa` wins over the app's own default.

## Phase 2 — the survey, which is the decision gate

No new code. Run the instrument at `--msaa 4` over the corpus and record where extrapolation
actually happens, and how much:

- The 23 golden scenes — read scene, size and flags straight out of `scripts/goldens.py:56-189`
  (`RECIPES` is the single source of truth for those commands).
- `apps/tree` at the framing that showed the specks, and `apps/forest`.

Record per scene: the pixel count above the floor in each channel. That table is what phase 4
decides from.

**The varyings with no invariant get measured differently.** `WorldPos`, `ViewPos`,
`CurrClip`/`PrevClip` are positions — there is no in-shader bound to test them against, because
no vertex length constrains them. Their measurement is the A/B itself: build once with those
qualified, diff against the baseline, and the diff *is* the number. Do this in the survey, not
in phase 4, so phase 4 is a decision rather than an experiment.

Roughly 25 renders. Pin exposure (`--no-auto-exposure -E 1.0`) and measure each config's noise
floor before quoting any pixel count.

## Phase 3 — the fixture

`assets/gen_varying_fixture.py`, modelled on `assets/gen_mask_fixture.py` (module docstring
stating what invariant each element carries, `struct.pack` buffers embedded as a base64 data
URI, one generator emitting **both** the `.gltf` and the `.cscn` at `json.dump(..., indent=1)`,
a `regenerate with:` line). Fixtures are generated, not hand-written — there are 31 `gen_*.py`
in `assets/`.

`assets/varying_fixture.gltf` carries four things, each load-bearing:

1. **A row of thin fins, curved across their width, with fanned vertex normals.** Thin so nearly
   every pixel is partly covered — that is the mechanism. **Curved is the requirement that is
   easy to miss and fatal to omit**: a flat quad's three vertices share one normal, and
   extrapolating a constant gives the constant, so a flat fin cannot show `Normal` excursion at
   all. Same for tangents. UVs span the full `0..1` per fin, each triangle spanning the whole
   range so an excursion leaves the box and is detectable.
2. **Opaque materials, no `ALPHA_MASK`.** `a2c_capable = engine->msaa_samples > 1 &&
   !engine->capturing` (`render.c:328`), so alpha-to-coverage switches on and off *with the
   sample count*. A masked material would make every MSAA-vs-1-sample read a measurement of two
   changes at once. This is also why 11.37 phase 3 cannot share this fixture.
3. **Vertex colours with real RGB near 1.0.** Nothing in the corpus exercises vertex colour RGB
   — `mask_fixture` pins RGB to white and uses `COLOR_0` only for alpha
   (`gen_mask_fixture.py:59-64`). So the one varying that *has* been fixed still has no test.
4. **A full-frame backdrop quad, and one positive-control quad.**
   - The backdrop: attachment 0 clears to a 0.1 grey (`engine.c:96`) and that is **not**
     scene-overridable, so without a backdrop the instrument's zero and the background are
     different values and every count is contaminated. A large flat fully-covered quad reads
     exactly zero in all three channels — it is the background, the in-frame negative control,
     and the proof the mode is not stuck on, all at once.
   - The control quad: **UVs authored past 1.0**, so the B channel must fire there always, at
     full coverage, at both sample counts. That is the permanent liveness check the house
     convention requires (`skin-off`/`skin-live`, `tsl-off`/`tsl-live`, and the note that *"three
     zeros are also what a dead flag produces"*), and it needs no shader lever to arm.

`assets/varying_fixture.cscn` — one directional light, authored `camera` (`eye` + `target` +
`fov`), `post` with `"tonemap": "neutral"` and pinned exposure. No textures: the `.cscn` material
vocabulary has no albedo or normal-map key, only `anisotropyMap` (`material.c:28-85`), so
anything textured would have to go in the `.gltf`. Nothing here needs a texture.

**A new `varying` gate group** — one `run_varying_gate(workdir)` plus one tuple in `GATE_GROUPS`
(`gates.py:5208`) is the whole registration.

| arm | reads | wants |
|---|---|---|
| `vary-coverage` | `--render-mode 5` (flat colour) at `--msaa 4` vs `--msaa 1`, via `compare()` | `ae >= floor` — proves the fixture *has* partly covered pixels. The `MASK_LIT_FLOOR` tradition: show the thing is there before its absence means anything. |
| `vary-frame` | instrument at `--msaa 4`, R and G counts on the fin box | exactly 0 |
| `vary-uv` | same frame: B on the fin box, and B on the control box | 0 on the fins, **above the floor on the control** |
| `vary-color` | fins' shaded box mean at `--msaa 4` vs `--msaa 1` | within tolerance — the behaviour-level arm for the bug already fixed |

Mechanics: `render()` hard-codes 400×300 and `-f 30` (`gates.py:122-127`), so this needs its own
`_vary_render` like every other gate has. **No existing helper counts pixels above a per-channel
ceiling in a box** — `_water_foam_px` (`gates.py:3308-3327`) is the shape to copy with the
predicate swapped. Every bar records the builds it was calibrated against, per house standard.

**R and G liveness is proven once, at implementation time, and recorded in the spec** — by
measuring them before the qualifiers land (or with one reverted). It cannot be a permanent arm,
because after the fix there is nothing left for it to fire on. This is the `e55106f` lesson
stated explicitly: a fixture that cannot fail hid a bug.

## Phase 4 — apply what the survey justifies, and re-bake

Per varying it is a **three-file edit** — `pbr_vert.glsl`, `pbr_skinned_vert.glsl`,
`pbr_frag.glsl`. Only `pbr` and `pbr_skinned` link `pbr_frag` (`program.c:426`, `:488-489`), and
a qualifier mismatch is a **link failure**, not a shading difference. If `TexCoords` is
qualified, mirror it in `shadow_depth_vert/frag` or the shadow map's alpha-cutoff fetch
(`shadow_depth_frag.glsl:45-49`) samples at a different point than the shading pass does.

**The cost to state plainly, because it is not confined to silhouettes.** `centroid` makes
screen-space derivatives inexact near a silhouette — a neighbour in the 2×2 quad can have a
different sample point. Two consumers read derivatives of these varyings: the specular-AA
variance term (`pbr_frag.glsl:1057-1064`, `dFdx(N)`) and `skinCurvature` (`:1293`, from
`dFdx(WorldPos)`). So qualifying `Normal` or `WorldPos` perturbs pixels *adjacent* to a
silhouette even where coverage is full. Isolate with `specularAAStrength = 0`.

Re-bake with `python3 scripts/goldens.py --rebake`, which renders twice and refuses if the two
differ (`goldens.py:270-277`) — so a non-deterministic scene cannot be baked by accident.

# As built

Phases 1 to 3 shipped as planned. **Phase 4 did not, and that is this spec's result rather than
a shortfall**: the survey it was gated on says the fix is worse than the defect. Phase 5's record
therefore documents a rejected approach instead of an applied one, and the corpus stays at 23/23
with its baseline untouched.

## The instrument (phase 1, `2899dbd`)

`RENDER_MODE_EXTRAPOLATION`, mode 12, an early-out in `pbr_frag` above the depth-only exits. R is
`max(0, length(Normal) - 1)`, G the same on `TBN[0]`, B the UV excursion outside `[0,1]`, all
times a gain of 64 and clamped.

R and G are **exact on any asset, with nothing to calibrate**. `pbr_vert.glsl:102` normalizes the
normal and `tbn.glsl:14` the tangent, so every vertex value is unit — and a convex combination of
unit vectors has length at most one by the triangle inequality, with equality only when they are
all equal. A length above one therefore *proves* a negative barycentric weight. fp32 error on a
length is ~1e-7 against the 6e-5 the gain needs to reach one 8-bit code, so rounding cannot fake
it. `TBN[1]` gets no channel: it is `cross(N, T) * w`, whose vertex length is the sine of the
angle between N and T, so the same test would report authored non-perpendicularity as
extrapolation.

Two properties of a debug frame that a reader will otherwise be caught by. It skips tone mapping
but **not the MSAA resolve**, so an excursion arrives multiplied by its own coverage — largest
exactly where coverage is smallest — which is what the gain is for. And attachment 0 clears to a
0.1 grey that is not scene-overridable, so an uncovered pixel reads **25/255** and any threshold
on a real scene has to clear it. `apps/tree` also gained `--msaa`, which it never had despite
running 4x MSAA and TAA together.

## The survey (phase 2)

Measured on real content first, at 800x600 requested (1600x1200 framebuffer), threshold 64/255:

| asset | normal @4x | tangent @4x | uv @4x | all three @1 sample |
|---|---|---|---|---|
| `apps/tree` grass framing | 2,198 | 1,986 | unreadable | 0 |
| raiden (the cross-build recipe) | 1,591 | 1,301 | **15** | 0 |
| `parallax_fixture` | 0 | 0 | 0 | 0 |
| `varying_fixture` | 13,149 | 13,149 | 13,122 | 0 |

Four things that table settles:

1. **The defect is real and not tree-only.** raiden is the house baseline and carries it.
2. **The UV channel fires on real content** — raiden's 15 px at peak 128/255 is an excursion of
   ~0.008 of the texture, about 8 texels on a 1024 map. Character atlases gutter at 2-8 texels,
   so that is marginal; `apps/tree`'s leaf atlas has **zero** gutter, so it bleeds outright.
3. **The UV channel is meaningless on tiling geometry**, as the shader comment claims. Tree reads
   1,170,351 px at ONE sample, where extrapolation is impossible, because grass and terrain
   author UVs outside `[0,1]` on purpose.
4. **`parallax_fixture` cannot see any of it**, which is why the fixture had to be built. One
   large near-axis-aligned quad covers 478,677 px and yields ~423 partly covered ones: area is
   not the quantity, perimeter at an angle is. Its normals are also constant, and extrapolating a
   constant returns the constant.

## Why phase 4 was not applied

Four qualifier variants, each built and run against the full golden set:

| qualified | goldens moved | `skin_curvature_fixture` | `skin_curvature_sss` |
|---|---|---|---|
| `Normal` + `TBN` | 11 | 310,313 | 149,932 |
| + `WorldPos` | 21 | 118,666 | 78,260 |
| every interpolated varying | 22 | 118,954 | 78,463 |
| `TexCoords` alone | 9 (6 of them ≤ 10 px) | 10 | 10 |

**`centroid` makes derivatives inexact — the GL spec leaves that accuracy undefined — and every
remaining varying feeds a derivative.** Explicitly: `dFdx(Normal)` drives the specular-AA variance
term (`pbr_frag.glsl:1057-1064`) and `dFdx(WorldPos)` drives `skinCurvature` (`:1293`) and the
receiver-plane shadow bias. Implicitly: **UV gradients drive hardware texture LOD selection**,
which is why `TexCoords` spreads across whole surfaces while differentiating nothing in the
source.

The decisive evidence is the diff *pattern*, not the count. On every variant it follows the
**tessellation** across the entire shaded surface rather than the silhouettes —
`skin_curvature_fixture` is spheres, whose silhouette is a thin ring, yet 118,666 px move. RMSE
is only 0.0025 and a 480px-wide A/B looks identical, which is exactly how a topology-correlated
high-frequency pattern hides from a downscaled comparison; at PAE 37/255 it is not last-bit. So
the trade is a *bounded, silhouette-local* error swapped for an *unbounded-in-area* one on the
skin path. Rejected on inspection.

**`Normal` and `WorldPos` are a coupled pair**, which only the subsets revealed: qualifying
`Normal` alone reads 310,313 px on the curvature fixture and adding `WorldPos` *halves* it to
118,666. `skinCurvature` compares the gradient of one against the gradient of the other, and one
centroid-sampled gradient against one centre-sampled gradient is worse than either matched pair.
A partial application is therefore worse than none or all — which is why "just do the cheapest
subset" is not available.

**And this explains the asymmetry with `35338e5` rather than leaving it as an inconsistency.**
`VertexColor` is the one varying in the interface that nothing differentiates: it is read at
`pbr_frag.glsl:930-931` and nowhere else, never through `dFdx`, never as a texture coordinate.
That is why it took the qualifier at 0 of 23 goldens moved while these move 9 to 22. The earlier
commit's "it wants its own change" is answered: the others want a *different mechanism*, not the
same one applied wider.

## What ships instead

The instrument, the fixture, and four characterization arms (`fdab26c`). `vary-ground` is the
permanent invariant — at one sample extrapolation is not small but impossible, so a nonzero
reading there is the instrument lying. `vary-msaa` records the open defect at its measured size,
deliberately, so that reaching zero requires a deliberate edit here rather than happening
silently.

**The structural escape already exists and is what the engine ships**: 1 sample plus TAA, immune
by construction, which `apps/render` defaults to since 11.34. `apps/tree` does not — it runs the
4x default *and* TAA, which is why the specks surfaced there — and `--msaa 1` now reaches the
immune path. Its default is left alone: the visible symptom was `VertexColor` and is already
fixed, the remainder is bounded by the `normalize()` at every consumer, and changing an app's
sample count is a look decision rather than a correctness one.

## Deferred, with the reason

**Per-sample shading on edge pixels** is the complete answer and needs `gl_SampleMaskIn` plus
`#version 400`, or `sample`-qualified varyings — the same incompatibility spec 11.17 rejected
`sampler2DMS` for. It is also the answer the industry declined: MSAA left AAA rendering around
2013 precisely because a fat G-buffer and per-pixel shading cannot both be right, and this engine
already ships the replacement.

**A UV fixture with a real atlas** would demonstrate the consequence rather than the mechanism —
tile bleed at a silhouette. Not built, because `apps/tree` already *is* that case at zero gutter,
and no fix is being applied for it to verify.
