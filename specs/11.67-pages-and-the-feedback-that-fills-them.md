# 11.67 — D10 stage 2: pages, and the feedback that fills them

## Context

Stage 1 (11.66) shipped the composite cache as one domain-wide atlas pair plus a runtime detail
term. Stage 2 makes it a real virtual texture: a **paged physical atlas** whose residency follows
the camera, filled on demand, with a **GPU feedback pass** reporting what pixels actually touched —
the mechanism, not a flag, because this VT's stated trajectory is roads, decals and arbitrary
meshes, where the CPU can no longer enumerate visibility and feedback is the only correct source.
The wanted-set is a **union from day one**: CPU frustum prediction (prefetch, frame-0 and
post-teleport coverage) ∪ GPU feedback (ground truth for what rendered) — the same shape UE runs.

Three exploration passes and one adversarial design review verified every capability claim against
the source. Nothing here needs anything above GL 3.3 except `glFenceSync` (3.2 core); no compute,
no sparse textures, no `glTexStorage`, no new sampler declaration in `pbr_frag`.

**Honesty clause carried from stage 1**: with grain frozen at bake, pages resolve only splat-edge
sharpness beyond the fallback, which already over-resolves today's 513² splat. So the *visual*
arms force the fallback coarse to make page content legible, and the *residency/feedback* arms
read probe integers at default density. Real page content arrives with roads/decals, which will
draw into pages through the bake FBO without touching `pbr_frag`'s ledger — that composability is
why the atlas is built now.

## The design (as pressure-tested)

### Physical page atlas — two-mip, guttered, GI-atlas layout

Per paged material: one new `GL_TEXTURE_2D` pair (same RGBA8 packing as the fallback pair).
2048² atlas, 64 page slots of 256² each with a **4-texel gutter ring** (248 usable), the GI-volume
layout (`gi_volume.c:24-38`, gutters *written* by the bake covering the bordered tile, not copied).
**Two mip levels** (`GL_TEXTURE_MAX_LEVEL = 2`, `LINEAR_MIPMAP_LINEAR`, aniso off, one whole-atlas
`glGenerateMipmap` on frames that baked): power-of-two page alignment makes generation bleed-free
by construction, and 4-texel gutters bound trilinear reach at level 2. Mip-free was reviewed and
rejected — up-to-4× unmipped minification shimmers on exactly the content pages carry.

### Page density is RELATIVE, and that bounds everything

**Page texel density = 4× the fallback's** — the ratio, not an absolute span. Pages only beat the
fallback where the fallback is magnified (footprint < 1 fallback texel = 4 page texels), so the
handoff constant K = 4 is the density ratio, not a tunable. Consequences:

- Virtual grid ≤ ceil(4·2048/248)² = **34² = 1156 pages for every domain size** — forest's 1 km
  and `--terrain-extent 4000` alike (the fallback res clamps at 2048, so page span scales with the
  domain). No sliding window, no table rewrites; a page's rect stays a pure function of its id,
  which the probe digest and deterministic bake order require.
- Handoff: `smoothstep(2.0, 4.0, maxAxisFootprintInPageTexels)` blends page → fallback. At the
  band's far end, page mip 2 and fallback mip 0 are the same macro at the same effective density —
  the band is invisible **by construction**, not by tuning.
- Guard: `--layers-vt-res` above 2048 (the diagnostic skips clamps on purpose) would re-overflow
  the grid — clamp the virtual grid to table capacity there.

### Page table — a UBO, not a sampler

`VtPageBlock` on **binding 7** (registry `ubo.h:24-30`; next free), entries packed 4-per-ivec4
(the `iesTap` idiom, `lights_ubo.glsl:79-81`): 34²→512 ivec4 + header ≈ 8.2 KB,
`_Static_assert(<= 16384)` (the IES pattern, `ubo.h:121-122`). Entry = atlas slot or −1.
Fragment-varying UBO indexing is proven in-tree (cluster grid, IES pool). Uploaded on change only,
revision-gated (`ies_uploaded_revision` idiom, `light_cluster.c:403-412`). **v1: one paged
material per scene**, engine-owned UBO, warn if a second qualifies — forest has exactly one, the
fixture authors one, and it honours `ubo.h`'s buffer-per-binding lifetime contract.

### Sampler units 3/4 — refusal-backed aliases, with the Exists hardening

The page pair rides `clearcoatNormalTex` (3) and `heightTex` (4) — both `sampler2D`, matching. A
**layered material refuses clearcoat-normal and height maps** (the IES refusal idiom: warn by name
in `cscene_apply`, backstop in `material_layers_vt_ensure` which already owns armed state). The
`heightTex` refusal is independently a bug fix: POM currently runs a dead march on layered
surfaces and can **discard** (`pbr_frag.glsl:976-991` has no layerCount test). Hardening from
review: in the vt-armed arm of `render.c:251-279`'s if/else, bind the page pair to 3/4 **and force
`heightTexExists`/`clearcoatNormalExists` to 0** — skip-the-binds alone leaves Exists=1 reading
page data as a coat normal. Same structural exclusivity as units 0/1.

### Residency — owned by `material_layers_vt_ensure`, one frame behind, honestly

The frame's frustum doesn't exist when ensure runs, so ensure builds its own from
`engine->view_matrix`/`projection_matrix` (the same three lines as `render.c:1075-1077`). That is
frame N−1's pose — one frame of admitted lag, absorbed by hysteresis and by the fallback (a
missing page renders softer, never wrong). Mechanics:

- wanted = virtual pages whose rect intersects the frustum, tested via
  `frustum_test_aabb_transformed` with a conservative Y span; rects are AUTHORED space, the
  frustum is STORAGE — convert by `+ uWorldOrigin` (`world_origin.glsl:32-34`); ensure runs after
  `engine_apply_origin_shift`, so this is correct iff the conversion is applied, in one place.
- The **capacity clamp is the governor** (the transverse footprint bound is ~1200 pages at 1080p
  against 64 slots): sort candidates by (distance, page id) — deterministic — take the first
  `slots`, and apply hysteresis at the truncation edge too, or the last slots oscillate.
- Bake budget N pages/frame (default 2; the `gi_volume_update` budget idiom), evict
  farthest-from-want. All state on `MaterialLayersVt`.

### Page bake — the existing program, verified

`layers_vt_bake` gains a `vtBakeRect` uniform (world rect, defaults to `splatDomain`);
`glViewport` into the page's atlas sub-rect (the GI precedent — the engine's one non-origin
viewport gains a sibling). Review verified: `dFdx = span/256` = one page texel exactly; the splat
tap magnifies correctly; `layerGrainFrozen` untouched; gutters bake as rect+margin.

### Shader read

In `sampleCachedSurface`: compute the virtual page from the splat uv; UBO lookup; if resident and
footprint < 4 page texels, sample the page pair via the gutter-inset transform — **`textureGrad`
from the already-hoisted derivatives** (atlas UV is discontinuous at page borders; implicit LOD
there is a seam machine) — and blend toward the fallback over the [2,4]-texel band. The
dominant-index `texelFetch` keeps reading the **fallback** at mip 0 (page/fallback index
disagreement at blend boundaries would flicker the detail term through the smoothstep).

### GPU feedback — fixed-latency, content-deterministic

- **Pass**: a small FBO (~1/8 res, one RGBA8 attachment encoding page id + wanted mip, plus
  depth), two sweeps in the `_submit_depth_prepass` shape (`render.c:797-928`): non-VT opaque
  items through the existing depth-prepass program (occluders), VT-sampling items through a new
  tiny `layers_vt_feedback` program (own ledger, ~0 samplers). Written GENERAL: it renders
  whatever samples the VT — today terrain, later decals join without touching the pass.
- **Readback**: `glReadPixels` into a **PBO ring, consumed at exactly frame N−R** (fixed slot,
  never "whichever fence signalled" — that was 10.2's nondeterminism and it does not apply to a
  fixed-latency consume). Content is a pure function of frame history → every gate arm stays
  deterministic; a late map costs wall time, never data. **R measured in its phase**: 10.2's data
  shows 2-deep still blocked 4.7 ms on this CPU-ahead-of-GPU engine; start at 4, record the
  measurement in the spec.
- **Union**: requested pages parsed CPU-side (dedup via a 1156-entry bitset), unioned with the
  frustum prediction before the capacity clamp. Feedback can only ADD demand the frustum missed
  (occlusion never removes; prediction covers frame-0/teleport/pre-feedback frames).

## Gates

Fixture arms (render app, 0 px paths, ~0.5 s each):

- **`vt-pages-identity`** — pages on vs off at default res → ~0 px (pages resolve nothing the
  fallback doesn't at fixture density); anti-vacuity: the probe must report >0 pages resident, or
  the identity is the flag doing nothing. Mutation: skip the page-table upload.
- **`vt-pages-effect`** — `--layers-vt-res 8` + pages vs coarse-only: near field differs (pages
  restore splat-edge sharpness), far field matches. The visual claim, decoupled from residency by
  design (at coarse res the virtual grid is 2×2 — the review's coupling bug, stated in the arm).
  Mutation: never bake pages (table stays −1).
- **`vt-pages-churn`** — `--layers-vt-page-slots 4` (25 virtual vs 4 slots) + `--cam-at` teleport
  at frame N: loads>0, evicts>0, resident ≤ slots always, resident-set digest deterministic ×2,
  and the post-teleport frame reads fallback (bounded diff vs the coarse leg) converging within
  the budgeted frames. Mutations: drop the capacity clamp; drop hysteresis (digest churns).
- **`vt-feedback-sky`** — camera aimed at sky: feedback requests **zero** pages
  (the `overdraw-empty` idiom). Mutation: unconditional request write.
- **`vt-feedback-occlusion`** — the fixture ramp occluding floor behind it from a low camera:
  occluded pages absent from the feedback stream while frustum-visible; the arm that discriminates
  feedback from prediction. Mutation: disable the depth sweep in the feedback pass.

Forest arms (integers, riding the existing 400-frame region walk process — `_region_run` gains
`--layers-vt-probe`, whose lines existing parsers ignore by prefix):

- **`vt-pages-walk`** — resident follows the walk, count ≤ slots, loads/evicts > 0 at default
  density (34² virtual vs 64 slots: churn exists by default), digest identical across the
  round-trip return (determinism + rebuild-identical, the region-return property).

Every arm's mutation run, not reasoned about. `run_layers_gate`'s docstring list extended
(gate-arm-docs contract; arms stay inline).

6. Spec AS-BUILT + roadmap D10 (stage 2 delivered; what remains is content — roads/decals — and

## Known risks (from the adversarial review, carried openly)

1. **Page-boundary filtering** — every VT bleeds here first. Mitigations built in: 4-texel
   gutters, MAX_LEVEL 2, `textureGrad`, fallback-owned dominant index. The fixture's ramp +
   checker is the instrument.
2. **Wanted-set stability at the capacity edge** — hysteresis applied at the truncation boundary;
   the churn arm's digest is the detector.
3. **The lag/teleport/origin-shift triangle** — authored↔storage conversion lives in exactly one
   place in ensure; `--cam-at` fires before ensure so a teleport is visible to residency the same
   frame; origin-shift ordering verified (shift applies before ensure).
4. **PBO ring depth is a measurement, not an assumption** — phase 4 measures it; a deeper ring
   costs staler feedback only.
5. **The handoff band on real content is unproven** — today it blends near-identical signals; when
   roads land it becomes a sharpness front. The forced-coarse arm is the proxy until then, stated
   as such in the spec.

## AS-BUILT

Every phase shipped; two deviated from the letter of the plan (7 and 8 below). Eight decisions
and corrections landed during implementation and review, all recorded where they live and
summarised here:

**1. The stage-1 gate legs stopped seeing pages.** `layers-vt-identity`'s coarse anti-vacuity leg
measures the FALLBACK's coarseness; with pages restoring sharpness it fell from 32,161 px to
10,205 -- two per cent above its floor. The leg (and `layers-vt-macro`, which shares the shot) now
passes `--no-layers-vt-pages`: stage-1 arms measure stage 1.

**2. The churn arm runs feedback-off, because feedback made residency smarter than the arm's
forcing.** After the teleport, the still-visible old pages vote, the seen-first sort keeps them
resident, and correctly nothing moves. The arm's charter is the eviction machinery in isolation;
feedback's behaviour has its own two arms.

**3. The union's concrete form is a sort key, not a set union.** Feedback pages are a subset of
frustum candidates by construction (a vote comes from rasterized geometry), so "union" landed as
priority: candidates sort (seen, distance, id). A page behind a hill is frustum-admitted but
unseen, and ranks below every page actually looked at -- occlusion-awareness as one comparator.

**4. The fixture's draw order became load-bearing, and the mutation round is what found it.**
Deleting the vote pass's depth test changed nothing while the occluder drew LAST -- painter's
order masked the deletion. The ramp now draws first (`scenes.nodes [1, 0]`, comment in the
generator), making depth the only thing rejecting the hidden floor; the lit golden moved on the
floor/ramp coplanar seam (the documented draw-order-tie class) and was rebaked deliberately.

**5. Arms measure at the size their numbers were taken.** The depth-off leak read 16 requested
pages at 400x300 and 12 -- a clean pass -- at the probe helper's original 200x150. The helper now
runs the group's own 400x300.

**6. The anti-thrash clause needed a measured ceiling, not a stability read.** "Tail stable" is
structurally guaranteed by the deterministic sort at a static camera, so the want-guard deletion
passed everything -- until the WALK arm gained `loads <= 200`: healthy measures 71 loads over the
round trip, the deleted guard measures 701. A 10x thrash, now a hard number.

**7. The feedback pass shipped as ONE sweep, not the plan's two, and it lives in `layers_vt.c`,
not `render.c`.** Only the paged surfaces draw, depth-tested against each other: terrain
self-occlusion is the occlusion that matters for ground pages, and omitting a foreign occluder (a
building over terrain) makes the vote conservative -- an extra page requested, never one lost. The
two-sweep occluder pass returns when the VT's consumers stop being one material's ground; the
single-material walk made the pass self-contained enough to live beside the residency it feeds.

**8. The review round found one genuine portability bug: the vote encoding sat on a unorm
rounding tie.** `(i + 0.5)/255` reconstructs to exactly `i + 0.5` under the RGBA8 write's
round-to-nearest, a tie the GL spec leaves implementation-defined -- so votes could decode one
page off, a silent diagonal shift every arm here would keep passing (the sky arm stays 0, the
occlusion band holds, the digest stays deterministic-per-build). Not theoretical: the fix moved
live readings on THIS machine (occlusion 12 -> 13 requested, identity 490 -> 696 px, walk loads
71 -> 79 -- the tie's fp32 residue varies per coordinate, so some votes were already decoding
one page off here). Now `i/255`, exact for all i <= 255, with the grid bound statically
asserted against the byte. Same round:
the uv-to-page mapping became `vtPageCoord` in `vt_pages.glsl` (the vote and the read must name
the same page -- two copies of that arithmetic were the punctualAngular class of drift), the
handoff band's endpoints now come from the uploaded density ratio instead of restating 2.0/4.0
as literals, the feedback pass gained the pages-off gate and a frustum cull over the vote walk
(exact for what the pass draws: its vertex stage applies no displacement), and the walk arm now
rides `_region_run`, so the residency walk and the region walk are the same launch.

### Measured

Fixture (`layer_vt_fixture`, all probe histories bit-identical across runs):

- Pages on vs off at derived resolution: **490 px** of 480,000 -- splat-edge resample only -- with
  25 pages resident (the anti-vacuity that catches a never-arming build, which reads 0 px and 0
  resident).
- Forced-coarse fallback: pages move **32,289 px** off coarse-only and land within **10,205 px**
  of the full-density reference -- pages recover about two-thirds of what coarseness lost, the
  density-ratio rule's exact prediction.
- Churn at 4 slots: fill to capacity, teleport evicts 2 and reloads 2, stable digest, no thrash.
- Feedback: **16 pages requested** at the default view, **0 aimed at the sky** (prediction still
  wanting 25 -- the anti-vacuity), **12 behind the ramp** with the occluded floor casting no votes
  against a frustum wanting all 25.

Forest:

- Grid **34** at every probe -- the relative-density bound holding at 1 km exactly as derived.
- The 400-frame region walk: **71 page loads, 7 evictions** under the capacity clamp, with
  feedback steadying residency (pre-feedback the same walk measured 110/46).
- Pages on vs off at walking distance: **0 px** -- on today's content the pages are an exact
  identity, the honesty clause's prediction; they earn their keep when roads/decals give the macro
  content beyond the fallback.
- Cost of the whole stage: **+0.23 ms opaque GPU (~2%)** at a half-ground framing, A/B/A/B
  release, CPU at noise -- which also settles the ring depth: at R = 4 the fixed-latency map never
  manifests as a stall. VRAM: 32 MB page atlas pair + 4.7 KB page table.

### Falsification, all run

| mutation | killed |
|---|---|
| residency never runs | all six page/feedback arms (identity via its resident-count anti-vacuity) |
| page-table upload skipped | pages-effect + feedback-occlusion (the shader's grid stays 0) |
| capacity clamp dropped | pages-churn + pages-walk (nothing is ever evictable) |
| want-guard and hysteresis deleted | pages-walk's thrash ceiling (701 loads vs 71) |
| the clear colour votes | feedback-sky (1 request against an exact-zero bar) |
| vote pass depth test off | feedback-occlusion (16 requested vs the 8..14 band) -- after the fixture reorder that made it catchable |
| density ratio halved | pages-identity, -effect, -walk (grid 17 vs the stated 34), feedback-occlusion |

### What remains, honestly

Pages resolve nothing on today's content -- the macro's finest content is the 513-square splat,
which the 2048 fallback already over-resolves. Stage 2 built the machinery and proved it under
forced-coarse configurations; the content that lights it up is roads and decals composited into
pages at bake time (they draw into the atlas FBO and never touch pbr_frag's ledger), and the
general-mesh era is what turns the feedback stream from an occlusion refinement into the only
correct source. Both are future specs; nothing in this one blocks either.
