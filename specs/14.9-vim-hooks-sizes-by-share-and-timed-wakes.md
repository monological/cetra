# 14.9: vim keys the host answers, sizes by share, and every timed wake

## Context

pcb's window (pcb spec 6.1) was reviewed, and some of its findings were changes to cetra. Spec 14.7
took three of them. This spec takes the rest. pcb's next view, the schematic (pcb 6.2), needs none of
them, since each has a workaround in pcb that works. The user wants them done properly anyway, so
pcb's workarounds can go.

- **Vim keys the host answers.** pcb's `gd` goes to a name's definition. cetra's vim mode has no
  `gd`, and no way for a host to answer one, so pcb peeks. When a `d` arrives, pcb asks the vim mode
  what it holds half-typed, and if that is exactly `g`, goes to the definition, while the vim mode
  drops the `gd` it does not know (pcb `src/window/keys.c:609-614`). That reads the vim mode's
  status-line text, and it breaks if the vim mode ever does `gd` itself. The user also wants three
  more of vim's commands that need the language: `K` (what a name is), `=` (re-indent) and `gq`
  (lay lines out again).
- **A size as a share of the parent.** pcb's splits keep a ratio, such as 0.7. cetra's layout can
  only make a pane FIXED, FIT or GROW, and GROW shares the room evenly. So pcb works the split's
  sizes out itself, from the room's size at the last layout, pins both sides FIXED, and does it
  again before and after each layout pass (pcb `src/window/panes.c:292-320`, and its two
  `size_panes` calls). It draws right, but pcb is doing the layout's arithmetic, and it depends on
  running at the right moment.
- **Every timed wake kept.** `engine_request_frame_after` keeps only the soonest time asked for.
  Ask for 2 s and then for 0.4 s, and the 2 s wake is lost. pcb asks for three -- the Space menu's
  0.4 s, the typing save's 0.5 s and a failed save's retry every 2 s -- and asks for each again
  every frame until it comes (pcb `keys.c:699`, `window.c:58`, `disk.c:762`).

**Decided with the user:**
- **The vim keys are hooks, not a `:map`.** Vim already has `gd`, Ctrl+], `K`, `=` and `gq`, so pcb
  does not need new keys. It needs to answer a question vim already asks. Real vim does this with
  options a program sets: `tagfunc` answers Ctrl+], `keywordprg` answers `K`, `indentexpr` answers
  `=`, and `formatexpr` answers `gq`. cetra's vim mode already hands two jobs to a host this way:
  `ui_editor_vim_set_undo` and `ui_editor_vim_set_prompt`. A general `:map` for the host would
  have to settle counts before a host's key, an operator before it, and a host claiming one of
  vim's own keys. It waits until pcb wants a command vim has no meaning for.
- **Completion** (Ctrl+X Ctrl+O, vim's `omnifunc`) is later, a spec of its own: it needs a list at
  the caret that cetra's editor does not have.
- **`gd` keeps its meaning in pcb.** The hook serves `gd` and Ctrl+] alike, so pcb's `gd` stays go
  to definition, as decided for pcb 6.1. In real vim only Ctrl+] asks `tagfunc`, and `gd` is always
  vim's text search. So `gd` asking the host is cetra's choice, not a copy of vim. With no host, or
  a host that declines, `gd` is vim's own.

Branch `14.9-vim-hooks-sizes-by-share-and-timed-wakes`. pcb takes these up in its spec 6.1.2.

## Found while planning

- **The vim mode's host hooks** are `ui_editor_vim_set_prompt` (`ui_editor_vim.h:45-46`) and
  `ui_editor_vim_set_undo` (`ui_editor_vim.h:58`). Each takes a function and a `user`, and the undo

- **`>` and `<` are the template for `=`.** `_operate_on` (`ui_editor_vim.c:2184`) gathers every

  with spaces only, from a column (`_shifted`, `ui_editor_vim.c:2088`), as vim does with
  `expandtab`.
- **A new line copies the indent of the line it was made from**: `o` and `O` in `_enter_insert`
  (`ui_editor_vim.c:2644-2675`), Enter in `_insert_break` (`ui_editor_vim.c:2863`), and `cc` and
  `S` keep their first line's indent (`ui_editor_vim.c:2228-2236`). That is vim's `autoindent`,
  which the oracle sets.
- **`*` already finds the word under or after the cursor and searches for it whole**
  (`_search_word`, `ui_editor_vim.c:883`). Vim's `gd` and `gD` use the same word.
- **The vim oracle** runs each case through vim 9.2 and through the vim mode, and compares text and
  cursor byte for byte:
  - vim's side: `_vim_reference` (`scripts/gates.py:26399`), `vim -Nu NONE -es` with `_VIM_SET`
    (`gates.py:26162`: `autoindent expandtab tabstop=4 shiftwidth=4`, and the rest), the keys fed
    as typed;
  - the mode's side: `_vim_cetra` (`gates.py:26430`), every case in one `gametest --ui-probe
    vim-run` with the cases in `CETRA_VIM_CASES`, and `CETRA_VIM_READ_ONLY` for the read-only run.
  So a hook can be checked against vim: vim's side sets `indentexpr` or `formatexpr` to a vimscript
  function, and the probe installs a hook doing exactly the same in C.
- **The layout shares room only among GROW children**, and on top of what each measures: the room
  left after every child's measured length and the gaps is split evenly, round by round, a child
  held at its `max_size` leaving its share to the rest (`ui.c:1094-1130`). `UIElement.size` is "the
  number FIXED uses" (`ui.h:400`), and GROW ignores it. pcb passes 260 with GROW in one place
  (pcb `src/window/status.c:106`), keeping the number for when the element turns FIXED.
- **A weight on GROW**, the roadmap's "grow weights", **would not give an exact ratio.** GROW adds
  its share on top of what a child measures. A side of pcb's split that is itself a split measures
  at least its gap, so a 0.7 split would come out a few points off. pcb maps the pointer to a ratio
  when a divider is dragged, so the divider would sit off the pointer. Hence a share of the parent
  (design 2), which Clay's PERCENT sizing also is.
- **The engine keeps one timed wake**: `EngineWake.wake_at`, the earliest (`engine.c:92`), set by
  `engine_request_frame_after` only when earlier (`engine.c:1072-1085`), and cleared once passed
  at the end of the wait (`engine.c:1048`). The idle decision reads it (`engine.c:982-983`): due
  means draw, and set means a headless run is not over. Callers, besides pcb's three: the UI's
  caret blink (`ui.c:2480`), and the canvas app's `--idle-wake` and two of its own
  (`canvas_app.c:2296`, `2466`, `2491`). It is main-thread only.
- **The canvas app's `--idle-wake S,S,...`** asks each time on its own frame, in turn
  (`canvas_app.c:2902-2906`), so it never asks two times in one frame, which is what loses one.
- **Vim 9.2, measured** with `_VIM_SET`, a rule as `indentexpr` (two spaces for every `(` still open
  at the line's start), a rule as `formatexpr` (the lines' words joined on one line), and
  `indentkeys=o,O`:

  | keys | what vim did |
  |---|---|
  | `=G` | every line from the cursor's to the end re-indented by the rule; a blank line left empty; the cursor on its first line's first character that is not a blank |
  | `o`, `O`, and Enter in insert mode | the new line indented by the rule, not copied from the line above |
  | the same with `indentkeys=` empty | the new line copied from the line above (`autoindent`): `o` and `O` in `indentkeys` are what make a new line ask |
  | `cc`, `S` | the line indented by the rule |
  | `gqj` with `formatexpr` | the two lines joined; the cursor where the function left it, which depends on how the function edits |
  | `gqj` with no `formatexpr` (vim's own) | the cursor on the last formatted line's first character that is not a blank |
  | `gd` on a word | the cursor on the word's first use from the top (no `{` in column 0, so from line 1); the last search set to that word, whole |
  | `dgd` | a delete from the cursor back to where `gd` goes: `gd` is a motion after an operator |

  Vim's own documentation adds two things. `gw` is `gq` that never asks `formatexpr`, so it is left
  out (nothing in cetra formats text without a host). And vim's default `indentkeys` also re-indent
  as `{`, `}`, `)` and a few others are typed. That is left out too, so the oracle sets
  `indentkeys=o,O`.

## The design

### 1. Every timed wake kept (`engine.c`)

- **`engine_request_frame_after` keeps every time it is asked for**, in a list of the times not yet
  come, sorted. The loop waits until the soonest. At the end of each wait, every time that has
  passed is dropped, and the rest stay. So the 2 s wake asked before a 0.4 s one still draws its
  frame, and a caller asks once.
- **A time within a millisecond of one already held is taken as the later of the two.** A caller that
  still asks for the same time every frame, as the UI's caret does, then holds one entry and not
  one a frame. Keeping the later means every caller's time has passed when the frame comes: a
  millisecond late, never early.
- **The list holds 64.** Asked for a 65th time, the engine says so once and merges it into the nearest
  later time held, or into the latest if it comes after all of them. A wake can come late, but none
  is lost.
- Still main-thread only, still at most a day ahead, and still no deadline while the loop waits for
  work (`IDLE_WAIT_WORK`). Headless, a run in idle mode does not end while any time is held.
- No new call. The header comment of `engine_request_frame_after` ("There is one deadline...")
  says what it now does.

### 2. A size as a share of the parent (`ui.h`, `ui.c`)

- **`UI_SHARE`**, a fourth size mode, appended to `UISize` so the others keep their numbers. With it,
  `size[axis]` is a share, from 0 to 1:
  - **along the parent's main axis**, the element is that share of the parent's inner length less
    the gaps between its children in the flow;
  - **across the parent's main axis**, the element is that share of the parent's inner length.
- **It is settled before GROW**, as a FIXED length is: GROW siblings share what is left. So a split
  is one side at `UI_SHARE` 0.7 and the other GROW, and the second side takes exactly the rest,
  whatever it measures.
- **A SHARE element adds nothing to a FIT parent's measure**, since its length depends on the
  parent's. Under a FIT parent, the share is of what the parent comes to.
- **A share is rounded down to a whole point**, so a pane's edge stays on a pixel boundary and its
  border and background draw sharp. cetra snaps only text to pixels (`ui_draw.c:755`), so an edge
  between pixels draws soft. pcb floors its split today (pcb `panes.c:309`), and this keeps that.
  A GROW sibling takes the rest, so a share beside a GROW fills the room exactly. Two shares adding
  to 1 may leave a point or two unfilled, which the main-axis alignment places as it places any
  room left.
- `max_size` holds a SHARE element as it holds FIT and GROW. Shares adding to more than 1 overflow
  as FIXED lengths do. FIXED and GROW are not rounded, as now.
- **Every layout without `UI_SHARE` comes out as before, to the float.** The `ui` group's layout arms
  are what show it.
- `UIElement.size`'s comment says what it holds for each mode.

### 3. The vim keys that ask what a name is (`ui_editor_vim.c`, `ui_editor_vim.h`)

- **`ui_editor_vim_set_lookup(vim, fn, user)`**, with
  `typedef bool (*UIEditorVimLookupFn)(UIElement* el, UIEditorVimLookup kind, void* user)` and
  `UIEditorVimLookup` one of:
  - `UI_VIM_LOOKUP_DECLARATION`, for `gd`;
  - `UI_VIM_LOOKUP_GLOBAL`, for `gD`;
  - `UI_VIM_LOOKUP_TAG`, for Ctrl+];
  - `UI_VIM_LOOKUP_KEYWORD`, for `K`.

  The host reads the name from the editor itself: its caret and, in visual mode, its selection, as
  pcb does now. It goes where it likes, another text included, and returns true. False means it
  found nothing, and NULL unsets the hook.
- **The vim mode reads the keys, as for any of its commands.** A count, Esc part way, and the `g`
  shown half-typed all work as vim's. None of these is kept for `.`.
- **When the host is asked:**
  - `gd`, `gD`, Ctrl+] and `K` in normal mode, with no operator waiting;
  - Ctrl+] and `K` in visual mode, with the selection still in place for the host to read; visual
    mode ends after, as vim's does;
  - **`gd` and `gD` after an operator, or in visual mode, are vim's own motions and never the
    host's**, since a host may answer with another text, which no operator can reach (measured
    above: `dgd` deletes back to where `gd` goes).
  - A read-only text asks as usual: a lookup changes nothing.
- **With no hook, or a hook that returns false:**
  - `gd` and `gD` are vim's own text search: the word as `*` takes it, searched for from the top
    of the block (`gd`) or of the text (`gD`), skipping lines vim takes for comments, the cursor on
    the first match, and the last search set to the word, whole, so `n` and `N` follow it and its
    matches are lit. They are held to vim by the oracle, motions after an operator included.
  - Ctrl+] and `K` do nothing, as vim's Ctrl+] does with no tags file. Vim's `K` runs `man`, which
    nothing here imitates.
- `ui_editor_vim_keys` lists `gd`, `gD`, Ctrl+] and `K`.

### 4. The vim keys that lay lines out (`ui_editor_vim.c`, `ui_editor_vim.h`)

- **`ui_editor_vim_set_indent(vim, fn, user)`**, with
  `typedef int (*UIEditorVimIndentFn)(UIElement* el, size_t line, void* user)`. It returns the
  column a line's indent should reach, or -1 to keep the indent it has. It is vim's `indentexpr`
  with `indentkeys=o,O`, and it is asked:
  - **by `=`**, an operator over any motion or text object, as `>` is: `==`, `3==`, `=ip`, `=G`,
    and `=` in visual mode. Each line is asked in turn, after the lines above it are re-indented,
    as vim asks. A blank line stays empty. The whole operator is one step of undo and one `.`, and
    each caret ends on its first line's first character that is not a blank;
  - **for a line just made**, by `o`, `O` and Enter, and for `cc` and `S`. The line takes the
    hook's answer in place of the indent copied from above; -1 keeps the copy. An indent nothing
    is typed after is taken out at Esc, as a copied one is.
  Indents are built with spaces, as `>`'s are. Lines are numbered from 0, as the text's are.
- **`ui_editor_vim_set_format(vim, fn, user)`**, with `typedef bool (*UIEditorVimFormatFn)(UIElement*
  el, size_t first, size_t last, char** out, size_t* len, void* user)`. The host writes the new text
  of lines `first` to `last`, malloc'd, into `*out` and its length into `*len`. That text runs from
  the first line's start to the last line's end, without its line break, with the text's own line
  breaks between lines. The vim mode frees it. It is vim's `formatexpr`, and it is asked:
  - **by `gq`**, an operator over any motion or text object: `gqq`, `gqj`, `gqap`, and `gq` in
    visual mode. The new text replaces the lines as one step of undo and one `.`, and the caret ends
    on the last new line's first character that is not a blank, where vim's own `gq` leaves it.
  - **A host that returns false leaves the lines**, and the caret where the operator started.
- **With no indent hook, `=` does nothing and is not kept for `.`**, and a new line copies its indent
  as today. **With no format hook, `gq` does nothing, likewise.** cetra has no indent rule and no
  formatter of its own for any language, so it does not guess one: vim's C indenting and its
  `textwidth` wrapping are not imitated.
- **On a read-only text, `=` and `gq` are refused as `>` is**: reported as made and kept for `.`,
  with the carets at the operator's start (14.7). The hooks are not asked.
- `ui_editor_vim_keys` lists `=`, `==`, `gq` and `gqq`. `gw` stays out (above).

### 5. The canvas app

- **`--split-share F`**: F8's split gives its first side `UI_SHARE` F and its second GROW, so a
  share can be watched and resized with the window.
- **`--vim-lookup`**, with `--vim`: a lookup hook that says on the vim line what it was asked and
  the word at the caret ("gd memory-bank"), and returns true. Without it, no hook is set, and `gd`
  is vim's own.
- **`--vim-layout`**, with `--vim`: an indent hook (two spaces for every bracket still open at the
  line's start, its S-expressions' shape) and a format hook (the lines' words joined on one line, at
  that indent).
- **`--idle-wake`** takes `+` within an item for times asked in one frame: `--idle-wake 0.6+0.2`
  asks both on the first frame.

### 6. What pcb does with this, in its own spec (6.1.2), not this one

- `gd` and Ctrl+] through the lookup hook, so its peek at the vim mode's half-typed keys goes; `K`
  says what pcb knows of a name.
- `=` and new lines indent by pcb's reader; `gq` lays lines out as `pcb fmt` does, which needs
  `pcb fmt` to work on part of a file.
- Its splits are a side at `UI_SHARE` and a side GROW; `size_under` and its two calls go.
- Its three timed wakes are asked once.

### Phase 1: every timed wake

As designed (987b1233), with one addition:
- **The list**, `EngineWake.wakes`, held sorted with one slot spare. A new time goes in its place;
  if the time held after it is within a millisecond, the new one is that one, and otherwise, if the
  time before it is within a millisecond, that one moves to the new. Held times are therefore more
  than a millisecond apart, and the new one meets at most one neighbour. A 65th time is merged the
  same way, into the next held or with the latest moved to it, and warned about once a run.
- **Added: passed times are dropped at the end of every frame's events, with idle mode or
  without.** Without idle mode `_engine_frame_events` used to return before the clearing, which was
  harmless with one slot, since a later time was ignored. The UI's caret asks for its next blink
  every frame in every app with a text field, so a list never emptied would have filled in about
  half a minute and said so.
- **`--idle-wake`** reads its argument with `strtod`, an item per comma and its times joined by `+`,
  each item's times asked on one frame. It holds 128. Under `--idle` the app also prints each
  frame's wall clock (`canvas idle at N T`), which the arm reads.
- **`idle-wakes-kept`**, in the `idle` group. Measured: `0.6+0.2` drew frames at 0.201 and 0.600 s
  after the ask, and ended; `0.3+0.3005` drew one, at 0.3013 s; 65 times (0.02 to 0.65 s by
  hundredths, then 1 s) warned once and drew their last frame at 1.001 s, 62 frames in all, a few
  times landing in one frame. Not run on master: by the code it replaced, which kept the soonest
  time, the first case ends after its 0.2 s frame, the second draws at 0.3 s, and the third ends
  at 0.02 s.
- `_idle_run` reads the app's log as well as its output, through `_canvas_shot(log=True)`, to count
  the warning.

The `idle` group passes, all 13 arms, and `gate-docs`.
