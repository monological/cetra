# cetra 14.40: text that reads from either side

## Context

pcb 8.2.1 turns a pane's board layout over, to see the board from below, by setting
`CanvasView.mirror_x` (spec 14.0's "seen from the other side, as a board from below"). The
geometry is right: the board is mirrored left to right about the view's middle. Its text is not:
every string -- a part's path, a pad's number and net, a via's or a track's net, a measurement --
reads backwards, because a glyph is placed in the canvas's units and the view mirrors it with
everything else.

pcb got text to read by making every string a second time with `CanvasText.mirrored` toggled, onto
twin layers that a view seen from below shows in place of the originals (pcb's
`specs/8.2.1-the-layout-flipped-and-the-mat-numbered.md`, phase 2). It works, and six reviews of
that branch on 2026-11-17 found what it costs:
- **The time**: making the second set costs the evaluation thread about 1.4 ms and `canvas_apply`
  on the main thread about 3.8 ms (6.6 to 10.5 ms) on a 118-part board, every evaluation while any
  pane is flipped. So pcb makes it only then, and the first flip waits on an evaluation with no
  labels shown.
- **Two bugs** where the second set is missing: a version compared and blinked before the first
  flip keeps a canvas with none; a flip while the design has errors gets none until it evaluates
  clean.
- **Layers**: 34 more of the canvas's 256, so a window fits about 15 layout panes, not 27.
- **The machinery**: twin layers, a three-valued "which ways the text is made" carried into the
  evaluation, a flag of what the canvas holds, the twins' order kept beside their originals'.

All of it stands in for one fact the canvas already knows at draw time: whether the view is
mirrored. Three of the reviews independently proposed moving it into cetra, and the user chose
that on 2026-11-17, to be implemented in a session of its own.

Branch and spec: `14.40-text-that-reads-from-either-side`, off cetra's master (`799d86c6`).

## What exists (explored)

- **A glyph's mirror is a flip in its own frame, about its anchor, before its turn**:
  `cetra/shaders/canvas_vert.glsl:243-247` -- `local` the glyph's corner in pixels from the
  anchor, `if ((flags & CANVAS_FLAG_MIRROR) != 0u) local.x = -local.x;`, then turned by `aF.w`.
- **The view's mirror is applied after, to the whole picture**: `canvas_paint.glsl:30`,
  `pos.x *= uMirror`, `uMirror` -1 for a `mirror_x` view (`canvas.c:1099`, `_view_uniforms`, set on
  both canvas programs).
- So a glyph flagged mirrored, drawn in a mirrored view, is the unflagged glyph turned by the
  negated angle: it reads the right way round, along its line as that view shows it, aligned to its
  anchor as before. pcb's renders confirmed it (a half turn added on top read upside down).
- **The flags** (`cetra/shaders/include/canvas_constants.glsl`, shared with C): 3, 4, 8, 16
  (`CANVAS_FLAG_MIRROR`), 32 and 64 are taken; a record's flags are 10 bits (`canvas_record.h`,
  `canvas_record_head`), so 128 is free.
- **A text's bound** (`cetra/src/canvas_edit.c`, `canvas_edit_text`, about line 1166): the ink's
  four corners, mirrored by the text's own `mirrored`, turned about the anchor; every glyph takes
  the whole string's bound, which tile culling reads.
- **The canvas app** (`apps/canvas`) has `--mirror` and the mirror twin gate (spec 14.0's
  `canvas-mirror`, within a code: a mirrored triangle's varyings round a few pixels the other way).

## The design

- **A text that reads from either side**: a new `CanvasText` field,
  `bool reads_either_side; // in a view seen from the other side, flipped back so it still reads`.
  Its glyphs are flipped across the anchor's line when `mirrored` XOR (`reads_either_side` and the
  view is `mirror_x`). In a view not mirrored it changes nothing; in a mirrored view it draws
  exactly what the same text with `mirrored` toggled draws today, so a string reads the right way
  round, along its line as that view shows it.
- **Carried as a flag**: `CANVAS_FLAG_EITHER_SIDE` (128), set by
  `canvas_edit_text` beside `CANVAS_FLAG_MIRROR`; in `canvas_vert.glsl`'s glyph branch the flip is
  `mirror != (either_side && uMirror < 0.0)`. One program, no variant.
- **Its bound covers both**: with the flag set, `canvas_edit_text` takes its bound over the ink
  mirrored and not, since the view decides at draw time; so a string near a tile's edge is drawn in
  a mirrored view as in a plain one.
- **Nothing else moves**: `canvas_text_width` measures as before (a mirror changes no width); a
  string without the field reads as now in every view, so every existing golden and gate holds
  byte for byte. Picking stays the app's (roadmap item 1, "Not cetra's").
- **Rejected**: a per-view setting (`CanvasView.text_reads`, mirroring every string), which would
  also turn over text meant to mirror with the board, such as a bottom side's printing drawn as
  font text; a per-layer one, which is the per-text flag with less reach. The per-text flag says
  what the text is, and the view says how it is seen.

## Phases

Each records "As built" in this file and commits it; verification is scoped to what the phase can
reach (`AGENTS.md`, Verifying).

0. **The spec**, this file, committed alone; `docs/eda-roadmap.md` item 1 says 14.40 is started.
1. **The flag**: the field, the flag bit, the shader's XOR, the bound over both mirrorings;
   `canvas.h`'s comment on the field; `apps/canvas` given a string with the field set (a sheet's
   label, or a `--either-side` switch), so a mirrored run shows it reading.
2. **The gates**: in the canvas group, twins at 0 px (geometry identical, no varyings reordered):
   - a view not mirrored: a text with the field against the same text without it;
   - a mirrored view: a text with the field against the same text with `mirrored` toggled and no
     field;
   - the bound: a flagged string placed past a tile's edge, in a mirrored view, drawn whole.
   Falsified: the shader's XOR dropped fails the second twin; the bound taken one way alone fails
   the third. Run with `scripts/gates.py --arms` naming the canvas arms the change reaches.
3. **The look**: `apps/canvas` run mirrored and not, side by side, its labels reading in both;
   shown to the user.
4. **The docs**: `docs/canvas.md` (text: the field, what a mirrored view does with it);
   `docs/eda-roadmap.md` item 1 (built, and what pcb does with it); `CHANGELOG.md`.
5. **The reviews**: code-quality reviews as background agents at effort high, applied once all
   are back; the canvas group whole; goldens.

**Then**, with the user's say-so, master fast-forwards and pcb bumps `extern/cetra` to it.

## What pcb does with it (pcb's, not this spec's)

On the bump, pcb 8.2.1 sets `reads_either_side` on its part paths, copper labels and marks, and
deletes the second set: `names_mirrored`, `labels_mirrored`, `LayoutReads`, `TextLayers` and its
helpers, `layout_text_seen`, `Marks.mirrored`, the job's `layout_reads`, `layout_take`'s
`both_ways`, the evaluation the first flip asks for, the twins' place in `view_shown` and
`stack_seen`, and the probe's "text made both ways". The two bugs above go with it.

## Not in this spec

A view mirrored top to bottom (`mirror_y`); text in the 3D scene; a string's glyphs reordered for
right-to-left scripts.

## Verification

- `./build.sh`, no warnings; the canvas group's arms the change reaches, named; the new twins at
  0 px; every existing canvas golden unchanged.
- `apps/canvas` run mirrored, headless and in a window, its flagged text reading.
