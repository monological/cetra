# cetra 14.40: text that reads from either side

## Context

pcb 8.2.1 turns a pane's board layout over, to see the board from below, by setting
`CanvasView.mirror_x` (spec 14.0's "seen from the other side, as a board from below"). The
geometry is right: the board is mirrored left to right about the view's middle. Its text is not:
every string -- a part's path, a pad's number and net, a via's or a track's net, a measurement --
reads backwards, because a glyph is placed in the canvas's units and the view mirrors it with
everything else.

pcb got text to read by making every string a second time with `CanvasText.mirrored` toggled, onto
twin layers that a view seen from below shows in place of the originals (pcb's
`specs/8.2.1-the-layout-flipped-and-the-mat-numbered.md`, phase 2). It works, and six reviews of
that branch on 2026-11-17 found what it costs:
- **The time**: making the second set costs the evaluation thread about 1.4 ms and `canvas_apply`
  on the main thread about 3.8 ms (6.6 to 10.5 ms) on a 118-part board, every evaluation while any
  pane is flipped. So pcb makes it only then, and the first flip waits on an evaluation with no
  labels shown.
- **Two bugs** where the second set is missing: a version compared and blinked before the first
  flip keeps a canvas with none; a flip while the design has errors gets none until it evaluates
  clean.
- **Layers**: 34 more of the canvas's 256, so a window fits about 15 layout panes, not 27.
- **The machinery**: twin layers, a three-valued "which ways the text is made" carried into the
  evaluation, a flag of what the canvas holds, the twins' order kept beside their originals'.

All of it stands in for one fact the canvas already knows at draw time: whether the view is
mirrored. Three of the reviews independently proposed moving it into cetra, and the user chose
that on 2026-11-17, to be implemented in a session of its own.

Branch and spec: `14.40-text-that-reads-from-either-side`, off cetra's master (`799d86c6`).

## What exists (explored)

- **A glyph's mirror is a flip in its own frame, about its anchor, before its turn**:
  `cetra/shaders/canvas_vert.glsl:243-247` -- `local` the glyph's corner in pixels from the
  anchor, `if ((flags & CANVAS_FLAG_MIRROR) != 0u) local.x = -local.x;`, then turned by `aF.w`.
- **The view's mirror is applied after, to the whole picture**: `canvas_paint.glsl:30`,
  `pos.x *= uMirror`, `uMirror` -1 for a `mirror_x` view (`canvas.c:1099`, `_view_uniforms`, set on
  both canvas programs).
- So a glyph flagged mirrored, drawn in a mirrored view, is the unflagged glyph turned by the
  negated angle: it reads the right way round, along its line as that view shows it, aligned to its
  anchor as before. pcb's renders confirmed it (a half turn added on top read upside down).
- **The flags** (`cetra/shaders/include/canvas_constants.glsl`, shared with C): 3, 4, 8, 16
  (`CANVAS_FLAG_MIRROR`), 32 and 64 are taken; a record's flags are 10 bits (`canvas_record.h`,
  `canvas_record_head`), so 128 is free.
- **A text's bound** (`cetra/src/canvas_edit.c`, `canvas_edit_text`, about line 1166): the ink's
  four corners, mirrored by the text's own `mirrored`, turned about the anchor; every glyph takes
  the whole string's bound, which tile culling reads.
- **The canvas app** (`apps/canvas`) has `--mirror` and the mirror twin gate (spec 14.0's
  `canvas-mirror`, within a code: a mirrored triangle's varyings round a few pixels the other way).

## The design

- **A text that reads from either side**: a new `CanvasText` field,
  `bool reads_either_side; // in a view seen from the other side, flipped back so it still reads`.
  Its glyphs are flipped across the anchor's line when `mirrored` XOR (`reads_either_side` and the
  view is `mirror_x`). In a view not mirrored it changes nothing; in a mirrored view it draws
  exactly what the same text with `mirrored` toggled draws today, so a string reads the right way
  round, along its line as that view shows it.
- **Carried as a flag**: `CANVAS_FLAG_EITHER_SIDE` (128), set by
  `canvas_edit_text` beside `CANVAS_FLAG_MIRROR`; in `canvas_vert.glsl`'s glyph branch the flip is
  `mirror != (either_side && uMirror < 0.0)`. One program, no variant.
- **Its bound covers both**: with the flag set, `canvas_edit_text` takes its bound over the ink
  mirrored and not, since the view decides at draw time; so a string near a tile's edge is drawn in
  a mirrored view as in a plain one.
- **Nothing else moves**: `canvas_text_width` measures as before (a mirror changes no width); a
  string without the field reads as now in every view, so every existing golden and gate holds
  byte for byte. Picking stays the app's (roadmap item 1, "Not cetra's").
- **Rejected**: a per-view setting (`CanvasView.text_reads`, mirroring every string), which would
  also turn over text meant to mirror with the board, such as a bottom side's printing drawn as
  font text; a per-layer one, which is the per-text flag with less reach. The per-text flag says
  what the text is, and the view says how it is seen.

## Phases

Each records "As built" in this file and commits it; verification is scoped to what the phase can
reach (`AGENTS.md`, Verifying).

0. **The spec**, this file, committed alone; `docs/eda-roadmap.md` item 1 says 14.40 is started.
1. **The flag**: the field, the flag bit, the shader's XOR, the bound over both mirrorings;
   `canvas.h`'s comment on the field; `apps/canvas` given a string with the field set (a sheet's
   label, or a `--either-side` switch), so a mirrored run shows it reading.
2. **The gates**: in the canvas group, twins at 0 px (geometry identical, no varyings reordered):
   - a view not mirrored: a text with the field against the same text without it;
   - a mirrored view: a text with the field against the same text with `mirrored` toggled and no
     field;
   - the bound: a flagged string placed past a tile's edge, in a mirrored view, drawn whole.
   Falsified: the shader's XOR dropped fails the second twin; the bound taken one way alone fails
   the third. Run with `scripts/gates.py --arms` naming the canvas arms the change reaches.
3. **The look**: `apps/canvas` run mirrored and not, side by side, its labels reading in both;
   shown to the user.
4. **The docs**: `docs/canvas.md` (text: the field, what a mirrored view does with it);
   `docs/eda-roadmap.md` item 1 (built, and what pcb does with it); `CHANGELOG.md`.
5. **The reviews**: code-quality reviews as background agents at effort high, applied once all
   are back; the canvas group whole; goldens.

**Then**, with the user's say-so, master fast-forwards and pcb bumps `extern/cetra` to it.

## What pcb does with it (pcb's, not this spec's)

On the bump, pcb 8.2.1 sets `reads_either_side` on its part paths, copper labels and marks, and
deletes the second set: `names_mirrored`, `labels_mirrored`, `LayoutReads`, `TextLayers` and its
helpers, `layout_text_seen`, `Marks.mirrored`, the job's `layout_reads`, `layout_take`'s
`both_ways`, the evaluation the first flip asks for, the twins' place in `view_shown` and
`stack_seen`, and the probe's "text made both ways". The two bugs above go with it.

## Not in this spec

A view mirrored top to bottom (`mirror_y`); text in the 3D scene; a string's glyphs reordered for
right-to-left scripts.

## Verification

- `./build.sh`, no warnings; the canvas group's arms the change reaches, named; the new twins at
  0 px; every existing canvas golden unchanged.
- `apps/canvas` run mirrored, headless and in a window, its flagged text reading.

## As built

### Phase 0: the spec

- `14.40-text-that-reads-from-either-side` branched from master at `799d86c6`; this spec
  committed alone (`8cd1eec0`).
- `docs/eda-roadmap.md`: item 1 says text that reads from either side is started in 14.40, its row
  names the spec.

### Phase 1: the flag

- `CanvasText.reads_either_side` (`canvas.h`), after `mirrored`, with the spec's one-line contract.
- `CANVAS_FLAG_EITHER_SIDE` 128 in `canvas_constants.glsl`, the flag block's comments realigned to
  the longer name; `canvas_record.h`'s glyph row names it.
- `canvas_vert.glsl`'s glyph branch: `flipBack` is the flag and `uMirror < 0.0`, and the glyph is
  flipped when its mirror flag differs from it. The negation is the same expression as before, so
  a string without the field takes the branch it took.
- `canvas_edit_text`: the flag beside `CANVAS_FLAG_MIRROR`; for a flagged text the ink's x range
  in its own frame is widened to its mirror image (`lo = min(lo, -hi)`, `hi = max(hi, -lo)`)
  before the four corners are mirrored and turned. A box's corners are each a corner of one of the
  two mirrorings' boxes, so this is exactly the union of the two bounds, with no second loop.
- `apps/canvas`: `--either-side` sets the field on every string a sheet makes. Every sheet's
  `canvas_edit_text` call goes through one helper, `edit_text`, which applies it (a mechanical
  rename of 18 calls; clang-format realigned their continuation lines).
- Looked at: the symbol sheet mirrored, with and without `--either-side`. Every string reads with
  it. What the spec chose shows on this sheet: a string flagged and drawn mirrored is the string
  with `mirrored` toggled, so a left- or right-aligned string lies on the other side of its anchor
  from where it lies in a plain view. The pin names, aligned to the box's inside edge, cross the
  pins, and the top pins' names run up out of the box. Centred strings, which is pcb's pad
  numbers, nets and part paths, are unaffected. Kept as the spec says, for phase 3's look.
- Ran: `./build.sh`, no new warnings; the symbol sheet plain against plain with `--either-side`,
  0 px; the canvas arms that draw text (`canvas-mirror`, `canvas-glyph-edge`, `canvas-text-width`,
  `canvas-kern-pairs`, `canvas-atlas-fields`, `canvas-text-band`, `canvas-tags`, `canvas-fade`,
  `canvas-split`, `canvas-dash-twins`), all PASS.

### Phase 2: the gates

- `apps/canvas`: `--flip-text` toggles every string's `mirrored`, through the same helper, so a
  mirrored view of a sheet under it is what that view draws under `--either-side`. A new sheet,
  `margin` (8 mm across, black): one string, "Past the edge", anchored 0.3 mm past the view's
  right edge, read off the view the sheet is built for, and alone in its tile. Its ink runs on
  past the edge, so a plain view draws none of it; a mirrored view under `--either-side` flips it
  back across its anchor, onto the view. The 0.3 mm (30 px in the gate) clears the culling's own
  margin of a few pixels.
- Three arms in the canvas group, named `canvas-reads-*` to fit the group's verdict column
  (`--arms canvas-reads` chooses them), each documented in the group's docstring:
  - `canvas-reads-plain`: the symbol sheet under `--either-side` against it plain, 0 px.
  - `canvas-reads-mirror`: the symbol sheet mirrored under `--either-side` against it mirrored
    under `--flip-text`, 0 px, and against it mirrored as it is, which must differ (28,588 px),
    or a flag that flipped nothing would pass.
  - `canvas-reads-bound`: the margin sheet under `--either-side`: plain, no ink; mirrored, 19,105
    px of ink and 0 px from the margin mirrored under `--flip-text`.
- A run a sheet takes under switches is one cached `switched_run`, named by its switches, which
  the three share.
- Falsified with the work committed (`8c661e56`): the shader's XOR dropped (the flip on
  `CANVAS_FLAG_MIRROR` alone) fails `canvas-reads-mirror` (28,588 px from the toggled twin, 0 from
  the plain mirror) and `canvas-reads-bound` (no ink: drawn unflipped, off the view); the bound
  taken one way alone fails `canvas-reads-bound` alone (no ink, 19,105 px from the twin: the
  mirrored view culled the tile). Each restored, rebuilt, all three PASS.
- `gate-docs` (its three arms) PASS.

### Phase 3: the look

- Run: `apps/canvas --sheet symbol --split`, the left view plain and the right mirrored, at
  1200x500 points, with and without `--either-side`, headless and in a window (30 frames), the
  window's picture 0 px from the headless one. The board sheet's mirrored view shows only the
  bottom layers, so none of its text is in it; the symbol sheet is the one that shows text both
  ways.
- Without the field the right half reads backwards. With it every string in both halves reads:
  the pin names and numbers, the part's name and value, "2 mm text" down to the sizes the floor
  drops, and both silk lines, each as it reads in the plain half (the mirrored silk line reads
  backwards in both, as authored).
- What it shows beside that, the spec's own rule made visible: a string flagged and seen mirrored
  is the string with `mirrored` toggled, so it reads from its anchor the way the plain view reads
  it, and a left- or right-aligned string lies on the other side of its anchor from where its
  layout put it. On this sheet the pin names, aligned to the box's inside edge, cross the pins
  and the box's edge; the top pins' names run up out of the box over their numbers; the text
  column beside the part runs into the box. A centred string stays centred on its anchor (its ink
  moves by the difference of its ends' side bearings, phase 5's correctness pass found), so pcb's
  pad numbers, nets and centred part paths are where they would be. Recorded for the user's look, with
  the one alternative the code allows: flip a flagged string about its own middle instead of its
  anchor, so it keeps the place its layout gave it, which the shader can do only if the record
  carries that middle (a long record's two spare lanes, or the anchor moved to the middle). Not
  built: the spec chose the anchor, and the user decides.
- The renders are in the session's scratchpad, `1440/split_symbol.png` (no field),
  `1440/split_symbol_either.png` (the field) and `1440/crop_pins.png` (the mirrored half's top
  right at 3x).

### After the user's look (2026-11-18)

- The user saw phase 3's render, every string on the symbol sheet flagged, as jumbled: the pin
  names across the pins, the top names over their numbers. Phase 3 had written that up as the
  spec's choice and gone on; it was a defect of the look, and the limit it shows is real. The
  anchor rule draws pcb's text right: its part paths, copper labels and measures are centred, and
  its one aligned mark, a pour's name, is placed per view and relies on the anchor. So the rule
  stays, and the user chose to say what it suits:
  - `canvas.h`'s `CanvasText` comment and `docs/canvas.md` (9): it suits centred text; an aligned
    string lies on the anchor's other side in a mirrored view, and one aligned to an edge crosses
    it.
  - `apps/canvas`: `--either-side all|centred`. `all` flags every string, as the gates need, the
    margin sheet's aligned strings included; `centred` flags only centred strings, as pcb flags
    its text. The gates pass `all`, the same numbers as before.
- The look again, `--sheet symbol --split --either-side centred`: in the mirrored half the pin
  numbers and the part's value read, each in its place by its pin; the names, "U1" and the text
  column stay mirrored with the board; nothing overlaps (`1440/split_symbol_centred.png`, the top
  at 3x in `1440/crop_centred.png`).
