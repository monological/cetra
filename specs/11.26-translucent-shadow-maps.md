# 11.26 — Translucent shadow maps (deep opacity maps)

Roadmap item **C1** (Tier 4, `docs/aaa-rendering-roadmap.md`).

## Context

Hair casts **no shadow at all** and glass casts a **solid black** one.

`shadow.c:485-489` skips every `ALPHA_MASK` material unless it opts back in via `foliage_shadows`
(one caller in the whole repo: `apps/tree/src/tree.c:1548`). `ALPHA_BLEND` and `transmission > 0`
are never tested, so they rasterise opaque depth like rock. Measured, not argued — a 100%
transmissive sphere over the studio HDR:

| floor sample | shadows on | shadows off |
|---|---|---|
| under the sphere | 141.0 | 176.3 |
| beside it | 149.8 | 149.8 |

**A fully transparent object deletes 20% of the floor's radiance — the entire analytic key-light
contribution — in a hard-edged ellipse.**

This is roadmap item C1, and it is a feature, not only a repair: per-texel transmittance in the
shadow map is how hair, foliage, curtains and glass are shadowed in a modern engine (deep opacity
maps, Fourier opacity maps). The intended outcome is that a translucent caster attenuates light in
proportion to what it actually blocks.

**Target: transmittance storage, no moment reconstruction** — Yuksel & Keyser's deep opacity maps.
The four-moment path is a separately-scheduled follow-up, for reasons in "Deliberately deferred".

## What exploration established (all verified against the code)

- **The sampler wall does not block this.** `pbr_frag` is 16/16 and the driver counts
  declarations. But unit 10 *already* binds one of two textures — `msm_on ? msm_array :
  shadow_map_array` (`shadow.c:396-400`) — so there are two independent homes for transmittance
  that never coexist. This plan uses the depth-array home, which keeps PCF/PCSS intact.
- **`DEPTH_COMPONENT24` is the right storage.** It is a 24-bit UNORM scalar — better for a
  transmittance in [0,1] than the moment array's fp16 — and the depth array's existing
  `CLAMP_TO_BORDER` **white** border already means "nothing occludes here", so storing `exp(-b0)`
  makes 1.0 the correct out-of-footprint default with no bounds check.
- **Store transmittance, not absorbance, and filtering is exact.** Transmittance averages
  linearly; absorbance does not. `exp(-b0)` in the layer means a box filter has *zero* Jensen
  bias — the hazard 11.17 recorded (0.368 reconstructed where truth is 0.568) applies only to
  filtering absorbance moments, and this design never does.
- **Opaque casters must never enter the transmittance map.** The Jensen error is `≈A²/8`,
  quadratic in absorbance, and opaque is the maximum-absorbance case: an opaque silhouette edge
  reconstructs 0.010 where truth is 0.500. So opaque occlusion and translucent transmittance stay
  separate and combine **multiplicatively** — the caster sets are disjoint by construction.
- **The fog is untouched.** Appended layers sit above every index `postfx_build_fog_esm` and
  `froxel_inject_frag` reach, so `shadow.h:190-195`'s never-repoint invariant holds unmodified.
- **The receive-side exclusion is correct and stays.** Letting hair read the cascades was measured:
  195,821 px of hard-edged, card-boundary-shaped patches across the groom. `pbr_frag.glsl:1519`
  and `:1526` do not change. **This plan makes hair cast onto shoulders; it does not make hair
  shadow itself.**
- **The asset can show it.** raiden's hair atlas is 36.6% alpha-0, 19% alpha-1, mean alpha 43.1% —
  a real continuous gradient. (A binary cutoff test gets the *average* right on this atlas by
  luck, 44.0% vs 43.1%, and the *distribution* wrong.)
- **Nothing in the corpus can currently see any of this.** Zero `ALPHA_MASK` materials in
  `assets/`. `oit_sphere_fixture` and `abandoned_window` both measure **0 px vs `--no-shadows`**
  (no shadow-casting light). And `catcher-tr` is blind by **geometry**, not tolerance — its four
  samples sit a world unit outside the panel's cast band, three returning the identical linear
  triple. Nothing to retune; a fixture must be authored.

## Design

**Storage** — `shadow_map_array` grows past the cascade block, at a fixed base so the index law
never moves when a light starts or stops casting (grow-only, mirroring `allocated_cascades`):

```
TSM_BASE = MAX_SHADOW_LIGHTS * cascade_count
tsmLayer(slot, c, part) = TSM_BASE + ((slot*cc + c) * 2) + part
  part 0 = transmittance exp(-b0)          24-bit UNORM
  part 1 = nearest translucent depth       (the front layer)
```

VRAM: **+112 MB at one sun** (6 layers × 16 MiB + one 16 MiB R32F scratch), +304 MB at three.
Opt-in; nothing allocated when off.

**Capture** — a separate accumulation pass over translucent casters only, mirroring
`engine_begin_moment_pass` (`engine.c:1976-1998`): additive `GL_ONE/GL_ONE` absorbance into a
reusable `GL_R32F` 2048² scratch, then one fullscreen resolve writing `gl_FragDepth = exp(-b0)`
into part 0. `begin_depth_layer` (`shadow.c:83-97`) already does everything that write needs.

Not a colour attachment on the existing depth pass: that pass is colour-less by construction
(`glDrawBuffer(GL_NONE)` in the shared allocator), its `glPolygonOffset(2,2)` must not apply to
translucent casters, and keeping it untouched is what makes the off path *the path that was there*
rather than a rebuild of it.

**Part 1 needs no new shader** — the existing `shadow_depth` program and `draw_shadow_layer` with
the inverted mesh predicate; the hardware depth test min-blends for free. Without it every receiver
is treated as behind every translucent caster (a shoulder in front of strands gets wrongly
darkened), so it is not optional.

**Routing** (`shadow.c:485-489`), gated so the off path is character-identical:

| material | today | flag on |
|---|---|---|
| `ALPHA_MASK`, no `foliage_shadows` (hair) | excluded entirely | → accumulation pass |
| `ALPHA_MASK` + `foliage_shadows` (leaves) | alpha-tested depth | **unchanged** — keeps the depth path |
| `ALPHA_BLEND` (glass, curtains) | opaque depth → black shadow | → accumulation pass |
| `transmission > 0` | opaque depth | → accumulation pass |

Foliage deliberately stays on the depth path: `apps/tree` is the only A2C content in the repo, and
moving it would move a baseline for no defect.

**Sampling** — inside `cascadeShadowTap` (`pbr_frag.glsl:611-701`), before the existing cascade
`min()`:

```glsl
if (tsmEnabled != 0)
    visibility *= csmTransmittance(layer, projCoords.xy, projCoords.z);
```

Product, because the two caster sets are disjoint — independent attenuations of the same ray. The
return stays a **scalar float**, so all three consumption sites are unchanged;
`csmOutermostOcclusion` (`csm.glsl:82-107`) takes one line and both the catcher and particles
follow from that one text.

**The drift firewall.** The absorbance must describe the same opacity the shading pass computes.
11.17 solved this by making moment generation a *mode* of `pbr_frag` ("a mode cannot drift"); that
escape is unavailable here (different vertex layout, no G-buffer, no cluster UBOs). So the coverage
chain at `pbr_frag.glsl:993-1001` moves into a shared include that both `pbr_frag` and
`shadow_absorb_frag` use. Without it, a change to the opacity chain silently desynchronises the
shadow from the surface and nothing fails. The vertex side must evaluate `skin.glsl` and
`wind.glsl` identically to `shadow_depth_vert.glsl:16-27` for the same reason.

## Verification

**The apparatus does not exist and is half the work.** `assets/gen_translucent_shadow_fixture.py`
following `gen_oit_cards_fixture.py`'s discipline: alpha authored as `baseColorFactor[3]` with no
base-colour texture so every prediction is closed form, and a **generated** `.cscn` whose camera is
derived from geometry (`_cscn_camera` reads it back).

The trick that makes it analytic is the OIT card stack's, transposed: transmittance through N
layers is `∏(1 − aₖ)` — order-independent, so the gate constrains the *answer*, not the storage.

One scene, six disjoint ground regions: a 4-panel BLEND staircase with nested x-extents
(`T = 0.65^k`), a MASK panel with a linear alpha ramp (`T(x) = 1 − α(x)`), a red BLEND panel, an
opaque block, and a bare acne strip. Sun at elevation 75°, azimuth 180 so the caster is never on a
sight line to its own shadow.

Arms, each stating what break it catches:

| arm | asserts | catches |
|---|---|---|
| `tsl-stack` | `\|T_k − 0.65^k\| ≤ 0.02` | no shadow, solid, nearest-only, additive alpha, alpha-squared |
| `tsl-ratio` | `T_{k+1}/T_k` within 0.03 of 0.65, **no reference frame** | the same models through a differently-conditioned path — immune to tonemap-inversion or exposure error, so it cannot fail for the same instrument reason as `tsl-stack` |
| `tsl-partial` | `0.50 ≤ T₁ ≤ 0.80` | both degenerate answers in one arm |
| `tsl-mask-ramp` | RMS vs `1 − α(x)` ≤ 0.03 | hair still skipped (RMS 0.29), solid (0.58), **a binary alpha test (0.29)** |
| `tsl-ramp-discrim` | ramp residual ≥ 4× better than the best binary step | the fixture losing its gradient — `tsl-mask-ramp` otherwise scores its best mark on a broken fixture |
| `tsl-speckle` | sd along a constant-α line ≤ 3× the bare-ground floor | **a stochastic/screen-door alpha test** — three lines, correct in expectation, invisible to every mean-based arm |
| `tsl-churn` | TAA churn vs floor | the same scheme reseeded per frame, which `tsl-speckle` passes if the seed is frozen |
| `tsl-opaque` | opaque umbra ≤ 0.02, **same frame** | transmittance leaking onto opaque casters |
| `tsl-acne` | bare strip `\|T − 1\| ≤ 0.05` | a target never cleared — the failure `tsl-ratio` is blind to, since a global factor cancels in a ratio |
| `tsl-cc1` / `tsl-cascade-seam` | stack under `--shadow-cascades 1`; within-band near vs far across a split | a layer indexed without the `slot*cc + c` stride, and per-cascade seams every interior arm averages away |

**The inverse arm**, and the reason `--no-translucent-shadows` is not optional: `run_translucent_offpath_gate`
asserts **exactly 0 px** between default and the flag on three all-opaque fixtures, *and* **≥ 50,000 px**
on the new one. Three zeros are also what a dead flag, an unparsed argument or a failed allocation
produce — this is 11.22's `DIR_PILLAR_BLUR_MIN` lesson, where all six MSM arms passed silently
because a bailed frame *is* the off case.

**A new reader is required.** `_term_reader` uses `_linear_luma` and does **not** invert Khronos
Neutral — measured 0.2559 where exact inversion gives 0.3334, **23% low**. Its existing arms are
immune (bounds at ~0, ~1, and 50% crossings); an assertion of the form `T = (1−a)^k` is not. Use
`_oit_untonemap`'s closed form, keep samples below Neutral's 0.76 knee, and assert that.

**One golden** (`translucent_shadow`, added to `goldens.py:RECIPES`). Every arm samples a line and
erodes band edges by construction; the failures a scalar cannot see are two-dimensional — acne in
the transmittance target, dither patterning, a silhouette losing its shape.

**`catcher-tr` is a falsification test, not a retune.** Predict in the spec that it reports
`0.1273 / 0.1575 / 0.0000` digit for digit, and record why (samples at z≈1.58; the panel's cast
band is `x ∈ [0.2, 3.45], z ∈ [0, 0.46]`). If those move, the change touched the transparent pass
or the catcher's depth, which it must not.

**The raiden baseline will move, and it is a behaviour change, not sensitivity** — one MASK
material starts casting, three BLEND materials stop casting solid. `AGENTS.md` gains a fourth
entry naming `--no-translucent-shadows` as the escape, alongside `--no-oit` / `--no-oit-moments` /
`--no-dither`.

## Deliberately deferred

- **The four-moment reconstruction** (gradation *inside* the volume rather than a hard front-layer
  cut). It pairs MSM's linear warp with MBOIT's reconstruction — **a configuration in neither
  paper** — with bias constants 60× apart and an overestimation term whose principled value changes
  when the receiver is not one of the accumulated layers; and 11.17 recorded that the reconstruction
  is ill-conditioned where layers coincide, *"which is what hair is"*. Schedule after looking at
  this. If the `tsl-between` residual is small on real content, recording it as a measured
  rejection is a legitimate outcome.
- **Hair receiving** its own shadow — measured to produce card-shaped streaks; wants its own item.
- **The punctual path** (unit 15) — no MSM branch at all, and adding 2 layers per light collapses
  every punctual map to the 1024 floor against its 96 MB budget. 11.22 scoped it out too.
- **Coloured transmittance** — would break the scalar contract at all three sites.

## As built

Shipped to the design: transmittance storage in appended depth-array layers, opt-in behind
`--translucent-shadows`, no moment reconstruction. **Effort was L, not the M the roadmap
priced.**

Two departures from the plan, both found in review rather than in building:

- **The plan's eleven arms are eleven, but two of them asserted nothing** as first written.
  `tsl-opaque` took its black point from the same sample it then tested, so it evaluated
  `(black - black) <= 0.02` -- true for every possible renderer, including one that floods
  every umbra with light. The zero is 0 by construction (one directional light, no
  environment) and is now written as such. `tsl-mono` checked only a channel spread, which is
  0 on bare ground and 0 in a full umbra alike, so it passed if its sample walked off the
  panel; it now pins the level too. `tsl-acne` was not dead but was redundant, restating
  `tsl-stack`'s band 0 at a looser bound.
- **The fixture camera was wrong for the arms it served.** Two sample points sat outside the
  frame -- the opaque umbra at px 809 of 800, the ramp's left end 9 px past the edge -- and the
  reader clamped instead of raising, so both silently read the picture's border. The camera
  moved to `(0,6,10)` at 38 degrees, every sampled point now clears by >= 1.5 world units, the
  reader raises, and the generator's self-guard gained the x half it never had (`ASPECT` was
  declared and unused). The golden was re-baked for the new framing.

### What it measures

`assets/translucent_shadow_fixture` against the analytic answer, all in one render:

| claim | measured | predicted | bound |
|---|---|---|---|
| staircase bands | 1.000 / 0.650 / 0.421 / 0.273 / 0.179 | 0.65^k | worst err **0.0016** (0.02) |
| the same, as ratios, with no reference frame | 0.650 / 0.648 / 0.648 / 0.656 | 0.65 | worst **0.0063** (0.03) |
| mask ramp | RMS **0.0030** against `1 - alpha(x)` | — | 0.03 |
| ... and a binary alpha test would score | 0.3153 | — | **105x worse** |
| opaque umbra, same frame | 0.0000 | 0 | 0.02 |
| bare ground, same frame | 0.0000 max err | 1 | 0.05 |
| red panel, all three channels | 0.4976 at spread 0.0000 | 0.5 | 0.02 |

Off-path: **0 px on `cornell_point`, `dir_shadow_fixture` and `contact_fixture` with the flag
ON** — the stronger claim, since the accumulation is skipped where nothing is translucent and a
transmittance of 1 multiplies exactly. `tsl-live` fires at 76,635 px so the three zeros cannot
be a dead flag. All 20 goldens pass.

**On the gate suite: it passes, but it does not pass every time, and that is not this spec's
doing.** Six full runs across master and this branch produced a DIFFERENT failing set each time
-- `dir-hole-pcf` / `dir-pillar-pcf` / `dir-acne-40deg` on one run, `dir-pillar-pcf` /
`dir-pillar-msm` / `skin-offpath` on another, none on the next -- and two runs of one unchanged
build disagreed (`dir-pillar-pcf` at 1.2481, then 0.0000). `run_flare_gate` also crashes
intermittently with an IndexError out of `_flare_centroid`, which is the same fault wearing a
different hat. Master flakes identically, so the shadow arms are measuring something that is
not settled at the frame they read. **Filed, not fixed here**: a suite whose failing set is
drawn fresh each run cannot support the sentence "all 56 gate checks pass", and the earlier
draft of this section asserted exactly that.

The trap this walked into is worth recording, because it is the inverse of 11.22's: a single
clean run of master was read as proof that the branch had broken three gates. It was one sample
of a nondeterministic test. **The off-path arms have the matching blind spot** -- `tsl-off`
compares branch-on against branch-off and never against master, so a change that moves both
arms equally is invisible to it, and no arm in this spec would have caught a genuine regression
of that shape.

**Raiden moves 331,967 px (4.0%), PAE 33/255**, and the diff map is the groom and the shoulder
under it and nothing else — a behaviour change, not the last-bit sensitivity its three previous
moves were.

### Six bugs, three found by the arms and three by reading the code

The split is the point: the arms caught what they were pointed at, and the three below them were
all in places no arm looked. A gate finds the bug it was written to find.

### Three the arms found, all presenting as something they were not

1. **An unrestored blend FUNCTION.** The accumulation needs `GL_ONE/GL_ONE`; restoring only the
   *enable* left it installed for whatever blended next. It desaturated the entire frame while
   the shadows looked correct — 100% of `contact_fixture`'s pixels, reading exactly like an
   exposure shift. The clear colour had the same fault and was found first, which is why the
   second one took a second look: fixing a real bug that was not *the* bug.
2. **The resolve covered half the map.** `create_fullscreen_quad_vao` builds a **4-vertex
   TRIANGLE STRIP**, and the resolve drew it as `GL_TRIANGLES, 0, 3` — one triangle. `exp(-b0)`
   landed on half the map and the rest kept the cleared 1.0. The shape is why it survived three
   wrong hypotheses: the values *inside* the wedge were exact to three decimals, so any profile
   crossing it read correctly, and an iso-x line projects to a diagonal so the artifact looked
   like a gradient. The cascade theory died on `--shadow-cascades 1`, the front-layer gate died
   on disabling it, and **dumping the absorbance scratch settled it in one look** — the
   accumulation was right, so the fault was downstream.
3. **Two instrument faults that read as renderer faults.** A lit reference at the frame edge was
   vignetted, which pulled every transmittance up and made the per-layer ratio *drift with
   depth* — the exact signature of an ambient floor, which is what it was mistaken for. And the
   black point taken from the opaque block's umbra carried GTAO the canopy bands did not,
   biasing every band 2.8% high. Both fixed by rendering the fixture the way the OIT gate
   renders its own, for the same recorded reason.

### Three the arms could not have found

4. **A cull restore that halved the answer.** The accumulation pass disables culling on purpose,
   so a closed transmissive volume contributes both of its surfaces. But the traversal restored
   `GL_CULL_FACE` unconditionally after drawing any two-sided mesh, on the assumption that
   culling was on when it was entered. So the first two-sided mesh in a cascade re-enabled
   culling for every translucent mesh drawn after it, which then accumulated front faces only
   and came out at **the square root of its true transmittance** — with the affected set decided
   by scene-graph order. Invisible to every arm because the fixture's panels are single quads:
   this needs a closed volume and a two-sided mesh in one cascade, which no fixture has.
5. **The catcher and the particles lost the shadow entirely.** `csmOutermostOcclusion` reads the
   depth cascades, translucent casters are withheld from those, and nothing multiplied the
   transmittance back in. A glass panel that cast a solid shadow onto the shadow-catcher ground
   before the feature cast **none at all** after it — strictly worse than off. No arm reads the
   catcher; `catcher-tr` was predicted to be blind here and was.
6. **Turning it off kept the memory.** The toggle frees the array layers, and the comment beside
   it promises the VRAM back, but the 16 MB accumulation scratch is not part of the array and
   survived to shutdown.

Plus one duplicate: `shadow_absorb_vert.glsl` was `shadow_depth_vert.glsl` with different
comments. Its own comment argued it was "a deliberate mirror" so skinning and wind could not
drift — which is the argument against copying it. The program now compiles the depth vertex
stage directly and the copy is deleted.

### Where the plan was wrong

- **`TSM_SLOTS` is 1.** The plan implied transmittance for every directional caster; three would
  triple the largest array the renderer allocates. Slot 0 only, which matches how contact
  shadows already treat the key light. Slots 1-2 keep today's behaviour.
- **The plan's VRAM figure was right** — 112 MB at one sun, logged at allocation.
- **`_render_shadow_node` re-enables culling unconditionally after a two-sided mesh**, so a pass
  that disables culling up front does not stay disabled. It happens not to matter here (every
  caster faces the light), and it is left alone rather than fixed inside this branch.

### Still true, and still deferred

The four-moment reconstruction, hair *receiving* its own shadow, the punctual path and coloured
transmittance all stand exactly as scoped above. Nothing measured here argues for reopening any
of them; the ramp arm in particular shows the transmittance path resolving a continuous alpha
gradient to RMS 0.0025, which is the thing the moment path would have been bought for.
