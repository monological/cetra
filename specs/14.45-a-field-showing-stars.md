# cetra 14.45: a field showing stars

## Context

pcb 10.3, the datasheet extraction, sends a datasheet's pages to an AI provider with the user's
key, kept in a file of pcb's config folder that only the user can read. The key is given at a
terminal (`pcb key openrouter`, each character a star) or in pcb's window, by a dialog whose
field shows a star for each character typed. cetra's text field shows its text as it is.

Settled with the user in pcb 10.3's talk: "we'll update cetra to do hidden text field then with
asterisks", built before pcb's dialog, which uses it once it is landed and pinned (pcb's spec,
phase 10).

Branch and spec: `14.45-a-field-showing-stars`, off cetra's master (`134b4ed5`).

## The design

```c
enum {
    UI_FIELD_MULTILINE = 1,
    UI_FIELD_READ_ONLY = 2,
    UI_FIELD_SUBMIT_ON_ENTER = 4,
    UI_FIELD_SECRET = 8, // each character shown as a star; never copied, cut or dragged out
};
```

- **A mirror of the text, one star a character.** The field keeps a second buffer of a `*` for
  each character of its text, whatever its length in UTF-8, and measures, places its caret,
  selects and draws over it, each offset of the text handed to it as the characters before it; a
  click lands on the star it is over. `ui_field_text` gives the text itself. (Built first with a
  mark as long as each character, which the look turned down: see As built, the look.)
- **Nothing of it leaves the field but by the app**: copy and cut copy nothing and cut nothing;
  word moves and a double press see one word, stars having no spaces, so a move tells nothing of
  where the text's words are. Paste, undo and typing are a field's.
- **Wiped when let go**: the text's and the mirror's bytes are zeroed before they are freed or
  grown past, so a key does not stay in the heap after its field.
- **A field of one line**: a secret field that is also multi-line is one line, as a password's
  is; the flag is taken, the other left.
- Nothing else changes: the placeholder shows as it is, the field's size and style are a field's.

## Phases

0. **The spec**, this file, committed alone.
1. **The field**: `UI_FIELD_SECRET`, the mirror kept with every edit, copy and cut refused, the
   wipe; `docs/ui.md`'s text field.
2. **The arm**, `ui-field-secret` in the UI group, reading gametest's `--ui-probe field-secret`: a
   field typed `ab1`, `é` and a four-byte character -- the glyphs drawn are stars, as many as
   the characters, each the same width; the caret after each character where the stars put it; select all and copy leaves the clipboard as it was, cut leaves the text; a word move from
   the end goes to the start; `ui_field_text` the text typed; a click on the second star puts the
   caret after the first character.
3. **The look**: `apps/canvas --ui --ui-secret TEXT`, a flag to look at one, run and looked at;
   the roadmap's line; the README and the CLI reference.

## As built

**Phase 1, the field.**
- `UI_FIELD_SECRET = 8` in `ui.h`. The field's `shown` buffer is NULL for any other field, so "is
  it secret" is `f->shown` inside `ui_field.c`, and `_shown(f)` is what measures and draws.
- `_mirror` rewrites the marks from the text in `_sync_from`, which every edit, `ui_field_set_text`
  and `ui_field_append` already pass through; `_width` measures `_shown(f)`. Each mark is as long
  in UTF-8 as its character: `*`, `·` (U+00B7), `∗` (U+2217) and U+10FFFD. The atlas holds the
  first two; the other two draw as the UI's missing-glyph box at the face's .notdef advance.
- The two buffers grow together (`_move_secret`): a new one allocated, the old copied, zeroed
  through a volatile pointer (`_wipe`) and freed, where `grow_array`'s realloc would leave the old
  bytes behind. `_delete_chars` and `ui_field_set_text` zero the tail a shorter text leaves;
  `ui_field_free` zeroes the text and stb's state, which holds what undo would bring back.
- Copy returns at once and cut cuts nothing. The word moves go to the text's ends and
  `_select_word` selects the whole.
- `ui_field_make` takes the multi-line and submit-on-Enter flags off a secret field before the
  buffers are made, so `_reserve`'s first call already sees the flag.
- `docs/ui.md`'s text field says it.

**Phase 2, the arm.** `--ui-probe field-secret` types `ab1`, `é`, `€` and `😀`, a character of
each length, the three-byte one added to the spec's list so each mark is drawn. In the field's own
rect it counts 4 glyph quads (3 the star's box, 1 the dot's) and 2 missing-glyph boxes; the caret
at every character is 0 points from where the marks' widths put it, the stars a step of 7.396
points apart; copy and cut leave the clipboard and the text; a word move from the end goes to 0
and back to 12; a double press selects 0 to 12; a press a quarter into the second star sets the
caret at 1; a field asked for `SECRET | MULTILINE | SUBMIT_ON_ENTER` takes `a`, Shift+Enter, Enter,
`b` as `ab`. The field arms (`ui-field-*`), `ui-type-palette`, `ui-click-palette` and `ui-typed`,
17 in all, pass. Falsified: copy let through for a secret field fails the arm on `copied clip` and
`cut clip`.

**Phase 3, the look.** `apps/canvas --ui-secret TEXT` puts the field under the `--ui` panel,
focused and live. `--ui-secret "hunter2 é€😀"` headless showed eight stars, a dot and two boxes
with the caret after them. The roadmap's line, the README and the CLI reference say it.

**The user's look** turned the dot and the boxes down: "show * for every character". The marks
of each character's own length kept every offset the text's, but drew an atlas's missing box for
three and four bytes, and told an accented letter or an emoji from ASCII.
- The mirror is now a `*` for each character (`_mirror`), as text_utf8_next steps over them, and
  the measuring text is as long as the stars. stb_textedit and the field keep their offsets in
  the text's bytes; `_shown_at` turns one into the number of characters before it wherever the
  stars are measured or drawn: a glyph's width and a row's for stb, the caret, the scroll, the
  selection. A secret field is one line, so its one row starts at 0 in both.
- The arm counts 6 glyphs, all the star's, and no box; the caret after each character where that
  many stars put it, 0 points off, every step 7.396 points, spread 0.0001. The 17 field and typing
  arms pass. The same text headless now shows eleven stars and the caret.

## Not in this spec

A field that shows its last character for a moment as phones do; a button that shows the text;
the system's secure input mode on macOS (`EnableSecureEventInput`), which keeps other apps from
reading the keys typed and is the app's to turn on.
