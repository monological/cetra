# 11.51 — An ivy arcade

## Context

Rows of stone arches forming a tunnel, clad in ivy, with sun raking through the gaps between
ribs as vertical light streaks. Authored in Blender, exported as GLB, rendered by the `render`
app, with the foliage animated at runtime through `Material.wind_response` rather than baked
keyframes.

It is the first asset in the corpus with **authored per-vertex wind data**, and the first
**imported** foliage scene of any kind. Both firsts are the reason it needs a spec rather than
being a modelling session: every existing vegetation surface here is generated in C
(`apps/tree`, `apps/forest`), where the wind channels are written by the same code that builds
the mesh and cannot disagree with it. Through a file they can.

**11.50 is a completed dependency, merged.** `foliageShadows` is a `.cscn` material key now, so
imported ALPHA_MASK foliage can cast and receive. This spec authors the key; it does not redo
that work.

That merge changed the design, and the change is worth stating rather than quietly inheriting.
The hybrid build below was originally chosen for **two** reasons and only one survives:
shadowing no longer requires an opaque shell. The overdraw argument does, and it is now the
entire case.

### What the wind contract actually demands

`wind_mode` 2 ("vegetation leaf") does not read texture coordinates from UV1. It reads wind
data — `cetra/shaders/include/wind.glsl:49-72`:

- **UV1.x** is a phase in `[0,1)`. The shader multiplies by 2π itself, so the unit is turns.
  Values outside the range alias in the sway terms but *not* in mode 2's flutter, which uses
  `phase * 7.0` — so 0.3 and 1.3 are the same sway and different flutter. Wrap it.
- **UV1.y** is a flex weight used as a raw linear multiplier: 0 anchored, 1 maximum travel.
  Nothing clamps it in the shader, the importer, or the VBO upload.
- **UV0.y** additionally weights mode 2's flutter, so a card pivots about `v = 0` rather than
  sliding bodily. That is the same UV that samples the albedo atlas, so it is doubly
  load-bearing and cannot be chosen freely.

A card whose UV0.y runs the wrong way flutters about its tip and swims. A mesh with no UV1 at
all does not error: `tex_coords2` is NULL, attribute 8 reads `(0,0)`, and the result is phase 0
and flex 0 — a stiff, uniformly-phased lean. **The failure is silent and looks nearly right**,
which is why the convention gets proved on three quads before ten thousand cards depend on it.

## Decisions

- **Hybrid ivy.** An OPAQUE displaced shell carries the mass; ALPHA_MASK cards only on
  silhouettes and gap rims. `doubleSided` disables face culling (`render.c:682-684`) so every
  card rasterizes twice, and `discard` forfeits early-Z — an all-card surface's bill is
  overdraw, not triangles. A dense ivy mat genuinely is opaque, so the shell is not a cheat.
- **Dimensions**: 3.0 m inner span, 4.0 m to the flat top, 1.2 m shoulder radius, 0.7 m piers,
  ribs 0.5 m deep at a 1.4 m pitch, 24 ribs ≈ 33 m. Metric, one unit is one metre.
- **The profile is an "n"** — vertical piers, rounded shoulders, flat top. Not a semicircle.
- **The gaps between ribs are load-bearing.** They are what make the vertical light streaks. A
  continuous swept tunnel loses the defining feature of the reference.
- **PolyHaven has no ivy.** Its texture categories carry no ivy, leaf or foliage entry, so the
  mat is baked. PolyHaven remains the right source for rib masonry.
- Files land in `assets/ivy_arcade/`, mirroring `assets/abandoned_window/`.

## Phase 1 — Calibration spike

Three quads, before any scatter.

A **double V-flip** stands between Blender and the shader: the exporter writes
`v_gltf = 1 - v_blender`, assimp's glTF2 importer flips every texcoord set back
(`glTF2Importer.cpp:642-644`), and cetra applies `aiProcess_FlipUVs`, which flips all sets
again (`import.c:84-88`, `import.c:1715`). Net prediction: the shader sees `1 - v_blender`, so
UV1.y is authored as `1 - flex` and UV0.y as 1 at the stem.

The two assimp flips are traced from source. **The exporter's flip is the one link in the chain
that cannot be verified inside this repo**, which is the whole justification for the phase.

Author three quads with UV1.y = 0.0 / 0.5 / 1.0 and a known UV0.y gradient; drive them from a
`.cscn` with `windMode: "vegetation leaf"`, a large `wind.strength` and `windResponse` — all
authorable, so this needs no C. Observe which quads move and which end each pivots about.
Record the confirmed convention; everything downstream depends on it.

### Result — **CONFIRMED, and the prediction was exact**

The exporter's flip was read straight out of the GLB accessor rather than inferred: a quad
authored UV1.y **0.0** in Blender arrives as **1.0** in the glTF, 1.0 arrives as 0.0, and 0.5 is
the fixed point. It applies to TEXCOORD_0 identically. Assimp's two flips then cancel, so **the
shader sees the raw accessor value**.

Both channels were then measured in the renderer rather than trusted:

- **UV1.y (flex).** Top-of-quad displacement +45.0 / +33.0 / +21.0 px for glTF flex 1.0 / 0.5 /
  0.0 — steps of exactly 12 px per 0.5, linear as `sin(...) * amp * flex * 0.5` requires. The
  +21 px residual on the flex-0 quad is the height-mask body lean, which carries no flex, and
  the 24 px spread is identical at top and bottom because flex is constant per card.
- **UV0.y (flutter pivot).** +13.40 / +11.89 / +10.31 px for glTF 0.0 / 0.5 / 1.0, steps of 1.51
  and 1.58. **The first attempt at this was confounded and wrong**: the mode-2 flutter is
  `f = sin(... + p.x*3.0 + p.z*2.7)`, and three quads spaced 2.0 apart in x span nearly a full
  period of `p.x*3`, so the trend was position, not UV. `f` has no `p.y` term, so the quads were
  restacked vertically at one x and z; their no-wind centres then agree to 0.1 px, which is the
  control that makes the remaining difference attributable.
- Turbulence drives **two** terms and only the mode-2 one is weighted by `uv0.y`; the other is
  uniform across the card and dominates the magnitude. Isolating the gradient needs the constant
  removed, not just turbulence turned up.

**Authoring rules, in Blender coordinates:**

1. `UV1.y = 1 - flex`.
2. `UV1.x = phase` in `[0,1)`, unflipped — only `.y` is affected.
3. **The stem goes at Blender `v = 1`**, so the shader reads 0 there and the card pivots about
   the stem instead of swimming.
4. Following from (3) and from textures being uploaded unflipped
   (`async_loader.c:207`, so shader `t = 0` is the TOP image row): **the leaf's stem must sit at
   the top row of its texture cell.** `IvyLeafReal_base.png` has the stem at the bottom, so it
   is flipped vertically when the atlas is built. This one is derived rather than measured, and
   it is self-announcing — a leaf mapped the wrong way up is visible immediately, unlike the
   wind channels, which fail silently.

### Phase 1b — the convention gets an instrument

`assets/wind_uv_fixture.gltf` plus the `wind-uv-flex` arm. Three identical quads differing only
in TEXCOORD_1.y (1.0 / 0.5 / 0.0), rendered still and then under wind: travel must descend in
that order by equal steps, because flex is a raw linear multiplier. Measured 48.57 / 31.80 /
15.04 px, steps of 16.76 against 16.77 — **0.0% apart**. 0 px twice on one build.

**Scoped to the half cetra owns.** The fixture writes glTF accessor values directly rather than
going through Blender, because what can regress here is assimp's two flips CANCELLING — an
assimp bump or a change to `uv_flip_flag()` inverts the convention silently and every imported
plant animates wrong. The exporter's flip is glTF-spec behaviour on the far side of the file
boundary, is not in CI, and stays recorded here rather than asserted.

**The arm was written once in a form that could not fail**, and the near-miss is worth keeping.
It first normalised travel by the sign of `(first - last)` so the fixture's wind could be
re-aimed without touching the arm. But an inverted convention hands the first quad 0.0 and the
last 1.0, the travels come back ascending, and that sign flip turns them into a descending
sequence passing every check — the one regression the fixture exists for would have been the
one thing invisible to it. It now compares MAGNITUDES in authored order, which survives a re-aim
and still fails an inversion; verified by regenerating the fixture with the flex reversed and
watching the arm go red.

It also reads the flex values **out of the glTF** rather than holding a copy, for the reason
`_water_ramp_edges` does. A stale copy here would not be a stale threshold but a stale LABEL:
the arm would report flex values the fixture does not carry, which is how a red gate ends up
describing the wrong defect.

The UV0.y pivot half is **not** covered. It needs turbulence, and turbulence arms two terms of
which only the mode-2 flutter reads `uv0.y` — the other is uniform across the card and larger,
so the signal is ~10% of the movement. Deferred rather than bolted on; the failure it guards
(cards swimming instead of pivoting) is visible rather than silent.

## Phase 2 — Base geometry

One parametric "n" rib, instanced 24 times as linked duplicates so they share a glTF mesh;
assimp maps shared `node.mesh` indices to one `aiMesh` and cetra dedups to one `Mesh*`
(`import.c:1546-1560`), which is what the batcher keys on.

**Do not expect 24 ribs to become one draw**, and do not read it as a defect when they do not.
The opaque lane re-sorts every frame on
`[63:48] depth bucket | [47:28] material | [27:4] mesh | [3:0] lod` (`draw_list.c:365-370`),
with depth in the HIGH field — so ribs spread down 33 m of tunnel land in different buckets and
their runs fragment before mesh identity is ever consulted. `gates.py` already models exactly
this for forest with two arms rather than one: `forest-batch` wants ratio ≥ 8 with sorting off,
`forest-batch-ship` wants ≥ 1.4 and measures 2.64. Read this asset the same way, as a pair.

Graph order still governs the **shadow** passes, which read `scene->draw_list` raw
(`shadow.c:1131`, `1170`, `1469`, `1498`) and get no sort at all. Emit ribs as contiguous
siblings.

Checkpoint: screenshot against the reference before any ivy. Proportions and rib pitch are far
cheaper to fix now than after cladding.

## Phase 3 — The mat, baked

Scatter leaf cards on a plane with toroidal wrap so the result tiles; bake albedo, normal,
roughness and AO at 2048 in Cycles. Build it from
`assets/abandoned_window/textures/IvyLeafReal_base.png` (512², alpha present, single leaf) so
the mat and the Phase 5 cards are provably the same plant rather than two plants that happen to
be green.

## Phase 4 — The opaque shell

Offset the rib surface outward ~0.15 m and displace with noise for a lumpy silhouette.
ALPHA_OPAQUE wearing the Phase 3 mat: early-Z intact, no `discard`, shadows with no special
casing, one material for the whole mass.

Three or four shell variants rather than 24 identical ones. Variety is nearly free — the camera
pass groups by mesh within a depth bucket on its own, and depth has already split the ribs, so
distinct meshes cost little that was not already spent.

**No wind on the shell.** A dense mat on masonry barely moves, and `wind_response > 0` sets
`DRAW_UNBOUNDED`, exempting the mesh from frustum culling entirely (`draw_list.c:108-111`).
`apps/forest` states the rule at `forest.c:14-15`: no wind on anything scattered.

Thin the density near the openings so the gaps stay open and the streaks survive.

## Phase 5 — The masked fringe

Geometry-nodes scatter on silhouette edges, gap rims and the shell's outer fringe; ~10-15k
cards. Wind data follows `apps/tree`, which is the reference implementation:

- **UV1.x** — one random phase per runner in `[0,1)`, smoothstep-blended from the parent runner
  over the first quarter of the arc so a joint has no phase discontinuity to tear along
  (`tree_gen.c:354-359`); cards inherit their runner's phase plus a jitter, wrapped
  (`tree_gen.c:740-741`).
- **UV1.y** — `pow(arc_dist / max_arc_dist, 1.2)`, constant across a card's four vertices
  (`tree_gen.c:742`). The exponent is superlinear deliberately; linear flex reads differently.
- **UV0.y** — stem to tip, per the Phase 1 convention.

ALPHA_MASK, cutoff 0.4, doubleSided, matching `tree.c:1288-1298` and `forest.c:660-668`. The
mask lives in the albedo texture's **alpha**; `baseColorFactor[3]` does not feed the cutoff
(`assets/gen_mask_fixture.py:28-32`). Trim quads tight to the silhouette. Avoid exactly
coplanar overlaps, the one draw-order dependence left after 11.31.

**Chunk as ~24-96 merged meshes, one or a few per rib.** Not 60k objects: that hits a 938-draw
floor from `UBO_INSTANCE_MAX 64` and realistically 26-34k draws at forest's measured ~1.77
instances per draw. Not one giant mesh either, and the reason is the wind rather than culling:
`uWindMaskMinY/MaxY` come from the per-mesh AABB (`render.c:553-555`), so a chunk must span the
full rib height. A near-horizontal chunk saturates the height mask across millimetres and
translates bodily along the wind vector instead of bending.

These chunks are uncullable. At 24-96 that is acceptable; at 60k it would not be.

## Phase 6 — Export and scene file

Each of these is a failure that is silent or fatal rather than obvious:

- **Export NORMAL always.** `import.c:757-759` dereferences `mNormals` with no null check, so a
  primitive without normals crashes the importer.
- **No GPU Instances, Draco, or meshopt.** The vendored assimp supports none of them and drops
  `EXT_mesh_gpu_instancing` silently.
- **Apply all object transforms.** Wind is applied in object space before the model matrix
  (`object_position.glsl:43-47`), so a rotated node rotates the wind, a scaled node scales the
  displacement, and the height mask measures the wrong axis.
- **Two UV layers, in order.** glTF requires contiguous `TEXCOORD_n`, and a missing UV0 makes
  assimp skip UV1 entirely (`glTF2Importer.cpp:628-630`).
- **COLOR_0 alpha must be 1.0** if shipped at all — `pbr_frag.glsl:1035-1042` multiplies vertex
  alpha into the cutoff test, so alpha below 1 silently erodes the ivy.
- No occlusionTexture on a vegetation material; UV1 is wind data there.

`assets/ivy_arcade/ivy_arcade.cscn` auto-loads from `-m ivy_arcade.glb`
(`cscene_apply.c:30-53`). Its `environment` uses a **nested** `sun: { elevation, azimuth }` — a
flat `sun_elevation` is read by nothing, and that exact mistake cost `water_fixture` four specs
(`cscene.c:126-140`). A low sun down the tunnel axis is what makes the shafts. The fringe
material takes `windResponse`, `windMode: "vegetation leaf"`, `foliageShadows: "on"`, and
`abandoned_window.cscn:57-65`'s tuned ivy SSS (`color [0.727, 1.0, 0.614]`, `radius 0.06`).

## Verification

1. Determinism floor first: render one config twice and require `magick compare -metric AE` to
   print 0 before any later comparison is quoted. Wind rides the fixed-step frame clock, so
   frame N is phase N and this should hold.
2. `--profiler`, SHADING block: **depth complexity** is the number that matters for masked
   foliage, not triangle count. Take it before and after Phase 5 so the fringe's cost is
   attributable to the fringe.
3. Batching as a pair: `draws` / `instances` on the `opaque` row under the shipping config and
   again under `--no-sort-opaque`. The second is the batching ceiling; the first is what ships.
4. Import log `Import: N meshes built, M shared references, K LOD chains`. `M` proves the ribs
   collapsed to a shared mesh. Expect `K` low — leaf cards are nearly all boundary and meshopt
   returns roughly what it was given (`lod.h:24-30`).
5. `foliageShadows` earning its place: render with the key and without it. This is the first
   asset that can exercise 11.50 as it was intended, rather than through raiden's hair, which is
   the case the default deliberately excludes.
6. Visual against the reference: rib pitch, streak spacing, density gradient. Measure
   `--depth-prepass` rather than assuming — CLAUDE.md records it losing everywhere in this
   corpus, but a dense masked colonnade is precisely the content it was designed for and
   precisely what the corpus has never contained.
