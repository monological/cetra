# 5.6 Data-driven ambient dust (.cscn `dust` block)

## Context

The abandoned-window scene's floating dust is built by `attach_window_dust` in
`apps/render/src/render.c` -- a hardcoded particle recipe (spawn rate, curl-noise
scale/strength/timescale, drift, size, color, lifetime) triggered by a filename gate
(`strstr(model_path, "abandoned_window")`). Tuning any of it means editing C and
recompiling, and the earlier review flagged the filename gate as a smell. The wind
feature just moved the same class of per-scene look into the `.cscn`; the dust should
follow. Goal: author the dust motion in the scene file (so it can be **calmed without a
rebuild**, per-scene, with spores untouched -- it is a separate app with its own recipe),
and delete the filename gate.

## Design

### 1. `.cscn` `dust` block (`cetra/src/cscene.h` / `cscene.c`)
Add a `CSceneDust` struct to `CetraSceneDesc` (a single scene-level effect, like `fog`),
each field with a `has_*` presence flag so absent fields keep the built-in recipe default:
`spawnRate`, `lifetime[2]`, `size[2]`, `color[4]` + `colorJitter`, a nested
`curl{scale,strength,timescale}`, `drift[3]`, `damping`. Parse in a new `parse_dust`
(mirrors `parse_wind`); add a small `get_floats(obj,key,out,n)` helper (generalizes
`get_vec3`) for the 2- and 4-element arrays.

### 2. `apply_cscene_dust` (`apps/render/src/cscene_apply.c` / `.h`)
Move the recipe out of `render.c` into `apply_cscene_dust(engine, scene, cscn, center,
radius)`: seed defaults = the current recipe, override each from the desc `has_*` flags
(like `apply_cscene_wind`), then build the emitter (the exact
`create_particle_program`/`create_tf_particle_sim_backend`/`particle_module_*` stack that
was in `attach_window_dust`). Spawn box + capacity stay derived from the scene bounds.
Gated on `cscn->dust.enabled` -- the dust appears because the scene **declares** it.

### 3. Delete the filename gate (`apps/render/src/render.c`)
Remove `attach_window_dust` and the `strstr(model_path, "abandoned_window")` call; call
`apply_cscene_dust(engine, scene, cscn, scene_center, scene_radius)` in the same spot.
Keep `render_frame_update` (the engine_run tick hook, unrelated). Move the particle
includes to `cscene_apply.c`.

### 4. Author + calm the dust (`assets/abandoned_window/abandoned_window.cscn`)
Add a `dust` block overriding only the motion knobs to calm it:
```json
"dust": {
  "curl":  { "scale": 0.3, "strength": 0.035, "timescale": 0.04 },
  "drift": [0.0, 0.0025, 0.0]
}
```
(`curl.strength` 0.06 -> 0.035, `drift` 0.004 -> 0.0025; spawn/size/color keep defaults.)

## Reuse
- `parse_wind` / `apply_cscene_wind` as the structural template.
- The `particle_module_*` stack + `create_billboard_particle_renderer` /
  `create_tf_particle_sim_backend` -- moved verbatim, values sourced from the desc.
- `get_vec3` -> generalize to `get_floats`.
- The already-computed `scene_center`/`scene_radius` for the spawn box.

## Verification
1. `./build.sh` clean.
2. `render assets/abandoned_window/abandoned_window.cscn --headless --frames 400
   --screenshot dust.ppm --screenshot-every 80`: dust present but visibly calmer than
   before; edit `curl.strength` in the `.cscn` and re-run (no rebuild) to confirm it is
   live-tunable.
3. Non-window model: no `dust` block -> no dust (gate gone, nothing declares it).
4. Confirm spores is untouched (separate app, own recipe).

## Notes
- Defaults reproduce the historical recipe, so a bare `"dust": {}` == the old look; the
  scene file authors the intended (calmer) values.
- Continues on the `curtain-wind` branch (same abandoned-window scene-look effort, same
  `.cscn`/cscene files).
