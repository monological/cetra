# cetra 14.39: tags in 3D

## Context

**What 14.39 builds.** A surface in a 3D view carries a tag, the net or part it is of, and a class,
the kind of surface it is. A table says how each tag is drawn (a colour, an outline, dimmed, hidden,
lit); each view says how each class is drawn (see-through, a colour, hidden) and how far what is not
lit fades. Choosing, the spotlight, see-through, a pane's layers and the layout's colours below 100%
become table writes, with no mesh rebuilt. A chosen thing is outlined after a still view's average,
so choosing restarts nothing.

**Why now.** pcb's spec 8.1, the 3D view, needs it for its phase 8: picking, hover, choosing, the
outline, the spotlight's fade and ghost, see-through and its keys, the layout's colours below 100%,
the ceiling and the part the height check finds. The brief is in pcb's spec, "What cetra builds"
(`apps/pcb/.claude/worktrees/8.1-the-3d-view/specs/8.1-the-3d-view.md:152-160`). 14.38's views are
on master (`80d047f2`); the roadmap's Order paragraph already names 14.39 (`docs/eda-roadmap.md:78`).

### Decided with the user (2026-11-16)

1. **A tag says how it is drawn, not what it means**: colour, outline, dim, hidden, lit, the
   canvas's own fields (`CanvasTagState`, `canvas.h:102`) less `raised`. The brief's "chosen" and
   "marked" stay pcb's words: pcb's layout already turns every meaning into a colour, a dim, hidden
   or lit (`layout_picks.c:752-811`), and a chosen part's box becomes an outline in 3D.
2. **One tag table, borrowed by the views**, as canvases borrow theirs; every 3D pane shows one
   write. A view with its own table borrows another. The class table and the fade are per view.
3. **A surface below full opacity, or faded, casts no shadow**, so what is lit inside a see-through
   board is lit.
4. **The outline shows through what hides it, fainter**, so a chosen part on the far side shows.
5. **The class is on the node, not the vertex.** A vertex carries only its object (pcb's
   `Board3dVertex.object`, the net); the node carries the class and, for a part, its object. pcb
   already builds one mesh per class per cell (`Board3dMesh.klass`) and tags a part per placement
   (`view3d_build.c:206`).
6. **A fading view fades everything not lit, untagged included.** pcb's FR4, mask and silk are
   object 0 (`board_3d.c:924, 931, 1071`); under the canvas's rule they would never fade and the
   spotlight could not show a net inside the board. pcb tags nothing new.

### My calls, for the user to overturn

- **The vertex's object wins over the node's where both are set**, the more specific; a node's
  object and class are inherited down the tree where a child's are 0, as `view_mask` is ANDed.
- **Class 0 means none** (no class row read), as tag 0 does; pcb's classes start at 1.
- **The table is dense**, as long as the largest tag set, limit 2^22 (the canvas's). pcb's part
  tags set bit 23 today (`BOARD_3D_PART`, `board_3d.h:42`), which would make 8M rows: pcb numbers
  nets and parts from one count. Recorded as a pcb need in the roadmap.
- **A colour is a matte paint**: rgb in place of the material's colour, its alpha the share
  painted; under the paint metal 0 and roughness 1, so copper in a layer colour reads as that colour
  and not as coloured metal. A class's `flat` mixes in the paint drawn unlit at the view's exposure,
  so it reads in shadow (pcb's "lightly lit so its shape reads", set at its look). A tag's colour
  wins over its class's; either hides.
- **The fade is see-through**: a surface not lit is drawn at `(1 - fade)` of its opacity, so it
  fades toward whatever is behind it, the background included; at 1 it is gone. No room round what
  is lit (the canvas's `fade_room`): in 3D a distance on screen means nothing. `dim` darkens toward
  black, as the canvas's.
- **A triangle's three corners carry one object.** A dropped surface (hidden, or in the other lane)
  is collapsed in the vertex stage, so it costs no fragment and works in the depth-only programs. A
  triangle spanning two objects would stretch; pcb's surfaces are per-net regions, so it holds.
- **The second lane runs only in a view that ghosts** (a fade above 0, or a class below full
  opacity): there every opaque item is drawn again in the OIT moments and accumulate passes, its
  solid surfaces dropped there and its ghosts dropped from the opaque, prepass and shadow passes. A
  view that ghosts nothing draws as today.
- **Transmissive surfaces and the late lane honour hidden only**; neither fades nor is painted.
- **The outline is the view's own pass after its chain**: a depth pass of the solid surfaces,
  unjittered, then the outlined surfaces with the depth test off, each fragment comparing its depth
  to say seen or hidden, then a ring outside the silhouette, `outline_points` wide (1.5, the
  canvas's), its outer edge antialiased by distance, `outline_hidden` (0.35) where only hidden. It
  is an RGBA8 overlay blended over the picture when the picture is copied into the window
  (`_engine_copy_view`), so the picture is never touched. Views with no outlined tag skip it.
- **What restarts a view**: a table write to colour, dim, hidden or lit restarts the views
  borrowing the table; an outline write re-runs only their outline pass. Class rows and the fade
  are settings, compared byte for byte with the rest; a node's tag or class changed is noticed by
  the walk, as a changed `view_mask` is. No new `mark_changed` call.
- **Captures and kept lamp shadows see no tags.** The engine logs once when a view hides or ghosts
  something within a kept lamp's reach, as 14.38 logs the mask. pcb uses neither.
- **The tag table is read on texture unit 16, a vertex-stage unit** outside `pbr_frag`'s full
  ledger of 16: within one program two sampler types on one unit fail at draw
  (`docs/shaders.md:453`), and every unit below 16 is a fragment sampler's in the full variant. The
  engine checks `GL_MAX_COMBINED_TEXTURE_IMAGE_UNITS` and refuses tags with a log if 16 is not
  there. Phase 1 proves it first on this machine. The class rows are a uniform block (binding 11,
  256 rows of 16 bytes); `pbr_frag` keeps its two free blocks.
- **The tag path is a feature bit** (`PBR_FEAT_TAGS`, 1024), on for a view with a table, a class
  row or a fade; the depth-only programs branch on a uniform. An app using no tags compiles and
  draws what it does today.
- **A tags render mode** paints each object a colour from its number, so the arms see that a tag
  reached a surface without reading the table's effects.
- **The roadmap gains item 4a, Tags in 3D**, beside 3 and 4, as 6a sits beside 6.

## Found while planning

- **Location 4 is free on every mesh program** (`common.h:6-36`; 6 and 7 are the bones); the GPU
  particle sim uses 4 on its own VAO, and `docs/shaders.md:340-344` calls 4 the particles'
  convention, so that line changes. An integer stream exists (`_upload_int_stream`, `mesh.c:382`,
  the bone IDs). No generic attribute value is ever set, and a disabled integer attribute reads an
  undefined value unless one is, so the engine sets location 4's to 0 once.
- **The mask's path is the tag's**: `view_mask` is ANDed in the transform walk (`scene.c:1188`,
  `walked_mask`) and the draw-list walk (`draw_list.c:375`, stored on `DrawItem` at :412).
- **The instance block** grows by a `uvec4` an instance, 12288 to 13312 bytes, under the 16 KB
  guaranteed (`ubo.h:41, 64`); `_instance_chunk_fill` (`render.c:980`) must fill it on the depth and
  shadow path too. pbr_skinned and the single-object draws take a uniform.
- **Programs drawing draw items**: pbr variants and pbr_skinned (`pbr_vert`, `pbr_skinned_vert`),
  the prepass (`depth_prepass_vert`, and the masked prepass through pbr at `passMode` 3),
  `shadow_depth_vert` for cascades, punctual, kept tiles, rain and the absorb (TSM), the OIT moments
  and accumulate through pbr (`passMode` 2 and 1), the late lane (`late_surface_vert`, the app's
  own shader).
- **A lane comes only from the material** (`classify`, `draw_list.c:84-117`); OIT alpha is
  `finalOpacity` (`pbr_frag.glsl:1803`), for moments and accumulate alike.
- **Varyings**: 35 components between `pbr_vert` and `pbr_frag` (+5 under fur). The tag's paint
  and misc ride two packed `flat uint`s.
- **The canvas's table** is a growable `GL_TEXTURE_BUFFER` of RGBA8, three texels a tag, uploaded
  by dirty range, its generation noticed by `canvas_generation`, an `outlined` count skipping the
  ring pass (`canvas.c:14-171, 454`). The 3D table keeps the same layout.
- **A finished view's depth is not kept**: `fx->depth_texture` is written only when something reads
  it, and `draw_projection` is the last frame's jitter (`scene_view_state.h:89`), hence the
  outline's own unjittered depth.
- **The glTF importer drops custom vertex attributes** (assimp's `GetAttribVector`,
  `glTF2Asset.inl:199-219`), so per-vertex tags in the gates come from the render app, not a file.
- **Gate names**: the canvas group owns `canvas-tags` and `canvas-dash-tags`, so the new arms are
  `scene-tag-*`, which `--arms tags` would also choose, and `--arms scene-tag` alone.

## Design

### Public API

```c
// scene_tags.h
typedef struct SceneTagState {
    uint32_t colour;  // a matte paint in place of the material's colour, alpha its share; 0 = none
    uint32_t outline; // a ring round the silhouette, after the picture is made; 0 = none
    float dim;        // 0 = as drawn, 1 = black
    bool hidden;      // drawn nowhere, shadows included
    bool lit;         // spared by a fading view
} SceneTagState;
SceneTags* create_scene_tags(void);
void free_scene_tags(SceneTags* tags);
bool scene_tags_set(SceneTags* tags, uint32_t tag, SceneTagState state); // false: 0 or past the limit
SceneTagState scene_tags_get(const SceneTags* tags, uint32_t tag);

// scene_view.h
typedef struct SceneTagClass {   // all zeros = as the material
    uint32_t colour;             // as SceneTagState.colour, under a tag's
    float see_through;           // 0 = solid, 1 = gone
    float flat;                  // the paint's share drawn unlit
    bool hidden;
} SceneTagClass;
// SceneViewSettings gains: SceneTagClass tag_classes[256]; float tag_fade;
//   float outline_points; float outline_hidden;
// SceneView gains (SETTINGS): SceneTags* tags; // borrowed; NULL = every tag as drawn
// SceneNode gains (SETTINGS): uint32_t tag; uint8_t tag_class; // 0 = the parent's
// Mesh gains a uint32_t stream: tags, one object a vertex, on location 4
```

### In the shaders (`include/tags.glsl`, one include for every program)

Per vertex: the object (attribute, else the instance's or node's), the class (instance or node);
the table's row (unit 16) and the class row (block 11); the view's fade and lane. Out: drop the
vertex (hidden, or the other lane's), else two flat words: the paint (rgba8) and the misc (opacity,
flat, dim). `pbr_frag`, under the bit: the paint into albedo, metal and roughness before shading,
the flat share and the dim after, opacity into `finalOpacity`. No existing expression is regrouped.

### The frame

Unchanged but for: the walk carries each node's effective tag and class into its draw items and
notices a change; each view with tags binds its table and class block before its passes; a view
that ghosts draws its opaque items through the OIT passes too; after its chain, a view with an
outlined tag runs the outline pass into its overlay; the copy into the window blends the overlay.

### Phase 3: see-through

**Built:**
- **A lane a draw keeps** (`uTagLane`): in a view that ghosts this frame an opaque item keeps its
  solid surfaces in the opaque pass and the prepass (1) and its see-through ones in the OIT moments
  and accumulate (2); any other item keeps both (0). `SceneViewState.ghosts_this_frame` says the
  view ghosts and OIT can run (on, PBR, not a capture), set where its scene pass starts.
- **The OIT passes run for a view that ghosts** whether or not the scene has a translucent mesh,
  taking the opaque lane too; an opaque item there counts as a pass past the opaque one
  (`alpha_pass`), so its ambient specular stays inline.
- **The opacity**: `finalOpacity` times the tag's, for the moments and the accumulate alike; a
  surface the opaque pass keeps is solid, so it multiplies by exactly one there.
- **Shadows**: every shadow pass keeps only solid surfaces (lane 1), so what is see-through or faded
  casts nothing, in every view and whether or not OIT runs.
- **The kept lamps' log**: said once when a view hides or ghosts by its tags while any lamp's
  shadow is kept. Tags are per vertex, so which surfaces lie in a lamp's reach is the GPU's to
  know; the mask's log could ask the CPU.

**Departures:**
- **A view whose see-through surfaces have no OIT to go to draws them solid** (OIT off, a debug
  mode): the opaque pass keeps them, and they still cast nothing. If the OIT targets cannot be made
  in a frame that ghosts, its see-through surfaces are missing from that frame.
- **The moment-based OIT darkens a lone see-through layer by about a tenth**: its transmittance
  estimate counts the layer against itself. Under the weighted OIT one layer composites within
  0.4% of the half-and-half mean. It is the moments' bias on every translucent surface, not the
  tags'; `scene-tag-fade` measures under the weighted OIT and says so.
- **An authored occluder drawn see-through still occludes**: the occlusion proxies are the CPU's,
  and pcb authors none.

**Arms:** `scene-tag-fade`, `scene-tag-ghost-off`, `scene-tag-shadow`. The goldens, 33 of 33, 0 px.

**Looked at:** the fixture faded by 0.6 with strip 2 and part1 lit, the rest, the untagged floor
too, see-through and casting nothing, the two lit ones' shadows on the faded slab; and the slab's
class at 0.7 see-through, the strips' shadows falling through it onto the floor.

**Falsified** (the work committed first): the OIT passes not taking a ghosting view's opaque lane,

### Phase 4: the outline

**Built:**
- **`render_view_outline`**, for every shown view each frame, after the views draw: drawn again
  when the view drew this frame or its table's outline generation moved, kept otherwise, dropped
  while it outlines nothing. Three passes at the picture's size from the view's unjittered camera:
  the depth of its solid surfaces through the prepass; its outlined surfaces into the mask
  (`outline_mask_vert/frag`), everywhere at `outline_hidden`, then over that at full where the
  depth lets them through; the ring (`outline_ring_frag`) outside each silhouette, `outline_points`
  wide in framebuffer pixels, its outer edge antialiased by distance, the strongest of the nearest
  covered pixels deciding its colour and strength.
- **The overlay at the copy**: `present_frag` lays it over the view's picture, premultiplied, when
  the view's copy passes it; the window's own present passes none. The picture is never drawn into.
- **Only what can carry an outline is drawn into the mask**: a node tagged with one, or a mesh
  tagged by vertex, through a program that drops every vertex whose object has none.

**Found:** phase 1 put the table and its generation on the view's change record and never compared
them, so a row written to the table restarted no still view; `scene-tag-node` passed through the
moved mask, which a node's tag reaches, and nothing tried a table write. `_view_changed` compares
them now, and `scene-tag-restart` and `scene-tag-shared` are the arms that would have caught it.

**Arms:** `scene-tag-outline`, `scene-tag-outline-still`, `scene-tag-restart`, `scene-tag-shared`.
The goldens, 33 of 33, 0 px.

**Looked at:** part0 and its cap ringed purple and strip 1 yellow, at 5x: the rings clean, three
pixels, their outer edges soft.

**Falsified** (the work committed first): the mask's hidden pass skipped, `scene-tag-outline` finds
part2 behind part3 ringed at 0.00 where 0.35 is wanted; an outline write counted with the writes
that restart a view, `scene-tag-outline-still`'s resting view draws 17 frames again after 40 and
its last frame is 7883 px from the outline there from the start.
