# 11.69 — terrain streaming: windows into a streamed pyramid (roadmap D4)

## Context

D4 is the last unbuilt half of the terrain track: 11.63 made the terrain big (CDLOD quadtree,
in-memory mip pyramid, resident regions) and D7 made it data (erosion), but everything is
fully resident — 4 MB at forest's 513², 291 MB at 4097², 1.16 GB at 8193². The roadmap's own
scope (D4 entry + row 36, and 11.63's out-of-scope hand-off): *windowed reads, an on-disk mip
chain, a range manifest* — "rings or quadtree nodes as windows into a streamed mip pyramid.
Erode offline at top resolution; stream the result." Three exploration passes and two design
passes verified every claim below against source.

**The core decision: per-level rectangular WINDOWS, not a tile cache.** One window of nodes
per pyramid level anchored near the player, the coarse tail always fully resident. Chosen
over 11.67's page-table shape on three grounds: the hot path (`sample_plane` runs ~30k
calls/patch-build; a window resolves to `base[(j-z0)*stride + (i-x0)]` — one 4-compare
containment test per sample, where a page table pays a lookup per footprint corner, the 4×4
bicubic straddling up to 4 tiles); the access pattern (every heavy consumer walks a
contiguous square, and CDLOD selects level-k patches in an annulus whose radius doubles with
k — exactly fixed-node-count windows whose coverage doubles per level; page tables earn their
keep on sparse feedback-driven access, which this is not); and determinism (a window's
position is a pure function of the anchor path — the eviction ordering, want-guard and
hysteresis machinery 11.67 needed mostly evaporates). Window shifts `memmove` the overlap by
whole 64-node tile columns (chosen over toroidal addressing, which puts a modulo on every tap).

**The organizing consumer rule** (stated once here and once at the ensure entry point):
anything that builds a PERSISTENT artifact — a Jolt BVH, a scatter placement, a cached patch
mesh — reads exact data via synchronous ensure; anything transient falls to the coarse tail;
prediction exists to make the ensures cheap, never to be correct on its own. This closes the
patch-staleness problem structurally: `patch_get` is already a synchronous build point, so
ensure-at-build keeps the drawn surface a pure function of the camera path rather than of I/O
arrival order (the 11.67 fixed-latency lesson, honored by having no async completions at all
— fill is synchronous budgeted `pread` on the main thread; `async_loader` stays the named
escape hatch).

## On-disk format — `.cts`, fp32, the SAVED pyramid

u16 cannot be bit-identical to the in-memory field (the pyramid is fp32 filtered from
dequantized L0), and the roadmap's own budget figures are fp32. `.r16` + `.r8` siblings stay
the interchange format, `heightmap.c` untouched; `.cts` is an engine-private derived artifact.

```
Header: magic 'CTER', version, res, level_count, tile_nodes=64, f32 min_y/max_y,
        mask_res (coarse resident masks; 0 = none), reserved
LevelTable[level_count]: res_k, tiles_k, u64 offset_k   (tile (tx,tz) at pure arithmetic)
CoarseMasks: flow/deposit/wear at mask_res², filtered by the same filter_plane at save
Tiles: L0 = 64×64 fp32 × 4 planes contiguous (one pread); L>=1 = height only.
       Edge tiles padded by edge replication (the sampler clamps anyway).
```

Two contracts: **the stored levels ARE the saved in-memory pyramid** ([1 2 1] tent), never
re-filtered at load — or the fallback's bit-equality claim dies while L0 identity stays
green; and **extent-independent** node space, like `.r16` (extent/center stay on
TerrainParams). Save refuses a field with no coarse pyramid levels (the (res−1)-even rule —
4096² builds none, 4097² builds eleven; already documented at `forest.c:915-934`).
Sizes: 4097² ≈ 296 MB, 8193² ≈ 1.18 GB. Written offline; opened reading header + tail only.

## Mechanism (new `cetra/src/procedural/terrain_stream.c/h`)

Leaf header the roads.h way: `TERRAIN_STREAM_TILE_NODES 64`, `WINDOW_TILES 8` (levels >= 1),
`RESIDENT_RES 1025` (levels at/under stay whole — at 513² that is EVERYTHING, so the
identity config is free), `APRON_NODES 4` (bicubic's asymmetric [i−1,i+2] + the widened
normal step), `BUDGET 16` tiles/frame (cap 64). `TerrainStream` owns a `TerrainField` (the
installed seam), per-level `{mem[4], window rect, resident sub-rect, file offset}`, coarse
masks, and counters `loaded/ensured/misses` (misses counted at the read).

- **terrain.h**: `TerrainField` gains `struct TerrainStream* stream;` (NULL = every field
  before 11.69; calloc already zeroes it). Contract comment: when set, plane pointers are
  windows and direct res×res indexing is suspended — `heightmap_save`, `terrain_field_measure`
  and erosion refuse a streamed field (min/max come from the manifest).
- **terrain.c** (the only sampler changes): `sample_plane` → thin wrapper over
  `sample_plane_view(base, res, stride, ...)` with `stride == res` — identical float op
  sequence, so the unstreamed path is bit-identical. `terrain_height_at_level` and
  `terrain_mask_at`'s field branches gain one `if (field->stream)` each — zero cost
  unstreamed, never reached on the analytic path. The stream resolver is static in terrain.c,
  sharing `catmull_rom`, the clamp and `terrain_to_domain` — one bicubic, one clamp, one
  mapping ("two sources one contract" becomes "two residencies one sampler").
- **Miss policy** — `field_level`'s clamp-don't-fail extended spatially: a query whose
  CLAMPED footprint escapes level k's resident rect retries at k+1 (2× the world coverage),
  terminating at the always-resident tail; the answer is exactly
  `terrain_height_at_level(x,z,j)` for the served j — never 0, never a stall. Masks fall
  from the L0 window to the coarse resident planes, still clamped [0,1].
  **terrain-clamp's exact equality survives in every residency state**: the coordinate is
  clamped BEFORE the containment test, so an outside-domain query and its edge twin take the
  same decision and return the same float.
- **`terrain_stream_update(s, p, eye, focus)`** — called at the HEAD of forest's
  `regions_update` (forest.c:1484), which one hook covers all three call sites (init :1963,
  rebuild-internal :1678, per-frame :2295) with exactly the two anchors the stream needs
  (camera = drawn levels, player = L0): re-target windows (snapped to tile columns, with a
  dead-band so sub-tile motion never re-targets), advance resident rects toward the window
  by <= budget tiles in a fixed total order. `loaded` counts every tile pread INCLUDING the
  tail/whole-level fill at open — the definition the identity arm's anti-vacuity rests on.
- **`terrain_stream_ensure_rect(s, p, x0, z0, span, level)`** — synchronous, unbudgeted,
  pads by the apron; MAY re-anchor the window when the rect lies outside it (this IS the
  teleport path); warns once and falls coarse only when a rect exceeds the window's capacity.
  Residency stays a pure function of the run because every ensure site is deterministic.

## Flags (forest only — the only terrain consumer) and probe

`--terrain-stream <p.cts>` (opt-in install; wins over `--heightmap` wins over `--erode`,
said out loud at the forest.c:1872 idiom — so there is no `--no-terrain-stream`; the off leg
is the already-gated whole-file path), `--terrain-stream-save <p>` (write from the installed
field after the pyramid site; doubles as the `.r16`→`.cts` converter),
`--terrain-stream-budget N`, `--terrain-stream-window N` (window tiles per axis — the
forced-small churn lever), `--terrain-stream-resident-res N` (diagnostic: lower the
always-resident threshold so a fixture-scale field streams at all),
`--terrain-stream-probe N`. All in the `--no-X` / `--X-when->0` idiom (forest.c:2471).

One printf shape, one gate regex (the `_VT_PROBE` lesson):

```
terrain-stream-header path= res= levels= tile= min= max= ms=
terrain-stream-probe frame= levels= l0=%d,%d resident_kb= loaded= ensured= misses= digest=%08x
terrain-stream-probe saved path= res= levels= tile= min= max=
terrain-stream-probe level idx= res= window= resident=      (final block, one per level)
terrain-stream-probe fallback x= z= h= expect= level= resident=   (final block; h vs expect bit-equal)
```

digest = FNV-1a over window origins + resident rects, so determinism is one comparison.

## Risks, bounded

1. **Hot-path cost** of the containment test on ~30k-eval patch builds: A/B/A/B on release
   with `--profiler` (the interleaving discipline); the unstreamed path is bit-identical by
   construction, so the risk is streamed-only.
2. **Teleport hitch**: ensures are unbudgeted by design — one window refill (~tens of ms at
   4097²) at the region-load hitch that already exists; async_loader is the named escape
   hatch, out of scope now.
3. **Splat fidelity at 8 km+**: capped at 2048, stream beds smear far out — explicitly D10's
   splat-pyramid problem, breadcrumbed.
4. **Invariant suspension**: direct res×res indexing invalid on a streamed field — enforced
   by refusals in heightmap_save/measure/erode plus the contract comment; a future direct
   indexer is the residual hazard.
5. **Mixed-level normals** where a ±h pair straddles a window edge: deterministic, bounded
   by inter-level detail, named here. The 4-node apron covers the common case.
6. **Collider segment derivation** (`COLLIDER_SEGMENTS 256` over the whole domain,
   forest.c:1414) coarsens at big extents — a constant collider CELL is the small follow-up,
   not this spec's scope.

## AS-BUILT

**1. A window is `n * tile + 1` nodes, and getting that wrong made the far edge of
the world unreachable.** The grid is node-centred -- which is why a level is `2^k + 1` and why
the pyramid halves as `(res-1)/2+1` -- so a run of whole tiles covers one node FEWER than it
looks. Sized as `n * tile`, no tile-aligned window can ever reach the level's last node: every
rect touching it silently failed to become resident, and everything built there came from the
fall. The `+ 1` also lands the origin bound on a tile (`res - win_nodes` is `2^k - n * tile`),
so the snap is a no-op rather than a source of further slack. This is the same arithmetic the
rest of the file already lives under, arrived at a third time.

**2. The window shift ran its source index backwards, and Jolt is what said so.** `delta` is
`dst - src`, so a row's source is `dst - delta`; written as a plus, the terrain slid the wrong
way onto tiles that stayed marked resident. Nothing fell, nothing warned, and the surface was
simply somewhere else. It reached the region collider as geometry flat enough that Jolt's AABB
tree builder took a random split and traced -- and `JPH::Trace` defaults to `DummyTrace`, which
is `JPH_ASSERT(false)`, so the process took a SIGTRAP. **That also swallowed the buffered probe
rows**, so the first symptom was an arm reporting zero rows rather than a crash, and the
diagnosis started in the wrong place. `AGENTS.md` already records the trace-on-coplanar failure
mode from 11.63; this is its second appearance and the first where the geometry was accidental.

**3. A window's last tile holds one node column, so a move can promote a stub to an interior
tile.** After a shift by one tile, the old edge tile becomes an interior tile needing all 64
columns, of which 63 were never read. Carrying its residency bit marked a tile resident over
stale memory -- again with nothing falling and nothing warning. Residency now carries only from
a source tile that was COMPLETE, which costs one tile row and column of re-reading per move.

**4. The refuse arm's guard is not the one the plan named.** The manifest length check does not
hold it in any configuration tried: the coarse levels sit at the END of the layout and are read
whole whatever the residency, so a truncated tail always fails a READ first. Deleting either
guard alone leaves the arm green; both together install a half-loaded field and the probe reads
`source=field`. The check is defence in depth against a header and a length disagreeing without
the tail being touched. The arm now runs forced-small so the refusal is at least exercised in
the configuration the feature lives in.

**5. The collider arm cannot see a uniformly coarse world, and that is correct.** Forcing every
containment test false leaves it green: the printed `terrain` column falls exactly as the
collider does, so the two agree and the clearance is undisturbed. What the arm measures is
DISAGREEMENT between the ground a capsule stands on and the height function everything else
reads -- which is what the shift bug produced (70.03 units) and what building the collider two
levels coarse produces (0.320 against 0.120). Correctness of the surface itself belongs to
`terrain-stream-correct`, and that is the arm the uniform-coarse mutation kills, at 5759 codes.

**6. Level 0's window is sized by the REGION radius, so `--region-radius` is the lever that
makes it stream.** `--terrain-stream-window` sizes the coarse levels; level 0 takes whichever is
larger of that and the coverage a region load needs. Left at the shipping 1500, the finest
window covers a 1 km domain outright and nothing about streaming is observable -- which is why
every arm here passes `--region-radius 60` and why the walk arm inherits `REGION_CHURN`.

**7. `sample_plane`'s refactor is a true identity and was checked as one before anything else
landed.** All nine `terrain` arms read their documented numbers unmoved -- closed-form 0.47
codes, bicubic 53.3, the thread digest `acb2307e955eda10`.

## Measured

- **Round trip, 257 nodes:** 59 height-probe rows -- header, 25 samples, 8 clamp pairs, 25
  midpoints -- byte-identical between the in-memory field and the streamed one. The format
  carries fp32 bit patterns, so this is equality and not agreement.
- **Correctness under pressure:** 0.45 codes worst against the painted closed form at a 1-tile
  budget with a 2-tile window, where the whole domain is read, dropped and re-read beneath the
  probe. 116 tiles read against the 25 that cover level 0.
- **The fall:** 16 probe points, 11 outside level 0's window, every one returning its settled
  level's own value exactly.
- **Walk (400 frames, 513-node field, 4-tile window):** 475 tiles read, 5 distinct window
  positions, 4461 kB of window, identical twice with digest `0d57ae42`. The character stays
  grounded at every settled trace row with a worst clearance step of 0.120 -- the SAME number
  the walk measures with the field fully resident.
- **At scale (release, 4097² eroded 60 iterations):** bake and save 15.6 s wall, 11 levels, a
  300 MB file against a 291 MB resident field. Streamed over a 4 km domain the windows hold
  **86.5 MB** -- level 0 windowed at 2113 of 4097 nodes, level 1 at 513 of 2049, levels 2 and
  coarser whole -- which is 3.4x off resident.
- **And the scaling is not what "streaming" suggests, which is worth stating before anyone
  plans against it.** Resident cost tracks the COVERAGE the app asks for divided by the CELL,
  not the size of the map. The same file over an 8 km domain holds **36.5 MB**, less than half,
  because doubling the world at a fixed node count doubles the cell. So **growing a world is
  free and refining it is not** -- which is the opposite of the intuition that a bigger world
  costs more to stream.
- **On forest's own shipping configuration it buys nothing, by construction.** At a 1 km domain
  the region radius (1500, plus two spans) asks for exact heights across the whole world, so
  level 0's window covers the entire field and holds 274 MB. That is the system answering the
  question correctly: this is a big-world feature, and forest's default world is not one.
- **Falsification, all run:**

| mutation | killed |
|---|---|
| containment forced false | terrain-stream-correct (5759 codes against a 3-code bar) |
| off-by-one tile index | identity, correct, fallback, walk -- the read runs past the file and the open reports 0 levels |
| zero returned on a miss | terrain-stream-fallback (5 of 16 rows leave their level) |
| manifest length check skipped | nothing -- the coarse-tail read catches it first |
| refusal-on-read-failure skipped | nothing -- the length check catches it first |
| both refusal guards skipped | terrain-stream-refuse (`source=field`, a half-loaded field renders) |
| dead-band deleted | terrain-stream-walk (598 reads against a 520 ceiling, 475 healthy) |
| mesh ensure deleted | terrain-stream-walk (level 0's window takes 1 position, not 5) |
| collider built two levels coarse | terrain-stream-collider (0.320 clearance step against 0.120) |
